In one paragraph

A random test sweep over arrays with Real index and element sorts found two inputs that Z3 refutes but whose Lean reconstruction failed. In the first, a cnf lemma reads an array that is equated to a constant array, but nothing stated the constant array's value at that index. In the second, Z3's congruence closure treats the extensionality witness as commutative, and Lean had no matching fact. The reconstructor now states both facts. Each one is a theorem proved inside the generated Lean file, so the trust boundary does not grow. More Z3 refutations over arrays now end in a Lean-checked proof.

Background

Before this PR, the pipeline already certified many array inputs: select and store, constant arrays, long store chains, and arrays of enumerations. For a constant array, it stated reads only at indices that some store wrote to. It also stated one extensionality fact per witness, but only in the argument order that appeared. So a lemma that read a constant array elsewhere, or used the witness of b, a where it had a, b, failed in Lean. This work belongs to milestone 4 of the plan, "Broader theories and integration", where arrays are one of the theory extensions.

What changed

  • A cnf lemma that reads an array equated to a constant array can now be proved, because the constant array's value at each read index is stated as a fact.
  • A lemma that uses the extensionality witness of two arrays in both orders can now be proved, thanks to the new prelude theorem _array_diff_comm.
  • These extra read facts are capped at 64 per lemma, so a large input cannot blow up the Lean file.
  • The random array test generator can now produce Real-indexed and Real-valued arrays, and two failing Real seeds are pinned as regression tests.
  • The README and the plan document now explain where the new facts in a generated file come from.

Think of the first fix like two keys that open the same locker. Knowing a = K tells you the lockers are the same. You still have to look inside K to learn what is stored there. The new read facts are that look inside.

The second fix is like asking for "a place where two lists differ". The answer should not depend on which list you name first. Z3 used that symmetry silently. Lean needed it proved, and the new theorem proves it.

Worked example

This input is the PR's new documented test read_of_an_array_equated_to_a_constant. The outputs below come from real runs of the old and new scripts on it.

(a) The input

(set-logic ALL)
(declare-const a (Array Int Int))
(declare-const k Int)
(assert (= a ((as const (Array Int Int)) 1)))
(assert (distinct 3 (select a k) (select a 0)))
(check-sat)

Array a holds 1 everywhere, yet one of its reads must equal 3, which is impossible.

For every interpretation, the two assertions together imply False.

The cnf lemma that used to fail, now with the new read fact:

private theorem th_lemma_15 (_atoms : Nat -> Prop) (_vars : Nat -> Int) (_m : Interpretation)
    : (formula_14 _atoms _vars _m) := by
  unfold formula_14 formula_13 formula_12 formula_11 term_6 term_5 term_4 formula_3
  have _t2 : (term_2 _atoms _vars _m) = (@_const_array Int Int (((1 : Int)))) := rfl
  ...
  have _dc2_5 := _select_const (I := Int) (((1 : Int))) (_vars 0)
  first | omega | grind (splits := 64)

The new line _dc2_5 says the constant array of 1 holds 1 at k, so grind can chain a = const 1 to select a k = 1.

The new prelude theorem, which every array file now carries. This example does not need it, but the PR's input commuted_extensionality_witnesses does:

private theorem _array_diff_comm {I E : Type} (h : Nonempty I) (a b : I -> E) :
    _array_diff h a b = _array_diff h b a := by
  have _p : (fun _j => Not (a _j = b _j)) = (fun _j => Not (b _j = a _j)) :=
    funext (fun _j => propext (Iff.intro (fun _n _e => _n _e.symm) (fun _n _e => _n _e.symm)))
  exact congrArg (@Classical.epsilon I h) _p

The witness is chosen by Hilbert's epsilon from "where a and b differ", which is the same predicate either way round, so both choices are equal.

Lean accepted the generated file. The reconstructor printed "Lean checked the refutation", and check_lean.sh printed "Lean checks passed."

Review

The reviewer approved with no blockers and no major findings. They re-ran the new tests against the old code and saw them fail. They also ran their own Real/Real sweep, 96 of 96 verified.

Minor, README. The reviewer read the README section on array facts. It did not mention _array_diff_comm or the new reads. Someone auditing a generated file would find facts with no explanation. The soundness claim still held, so this was drift, not a bug. The README now describes both.

Nit, fragment check. The pinned-seed test guessed the logic fragment from whether "Real" appeared in the input. That guess is wrong when the index is Real and the element is Int. Pinning such a seed would fail for a reason unrelated to Lean. The test now derives the fragment from the sorts and maps mixed sorts to qf_uflira.

Suggestion, combined cap. One lemma could get up to 640 chain reads plus 64 side reads. That is bounded, and the docstring says so. It stays as a follow-up.

Suggestion, witness count. The test asserts exactly two witnesses, which may break if Z3's certificate shape changes. The author kept it, because it documents that both argument orders occur.

Risks and open questions

  • Lemmas over constant arrays get more facts, up to 64 each. The sweeps showed no slowdown.
  • If a future input has both long store chains and selects, the two kinds of reads should share one cap.
  • An index written as an unnormalized numeral, such as (/ 2 2) next to 1.0, still fails. Z3's rewriter evaluates it, but grind keeps the two indices apart.
  • Real-indexed arrays of Int elements can still hit the rejection "arithmetic step over both Int and Real atoms".
  • CI results on master after the merge are unknown to this report.

What comes next

The follow-ups named in the PR are a Lean-proved value fact for numeral-only index expressions, and support for arithmetic steps that mix Int and Real atoms. Another is letting the exporter prefer the conjunct a clause was split from, which would give simpler cnf lemmas.

Glossary

array
A total map from an index sort to an element sort, written (Array Int Int) in SMT-LIB. In Lean it becomes a function, such as Int -> Int.
clause
A disjunction of literals: it is true when at least one literal is true.
cnf lemma
A lemma that links a clause to the original assertions it was derived from during conversion to clause form.
commutative
An operation whose result does not change when its two arguments are swapped, like x + y = y + x.
congruence closure
The procedure that groups equal terms, using the rule that equal arguments give equal function results.
constant array
An array with the same value at every index, written ((as const (Array Int Int)) 1).
equality
A formula (= s t) stating that two terms have the same value. Two arrays are equal when they agree at every index.
extensionality
The principle that two arrays are equal if they agree at every index.
extensionality witness
An index where two different arrays differ. Z3 writes it (_ array-ext 0), and Lean writes it _array_diff.
Hilbert's epsilon
A choice operator that picks some value satisfying a predicate if one exists. Lean provides it as Classical.epsilon.
lemma
A small proved statement used as a step in a larger proof.
literal
An atomic formula or its negation, such as (= 3 (select a k)) or its not.
refutation
A proof that a set of assertions implies False.
select
Reading an array at an index: (select a k) is the value of a at k.
sort
The type of a value, such as Int, Real, Bool, or (Array Int Int).
store
Writing to an array: (store a i v) is a with the value at i replaced by v.
store chain
Several stores nested on one array, such as (store (store a 1 5) 2 7).
tactic
A Lean command that builds part of a proof automatically. grind and omega are tactics.
theorem
A statement together with a proof that Lean's kernel has checked.
trust boundary
The set of things a check assumes without proof. This PR adds nothing to it, because every new fact is proved in the file.
