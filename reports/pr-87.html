Certify arithmetic steps over ites with conditions of the other sort

Pull request levnach/z3#87 into master · State: OPEN · Opened 2026-11-07T07:28:51Z · Loop iteration 87

This pull request is open and not merged. The change described here is commit 6b4109c. It contains two commits: the code change and a README update made after review.

In one paragraph

In inputs that mix Int and Real, the Lean reconstructor used to reject a theory lemma that touched an if-then-else term whose result has one sort but whose condition compares values of the other sort. An example is an Int ite chosen by the condition x > y over Real values. The reconstructor treated the condition's values as atoms of the step. It then saw both sorts and gave up. Now the ite counts as a single atom of its own sort, and its condition is left out. These steps get a Lean proof, and Lean's kernel check still checks every one. No axiom or sorry was added. More mixed-sort refutations from Z3 can now be certified end to end.

Background

The fragments qf_lira and qf_uflira already worked when each arithmetic step stayed within one sort. An uninterpreted function application was already treated as one atom, whatever the sorts of its arguments. An ite was not. The project plan listed this as a known gap in its qf_uflira section. The gap also appeared without any ite in the input. Z3's rewriter turns an array read of a store over (Array Real Int) into an Int ite over a Real equality. That is why one random seed (103) was rejected in iteration 86. This PR serves milestone 3 of the plan, "Equality and linear arithmetic". It also helps the array work of milestone 4.

What changed

  • The reconstructor now certifies an arithmetic step over an Int ite whose condition compares Real values, and the reverse case too.
  • A step whose own literals really mix both sorts is still rejected, exactly as before.
  • Reads of stores into Real-indexed arrays of Int elements, which the rewriter turns into such ites, now verify in Lean.
  • The random test generator for mixed problems can now wrap variables in ites over conditions of the other sort, so tests can find these cases.
  • The project plan and the examples README now say that an arithmetic ite's condition does not decide the step's sort.

Think of an ite as a sealed envelope that always holds an integer. The label on the outside may talk about real numbers, but the arithmetic only cares about what is inside. The code change is three lines in one helper. It stops the helper from looking into the condition, which is the first argument of an arithmetic ite.

Worked example

This input is the PR's new test input lira_int_ite_over_real_condition. It was run through the pipeline before and after the change for this report.

(a) The input

(set-logic QF_LIRA)
(declare-const x Real)
(declare-const y Real)
(declare-const a Int)
(declare-const b Int)
(assert (< (+ (ite (> x y) a b) 1) a))
(assert (< a (+ b 1)))
(check-sat)

The ite picks a or b, both Int, using a condition over Reals. If it picks a, the first assertion says a + 1 < a. If it picks b, the two assertions say b + 1 < a < b + 1. Both are impossible.

(b) Before: the base commit's scripts

The old exporter produced a certificate. The old reconstructor then stopped with this error:

proof_to_lean.py: error: arithmetic step over both Int and Real atoms at node 38

Node 38 is a Farkas lemma over the ite. The old code counted x and y from the condition as atoms of that step.

The ite is declared with result type Int. Its condition formula_2 compares two Rat values. Z3 rewrote it into term_13, the same choice with the condition flipped to x <= y.

The main theorem says that the two assertions, _h0 and _h1, together imply False for every value of the variables.

private theorem th_lemma_38 (_atoms : Nat -> Prop) (_vars : Nat -> Rat) (_ivars : Nat -> Int)
    : (formula_37 _atoms _vars _ivars) := by
  unfold formula_37 formula_36 formula_35 formula_30 term_29 term_28 formula_22 term_21 term_6 term_4 term_3
  first
    | (generalize (term_13 _atoms _vars _ivars) = _o0
       omega)
    | (unfold term_13 formula_11 term_4 term_3 term_1 term_0
       have _g13_0 : (((_vars 0) <= (_vars 1))) -> ((@ite Int ...)) = (_ivars 3) := fun _h => ite_eq_left _h
       have _g13_1 : (Not (((_vars 0) <= (_vars 1)))) -> ((@ite Int ...)) = (_ivars 2) := fun _h => ite_eq_right _h
       first | omega | grind (splits := 64))

This is the step that was rejected before. It now proves its clause as pure Int arithmetic: it replaces the ite by an unknown integer _o0 and calls the tactic omega. A fallback unfolds the ite and adds its two gate facts.

Review

The reviewer approved the change. There were no blockers and no major findings.

  • Minor, fixed. The reviewer compared the new behavior with the examples README. They built a probe with a to_real inside an ite's condition. The README said such a step is a cast step, but the code now treats it as a plain Int step. Documentation that disagrees with the code misleads the next person who changes it. A second commit added the ite exception to both README paragraphs.
  • Suggestion, not changed. The reviewer noticed that one pinned test's pattern only checks the Int-ite-over-Real direction. The reverse direction is already covered by its own documented input and by the new validation test.
  • Suggestion, out of scope. While sweeping, the reviewer hit an exporter error on seeds 201 and 242: "unsupported operator in the clause log: +". That error comes from a file this PR does not touch, so it was recorded as a follow-up.

Risks and open questions

  • A step whose only to_real sits inside an ite's condition used to take the cast path. It now takes the Int or Real path. The PR argues this is sound because Int rounding over atoms that are all Int is valid. Lean also checks every step.
  • No random sweep yet puts cross-sort ites outside function applications in qf_uflira. The reviewer's hand probe of that case passed.
  • The CI and local gate results were not known when this page was written.

What comes next

  • Fix the clause-log exporter so it accepts + in the mixed ite instances from seeds 201 and 242.
  • Handle numeral indices that are not normalized, such as (/ 2 2) next to 1.0. This is still open from iteration 86.
  • Add a random sweep with cross-sort ites outside function applications in qf_uflira.

Glossary

array read and store
Array operations in SMT-LIB. (select a i) reads index i of array a. (store a i v) is a copy of a with v written at i.
atom
The smallest piece the arithmetic reasoning treats as one unknown value. A variable like a is an atom. After this PR, a whole ite is one atom too.
axiom
A statement accepted without proof. A trustworthy certificate must not add new ones.
Boolean
The sort of truth values, true and false. Conditions such as (> x y) are Boolean.
cast (to_real)
A conversion from one sort to another. (to_real n) turns the Int n into the same Real number.
clause
A disjunction of literals: at least one of them must be true. Example: p or not q or x < 3.
Farkas lemma
A theory lemma backed by coefficients. Multiplying the inequalities by those numbers and adding them gives an obvious contradiction such as 0 < 0.
fragment
A family of inputs the pipeline supports, named after SMT-LIB logics. qf_lira is quantifier-free linear Int and Real arithmetic. qf_uflira adds uninterpreted functions.
gate clause
A clause that ties a compound term to its parts. For an ite, one gate clause says "if the condition holds, the ite equals the then-branch".
if-then-else term (ite)
A term (ite c t e) whose value is t when the Boolean condition c holds and e otherwise. Its sort is the sort of t and e.
kernel check
The final check by Lean's small trusted core. Every proof step must pass it, whatever tactic produced it.
literal
An atom or the negation of an atom, used as one part of a clause. Example: not (x <= y).
proof core
One of the two ways the pipeline gets evidence from Z3: the clause log or the legacy proof object. New tests run on both.
refutation
A proof that a set of assertions leads to False, so they cannot all hold together.
rewriter
The part of Z3 that simplifies terms before solving. For example, it can turn a read of a store into an ite.
seed
A number that fixes the choices of a random generator. The same seed always gives the same test problem, so a failing case can be repeated and pinned.
sorry
A Lean placeholder that skips a proof. A certified file must not contain it.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that builds part of a proof automatically. omega proves facts about Int linear arithmetic. grind is a more general search.
theory lemma
A clause that holds because of the meaning of arithmetic, arrays, or equality, not because of Boolean logic alone. Each one is a separate proof step.
uninterpreted function
A function symbol with no fixed meaning. The only rule is that equal arguments give equal results. Example: f : Int -> Real.
