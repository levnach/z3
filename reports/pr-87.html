Certify arithmetic steps over ites with conditions of the other sort

Pull request #87 State: MERGED Merged: 2026-11-07T07:38:56Z Merge commit: e6c0ca7 Loop iteration 87

In one paragraph

Problems that mix the sorts Int and Real can contain an Int if-then-else term whose condition compares Reals, or the reverse. Before this PR, the Lean reconstructor rejected every theory lemma that reached such a term, because it saw atoms of both sorts. Now it treats the ite as one atom of its own sort. Steps such as Farkas lemmas over it now reach Lean and are kernel-checked, with no new axiom or sorry. This closes a known gap in the fragments QF_LIRA and QF_UFLIRA. It also covers inputs where Z3's rewriter creates such a term from an array read.

Background

The reconstructor already handled Int and Real side by side, with casts and uninterpreted functions. It gives each theory lemma one sort, read off the atoms it reaches. Function applications and array reads already counted as single atoms. The condition of an arithmetic ite did not, and the plan listed this as a known gap. In iteration 86, the same gap rejected a random constant array problem with Real indices and Int elements. This work serves milestone 3 of the plan, "Equality and linear arithmetic".

What changed

Think of an ite as a ticket machine. A Real comparison picks the ticket, but the ticket is always an Int. An Int step only needs the ticket. The gate clauses record which branch each ticket comes from.

  • Reconstructor: steps over an Int ite with a Real condition, or a Real ite with an Int condition, are now certified.
  • Reconstructor: a step whose own literals mix the two sorts is still rejected.
  • Tests: two new QF_LIRA inputs, one per direction, are checked in Lean on both proof cores.
  • Tests: the random mixed-problem generator can now add cross-sort ite terms, and three seeds are pinned.
  • Tests and docs: an Int read of a Real-indexed array and seed 103 are regression tests, and the plan and README describe the change.

Worked example

This input is the PR's new test lira_int_ite_over_real_condition. The outputs come from real runs.

(a) The input

(set-logic QF_LIRA)
(declare-const x Real)
(declare-const y Real)
(declare-const a Int)
(declare-const b Int)
(assert (< (+ (ite (> x y) a b) 1) a))
(assert (< a (+ b 1)))
(check-sat)

Over the integers, the second assertion means a <= b. The ite is a or b, so it is at least a. Then the first assertion, ite + 1 < a, cannot hold.

(b) Before this PR

The old certificate exporter accepted the input. The old reconstructor then stopped with:

proof_to_lean.py: error: arithmetic step over both Int and Real atoms at node 38

Node 38 is an Int Farkas step. The old code walked into the ite's condition, found the Real variables x and y, and refused the step.

This is node 38, rejected before. It treats the ite as an opaque Int and proves the clause with the tactic omega, with a fallback that unfolds the ite.

private theorem def_axiom_16 (_atoms : Nat -> Prop) (_vars : Nat -> Rat) (_ivars : Nat -> Int)
    [_df11 : Decidable (formula_11 _atoms _vars _ivars)]

This gate clause says that if x <= y, the ite equals b. Lean proves it from the definition, so it is not assumed.

Review

The reviewer approved the PR. There were no blockers and no major findings.

  • Minor, fixed. The reviewer probed a to_real cast inside an ite condition. The code classed that step as Int, but the README still called it a cast lemma. Users would have been misled, so two README paragraphs were updated.
  • Suggestion, not changed. The pinned random test only checks the Int-over-Real direction. Other tests already cover the reverse, so it was kept.
  • Suggestion, out of scope. The reviewer's sweep found two seeds where the clause-log exporter fails on +. That code is untouched here, so it became a follow-up.

Risks and open questions

  • A step whose only to_real sits in an ite condition now takes the plain Int or Real path, not the cast path. Int rounding, such as a cut, is sound over Int atoms, and Lean checks each step.
  • The change only widens the sort check. Lean must still prove every step, so nothing new is trusted.

What comes next

  • Fix the clause-log exporter's rejection of + in some mixed ite problems, seeds 201 and 242.
  • Normalize numeral array indices, such as (/ 2 2) versus 1.0, open since iteration 86.
  • Sweep QF_UFLIRA problems with cross-sort ite terms outside function applications. No random test covers this yet.

Glossary

array (select, store)
A map from indices to elements. select a i reads index i. store a i v is a copy of a with v written at i.
atom
A smallest unit that a step treats as one opaque value or fact, such as a variable, a function application, or x <= y.
axiom
A statement accepted without proof. A trustworthy certificate adds none of its own.
cast (to_real)
A conversion from one sort to another. (to_real n) turns the Int n into the same Real number.
clause
A disjunction of literals: at least one of them must be true. Example: x <= 0 or y > 2.
condition
The Boolean test of an ite, the part that picks which branch is the value.
constant array
An array that holds the same value at every index, written ((as const (Array Int Int)) 0).
core (clause log, legacy proof object)
The two ways Z3 records evidence for this project. The legacy proof object is a tree of proof steps. The clause log is a list of learned clauses with hints.
cut
An Int step that rounds a bound to a whole number. From 2n <= 3 it concludes n <= 1.
Farkas lemma
A linear-arithmetic step. It adds the given inequalities with non-negative coefficients and reaches an obvious contradiction such as 0 < 0.
fragment (QF_LIRA, QF_UFLIRA)
A family of problems the checker supports. QF_LIRA is quantifier-free linear Int and Real arithmetic. QF_UFLIRA adds uninterpreted functions.
gate clause
A clause that defines a compound term by its parts. For t = (ite c a b): if c then t = a, and if not c then t = b.
if-then-else term (ite)
A term whose value is one of two branches, chosen by a condition. (ite (> x y) a b) is a when x > y and b otherwise. Its sort is the sort of its branches.
kernel check
The final check by Lean's small trusted core. Every proof, however it was found, must pass it.
literal
An atom or its negation, such as x <= y or not (x <= y).
refutation
A proof that the assertions together lead to False, so they cannot all hold.
rewriter
The part of Z3 that simplifies terms before solving. For example, it turns a read of a store into an ite that compares the indices.
seed (random sweep)
A number that fixes the output of a random problem generator. A sweep runs many seeds to find failures.
sorry
A Lean placeholder that skips a proof. A certified file must contain none.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that builds part of a proof automatically. omega decides Int linear arithmetic. grind is a more general search.
theory lemma
A clause that is true by the rules of a theory, such as arithmetic, rather than by pure logic.
uninterpreted function
A function symbol with no fixed meaning. The only rule is that equal arguments give equal results.
