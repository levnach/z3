In one paragraph

This PR makes one kind of theory lemma smaller and simpler in the generated Lean file. These are the EUF lemmas that mention an if-then-else term. Until now each such lemma carried two proofs inside Lean's first combinator. The first proof kept the ites folded. The second unfolded everything as a fallback. The fallback was never used in the test suite. It doubled the text of these lemmas. It could also starve, because a failed first try can spend the whole heartbeat budget. Now each lemma has only the folded proof, closed by the grind tactic. On the largest test input, the Lean check dropped from about 20 seconds to about 7. The theorem statements and the trust boundary do not change, so the soundness of the refutation is untouched.

Background

The previous PR, #108, taught the reconstructor that Z3's e-graph treats an ite term as a leaf. So an EUF lemma is a congruence argument over its literals, with the ites folded. That PR added the folded proof but kept the old unfolded proof behind it, just in case. Both its summary and its review flagged the cost of that safety net. This PR removes the net. It serves milestone 3, equality with uninterpreted functions. It also helps milestone 4, because large inputs with arrays produce most of these lemmas.

What changed

  • An EUF lemma that reaches an ite term now has exactly one proof, with the ites kept folded and no first.
  • A reader of the generated Lean file now sees one short proof per such lemma instead of two near-copies.
  • The rarely used store-identity attempt, a proof that simplifies array writes, still works over the fully unfolded terms as before.
  • The array tests now fail if any EUF lemma again carries a first or unfolds an ite.
  • The README and the project plan describe the new shape and record the size and time measurements.

Only the Python reconstructor changed. There is no C++ change, so the exporter and Z3's own checker behave as before.

Worked example

This PR certifies no new input. It only changes the shape of proofs the pipeline already produced. So the example below shows a tiny input that both versions accept, and how its proof got shorter. All three pieces come from real runs of the exporter, the reconstructor, and the Lean check.

(a) The input

(set-logic QF_UFLIA)
(declare-fun f (Int) Int)
(declare-const c Bool)
(declare-const x Int)
(declare-const y Int)
(declare-const z Int)
(assert (= (ite c x y) z))
(assert (not (= (f z) (f (ite c x y)))))
(check-sat)

The ite equals z, so f must give the same result on both. The second assertion denies that.

(b) Before: the base reconstructor

The base code did not reject this input. Lean accepted its file too. But the EUF lemma carried two proofs:

set_option maxHeartbeats 1000000 in
private theorem th_lemma_21 (_atoms : Nat -> Prop) (_vars : Nat -> Int) (_m : Interpretation)
    : (formula_20 _atoms _vars _m) := by
  first
    | (unfold formula_20 formula_19 formula_8 term_7 term_6 formula_5 term_4
       grind (splits := 64))
    | (unfold formula_20 formula_19 formula_8 term_7 term_6 formula_5 term_4 term_3 term_2 term_1 formula_0
       grind (splits := 64))

The second line also unfolds term_3, the ite, and everything under it. That is the fallback.

(c) After: the current reconstructor

...
def formula_5 (_atoms : Nat -> Prop) (_vars : Nat -> Int) (_m : Interpretation) : Prop := ((term_3 _atoms _vars _m) = (term_4 _atoms _vars _m))
def term_6 (_atoms : Nat -> Prop) (_vars : Nat -> Int) (_m : Interpretation) : Int := _m.ifuns 0 [(_m.int (term_4 _atoms _vars _m))]
noncomputable def term_7 (_atoms : Nat -> Prop) (_vars : Nat -> Int) (_m : Interpretation) : Int := _m.ifuns 0 [(_m.int (term_3 _atoms _vars _m))]

term_3 is the ite. term_6 and term_7 are f z and f applied to the ite.

theorem unsat (_atoms : Nat -> Prop) (_vars : Nat -> Int) (_m : Interpretation)
    (_h0 : (formula_5 _atoms _vars _m))
    (_h1 : (formula_9 _atoms _vars _m))
    : False :=
  ...

The main theorem says that the two assertions together imply False.

set_option maxHeartbeats 1000000 in
private theorem th_lemma_21 (_atoms : Nat -> Prop) (_vars : Nat -> Int) (_m : Interpretation)
    : (formula_20 _atoms _vars _m) := by
  unfold formula_20 formula_19 formula_8 term_7 term_6 formula_5 term_4
  grind (splits := 64)

This is the EUF lemma: if the ite equals z, then f z equals f of the ite. It has one proof, and term_3 stays folded.

Lean accepted the file. The project's Lean check printed "Lean checks passed." The new file is 156 bytes shorter than the old one.

Review

The reviewer approved. There were no blocker or major findings.

Minor: the store-identity attempt changed by accident. The reviewer traced how the code builds a rarely used extra attempt that simplifies array stores. It was built from the fallback. So it silently inherited the new folded unfold. Its simplifier cannot rewrite inside a folded ite. A lemma that once relied on it could have failed. The documentation also claimed this attempt "stays as before", which was no longer true. The fix builds the attempt from the full unfold again, and a code comment explains why. Output stayed byte-identical over 206 array inputs. No documented input reaches this path, so Lean never tests it.

Nit: a test that could not fail. The reviewer ran a changed test against the base code, and it still passed. On the base code, the lines it looked for sat inside first alternatives, which its matcher skips. So it checked nothing. The test now also asserts that it found at least one such lemma. It now fails on the base code, as a guard should.

Suggestion: run the array tests in CI. This was left as a follow-up, because CI wiring is outside this change.

Risks and open questions

  • This trades completeness, not soundness. An EUF lemma that the folded proof cannot prove now fails in Lean, and the certificate is rejected. No such lemma appeared in any tested input, including 803 EUF lemmas of dlx-regfile.
  • The suspected trigger is a helper fact written after the unfold that spells out an ite term. None was found.
  • The array test file, which holds all the EUF and ite-folding coverage, still runs in no CI job.
  • The rise in peak memory on register_file_instance(8) is not explained.

What comes next

  • dlx-regfile still fails on one cnf lemma, th_lemma_1612. Z3's preprocessing rewriter reshaped that clause's ites. A proof would need a trace of each rewrite, or a way to stop that rewrite.
  • The theory lemmas of dlx-regfile still take about 206 seconds. The next step is to profile which lemmas dominate.
  • Wire the array module's non-Lean tests into CI.

Glossary

array
A theory of maps from indices to values. select a i reads index i, and store a i v writes v there.
clause
A disjunction of literals, such as p ∨ ¬q. At least one must be true.
cnf lemma
A proof step that turns a formula into clauses, in conjunctive normal form.
completeness
Whether the checker can prove every true claim it is given. Losing it means some valid certificates get rejected.
congruence
The rule that equal arguments give equal results. If a = b, then f a = f b.
e-graph
The data structure a solver uses to track which terms are known to be equal, and to apply congruence.
EUF
The theory of equality with uninterpreted functions. Its lemmas follow from equality and congruence alone.
fallback
A second proof that runs only if the first one fails.
first
A Lean tactic combinator. It tries several proofs in order and keeps the first that succeeds.
folded definition
A named definition left as its name, like a sealed box. Lean treats it as an opaque term until it is unfolded.
grind
A Lean tactic that proves goals by equality reasoning, congruence, and case splits.
heartbeats
Lean's work budget for one declaration. When it runs out, the proof fails, and first cannot recover.
if-then-else term (ite)
A term whose value depends on a condition. (ite c x y) is x when c holds, else y.
literal
An atomic formula or its negation, such as x = y or ¬(x = y).
refutation
A proof that a set of formulas leads to False.
rewriter
The part of Z3 that simplifies formulas before solving, by replacing terms with equivalent ones.
soundness
The guarantee that the checker never accepts a false claim.
tactic
A Lean command that builds part of a proof, such as unfold or grind.
theory lemma
A clause that is true because of a theory, such as equality or arithmetic, rather than by pure logic.
uninterpreted function
A function symbol with no fixed meaning. The only thing known is that equal inputs give equal outputs.
unfold
The Lean tactic that replaces a definition's name with its body, like opening the sealed box.
