Prove euf lemmas over folded ites without the unfolded fallback

Pull request levnach/z3#109 into master · State: OPEN · Opened 2026-11-10T21:01:06Z · Loop iteration 108

This pull request is open and not merged. The change it proposes ends at commit eb0a576.

In one paragraph

Some theory lemmas come from Z3's EUF solver. When such a lemma mentions if-then-else terms, the generated Lean proof used to try two tactic scripts under first. The first kept the ite terms folded. The second unfolded everything and served as a fallback. This PR deletes the fallback and keeps only the folded proof. The congruence reasoning in these lemmas never looks inside an ite, so the fallback was never needed in any test. The Lean files get smaller and faster to check. On the eight-stage register-file test, the check time drops from 20 to 7 seconds. The theorem that the input is refuted stays exactly the same, so soundness is unchanged.

Background

The previous PR, #108, taught the reconstructor to prove EUF lemmas with ite terms folded. It kept the fully unfolded proof as a fallback just in case. That fallback doubled the text of these lemmas. It also could not help when the folded attempt ran out of heartbeats, because the budget is shared per declaration. The large QF_AUFLIA benchmark dlx-regfile still did not verify before this PR, and it still does not. The work serves milestone 4, "Broader theories and integration", which covers arrays together with uninterpreted functions and integer arithmetic.

What changed

  • An EUF lemma that reaches ite terms now gets a single proof, with the ites kept folded and no first.
  • The proof files for array-heavy inputs shrink, and some of them check much faster in Lean.
  • A rarely used extra attempt that rewrites array stores still unfolds everything, as before, because it cannot see inside a folded ite.
  • The tests now fail if any EUF lemma gets a first or unfolds an ite, and a Lean test checks more than 50 such folded proofs directly.
  • The README and the project plan describe the new behavior and record the size and time measurements.

Worked example

This PR makes no new input certifiable, so there is no "rejected before" input. The example shows one input checked by both versions, and how its proof changed.

(a) The input

This is the smallest case of the PR's test generator, register_file_instance(1). Two equal inputs u0 and w0 pass through the same ite stage, yet the outputs are said to differ. 

(set-logic QF_AUFLIA)
(declare-fun f (Int Int) Int)
(declare-fun p (Int) Bool)
(declare-const A (Array Int Int))
(declare-const u0 Int)
(define-fun u1 () Int (ite (p u0) (f u0 (select A u0)) (select (store A u0 1) (f u0 1))))
(declare-const w0 Int)
(define-fun w1 () Int (ite (p w0) (f w0 (select A w0)) (select (store A w0 1) (f w0 1))))
(assert (= u0 w0))
(assert (not (= u1 w1)))
(check-sat)

(b) Before: the base reconstructor's output

The base code accepted this input, and Lean checked its file. But each EUF lemma that reaches the ites carried two copies of its proof. Here is one of them, quoted from the real output.

The second alternative also unfolds term_11 and term_18, the two ites, and repeats everything else. Three lemmas in this file had this shape.

From u0 = w0 and not (u1 = w1), every interpretation reaches False.

Review

The reviewer approved. There were no blocker or major findings.

  1. Minor: a side path lost its full unfold. The reviewer traced how the store-identity attempt is built. It copied the folded unfold, but its rewriting tactic cannot work inside a folded ite. So some lemma could fail where it used to succeed, and the plan's "stays as before" was wrong. Fix: the path is now built from the full unfold again, and a code comment explains why. No tested input reaches this path, and the output stayed byte-identical on 206 inputs.
  2. Nit: a test check that could not fail. The reviewer ran a new test branch against the base code, and it still passed. On the base code, the lines it inspects sat inside first alternatives, which the test skips. Fix: the test now also requires that the branch is reached, and it fails on the base code. This matters because a test that cannot fail gives false confidence.
  3. Suggestion: run the array tests in CI. Not a defect. It was left as a follow-up, because CI wiring is outside this change.

Risks and open questions

  • This is a completeness risk, not a soundness risk. If the folded proof cannot prove some EUF lemma, Lean now rejects the certificate. No such lemma appeared in any tested input, including 803 EUF lemmas of dlx-regfile.
  • The store-identity path has no Lean test, since no documented input reaches it.
  • Peak memory on register_file_instance(8) rose. The cause was not investigated.
  • The array and EUF tests still run in no CI job.

What comes next

  • dlx-regfile still fails on one cnf lemma. Z3's preprocessing rewrote an ite chain, so the input and the rewritten form no longer match level by level. A proof that follows the rewrite steps is needed.
  • dlx-regfile's other theory lemmas still take about 206 s and 5 GB. The next step is to profile which lemmas dominate.
  • Wire the array tests that do not need Lean into CI.

Glossary

array
A theory of maps from indices to values. select A i reads position i, and store A i v is a copy of A with position i set to v.
clause
An OR of literals, such as (not a) or b. A theory lemma is a clause.
cnf lemma
A proof step that turns a formula into clauses in conjunctive normal form, an AND of ORs of literals.
completeness
The checker's ability to accept every correct proof. A completeness gap means a true result fails to verify, never that a false one passes.
congruence
The rule that equal arguments give equal results: if a = b, then f a = f b.
EUF
Equality with uninterpreted functions. Z3's EUF solver reasons only with equalities and congruence, and treats an ite term as a single opaque value.
fallback
A second proof attempt, tried only if the first one fails. In Lean, first | A | B tries tactic A, then B.
folded definition
A defined name, such as term_11, left as a name instead of being replaced by its body. A prover then treats it as one opaque value.
heartbeat
Lean's unit of work. maxHeartbeats limits how much work one declaration may use, and running out is an error that first does not catch.
if-then-else term (ite)
A term (ite c x y) whose value is x when the Boolean c is true and y otherwise.
literal
A Boolean atom or its negation, such as u0 = w0 or not (u1 = w1).
refutation
A proof that a set of assertions leads to False, so no interpretation satisfies them all.
soundness
The guarantee that the checker never accepts a false claim. This PR changes only tactic text, not what is proved, so soundness is unaffected.
tactic
A command inside a Lean by block that builds part of a proof, such as unfold or grind.
theory lemma
A clause that a theory solver, such as EUF or arrays, claims is always true. The Lean file must prove each one.
uninterpreted function
A function symbol, like f or p above, with no fixed meaning. The only thing known about it is congruence.
unfold
The Lean tactic that replaces a defined name with its body, so a prover can see inside it.
