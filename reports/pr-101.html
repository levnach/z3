State Lean scaling facts and scaled ite gates over folded definitions

Pull request levnach/z3#101 · state OPEN · opened 2026-11-09T14:39:32Z · loop iteration 101

This pull request is open and not merged. The change under review is commit 6b725f36d on top of base 56ceebdc8. It contains three commits.

In one paragraph

This PR shortens two kinds of helper facts in the Lean proof of each theory lemma in linear arithmetic: scaling facts about atoms with fractions, and scaled gates about if-then-else terms. They used to write every nested ite out in full. Now they refer to short named definitions, and each proof unfolds only what it needs. For a deeply nested input, the Lean file shrinks from 44 MB to under 1 MB. Lean could not check the old file, and it now accepts the refutation. Every helper is still proved by Lean, so nothing new is trusted.

Background

Earlier iterations 99 and 100 already folded the integral gates and the uninterpreted function argument equalities. Gates with fractions, and all scaling facts, stayed written out. So QF_LRA inputs with deeply nested ite terms and rational constants gave huge Lean files, and the largest ran out of memory. This PR serves milestone 3 of the plan, "Equality and linear arithmetic", which asks for each fragment to be certified end to end.

What changed

  • Reconstructor: deeply nested Real ite chains without arrays can now be certified, because their helpers name term_N definitions instead of repeating them.
  • Reconstructor: each helper's proof now hides the nested ites from the grind tactic, so it no longer splits on them.
  • Reconstructor: in QF_LIRA, an Int term inside a Real fact now appears as a cast of its short name.
  • Tests: anyone can now generate Real chains of any even depth and check the folded shape in QF_LRA and QF_LIRA.
  • Docs: the proof plan and README now describe the folded helpers.

An analogy: the old helpers wrote a friend's full street address every time. The new ones use the friend's name and look up the address only when needed. Certificates with arrays keep the old form. There is no C++ change.

Worked example

The input comes from the PR's new generator, real_modular_chains_instance(8). It has 17 lines because depth 8 is what the old pipeline could not handle. Chain a adds 5/2 eight times, chain b adds 5 four times, and each step wraps at 17/2. Both end at the same value, so asserting that they differ is unsatisfiable.

Review

The reviewer approved, with no blocker and no major issue. To test soundness, they strengthened one scaling fact and one gate, and Lean rejected both.

SeverityFindingResolution
minorNo test covered the folded Int-to-Rat cast in QF_LIRA.Fixed
nitThe chain generator is unsat only for even depth.Fixed in docstring
nitThe shape test demanded more than 50 facts, a count that depends on Z3.Fixed
nitSmall inputs grow slightly.Accepted

The untested cast. In QF_LIRA, an Int term inside a Real fact must be cast to Rat. The reviewer saw that no test used this path, so a later edit could drop the cast unnoticed. Their hand-written probe verified, and the integrator turned it into a shape test and a Lean test.

The odd-depth trap. With an odd depth the two chains end at different values, so the input is satisfiable. The generator's docstring now says depth must be even.

The brittle count. The shape test demanded more than 50 facts, a number set by Z3, not by the converter. It now asks for at least one of each, and a 1.5 MB size bound checks what folding buys.

Small files grow. Each fact now carries its own unfold list, so tiny files grow by a few hundred bytes. Correctness is unaffected, so this was accepted.

Risks and open questions

  • The trust boundary is unchanged. Each fact is the same proposition as before, and Lean checks its proof. There is no sorry and no new axiom.
  • Grind now sees atoms folded, so a fact that needed an atom's definition would fail. The authors argue this cannot happen, and the suite passes.
  • CI and local gate results were unknown when this page was written.

What comes next

  • The QF_UFLRA chain at depth 8 still fails. An older argument-equality helper unfolds both arguments fully, and grind runs out of heartbeats.
  • Other helpers still write terms out, including cast facts and every helper in certificates with arrays.

Glossary

atom
A smallest true-or-false statement, such as x < 17/2. It has no Boolean connectives inside.
axiom
A statement Lean accepts without proof. Adding one would widen what must be trusted.
cast
Converting a value from one sort to another, for example an Int 3 to the rational 3.
clause
A disjunction of literals, read as "at least one of these holds", such as (x < 1) or (y = 2).
definition
A named abbreviation for a term or formula, such as term_13. It can be unfolded back to its body.
grind
A Lean tactic that combines case splits, equality reasoning, and linear arithmetic to close a goal.
heartbeat
Lean's unit of work. A tactic that uses more than its heartbeat budget fails.
if-then-else term (ite)
A term that picks one of two values by a condition. (ite (< s 5) s 0) is s when s < 5, else 0.
linear arithmetic
Arithmetic with addition and multiplication by constants only, such as 2x + 3y ≤ 7.
logic (QF_LRA, QF_LIRA, QF_UFLRA)
An SMT-LIB name for a class of problems. QF means quantifier-free. LRA is linear Real arithmetic. LIRA mixes Int and Real. UF adds uninterpreted functions.
rational number
A fraction of two integers, such as 17/2. Lean's Rat sort represents Real values in these certificates.
refutation
A proof that a set of assertions leads to a contradiction, that is, to False.
scaled gate
A project helper fact: under the condition of an ite, a multiple of the ite equals the same multiple of its branch, chosen so no fractions remain. A gate is integral when no scaling is needed.
scaling fact
A project helper fact: an atom with fractions, multiplied through so all coefficients are integers. x ≥ 7/2 becomes -2x + 7 ≤ 0.
sort
The type of a value, such as Int, Real, or Bool.
sorry
A Lean placeholder that skips a proof. A trusted certificate must contain none.
tactic
A Lean command that builds part of a proof, such as unfold, rw, or grind.
theory lemma
A clause that holds by the rules of a theory, such as arithmetic, and that the solver adds during its search.
uninterpreted function
A function symbol with no fixed meaning. The only rule is that equal arguments give equal results.
unfold
Replacing a defined name by its body, like expanding term_13 into its ite.
