Certify arrays over Int and Real (QF_ALIA, QF_AUFLIA) via clause log

Pull request levnach/z3#69 · state OPEN · 2026-11-04T04:47:21Z · loop iteration 69

This pull request is open and not merged. The change is commit d07708a7c. The pull request holds two commits on top of its base c4fc7ed36.

In one paragraph

Before this pull request, the clause log path could certify arrays only when both the index sort and the element sort were uninterpreted sorts. Now the index and element sorts may also be Int or Real, as in (Array Int Int). A select from such an array becomes one more atom of linear arithmetic, so a Farkas lemma can reason about reads directly. Uninterpreted functions and predicates may also take arrays as arguments, through an injection into the carrier. Every array fact used in the generated Lean file is a proved theorem, with no sorry and no new axiom. As a result, 8 of the 13 z3test QF_AUFLIA benchmarks with arrays now have a refutation that Lean checks. Before, none did.

Background

Iteration 68 (#68) added arrays over uninterpreted sorts, the logic QF_AX. The exporter still rejected any array with an Int or Real component, and any function with an array argument. So the common benchmark families storecomm, storeinv, and swap over (Array Int Int) could not be certified. Ten of them also use a Skolem function sk that takes two arrays. This work belongs to milestone 4 of the project plan, "Broader theories and integration", which lists arrays as one extension. It builds on the uninterpreted function and arithmetic slices from milestone 3.

What changed

  • Exporter. You can now export a certificate for an input whose arrays have Int or Real indices or elements.
  • Clause-log replay. A read such as (select b j) can now appear inside a native Farkas check, because it counts as a linear atom.
  • Reconstructor, array types. Each Lean array type, such as Int -> Int or Rat -> Rat, now gets its own family of array constants, and the array theorems work for any index and element type.
  • Reconstructor, functions over arrays. A function or predicate can now take an array argument, much like a coat check: the array is handed in and the function only ever sees its ticket, a point of the carrier.
  • Reconstructor, review fix. A theory lemma that is not a rewrite, such as a cnf step, can now use the store identities, so predicates over overwritten arrays check in Lean.
  • Tests and docs. Eleven new inputs over Int and Real arrays are checked in Lean, and the README states a corrected soundness argument.

Worked example

This input is the PR's new test int_read_other_index. Array b is a with the value 5 written at index i. At a different index j, b must read the same as a, so b[j] > a[j] + 2 is impossible.

(declare-fun a () (Array Int Int))
(declare-fun b () (Array Int Int))
(declare-fun i () Int)
(declare-fun j () Int)
(assert (= b (store a i 5)))
(assert (> (select b j) (+ (select a j) 2)))
(assert (not (= i j)))

The main theorem: for every interpretation, the three assertions together imply False.

private theorem th_lemma_26 (_atoms : Nat -> Prop) (_vars : Nat -> Int) (_m : Interpretation)
    : (formula_25 _atoms _vars _m) := by
  unfold formula_25 formula_24 term_23 formula_12 term_8 term_6 term_2
  have _t4 : (term_4 _atoms _vars _m) = (_store ((term_1 _atoms _vars _m)) (_vars 0) (((5 : Int)))) := rfl
  have _s23 := _store_apply ((term_1 _atoms _vars _m)) (_vars 0) (((5 : Int))) (_vars 1)
  first | omega | grind (splits := 64)

This array lemma says i = j or the read of the store at j equals a[j]. It is proved by instantiating _store_apply.

Review

The reviewer approved the change. There were no blocker or major findings, two minor findings, and no nits.

SeverityFindingResolution
minorPredicates over arrays failed in Leanfixed, 3 tests added
minorThe soundness note for the array injections was falsefixed in README, docstring, and plan

Predicates over arrays. The reviewer asserted (p c) and (not (p (store c n (select c n)))). Writing back the value already there leaves c unchanged, so this is unsat. Z3 proved it with a cnf step, but the reconstructor offered the store identities only to rewrite steps. The tactic grind could not find the identity alone, so Lean rejected the file. The fix offers the identity to any theory step whose stores match one syntactically. A first, broader version grew one QF_AX certificate from 4.9 to 8.6 MB, so the match was narrowed. This mattered because the PR claimed predicates over arrays work. Lean still rejected the bad files, so it was a completeness gap, not a soundness hole.

The injection argument. The README said a model can pick a carrier large enough to embed all its arrays. The reviewer pointed out that this is impossible for U -> U, by Cantor's theorem. The encoding is still sound for another reason. Only finitely many array values are named by the input's terms. So the carrier needs just one fresh point per named array. The docs now say this. It mattered because a reader auditing the trust argument would have found a false step.

Two suggestions were not adopted. A cosmetic duplicate in a header comment is left as a follow-up. A hand-edited Lean negative test was judged redundant, because Lean's type checker already separates Rat -> Rat from Int -> Int.

Risks and open questions

  • The trust boundary is unchanged. The injections carry no injectivity assumption, and lemmas use only their congruence.
  • Real arrays become Rat -> Rat. This relies on the fragment staying linear. Nonlinear multiplication is still rejected.
  • Four swap benchmarks reconstruct to 66 to 243 MB of Lean and were not checked. Their QF_AX versions are much smaller.
  • Exporting cvc/dlx-regfile.smt2 runs out of memory in the exporter.
  • The store-identity match compares shared term ids. An equal but unshared store would miss the alternative, and Lean would reject the file.
  • CI and the local gate have not reported yet.

What comes next

  • Profile what is duplicated in the very large swap certificates.
  • Still rejected: arrays over Boolean values, nested arrays, constant arrays, functions that return arrays, and arrays on the legacy core. The blocked z3test regressions are t8, 3006, segfault2, 2549, t168, and t170.

Glossary

array
A total map from an index sort to an element sort. (Array Int Int) maps every integer to an integer. In Lean it becomes a function Int -> Int.
atom
The smallest piece a reasoning step treats as one unit. For arithmetic, (select b j) can be an atom, just like a variable x.
axiom
A statement accepted without proof. Adding one would widen what the checker must trust.
Boolean
A value that is either true or false. Its sort is Bool in SMT-LIB.
carrier
The set of values that an uninterpreted sort ranges over in a model. Here it is the Lean type _m.U.
clause
A disjunction of literals, such as x ∨ ¬y. A literal is an atom or its negation.
clause log
The record of clauses Z3 learns or uses while solving, with a hint for why each one holds.
cnf step
A step that turns a formula into clauses, conjunctive normal form, without new theory reasoning.
completeness
Being able to certify every correct result. A completeness gap means some true results fail to check.
congruence
The rule that equal arguments give equal results: if a = b then f(a) = f(b).
exporter
The script that runs Z3 and writes its proof evidence as a certificate file.
extensionality
The rule that two arrays are equal when they agree at every index. If they differ, a witness index shows where.
Farkas lemma
A proof that some linear inequalities cannot all hold, given as a weighted sum that adds up to a false claim like 0 < 0.
injection
A map that sends different inputs to different outputs. Here, a map from arrays into the carrier, so functions can take arrays.
linear arithmetic
Arithmetic with sums and constant multiples only, such as 2x + y ≤ 3, but not x · y.
model
An assignment of values to all symbols that makes the assertions true. An unsat input has none.
predicate
An uninterpreted function whose result is Boolean, such as p : (Array Int Int) -> Bool.
refutation
A proof that the assertions together lead to False.
select and store
(select a i) reads array a at index i. (store a i v) is a new array equal to a except that index i holds v.
Skolem function
A function that names a value whose existence was claimed. In the swap benchmarks, sk names an index where two arrays differ.
sort
The type of a value in SMT-LIB, such as Int, Real, Bool, or an array sort.
soundness
Never certifying a false result. A soundness hole would be much worse than a completeness gap.
sorry
A Lean placeholder that skips a proof. A certificate containing it proves nothing.
tactic
A Lean command that builds part of a proof automatically. omega solves integer linear arithmetic, and grind combines equality and case splits.
theorem
A statement together with a proof that Lean has checked.
theory lemma
A clause that holds because of a theory, such as arithmetic or arrays, rather than by pure logic. Z3 marks it th-lemma.
trust boundary
The set of things one must believe without a Lean proof, such as the encoding of the input.
uninterpreted function
A function symbol with no fixed meaning. Only congruence is known about it. Example: (declare-fun f (Int) Int).
uninterpreted sort
A sort with no fixed values, declared with declare-sort. Only equality between its values is known.
