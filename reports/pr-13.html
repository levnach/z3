Certify QF_UFLIA refutations in Lean through the clause log

Pull request #13 Merge commit 8d6aa542 Merged 2026-10-15T23:44:53Z Loop iteration 13

In one paragraph

This PR adds a sixth certified fragment, QF_UFLIA. That is linear integer arithmetic mixed with uninterpreted sorts and uninterpreted functions. Before, the exporter rejected every input that placed an Int-valued uninterpreted function next to integer literals. Now such an input is exported through the clause log, turned into a Lean file, and checked by the Lean kernel. Each integer theory lemma is proved by the tactic omega, with grind as the fallback. The stress runs also found a gap unrelated to integers. An if-then-else term whose two branches are the same term produced gate clauses that the reconstructor rejected. Those are now proved by a case split on the condition. Nothing new is trusted. Every lemma is still checked under Lean's three standard axioms.

Background

Before this PR the pipeline certified five fragments, from pure Boolean reasoning up to QF_LIA. Int next to an uninterpreted symbol was the one combination of already certified pieces still rejected at the exporter. A probe of the clause log showed that Z3 emits no new hint kind for this fragment. An application with an Int result is just an opaque integer atom inside the Farkas, bound, implied equality, and cut hints, and congruence steps arrive as before. The work serves milestone 3 of the plan, equality and linear arithmetic, which asks that each fragment be completed end to end before the next one is added.

What changed

  • Exporter. An input with Int arithmetic next to uninterpreted sorts or functions is now classified as qf_uflia and exported through the clause log instead of being rejected. Mixing Int with Real is still rejected.
  • Reconstructor. The Lean file for this fragment binds integer variables, an injection from Int into the carrier type, and a family of Int-valued functions, then proves every theory lemma with omega first and grind second.
  • Same-branch if-then-else. A gate clause for (ite c a a) in either orientation, and the bare unit clause saying it equals a, are now proved by splitting on c. Think of a fork where both roads lead to the same town: whichever way you go, you arrive at a.
  • Validation. A certificate with the wrong fragment label is rejected with a message naming the allowed fragments. The legacy proof object still rejects both integer fragments.
  • Tests and documentation. A new test module holds twelve documented inputs and a random generator in three shapes. Four sibling modules and three documents were updated.

Worked example

The input below is one of the twelve documented inputs of the new test module, with unused declarations removed. Two elements of an uninterpreted sort are equal, yet an Int-valued function maps them to values more than one apart. The refutation needs one congruence step and one Farkas step.

(a) The input

(set-logic QF_UFLIA)
(declare-sort U 0)
(declare-fun g (U) Int)
(declare-const a U)
(declare-const b U)
(assert (= a b))
(assert (> (g a) (+ (g b) 1)))
(check-sat)

Review

The reviewer approved the change with no blocker, major, or minor findings, only three nits. All three were fixed in a follow-up commit before the merge.

  • Nit: dead code. A scan of the three gate functions found one local variable that was assigned and never read, left behind when the unit-clause case moved into its own function. It mattered only for clarity. The variable was removed.
  • Nit: a docstring promised too much. Two test classes claimed their checks "run on every runner". The reviewer read the CI workflow and saw that these classes run only in the Lean job. A reader could have assumed Windows or manylinux coverage that does not exist. The docstrings now say the checks need neither the z3 executable nor Lean.
  • Nit: a documentation claim went beyond the evidence. The README said the same-branch fix applies "in every fragment". The reviewer tried Real and uninterpreted-sort inputs and found that Z3 simplified the if-then-else away, so no gate clause was logged there. The text now says the lemma is fragment-independent while the Z3-logged evidence is Int-only.

The reviewer also confirmed the trust boundary directly: one arithmetic sort per certificate, the original input bound by its terms and signatures, and no sorry or new axiom. Tampered gate clauses with distinct branches were rejected before Lean ran.

Risks and open questions

  • Soundness is unchanged. Int atoms under applications go through the same tightening, rounding, and Farkas re-derivation as Int variables. Cut steps are shape-checked and then proved by Lean alone, and a new test shows Lean rejecting false ones over an application.
  • The injection is never assumed one-to-one. No injectivity axiom was added for _int, so the encoding proves nothing it should not.
  • Behaviour changes only for inputs that were rejected before. QF_UFLIA is opt-in through the Python API, so z3test's harness still reports it as unsupported until it opts in.
  • The same-branch evidence from Z3 is Int-only. Over Real and uninterpreted sorts Z3 simplified the term away in every input tried. Whether it ever logs such a clause there is unknown.
  • Random instances are often trivial. Many are refuted by a single numeral comparison such as (= 2 -1), so the pinned seeds were filtered for larger conflicts.

What comes next

  • QF_LIRA, meaning Int mixed with Real, stays rejected and is the obvious next fragment.
  • The legacy proof object still rejects both integer fragments.
  • No QF_UFLIA matrix cell exists in z3test yet. The twelve documented inputs are the candidates.
  • The random generator could avoid trivial numeral atoms.

Glossary

application
A function symbol applied to arguments, such as (g a).
axiom
A statement accepted without proof. Lean's three standard axioms are propositional extensionality, choice, and quotient soundness, and every generated proof is checked to use no others.
Boolean
The sort of truth values, true and false.
bound
A hint that an inequality over integers was tightened or rounded, for example turning x < 3 into x <= 2.
case split
A proof that handles a statement separately for the case where a condition holds and for the case where it does not.
certificate
The exported JSON record of a refutation, together with the declarations and original input it depends on.
clause
A disjunction of literals, such as "not (a = b) or g a = g b".
clause log
The stream of clauses, each tagged with a hint, that Z3's SAT-based SMT core writes while solving. One of the two proof cores the exporter can read.
congruence
The rule that equal arguments give equal results: if a = b then g a = g b.
cut
An integer reasoning step that derives a new inequality not implied over the reals, using the fact that the variables are whole numbers.
Farkas lemma
The rule that a non-negative weighted sum of true linear inequalities is also true. Z3 reports the weights as a farkas hint.
fragment
A restricted class of inputs, defined by which sorts and operators may appear, that the pipeline handles with one fixed encoding.
gate clause
A clause that defines a compound term by its parts, such as "not c or (ite c a b) = a". Z3 logs these under the name def-axiom.
hint
The short tag on a logged clause, such as farkas or euf, that says which kind of reasoning produced it.
if-then-else term
A term written (ite c a b) in SMT-LIB that equals a when c holds and b otherwise.
implied equality
A hint that two bounds, such as x <= y and x >= y, together force an equality x = y.
injection
Here, the map that places integer values inside the carrier type so that a function over an uninterpreted sort can take an Int argument. The Lean binder is _int.
kernel
The small trusted core of Lean that re-checks every proof term. A tactic only helps produce the term. The kernel decides whether it is valid.
legacy proof object
Z3's older tree-shaped proof format. It is the other proof core the exporter can read, and it does not yet cover integer steps.
linear integer arithmetic
Reasoning about Int variables with addition, multiplication by constants, and comparisons. SMT-LIB calls the pure form QF_LIA.
literal
An atomic statement or its negation, such as x < 3 or not (a = b).
QF_UFLIA
The SMT-LIB logic of quantifier-free formulas over uninterpreted functions and linear integer arithmetic.
refutation
A proof that a set of assertions leads to a contradiction, ending in the empty clause or False.
sort
The type of a value, such as Int, Real, Bool, or a user-declared sort U.
tactic
A Lean program that searches for a proof of a goal. omega handles linear integer arithmetic and grind handles equalities and congruence.
theory lemma
A clause that is true by the rules of a theory alone, such as arithmetic or equality, independent of the input assertions.
uninterpreted function
A function symbol with a declared signature but no fixed meaning. Only congruence constrains it.
uninterpreted sort
A user-declared sort with no fixed set of values, such as (declare-sort U 0).
unit clause
A clause with exactly one literal, such as (ite c a a) = a on its own.
