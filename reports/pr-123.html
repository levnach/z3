Certify the default-map axiom at an index no store writes

Pull request #123 State: OPEN Date: 2026-11-12T00:07:21Z Loop iteration 122

This pull request is open. It is not merged. The change commit is 7dfcbb0ff, and the target branch is master.

In one paragraph

The pipeline can now certify a refutation that rests on the default-map axiom of the array theory solver. This works when no assertion of the input names a default value. Z3 uses this axiom to compare sets without naming a member. The reconstructor now reads every default value at one index that no store in the certificate writes. At that index the axiom holds by definitional equality, so Lean takes nothing on trust. The final theorem keeps its statement and hypotheses, and no Lean axiom is added. In a sweep of random set problems, all 104 inputs rejected for this reason now pass the Lean check.

Background

Before this PR, the pipeline certified set refutations that read concrete members, including sets compared member by member since pull request #122. Every refutation that used the default-map axiom was rejected. The axiom could not be proved for the Lean definition in use then, because a map of two arrays need not have a default value in that sense. This was the only rejection left in the random set sweep. The work serves milestone 4 of the plan, "Broader theories and integration", for arrays.

What changed

An analogy helps. Picture an array as an endless row of lockers. A store repaints one locker. To learn the usual colour of the row, open one locker that nobody repainted.

  • Reconstructor, default values. When a refutation uses the default-map axiom and the input names no default value, every default value becomes a read at one generic index.
  • Reconstructor, a proved fresh index. The Lean file picks that index, named _generic_i, and proves that it differs from every stored index.
  • Reconstructor, the axiom as a fact. The axiom is stated in array theory lemmas, rewrite steps, and cnf lemmas, and Lean accepts it by definitional equality.
  • Exporter. A refutation that uses the axiom is now rejected only when an assertion names a default value.
  • Tests. Fifteen new inputs and four pinned random seeds are checked in Lean. A tampering test confirms that Lean rejects an index not proved fresh.
  • Documentation. The plan gains a dated section, and the README paragraph on maps is updated.

Worked example

The input is the PR's test store_under_union_default. All output comes from real runs.

(a) The input

(declare-fun a () (Array Int Bool))
(declare-fun b () (Array Int Bool))
(declare-fun i () Int)
(assert (= (union (store a i false) b) ((as const (Array Int Bool)) false)))
(assert (= a ((as const (Array Int Bool)) true)))
(check-sat)

A full set minus one member, joined with another set, is claimed to be empty. No member is named, so Z3 refutes this through default values.

Review

The verdict was APPROVE, with no blocker and no major finding. The reviewer tampered with a generated file in five ways, such as dropping a stored index from the list. Lean rejected every tampered file.

  • Minor, fixed. A test asserted, for twelve pinned seeds, whether the Lean file reads a generic index. That depends on the route Z3 takes to the refutation, measured only on macOS. On Linux another route for an older seed would verify in Lean, yet fail the test. The test now asserts this for the four new seeds only.
  • Nit, fixed. Two edited documentation paragraphs were too wide and were re-wrapped.
  • Nit, rejected with evidence. The reviewer tried an unrelated Real-indexed array next to sets over Int. The Lean file defined a Real generic index too, which the reviewer called unused. The integrator found four lemmas in that file that use it, so removing it would break them. The input is now the fifteenth Lean-checked test.

One suggestion led to a code comment on how the exporter's and reconstructor's tests for the axiom differ. A clearer error for refutations that only Lean turns down was not added, since no input needs it.

Risks and open questions

  • The tests expect Z3 to take the default-value route on the new inputs. That was measured on macOS only.
  • Soundness rests on Lean. The mode requires that no assertion mentions a default value, and the reconstructor checks this.
  • The exporter now accepts some refutations that a later stage could still turn down. Examples are a stored index that mentions a default value, or a lemma needing case facts of an enumeration. No tested input produced either.
  • The freshness proofs grow quadratically with the number of distinct stored indices. The reviewer measured 200 stores at 6.5 seconds and 3.0 GB.

What comes next

  • The axiom next to a default value that the input names stays rejected.
  • In the two failing seeds that were examined, a read through a store into a map lacks a read fact.
  • A map over a chain of two stores fails in a rewrite step.
  • Maps over arrays of an enumeration are still rejected by the exporter.
  • Linear-size freshness proofs and enumeration case facts are in the backlog.

Glossary

array
A value that maps every index to an element, like a function. Example: (Array Int Bool) maps integers to Booleans.
assertion
A formula the input states as true, written (assert ...) in SMT-LIB.
axiom
A statement accepted without proof. A Lean file that adds none relies only on Lean's standard ones.
Boolean
The sort with the two values true and false.
certificate
A file of evidence for a result that an independent checker can verify without trusting the solver.
choice
The Lean principle Classical.choose. It picks a witness from a proof that one exists.
cnf lemma
A proof step that turns a formula into clauses, each an "or" of simple facts.
constant array
An array with the same element at every index, written ((as const (Array Int Bool)) true).
default-map axiom
The array solver's rule that the default value of a map is the function applied to the arguments' default values. Example: the default of (union a b) is the default of a or the default of b.
default value
A single representative element of an array, written (default a). For a constant array it is the constant.
definitional equality
Two expressions that become identical once definitions are unfolded. Lean proves such an equality with rfl.
enumeration
A sort with a fixed finite list of named values, such as red, green, and blue.
exporter
The script that replays the solver's proof log and writes the certificate.
hypothesis
An assumption of a theorem. Here the hypotheses are exactly the input's assertions.
index
The position at which an array is read or written.
map
An array built by applying a function at every index of other arrays, written ((_ map f) a b).
reconstructor
The script that turns a certificate into a Lean file for Lean to check.
refutation
A proof that a set of assertions leads to a contradiction.
rewrite
A proof step that replaces a term with a simpler equal one.
seed
A number that fixes the output of a random generator. Each seed here names one random set problem.
select
A read of an array at an index, written (select a i).
set
An array with Boolean elements. An index is a member when its element is true. Union and intersection are maps of "or" and "and".
sort
The type of a value, such as Int, Real, or Bool.
soundness
The property that a checker accepts only correct proofs.
store
An array equal to another except at one index, written (store a i v).
tactic
A Lean command that searches for a proof automatically. The generated files use grind and omega.
theorem
A statement with a proof that Lean has checked.
theory lemma
A fact that a theory solver contributes to a proof, valid by the rules of its theory alone.
theory solver
The part of an SMT solver that reasons about one theory, such as arrays or arithmetic.
