Certify the default-map axiom at an index no store writes

Merged into master on 2026-11-12T00:22:46Z as merge commit 1bb828779.

In one paragraph

The pipeline now certifies a refutation that uses the default-map axiom of the array theory solver. This works when no assertion of the input names a default value. Z3 uses this axiom to compare sets without naming a member. The reconstructor now reads every default value at one index that no store in the certificate writes. There the axiom holds by definitional equality, so Lean proves it outright. The final theorem keeps its statement and hypotheses, and no Lean axiom is added. All 104 random set inputs that were rejected for this axiom now pass the Lean check.

Background

Before this PR, the pipeline certified set refutations that read concrete members. Every refutation that used the default-map axiom was rejected. The earlier Lean definition of a default value could not prove the axiom, because the arguments of a map need not have such a value. This was the only rejection left in the random set sweep. The work serves milestone 4 of the plan, "Broader theories and integration", for arrays.

What changed

An analogy helps. Picture an array as an endless row of lockers. A store repaints one locker. To learn the usual colour of the row, open one locker that nobody repainted.

  • Reconstructor. When a refutation uses the axiom, every default value becomes a read at one generic index.
  • Reconstructor. The Lean file picks that index, named _generic_i, and proves that it differs from every stored index.
  • Reconstructor. Array theory lemmas, rewrite steps, and cnf lemmas can now state the axiom, and Lean accepts it by definitional equality.
  • Exporter. A refutation that uses the axiom is now rejected only when an assertion names a default value.
  • Tests and documentation. Fifteen new inputs and four pinned random seeds are checked in Lean, and the plan gains a dated section.

Review

The verdict was APPROVE, with no blocker and no major finding. The reviewer tampered with a generated file in five ways, and Lean rejected each one.

  • Minor, fixed. A test asserted, for twelve pinned seeds, whether the Lean file reads a generic index. That depends on Z3's route to the refutation, measured only on macOS. A different route on Linux could verify in Lean yet fail the test. The test now asserts this for the four new seeds only.
  • Nit, fixed. Two edited documentation paragraphs were too wide and were re-wrapped.
  • Nit, rejected with evidence. The reviewer tried a Real-indexed array next to sets over Int, and called the extra Real generic index unused. The integrator found four lemmas that use it, so it stays. That input is now a Lean-checked test.

One suggestion led to a code comment on how the exporter and the reconstructor recognise the axiom. Another, a clearer error for refutations that only Lean turns down, was not done.

Risks and open questions

  • The tests expect Z3 to take the default-value route, which was measured on macOS only.
  • Soundness rests on Lean, and on the reconstructor's check that no assertion mentions a default value.
  • The exporter now accepts some refutations that a later stage could still turn down. No tested input produced one.
  • The freshness proofs grow quadratically with the number of distinct stored indices.

What comes next

Glossary

array
A value that maps every index to an element, like a function. Example: (Array Int Bool) maps integers to Booleans.
assertion
A formula the input states as true, written (assert ...) in SMT-LIB.
axiom
A statement accepted without proof. A Lean file that adds none relies only on Lean's standard ones.
Boolean
The sort with the two values true and false.
certificate
A file of evidence for a result that an independent checker can verify without trusting the solver.
clause
A disjunction of literals, such as "p or not q".
cnf lemma
A proof step that turns a formula into clauses.
constant array
An array with the same element at every index, written ((as const (Array Int Bool)) true).
default-map axiom
The array solver's rule that the default value of a map is the function applied to the arguments' default values. Example: the default value of (union a b) is the default value of a or that of b.
default value
A single representative element of an array, written (default a). For a constant array it is the constant.
definitional equality
Two expressions that become identical once definitions are unfolded. Lean proves such an equality with rfl.
enumeration
A sort with a fixed finite list of named values, such as red, green, and blue.
exporter
The script that replays the solver's proof log and writes the certificate.
hypothesis
An assumption of a theorem. Here the hypotheses are exactly the input's assertions.
index
The position at which an array is read or written.
literal
An atomic formula or its negation.
map
An array built by applying a function at every index of other arrays, written ((_ map f) a b).
reconstructor
The script that turns a certificate into a Lean file for Lean to check.
refutation
A proof that a set of assertions leads to a contradiction.
rewrite
A proof step that replaces a term with a simpler equal one.
seed
A number that fixes the output of a random generator. Each seed here names one random set problem.
set
An array with Boolean elements. An index is a member when its element is true. Union and intersection are maps of "or" and "and".
sort
The type of a value, such as Int, Real, or Bool.
soundness
The property that a checker accepts only correct proofs.
store
An array equal to another except at one index, written (store a i v).
tactic
A Lean command that searches for a proof automatically. The generated files use grind and omega.
theorem
A statement with a proof that Lean has checked.
theory lemma
A fact that a theory solver contributes to a proof, valid by the rules of its theory alone.
theory solver
The part of an SMT solver that reasons about one theory, such as arrays or arithmetic.
