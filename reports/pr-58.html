Certify abs over Real terms on both proof cores

Pull request levnach/z3#58 · loop iteration 58 · opened 2026-10-31T10:52:52Z

State: OPEN — this PR is not merged. The change is commit 03bf2598c, on top of base 8cd110b0a.

In one paragraph

This PR lets the pipeline certify inputs that use abs over terms of sort Real. SMT-LIB defines abs on Int only, but Z3 also accepts it over Real. Z3 gives it the same meaning, the if-then-else term (ite (>= t 0) t (- t)). Before, every such input was rejected. Now both proof cores export it, and the reconstructor states a Real abs as exactly that ite over rational numbers. The Lean kernel still checks every lemma of the refutation. No new axioms appear, and the trust boundary does not move. This matters because hand-written linear real arithmetic inputs often use abs for distances and error bounds.

Background

Before this PR, the pipeline already certified linear real arithmetic, with and without uninterpreted functions. It also handled abs over Int. A Real abs stopped the exporter with the message "unsupported arithmetic operator: abs over Real". The reconstructor would have refused it too, because it accepted the abs declaration only over Int. Without a logic, (abs 3) in a Real position became the coercion (to_real (abs 3)), which was rejected as well. A probe of 27 common hand-written constructs found that the other remaining gaps are mixed Int and Real, Int rem, and datatypes. The PR serves milestone 3 of the plan, "Equality and linear arithmetic".

What changed

  • Exporter: you can now export a certificate for a Real abs, while a nonlinear argument such as (abs (* x y)) is still rejected.
  • Coercions: an input with no logic can now use (abs 3) as a Real, and it is read exactly as QF_LRA reads it.
  • Clause-log replay: a logged (abs t) is now rebuilt as the same abs term that the input contains, for Int and Real.
  • Reconstructor: the Lean statement now contains a Real abs as the ite "if t ≥ 0 then t else −t" over Rat, while div and mod stay Int only.
  • Tests and docs: nine new inputs are checked in Lean on both cores, tampered declarations are shown to fail, and the README and plan describe the new case.

Review

The reviewer approved the change with no blockers and no major findings.

  • Minor, fixed in f3965a2f4. The reviewer traced how the replay rebuilds a logged (abs t). It used z3py's Abs, which builds (ite (> t 0) t (- t)). That is a different term from the logged abs, and it even uses > instead of >=. An untrimmed clause log that keeps the two abs case axioms would then be compared against the wrong term. Lean would still catch any error, so soundness was safe, but such inputs could fail for no good reason. The fix builds the real abs application. A new test replays random seed 59 without trimming, which keeps that lemma, and checks it in Lean.
  • Nit, fixed in 03bf2598c. A dictionary whose values were never read became the set _NUMERIC_KINDS, which says what is meant.
  • Nit, fixed in 03bf2598c. One README line of about 110 characters was rewrapped.

The reviewer also saw that running single test modules from the repository root can pick up stale copies of the tests. This is a local setup issue. The CI command is not affected.

Risks and open questions

  • The Lean statement now covers an operator that SMT-LIB does not define over Real. It uses Z3's meaning, t >= 0 ? t : -t. A consumer that wants strict SMT-LIB can reject a Real abs declaration in the certificate.
  • An untrimmed clause log of a Real input with no logic can contain (to_real <numeral>), which the replay rejects. This is older than the PR, and trimming normally hides it.
  • In seeds 0–149, plus 0–79 with functions, only two raw logs kept an abs lemma. So the untrimmed path is rare, and it is tested by one seed.

What comes next

The largest remaining gap is mixed Int and Real input, such as to_real of an Int variable. Lean's grind tactic does not reason through the cast from Int to Rat. So this needs explicit cast bridging. Int rem and datatypes are also still rejected. The Lean status of the large QF_IDL sample exports is still unmeasured.

Glossary

abs (absolute value)
The distance of a number from zero. (abs (- 2.5)) is 2.5. SMT-LIB defines it only for Int.
axiom
A statement accepted without proof. These Lean files use only Lean's three standard axioms, and the PR adds none.
clause log
A record of every clause a solver learns, with a hint for each.
clause
A disjunction ("or") of literals, such as (or p (not q)).
coercion
A conversion from one sort to another. (to_real n) turns the Int n into a Real.
declaration
The name, argument sorts, and result sort of a function symbol, such as abs : Real -> Real.
exporter
The step that turns a Z3 proof into a JSON certificate. Here it is proof_certificate.py.
fuzzing
Testing with many randomly generated inputs to find cases nobody thought of.
if-then-else term (ite)
A term that picks one of two values by a condition. (ite (>= t 0) t (- t)) is t when t ≥ 0, else −t.
kernel
The small core of Lean that checks every proof. Only the kernel has to be trusted.
lemma
A small proved statement used as a step toward a larger theorem.
linear real arithmetic (QF_LRA)
Constraints over Real variables using +, −, and multiplication by constants, like 2x + y < 3. QF_UFLRA adds uninterpreted functions.
literal
An atom or its negation, such as p or (not (< x 3)).
logic
The SMT-LIB fragment an input declares with set-logic, such as QF_LRA. It fixes which sorts and operators may appear.
mutation check
Putting a known bug back on purpose to confirm that the tests fail.
nonlinear term
A term that multiplies two variables, such as (* x y). The pipeline does not support these.
proof core
One of Z3's two proof sources: the legacy proof object or the clause log.
rational number (Rat)
A fraction of two integers, like 3/2. The Lean files use Lean's Rat for Real values.
reconstruction
Turning a certificate into a Lean file that proves the same result. Here it is proof_to_lean.py.
refutation
A proof that a set of assertions leads to False, so they cannot all hold.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that builds part of a proof automatically. grind is one.
trimming
Removing clauses from a clause log that the final refutation does not need.
trust boundary
The line between what must be trusted, here the Lean kernel and the statement of the input, and what is checked.
uninterpreted function
A function symbol with no fixed meaning, only that equal arguments give equal results. Example: (declare-fun f (Real) Real).
