In one paragraph

Z3 lets you apply abs to Real terms, although the SMT-LIB standard defines it only on Int. Before this PR, every input that used abs on a Real term was rejected, on both proof cores. Now the exporter accepts these inputs. The reconstructor states each Real abs as Z3's own if-then-else term over Rat: if t >= 0 then t, else -t. The Lean kernel still checks every lemma of the refutation. No new axioms are added, so the trust boundary stays where it was. Distances and error bounds such as (< (abs (- x y)) 1.0) can now get a Lean-checked unsat certificate.

Background

The pipeline already certified linear arithmetic over Real and over Int, with uninterpreted functions. It also accepted abs, but only on Int. A Real abs stopped the exporter with "unsupported arithmetic operator: abs over Real". Without a logic line, (abs 3) in a Real position is read as (to_real (abs 3)), and that was rejected as "to_real". A probe of 27 common hand-written constructs found this among the few remaining gaps. The others are mixed Int and Real, Int rem, and datatypes. This work serves Milestone 3, "Equality and linear arithmetic", which asks that each fragment be completed end to end.

What changed

  • You can now export a certificate for an input that applies abs to a Real term, on either proof core.
  • An abs nested inside a nonlinear term, such as (abs (* x y)), is still rejected, because the check continues below abs.
  • Without a logic line, (abs 3) in a Real position is now read the way QF_LRA reads it, as the Real abs of 3.0.
  • The generated Lean file states a Real abs as the if-then-else term over Rat, and a header comment says so.
  • When the clause log keeps an (abs t) term, the replay now rebuilds exactly that term instead of a different ite.
  • A tampered abs declaration is rejected. Examples are a wrong name, a wrong sort, or two arguments instead of one.

Think of the reconstructor as a translator with a fixed dictionary. This PR adds one word, abs over Real, and the dictionary entry says exactly what Z3 means by it.

Review

The reviewer approved, with no blockers and no major findings.

  • Minor: the replay rebuilt abs as a different term. The reviewer read the clause-log replay. When the log kept an (abs t) term, the replay built it with z3py's Abs. That function gives (ite (> t 0) t (- t)), with > instead of Z3's >=. So the replay compared Z3's hints against the wrong term. Random seed 59 produces such a log before trimming, and no test covered it. Soundness was never at risk, because Lean re-proves every lemma. Still, a valid input could have been rejected. The fix builds the real abs application. A new test replays seed 59 untrimmed and checks the theory lemma over abs in Lean.
  • Nit: a lookup table whose values were never read. It was turned into a plain set, _NUMERIC_KINDS.
  • Nit: one README line was about 110 characters long. It was rewrapped.

The reviewer also noticed that running single test modules from the repository root can pick up stale copies in build/python. This is a local setup issue, and the CI command is not affected.

Risks and open questions

  • The theorem now covers an operator outside SMT-LIB. It uses Z3's meaning, which the Lean definition matches. A consumer that wants strict SMT-LIB can reject Real abs declarations in the certificate.
  • An untrimmed clause log of a Real input without a logic line can contain (to_real <numeral>), which the replay rejects. This predates the PR and is normally hidden by trimming.
  • GitHub CI results after the merge are not known to this report.

What comes next

The biggest remaining gap is mixed Int and Real, the QF_LIRA logic. Lean's grind tactic does not reason through the cast from Int into Rat. So to_real of Int terms needs an explicit bridge. Int rem and datatypes are also still unsupported. Measuring the Lean status of large QF_IDL sample exports is on the backlog too.

Glossary

axiom
A statement accepted without proof. Here only Lean's standard axioms are allowed: propext, Classical.choice, and Quot.sound.
certificate
A file that records a proof so another program can check it. Here it is JSON written by the exporter.
clause log
One of the two proof cores: a log of the clauses the solver learned or used, replayed step by step.
clause
A disjunction of literals, such as x > 0 or y < 1.
declaration
An entry that names a symbol and gives its argument sorts and result sort, such as abs : Real -> Real.
exporter
The program that turns Z3's proof into a certificate. Here it is proof_certificate.py.
if-then-else term (ite)
A term that picks one of two values by a condition. (ite (>= t 0) t (- t)) is t when t >= 0, and -t otherwise.
Int
The sort of mathematical integers, such as -2, 0, and 7.
kernel
The small core of Lean that checks every proof step. It is the part that must be trusted.
lemma
A proved helper statement used by a larger proof.
linear arithmetic
Arithmetic where variables are only added or multiplied by constants. 2x + y < 3 is linear, x * y < 3 is nonlinear.
literal
An atomic formula or its negation, such as x > 3 or not (x > 3).
logic
An SMT-LIB name for an allowed fragment, set with set-logic. QF_LRA is linear Real arithmetic without quantifiers. QF_UFLRA adds uninterpreted functions. QF_LIRA mixes Int and Real.
proof core
The part of Z3 that records proof evidence. This project uses two: the clause log of the newer SAT-based core, and the legacy proof object.
Rat
Lean's type of rational numbers, the fractions. The certificates encode Real variables as Rat, which is enough for linear problems.
Real
The SMT-LIB sort of real numbers, such as 1.0 or 2.5.
reconstructor
The program that turns a certificate into a Lean file and checks it. Here it is proof_to_lean.py.
refutation
A proof that a set of assertions leads to False, so they cannot all hold together.
SMT-LIB
The standard input language and theory definitions shared by SMT solvers.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that builds part of a proof automatically. grind is one such tactic.
theory lemma
A clause that holds because of a theory such as arithmetic, not because of Boolean logic alone. Z3 logs these as th-lemma.
trimming
Removing the steps of a clause log that the final refutation does not need.
trust boundary
The line between the parts you must trust, such as the Lean kernel and the theorem statement, and the parts that are checked.
uninterpreted function
A function symbol with no fixed meaning. The only rule is that equal arguments give equal results, as in f(x).
