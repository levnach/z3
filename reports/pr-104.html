In one paragraph

The Lean reconstructor now gives a floor atom the key of its argument's normal form. Before, the floor of a deep chain of nested if-then-else terms and the floor of the rewriter's copy of that chain looked unrelated. Lean then had to unfold both chains inside one lemma, and it ran out of heartbeats. Now the two floors get their own equality, proved by congruence from the equality of the chains. A second commit caches and interns the keys, so keying takes linear time instead of exponential time. So a QF_UFLIRA refutation (see logic) over an uninterpreted function of such floors now checks in Lean.

Background

PR #102 taught the reconstructor to prove equalities of nested if-then-else terms one level at a time. But a floor, written to_int, was still keyed by its node alone. So when the rewriter rebuilt a floored Real chain in a clause log certificate, nothing related the two floors. At depth 8 the Lean check failed, and at depth 6 it needed 47 seconds and 3.7 GB. This PR serves milestone 3 of the plan, "Equality and linear arithmetic".

What changed

  • Reconstructor: floors of two terms with one normal form now share a key, so they are recognized as equal.
  • Reconstructor: Lean proves each such floor equality with only the two floors unfolded.
  • Reconstructor: keys are cached and interned, so keying a depth-16 chain takes under a second.
  • Tests: new tests cover the floor equalities, keying speed, and the depth-8 chain in Lean on both proof cores.
  • Docs: the plan and the README describe the new keying.

Think of a library that files books by content, so two copies share one catalog number. Before, a floor was filed by its copy, so the rewriter's copy got a new number. Interning is like a coat check: you carry a small ticket instead of the coat.

The slow keys. The reviewer timed the reconstructor on deep floor chains. Keying a floor now recomputed each level of the chain three times. A depth-12 chain went from 0.2 seconds to over two minutes. That mattered because callers without a time limit could hang where they used to fail fast. Caching brought depth 12 to about 4 seconds, and interning the nested keys removed the rest. This also fixed an older exponential case for if-then-else arguments.

The two nits. Two over-long lines were rewrapped, and a docstring now mentions floors.

Risks and open questions

  • The trust boundary is unchanged. Every new fact is a have that Lean must prove. A wrong key could only produce a fact that Lean rejects.
  • Interned keys compare by identity, which is only correct inside one proof graph. They never cross graphs.
  • New bridge facts between floors unfold both chains, so a very deep chain could run out of heartbeats. The reviewer found no such input.
  • Integer division, modulo, and integrality tests are still keyed by node, so the same gap may exist there.
  • The depth-12 floor chain was not checked in Lean.
  • The new Lean subtests add about 30 seconds to one CI job.

What comes next

  • Prove the bridge facts level by level, like the equalities.
  • Key integer division, modulo, and integrality tests by their arguments too.
  • Check the depth-12 floor chain in Lean.
  • Confirm that GitHub CI passes on the merge commit.

Glossary

atom
A term that linear arithmetic treats as a single unknown, such as (to_int a8).
cache
A stored table of answers already computed, so the same question is not worked out twice. Also called memoization.
certificate
A file of proof evidence exported from the solver, which a separate checker can replay.
clause log
A record of the clauses the solver learned and the theory steps behind them, which the exporter turns into a certificate.
congruence
The rule that equal inputs give equal outputs: if s = t then g(s) = g(t) for any function g.
exponential time
Work that multiplies with each extra step of input size, such as 3, 9, 27, 81 calls for depths 1 to 4.
floor
The largest integer not above a real number. In SMT-LIB it is written to_int. In Lean it is Rat.floor. Example: the floor of 7/2 is 3.
heartbeat
Lean's unit of work for a proof step. A step that uses more than its heartbeat budget fails.
if-then-else term
A term (ite c s t) whose value is s when the condition c holds and t otherwise.
interning
Keeping one shared copy of each distinct value, so two equal values are the same object and compare instantly.
key
A label the reconstructor computes for a term, so that terms with the same label are known to denote the same value.
lemma
A proved helper statement that a larger proof uses as one step.
linear arithmetic
Arithmetic with sums of variables times constants, such as 2x + 3y <= 5, but no products of variables.
linear time
Work that grows in proportion to input size: twice the depth, about twice the time.
logic (SMT-LIB)
A named fragment of SMT-LIB. QF_UFLIRA means no quantifiers, uninterpreted functions, and linear arithmetic over Ints and Reals together.
normal form
A standard way of writing a term, so that terms with the same meaning tend to be written the same way.
proof core
Where the exporter takes its evidence from: the clause log, or the older legacy proof object.
refutation
A proof that a set of assertions leads to a contradiction, that is, to False.
rewriter
The solver component that simplifies terms into a normal form before and during solving. Each rewrite is a proof step.
tactic
A Lean command that builds part of a proof automatically. The tactic grind, for example, combines case splits, congruence, and arithmetic.
uninterpreted function
A function symbol, such as f, with no fixed meaning. The only thing known about it is congruence.
unfold
Replace a named definition by its body, so a tactic can see what the name stands for.
