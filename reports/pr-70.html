Certify constant arrays over Int indices in Lean via the clause log

This pull request is open and not merged. The change it proposes ends at commit 1f463436a. The PR has two commits: the feature and a round of review fixes.

In one paragraph

This PR lets the pipeline certify inputs that contain a constant array whose index sort is Int. Before, the exporter rejected every such input. Now the clause log replay reads constant arrays and their default values. The reconstructor turns the array solver's axioms about them into theorems that Lean proves in each generated file. The element sort may be Int, Real, or an uninterpreted sort. Two z3test regressions that failed before now pass the Lean check: 2549.smt2 and all six queries of array.smt2. The change adds no Lean axiom and no sorry, so the trust boundary does not move.

Background

The two previous iterations certified arrays over uninterpreted sorts (PR #68) and over Int and Real (PR #69). Those PRs covered select and store. Every other array operator was still rejected. So any input with ((as const (Array Int Int)) 0) stopped at the exporter with "unsupported array operator: const". This work serves milestone 4 of the plan, "Broader theories and integration", which names arrays as one of the extensions.

What changed

A helpful picture: think of an array as a canvas with a background color. A constant array is a canvas painted in one color. Each store paints one pixel. The default value is the background color, and painting a few pixels never changes it. Z3 uses exactly this idea to tell arrays apart.

  • Exporter. You can now export an unsat input with a constant array over Int indices. Other index sorts get the clear message "constant arrays are supported over Int indices only".
  • Replay. The replay can now read as const terms and default terms, and it recognizes the three array axioms about them in the clause log. Each such hint is a one-literal clause that states the equality.
  • Lean encoding. A generated file now defines a constant array as a constant function and proves the two default-value axioms, starting from the fact that no finite list contains every Int.
  • Rewriter steps. When Z3's rewriter decides an equality between stores over constant arrays, the lemma for that step now receives the default and read facts it needs, plus congruence facts for equal arrays.
  • Tests and docs. Six new inputs are checked in Lean, including a read under a Farkas lemma, and new tests show that tampered certificates are rejected and that the new facts are really needed.

Why only Int? Over a finite index sort you could paint every pixel. Then no background would remain, and the default-value axioms would be false. An uninterpreted sort might be finite, so it stays rejected. Real is infinite, but the matching Lean lemma over rationals is not written yet.

Worked example

This is z3test regressions/smt2/2549.smt2, one of the PR's new test inputs. I ran it through the old and new scripts for this report.

(a) The input

(declare-const A0 (Array Int Int))
(declare-const A1 (Array Int Int))
(assert (= A0 ((as const (Array Int Int)) 0)))
(assert (= A1 ((as const (Array Int Int)) 1)))
(assert (= (store A0 2 3) (store A1 2 3)))

A0 is all zeros and A1 is all ones. Writing 3 at index 2 into both cannot make them equal.

Review

The reviewer approved the PR. They found no blockers, no major issues, and no minor issues. They found four nits, and all four were fixed in the second commit.

SeverityCount
Blocker / Major / Minor0
Nit4, all fixed
  1. A wrong reason in the docs. The reviewer read the README and the plan. Both said Real indices were rejected because the index sort might be finite. But Real is infinite. A future reader might think Real indices are unsound, when they are only unimplemented. The docs and comments now give the true reason: a missing unboundedness lemma over rationals.
  2. Coverage understated. The plan said only queries 0 to 2 of array.smt2 pass in Lean. The reviewer checked all six, and all six passed. The plan now says so, which saves a later iteration from re-checking.
  3. A missing targeted test. The reviewer asked: what if the read facts for rewrite steps silently disappeared? Only an indirect test would notice. The new test test_comparison_reads_are_needed strips those facts and requires Lean to fail.
  4. Slow counting. A list lookup inside a sum made the count of read facts quadratic in the number of arrays. The count now sums over the two lists separately. The result is the same, and the cost is linear.

The reviewer also checked the trust boundary on their own. They changed one default fact by hand, and Lean rejected the file.

Risks and open questions

  • The facts for rewriter steps come from a shape-driven heuristic, capped at 64 reads per step. A step that needs more fails in Lean openly. It is never accepted unsoundly.
  • Lemmas that reach a default value now carry a few more have lines, so files grow a little.
  • Default facts reach rewriter steps only. Whether other step kinds will need them is open.
  • CI results are unknown at the time of writing.

Glossary

array
An SMT-LIB value that maps indices to elements, like a function. (Array Int Real) maps Int indices to Real elements.
axiom
A statement accepted without proof. Z3's array solver applies array axioms as rules. In Lean, an axiom is an unproved assumption, and this project adds none.
clause
A disjunction of literals, read as "at least one of these holds".
clause log
The record of clauses Z3's SAT-based solver learns or adds, each with a hint saying why it holds.
congruence
The rule that equal inputs give equal outputs. If a = b, then (select a i) = (select b i).
constant array
An array with the same element at every index. SMT-LIB writes it ((as const (Array Int Int)) 0).
default value
The value an array takes at all but finitely many indices. A constant array of 0 has default 0.
element sort
The sort of the values stored in an array. In (Array Int Real) it is Real.
exporter
The step that runs Z3 and writes its proof evidence into a certificate file.
Farkas lemma
A proof that some linear inequalities have no solution, given as weights that add them up to a false statement such as 0 < 0.
index sort
The sort of the positions of an array. In (Array Int Real) it is Int.
lemma
A small proved fact used on the way to a bigger theorem.
literal
An atomic formula or its negation, such as x = y or not (x = y).
reconstructor
The step that turns a certificate into a Lean file for Lean to check.
refutation
A proof that a set of assertions leads to False.
replay
The step that re-reads a clause log and rebuilds each clause as a formula over the input's terms.
rewriter
The part of Z3 that simplifies terms before solving, for example replacing an equality it can decide by false.
select
Reading an array: (select a i) is the element of a at index i.
sorry
A Lean placeholder that skips a proof. A file containing it proves nothing.
sort
The type of a value, such as Int, Real, or Bool.
store
Writing an array: (store a i v) is a with index i changed to v.
tactic
A Lean command that builds part of a proof automatically. omega and grind are tactics.
theorem
A statement together with a proof that Lean has checked.
trust boundary
The list of things one must believe without checking, such as Lean's kernel and its standard axioms.
uninterpreted sort
A sort declared with only a name, like (declare-sort Element 0). It may have any number of values, even only one.
