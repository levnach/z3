Certify constant arrays over Int indices in Lean via the clause log

Pull request levnach/z3#70 · loop iteration 70

State: MERGED on 2026-11-04T07:26:30Z into master. Merge commit: 17223c30f.

In one paragraph

This PR lets the pipeline certify inputs that contain constant arrays whose index sort is Int. The element sort may be Int, Real, or an uninterpreted sort. Z3's array solver reasons about these arrays through default values. It records three array axioms as hints in the clause log. The exporter, the replay, and the Lean reconstructor now all understand these axioms. In Lean, each axiom becomes a theorem that is proved in every generated file. So nothing new is assumed, and the trust boundary stays the same. As a result, the z3test regression 2549.smt2 and all six queries of array.smt2 now end in a refutation that Lean accepts.

Background

The two previous PRs taught the pipeline about arrays. PR #68 covered arrays over uninterpreted sorts. PR #69 covered arrays over Int and Real. Both handled select and store. A constant array, written ((as const (Array Int Int)) 0), was still refused with "unsupported array operator: const". This work belongs to milestone 4 of the project plan, "Broader theories and integration", which lists arrays as one of the theories to add.

What changed

  • You can now export an unsat input that uses a constant array over Int indices. Other index sorts get a clear rejection.
  • The clause-log replay can now read as const terms and default terms, and it accepts the three new array axioms.
  • Lean now has a constant array, the constant function _const_array, and a proved notion of default value, _default.
  • When Z3's rewriter decides an equality between stores over constant arrays, the Lean lemma for that step now gets default facts, read facts, and congruence implications.
  • Six new test inputs are Lean-checked, and new tests show that tampered certificates fail and that the new facts are really needed.

Think of a default value as the background color of a canvas. A constant array is a canvas painted one color everywhere. A store paints one pixel, and the background color stays the same. That is the axiom (default (store a i v)) = (default a). It only works when the canvas has infinitely many pixels. Over a finite index sort, enough stores could repaint the whole canvas. That is why uninterpreted index sorts, which may be finite, are rejected. Real indices are infinite, but they are not implemented yet.

Worked example

The input is z3test regressions/smt2/2549.smt2, which is also the test input z3test_2549. Two different constant arrays receive the same store, and the input claims the results are equal.

(declare-const A1 (Array Int Int))
(assert (= A0 ((as const (Array Int Int)) 0)))

(assert (= (store A0 2 3) (store A1 2 3)))

Review

The reviewer approved the PR. There were no blockers, majors, or minors. There were four nits, all fixed in commit 1f463436a.

  • Nit: a wrong reason in the docs. The reviewer read the README and the plan. They said Real indices are rejected because of finiteness, but Real is infinite. A later contributor could wrongly think Real-indexed constant arrays are unsound. The docs and comments now say Real indices are simply not implemented yet.
  • Nit: coverage understated. The plan said only array.smt2 queries 0 to 2 verify. The reviewer exported all six queries and all six passed Lean. The plan now says so, which saves a later iteration from rechecking them.
  • Nit: a missing negative test. No test proved that the comparison read facts are needed. A future bug could silently drop them. The new test_comparison_reads_are_needed removes them and requires Lean to fail.
  • Nit: a slow count. A list membership test inside a sum made one count quadratic in the number of arrays. The count now sums over the two lists separately, with the same result.

The reviewer also changed a default fact from 1 to 0 by hand. Lean rejected it, which shows the check is not vacuous.

Risks and open questions

  • The rewrite-step facts come from a heuristic based on the shape of terms. It is capped at 64 read facts per step. A step that needs more fails in Lean openly. It is never accepted unsoundly.
  • Lemmas that reach a default term now carry a few extra have lines.
  • GitHub CI results for this change are not part of the inputs, so they are unknown here.

What comes next

The PR lists these follow-ups in the backlog.

  • Constant arrays over Real indices. These need an unboundedness lemma over Rat.
  • Constant arrays over uninterpreted index sorts. Z3 uses extra witness symbols there, which the replay rejects.
  • Comparison facts for steps other than rewrites.
  • The map and as-array operators, Bool elements, and nested arrays.

Glossary

array
A map from indices to elements, like a function. (Array Int Real) maps each Int to a Real.
axiom
A statement taken as true without proof. Here, Z3's array axioms are re-proved as theorems in Lean.
clause
A disjunction of literals, such as a or not b.
clause log
The record of clauses Z3's SAT-based solver learned or used, each with a hint saying why it holds.
congruence
The rule that equal inputs give equal outputs. If a = b, then f a = f b.
constant array
An array with the same value at every index. In SMT-LIB: ((as const (Array Int Int)) 0).
default value
The value an array takes at all but finitely many indices. Z3 writes it (default a).
hint
A label on a logged clause naming the theory reason for it, such as array or euf.
lemma
A helper theorem proved on the way to the main result.
literal
An atomic formula or its negation, such as x = y or not (x = y).
refutation
A proof that a set of assertions implies False.
rewriter
The part of Z3 that simplifies terms before and during solving, such as turning an equality it can decide into false.
select
Reading an array at an index: (select a i).
sort
The type of a value, such as Int, Real, or Bool. An array sort has an index sort and an element sort.
store
Writing one index of an array: (store a i v) is a with the value at i replaced by v.
tactic
A Lean command that builds part of a proof automatically, such as omega or grind.
theorem
A statement with a proof that Lean has checked.
trust boundary
The things one must trust without proof. A change that adds no assumption and no new trusted step leaves it unchanged.
uninterpreted sort
A sort declared with only a name, such as (declare-sort Element 0). It may have any number of values, even finitely many.
