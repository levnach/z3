Prove propagation lemmas as tactic scripts over named gates

Pull request levnach/z3#38 · State: MERGED · Merged 2026-10-27T22:34:55Z · Loop iteration 38

Merge commit e088115 on master, base d3628f4.

In one paragraph

The reconstructor now writes each propagation proof as a tactic script, one step per line. Before, it wrote one deeply nested proof term. Inside a cnf lemma, each gate is now named by its existing Lean definition, so nothing is unfolded up front. The replay also interns its canonical forms, which makes export of deep Boolean circuits fast. Together, these let a large bounded model checking input from the difference logic benchmarks get a refutation that Lean accepts. That input used to run out of heartbeats. No lemma statement changes, and no axiom is added.

Background

Before this PR, small and medium inputs already got Lean proofs. The corpus scan of iteration 32 left one QF_IDL input failing in Lean. Its whole refutation rests on a single theory lemma. That is a cnf lemma tying an assumed clause to the one 13,000-node assertion. Three separate costs each sank that lemma. They were unfolding every definition, Lean's elaboration of a deeply nested term, and slow key sorting during export. The work serves milestone 3 of the plan, equality and linear arithmetic, on larger benchmarks.

What changed

  • Reconstructor: a propagation proof is now a list of have lines that Lean checks in close to linear time, so a lemma with ten thousand steps no longer times out.
  • Reconstructor: gates are named by the definitions they came from, so a cnf lemma unfolds nothing first and unification opens one definition per step.
  • Reconstructor: a step through a conjunction or disjunction no longer writes out the other operands, so its text stays short even for very wide gates.
  • Replay: each canonical form gets a small integer key built from its children's keys, so the deep circuit now exports in seconds instead of minutes.
  • Tests: the full BubbleSort benchmark file is now a regression test that must verify in Lean, and existing shape tests expect the new script form.

An analogy for the first bullet: a nested term is like one sentence with ten thousand nested clauses. Lean must re-read the rest of the sentence at every clause. A tactic script is a numbered list, where each line is read once.

Review

The reviewer approved with no blocker and no major findings. They checked that no lemma or theorem statement changed, so a bad proof can only be rejected.

  • Minor: the slow test did its work twice. The reviewer timed the new test and saw it rebuild the 3.9 MB Lean file just to read one lemma. That wasted CI time in a job with a 90-minute limit. Fixed: a new helper, checked_text, returns the text Lean already checked.
  • Nit: outdated comments. Two comments still described the old nested term, which could mislead someone tuning the size budget. Fixed: both now describe tactic scripts.
  • Nit: a clock-based assertion. A wall-clock limit could fail on a slow runner for no real reason. Fixed: removed, since the heartbeat limit catches a slowdown deterministically.
  • Nit: two lines over 120 characters. Fixed: wrapped.
  • Suggestion: note the memory use. Done: the test comment records the peak of about 4.5 GB.

Risks and open questions

  • Many lemmas now have new proof text. Lean checks each one, so a mistake can only make a lemma fail.
  • Case splits rely on refine listing its open goals in source order. Every case split in the tests exercises this.
  • The new test needs about 4.5 GB of memory and about a minute. That adds load to a CI job with a time limit.
  • On a huge formula, the fallback still unfolds names one at a time. A failed structural attempt now fails slowly instead of fast.
  • The CI result of the job that runs the new Lean test was not known at report time.

What comes next

  • Use delta instead of a name-by-name unfold in the fallback paths.
  • Use definitions instead of tactic let lines for normalized rewrites over thousands of gates.
  • Re-scan the benchmark corpus. The old key-sorting cost may have hidden other large failures behind the 60 s export timeout.

Glossary

assertion
A formula given to the solver with assert. All assertions together must be shown impossible.
axiom
A statement Lean accepts without proof. The standard ones here are propext, Classical.choice, and Quot.sound.
Boolean
The sort of truth values, true and false. In SMT-LIB it is Bool.
bounded model checking
Checking a system for a fixed number of steps by unrolling it into one big formula. The result is often a huge circuit of gates.
canonical form
One standard way of writing a formula, so that two equal formulas look the same. For example, (and b a) and (and a b) get one form.
case split
Proving a goal by handling each possibility separately, for example once with p true and once with p false.
clause
A disjunction of literals, such as a or not b or c.
cnf lemma
A theory lemma that ties a clause to the formula it came from when the formula was turned into clauses (conjunctive normal form).
conjunction
An "and" of formulas. It is true only when every part is true.
definition
A named Lean expression, such as formula_46, that stands for a longer formula.
difference logic
Arithmetic where every atom compares a difference of two variables to a constant, like x - y <= 3. The integer version is the SMT-LIB logic QF_IDL.
disjunction
An "or" of formulas. It is true when at least one part is true.
elaboration
Lean's step of turning written proof text into a fully typed term it can check.
gate
One node of a Boolean circuit, such as an and, or, or not of other nodes.
heartbeat
Lean's unit of work. A proof that uses more than maxHeartbeats stops with a timeout error.
interning
Storing each distinct value once and referring to it by a small number. Equal values then get equal numbers.
proof term
A proof written as one expression, where each step is nested inside the next.
propagation
Deriving new facts one at a time from known ones. For example, from a and b derive a, or from a or b and not a derive b.
refutation
A proof that a set of formulas leads to False, so they cannot all be true.
tactic script
A proof written as a list of tactics, one per line, that Lean runs in order. A tactic is a command that builds part of a proof, such as have, refine, or exact.
theory lemma
A clause justified by a theory, such as arithmetic or the clause conversion, rather than by resolution.
unfold
Replacing a definition's name by its body, such as formula_46 by the formula it stands for.
unification
Lean's way of filling in a placeholder _ by matching the types on both sides.
