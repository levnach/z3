Prove propagation lemmas as tactic scripts over named gates

Pull request levnach/z3#38 · State: OPEN · Date: 2026-10-27T22:12:00Z · Loop iteration 38

This pull request is open and not merged. The change it proposes is commit ba9390a, on top of an earlier commit in the same PR.

In one paragraph

The reconstructor now writes each propagation proof as a tactic script, one step per line, instead of one deeply nested proof term. Inside a cnf lemma, it refers to each gate by its existing definition, so nothing has to be unfolded first. The replay also stores its canonical keys by interning, which makes export of deep Boolean circuits fast. Together, these let a large bounded model checking input from the difference logic benchmark set get a refutation that Lean accepts. That input used to run out of heartbeats. No lemma statement changes, and no axiom is added.

Background

Before this PR, smaller inputs already got Lean proofs. The corpus scan of iteration 32 left one QF_IDL input failing in Lean. Its whole refutation rests on one theory lemma, a cnf lemma that ties an assumed clause to the single 13,000-node assertion. Three separate costs each sank that lemma: unfolding every definition, Lean's elaboration of a deeply nested term, and slow key sorting during export. The work serves milestone 3 of the plan, equality and linear arithmetic, and the plan's goal of checking larger benchmark collections.

What changed

  • Reconstructor: a propagation proof is now a list of have lines that Lean checks in close to linear time, so a lemma with ten thousand steps no longer times out.
  • Reconstructor: gates are named by the definitions they came from, so a cnf lemma unfolds nothing up front and unification opens one definition per step.
  • Reconstructor: a step through an and or an or no longer writes out the other operands, so its text stays short even for very wide gates.
  • Replay: each canonical form gets a small integer key over its children's keys, so exporting the deep circuit now takes seconds instead of minutes.
  • Tests: the full BubbleSort benchmark file is now a regression test that must verify in Lean, and existing shape tests expect the new script form.

An analogy for the first bullet: a nested term is like one sentence with ten thousand nested clauses. Lean must re-read the rest of the sentence at every clause. A tactic script is a numbered list, where each line is read once.

Review

The reviewer approved with no blocker and no major findings. They checked that no lemma or theorem statement changed, so a bad proof can only be rejected.

  • Minor: the slow test did its work twice. The reviewer timed the new test and saw it rebuild the large Lean file just to read one lemma. That wasted CI time. Fixed: a new helper, checked_text, returns the text Lean already checked.
  • Nit: outdated comments. Two comments still described the old nested term, which could mislead someone tuning the size budget. Fixed: both now describe tactic scripts.
  • Nit: a clock-based assertion. A wall-clock limit could fail on a slow runner for no real reason. Fixed: removed, since the heartbeat limit catches a slowdown deterministically.
  • Nit: two over-long lines. Fixed: wrapped.
  • Suggestion: note the memory use. Done in the test comment.

Risks and open questions

  • Many lemmas now have new proof text. Lean checks each one, so a mistake can only make a lemma fail.
  • Case splits rely on refine listing its open goals in source order. Every case split in the tests exercises this.
  • The new test needs about 4.5 GB of memory, which adds load to a CI job with a time limit.
  • On a huge formula, the fallback still unfolds names one at a time, so a failed attempt now fails slowly.

What comes next

  • Use delta instead of a name-by-name unfold in the fallback paths.
  • Use definitions instead of tactic let lines for normalized rewrites over thousands of gates.
  • Re-scan the benchmark corpus, since the old key-sorting cost may have hidden other large failures.

Glossary

assertion
A formula given to the solver with assert. The solver must show that all assertions together cannot be true.
axiom
A statement Lean accepts without proof. The standard ones here are propext, Classical.choice, and Quot.sound.
Boolean
The sort of truth values, true and false. In SMT-LIB it is Bool.
bounded model checking
Checking a system for a fixed number of steps by unrolling it into one big formula. The formula is often a huge circuit of gates.
case split
Proving a goal by handling each possibility separately, for example once with p true and once with p false.
clause
A disjunction of literals, such as a or not b or c.
cnf lemma
A theory lemma that ties a clause to the original formula it was derived from when the formula was turned into clauses (conjunctive normal form).
conjunction
An "and" of formulas. It is true only when every part is true.
definition
A named Lean expression, such as formula_46, that stands for a longer formula.
difference logic
Arithmetic where every atom compares the difference of two variables to a constant, like x - y <= 3. The integer version is the SMT-LIB logic QF_IDL.
disjunction
An "or" of formulas. It is true when at least one part is true.
elaboration
Lean's step of turning written proof text into a fully explicit internal term, filling in types and missing parts.
fallback
A second proof attempt that runs only when the first one fails, here an automatic tactic such as grind.
gate
One connective node of a Boolean circuit, such as an and, or, not, or iff applied to its inputs.
heartbeat
Lean's unit of work. A proof that uses more than its heartbeat limit stops with a timeout error.
interning
Storing each distinct value once and referring to it by a small number. Two equal values always get the same number.
literal
An atom or its negation, such as p or not p.
proof term
A proof written as a single expression, where every step is nested inside the next one.
propagation
Deriving new truth values from known ones. If a and b is true, then a is true.
refutation
A proof that a set of formulas leads to a contradiction, so the formulas cannot all be true.
tactic
A command in a Lean by block that builds part of a proof, such as have, refine, or exact. A tactic script is a list of them.
theory lemma
A clause that holds because of a background theory, such as arithmetic, rather than by pure Boolean reasoning.
unfold
Replacing a definition's name with its body. Unfolding thousands of names one by one rewrites a large goal thousands of times.
unification
Lean's way of finding the missing pieces of an expression, written _, by matching it against the expected type.
