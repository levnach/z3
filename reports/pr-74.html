In one paragraph

Since the previous iteration, sets could be certified, but they could not be combined. This PR lets the pipeline certify a map of the connectives not, and, or, and => over sets of one sort. It also covers Z3's four set operators and default values written in the input. The clause log replay reads these terms. The reconstructor turns them into Lean functions that apply a Boolean connective pointwise. Each new step in the refutation is closed by rfl or a proved extensionality theorem, with no new axiom. The z3test De Morgan file t8.smt2 and two queries of issue-1665.smt2 now verify in Lean.

Background

Before this PR, the pipeline certified arrays through the clause log. That included arrays with Boolean elements, which are sets, and constant arrays. But the exporter stopped with “unsupported array operator: map” on any map. It also rejected union, intersection, setminus, complement, and (default a) in the input. The previous iteration's backlog named t8.smt2 and issue-1665.smt2 as blocked only by maps. This work serves milestone 4 of the plan, “Broader theories and integration”, which treats arrays as one of the extensions.

What changed

  • The exporter now accepts maps of not, and, or, and =>, and the four set operators, over sets whose elements are all of one index sort.
  • Maps of any other function, such as an uninterpreted function or xor, are still rejected with a clear message.
  • The reconstructor states each map in Lean and adds, as proved theorems, the identities the solver and the rewriter use, such as commutativity and double complement.
  • An input may now write (default a) over Int and Real indices, the rule that already held for constant arrays.
  • The default-map axiom is rejected on purpose, because it cannot be proved for the Lean meaning of a default value.

A helpful picture: a map is like a spreadsheet column computed from two other columns, row by row. Lean only needs to know the formula for one row to know the whole column.

This is setminus_named, a new test input from the review fix. It claims that x is in both c = a \ b and b, which is impossible.

(b) Before: the exporter at the base commit

proof_certificate.py: error: unsupported array operator: setminus

The old exporter stopped before writing a certificate.

(c) After: the Lean file the reconstructor now writes

def _map1 {I : Type} (f : Prop -> Prop) (a : I -> Prop) : I -> Prop := fun _i => f (a _i)

def _map2 {I : Type} (f : Prop -> Prop -> Prop) (a b : I -> Prop) : I -> Prop := fun _i => f (a _i) (b _i)

A map is a new set whose membership at each index is the connective applied to the members at that index.

def term_3 ... : (Int -> Prop) := (_map2 (fun _p _q : Prop => And _p (Not _q)) (term_1 _atoms _vars _m) (term_2 _atoms _vars _m))
def formula_4 ... : Prop := ((term_0 _atoms _vars _m) = (term_3 _atoms _vars _m))
...
def term_9 ... : (Int -> Prop) := (_map1 Not (term_2 _atoms _vars _m))
def term_10 ... : (Int -> Prop) := (_map2 And (term_1 _atoms _vars _m) (term_9 _atoms _vars _m))

term_3 is (setminus a b) as written. term_10 is the and-map over the complement of b that Z3's rewriter turns it into.

theorem unsat (_atoms : Nat -> Prop) (_vars : Nat -> Int) (_m : Interpretation)
    (_h0 : (formula_4 _atoms _vars _m))
    (_h1 : (formula_6 _atoms _vars _m))
    (_h2 : (formula_7 _atoms _vars _m))
    : False :=
  ...

The three assertions, taken as hypotheses, lead to False under every interpretation.

private theorem rewrite_13 ... : (formula_12 _atoms _vars _m) := by
  unfold formula_12 formula_11 formula_4
  ...
  have _md3 : ((term_3 _atoms _vars _m)) = _map2 And ((term_1 _atoms _vars _m)) (_map1 Not ((term_2 _atoms _vars _m))) := rfl
  ...
  have _mc10 := _map2_and_comm ((term_1 _atoms _vars _m)) ((term_9 _atoms _vars _m))
  first | omega | grind (splits := 64)

The _md3 line is the review fix. It tells Lean that both ways of writing the difference are the same set, before the tactic grind runs.

private theorem th_lemma_65 ... : (formula_54 _atoms _vars _m) := by
  ...
  have _m53 : _select ((term_10 _atoms _vars _m)) (_vars 0) = (And (_select ((term_1 _atoms _vars _m)) (_vars 0)) (_select ((term_9 _atoms _vars _m)) (_vars 0))) := rfl

Reading a map at x unfolds to the connective applied to the reads below it, one level at a time, by rfl.

Review

The reviewer asked for changes. There was no blocker. Every finding was resolved before the merge.

Major: setminus failed in Lean outside a direct read

The reviewer tried inputs where the set difference stays a term, such as (= c (setminus a b)). The exporter accepted them, but Lean failed with “grind failed”. The rewriter had replaced setminus by an and-map over a complement. In Lean those were two different functions, and nothing said they were equal. The fix adds one rfl fact per setminus node, the _md3 line above. Three new inputs fail without it and pass with it. It mattered because setminus was advertised as supported but worked in only one shape.

Nit: test fragments were guessed from the input text

The tests guessed each input's logic fragment from substrings like "Int)". An explicit table now names them.

Nit: unclear wording in the plan

A sentence read as if maps were arrays of arrays. It was reworded.

Suggestion not adopted

The reviewer suggested widening the check that rejects the default-map axiom. The author declined, because Z3 logs that axiom as an equality today. If it ever slipped through, Lean would fail, so the gap is incomplete, not unsound.

Risks and open questions

  • A new rule compacts some untrimmed certificates. It fires only on logs that were rejected before, so no accepted certificate changes.
  • Lemmas that touch a map get a few extra facts. The array test module grew from about 83 s to about 124 s.
  • The replay assumes a map-read hint states the propagated equality. If Z3 logged the complement, Lean would fail, which is incomplete, not unsound.
  • GitHub CI results for the merged commit are unknown here.

Glossary

array
A total function from an index sort to an element sort, written (Array I E). You read it with select and write it with store.
axiom
A statement accepted without proof. Each new axiom is something the checker must trust.
Boolean
The sort Bool, whose values are true and false. In Lean the reconstructor uses Prop.
clause log
The record of clauses Z3 derives while solving, each with a hint naming the theory that justified it. A clause is an “or” of literals, such as p or not q, and a literal is an atom or its negation.
commutativity
The rule that the order of arguments does not matter, as in a and b = b and a.
connective
A Boolean operator that builds a formula from smaller ones: not, and, or, =>.
constant array
An array with the same value at every index, written ((as const (Array I E)) v).
default value
The value (default a) that an array takes at all but finitely many indices.
double complement
The rule that complementing a set twice gives the set back.
extensionality
The rule that two arrays or functions are equal when they agree at every index. Lean calls it funext.
incomplete, unsound
A checker is incomplete if it may reject a valid proof. It is unsound if it may accept an invalid one, which is the worse failure.
map
The array ((_ map f) a b) whose value at each index i is f applied to a[i] and b[i].
pointwise
Applied separately at each index. A pointwise and of two sets is their intersection.
refutation
A proof that the assertions together lead to False.
rewriter
The Z3 component that simplifies terms, for example turning setminus into an and-map over a complement.
rfl
A Lean proof that two sides are equal because they unfold to the same thing.
set
An array with Boolean elements, (Array I Bool). The value at i says whether i is a member.
set operator
Z3's built-in union, intersection, setminus (difference), and complement.
sort
The type of a value, such as Int, Real, Bool, or a declared sort.
tactic
A Lean command that searches for a proof, such as grind or omega.
theorem, lemma
A statement together with a proof that Lean has checked. A lemma is a small theorem used inside a larger proof.
uninterpreted function, uninterpreted sort
A function or sort declared with no fixed meaning. The solver may only assume that equal inputs give equal outputs.
