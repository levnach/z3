Certify maps and set operators over sets in Lean via the clause log

Pull request levnach/z3#74 · State: OPEN · Opened 2026-11-06T01:18:19Z · Loop iteration 75

This pull request is open and not merged. The change it proposes is commit a3281acb8 on top of base 83e41fb29.

In one paragraph

Before this PR, the pipeline could certify single sets, but it could not combine them. It rejected every map, the four set operators, and an input default value. Now a map of the connectives not, and, or, and => is accepted over sets of one sort. So are union, intersection, setminus, and complement. The exporter writes them into the certificate. The reconstructor turns each one into a Lean function applied pointwise. Every new Lean fact is either true by definition or a proved function-extensionality theorem. No new axiom was added. As a result, the z3test file t8.smt2, which states De Morgan's law over sets, now gets a refutation that Lean accepts. So do two of the three queries in issue-1665.smt2.

Background

Since iteration 74, arrays with Boolean elements have been certified through the clause log. Reads, stores, and constant arrays all worked. But any input that built a new set from old ones stopped at the exporter with "unsupported array operator: map". The iteration-73 backlog named t8.smt2 and issue-1665.smt2 as blocked by exactly this. The work serves milestone 4 of the plan, "Broader theories and integration", which lists arrays as one of the theory extensions.

What changed

  • You can now give the exporter a map such as ((_ map and) a b) over sets and get a certificate. Maps of any other function, such as an uninterpreted function or xor, are still rejected with a clear message.
  • You can now use union, intersection, setminus, and complement in an input, and the generated Lean file checks.
  • You can now write (default a) in an input when the index sort is Int or Real. Other index sorts are still rejected, as for constant arrays.
  • The Lean file now states the identities that Z3's rewriter and congruence closure use on maps. Examples are commutativity and idempotence of and and or maps, and a double complement cancelling out.
  • A tampered certificate that swaps one connective for another is now caught, because the input is matched by connective name.
  • The default value of a map is refused with "the default value of a map is not certified". Lean cannot prove that fact, so it is rejected rather than trusted.

Think of a map like a spreadsheet column formula. If column C is "A AND B", every row of C is fixed by the same rows of A and B. Lean's _map2 says exactly that, one row at a time.

Worked example

The input is the z3test regression t8.smt2, which is also a test in the PR. It claims that De Morgan's law fails for two sets of integers. All three pieces below come from real runs on the PR's head and base code.

(a) The input

(declare-const s1 (Array Int Bool))
(declare-const s2 (Array Int Bool))
(set-info :status unsat)
(assert (not (= ((_ map and) s1 s2)
                ((_ map not) ((_ map or) ((_ map not) s1) ((_ map not) s2))))))
(check-sat)

It says "the intersection of s1 and s2 is different from the complement of the union of their complements".

(b) Before: the base exporter

proof_certificate.py: error: unsupported array operator: map

The old exporter stopped at the first map, so no certificate and no Lean file were produced.

(c) After: the generated Lean file, trimmed

The exporter wrote a certificate and the reconstructor wrote a Lean file. Lean accepted the file: check_lean.sh printed "Lean checks passed."

  have _m10_2 : _select ((term_3 _atoms _vars _m)) (...) = (Not (_select ((term_0 _atoms _vars _m)) (...))) := rfl

By extensionality, the two sides differ at some witness index. This lemma reads the right-hand side at that index through all three nested maps, one rfl fact per level, and then the grind tactic closes the goal. The (...) stands for the long witness index _array_diff ... term_2 ... term_6, cut for width.

Review

The reviewer asked for changes. There was no blocker, one major finding, and two nits. All three were fixed in a3281acb8.

Major: setminus failed in Lean unless it was read directly

The reviewer wrote small inputs that use a set difference as a whole set, such as (assert (= c (setminus a b))). Z3 proved each one unsat and the exporter accepted it, but Lean then failed with "grind failed". The cause was a mismatch of names. Z3's rewriter turns (setminus a b) into "a and the complement of b", built from maps. In Lean those two shapes were different functions, and nothing said they were equal. It is like two clerks filing the same document under two labels with no cross-reference. The fix adds one fact per setminus node, proved by rfl, that links the two shapes. Three new test inputs cover it, and a test shows Lean fails if the fact is removed. This mattered because the PR advertised setminus as supported, but most real uses would have failed. A Lean-free test now also checks that the other three set operators already share their Lean function with their map form.

Nit: test fragments were guessed

The tests decided each input's logic fragment by looking for substrings like Int) in the source. A future input could have been classed by accident. The fix is an explicit table, checked against the exported fragment.

Nit: unclear sentence in the plan

One sentence read as if maps were a kind of array of arrays. It was reworded.

Suggestion not adopted

The reviewer suggested that the default-map rejection also inspect a bare atom, not only the sides of an equality. The implementer declined. Z3 logs that axiom as an equality today, and a missed case would only make Lean fail. That makes the gap incomplete, not unsound.

Risks and open questions

  • A new compaction rule changes the certificate shape for some untrimmed logs. It applies only when the log takes a default value over a non-Int, non-Real index. Such logs were rejected before, so no previously accepted certificate changes.
  • Map identity facts are added to every lemma that reaches a map node. The array test module went from about 83 s to about 124 s.
  • The replay treats any one-literal array hint on a read of a map as the propagated equality. If Z3 ever logged the opposite, Lean would fail. That is incomplete, not unsound.
  • CI results and the local gate result were not available when this page was written.

What comes next

The PR lists these follow-ups in the backlog:

  • The default-map axiom. It would need a different Lean definition of the default value.
  • Default values over uninterpreted index sorts. These block query 0 of issue-1665.smt2.
  • Maps of other functions: uninterpreted, arithmetic, xor, or =.
  • The rewriter's remaining set identities, such as a ∩ ¬a being the empty set.
  • Other blocked z3test set files: t150, t109, t155, t154, issue-1816.

Glossary

array
A total map from an index sort to an element sort, written (Array I E). It may have infinitely many entries.
axiom
A statement accepted without proof. Adding one to Lean means trusting it, so the project avoids new ones.
certificate
A file that records the solver's refutation in a form another tool can check step by step.
clause
A disjunction of literals, such as p ∨ ¬q ∨ r.
clause log
The list of clauses the solver writes while it works, each tagged with a hint saying why it holds.
commutativity
The rule that argument order does not matter: a ∧ b = b ∧ a.
complement
The set of all indices not in a given set. A double complement gives back the original set.
congruence closure
The solver procedure that merges equal terms: if a = b, then f(a) = f(b).
connective
A Boolean operator that builds formulas from formulas: not, and, or, =>.
constant array
An array with the same value at every index, written ((as const (Array I E)) v).
De Morgan's law
The rule a ∧ b = ¬(¬a ∨ ¬b). Over sets it reads: the intersection is the complement of the union of the complements.
default value
The value an array takes at all but finitely many indices, written (default a) in Z3.
exporter
The program that reads Z3's proof evidence and writes a certificate.
extensionality
The rule that two arrays are equal if they agree at every index. If they differ, there is a witness index where they differ.
function extensionality (funext)
The Lean principle that two functions are equal if they give equal results on every input.
hint
A tag on a logged clause naming the reason it holds, such as array or arith.
idempotence
The rule that combining a thing with itself changes nothing: a ∧ a = a.
literal
An atom or its negation, such as p or ¬p.
map
An array operator that applies a function at every index. ((_ map and) a b) is the array whose entry at i is a[i] ∧ b[i].
reconstructor
The program that turns a certificate into a Lean file whose proof Lean can check.
refutation
A proof that a set of assertions leads to False.
rewriter
The part of Z3 that simplifies terms before and during solving, for example turning a set difference into a map.
rfl (true by definition)
A Lean proof that two sides are equal because they unfold to the same thing.
set
An array with Boolean elements, (Array I Bool). The entry at i says whether i is a member.
set operator
One of Z3's built-in operations on sets: union, intersection, setminus (set difference), and complement.
sort
The type of a value, such as Int, Real, Bool, or (Array Int Bool).
store
The array update (store a i v): the array a with the entry at i replaced by v.
tactic
A Lean command that builds part of a proof automatically. grind and omega are tactics.
theorem
A statement together with a proof that Lean has checked.
uninterpreted function
A function symbol with no fixed meaning, only the rule that equal inputs give equal outputs.
