In one paragraph

Lean proves a large integer Farkas lemma by adding up its scaled bounds. The last step is an identity: the sum equals a negative constant. Before this PR, that sum was a right-nested sum proved by omega. On lemmas of about 200 bounds, this ran out of heartbeats, and the whole refutation failed to check. Now the sum is a balanced tree, and the tactic simp +arith proves the identity, with omega as the fallback. Two QF_LIA files with regressions verify again. The kernel still checks every proof, and no theorem statement changes.

Background

The reconstructor already proved wide Int Farkas lemmas by their direct combination. A rescan of z3test's smtlib-sample found two QF_LIA files that had verified before but now failed. In each, one theory lemma had 202 bounds over 428 atoms. Its identity needed about five million heartbeats against a budget of one million. Lean's first combinator does not catch that error, so the fallback proofs never ran. This work serves milestone 3, linear arithmetic, and the regression methodology the plan names as its top priority.

What changed

  • Int Farkas lemmas of about 200 wide bounds now check in Lean instead of running out of heartbeats.
  • The scaled sum and its proof of nonnegativity are now a balanced tree, so a 202-term sum nests 8 levels deep instead of 201.
  • The identity is now tried with simp +arith first, and omega still runs if simp does not close the goal.
  • Proofs by one case split and two combinations now use the same faster identity on both sides.
  • Two new tests fail on the old code: one checks the tree shape and tactic text, and one checks a 140-bound conflict in Lean.

Think of adding 200 receipts. One at a time, you rewrite the whole running total after each receipt. In pairs, then pairs of pairs, like a knockout tournament, each partial total stays small. The cost was in the kernel checking the reflective proof, which normalizes each partial sum.

Review

The reviewer approved the PR. There were no blocker, major, or minor findings.

The reviewer asked whether the new test really catches the bug. They ran the 140-bound instance with the old right-nested sum and omega alone, and Lean ran out of heartbeats. A balanced sum with omega alone passed but was about five times slower than simp. So simp carries most of the gain.

SeverityFindingResolution

suggestionExplain why the depth check in the unit test works.Done: a comment was added.

The nits mattered because a reader of the old text would blame omega for a heartbeat problem.

Risks and open questions

  • If simp ever exhausts the budget, that error would escape first just as omega's did. No such case was seen.
  • Dense bounds stay costly. A synthetic 202-bound lemma with one 300-atom bound checks, but slowly.
  • The PR merged on the local gate. GitHub CI results on master were not recorded for this report.

What comes next

  • A proof term that states each bound's normal form once might keep the kernel's work linear on dense bounds.
  • Heartbeat exhaustion escaping first remains a general hazard wherever omega has a fallback tactic.
  • A few QF_LRA files from the rescan still hit the clause-log time limit, and one known failure remains.

Glossary

atom
A smallest term the arithmetic treats as one variable, such as x3.
balanced tree
A nesting where both halves have about the same size at every level, such as ((a + b) + (c + d)).
bound
An inequality that limits a linear expression, such as x1 + x2 ≤ 14.
case split
A proof that considers two cases that cover everything, such as s ≤ k or s > k, and proves the goal in each.
clause
A disjunction of literals, such as x1 < 1 ∨ x2 < 1. A literal is an atom or its negation.
Farkas lemma
A proof that some linear bounds conflict: scaled by nonnegative multipliers and added, they give an impossible fact such as 0 ≤ -1.
heartbeat
Lean's unit of work. Each declaration has a budget, and running out stops elaboration with an error.
identity
An equation true for all values of its variables, such as (y - x) + (x - y - 1) = -1.
kernel
The small trusted core of Lean that checks every finished proof term.
linear arithmetic
Reasoning about sums of variables times constants, with no variable multiplied by another.
normalization
Rewriting an expression into one standard form, such as collecting like terms in x + 2 + x to get 2x + 2.
omega
A Lean tactic that decides linear arithmetic over integers and natural numbers.
QF_LIA
The SMT-LIB logic of quantifier-free linear integer arithmetic.
reflective proof
A proof in which the kernel runs a computation, such as a normalizer, to confirm a fact.
refutation
A proof that a set of assertions leads to False.
regression
An input that used to pass and now fails.
right-nested sum
A sum nested to the right, such as a + (b + (c + d)). Its depth grows with every term.
simp +arith
Lean's simplifier with linear arithmetic normalization turned on. It can close linear identities.
tactic
A Lean command that builds part of a proof, such as omega or simp.
theory lemma
A clause that a theory solver, here arithmetic, asserts as valid. Lean must prove it.
valuation
An assignment of a value to every variable. In the generated Lean, _vars plays this role.
