Give index sorts of maps and set operators their own Lean type

Pull request #131 in levnach/z3, targeting master · loop iteration 130 · 2026-11-13T07:43:17Z

OPEN This pull request is not merged. The change commit is f78b60228.

In one paragraph

Some inputs apply a map, a set operator, or subset to an array whose index sort is an uninterpreted sort. The reconstructor now gives that index sort a Lean type of its own.Before, all uninterpreted sorts shared one Lean type. With these pointwise operations, a hypothesis of the generated theorem could then be stronger than the assertion it stands for. Lean could derive False from hypotheses that have a model. A refutation resting on them would say nothing about the input. No wrong certificate is known. The hypotheses now hold in every model of the input. No axiom was added and no check was removed.

Background

Arrays over uninterpreted sorts, maps, set operators, and subset were already supported. Every uninterpreted sort was the single carrier type of the interpretation. That is faithful while arrays are only read with select, updated with store, and compared. It fails for pointwise operations such as complement. The gap was the first backlog item. The work serves milestone 4 of the plan, which lists arrays among the broader theories. It is a soundness repair of the theorem statement and accepts no new input.

What changed

Reconstructor

  • The index sort of a map, set operator, or subset is now its own Lean type, _m.S0, whenever the carrier holds anything else.
  • An injection carries terms of that type into the carrier where an uninterpreted function or predicate takes them.
  • When the index sort is all the carrier holds, the certificate text is identical to before.
  • An enumeration used as such an index sort is rejected with its own message.

Tests and documentation

  • A new test module checks documented inputs and random seeds in Lean, including a model of hypotheses that used to be contradictory.
  • The plan and the README describe the new encoding.

(a) The input

It is taken from the new test module.

(declare-sort I 0)
(declare-sort E 0)
(declare-fun a () (Array I Bool))
(declare-fun i () I)

(assert (= (store a i true) (complement (store a i false))))

The first assertion is false, which gives an easy refutation. The second holds exactly when I has one element, and the third when E has at least two. The last two are satisfiable together.

Review

The reviewer approved with no blocker or major finding. The second commit addresses all six findings.

  • Minor: the subset case was untested. The reviewer disabled the subset branch, and every test still passed. A later edit could have silently restored the over-strong hypotheses. A new subset-only input now makes that mutant fail.
  • Minor: a mapped-only function was untested. Removing the clause for a predicate that is mapped but never applied also left every test passing. A new input isolates it.
  • Nit: no enumeration next to the index sort. The condition counts enumerations as inhabitants of the carrier. A new input covers this.
  • Nit, partly fixed: an unreachable guard. The exporter rejects arrays indexed by an enumeration first, so no real input reaches the guard. A new test reaches it by patching the sort classification.
  • Nit: stale documentation. Three passages still said every sort is one type. Corrected.
  • Nit: a stray blank line. Removed.

Risks and open questions

  • Every affected certificate changes text. The tactic grind sees different terms, so an unseen input could verify before and fail now. It would fail, not verify wrongly.
  • The condition for keeping the shared type carries the soundness argument. Any future feature that puts values into the carrier must extend it.
  • Several helper functions changed signature. The z3test scripts do not call them.
  • The model test breaks if the generated layout changes.
  • Open question: Z3 answers unsat on the example's set equality alone, which has a model with one index. Whether that is intended is a question for upstream. The pipeline does not certify such answers.

What comes next

  • Accept a constant array over a sort with its own type. In the first sweep, 32 unsat seeds are rejected only for that.
  • Give an explicit message for Z3's reasoning with default values.
  • Analyse the ten Lean failures of the new generator, which also fail at the base.
  • Consider always giving such sorts their own type, which would remove the condition above.

Glossary

array
A value that maps every index to an element. (Array I Bool) maps each index of sort I to a Boolean.
assertion
A formula the input declares to be true, written (assert ...) in SMT-LIB.
axiom
A statement accepted without proof. Fewer axioms mean less to trust.
Boolean
The sort with the two values true and false, written Bool.
carrier
The collection of values that an interpretation assigns to a sort. Here, the one Lean type shared by the uninterpreted sorts.
certificate
A record of a proof that an independent checker can verify without trusting the solver.
complement
The set operator that flips membership at every index. An index is in the complement exactly when it is not in the set.
constant array
An array that holds the same element at every index.
enumeration
A sort defined by listing its values, such as a sort Color with the values red and green.
hypothesis
An assumption of a theorem. The generated theorem has one hypothesis per assertion and concludes False.
index sort
The sort of the positions of an array. In (Array I Bool) the index sort is I.
injection
A function that carries the values of one type into another type. Here it places terms of the index sort inside the carrier.
interpretation
A choice of values for the sorts, constants, functions, and predicates of an input.
map
The array operation that applies a function at every index. ((_ map f) a) holds f of the element of a at each index.
model
An interpretation that makes every assertion true.
mutant
A copy of the code with one deliberate fault. A good test suite fails on it.
pointwise operation
An operation on arrays computed index by index. Maps, set operators, and subset are pointwise.
predicate
A function whose result is a Boolean.
refutation
A proof that a set of assertions leads to a contradiction, so no model exists.
satisfiable
Having at least one model.
select
Reading an array at an index, written (select a i).
set operator
An operation on sets, such as union, intersection, or complement. A set is an array with Boolean elements.
sort
The type of a value, such as Int, Real, or Bool.
soundness
The property that whatever is proved is actually true of the input.
store
Updating an array at one index. (store a i v) is a with v at index i.
subset
The relation that every member of one set is a member of another, written (subset a b).
tactic
A Lean command that builds part of a proof automatically. grind is one.
theorem
A statement together with a proof that Lean has checked.
uninterpreted function
A function symbol with no fixed meaning. A model may choose any function for it.
uninterpreted sort
A sort with no fixed meaning, declared with declare-sort. A model may choose any nonempty collection of values for it.
