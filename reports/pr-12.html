Certify QF_LIA refutations in Lean through the clause log

Pull request: levnach/z3 #12 Merge commit: 24813ce Merged: 2026-10-15T19:42:38Z Loop iteration: 12

In one paragraph

This PR adds a fifth fragment to the pipeline: QF_LIA, or quantifier-free linear arithmetic over the sort Int. Before, any input with an integer variable was turned away at the exporter. Now the clause log is replayed with the integer conventions of Z3's own checker, and every integer theory lemma becomes a Lean theorem. The integer-only steps, called cuts, are the steps Z3's C++ checker never verifies. Lean now proves them directly with the tactic omega, so the refutation is certified end to end and nothing new is trusted.

Background

Before this PR the pipeline certified four fragments: propositional logic over Boolean variables, equality with uninterpreted functions, linear arithmetic over Real (QF_LRA), and their combination (QF_UFLRA). Integer input failed with the message "unsupported sort: Int". The plan had listed QF_LIA as open since the first Real slice, because a cut carries no coefficients that a Farkas lemma check could re-derive. This work belongs to milestone 3 of the plan, "equality and linear arithmetic", which asks for each fragment to be completed end to end before the next is added.

What changed

  • Integer input is exported. An input whose variables are all Int is now classified as the fragment qf_lia, while Int mixed with Real or with uninterpreted functions is still rejected with a clear message.
  • The clause log is replayed with integer rules. Numerals are read as integers, and a strict bound is tightened, so x < 5, x ≤ 4, and "not 5 ≤ x" are recognised as the same atom.
  • Cuts go straight to Lean. A cut is checked for shape only in Python, and Lean proves the clause itself, much as a teacher who cannot see a student's scratch work simply re-solves the problem.
  • Integer Farkas and bound lemmas can fall back to Lean. When Z3's coefficients rest on an earlier cut, the lemma is kept without them and marked as proved by Lean alone.
  • The Lean file speaks Int. Variables are integers, if-then-else terms are rendered over Int, and each integer lemma and rewrite is proved by omega first and grind second.
  • Wide integer rewrites work. After the review, a tightened strict atom and its complement share one name, so the propositional proof can see that they contradict each other.

Worked example

The input is the gcd conflict from the PR's new test module. It asks for integers x and y with 2x = 2y + 1, so an even number would equal an odd one. Over Real this has solutions, so the refutation needs a cut.

(a) The input

(set-logic QF_LIA)
(declare-const x Int)
(declare-const y Int)
(assert (= (* 2 x) (+ (* 2 y) 1)))
(check-sat)

(b) Before the PR

The exporter from the merge commit's parent stops at the first integer declaration and exits with code 2.

proof_certificate.py: error: unsupported sort: Int

(c) After the PR

The current exporter labels the certificate qf_lia and records two theory lemmas, one of them hinted as a cut. The generated Lean file follows, trimmed.

-- Int variables are encoded as Int; the integer lemmas are proved by omega, else grind.
def term_0 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Int := ((2 : Int))
def term_1 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Int := _vars 0
def term_2 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Int := ((term_0 _atoms _vars) * (term_1 _atoms _vars))
...
def formula_7 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Prop := ((term_2 _atoms _vars) = (term_6 _atoms _vars))
...
def formula_14 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Prop := (Not (formula_10 _atoms _vars))
def formula_15 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Prop := (Or (formula_14 _atoms _vars) (formula_14 _atoms _vars))

The declarations. Every variable now lives in Int, and the original assertion becomes the proposition formula_7.

set_option maxHeartbeats 1000000 in
private theorem th_lemma_16 (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    : (formula_15 _atoms _vars) := by
  unfold formula_15 formula_14 formula_10 term_9 term_5 term_4 term_3 term_2 term_1 term_0
  first | omega | grind (splits := 64)

The cut lemma. It states that 2x = 1 + 2y is false, and omega proves it without any coefficients from Z3.

theorem unsat (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    (_h0 : (formula_7 _atoms _vars))
    : False :=
  ...
  let _step_16 : (formula_15 _atoms _vars) :=
    (th_lemma_16 _atoms _vars)
  ...
  _step_21

The final theorem. From the one original assertion it derives False by chaining a rewrite, the cut lemma, and unit resolution.

Review

The reviewer asked for changes. They found one major issue, one minor issue, and two nits.

  • Major, fixed. The reviewer built an input with nine integer variables and one clause of eighteen literals. Export succeeded, but Lean could not prove the wide rewrite, while the same input over Real verified. Tightening had turned x < 5 into x ≤ 4, and its complement x ≥ 5 got an unrelated opaque name, so the propositional proof could not see that one negates the other. The fix keys an integer atom by its complement, as the clause-log replay already did. The reviewer's input now verifies, and two tests cover the path. Without the fix, every wide integer rewrite with one strict comparison would have failed.
  • Minor, documented, not fixed. The reviewer's stress generator placed an if-then-else term inside the condition of another one. On that shape one lemma ran past Lean's heartbeat budget, and the certificate was rejected. Nothing false was proved, so this is a completeness limit. It is recorded in the README and the plan.
  • Nit, fixed. The generated Lean header said the lemmas are proved by grind, while the tactic tries omega first. The header now says "by omega, else grind".
  • Nit, fixed. A cut hint with no literals gave the wrong error message, "cut hint over Real atoms". It now says "cut hint without literals", with a unit test.

The reviewer also tampered with certificates. Changed numerals, relabelled sorts, a Real twin of the input, and a false cut were all rejected, either in Python or by Lean.

Risks and open questions

  • Soundness rests on Lean. The new Python checks are pre-filters that can only fail early, and every integer lemma is a Lean theorem over the certificate's own clause.
  • A policy change for integers only. A Farkas or bound lemma whose coefficients do not add up is handed to Lean rather than rejected, so tampered integer coefficients are caught later, by Lean. Over Real such a lemma is still rejected in Python.
  • The bound rounding path is lightly exercised. Only unit tests and one constructed log reach it.
  • Nested if-then-else terms can time out. See the minor review finding above.
  • The integer fragment is opt-in in the shared parser. The upstream z3test harness still expects integer input to be reported as unsupported, and keeps passing for that reason.

What comes next

  • QF_LIRA, integers mixed with reals, and QF_UFLIA, integers next to uninterpreted functions. Neither has an encoding yet.
  • Integer steps in the legacy proof object, which still rejects integer input before producing a proof.
  • In z3test: opt in to the integer fragment, add integer regression inputs and a matrix cell, and drop the two rows that expect Int to be unsupported.
  • Rename the CI step "Check native Boolean proofs in Lean", which now covers five fragments.

Glossary

Atom
The smallest statement in a formula, such as x ≤ 4 or p. It has no logical connectives inside it.
Boolean
A value that is either true or false.
Bound lemma
A theory lemma that derives one bound on a term from other bounds. Over integers the sum may be rounded before the last step.
Clause
An "or" of literals, such as "x ≤ 4 or y ≥ 1".
Clause log
Z3's record of every clause it learned during a run, with a hint saying why each one holds.
Complement
The negation of a literal. The complement of x < 5 is x ≥ 5.
Congruence
The rule that equal inputs to the same function give equal outputs. If a = b then f(a) = f(b).
Cut
An inference that holds only because the variables are integers, such as a parity or gcd argument. "2x = 2y + 1 is impossible" is a cut. Gomory cuts and gcd conflicts are the two kinds Z3 records.
Farkas lemma
A refutation of a set of linear literals by adding them with nonnegative coefficients until a false statement like 0 < 0 appears. The coefficients are the certificate.
Fragment
A class of inputs the pipeline handles, named after its SMT-LIB logic, such as QF_LRA or QF_LIA.
Heartbeat budget
Lean's limit on how much work one proof may take before it is abandoned.
If-then-else term
A term that picks one of two values depending on a condition, written ite in SMT-LIB. For example (ite (< x 0) 0 x).
Linear arithmetic
Arithmetic where variables are only added, subtracted, or multiplied by fixed numbers. 2x + 3y ≤ 7 is linear, x · y is not.
Literal
An atom or its negation.
Propositional
Built from Boolean variables and the connectives "and", "or", "not", with no arithmetic or functions.
Quantifier-free
Containing no "for all" or "there exists".
Refutation
A proof that a set of assertions cannot all be true at once.
Rewrite
A step that replaces a formula by an equivalent one, usually simpler or in a normal form.
Sort
The type of a value, such as Int, Real, or Bool.
Tactic
A Lean procedure that builds a proof automatically. omega decides linear integer arithmetic, and grind is a general-purpose prover.
Theory lemma
A clause that is true by the rules of a theory such as arithmetic, with no further premises.
Tightening
Turning a strict integer bound into the equivalent non-strict one, x < 3 into x ≤ 2.
Uninterpreted function
A function symbol with no fixed meaning, only the rule of congruence.
Unit resolution
Removing from a clause every literal whose negation is already known to be true.
