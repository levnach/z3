In one paragraph

This PR adds a fifth fragment to the pipeline: QF_LIA, which is quantifier-free linear integer arithmetic. "Quantifier-free" means no "for all" or "there exists". "Linear" means variables are only added, subtracted, or multiplied by a fixed number. "Integer" means every variable has the sort Int, where a sort is the type of a value. Before, any input with an integer variable was turned away at the first step. Now it is exported, replayed, translated into Lean, and checked by Lean's kernel. Integer reasoning uses steps that Z3's own C++ checker never verifies. Lean now proves those steps itself, so nothing new is trusted.

Background

Before this PR the pipeline certified four fragments: propositional logic over Boolean variables, equality with uninterpreted functions, linear real arithmetic (QF_LRA), and their mix (QF_UFLRA). An uninterpreted function is a function symbol with no fixed meaning, only the rule that equal inputs give equal outputs. Integer input failed at the exporter with "unsupported sort: Int". The obstacle was the cut hint, a proof step for which Z3 records no checkable coefficients. This work belongs to milestone 3 of the plan, "equality and linear arithmetic".

What changed

  • Integer input is exported. An Int-only input is now the fragment qf_lia. Int mixed with Real or with uninterpreted symbols is still rejected, with clear messages.
  • The clause log is replayed with integer rules. A clause log is Z3's record of every learned clause, where a clause is an "or" of literals and a literal is an atom or its negation. A strict bound such as x < 3 is tightened to x ≤ 2, since a whole number below 3 is at most 2.
  • Cuts are proved by Lean alone. A cut is an integer-only inference, such as "2x = 2y + 1 is impossible because one side is even and the other odd". Z3 writes no coefficients for a cut, so the clause goes to Lean's omega tactic, a decision procedure for linear integer arithmetic.
  • Farkas lemmas fall back to Lean. A Farkas lemma refutes literals by adding them with nonnegative coefficients. When Z3's integer coefficients rest on an earlier cut, the lemma is kept without them and Lean proves it.
  • The Lean file speaks Int. Variables are integers, if-then-else terms (written ite in SMT-LIB) are rendered over Int, and each lemma is proved by omega first and grind second.
  • Wide integer rewrites work. After the review, a strict atom and the bound it contradicts share one name, so the propositional proof sees they are complements.

Worked example

The input is the gcd conflict from the PR's new test module. It asks for integers x and y with 2x = 2y + 1, an even number equal to an odd one. Its refutation, a proof that the assertions cannot all be true, needs a cut.

(declare-const x Int)
(declare-const y Int)
(assert (= (* 2 x) (+ (* 2 y) 1)))
(check-sat)

The declarations. Every variable lives in Int, and the assertion becomes the proposition formula_7.

The final theorem. From the one original assertion it derives False by chaining the rewrite, the cut lemma, and unit resolution.

Review

The reviewer asked for changes. They found one major issue, one minor issue, and two nits.

  • Major, fixed. The reviewer built an input with nine integer variables and one clause of eighteen literals. Export succeeded, but Lean could not prove the wide rewrite, while the same input over Real verified. Tightening turned x < 5 into x ≤ 4, and its complement x ≥ 5 got an unrelated name. The propositional proof treats atoms as opaque, so it could not see they were negations of each other. The fix keys an integer atom by its complement, as the replay already did. The reviewer's input now verifies, and two tests cover the path.
  • Minor, documented and not fixed. An if-then-else term inside the condition of another pushed one lemma past Lean's heartbeat budget, its limit on work per proof. The certificate was rejected, never misproved, so this is a completeness limit. It is recorded in the README and the plan.
  • Nit, fixed. The generated Lean header said the lemmas are proved by grind. It now says by omega, else grind.
  • Nit, fixed. A cut hint with no literals gave the wrong error message. It now says "cut hint without literals".

The reviewer also tampered with certificates. Changed numerals, relabelled sorts, a Real twin of the input, and a false cut were all rejected, in Python or by Lean.

Risks and open questions

  • Soundness rests on Lean. The Python checks are pre-filters that can only fail early. Every integer lemma is a Lean theorem over the certificate's own clause.
  • A policy change for integers only. A lemma whose coefficients do not add up is handed to Lean rather than rejected, so tampered coefficients are caught by Lean instead of Python.
  • The bound rounding path is lightly exercised. Only unit tests and one constructed log reach it.
  • Nested if-then-else terms can time out. See the minor review finding above.
  • The integer fragment is opt-in in the parser. The upstream z3test harness still expects integer input to be reported as unsupported.

What comes next

  • QF_LIRA, integers mixed with reals, and QF_UFLIA, integers next to uninterpreted functions. Neither has an encoding yet.
  • Integer steps in the legacy proof object, which still rejects integer input.
  • In z3test: opt in to the integer fragment, add integer regression inputs and a matrix cell.
  • Rename the CI step "Check native Boolean proofs in Lean", which now covers five fragments.

Glossary

Atom
The smallest statement in a formula, such as x ≤ 4 or p.
Boolean
A value that is either true or false.
Bound lemma
A clause that derives one bound on a term from other bounds.
Clause
An "or" of literals.
Clause log
Z3's record of every clause it learned during a run.
Complement
The negation of a literal, such as x ≥ 5 for x < 5.
Congruence
The rule that equal inputs to the same function give equal outputs.
Cut
An inference that uses only the fact that variables are integers, such as a parity or gcd argument.
Farkas lemma
A refutation of a set of linear literals by adding them with nonnegative coefficients.
Fragment
A class of inputs the pipeline handles, named after its SMT-LIB logic.
Heartbeat budget
Lean's limit on how much work one proof may take before it is abandoned.
If-then-else term
A term that picks one of two values depending on a condition, written ite in SMT-LIB.
Linear arithmetic
Arithmetic where variables are only added, subtracted, or multiplied by fixed numbers.
Literal
An atom or its negation.
Quantifier-free
Containing no "for all" or "there exists".
Refutation
A proof that a set of assertions cannot all be true.
Rewrite
A step that replaces a formula by an equivalent simpler one.
Sort
The type of a value, such as Int, Real, or Bool.
Tactic
A Lean procedure that builds a proof automatically. omega decides linear integer arithmetic, and grind is a general-purpose prover.
Theory lemma
A clause that is true by the rules of a theory such as arithmetic, with no further premises.
Tightening
Turning a strict integer bound into the equivalent non-strict one, x < 3 into x ≤ 2.
Uninterpreted function
A function symbol with no fixed meaning, only the rule that equal inputs give equal outputs.
Unit resolution
Removing from a clause every literal whose negation is already known true.
