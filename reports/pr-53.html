Prove cnf lemmas over a distinct's pairs by propagation

Pull request levnach/z3 #53 · State: OPEN · Date: 2026-10-30T23:49:17Z · Loop iteration 53

This pull request is open and not merged. The change it proposes ends at commit 92134e4. It holds two commits on top of the base.

In one paragraph

When Lean checks a cnf lemma, the reconstructor first tries a short propagation proof. Only if that fails does it fall back to unfolding every definition and calling the grind tactic. Before this PR, the propagation prover treated a distinct over terms as one opaque atom. So a clause whose literal was (not (= a b)) found nothing to connect to. Now the prover reads (distinct a b c) as a conjunction of negated equalities, one per pair. It also takes conjuncts out of very wide conjunctions with far less proof text. On the largest QF_UF test, all twelve cnf lemmas now get a propagation proof. Lean's peak memory there fell from about 7 GB to about 5.5 GB, against an 8 GB limit. The set of certified inputs and the trusted base do not change.

Background

The previous iteration brought the SMT-LIB benchmark NEQ004_size4 under the 8 GB memory cap of the Lean check, but only just. Its assertion is a conjunction of about 400 conjuncts, and it holds (distinct c0 c1 c2 c3). Its twelve cnf lemmas all went to the grind fallback over the whole assertion. That was the slowest and most memory-hungry part of the file. This work serves milestone 3 of the plan, uninterpreted functions and equality reasoning, by keeping large QF_UF refutations checkable inside the limits.

What changed

  • A distinct over terms can now be split into its pairs, so a clause about one pair is proved by propagation instead of by grind.
  • The split happens only when every pair (a, b), with a before b, has its own equality in the proof, so the reading always matches the Lean definition.
  • A conjunct of a wide conjunction is now reached from a saved "tail" every 32 conjuncts, like using a bookmark instead of counting pages from the front.
  • New tests check that Lean accepts these propagation proofs with the grind fallback removed, both on a small input and on NEQ004.
  • The plan document and the examples README describe the new reading.

In Lean, the tail is a short projection such as h.2.2.1. Before, the prover wrote nested And.left (And.right ...) terms from the start of the conjunction each time. For one NEQ004 lemma that came to about 80,000 levels of nesting.

Worked example

This PR does not change which inputs are certified. It changes how the cnf lemmas are proved. So the "Before" below is not a rejection. It is the proof the old code produced. Every piece comes from a real run on the current code and on the base commit's scripts.

(a) The input

(declare-sort U 0)
(declare-const a U)
(declare-const b U)
(declare-const c U)
(declare-fun p (U U) Bool)
(assert (and (distinct a b c) (or (= a b) (p a c)) (or (= b c) (not (p a c)))))
(check-sat)

A smaller cousin of the PR's new test input, without its forty extra predicates. The distinct forbids a = b and b = c, which forces both (p a c) and its negation.

(b) Before

The base commit's scripts ran without error, and Lean accepted the result. But the old propagation prover found no proof for any of the four cnf lemmas. The generated file contained zero propagation attempts. Each lemma was proved only like this:

private theorem th_lemma_27 (_atoms : Nat -> Prop) (_m : Interpretation)
    : (formula_26 _atoms _m) := by
  first
    | (refine Classical.byContradiction ?_
       refine (fun (_f1 : (Not (formula_26 _atoms _m))) => ?_)
       have _f2 := (mt (@Or.inl _ _) _f1)
       have _f3 := (mt (@Or.inr _ _) _f1)
       have _f4 : (formula_9 _atoms _m) := (Or.inr _f3)
       have _f5 : (formula_10 _atoms _m) := (Classical.byContradiction (fun _g => _f2 _g))
       have _f6 := _f5.1
       have _f7 := _f5.2.1
       have _f8 := (Or.elim _f7 (fun _g => _g) (fun _g => absurd _g _f3))
       have _f9 : (Not (Not (formula_4 _atoms _m))) := (fun _g => _g _f8)
       exact (False.elim (_f9 _f6.1)))
    | (unfold formula_26 formula_12 formula_10 formula_9 formula_8 formula_7 formula_6 formula_5 formula_4 formula_3 term_2 term_1 term_0

The lemma assumes its clause is false and propagates. It concludes a = b, then contradicts it with _f6.1, the distinct's first pair. _f5.2.1 is the new projection style.

Risks and open questions

  • Projections now use field notation everywhere in the prover. This relies on Lean seeing through the formula definitions. A failure would be loud or fall back to grind, never unsound.
  • If Z3 logs a pair with its sides swapped, the distinct stays one atom. That is no gain, but no regression either.
  • The memory figures come from macOS. CI runs on Linux, where the peak may differ.

What comes next

  • Synthetic atoms for swapped distinct pairs.
  • The mirror problem for false wide disjunctions, whose proof chains still grow quadratically.
  • More memory headroom for a QF_LIA input that peaks at 7.93 GB.

Glossary

assertion
A formula the input claims is true, written (assert ...) in SMT-LIB.
atom
A formula with no Boolean connective at the top, such as (= a b) or (p a c). A prover treats it as one unit.
Boolean
The sort of truth values, true and false, written Bool.
clause
A disjunction of literals. It is true when at least one literal is true.
cnf lemma
A clause Z3 adds while turning formulas into clause form. It must follow from the formulas' Boolean structure alone.
conjunct
One part of a conjunction. In (and x y z), y is the second conjunct.
conjunction
An "and" of formulas. It is true only when every part is true.
disjunction
An "or" of formulas. It is true when at least one part is true.
distinct
The SMT-LIB operator saying all its arguments differ. (distinct a b c) means a ≠ b, a ≠ c, and b ≠ c.
equality
The atom (= a b), true when both sides denote the same value.
grind
A general-purpose Lean tactic that searches for a proof by case splits and congruence reasoning. Powerful but can be slow on big goals.
literal
An atom or its negation, such as (= a b) or (not (= a b)).
projection
Taking one part out of a proof of a conjunction. In Lean, h.1 is the first part and h.2 the rest.
propagation
Deriving truth values step by step from the ones already known. If x or y is true and x is false, then y is true.
QF_UF
The SMT-LIB logic of quantifier-free formulas over uninterpreted sorts and functions with equality.
refutation
A proof that a set of formulas leads to false, so they cannot all hold together.
sort
The type of a value, such as Int, Bool, or a declared sort U.
tactic
A Lean command that builds part of a proof for you, such as unfold or grind.
unfolding
Replacing a defined name by its definition, so a tactic can see inside it.
uninterpreted function
A function symbol with no fixed meaning, only that equal inputs give equal outputs. The predicate p above is one.
