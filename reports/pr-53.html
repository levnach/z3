Prove cnf lemmas over a distinct's pairs by propagation

Pull request #53 on levnach/z3 · MERGED · 2026-10-31T00:09:42Z · loop iteration 53

In one paragraph

The Lean reconstructor now proves more cnf lemmas by propagation instead of by the expensive grind fallback. Before, it treated a distinct over terms as one opaque atom. So a clause whose literal was one pair of that distinct, such as (not (= c2 c3)), named nothing the prover could see. Now the distinct is read as a conjunction of negated equalities, one per pair. A second fix makes the resulting proofs short. Conjuncts of a wide conjunction are now reached through projections from checkpoints bound every 32 conjuncts. On the hardest QF_UF test in CI, Lean's peak memory fell from about 7.1 GB to 5.5 GB. That widens the safety margin under the 8 GB cap that every Lean check runs with.

Background

The pipeline could already certify this kind of refutation. Every cnf lemma has a fallback that unfolds all definitions and calls the tactic grind. That works, but it is slow on large assertions. The test NEQ004_size4 has one assertion with 814 definitions. Its 12 cnf lemmas all took the fallback, about 3 seconds each. This put the file within about 1 GB of the memory cap. The work serves milestone 3 of the plan, equality and uninterpreted functions, and keeps the regression suite within its limits.

What changed

  • A cnf lemma whose literal is one pair of an asserted distinct can now be proved by propagation alone.
  • The prover now reaches deep conjuncts through checkpoints, so a 400-conjunct assertion no longer needs tens of thousands of projections.
  • A distinct whose pair Z3 logged with its sides swapped stays one opaque atom, exactly as before.
  • New tests check the propagation proofs in Lean with the grind fallbacks removed, so a broken proof can no longer hide behind the fallback.
  • The plan document and the examples README describe the new reading of a distinct.

An analogy for the checkpoints: to find page 390 of a long book, you do not count from page 1. You jump to the bookmark at page 384 and count six more. The reconstructor now places such a bookmark, a Lean have, every 32 conjuncts.

Worked example

This input is a small version of the PR's new test UF_WIDE_DISTINCT_CONJUNCTION. It keeps the distinct and the two clauses, but drops the 40 extra predicate applications. All output below comes from real runs of the old and new scripts.

(a) The input

(declare-sort U 0)
(declare-const a U)
(declare-const b U)
(declare-const c U)
(declare-fun p (U U) Bool)
(assert (and (distinct a b c) (or (= a b) (p a c)) (or (= b c) (not (p a c)))))
(check-sat)

Three different values, and two clauses that together force two of them to be equal.

(b) Before

The old pipeline did not reject this input. This PR changes how lemmas are proved, not which inputs are accepted. The pre-PR scripts produced a Lean file that passed the check. But they made no propagation attempt in any of the 4 cnf lemmas. Each was proved only by the fallback:

Every definition is unfolded and grind searches the whole formula. Here that is cheap. On an 814-definition assertion it costs seconds per lemma.

Risks and open questions

  • All of the prover's projections now use field notation, which relies on Lean seeing through the formula definitions. A failure can only make a check fail, never make it unsound.
  • A distinct with a swapped pair gains nothing. This is not a regression.
  • The memory figures come from macOS. CI runs on Linux, where the peak may differ.

What comes next

  • Fix the mirror case: false wide disjunctions still build long chains that grow quadratically.
  • Add synthetic atoms for swapped distinct pairs.
  • Win back memory headroom for a QF_LIA test that peaks at 7.93 GB.

Glossary

assertion
A formula the input states as true, written (assert ...) in SMT-LIB.
atom
The smallest formula that is true or false on its own, such as (= a b) or (p a c).
Boolean
The sort of truth values, true and false, written Bool in SMT-LIB.
clause
A disjunction of literals, for example (or (not A) (not (= a b))).
cnf lemma
A clause Z3 adds while converting formulas to clause form. It holds by the Boolean structure of the formulas alone.
conjunction
An "and" of formulas. Each part is a conjunct.
disjunction
An "or" of formulas. Each part is a disjunct.
distinct
The SMT-LIB operator saying all its arguments differ. (distinct a b c) means a ≠ b, a ≠ c, and b ≠ c.
equality
An atom (= a b) stating that two terms have the same value.
field notation
Lean's dot syntax for taking a part of a proof or structure, such as h.2.1.
grind
A general Lean tactic that searches for a proof by case splits and rewriting. It is powerful but can be slow on big goals.
literal
An atom or its negation, such as p or (not p).
opaque atom
A formula the prover treats as a single unknown truth value, without looking inside it.
projection
Taking one part out of a proof of a conjunction. In Lean, h.1 is the first conjunct and h.2 is the rest.
propagation
Deriving truth values step by step from known ones. If "A and B" is true, then A is true.
QF_UF
The SMT-LIB logic of quantifier-free formulas over uninterpreted sorts and functions with equality.
refutation
A proof that a set of assertions leads to a contradiction, that is, to False.
sort
The type of a value, such as Int, Bool, or a declared sort like U.
tactic
A Lean command that builds part of a proof, such as unfold, exact, or grind.
uninterpreted function
A function symbol with no fixed meaning, only that equal arguments give equal results. p in the example is one that returns a Boolean.
