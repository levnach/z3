In one paragraph

Z3 accepts the exclusive or connective with a single argument, as in (xor p), and reads it as that argument. The reconstructor rejected every certificate whose term graph contained such a node, on both the legacy proof object path and the clause log path. This PR admits the node, renders it as its argument in every Lean definition, proves its two gate clauses, and lets the clause-log exporter build it if a log ever mentions it. A propositional input that Z3 refutes but the pipeline could not certify now yields a Lean refutation with no axioms. Zero or three or more arguments are still rejected, and no previously accepted certificate renders differently.

Background

Before this PR the pipeline certified Boolean inputs over the usual connectives, binary xor, Boolean equality and distinct, and the Boolean if-then-else term, plus a slice of linear arithmetic and uninterpreted functions. The one-argument xor had been a known gap since loop iteration 15, and the z3test corpus file 3434.smt2 was the input it kept out. The work serves Milestone 2 of the plan, the kernel-checked Boolean vertical slice, where every supported input must yield a theorem with no sorry and no solver-oracle axiom.

What changed

Think of xor over a list as asking whether an odd number of its arguments are true. With one argument, the answer is that argument.

  • Reconstructor accepts the node. A one-argument xor passes the arity check in proof_to_lean.py, while the declaration keeps its two-argument sort signature, as in Z3.
  • Lean sees the argument, not the connective. Formulas, congruence steps, and Boolean structures all render (xor p) as p, so Z3's rewrite (= (xor p) p) becomes an identity.
  • The two gate clauses are proved. The Tseitin gate clauses (or (xor p) (not p)) and (or (not (xor p)) p) are accepted as def-axioms and proved from the definition alone.
  • Clause-log exporter can build the node. A helper in proof_clause_log.py builds the one-argument application, which the z3py API lacks, and the gate-clause generator no longer crashes on it. Z3's simplifier removes the node before logging, so these branches serve constructed or future logs.
  • Tests cover the new shape. Unit tests check rendering, arity rejections, gate clauses, and a constructed log. Integration tests push the inputs through both proof cores into Lean.

Worked example

This input is the PR's new UNARY_XOR test case. It uses the one-argument xor under a binary xor, under a negation, and as a whole assertion.

(a) The input

(declare-const p Bool)
(declare-const q Bool)
(assert (xor (xor p) (xor q)))
(assert (not (xor (not p))))
(assert (xor q))

Read with Z3's meaning, the three assertions say p xor q, p, and q, which cannot all hold.

(b) Before the PR

The base-commit exporter produced a certificate, but the base-commit reconstructor stopped at the first one-argument node:

proof_to_lean.py: error: wrong number of arguments at node 1

No Lean file was written. The corpus file 3434.smt2 failed with the same message.

(c) After the PR

The current reconstructor writes a Lean file of 134 lines. Cut lines are marked "...".

Node 1 is (xor p) and node 3 is (xor q). Each is defined as its argument, and node 4 builds the binary xor on top of them.

private theorem rewrite_29 (_atoms : Nat -> Prop)
    : (formula_28 _atoms) := by
  unfold formula_28 formula_1 formula_0
  exact (Iff.intro (fun (_f1 : (_atoms 0)) => (_f1 : (_atoms 0))) (fun (_f2 : (_atoms 0)) => (_f2 : (_atoms 0))))

This lemma is Z3's rewrite (= (xor p) p). After unfolding, both sides are the same proposition, so each direction is the identity function.

The theorem takes the three assertions as hypotheses and derives False. The congruence step rewrites the outer xor argument by argument, using the identity lemmas as pieces.

Lean accepted the file. The check script reported "Lean checks passed", and the file imports only Init. The same run on the corpus file 3434.smt2 also passed.

Review

The reviewer approved with no blocker, major, or minor findings. They confirmed in Z3's rewriter source that one argument gives the argument, and found that live clause logs for seven such inputs never contain the node. They then attacked the change. A tampered certificate and five wrong gate clauses were rejected, and false rewrites such as (= (xor p) q) failed in Lean while the true ones passed.

Two nits came out of this, both fixed in the follow-up commit:

  • Nit 1, an unexplained trick. The helper that builds a one-argument xor first builds and discards a two-argument one, only to borrow its declaration. A comment now says so, lest a reader think the discarded term mattered.
  • Nit 2, dead-looking code. The new clause-log branches are reachable only from a constructed log. Both now say so, so nobody hunts for a live producer.

Risks and open questions

  • Z3's meaning, not SMT-LIB's. The SMT-LIB standard does not define xor with one argument. The Lean theorem states what Z3 read, as the pipeline already does for the one-argument distinct.
  • Gate clauses tested only by a constructed log. Live logs never contain the node. If a future log variant keeps it, a canary input such as (assert (xor p)) in the regression matrix would catch regressions.
  • Lean CI was pending at merge time. The GitHub releaseClang job that runs the Lean tests had not finished when this report was written.

What comes next

  • Fix the legacy core's unsupported arithmetic lemma on integer lattice conflicts, which the stress run exposed.
  • Find a cheaper tie between simplified clauses and the original assertions on the clause-log path, which still uses a solver call at export and a tactic proof in Lean.
  • Continue Milestone 3 work on equality and linear arithmetic, now that the Boolean slice covers every xor arity Z3 can produce.

Glossary

arithmetic (linear)
Constraints over numbers using only addition, subtraction, and multiplication by constants. Example: (<= (+ x (* 2 y)) 5).
arity
The number of arguments a function or connective takes. (xor p q) has arity two, (xor p) has arity one.
Boolean
A value that is either true or false, or a formula that evaluates to one.
certificate
The JSON file the exporter writes from Z3's proof. It lists the declarations, the term graph, and every inference step with its rule name.
clause
A disjunction of literals, such as (or p (not q)). A proof by resolution works on clauses.
clause log
The newer of Z3's two proof formats. The SAT-based core writes each learned clause with a hint, and the exporter replays the log into a certificate.
congruence
If each argument of a term is replaced by an equal one, the whole term stays equal. Example: from p = p' and q = q' conclude (xor p q) = (xor p' q').
declaration
The name, argument sorts, and result sort of a function or connective, as in xor : Bool Bool -> Bool.
def-axiom
Z3's rule name for a clause that holds by the definition of a connective alone, such as a Tseitin gate clause. The reconstructor must prove each one.
Farkas lemma
A result from linear arithmetic: if a set of linear inequalities has no solution, some nonnegative combination of them yields a plain contradiction such as 0 < 0. Solvers use those coefficients as proof hints.
gate clause
One of the small clauses that link a connective to its arguments in a Tseitin encoding. For g = (xor p) they are (or g (not p)) and (or (not g) p).
if-then-else term
Written ite in SMT-LIB: (ite c a b) is a when c holds and b otherwise.
legacy proof object
The older of Z3's two proof formats. The solver builds a tree of proof terms with rule names such as rewrite, monotonicity, and unit-resolution.
literal
An atom or its negation, such as p or (not p).
propositional
Built from Boolean variables and connectives only, with no arithmetic, functions, or quantifiers.
reconstructor
The script that reads a certificate and the original input and writes Lean source for the refutation. Here it is proof_to_lean.py.
refutation
A proof that a set of assertions leads to False, so the assertions cannot all hold at once.
rewrite
A proof step stating that one term equals a simplified form of itself. Example: (= (xor p) p).
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that searches for a proof automatically, such as decide, omega, or grind. The result is still checked by Lean's kernel.
term graph
The shared, numbered representation of all terms in a certificate. Each node names its declaration and points to its argument nodes, so repeated subterms are stored once.
Tseitin encoding
A way to turn a formula into clauses by giving each connective a fresh name and adding gate clauses that tie the name to its arguments.
uninterpreted function
A function symbol with declared sorts but no fixed meaning. The only thing known about it is that equal arguments give equal results.
exclusive or (xor)
The connective that is true when an odd number of its arguments are true. With two arguments it means "exactly one of them". With one argument, in Z3's reading, it is that argument.
