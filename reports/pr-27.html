This PR is not merged. The report describes the change commit b19d7763 on top of base 7bbb9739. The PR holds two commits, and this page covers both.

In one paragraph

Z3 accepts the exclusive or connective with a single argument, as in (xor p), and reads it as plain p. The Lean reconstructor refused every certificate that mentioned such a node, so one known regression input could never be certified. This PR treats a one-argument xor as a Boolean formula equal to its argument. It proves the node's two gate clauses, handles it in congruence and rewrite steps, and lets the clause-log exporter build it. Both the legacy proof core and the clause-log core now yield a Lean refutation for these inputs. The arity check still rejects zero and three or more arguments.

Background

Before this PR the pipeline certified propositional inputs with two-argument xor, plus equality, uninterpreted functions, and linear arithmetic. A one-argument xor failed the arity check on both cores with "wrong number of arguments". The z3test regression 3434.smt2 is exactly (assert (xor false)) and had sat on the backlog since iteration 15. The previous PR handled the one-argument distinct the same way, so this change completes the pattern. The work serves milestone 2, the kernel-checked Boolean slice, which wants every Boolean shape Z3 accepts to reach a Lean theorem without axioms.

What changed

  • Legacy core. A certificate containing (xor p) now reconstructs, and its rewrite step (= (xor p) p) is proved as a plain identity.
  • Clause-log core. A log that mentions a one-argument xor now replays, and the node's two gate clauses become def-axiom steps instead of crashing the exporter.
  • Gate proofs in Lean. The clauses (or (xor p) (not p)) and (or (not (xor p)) p) are each proved by one function application, since the node unfolds to its argument.
  • Everywhere Lean looks. Formula definitions, the propositional rewrite prover, and the congruence builder all render the node as its argument.
  • Tests and docs. The suites gain the new shapes, the verbatim 3434 input, a constructed log that keeps the literal, and arity rejections.

Think of a one-argument xor as a sum with one term. The sum sign is written, but the value is just the term. The reconstructor now reads it that way, as Z3 does.

Worked example

The input is the PR's new UNARY_XOR test case, written as an SMT-LIB file. It uses the one-argument xor under a binary xor, under a negation, and as a whole assertion. The assertions say "p differs from q", "p holds", and "q holds", which cannot all be true.

(a) The input

(declare-const p Bool)
(declare-const q Bool)
(assert (xor (xor p) (xor q)))
(assert (not (xor (not p))))
(assert (xor q))

The pre-PR exporter accepted the input and produced the same certificate as today. The pre-PR reconstructor stopped at the first one-argument xor node and exited with code 2:

The legacy core records the rewrite (= (xor p) p). Since the node unfolds to its argument, the lemma is a two-way identity with no case analysis.

private theorem rewrite_29 (_atoms : Nat -> Prop)
    : (formula_28 _atoms) := by
  unfold formula_28 formula_1 formula_0
  exact (Iff.intro (fun (_f1 : (_atoms 0)) => (_f1 : (_atoms 0))) (fun (_f2 : (_atoms 0)) => (_f2 : (_atoms 0))))

Review

The reviewer approved the PR with no blocker, major, or minor issue. Two nits were fixed in the second commit.

What the reviewer tried. They confirmed in Z3's Boolean rewriter that one-argument xor means the argument. They produced live clause logs for seven such inputs and found that Z3's simplifier removes the node before logging. They tampered with certificates by dropping an argument and by feeding five wrong unary gate clauses. Every tampered input was rejected. They checked that Lean rejects the false rewrite (= (xor p) q) while the true identity (= (xor p) p) passes.

Nit 1: an unexplained trick. To build a one-argument xor, the exporter creates a throwaway two-argument one and takes its declaration, because the Python API only offers the binary form. The code looked odd, so a comment now explains it.

Nit 2: dead-looking branches. The two new clause-log branches are reachable only from a constructed log, since live logs never keep the node. A future reader might hunt for a producer that does not exist. Both branches now say so in a comment.

Risks and open questions

  • Semantics beyond the standard. SMT-LIB does not define a one-argument xor. The Lean theorem states what Z3 reads the input as, like the one-argument distinct before it.
  • Constructed-log coverage only. The clause-log gate clauses for this node are exercised only by a hand-built log. A canary with (assert (xor p)) would catch a future log variant that keeps the node.
  • Everything else is additive. No previously accepted certificate changes its rendering.
  • CI not yet complete. At report time the three jobs that run the new tests were pending.

What comes next

  • The legacy core emits an unsupported arithmetic theory lemma on some integer conflicts when its own Farkas check fails. The stress run found five such inputs. Backlog.
  • One clause-log stress input hit the Lean heartbeat limit on arithmetic lemmas over division and modulo atoms. Backlog.
  • Through the clause-log core, these inputs still tie the simplified clauses to the assertions by cnf lemmas, which cost a solver call at export and a tactic call in Lean.

Glossary

arity
The number of arguments a function or connective takes. (xor p q) has arity two, (xor p) has arity one.
Boolean
A value that is either true or false, or a formula that evaluates to one of them.
certificate
A machine-readable record of the steps a solver took to reach its answer, so that an independent checker can replay them.
clause
A disjunction of literals, such as (or p (not q)). A clause is satisfied when at least one literal is true.
clause log
A step-by-step record of clauses a solver assumed, defined, or derived, written out as it ran. One of the two proof formats this pipeline can replay.
congruence
The rule that equal arguments give equal results. If a = b, then f(a) = f(b). In Lean, lemmas such as or_congr apply it to connectives.
def-axiom
A proof step whose clause is true by the definition of a connective alone, such as a gate clause. Despite the name, Lean proves it rather than assuming it.
exclusive or (xor)
A connective that is true when exactly one of its two arguments is true. With one argument, Z3 reads it as that argument.
Farkas lemma
A result from linear arithmetic: a set of linear inequalities has no solution exactly when a nonnegative combination of them yields a contradiction such as 0 < 0.
gate clause
One of the clauses that links a compound formula to its arguments in a Tseitin transformation. For (xor p) they are (or (xor p) (not p)) and (or (not (xor p)) p).
linear arithmetic
Reasoning about sums of variables times constants, compared with <, <=, or =, over the reals or integers.
literal
An atomic formula or its negation, such as p or (not p).
negation
The connective not, which flips true and false.
proof core
The part of the solver that produces proof evidence. Z3 has two: the legacy core emits a proof object with named rules, and the newer core emits a clause log.
propositional
Built only from Boolean variables and connectives, with no functions, equalities over other sorts, or arithmetic.
refutation
A proof that a set of formulas cannot all be true, ending in False.
rewrite
A proof step stating that one formula equals a simplified form of itself, such as (= (xor p) p).
simplifier
The stage of the solver that rewrites formulas into simpler equivalent ones before search begins.
SMT-LIB
The standard input language for SMT solvers, with commands such as declare-const, assert, and check-sat.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that searches for a proof automatically, such as decide, omega, or grind.
theory lemma
A proof step justified by reasoning in a theory such as arithmetic, often with a hint saying which coefficients or bounds were used.
Tseitin transformation
A method that names each compound subformula with a fresh variable and adds gate clauses tying the name to its arguments, producing clauses of bounded size.
uninterpreted function
A function symbol with no fixed meaning, about which only congruence is known. f(1) and f(2) may or may not be equal.
