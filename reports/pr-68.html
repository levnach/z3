In one paragraph

This PR lets the pipeline certify inputs that use arrays whose index and element sorts are both uninterpreted sorts. This is the QF_AX fragment. Z3's array solver already wrote each axiom instance it used into the clause log. The exporter, the replay, and the Lean reconstructor now read those array lemmas. Lean sees an array as a function, store as a function update, and the extensionality witness as a choice. Every array fact the refutation uses is a theorem proved inside the generated file. So the trust boundary does not move. In a sweep, 23 of z3test's 25 QF_AX benchmarks now verify in Lean. Before this PR, none did.

Background

Before this PR, the pipeline certified Boolean inputs, linear arithmetic over Int and Real, and uninterpreted functions next to them. It rejected any array sort at the very first step. So the 25 QF_AX samples in z3test (storecomm, storeinv, swap) could not be certified, although Z3 solves all of them. This work serves milestone 4 of the plan, "Broader theories and integration", which lists arrays as a distinct extension. It covers only arrays over uninterpreted sorts. Arrays over Int, Real, or Boolean values are still out of scope.

What changed

The change is Python only. No C++ file changed.

  • Exporter. You can now export a certificate for an input that uses select, store, ite over arrays, and equality between arrays.
  • Clear rejections. Unsupported array shapes, such as arrays over Int, constant arrays, or functions over arrays, now fail with a named error.
  • Clause-log replay. The replay now reads array terms and turns each array hint into a clause, the store axiom included.
  • Lean encoding. Each generated file now defines select, store, and the witness, and proves four facts about them before using them.
  • Size control. Long chains of stores stay folded under one name, so large benchmarks no longer produce 28 MB files.

An analogy for store: think of a phone book where you correct one entry. The result is a new book that agrees with the old one on every line but that one. The extensionality witness is the reverse idea. If two books differ, it points at one line where they differ.

Inside the generated file, the tactic grind proves each array lemma. The reconstructor hands it only the few facts that lemma needs. If those facts are removed, grind fails. A new test checks exactly that.

The model gains a family of array constants, each a function from U to U, and a promise that U is not empty.

def _select {U : Type} (a : U -> U) (i : U) : U := a i

noncomputable def _store {U : Type} (a : U -> U) (i v : U) : U -> U :=
  fun _j => @ite U (_j = i) (Classical.propDecidable _) v (a _j)

private theorem _store_apply {U : Type} (a : U -> U) (i v j : U) :
    _select (_store a i v) j = @ite U (j = i) (Classical.propDecidable _) v (_select a j) := rfl

Review

The reviewer approved, with no blocker and no major finding.

  • Minor: a contradictory comment. The reviewer exported a plain QF_UF input with one uninterpreted sort. The Lean file said the sort was the type U, and also said "No uninterpreted sort". A split chain of conditions printed both lines. This touched every published UF certificate, not just arrays. Lean ignores comments, but people read these files. The fix restored one chain, and a new test checks the header lines.
  • Nit: an unused parameter. A helper had an arrays option that no caller used. It was removed. While fixing it, the author found that the helper's walk could leave the set of terms it was given. That could only make Lean fail, never accept a false lemma. The walk now stays inside its set.
  • Nit: a weak negative test. The test that removes the array facts only checked that Lean failed. It could have failed for an unrelated reason. It now requires every Lean error to be a grind failure. On that file there are four, all from grind.
  • Suggestion, not done: a tighter lemma check. An ordinary equality clause could be relabeled as an array lemma. This is harmless because grind must still prove it. The check is left as a follow-up.
  • Suggestion, noted: slow files. Some storecomm files take 60 to 90 s in Lean. That is close to the 120 s probe timeout.

Risks and open questions

  • Two QF_AX benchmarks still fail in the Lean kernel with "(kernel) excessive memory consumption". The failure is in outlined resolution steps, not in array lemmas. No certificate is published for them.
  • Storecomm files with 40 or more stores take 60 to 90 s each. If QF_AX joins a probe corpus, expect timeouts.
  • The replay recognizes the store axiom by its shape. A wrong match can only make Lean fail.
  • Open PR #67, on enumeration datatypes, edits the same functions. A merge conflict is likely, though the features are independent.
  • The sweep of all 25 files ran on the first commit only. The review fixes were not re-swept.

Glossary

array
A map from index values to element values. (Array Index Element) maps each Index to an Element.
axiom
A rule accepted without proof. Here, a rule of the array theory, such as "reading what you just wrote gives back the written value".
Boolean
The sort with exactly two values, true and false. Written Bool in SMT-LIB.
clause
A disjunction of literals, such as a = b or not (p). It holds if at least one literal holds.
clause log
The record Z3's SAT-based core writes while solving. Each line is a clause it learned or used, often with a hint saying why.
congruence
The rule that equal arguments give equal results. If a = b, then f(a) = f(b).
extensionality
The rule that two arrays are equal when they agree at every index.
fragment
A restricted class of inputs, named after an SMT-LIB logic. QF_AX means quantifier-free formulas over arrays.
if-then-else term (ite)
A term that picks one of two values by a condition. (ite p a b) is a when p holds, else b.
kernel
The small core of Lean that checks every proof step. Its memory limit is what the two failing benchmarks exceed.
lemma
A helper fact proved on the way to the main result. Here, each clause a theory solver contributes.
literal
An atomic formula or its negation, such as i = j or not (i = j).
refutation
A proof that a set of assertions leads to False.
resolution
The step that combines two clauses with opposite literals into one clause without them.
select
Reading an array. (select a i) is the element stored at index i.
sort
The type of a value, such as Int, Real, Bool, or a declared sort like Index.
store
Writing an array. (store a i e) is a new array equal to a except that index i holds e.
tactic
A Lean command that builds part of a proof automatically. grind and simp are tactics.
theorem
A statement together with a proof that Lean's kernel has checked.
trust boundary
What must be believed without a check. Here, only Lean's kernel and its three standard axioms, with no sorry and no added axioms.
uninterpreted function
A function symbol with no fixed meaning. Only congruence is known about it.
uninterpreted sort
A sort declared by name only, with declare-sort. Nothing is known about its values except equality.
witness
A concrete value that shows a claim holds. The extensionality witness is an index where two different arrays differ.
