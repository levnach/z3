Certify arrays over uninterpreted sorts (QF_AX) in Lean via clause log

Pull request levnach/z3#68 · State: OPEN · Opened 2026-11-04T02:24:45Z · Loop iteration 68

This pull request is open and not merged. The change under review is commit 6cc300a, which sits on top of one earlier commit in the same PR.

In one paragraph

This PR lets the pipeline certify problems that use arrays whose index and element sorts are both uninterpreted sorts. That is the QF_AX fragment. The refutation travels through the clause log. Each array axiom instance Z3 used becomes a lemma that Lean's grind tactic must prove. In Lean an array is a plain function. select is function application, and store is a one-point update. The extensionality witness is a choice. All four array facts are theorems proved inside each generated file. No sorry and no new axioms are added. On z3test's 25 QF_AX sample benchmarks, 23 now pass in Lean. None did before.

Background

Before this PR, the certificate exporter stopped at any array sort. Every QF_AX input failed with "unsupported sort". The pipeline already handled Boolean structure, uninterpreted functions with congruence, and linear Int and Real arithmetic. Z3's array solver was already writing each axiom instance into the clause log with an array hint. The pipeline did not read those hints yet. This PR serves Milestone 4 of the project plan, "Broader theories and integration". That milestone names arrays as one of the separate extensions.

What changed

  • You can now export a certificate for a QF_AX input with array constants, select, store, an if-then-else term over arrays, and equality between arrays.
  • The clause-log reader now understands array terms, including the extensionality witness (_ array-ext 0).
  • The Lean reconstructor now turns each array lemma into a theorem that grind proves from facts stated in the same file.
  • Long chains of stores now stay as short named terms in each lemma. Think of a footnote instead of copying a paragraph each time. Copying them out made files grow up to 28 MB and exhaust the Lean kernel.
  • Z3 sometimes rewrites stores before solving, for example two writes at one index become one. Those rewrite steps now also check in Lean.
  • Unsupported shapes are rejected with a clear message: arrays over Int, Real, Bool or arrays, multi-index arrays, constant arrays, and functions over arrays.

The code changes are all in Python. No C++ file changed.

Review

The reviewer approved. There were no blockers and no major findings.

  • Minor: a contradictory comment in every UF file. The reviewer reconstructed a plain QF_UF input with no arrays. The Lean header said the sort was _m.U and also said "No uninterpreted sort". A code split had broken one if/elif chain into two. Lean ignores comments, but people read these published certificates. The chain is whole again, and a new test checks the header lines.
  • Nit: an unused parameter. A helper took an arrays flag that no caller passed. It was removed. While fixing it, the author saw that the helper's walk could leave the set of terms it was given. That could only make Lean fail, never accept something false. The walk now stays inside the set.
  • Nit: a weak negative test. The test only checked that Lean failed. It would also pass if Lean failed for an unrelated reason, like a missing name. It now requires every error to be a grind failure.
  • Suggestion, not done: reject an array lemma that mentions no array term. Today a plain equality clause could be relabeled array. That is harmless because grind must still prove it. It is left as a follow-up.
  • Suggestion, noted: the slow storecomm files take 60 to 90 s, close to the probe's 120 s timeout.

Risks and open questions

  • Two QF_AX benchmarks still exhaust kernel memory. This happens in outlined resolution steps, not in array lemmas. Lean rejects them, so no certificate is published.
  • Large storecomm files need 60 to 90 s each in Lean. They would likely time out if added to a probe corpus.
  • The replay recognizes the store axiom by its shape. A wrong match can only make Lean fail.
  • Open PR #67 edits the same functions. A textual merge conflict is likely, though the features are independent.
  • CI results for this PR were unknown when this page was written.

Glossary

array
A value that maps each index to an element, like a table with one row per index. Its sort is written (Array Index Element).
axiom
A fact accepted without proof. Z3's array solver uses array axioms, but here each instance is proved in Lean instead.
Boolean
The sort with exactly two values, true and false.
certificate
A file that records how the solver reached its answer, so another program can check it.
choice (epsilon)
An operator that picks some value with a given property, if one exists. Lean's version is Classical.epsilon.
clause
A disjunction of literals. Example: i = j or (select b j) = (select a j).
clause log
The list of clauses the SAT/SMT core added or derived while solving, each with a hint saying why.
congruence
The rule that equal arguments give equal results: if x = y then f(x) = f(y).
extensionality
The rule that two arrays are equal if they agree at every index.
fragment
A restricted family of formulas, named by an SMT-LIB logic such as QF_UF or QF_AX.
grind
A Lean tactic that searches for a proof using equalities, case splits and given facts.
hint
A label on a logged clause that says which solver part produced it, such as euf, farkas or array.
if-then-else term
A term that picks one of two values by a condition, written (ite c x y) in SMT-LIB.
kernel
The small core of Lean that finally checks every proof.
lemma
A helper fact proved on the way to the main result. A theory lemma is a clause justified by one theory, such as arrays.
literal
An atomic formula or its negation, such as i = j or not (i = j).
QF_AX
The SMT-LIB logic of quantifier-free formulas over arrays with uninterpreted index and element sorts.
refutation
A proof that a set of assertions leads to false, so the assertions cannot all hold.
resolution
The rule that combines two clauses with opposite literals into one clause without them.
rewrite
A step that replaces a term by an equal, simpler one. Example: (store (store a i v) i w) becomes (store a i w).
select
Reading an array: (select a i) is the element of a at index i.
sort
The type of a value, such as Int, Real, Bool, or an array sort.
sorry
A Lean placeholder that skips a proof. A trusted certificate must not contain it.
store
Writing an array: (store a i v) is a new array equal to a except that index i holds v.
tactic
A Lean command that builds part of a proof automatically.
uninterpreted function
A function symbol with no fixed meaning. Only congruence constrains it.
uninterpreted sort
A sort with no fixed meaning, declared with declare-sort. Only equality is known about its values.
witness
A concrete value that shows a claim holds. Here, an index where two unequal arrays differ.
