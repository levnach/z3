In one paragraph

Some Farkas lemmas over the Int sort are wide and have huge coefficients. The reconstructor already knew the linear combination that refutes each of them, yet the Lean proof asked the omega tactic to find that combination again. On such lemmas omega could search for minutes. This PR writes the combination into the Lean proof directly. Each bound becomes a fact that a difference is at least zero. The facts are scaled by their multipliers and added up. Omega only checks that the sum is a negative constant. A QF_LIA refutation that used to time out in Lean after ten minutes now checks in under two seconds. The kernel still checks every step, and no new axiom is added.

Background

Before this PR, every Int theory lemma with coefficients was proved by first | omega | grind, with all its literals and premises in scope. It failed on QF_LIA inputs from the cut_lemmas family, where one clause held 21 bounds with eight-digit coefficients. Lemmas without coefficients, such as a cut, remain out of reach. The work serves milestone 3 of the plan, "Equality and linear arithmetic", which asks for checked certificates for integer linear arithmetic.

What changed

  • A wide Int Farkas lemma with large coefficients is now proved by its own combination, the way you check a receipt by adding the listed items instead of guessing what was bought.
  • Equalities in such a lemma get their multipliers from Gaussian elimination, so they can join the sum too.
  • The new proof is tried only for lemmas with at least 16 bounds and one coefficient of 10000 or more, so small lemmas keep the cheaper omega proof.
  • If the new proof fails, the old proofs still run behind it as fallbacks under first.
  • New tests check that the shipped thresholds reach the two hard lemmas and that every Int Farkas lemma of the documented inputs can be proved by its combination alone.

First, omega proves that the 21 scaled differences add up to −1056, with no hypothesis in scope. Then one term adds the 21 facts "difference ≥ 0" and reaches the contradiction 0 ≤ −1056. The old proof stays as the second branch.

The second wide lemma gets the same shape. Lean accepted the whole file.

Review

The reviewer approved the PR with no blocker and no major finding. Three smaller findings were all fixed before merge.

  • Minor: memory margin on the wide division seed. The reviewer measured Lean's peak memory on an existing test with many wide lemmas. The new proof hit 59 of them, though omega already proved them fast. The peak rose from 8.10e9 to 8.31e9 bytes, close to the 8 GB cap. A small change on the CI machine could then fail that test. The fix added a second gate, a coefficient of at least 10000. Those 59 lemmas have coefficients of at most 780, so they keep omega, and their Lean text is unchanged from before the PR.
  • Minor: no test of the shipped thresholds. Both new Lean tests lowered the threshold to zero. A raised threshold would let the hard input time out again with every test green. A new test now asserts that the default reconstruction holds exactly two combination proofs.
  • Nit: text details. A README line was too long, and the plan said 1.5 s instead of 1.4 s. Both were corrected.

Risks and open questions

  • The two thresholds come from one slow case and one memory-heavy case. A wide lemma with moderate coefficients that omega cannot finish would still go to omega. None has been seen.
  • The new proof costs Lean about 3 MB per lemma, against about 1 MB for omega. The reason is not understood.
  • A new proof that fails falls through to the old branch. One that runs out of heartbeats would not fall through. This was never observed.

What comes next

  • cut_lemma_02_002, from the same family, still exhausts Lean memory on 186 cut lemmas without coefficients. Fixing it needs cut derivations in the hint, which is a C++ change.
  • Farkas lemmas over Real still use grind. A Real version needs order lemmas for rationals.
  • Making the combination cheaper in memory would allow lower thresholds.

Glossary

axiom
A statement Lean accepts without proof. Adding one widens what must be trusted.
bound
An inequality that limits a linear expression, such as x + 2y ≤ 7.
certificate
The proof data Z3 exports, which an independent checker replays step by step.
clause
A disjunction of literals: at least one of them must be true. Example: x ≤ 3 ∨ y > 5.
coefficient
The constant number that multiplies a variable, such as 66760014 in 66760014 * x8.
cut
A new inequality derived by rounding, which is valid for integers but not for reals.
Farkas lemma
A theory lemma saying some bounds cannot all hold, because a linear combination of them gives 0 ≤ negative number. Example: x ≥ 1 and x ≤ 0 add up to 0 ≤ −1.
Gaussian elimination
The school method for solving linear equations by eliminating one variable at a time.
grind
A general Lean tactic that combines case splits, congruence, and arithmetic.
heartbeat
Lean's unit of work. A proof that uses more heartbeats than allowed stops with an error.
kernel
The small trusted core of Lean that checks every finished proof term.
linear combination
A sum of facts, each multiplied by a constant. Example: 2 · (first fact) + 3 · (second fact).
literal
An atomic formula or its negation, such as x ≤ 3 or ¬(x ≤ 3).
multiplier
The constant by which a fact is scaled in a linear combination. It is positive for an inequality and may be negative for an equality.
omega
A Lean tactic that decides linear arithmetic over Int and Nat. It searches for a contradiction by itself.
premise
A fact a proof step takes as input, as opposed to the conclusion it derives.
QF_LIA
The SMT-LIB logic of quantifier-free linear integer arithmetic: Int variables, constants, sums, and comparisons.
refutation
A proof that a set of formulas leads to False, so they cannot all be true together.
sort
The type of a value in SMT-LIB, such as Int, Real, or Bool.
tactic
A Lean command that builds part of a proof automatically, such as omega or decide.
theory lemma
A clause that holds by the rules of a theory, here integer arithmetic, rather than by Boolean logic alone. Z3 records it as a th-lemma.
