Prove wide large-coefficient Int Farkas lemmas by their combination

Pull request levnach/z3 #51 into master · State: OPEN · Opened 2026-10-30T20:20:58Z · Loop iteration 51

This pull request is open and not merged. The change under review is commit 590ec5796, which sits on top of an earlier commit of the same PR.

In one paragraph

This PR changes how the reconstructor proves large Farkas lemmas over the sort Int. Before, the omega tactic searched again for a linear combination of the bounds that the reconstructor had already found. Now, when a theory lemma has at least 16 bounds and a coefficient of 10000 or more, the reconstructor writes the combination into the proof itself. Omega then only confirms that a weighted sum equals a negative constant. On one crafted QF_LIA benchmark, the Lean check went from a 600-second timeout to 1.4 seconds. The old proofs stay behind the new one as a fallback. No new axiom is added, so the trusted base is unchanged.

Background

Before this PR, the pipeline already produced certificates for QF_LIA problems and turned them into Lean refutations. Every Int Farkas lemma with coefficients was proved by first | omega | grind, with every bound in scope. That works well for small lemmas. It broke down on cut_lemma_03_012, a crafted benchmark from the SMT-LIB sample. Two of its lemmas are clauses of 21 literals over twenty variables, with seven- and eight-digit coefficients. Each ran past 150 seconds on its own, so the whole certificate never checked. This work serves milestone 3 of the plan, "Equality and linear arithmetic".

What changed

  • A wide Int Farkas lemma with large coefficients now gets a direct proof, so Lean checks arithmetic instead of searching for it.
  • Each bound becomes a fact of the form 0 <= upper - lower, and the facts are scaled by integer multipliers and summed in one proof term.
  • Equalities inside such a lemma also work, because their multipliers are now solved by Gaussian elimination.
  • The direct proof is tried first, and only on lemmas with at least 16 bounds and a coefficient of at least 10000, so small lemmas keep the cheaper omega proof.
  • The benchmark cut_lemma_03_012 now checks in Lean, and it ships as test data with tests that pin both thresholds.

An analogy: before, Lean was a teacher who threw away the student's worked solution and solved the problem again. Now the teacher only checks the arithmetic in it. The main new function is _farkas_combination. No C++ code changed.

Review

The reviewer approved with no blockers and no major findings. The hint's numbers only shape a proof that Lean's kernel checks. So a wrong multiplier can make the attempt fail, but never succeed falsely. All three findings were fixed in the second commit.

Minor: the new proof also hit lemmas that did not need it

The reviewer measured Lean's peak memory on an existing stress test. With only the 16-bound gate, 59 of its small-coefficient lemmas took the new, more memory-hungry path. Its headroom under the 8 GB cap shrank from about 0.47 GiB to 0.27 GiB. A slightly different CI machine could then fail with "excessive memory consumption". The fix added the second gate, a coefficient of at least 10000. The stress test now gets no combinations, and its Lean text is identical to before.

Minor: no test pinned the shipped thresholds

Both new Lean tests lower the thresholds to zero. Raising a threshold above 21 would have kept every test green while the benchmark timed out again. A new quick test now asserts that the benchmark gets exactly two direct combinations at the defaults.

Nit: wording

A README line was too long, and the plan said 1.5 s instead of 1.4 s. Both were corrected.

Risks and open questions

  • Both thresholds come from one slow case and one memory-bound case. A wide lemma with moderate coefficients that omega cannot finish would still go to omega. None has been seen.
  • The new proof costs about 3 MB of Lean memory per lemma, against about 1 MB for omega. Nobody yet knows why.
  • A combination that fails to elaborate falls through to the old proofs. One that ran out of heartbeats would not, but this was never observed.
  • CI had not finished when this page was written.

What comes next

  • The sibling benchmark cut_lemma_02_002 still exhausts Lean's memory on its 186 cut lemmas, which carry no coefficients. Fixing it needs cut derivations in the hint, which is a C++ change.
  • Farkas lemmas over Real still use grind. A Real version of the direct proof needs order lemmas for rationals.
  • Making the direct proof cheaper in memory would allow lower thresholds.

Glossary

axiom
A statement Lean accepts without proof. Every axiom is something the reader must trust.
bound
An inequality or equality between two linear expressions, such as x + 2y <= 5.
certificate
The file Z3 exports with the evidence for an unsat answer, which the reconstructor turns into Lean.
clause
A disjunction of literals, read as "at least one of these holds", such as a ∨ ¬b ∨ (x > 3).
coefficient
A number that multiplies something. In a Farkas hint, each bound gets one, such as 25553563.
cut
An integer reasoning step that rounds a bound to the nearest integer value, such as turning 2x <= 3 into x <= 1.
elaboration
Lean's step that turns the written proof into a fully explicit term before the kernel checks it.
fallback
A proof that runs only if the one before it fails. Lean's first | A | B tries A, then B.
Farkas lemma
A theory lemma saying some linear bounds cannot all hold. Its proof multiplies each bound by a nonnegative number and adds them up to get something false, such as 0 <= -1.
Gaussian elimination
The school method for solving linear equations by cancelling one variable at a time.
grind
A general Lean tactic that combines equality reasoning, case splits, and arithmetic.
heartbeats
Lean's work counter. A proof that uses more than its heartbeat budget stops with an error.
kernel
The small core of Lean that checks every finished proof. It is the part that must be trusted.
linear combination
A sum of things each multiplied by a number, such as 3·A + 5·B.
literal
An atomic formula or its negation, such as x <= 4 or ¬(x <= 4).
multiplier
The number a bound is scaled by in a linear combination. For inequalities it must be nonnegative.
omega
A Lean tactic that decides linear arithmetic over integers and natural numbers.
proof term
A proof written as one expression, like a function call, instead of a sequence of tactic steps.
QF_LIA
The SMT-LIB logic of quantifier-free linear integer arithmetic: integer variables, addition, multiplication by constants, and comparisons.
refutation
A proof that a set of assertions leads to False.
sort
The type of a value in SMT-LIB, such as Int, Real, or Bool.
tactic
A Lean command that builds part of a proof automatically, such as omega.
theory lemma
A clause that is true because of a theory such as arithmetic, not because of Boolean logic alone. Z3 records it as a th-lemma with a hint.
