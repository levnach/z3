In one paragraph

This PR shrinks the Lean files written for problems with arrays. Before, every array fact and if-then-else term gate in a theory lemma was written out in full. Now these facts name the shared definitions (term_N and formula_N) instead. Each lemma opens them with the unfold tactic only where needed. On a test with nested ite chains stored in an array, the file drops from 57 MB to 0.74 MB, and Lean accepts it. The trust boundary does not move. Every array fact is still a hypothesis proved in the file. More array refutations in the logic QF_AUFLIA can now reach a checked certificate.

Background

Iterations 099 to 105 folded ite gates over definitions, but only without arrays. With arrays, each store, select, and gate copied out every nested if-then-else term. Over a shared DAG, that text grows exponentially with nesting depth. On z3test's cvc/dlx-regfile, reconstruction was still printing after five minutes. This work belongs to milestone 4 of the project plan, "Broader theories and integration", which lists arrays as one of the extensions.

What changed

  • Array facts about stores, reads, witnesses, and defaults now name shared definitions, so their size no longer explodes with depth.
  • Folded ite gates, once skipped whenever arrays appeared, now work in array lemmas too.
  • Each lemma sets these facts aside, unfolds the definitions it needs, and brings the facts back.
  • The terms the array facts mention join the unfold list, so Lean still sees an index or stored value hidden inside an array term.
  • New tests use nested ite chains through arrays in six ways and check size and Lean acceptance.

Think of a recipe that says "add the sauce from step 3" instead of copying the sauce recipe into every step. Facts over only variables, constants, numerals, or array terms are printed as before. The old written-out helpers became unused and were deleted.

Worked example

The input comes from the PR's new generator, array_chain_instance(8, "value"). One chain's result is stored in an array, and another chain's equal result is compared with what is read back.

(a) The input

(set-logic QF_ALIA)
(declare-const x Int)
(declare-const i Int)
(declare-const A (Array Int Int))
(declare-const M (Array Int Int))
(define-fun a1 () Int (let ((s (+ x 5))) (ite (< s 17) s (- s 17))))
(define-fun a2 () Int (let ((s (+ a1 5))) (ite (< s 17) s (- s 17))))
; ... a3 to a8 repeat this line, each adding 5 to the one before
(define-fun b1 () Int (let ((s (+ x 10))) (ite (< s 17) s (- s 17))))
; ... b2 to b4 repeat this line, each adding 10 to the one before
(assert (and (<= 0 x) (< x 17)))
(assert (= M (store A i a8)))
(assert (not (= (select M i) b4)))
(check-sat)

Eight steps of +5 and four steps of +10 both add 40, so reading back a8 must equal b4. The real file has 21 lines. The two comments stand for 9 repeated lines cut here.

The reviewer approved with no blockers or major findings. They confirmed that the new size test fails on the old code and without the new unfold roots. Six extra array shapes of their own all passed Lean.

Stale README. The reviewer read the docs beside the code. They still said gates are folded only without arrays, which would mislead someone debugging an array lemma. The README now describes the folded array facts and the extra unfold roots.

Missing blank line. Two plan paragraphs ran together in Markdown. A blank line now separates them.

Fact order. Comparing old and new output, the reviewer saw that plain array facts had moved after the enumeration facts. This was harmless logically, but it weakened the "byte-identical" claim. The facts are back in their old place, and identity was re-measured.

More shapes. The tests covered only stores and reads. The reviewer asked for a constant array value, a Boolean element, and an ite over arrays. All three were added and are Lean-checked at depth 6.

Risks and open questions

  • The extra revert, unfold, and intro steps add kernel work per array lemma. Facts over plain variables stay unreverted for this reason.
  • With arrays, ite gates are now always folded, even when they are small. The known array inputs still pass.
  • cvc/dlx-regfile still does not verify. Lean hit the 12 GB limit on its 44 MB file, which is full of gates in congruence (euf) lemmas.
  • The large QF_AUFLIA swap files are unchanged by this PR.

What comes next

  • Drop ite gates from euf lemmas, or emit them only where arithmetic needs them.
  • Fold Boolean arguments and cast facts with arrays too, which the new unfold roots should make safe.

Glossary

array
A value that maps each index to an element, like a table with one row per index. In SMT-LIB its sort is written (Array Int Int).
Boolean
The sort with exactly two values, true and false. SMT-LIB calls it Bool.
certificate
A file of evidence that a result is correct, which a separate checker can verify without trusting the solver.
congruence
The rule that equal inputs give equal outputs: if a = b then f(a) = f(b). Z3's euf lemmas use it.
constant array
An array that holds the same element at every index, written ((as const (Array Int Int)) 0).
DAG (directed acyclic graph)
A tree in which identical subterms are stored once and shared. Writing a shared DAG out as plain text copies each shared part again.
definition
A name given to a term or formula, such as term_200, so later lines can refer to it instead of repeating it.
hypothesis
A fact available inside a proof. In Lean, have h : P := proof adds one.
if-then-else term (ite)
A term that picks one of two values by a condition. (ite (< s 17) s (- s 17)) is s when s < 17, else s - 17. An ite gate is the fact "if the condition holds, the term equals the first branch", plus the matching fact for the second branch.
kernel
The small, trusted core of Lean that checks every proof step in the end.
lemma
A proved statement used as a step toward a larger proof.
logic (SMT-LIB)
A named fragment of SMT-LIB. QF_AUFLIA means quantifier-free formulas with arrays, uninterpreted functions, and linear integer arithmetic.
refutation
A proof that a set of assertions leads to a contradiction, so they can never all be true.
select
Reading an array: (select a i) is the element of a at index i.
sort
The type of a value, such as Int, Real, or Bool.
store
Writing an array: (store a i v) is a new array equal to a except that index i holds v.
tactic
A Lean command that builds part of a proof automatically. revert moves a hypothesis back into the goal, intro brings it out again, and omega and grind search for proofs.
theory lemma
A clause that holds because of a theory, such as arithmetic or arrays, rather than by Boolean logic alone.
trust boundary
The line between what must be trusted, such as the Lean kernel, and what is checked, such as every fact in the generated file.
unfold
The Lean tactic that replaces a defined name with its body, for example term_200 with its ite expression.
