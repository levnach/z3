This pull request is not merged. The change under review is commit cd4cdbb. It has two commits on top of base 8927ff9.

In one paragraph

When a certificate uses the array theory, the Lean file now writes each array fact by naming shared definitions instead of copying every term out in full. Before, the index and the value of every store were expanded down to the variables. Over a DAG of nested if-then-else terms, that text grew exponentially. A small 21-line input produced 57 MB of Lean, far too much to check. Now the same input gives 0.74 MB, and Lean accepts the refutation. The ite gates of each theory lemma are folded the same way when arrays are present. The trust boundary does not move. Every array fact is still proved inside the file.

Background

Iterations 99 to 105 already folded ite gates over definitions, but only for certificates without arrays. With arrays, the reconstructor still wrote out every select and store fact in full. A rescan of the QF_AUFLIA samples in z3test found the file cvc/dlx-regfile. Z3 proves it in 0.04 s, but reconstruction was still rendering facts after five minutes. The PR serves milestone 4 of the plan, "Broader theories and integration", which lists arrays as a separate extension. It also feeds the regression scans that the plan treats as the top priority.

What changed

  • Array facts in a lemma now name the term_N and formula_N definitions they mention, so their size no longer explodes with nesting depth.
  • Facts that name a definition are set aside with revert, then the definitions are unfolded once, then the facts come back with intro.
  • The nodes the facts mention are added to that unfold list, because the unfold does not look inside array terms.
  • Ite gates are now folded in certificates with arrays too, and the old written-out helpers were removed.
  • New tests generate nested ite chains used through an array in six ways and check size limits and Lean acceptance.
  • The README and the plan document describe the new layout and its measurements.

Think of a spreadsheet. Each step of the chain uses the previous cell three times. Copying the formulas in full makes each step three times longer. Writing =B7 instead keeps every cell short. The revert, unfold, intro sequence is like picking up your notes, rewriting the cell references in all of them at once, and putting them back.

Worked example

This input comes from the PR's own generator, array_chain_instance(8, "value"). It is 21 lines, not ten, because each of the eight chain steps needs its own line. Each step adds 5 and wraps around at 17, written as an ite. The eighth step is stored into array A. A read of the result must differ from a second chain that reaches the same value.

Review

The reviewer approved the change with no blockers and no major findings. They first confirmed the new size test fails on the old code, at 57 MB, and fails again if the extra unfold roots are removed. They also built six array shapes beyond the tests, and all passed Lean.

  • Minor, stale README. The README still said gates are folded only without arrays. A reader debugging an array lemma would have been confused by the new revert and unfold lines. The gate and array paragraphs were rewritten. Fixed.
  • Nit, missing blank line. In the plan document, the tests paragraph ran into the "Still open" paragraph when rendered as Markdown. A blank line was added. Fixed.
  • Nit, fact order. The facts that stay written out had moved after the enumeration facts. This changed no proofs, but it made the "byte-identical output" claim false for certificates with enumerations. The facts now return to their old position, and the identity counts were measured again. Fixed.
  • Suggestion, more array shapes. Only stores and reads of stores were tested. The reviewer proposed a constant array, a Boolean element, and an ite over arrays. All three became new generator cases, Lean-checked at depth 6. Done. The author also corrected one detail of the review about which kinds of read facts the ite case produces.

Risks and open questions

  • Revert, unfold, and intro add some kernel work per lemma. Facts over plain variables, constants, and numerals are not reverted, which limits the cost.
  • With arrays, ite gates are now always folded, even where ites are small. The documented array inputs and generators all pass.
  • dlx-regfile still does not verify. It now reconstructs in 6.5 s, but its 44 MB file hit the 12 GB memory limit in Lean. Most of its text is ite gates in its 803 EUF lemmas.
  • Two other kinds of facts are still written out with arrays: Boolean argument facts and cast facts.
  • The large QF_AUFLIA swap files, 66 to 250 MB, are unchanged by this PR.

What comes next

  • Drop ite gates from EUF lemmas, or emit them only where a lemma's arithmetic needs them, to bring dlx-regfile within reach.
  • Fold Boolean argument facts and cast facts with arrays too, which the new unfold roots should make safe.

Glossary

array
A sort whose values map indices to elements, written (Array Int Int) in SMT-LIB. In Lean it becomes a function.
Boolean
The sort with the two values true and false, written Bool.
certificate
The proof data Z3 exports for an unsat result, which the reconstructor turns into a Lean file.
constant array
An array with the same element at every index, written ((as const (Array Int Int)) 0).
DAG
Directed acyclic graph. Here, terms that share subterms, so one subterm may be used many times.
definition
A name given to a term or formula, such as define-fun in SMT-LIB or def term_41 in Lean.
EUF
The theory of equality with uninterpreted functions. Its lemmas follow from congruence, the rule that equal arguments give equal results.
grind
A Lean tactic that combines case splits, congruence, and arithmetic to close a goal automatically.
if-then-else term (ite)
A term that picks one of two values by a Boolean condition, written (ite c a b).
ite gate
In this project, a pair of facts about an ite: if the condition holds the ite equals its first branch, otherwise its second.
kernel
The small trusted core of Lean that rechecks every finished proof.
lemma
A small proved statement that a larger proof uses as a step.
refutation
A proof that a set of formulas cannot all be true, ending in False.
revert and intro
Lean tactics. revert moves facts back into the goal, and intro takes them out again as named facts.
select
Reading an array at an index, written (select A i).
sort
The type of a value, such as Int, Real, or Bool.
store
A new array equal to an old one except at one index, written (store A i v).
tactic
A Lean command that builds part of a proof, such as unfold or grind.
term
An expression that denotes a value, such as (+ x 5).
theory lemma
A clause that holds because of a theory such as arithmetic or arrays, not because of propositional logic alone.
trust boundary
The line between what Lean checks and what it must take on faith. Here, nothing new is taken on faith.
unfold
A Lean tactic that replaces a defined name by its body, such as term_41 by its ite.
