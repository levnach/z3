Certify Bool-argument uninterpreted functions in QF_UF refutations

Pull request levnach/z3 #6 Merge commit 89a4c55 Merged 2026-10-13T00:50:45Z Loop iteration 6

In one paragraph

Before this change, the QF_UF slice of Z3's native proof certificates rejected every uninterpreted function or predicate with a Bool argument, such as (declare-fun f (Bool) U). These signatures are typical of hardware-derived QF_UF benchmarks and were the first item on the project backlog. The pull request admits them without touching the solver: the Lean theorem gains one quantified map _bool : Prop -> _U, each Boolean argument p is rendered as _bool p, and the exporter and reconstructor accept the matching declarations. It also closed an unrelated gap: Z3's SAT core logs an internal "true" variable as a phantom constant k!0 whenever a Boolean unit is asserted, which made the exporter reject plain QF_UF inputs with a negated unit assertion. Every new input verifies in Lean under the three standard axioms.

Background

The project's goal, stated in the plan document, is unsat results from Z3 that an independent Lean checker accepts without trusting the solver. Z3 produces evidence, either a legacy proof object or a clause log from its sat.smt core. A Python exporter replays that evidence against the original SMT-LIB input and saves a JSON certificate. A reconstructor turns the certificate into Lean source with one lemma per inference step and a final theorem that the assertions imply False. Lean's kernel checks that source, and only a successful check publishes the artifact.

The work sits in milestone 3 of the plan, "Equality and linear arithmetic", which asks for each fragment to be completed end to end before another is added. Iterations 2, 4, and 5 built the QF_UF slice: congruence lemmas discharged by Lean's grind tactic, ite terms over an uninterpreted sort, and many sorts collapsed onto one Lean carrier type _U through a disjoint-union soundness argument. This iteration adds Bool in argument positions.

The soundness argument extends that collapse by one sort. The theorem quantifies over every type and every indexed family of functions, so any model of the input is one instance of it. With Bool as one more sort, the model's two truth values join the disjoint union and _bool picks them classically. Nothing states that _bool True and _bool False differ; the lemmas use only the congruence p <-> q -> _bool p = _bool q, which grind proves through propext.

What changed

Exporter and fragment classification

The signature check now allows Bool among a function's or predicate's arguments; Real arguments and results stay rejected. One explicit refusal was added: a function whose arguments are all Bool, in an input with no uninterpreted sort, is rejected with a message naming the symbol. Z3 Ackermannizes such functions with fresh symbols the clause log cannot tie to the input, so no honest certificate is possible yet.

Clause-log replay

When a Boolean unit is asserted, Z3's goal2sat component logs its internal "true" SAT variable, which has no expression behind it, as a fresh nullary Bool constant k!0 and assumes it as a unit clause. The replay now treats such a log-declared constant named k!<n>, absent from the input, as a phantom and drops the assume and del commands over it. Dropping a clause can only remove support for a later propagation step, which then fails explicitly. Any inference or definition that mentions a phantom is still rejected.

Lean reconstruction

Every QF_UF definition and lemma gained the _bool binder, and each application argument is rendered as a term or as (_bool formula) according to its declared sort. Predicate applications now count as theory nodes, so a rewrite over one goes to grind rather than to the propositional truth-table lemma. Finally, every grind lemma first states excluded middle for each Boolean argument it reaches, because Z3's egraph knows every Boolean argument is true or false once assigned. Without these helpers, 5 of 40 random instances failed in grind; with them, none did.

Tests and documentation

New tests cover classification, two hand-pinned clause-log replays, two documented inputs verified live in Lean, a random generator with five pinned seeds, and a live check that the raw clause log contains k!0 while the certificate does not. The READMEs and the plan document describe the new binder, its trust boundary, and the phantom rule.

Review

  • Minor (fixed). The integrator confirmed this with a three-run probe, dropped the set-logic line from both inputs, and made both live tests assert that the raw log contains k!0 before asserting that the certificate does not.

Risks and open questions

  • Every QF_UF theorem changed shape. The _bool binder is present even when no Boolean argument exists. The full suite and the stress runs over the older generators cover this; propositional and QF_LRA output is unchanged.
  • The soundness of _bool is documented, not formalized. It is the same kind of frontend-encoding argument as Real-as-Rat and the many-sorted collapse.
  • Phantom dropping applies to every fragment that uses the clause log. It can only make a later step fail explicitly, and it is keyed narrowly on log-declared nullary Bool constants named k!<n> absent from the input. It is still a silent deletion, documented as part of the trust boundary.
  • The live phantom tests depend on solver behaviour. Why (set-logic QF_UF) suppresses the phantom was not tracked down. If a solver change stops logging it, the two live tests fail with a clear message.
  • Level-0 substitution. Z3 substitutes units into Boolean arguments before internalization even with value propagation disabled. Where this happens was not identified.
  • Proof cost. The helpers add one have per Boolean argument to each grind lemma. Stress lemmas stayed under a second; larger instances were not measured.
