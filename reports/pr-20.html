In one paragraph

Native arithmetic verification now keeps strictness on each linear row. A zero coefficient no longer supplies strictness, and a strict premise cannot make a separate consequent strict. This prevents false acceptance of arithmetic hints while preserving valid refutations. The Lean verification boundary is unchanged.

Background

The native checker used a shared flag while accumulating arithmetic evidence. That flag survived multiplication by zero and also applied to rows that had not received a strict inequality. A satisfiable set of premises could therefore appear contradictory. This is a correction to native checker correctness, not an expansion of the supported theory fragments or a change to ordinary solver search.

What changed

  • Each inequality carries its own strictness through native verification.
  • Zero-weight contributions cannot create a strict contradiction.
  • Row combinations and equality elimination retain genuine strictness.
  • A bound proof still succeeds when either row independently gives a contradiction.

Worked example: reject a false arithmetic hint

This native proof log claims a contradiction from a satisfiable assumption. It is intentionally an invalid proof, not a newly supported input fragment.

(declare-fun x () Real)
(declare-fun farkas (Int Bool) Proof)
(assume (< x 0.0))
(infer (farkas 0 (< x 0.0)))

The Farkas hint gives the premise zero weight. Its weighted row is non-strict zero, not a strict contradiction.

Before

The unfixed executable accepted the hint as native evidence:

(proofs +farkas 1)

After

The rebuilt executable reports rejection and a countermodel. These excerpts come from the actual replay output:

(proofs -farkas 1)
did not verify: l_true
...
(define-fun x () Real
  (- 1.0))

The second regression is a bound hint whose separate consequent is non-strict zero. Both of its literals hold at the same countermodel:

(bound 1 (< x 0.0) 1 (<= (- x x) 0.0))

Native rejection is a diagnostic, not a changed process-exit convention. The checks inspect the negative verification counter and rejection text. The proof exporter independently refuses the satisfiable source:

proof_certificate.py: error: sat: no unsat proof exists

Positive control: a genuine strict refutation still checks

The following input passed native Farkas and RUP replay without SMT fallback, and its generated Lean file also passed.

(set-logic QF_LRA)
(declare-const x Real)
(declare-const y Real)
(assert (< (+ x y) 0.0))
(assert (>= x 0.0))
(assert (>= y 0.0))

Review

A positive control exposed a completeness regression in the first draft: a genuinely contradictory premise was sent to SMT fallback. Checking both rows independently restored native verification. A regression and live replay cover that case. No findings remain open in the row-strictness change.

Risks and open questions

Strictness must survive valid combinations and equality elimination, but disappear with a zero contribution. Positive and negative regressions cover both requirements. Zero coefficients remain legal when other premises provide genuine evidence. No proof formats, theory fragments, or Lean assumptions change.

What comes next

Separate malformed implied-equality hints remain a backlog item. This repair makes no claim that every native arithmetic rule is complete. Lean continues to check its own proof obligations independently.

Glossary

Coefficient
A numeric weight multiplying a premise in an arithmetic combination.
Countermodel
A valuation demonstrating that the alleged contradiction is not justified.
Farkas hint
Coefficients proposing a linear combination of arithmetic premises that yields a contradiction.
Hint
Native evidence suggesting how an inference can be checked, not permission to trust it.
Linear row
A weighted sum of terms and a constant compared with zero.
Premise
A proposition used to justify an inference.
Refutation
A proof deriving contradiction from the input assertions.
RUP
Reverse unit propagation, checking a clause by propagating the negation of its literals.
SMT fallback
A solver-based diagnostic used when the native proof-rule checker cannot verify a claim.
Strictness
The distinction between a strict inequality such as < and a non-strict inequality such as <=.
