In one paragraph

This PR makes the generated Lean proof terms smaller without changing any statement. Three wordy patterns are replaced by shorter ones that say the same thing. A negated literal removed in a resolution step now uses one library function instead of a double-negation wrapper. A lemma used only once is applied where it is used, instead of first getting its own let-binding. Each proof by contradiction in classical lemmas now goes through one shared helper theorem. Lean's memory grows with the text it must elaborate, so smaller text means less memory. As a result, a large integer difference logic refutation now fits under Lean's 8 GB memory cap and is certified for the first time. An array theory input now verifies too.

Background

Before this PR, the pipeline could already turn these inputs into Lean. Lean then ran out of memory while checking them. The QF_IDL input DTP_k2_n35_c245_s9 had failed in every loop iteration so far. It produced 32.2 MB of Lean and stopped after 13,579 of its 16,557 lemmas. The earlier PR in iteration 112 found that memory tracks the size of the proof text. This PR attacks that size directly. It serves milestone 3, linear arithmetic with checked certificates, and the array inputs of milestone 4.

What changed

All code changes are in the Lean reconstructor, proof_to_lean.py.

  • A unit proof of p can now cut (not p) from a clause with Lean's Or.neg_resolve_left or Or.neg_resolve_right, with no lambda wrapper.
  • A lemma that one other step uses exactly once is now written inline at that use, like pasting a phone number instead of saving a contact you will call once.
  • Classical lemmas now prove by contradiction through one helper, classical_by_contradiction, instead of a separate decidability witness per formula.
  • The helper rests on the same axiom as before, Classical.choice, so the trust story is unchanged.
  • A new slow test now checks that the 14 KB QF_IDL input verifies under the 8 GB cap.

If a rewrite pattern is not found exactly once, the old text is kept. Lean re-checks every rewritten term, so a wrong rewrite would be rejected, not trusted.

Worked example

This PR does not make any tiny input newly certifiable. The only newly certified inputs are large, and their old failure was running out of memory. So this section shows a tiny input that both versions accept, and the exact text that changed. Both outputs below come from real runs of the old and new scripts.

(a) The input

(declare-const p Bool)
(declare-const q Bool)
(declare-const r Bool)
(assert (or (not q) p (not r)))
(assert q)
(assert r)
(assert (not p))
(check-sat)

The first clause is falsified once q, r, and not p are all asserted.

(b) Before

The pre-PR scripts accepted this input. They printed Lean checked the refutation. Their final step was: 

    (False.elim (((_step_10.resolve_left (fun _literal => _literal _step_12)).resolve_left _step_11) _step_13))

To remove (not q), the old code wrapped the proof of q in a lambda that turns q into "not not q".

The real pre-PR failure was on the 48-line QF_IDL file, which is too large to show here. The PR records that Lean stopped after 13,579 of its 16,557 lemmas under the 8 GB cap. That run was not repeated for this report.

(c) After

def formula_0 (_atoms : Nat -> Prop) : Prop := _atoms 0
def formula_1 (_atoms : Nat -> Prop) : Prop := (Not (formula_0 _atoms))
...
def formula_5 (_atoms : Nat -> Prop) : Prop := (Or (formula_1 _atoms) (Or (formula_2 _atoms) (formula_4 _atoms)))
def formula_6 (_atoms : Nat -> Prop) : Prop := (Not (formula_2 _atoms))
...

Each subformula gets a name. Atom 0 is q, atom 1 is p, and atom 2 is r.

theorem unsat (_atoms : Nat -> Prop)
    (_h0 : (formula_5 _atoms))
    (_h1 : (formula_0 _atoms))
    (_h2 : (formula_3 _atoms))
    (_h3 : (formula_6 _atoms))
    : False :=
  ...

The theorem says that the four assertions together imply False. It is unchanged by this PR.

  let _step_15 : (formula_14 _atoms) :=
    (False.elim (((_step_10.neg_resolve_left _step_12).resolve_left _step_11) _step_13))
  _step_15

Now the proof of q cuts (not q) directly, with no lambda.

Lean accepted this file. check_lean.sh printed Lean checks passed.

The other two changes only appear in larger proofs. Here is one lemma from the PR's new test input, DTP seed 1, before the PR:

private theorem proof_step_904 {_atoms : Nat -> Prop} {_vars : Nat -> Int}
    (_inputs : Inputs _atoms _vars)
    : (formula_881 _atoms _vars) :=
  let _df881 := Classical.propDecidable (formula_881 _atoms _vars)
  let _step_899 := proof_step_899 _inputs
  ...
    (False.elim (_step_901 (_step_899.resolve_left _hyp882)))
  (@Decidable.byContradiction (formula_881 _atoms _vars) _df881 _step_903)

The old lemma binds a witness and an import, and each is used once.

private theorem classical_by_contradiction {p : Prop} (h : Not p -> False) : p :=
  @Decidable.byContradiction p (Classical.propDecidable p) h
...
private theorem proof_step_904 {_atoms : Nat -> Prop} {_vars : Nat -> Int}
    (_inputs : Inputs _atoms _vars)
    : (formula_881 _atoms _vars) :=
  ...
    (False.elim (_step_901 ((proof_step_899 _inputs).resolve_left _hyp882)))
  (classical_by_contradiction _step_903)

Now the helper is stated once, and the imported lemma is applied right where it is used.

Review

The reviewer approved. There were no blocker, major, or minor findings. Two nits and two suggestions came up.

  • Nit: a dead sentinel term. The reviewer read the resolution code and found that it still built a not_not_intro term. That term could no longer reach the output. It only served as a "not empty" signal. A future caller might have emitted it untested. The fix replaced it with a clear yes-or-no check. The generated Lean stayed byte-identical on four inputs.
  • Nit: a loose size bound. The reviewer noted that DTP peaks at 7.86 GB under an 8 GB cap. The test allowed the file to grow to 27 MB, which could already exceed the cap. The bound was tightened to 26.5 MB, so a regression is caught by a cheap size check first.
  • Suggestion: a test comment. One test check only covers classical imports. A comment now says so, so readers do not assume more.
  • Suggestion: next targets. The reviewer agreed on the next size reductions. They are left as follow-ups.

During integration, a code span split across two lines in the plan doc was also rejoined.

Risks and open questions

  • Soundness is unchanged. The theorem and lemma statements are built as before, and Lean re-checks every rewritten term.
  • The margin is thin. DTP peaks at 7.86 GB under the 8 GB cap. Only the slow tier guards it, and CI does not run that tier.
  • Two rewrites work on generated text with regular expressions. They touch only generated names and keep the old text when unsure.
  • The helper finds its proposition by unification. The full suite confirms this works at every current site.
  • GitHub CI results after the merge are unknown to this report.

What comes next

  • Win more DTP margin by shortening the nested step headers and the repeated _atoms _vars arguments.
  • Rescan earlier QF_AX and QF_AUFLIA inputs that ran out of memory. Some may verify now.
  • Bring the same witness change to the non-outlined path, which still binds witnesses one by one.

Glossary

array theory
The theory of arrays with read and write operations, written QF_AX in SMT-LIB. Example: reading index i after writing v at i gives v.
atom
A formula with no Boolean connectives inside, such as a Boolean constant p or a comparison x - y <= 3.
axiom
A statement accepted without proof. Fewer axioms means a proof depends on fewer assumptions.
classical logic
Logic where every statement is either true or false, even without a way to compute which.
clause
A disjunction of literals, such as (or (not q) p (not r)).
decidability
Knowing that a statement is true or false. In Lean, a decidability witness is the object that records this. Classical logic supplies one for every statement.
difference logic
Arithmetic constraints of the form x − y ≤ c, written QF_IDL for integers.
double negation
Turning p into "not not p". It is needed to read p as a refutation of "not p".
elaboration
Lean's step of turning written proof text into fully checked internal terms. Its memory use grows with the text.
lemma
A helper theorem proved once and used by later proofs.
let-binding
Giving a name to a term with let name := term, so later lines can refer to it.
linear arithmetic
Constraints that add variables times constants, such as 2x + y ≤ 5, with no products of variables.
literal
An atom or its negation, such as p or (not p).
negation
The "not" of a formula. A negated literal has the form (not p).
proof by contradiction
Proving p by showing that "not p" leads to False.
proof term
A Lean expression whose type is the statement it proves.
refutation
A proof that a set of assertions leads to False.
resolution
The rule that combines two clauses with opposite literals into one. Example: from (or p q) and (not p), conclude q.
unification
Lean filling in a missing argument by matching the types around it.
unit clause
A clause with exactly one literal. A proof of it can cut the opposite literal from other clauses.
