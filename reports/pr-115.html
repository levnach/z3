This pull request is open and not merged. Everything below describes the change commit linked above.

In one paragraph

This PR makes the Lean text for large refutations smaller, so Lean stays under its 8 GB memory cap. It changes three patterns inside each outlined lemma. A negated literal removed by a resolution step no longer needs a double-negation wrapper. A lemma used only once is applied at that use instead of getting its own let binding. Every proof by contradiction in classical lemmas now goes through one shared helper. As a result, a 14 KB integer difference logic benchmark verifies in Lean for the first time. So does one theory of arrays benchmark. The theorem statement and the axioms used are unchanged.

Background

Before this PR, the pipeline could already reconstruct these benchmarks. The problem was size, not support. The benchmark DTP_k2_n35_c245_s9 produced 32.2 MB of Lean proof terms. Lean ran out of memory during elaboration in every loop iteration so far. Earlier iterations trimmed the output too, for example by naming hypotheses directly. It serves milestone 3 of the plan, equality and linear arithmetic, and the scaling work in the regression matrix.

What changed

  • A literal (not p) cut off a clause by a proof of p now uses Lean's Or.neg_resolve_left or Or.neg_resolve_right on that proof directly.
  • A lemma that its importing lemma uses exactly once is now applied right where it is used, with no separate name.
  • Classical lemmas now call one proved helper, classical_by_contradiction, instead of binding a fresh decidability witness for each formula.
  • The 14 KB difference-logic benchmark now verifies in Lean, and a new slow test guards it.
  • New and tighter tests check that the old patterns are gone and the output stays small.

The first change is like a recipe that used to say "add the opposite of no egg" and now just says "add the egg".

Worked example

The input this PR newly certifies is the DTP benchmark, with about 69,000 proof steps. That is too large to show. Small inputs already fit in memory, so none goes from rejected to accepted. Below are two real runs that show the new Lean shapes. Both inputs were also accepted before.

(a) Input

A tiny Boolean input. Unit resolution must cut the negated literal (not q) using the unit q.

(declare-const p Bool)
(declare-const q Bool)
(declare-const r Bool)
(assert (or (not q) p (not r)))
(assert q)
(assert r)
(assert (not p))
(check-sat)

(b) Before

The pre-PR scripts accepted this input and Lean checked it. The resolution step was:

    (False.elim (((_step_10.resolve_left (fun _literal => _literal _step_12)).resolve_left _step_11) _step_13))

The proof of q is wrapped in a lambda that turns it into "not not q".

For the DTP benchmark itself, the implementer recorded this failure before the PR. I did not rerun it.

After iter-113 it was 32.2 MB of Lean and stopped after
13,579 of its 16,557 lemmas.

(c) After

The current reconstructor's output for the tiny input, trimmed:

def formula_0 (_atoms : Nat -> Prop) : Prop := _atoms 0
def formula_1 (_atoms : Nat -> Prop) : Prop := (Not (formula_0 _atoms))
...
def formula_5 (_atoms : Nat -> Prop) : Prop := (Or (formula_1 _atoms) (Or (formula_2 _atoms) (formula_4 _atoms)))
...

Each formula gets a definition over the atoms q, p, r.

theorem unsat (_atoms : Nat -> Prop)
    (_h0 : (formula_5 _atoms))
    (_h1 : (formula_0 _atoms))
    (_h2 : (formula_3 _atoms))
    (_h3 : (formula_6 _atoms))
    : False :=
  ...
    (False.elim (((_step_10.neg_resolve_left _step_12).resolve_left _step_11) _step_13))
  _step_15

The theorem takes the four assertions as hypotheses, and the proof of q is now passed directly to Or.neg_resolve_left.

The two other changes need outlined lemmas, so they only appear on bigger inputs. Here is one lemma from the PR's new test input, DTP seed 1, which has 20 integer variables and 140 clauses. Before:

private theorem proof_step_904 {_atoms : Nat -> Prop} {_vars : Nat -> Int}
    (_inputs : Inputs _atoms _vars)
    : (formula_881 _atoms _vars) :=
  let _df881 := Classical.propDecidable (formula_881 _atoms _vars)
  let _step_899 := proof_step_899 _inputs
  ...
    (False.elim (_step_901 (_step_899.resolve_left _hyp882)))
  (@Decidable.byContradiction (formula_881 _atoms _vars) _df881 _step_903)

After:

private theorem classical_by_contradiction {p : Prop} (h : Not p -> False) : p :=
  @Decidable.byContradiction p (Classical.propDecidable p) h

private theorem proof_step_904 {_atoms : Nat -> Prop} {_vars : Nat -> Int}
    (_inputs : Inputs _atoms _vars)
    : (formula_881 _atoms _vars) :=
  ...
    (False.elim (_step_901 ((proof_step_899 _inputs).resolve_left _hyp882)))
  (classical_by_contradiction _step_903)

The single-use import of lemma 899 moved into its one use, and the witness let and formula vanished behind the helper.

Lean accepted both new files: check_lean.sh reported "Lean checks passed" for each. The seed-1 file shrank from 565,430 to 518,423 characters.

Review

The reviewer approved. There were no blocker, major, or minor findings. Two nits and two suggestions came up.

  • Nit, dead term. Reading the resolution code, the reviewer found a not_not_intro term that could no longer reach the output. It only acted as a yes-or-no signal, so a future caller might emit it untested. It was replaced by a plain predicate.
  • Nit, loose size bound. The slow DTP test allowed 27 MB, yet memory headroom was nearly gone. A small regression could pass the size check and still exhaust memory. The bound is now 26.5 MB.
  • Suggestions. A comment now notes that one seed-1 check covers only classical imports. The proposed next size targets are left as follow-ups.

Risks and open questions

  • Soundness is unchanged. Lean re-checks every rewritten term, so a wrong rewrite rejects the certificate.
  • The helper is a proved theorem with the same axiom as the witnesses it replaces.
  • The DTP margin is thin, and only the slow tier watches it.
  • Two rewrites edit generated text by regular expression. When a pattern is not found exactly once, the old form stays.

What comes next

  • Win more DTP margin, starting with nested step headers and repeated _atoms _vars applications.
  • Rescan earlier QF_AX and QF_AUFLIA memory failures, since some may verify now.
  • Use the helper on the non-outlined path too.

Glossary

axiom
A statement Lean accepts without proof. Fewer axioms means more trust. Example: Classical.choice.
classical reasoning
Logic that assumes every statement is either true or false, even when no procedure can decide which.
clause
A disjunction of literals. Example: (or (not q) p (not r)).
decidability
Having a way to tell whether a statement is true or false. In Lean, a "decidability witness" is that evidence as a value.
double negation
Stating "not not p" in place of p. Here, a lambda that turns a proof of p into a refutation of "not p".
elaboration
Lean's step that turns written proof text into fully typed internal terms. Its memory use grows with the text size.
hypothesis
A statement assumed inside part of a proof, later discharged by a lemma.
integer difference logic
Constraints of the form x - y >= c over integers. Its SMT-LIB logic name is QF_IDL.
lemma
A proved intermediate fact used by later proof steps.
let binding
Giving a value a local name, as in let x := ..., so later lines can refer to it.
literal
An atom or its negation. Example: p or (not q).
outlining
Splitting one huge proof into many separate Lean lemmas, so each is checked on its own.
proof by contradiction
Proving p by showing that "not p" leads to False.
proof term
A proof written as a Lean expression whose type is the statement it proves.
refutation
A proof that a set of assertions leads to False.
resolution
An inference that removes a literal from a clause using a fact that contradicts it. Unit resolution uses single-literal facts. Example: from (or (not q) p) and q, conclude p.
theory of arrays
Constraints over arrays read with select and written with store. Its SMT-LIB logic name is QF_AX.
