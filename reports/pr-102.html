Prove Lean argument equalities level by level over nested ites

Pull request #102 in levnach/z3 · State: OPEN · Opened 2026-11-09T16:02:56Z · Loop iteration 102

This pull request is open and not merged. The change it proposes ends at commit 8b39393. It has two commits on top of master.

In one paragraph

When Z3's rewriter changes the argument of an uninterpreted function, the Lean proof must show that the original argument equals its normal form. For arguments built from many nested if-then-else terms, that one equality used to be proved in a single step, with every definition unfolded. The tactic then had to consider every combination of branches at once, and Lean ran out of heartbeats. This pull request proves the equality level by level instead. Each matching pair of nested ites gets its own small intermediate fact, innermost first. Inputs with eight or ten nested steps under a function now get a full Lean-checked refutation, and smaller ones check several times faster. The trust boundary does not move, because Lean proves every new fact.

Background

Before this pull request, the reconstructor already stated these argument equalities over folded definitions, which kept the Lean text small. But it proved each one with both sides unfolded entirely. Two arguments with eight nested ites each, inside QF_UFLRA, failed on heartbeats. Depth ten failed too, for both sorts Real and Int. The work serves Milestone 3 of the project plan, "Equality and linear arithmetic", which combines congruence with linear arithmetic.

What changed

  • An equality between two nested-ite arguments is now split into one fact per level, each proved with only that level unfolded.
  • Inner facts are proved first, so each outer level can treat the ites below it as already matched.
  • A term that cannot be matched this way, such as an abs or a pair of ites of different sorts, is still unfolded with its level, as before.
  • If an ite condition is not a comparison of linear forms, that level falls back to the old "unfold everything" proof.
  • Certificates that contain arrays are unchanged. They still state these equalities written out in full.

An analogy: to check that two sets of nesting dolls match, compare the smallest pair first. Each larger pair then needs only its own shell compared. The old proof opened every doll at once, giving 216 branch combinations for eight a side. One level now has at most four.

(a) The input

(set-logic QF_UFLRA)
(declare-const x Real)

(define-fun m ((s Real)) Real (ite (< s 8.5) s (- s 8.5)))

Review

The reviewer approved. There were no blocker, major, or minor findings.

  • Nit: ites of different sorts. The reviewer wrote a QF_UFLIRA input where an Int ite under to_real faced a matching Real ite. The new code grouped ites by sort, so both stayed folded atoms. The level then stated a fact that could never be proved. The fix unfolds a mixed-sort group, just like an abs, and a new test covers it. This was about consistency, not a regression. The input still fails in Lean, as before the PR, because grind does not move the cast through the ite.
  • Suggestion: a faster lookup. The list of facts already stated was searched item by item. On certificates with many argument pairs, that grows quadratically. The fix keeps a set beside the ordered list.

Risks and open questions

  • Each level's proof sees fewer definitions than before. A level that needed a folded atom's definition would fail. The PR argues this cannot happen, and the full suite passes.
  • The order of the helper lines changed. Two tests that index those lines were updated.
  • Mixed-sort ites across to_real still fail in Lean. They need a cast bridge.
  • CI results and the recorded local gate were not available when this page was written.

What comes next

  • Certificates with arrays still prove these equalities written out, in one piece.
  • Other inline helpers, such as the cast facts, remain on the backlog.
  • Add a cast bridge for ites under to_real.
  • Two QF_AX files fail on kernel memory in a side scan. They belong to the existing many-lemma memory item.
  • Rescan the rest of QF_AUFLIA. Only its first seven files were checked.

Glossary

atom
A smallest piece that a formula treats as one unit, such as a variable, a function application, or a comparison like x < 6.
cast
A conversion of a value from one sort to another. to_real casts an Int to a Real.
congruence
The rule that equal arguments give equal results: if a = b, then f(a) = f(b).
definition (folded, unfolded)
A named abbreviation for a term, like term_10. Folded, it stays a short name. Unfolded, the name is replaced by what it stands for.
heartbeat
Lean's unit of work. A proof step that uses more than its limit of heartbeats stops with a timeout error.
if-then-else term (ite)
A term that picks one of two values by a condition. (ite (< s 8.5) s (- s 8.5)) is s when s < 8.5, else s - 8.5.
intermediate fact (have)
A statement proved inside a larger proof and then used as a known fact. Lean checks its proof like any other.
lemma
A small proved theorem that a larger proof uses as a step.
linear form
A sum of atoms times constant numbers plus a constant, such as 2*x + 5.
logic (SMT-LIB)
A named fragment of the language. QF_UFLRA means no quantifiers, uninterpreted functions, and linear arithmetic over Reals. In QF_UFLIA the arithmetic is over Ints.
normal form
A standard way of writing a term, so that equal terms written differently end up looking the same.
refutation
A proof that a set of assertions leads to False, so they cannot all hold at once.
rewriter
The part of the solver that simplifies terms into a normal form before solving. Each rewrite must be justified in the proof.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that searches for a proof automatically. grind is the tactic used here for arithmetic and case splits.
trust boundary
The line between what is checked by Lean and what is simply believed. Moving nothing across it means no new unchecked assumptions.
uninterpreted function
A function symbol with no fixed meaning, like f here. The only thing known about it is congruence.
