Prove Lean argument equalities level by level over nested ites

The pull request was merged into master on 2026-11-09T16:15:27Z as commit bc9b3db. It combined two commits: the change itself and a fix made after review.

In one paragraph

When the rewriter puts the argument of an uninterpreted function into normal form, the Lean file must prove the old and new arguments equal. Then congruence gives equal function values. Both arguments can be deep stacks of nested if-then-else terms. Before this PR, one tactic call had to see every level of both stacks at once. At depth 8 it ran out of heartbeats, and the refutation could not be certified. Now the equality is built from small have facts, one per pair of matching ites, innermost first. Each fact sees only its own level. Depth 8 and depth 10 inputs that failed now pass Lean, and smaller ones check several times faster. The trust boundary is unchanged: Lean proves every new fact.

Background

Two PRs earlier, these argument equalities were stated over folded definitions to keep the Lean text small. Their proofs still unfolded both arguments completely, though. For two arguments with eight nested ites each, the tactic faced up to 216 case splits. The previous iteration listed this as its open item. The work serves milestone 3 of the plan, equality and linear arithmetic, here for the logics QF_UFLRA and QF_UFLIA.

What changed

  • An argument equality over nested ites is now proved one level at a time, with deeper ites kept folded behind facts already proved.
  • Function-wrapped modular chains of depth 8 and 10, over Real and over Int, now pass the Lean check instead of timing out.
  • When a level holds an abs term, or ites of different sorts, that level unfolds them, so no fact is stated that cannot be proved.
  • Four new tests pin the new proof shape, including one Lean check at depth 8.

An analogy: think of two sets of nesting dolls that must match. The old proof opened every doll on both sides at once. The new proof compares the smallest pair first, then each next pair, with the inner dolls kept sealed and already known to match.

Review

The reviewer approved, with no blocker, major, or minor findings.

Nit: ites of different sorts. The reviewer built an input where an Int ite sits under a to_real cast and a Real ite has the same shape. The new code grouped ites by sort as well as by shape, so the two landed in separate groups and both stayed folded. The level then stated a fact that could never be proved. This mattered because the rule "unfold what cannot be paired" should hold everywhere. The fix unfolds a group whose ites differ in sort, as for abs, and a new test covers it. That input still fails in Lean, before and after, because grind does not push the cast through the ite.

Suggestion: a list scanned repeatedly. Facts already stated were looked up in a list, which grows quadratically. A set now sits beside it.

Risks and open questions

  • Each level's proof sees fewer definitions than the old whole-term proof. If two levels matched in shape but needed a folded definition, that have would fail. The PR argues this cannot happen for ites, and the full suite passes.
  • The helper order changed: all facts, then the unfolds, then clear. Two tests that read helper lines were updated.
  • The depth-10 rows were not re-measured after the review fix, which does not change their output.
  • The GitHub CI result on master is unknown.

What comes next

Glossary

abs
The absolute value of a number, written (abs x) in SMT-LIB.
case split
Proving a goal separately for each way a condition can go. Each ite gives two cases, so 16 ites give 216.
cast
Turning a value of one sort into another, such as to_real from Int to Real.
congruence
The rule that equal arguments give equal results: if a = b, then f(a) = f(b).
definition, unfold
The Lean file names each subterm with a definition such as term_38. Unfolding replaces the name with its body, so a tactic can see inside.
have fact
A local lemma inside a Lean proof. It must be proved before later steps can use it.
heartbeat
Lean's unit of work. A proof step that uses more than the limit is stopped with a timeout error.
if-then-else term (ite)
A term that picks one of two values by a condition: (ite (< s 8.5) s (- s 8.5)).
kernel
The small core of Lean that rechecks every finished proof.
linear arithmetic
Sums of variables times constants, compared with =, <, or <=. For example, 2x + 3 < y.
logic
An SMT-LIB name for a set of allowed features. QF_UFLRA means no quantifiers, uninterpreted functions, and linear Real arithmetic.
normal form
The standard shape the rewriter gives a term, so equal terms tend to look the same.
refutation
A proof that the assertions together imply False.
rewriter
The part of the solver that replaces terms with simpler equal terms before solving.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that builds part of a proof automatically. grind is the tactic these files use for arithmetic.
trust boundary
What a reader must trust without proof. Here it is Lean's checker and the encoding of the input, not the solver.
uninterpreted function
A function symbol with no fixed meaning, such as f above. Only congruence is known about it.
