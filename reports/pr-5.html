In one paragraph

Z3's QF_UF certification path previously accepted inputs over exactly one uninterpreted sort. This pull request lets the exporter, the certificate, and the Lean reconstructor handle any number of sorts. The certificate keeps every sort name, Python checks that the proof graph is well-sorted against those names, and Lean renders all sorts as a single type _U. Collapsing sorts is sound for unsatisfiability: a many-sorted model is one instance of the Lean theorem, with _U the disjoint union of the carriers, and well-sorted inputs only compare terms of one sort. The review found that this argument also needs each symbol name to denote a single symbol of the input. Z3's overloading by sort violates that, the binder did not enforce it, and a tampered certificate could be rebound to a satisfiable input. That hole was closed before merge. Many-sorted QF_UF is the shape of the hardware-derived SMT-LIB QF_UF families, which use one sort per bit width.

Background

The project goal, as stated in the repository's plan document, is unsat results from Z3 that an independent Lean checker accepts without trusting the solver. Z3 produces a native proof object or, for the theory fragments, a clause log from its sat.smt core. A Python exporter turns that evidence into a JSON certificate with a declaration table, a shared term and proof DAG, the assertion roots, and the original SMT-LIB source. A Python reconstructor validates the certificate, binds it structurally against a fresh parse of the input, and emits Lean source. The pinned Lean toolchain then checks that source with --trust=0, and only a successful check publishes the artifact.

This work serves milestone 3 of the plan, "Equality and linear arithmetic". The one-sort QF_UF slice through the clause log landed earlier in the loop, and a later iteration added ite terms over the sort. Lifting the one-sort restriction was the first backlog candidate because the clause log needs nothing new: every sort is declared in the log, and the euf, alldiff, tseitin, and rup steps are sort-agnostic.

In Lean, a QF_UF theorem quantifies over a type _U and indexed families of elements, functions, and predicates, and states that the assertions imply False under every such interpretation. This PR extends that reading from one sort to several.

What changed

Exporter

Fragment classification records a set of uninterpreted sort names instead of insisting on one. Functions may map between sorts. Bool or Real arguments and results, and mixing sorts with arithmetic, stay rejected. A new check rejects a symbol name declared with more than one signature in every fragment, because the certificate binds symbols by name.

Clause-log replay

Unchanged. It already checked declare-sort lines against the input's sort set and rebuilt applications with the input's declarations, so a cross-sort application in the log was already reported as ill-sorted.

Lean reconstruction

  • Sort set. The proof graph records a sorted tuple of sort names instead of one optional sort.
  • Well-sortedness. Functions take and return uninterpreted sorts only, an ite over sort S must have domain (Bool, S, S), and equality and distinct compare one sort. The per-node argument check then rejects every ill-sorted application.
  • No padding. A declaration over an uninterpreted sort that no node uses is rejected.
  • Binding against the input. The sort sets must match, overloaded names are rejected, every bound declaration must carry the input symbol's full signature, and interned terms carry their sort.
  • Generated text. Unchanged for one sort; with several, the header comment names them all as the one type _U.

Tests

Review

The reviewer requested changes: one blocker, two minor findings, no major or nit. The reviewer confirmed that all cited tests passed and that the disjoint-union argument is correct when symbols are bound faithfully, then built a counterexample to faithful binding. All three findings were fixed before the PR was opened, and the integrator reproduced the blocker before fixing it.

blocker Binding by name alone let a certificate be rebound to a satisfiable input

Z3 accepts one name declared at several sorts, such as (declare-fun c () A) with (declare-fun c () B), disambiguated as (as c A). The binder matched symbols by bare name, so two symbols differing only by sort matched one certificate declaration. The reviewer took the honest certificate of a one-sort unsat input, swapped its embedded source for a satisfiable two-sort input whose assertions print identically, appended one unused declaration, and obtained a Lean file that passed with --trust=0. The parent commit rejected that input through its single-sort check, so this was a regression.

Resolution. Classification rejects overloaded names in every fragment, so both the exporter and the reconstructor refuse them before binding. The binder repeats the check, requires each bound declaration to carry the input symbol's full signature, and interns terms with their sort. The exploit is a regression test, exercised with and without the frontend check.

minor The sort set could be padded with unused declarations

The sort set counted declarations no node referenced, which the exploit used to pass the sort-set comparison. Resolution. Graph validation rejects any declaration over an uninterpreted sort that no node uses. A blanket rule was not possible because the clause-log exporter pre-declares proof rules it may not apply.

minor README claimed overloading was rejected when only the binder did so

Only the binder rejected overloaded names, and only when both overloads reached the proof graph. Resolution. Rejection now happens at classification, and the README states the precondition of the one-carrier argument explicitly.

Risks and open questions

  • The one-carrier argument is not formalized. Soundness of collapsing sorts rests on the documented argument: disjoint-union instance, equality only within a sort, one symbol per name. Like the Real-as-Rat encoding, it lives in the trusted Python frontend rather than in Lean.
  • Python checks are integrity checks, not the trust boundary. Lean's statement depends only on the structure the binder compares against the parsed input, which is why the rebinding attack was serious.
  • Overloaded names are now rejected in every fragment. The PR body states that no previously certified input loses certification.
  • Still rejected. Bool arguments and results of uninterpreted functions, the most common remaining QF_UF rejection on hardware-derived benchmarks, plus QF_UFLRA, QF_LIA, and harmless set-option commands.
  • Unknown. No run against real SMT-LIB many-sorted QF_UF benchmarks is recorded, so coverage of those families is unmeasured.

What comes next
