In one paragraph

This PR makes the Lean proofs of array theory lemmas much smaller and faster. Each such lemma is one axiom instance of the array theory, such as the read-over-write axiom. Before, its Lean proof opened every if-then-else term it touched. It also carried two ite gates per ite and many extra facts. Now the ite terms stay folded, the gates are gone, and only facts about terms outside the ite terms are stated. Euf lemmas, which prove congruence steps, already worked this way. On one hard benchmark, the Lean check of the theory lemmas dropped from 208 seconds to 25 seconds. The theorem statements did not change, so the change cannot make Lean accept a false refutation.

Background

Before this PR, the reconstructor already handled arrays, uninterpreted functions, and integer arithmetic over ite terms. The previous PR kept ite terms folded in euf lemmas, but array lemmas still unfolded them. On the QF_AUFLIA benchmark cvc/dlx-regfile, Lean's profiler put about 150 of 208 seconds in 19 of its 50 array lemmas. Each one stated about 128 gates, unfolded about 60 ite terms, and then ran the tactics omega and grind on the result. The benchmark still fails on one cnf lemma, before and after this PR. The work serves milestone 4 of the plan, "Broader theories and integration", which treats arrays as a distinct extension.

What changed

  • An array theory lemma now gets no ite gates, so Lean no longer proves dozens of unused case facts for it.
  • An array lemma now unfolds only the definitions outside its ite terms, and leaves each ite as a closed box.
  • Its array, cast, and arithmetic facts now cover only the terms outside the ite terms, because facts inside a closed box cannot reach the goal.
  • One exception keeps working: a read of a mapped ite, built with (_ map ite), still unfolds the ite that its own axiom produces.
  • Two new tests check that array lemmas stay small and gate-free, and that the result still passes Lean.

An analogy helps. The read-over-write axiom is like a rule about a labeled box: "if you write to slot i and read slot j, you get the new value when i equals j." The rule only needs the label j. It never needs to open the box to see whether j is really "x if c, else y". The old proofs opened every box anyway. The new proofs leave the boxes closed.

The code change is in proof_to_lean.py. Euf lemmas and every other lemma kind produce byte-identical text.

Worked example

This PR certifies no new input. It only removes proved steps from proofs, so it cannot turn a rejection into an acceptance. The example therefore shows the same input before and after, and how the array lemma shrank. Both runs below are real runs of the pipeline on this file.

(a) The input

It writes v at index i, then reads at the index (ite c j k). Since i is below both j and k, the read cannot see the write.

(set-logic QF_AUFLIA)
(declare-const a (Array Int Int))
(declare-const i Int)
(declare-const j Int)
(declare-const k Int)
(declare-const v Int)
(declare-const c Bool)
(assert (< i j))
(assert (< i k))
(assert (not (= (select (store a i v) (ite c j k)) (select a (ite c j k)))))
(check-sat)

(b) Before

Review

The reviewer approved the PR. They found no blockers, no major issues, and no minor issues.

  • Nit, fixed. The reviewer read a code comment and a test docstring that said the timing covered "the file's theory lemmas (but its cnf lemma)". The word "but" was meant as "except", yet a reader could take it to mean only the cnf lemma was measured. That matters because a misread timing claim could mislead later profiling work. Both places now say "without its cnf lemma", fixed before the merge.
  • Suggestion, not changed. The reviewer noticed that the new helper keeps unfolded every value equated with a read of a mapped array, not only the map axiom's own ite. At worst this unfolds more than needed. That costs time but cannot affect soundness. It has not shown up in profiles, so narrowing it is left as a follow-up.
  • Suggestion, out of scope. Euf lemmas could also state facts only about terms outside their ite terms. This is listed under next steps.

Risks and open questions

  • The risk is completeness, not soundness. If some array lemma truly needs to look inside an ite, its Lean proof now fails, and there is no unfolded fallback. The full Lean suite and the reviewer's ten extra inputs all pass.
  • Array lemmas over Real values no longer get the Real scaling facts that came with the gates. The Real array test inputs still verify.
  • dlx-regfile is still not certified. Its cnf lemma th_lemma_1612 fails, and its 14 MB of outlined proof steps have never been checked.

What comes next

  • Fix or bridge the failing cnf lemma in dlx-regfile, now that the theory lemmas are cheap.
  • Restrict the facts of euf lemmas to the terms outside their ite terms, to shrink the 1.75 MB of euf lemma text in dlx-regfile.
  • Try folded ite terms for datatype lemmas.
  • Narrow the map exception to values whose head matches the mapped function.

Glossary

array
A sort of total maps from an index sort to a value sort, such as (Array Int Int). select reads a slot and store writes one, returning a new array.
axiom instance
A general rule of a theory, filled in with concrete terms. Example: the read-over-write rule applied to array a, index i, and value v.
Boolean
The sort with exactly two values, true and false. Written Bool in SMT-LIB.
clause
A disjunction of literals, meaning at least one of them is true. Example: i = j ∨ x = y.
cnf lemma
A lemma that relates a formula to its clausal form, produced when Z3 splits formulas into clauses.
completeness
The property that every correct proof gets accepted. A completeness bug rejects a valid result but never accepts a wrong one.
congruence
The rule that equal arguments give equal results. If a = b, then f(a) = f(b).
folded definition
A named term whose body Lean is not told to expand. Unfolding replaces the name by its body. Folded, the term acts like a sealed box.
if-then-else term
A term that picks one of two values by a Boolean condition. Written (ite c x y): it is x when c is true, else y.
ite gate
A pair of facts that describe an ite: "if c then the term equals x" and "if not c then it equals y".
literal
An atomic formula or its negation. Example: x < y or not (x < y).
read-over-write axiom
The array rule that reading index j after writing v at i gives v if i = j, and the old value otherwise.
refutation
A proof that a set of assertions leads to a contradiction, that is, to False.
soundness
The property that only true statements get accepted. A soundness bug would let a wrong result pass the check.
sort
The type of a value, such as Int, Real, Bool, or (Array Int Int).
tactic
A Lean command that builds part of a proof automatically. omega solves integer arithmetic goals, and grind combines congruence with case splits.
theory lemma
A clause that holds in a background theory, such as arrays or arithmetic, and that the solver adds to the proof. Called a th-lemma in Z3. Its hint names the theory, such as array or euf.
uninterpreted function
A function symbol with no fixed meaning. The only thing known about it is congruence. Example: (declare-fun f (Int) Int).
