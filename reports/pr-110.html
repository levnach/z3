Keep ites folded in array th-lemmas, without ite gates

Pull request levnach/z3 #110 · OPEN · 2026-11-10T22:24:40Z · loop iteration 109

This pull request is open and not merged. The change under review is commit 15e54b4b2.

In one paragraph

This PR makes the Lean proofs of array theory lemmas much smaller and faster. Each array lemma is one axiom instance, such as read-over-write. Before, the reconstructor gave every such lemma an ite gate for every if-then-else term it touched. It also unfolded those terms, so Lean had to reason through every branch. Now the ites stay folded and the gates are gone, as they already were for euf lemmas. On one hard benchmark, Lean's time on the theory lemmas dropped from 208 s to 25 s. The theorem statements are unchanged, so the change cannot make Lean accept a false refutation. At worst, a certificate fails to check, which is a completeness risk, not a soundness risk.

Background

Since iteration 107, the reconstructor has known how to keep ites folded inside euf lemmas, which reason by congruence. Array lemmas still got full ite gates and unfolds. On the QF_AUFLIA benchmark cvc/dlx-regfile, its theory lemmas still needed 208 s and 4.9 GB of Lean. Lean's profiler put about 150 of those seconds in about 19 of the 50 array lemmas. That benchmark still fails on one cnf lemma, both before and after this PR. The work serves milestone 4, "Broader theories and integration," where arrays are one of the listed extensions.

What changed

  • An array lemma now reaches Lean without ite gates, so Lean no longer case-splits on ites the lemma never needed.
  • An array lemma's ites now stay folded, and only the definitions outside them are unfolded, using the same code path as euf lemmas.
  • An array lemma now states its supporting facts only for terms outside its ites, so it carries far less text.
  • The one ite an array lemma must see inside, from a map of ite over arrays, is still unfolded by a new helper.
  • Two new tests check the smaller text and run Lean on a register-file input with eight array lemmas over ite chains.

An analogy: an ite is a sealed envelope that holds one of two values. An array axiom like read-over-write only needs to know the envelope exists. Before, the pipeline opened every envelope and listed both possible contents for Lean. Now it leaves the envelopes sealed.

Worked example

This PR is a speed and size change. It does not newly certify any input. So the example below shows an input that both versions certify, and how its Lean proof got smaller. Both outputs come from real runs of the base scripts and of the PR's scripts.

(a) The input

Built in the style of the reviewer's "read-over-write at an ite index" probe. The read index is an ite.

(set-logic QF_AUFLIA)
(declare-const a (Array Int Int))
(declare-const i Int)
(declare-const j Int)
(declare-const k Int)
(declare-const v Int)
(declare-const c Bool)
(assert (< i j))
(assert (< i k))
(assert (not (= (select (store a i v) (ite c j k)) (select a (ite c j k)))))
(check-sat)

Writing at i cannot change a read at j or k, since both are larger than i. So the assertions contradict each other.

Glossary

array
A value that maps indices to elements, like a table. (select a i) reads index i, and (store a i v) is a with index i set to v.
axiom instance
A general rule filled in with specific terms. Example: read-over-write for a, i, v says reading (store a i v) at i gives v.
Boolean
The sort with exactly two values, true and false. In SMT-LIB it is Bool.
clause
A disjunction of literals: it holds if at least one of them is true. Example: i = t or a[i] = b[i].
cnf lemma
A lemma that justifies how a formula was turned into clauses.
completeness
The checker's ability to accept every correct proof. A completeness gap means some true results are rejected.
congruence
The rule that equal inputs give equal outputs. If x = y, then f(x) = f(y).
euf lemma
A theory lemma about equality and uninterpreted functions, proved by congruence.
if-then-else term (ite)
A term that picks one of two values based on a Boolean condition. (ite c j k) is j when c is true, else k.
ite gate
A pair of facts telling Lean which branch an ite takes. Example: "if c, the ite equals j."
literal
An atomic formula or its negation. Example: i = j or not (i = j).
map (array map)
An array built by applying a function at every index. ((_ map ite) p a b) picks from a or b at each index.
refutation
A proof that a set of assertions leads to a contradiction.
sort
The type of a value, such as Int, Bool, or (Array Int Int).
soundness
The guarantee that the checker never accepts a false claim.
tactic
A Lean command that builds part of a proof automatically. grind and omega are tactics.
theorem
A statement together with a proof that Lean checks.
theory lemma
A clause that holds because of a theory, such as arrays or arithmetic. Z3 tags each one with a hint, such as array or euf.
unfold
To replace a defined name with its definition, so Lean can see inside it.
uninterpreted function
A function symbol with no fixed meaning. The only thing known about it is congruence.
