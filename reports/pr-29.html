Prove Int theory lemmas over their div/mod/abs atoms generalized

Pull request levnach/z3#29 · state OPEN · opened 2026-10-22T00:07:46Z · loop iteration 29

This pull request is not merged. The report describes the change as of its head commit 7d4ca0f4d, which sits on top of 08741c963 on master. The PR holds two commits.

In one paragraph

Before this change, the Lean reconstructor proved every integer theory lemma by unfolding the definitions of all its atoms, including Euclidean division and remainder and absolute value, and then running the omega or grind tactic. When a lemma mixed a dozen such atoms with negative divisors, that proof exhausted Lean's heartbeat budget, so one certificate from the iteration-27 stress run was never certified. The PR adds a first attempt that keeps each div, mod, abs, if-then-else and uninterpreted function atom closed, as if it were a fresh integer, states the known bounds of every remainder, and lets omega or grind close the remaining linear integer goal. If that attempt fails, the previous proof runs unchanged as a fallback. The trust boundary does not move. Both attempts use ordinary tactics checked by the Lean kernel, and a false lemma fails both.

Background

The pipeline exports Z3's clause log for linear integer problems with div, mod by a numeral, and abs, and checks each theory lemma in Lean. A Farkas or bound lemma with coefficients already has its linear combination re-derived in Python, while a cut or a coefficient-free lemma reaches Lean with only the shapes of its literals checked. Lean then had to re-prove each lemma from the definitions of division and remainder. The omega tactic does not read a remainder by a negative numeral, so every such lemma fell to grind, which case-splits each absolute value. That is where the seed-67 stress certificate timed out. The change serves milestone 3 of the plan, equality and linear arithmetic, and the regression methodology that gates it.

What changed

Lean reconstructor (proof_to_lean.py)

  • Opaque first attempt. An integer theory lemma with hint farkas, bound, or cut whose literals contain div, mod, abs, ite, or application atoms is now proved with those atoms generalized to fresh integers. Think of each atom as a sealed box: the new proof reasons about the labels on the boxes without opening them.
  • Remainder bounds restored. Before generalizing, the proof states 0 <= m < |k| for every remainder atom from Lean's library, because Z3 fixes these facts at base level and leaves them out of the lemmas it explains.
  • Tactic chosen by hint. A lemma with coefficients goes to omega, which closes the linear goal at once. A cut or a coefficient-free lemma goes to grind, whose integer module handled a twenty-atom cut in about a second where omega needed minutes.
  • Old proof kept as fallback. The two attempts sit under Lean's first combinator, so anything that verified before still verifies, and lemmas without such atoms produce byte-identical Lean text.

Tests (test_proof_to_lean_lia.py)

  • Shape and behaviour pinned. New tests check the two-branch text per hint and atom kind on four documented inputs and on seed 67, verify the seed-67 instance end to end, show that a lemma false over the generalized atom falls through to the fallback, and show that a false cut over a remainder atom is rejected by both attempts.

A Farkas lemma over a remainder, proved with the atom generalized. This is the new two-branch shape. The first branch states that the remainder lies in [0, 3), moves those facts into the goal, replaces the remainder by the fresh integer _o0, and lets omega finish. The second branch is the proof the pipeline used before.

set_option maxHeartbeats 1000000 in
private theorem th_lemma_556 (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    : (formula_555 _atoms _vars) := by
  unfold formula_555 formula_554 formula_553 formula_527 formula_438 formula_437 formula_433 term_432 term_29 term_24 term_6
  first
    | (have _m0_0 : ((0 : Int)) <= (term_380 _atoms _vars) := by unfold term_380 term_183 term_36 term_18; exact Int.emod_nonneg _ (by decide)
       have _m0_1 : (term_380 _atoms _vars) < ((3 : Int)) := by unfold term_380 term_183 term_36 term_18; rw [Int.emod_neg]; exact Int.emod_lt_of_pos _ (by decide)
       revert _m0_0 _m0_1
       generalize (term_380 _atoms _vars) = _o0
       omega)
    | (unfold term_380 term_183 term_36 term_18
       first | omega | grind (splits := 64))

The rewrite with Int.emod_neg turns the remainder by -3 into a remainder by 3, which is the form the library bound expects.

Review

The reviewer approved the change with no blocking or major findings. They re-ran every cited test, read the full diff, and checked that the other callers of the changed function still produce the old text.

  • Minor: README drift. The reviewer read the user-facing README and found it still described the single unfolded proof. A reader debugging a rejected certificate would not recognise the new have, revert, and generalize block. The second commit rewrote that paragraph to describe the generalized attempt, the stated remainder bounds, the tactic per hint, and the fallback.
  • Nit: no test of the fall-through. The reviewer wanted proof that a lemma whose first attempt fails really reaches the fallback. They tried relabelling two arith axioms of a documented input as cuts and saw Lean accept them. The implementer found that this evidence was wrong: those axioms are exactly the remainder bounds, which the first attempt proves from the stated facts, so the fallback never ran. The new test instead uses the unit x >= 3 * (div x 3), which no bound fact covers. Lean rejects it without the fallback and accepts it with the fallback. This mattered because the whole safety story of the change rests on first catching a failed branch.
  • Nit: divisor rendering assumption. The bound facts assume a negative divisor is printed as the negation of a numeral, which is how Z3 writes constants. A divisor written as a difference would make the fact fail and send the lemma to the fallback silently. The docstring now says the facts are best effort. There is no soundness impact, because a failed fact only fails the first branch.

Risks and open questions

  • Text changes broadly. Every integer Farkas, bound, or cut lemma over such atoms, in both proof cores, now gets the two-branch proof. Nothing that previously verified has been seen to regress, but the surface is wide.
  • A slow failure would hurt. The first attempt is designed to fail fast when it fails. If omega ever fails slowly on a large lattice goal, it would spend the shared heartbeat budget before the fallback runs. Choosing the tactic by hint avoids the one case observed.
  • Reliance on complete explanations. The cut branch assumes Z3 lists every non-base-level fact a cut uses. The remainder bounds were the only omitted facts seen. Another omitted kind would simply fall back to the old proof.
  • Unfilled PR text. The PR body still carries two placeholders for the suite and Lean results, so a reader of the PR alone does not see those numbers.

What comes next

  • Wait for the remaining Windows CI job, then move the PR forward.
  • A rewrite whose assertion sums a dozen absolute values still times out, in its rewrite lemma rather than in a theory lemma. Rendering abs as the rewriter's ite, or bridging same-key ite atoms, is the noted follow-up.
  • State the remainder bounds in the fallback too, so omega instead of grind can handle negative divisors in arith axioms.
  • Implied-equality lemmas still use the unfolded proof. Their two halves are not re-derived in Python yet.

Glossary

absolute value (abs)
The distance of an integer from zero. In SMT-LIB it is written as an if-then-else term: (ite (>= x 0) x (- x)).
atom
A smallest building block of a formula that a decision procedure treats as a unit. Here, a term such as (mod x4 -3) or (abs x2) inside a linear constraint.
bound
An inequality that limits a term from one side, such as 0 <= m or m < 3. A bound lemma is a theory lemma that derives one bound from others.
certificate
A machine-readable record of why a problem is unsatisfiable, exported from the solver and checked by an independent tool.
clause
A disjunction of literals, read as "at least one of these holds". Example: (or (not A) B C).
clause log
The stream of clauses and theory lemmas Z3's SAT-based core records while solving. One of the two proof sources the pipeline can export.
congruence
The rule that equal arguments give equal function results: from a = b conclude f(a) = f(b).
cut
A derived linear inequality that uses the fact that the variables are integers, cutting off non-integer solutions. Example: from 2x <= 3 conclude x <= 1.
Euclidean division and remainder (div, mod)
Integer division and remainder where the remainder is always between 0 and the absolute value of the divisor. For example, (mod -7 3) is 2 and (mod 7 -3) is 1.
Farkas lemma
A result saying that a set of linear inequalities is contradictory exactly when a weighted sum of them yields something false, such as 0 < 0. A Farkas theory lemma records those weights as coefficients.
generalize
A Lean tactic that replaces every occurrence of a term in the goal by a fresh variable, forgetting what the term was. Here it hides a division or remainder behind a plain integer.
grind
A Lean automation tactic that combines case splitting, congruence closure, and integer arithmetic (its cutsat module). splits := 64 caps the number of case splits.
heartbeats
Lean's unit of work for limiting how long elaboration may run. When a proof exceeds maxHeartbeats, Lean reports a deterministic timeout and rejects the proof.
hint
A short label Z3 attaches to each theory lemma saying which rule produced it: farkas, bound, cut, arith, euf, or implied-eq, sometimes followed by coefficients.
if-then-else term (ite)
A term that takes one of two values depending on a condition: (ite c a b) is a when c holds and b otherwise.
kernel
The small trusted core of Lean that re-checks every proof term. Tactics only produce terms; the kernel decides whether they are correct.
linear integer arithmetic (QF_LIA)
Formulas over integer variables built from sums, numeral multiples, comparisons, and Boolean connectives, without quantifiers. A linear goal is a statement in this language.
literal
An atom or its negation, such as (<= x 3) or (not (<= x 3)).
omega
A Lean decision procedure for linear integer arithmetic. It reads division and remainder by a positive numeral but treats a remainder by a negative numeral as an unknown.
refutation
A proof that a set of assertions implies False, which shows the assertions cannot all hold.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A command in a Lean proof that builds part of the proof automatically, such as unfold, revert, omega, or first, which tries alternatives in order.
theory lemma
A clause the arithmetic (or equality) solver asserts as a fact of its theory, independent of the problem's other constraints. Each one becomes a separate Lean theorem.
uninterpreted function
A function symbol with no definition, such as f in (declare-fun f (Int) Int). Only congruence is known about it.
