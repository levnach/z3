Prove Int theory lemmas over their div/mod/abs atoms generalized

Pull request levnach/z3#29 · state MERGED · merged 2026-10-22T03:51:08Z · loop iteration 29

Opened 2026-10-22T00:07:46Z against master at 08741c963, and merged as the squash commit 1b7595c70.

In one paragraph

This PR changes how the Lean reconstructor proves an integer theory lemma whose literals contain Euclidean division or remainder, absolute value, if-then-else term, or uninterpreted function atoms. Before, every such lemma was proved by unfolding all its atoms and running the omega or grind tactic. A lemma over a dozen atoms with negative divisors exhausted Lean's heartbeat budget, so one certificate from the iteration-27 stress run was never certified. Now a lemma with hint farkas, bound, or cut first generalizes each atom to a fresh integer, states the bounds of every remainder, and closes the remaining linear integer goal. If that fails, the previous proof runs unchanged as a fallback. Both attempts use ordinary tactics checked by the Lean kernel, and a false lemma fails both, so the trust boundary does not move.

Background

The pipeline exports Z3's clause log for linear integer problems whose atoms of sort Int include div, mod by a numeral, and abs, and checks each theory lemma in Lean. A Farkas or bound lemma with coefficients already had its linear combination re-derived in Python, while a cut or a coefficient-free lemma reached Lean with only the shapes of its literals checked. Lean then re-proved each lemma from the definitions of division and remainder. The omega tactic does not read a remainder by a negative numeral, so every such lemma fell to grind, which case-splits each absolute value. That is where the seed-67 stress certificate timed out. The change serves milestone 3 of the plan, equality and linear arithmetic, and the regression methodology that gates it.

What changed

  • Reconstructor: generalized first attempt. An integer theory lemma with hint farkas, bound, or cut is now proved with its atoms treated as sealed boxes, so Lean reasons about the labels without opening them.
  • Reconstructor: remainder bounds restored. Before sealing the boxes, the proof states 0 <= m < |k| for every remainder atom, because Z3 fixes these facts at base level and leaves them out of the lemmas it explains.
  • Reconstructor: tactic by hint, old proof kept. A lemma with coefficients goes to omega, a cut or coefficient-free lemma goes to grind, and the previous proof sits behind both under Lean's first combinator.
  • Tests: shape and behaviour pinned. New tests check the two-branch text per hint and atom kind, verify seed 67 end to end, show a real fall-through to the fallback, and show that a false cut is rejected by both attempts.
  • Documentation. The Python README describes the generalized attempt and its fallback, and the plan document carries a dated analysis of the problem and what remains undone.

A Farkas lemma over a remainder, in the new two-branch shape. The first branch states that the remainder lies in [0, 3), replaces the remainder by the fresh integer _o0, and lets omega finish, while the second branch is the proof used before.

set_option maxHeartbeats 1000000 in
private theorem th_lemma_556 (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    : (formula_555 _atoms _vars) := by
  unfold formula_555 formula_554 formula_553 formula_527 formula_438 formula_437 formula_433 term_432 term_29 term_24 term_6
  first
    | (have _m0_0 : ((0 : Int)) <= (term_380 _atoms _vars) := by unfold term_380 term_183 term_36 term_18; exact Int.emod_nonneg _ (by decide)
       have _m0_1 : (term_380 _atoms _vars) < ((3 : Int)) := by unfold term_380 term_183 term_36 term_18; rw [Int.emod_neg]; exact Int.emod_lt_of_pos _ (by decide)
       revert _m0_0 _m0_1
       generalize (term_380 _atoms _vars) = _o0
       omega)
    | (unfold term_380 term_183 term_36 term_18
       first | omega | grind (splits := 64))

The rewrite with Int.emod_neg turns the remainder by -3 into a remainder by 3, the form the library bound expects.

Review

The reviewer approved the change with no blocking or major findings, after re-running every cited test and reading the full diff.

  • Minor: README drift. The user-facing README still described the single unfolded proof, so a reader debugging a rejected certificate would not recognise the new generalize block. The second commit rewrote that paragraph.
  • Nit: no test of the fall-through. The reviewer wanted proof that a failed first attempt really reaches the fallback, and relabelled two arith axioms as cuts to show it. The implementer found that those axioms are exactly the remainder bounds, which the first attempt proves on its own, so the fallback never ran. The new test instead uses the unit x >= 3 * (div x 3), which Lean rejects without the fallback and accepts with it. This mattered because the safety of the change rests on first catching a failed branch.
  • Nit: divisor rendering assumption. The bound facts assume a negative divisor is printed as the negation of a numeral, which is how Z3 writes constants. A divisor written otherwise would send the lemma to the fallback silently, with no soundness impact, and the docstring now says so.

Risks and open questions

  • Text changes broadly. Every integer Farkas, bound, or cut lemma over such atoms, in both proof cores, now gets the two-branch proof. No regression has been seen, but the surface is wide.
  • A slow failure would hurt. The first attempt is meant to fail fast, for example when an uninterpreted function atom's congruence matters. If omega ever fails slowly on a large lattice goal, it would spend the shared heartbeat budget before the fallback runs.
  • Reliance on complete explanations. The cut branch assumes Z3 lists every non-base-level fact a cut uses. The remainder bounds were the only omitted facts seen, and another kind would fall back to the old proof.
  • Unfilled PR text. The PR body on GitHub still carries two placeholders where the suite and Lean results should appear.
  • Gate timing. The local gate's Lean reconstruction step took far longer than the test runner itself reported, and the cause is not recorded.

Glossary

absolute value (abs)
The distance of an integer from zero. In SMT-LIB it is written as an if-then-else term: (ite (>= x 0) x (- x)).
atom
A smallest building block of a formula that a decision procedure treats as a unit. Here, a term such as (mod x4 -3) or (abs x2) inside a linear constraint.
Boolean
The sort of truth values, true and false, and the connectives over them such as and, or, and not.
bound
An inequality that limits a term from one side, such as 0 <= m or m < 3. A bound lemma is a theory lemma that derives one bound from others.
certificate
A machine-readable record of why a problem is unsatisfiable, exported from the solver and checked by an independent tool.
clause
A disjunction of literals, read as "at least one of these holds". Example: (or (not A) B C).
clause log
The stream of clauses and theory lemmas Z3's SAT-based core records while solving. One of the two proof sources the pipeline can export.
congruence
The rule that equal arguments give equal function results: from a = b conclude f(a) = f(b).
cut
A derived linear inequality that uses the fact that the variables are integers, cutting off non-integer solutions. Example: from 2x <= 3 conclude x <= 1.
Euclidean division and remainder (div, mod)
Integer division and remainder where the remainder is always between 0 and the absolute value of the divisor. For example, (mod -7 3) is 2 and (mod 7 -3) is 1.
Farkas lemma
A result saying that a set of linear inequalities is contradictory exactly when a weighted sum of them yields something false, such as 0 < 0. A Farkas theory lemma records those weights as coefficients.
generalize
A Lean tactic that replaces every occurrence of a term in the goal by a fresh variable, forgetting what the term was. Here it hides a division or remainder behind a plain integer.
grind
A Lean automation tactic that combines case splitting, congruence closure, and integer arithmetic (its cutsat module). splits := 64 caps the number of case splits.
heartbeats
Lean's unit of work for limiting how long elaboration may run. When a proof exceeds maxHeartbeats, Lean reports a deterministic timeout and rejects the proof.
hint
A short label Z3 attaches to each theory lemma saying which rule produced it: farkas, bound, cut, arith, euf, or implied-eq, sometimes followed by coefficients.
if-then-else term (ite)
A term that takes one of two values depending on a condition: (ite c a b) is a when c holds and b otherwise.
kernel
The small trusted core of Lean that re-checks every proof term. Tactics only produce terms; the kernel decides whether they are correct.
linear integer arithmetic (QF_LIA)
Formulas over integer variables built from sums, numeral multiples, comparisons, and Boolean connectives, without quantifiers. A linear goal is a statement in this language.
literal
An atom or its negation, such as (<= x 3) or (not (<= x 3)).
omega
A Lean decision procedure for linear integer arithmetic. It reads division and remainder by a positive numeral but treats a remainder by a negative numeral as an unknown.
refutation
A proof that a set of assertions implies False, which shows the assertions cannot all hold.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A command in a Lean proof that builds part of the proof automatically, such as unfold, revert, omega, or first, which tries alternatives in order.
theory lemma
A clause the arithmetic (or equality) solver asserts as a fact of its theory, independent of the problem's other constraints. Each one becomes a separate Lean theorem.
uninterpreted function
A function symbol with no definition, such as f in (declare-fun f (Int) Int). Only congruence is known about it.
