In one paragraph

This PR lets the pipeline certify inputs that multiply nonconstant terms of sort Int, such as (* m n). Each product is treated as one more atom of the linear forms of linear arithmetic. So the existing checks for Farkas lemmas and cuts now work over products too. Products of Real terms stay rejected, because the certificate models Real by rational numbers. Theory lemmas of Z3's nonlinear solver are not certified either. A refutation that uses one is rejected by name. No axiom was added and no check was skipped.

Background

Before this PR, the exporter rejected every input with a product of two nonconstant terms. In the z3test regression corpus that was the largest class of rejected inputs after strings and bit-vectors: 78 queries. One hint of the nonlinear solver also rejected a whole clause log, even when the refutation never used that lemma. The PR is a first slice of milestone 4 of the plan, which lists nonlinear arithmetic as a separate extension.

What changed

  • Exporter. Inputs with products of Int terms are accepted in every integer fragment, also with uninterpreted functions and arrays.
  • Linear forms. A product of nonconstant factors counts as one atom, so Farkas lemmas and cuts over products are checked as before.
  • Lean tactic. For a certificate with an Int product, the theory tactic also receives Int.mul_eq_zero: a zero product has a zero factor.
  • Real products. A product of Real terms is still rejected, and the message now states the reason.
  • Nonlinear solver lemmas. An unused lemma of the nonlinear solver no longer rejects the log, and a used one is rejected by name.

An analogy: a product is a sealed box with a label. Linear arithmetic only weighs the box. Opening it to look at the factors is the nonlinear solver's job, and that part is not certified yet.

Why Real is different: the equation x * x = 2 has a real solution but no rational one. A theorem about rational numbers would not show that such an input is unsatisfiable.

The declarations: term_2 is the product, written with Lean's integer multiplication. The last line states a step of Z3's rewriter: the product is zero exactly when a factor is zero. 

set_option maxHeartbeats 1000000 in
private theorem rewrite_14 (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    : (formula_13 _atoms _vars) := by
  unfold formula_13 formula_12 formula_11 formula_10 formula_4 term_3 term_2 term_1 term_0
  first | omega | grind (splits := 64) [Int.mul_eq_zero]

The new feature: Lean proves the rewriter's step as a lemma, and the tactic line ends with the new fact.

Review

The reviewer approved the change with no blocker and no major finding. Attacks on its soundness found no gap: tampered certificates were rejected. A second commit on the branch answers the four findings.

Minor: one documented test input leaned on luck

The reviewer counted the hints in the raw clause log of each documented input. One log held lemmas of the nonlinear solver, and the input verified only because trimming dropped them. On another platform that test could fail. The input was replaced by one with a linear refutation, and the old one now accepts either outcome.

Minor: a rejection in the older export path looked untested

The reviewer found no test of how the older proof-object path rejects steps of the nonlinear solver. In fact one of the two step labels was already tested. The other label and a new test were added. This was a coverage gap only, because Lean must still prove such a step.

Nits: a test warning and a sum

One rejected input made the tests print a warning, and such noise can hide a real problem. It is now expected for that input only, and an error for the others. The plan also listed kinds of failing lemmas that summed to more than the failing instances. The kinds overlap, and the text now says so.

Risks and open questions

  • Tests depend on Z3's search. An input verifies only while Z3 refutes it without its nonlinear solver.
  • Late failures. Some refutations pass the exporter and then fail in Lean. Nothing is trusted, but the user sees a Lean error instead of a clear rejection.
  • Unknown. The tests ran on a Mac only. Their result on the Linux CI runner is not known yet.

What comes next

  • Replay the nonlinear solver's own lemmas in Lean.
  • Prove the rewriter's case split on the signs of the factors of a product.
  • Reject clauses assumed by the nonlinear solver by name, instead of sending them to Lean.
  • Certify products of Real terms, which needs a theorem over the real numbers.

Glossary

array
A term that maps indices to values, read with select and updated with store.
assertion
A formula the input states to be true, written (assert ...) in SMT-LIB.
atom
A term that a theory treats as a single indivisible unit. In 2*x + 3*(m*n), linear arithmetic sees two atoms: x and m*n.
axiom
A statement accepted without proof. A certificate that adds one asks the checker to trust it.
Boolean
Having the sort Bool, with the two values true and false.
certificate
A file that records a refutation in enough detail for an independent checker to confirm it.
clause
A disjunction of literals, such as p or not q.
clause log
The list of clauses a solver assumed and derived, each derived one with a hint for how to check it.
cut
A lemma of integer arithmetic that removes non-integer solutions. From 2*x >= 1 over Int it concludes x >= 1.
Farkas lemma
A proof that linear inequalities contradict each other: multiply each by a non-negative number and add them to get something false, such as 0 < 0.
fragment
A restricted class of formulas, such as linear integer arithmetic without quantifiers.
hint
A note attached to a derived clause that names the rule behind it, and sometimes its coefficients.
hypothesis
An assumption of a theorem. Here each assertion of the input becomes one hypothesis.
lemma
A small proved statement that a larger proof uses as a step.
linear arithmetic
Arithmetic where variables are only added and multiplied by constants, as in 2*x + 3*y <= 5.
linear form
A sum of atoms, each multiplied by a constant, plus a constant.
literal
An atomic formula or its negation, such as x <= 2 or not p.
nonlinear arithmetic
Arithmetic that multiplies variables with each other, as in x*y > 2.
nonlinear solver
The part of an SMT solver that reasons about a product from its factors, for example that a square is never negative.
rational number
A fraction of two integers. The square root of 2 is real but not rational.
refutation
A proof that a set of assertions leads to a contradiction.
rewriter
The part of a solver that simplifies formulas before solving. Here it replaces (= (* m n) 0) by (or (= m 0) (= n 0)).
sort
The type of a value, such as Int, Real, or Bool.
soundness
The property that a checker accepts only correct proofs. A soundness gap would let a wrong refutation pass.
tactic
A Lean command that searches for a proof of a goal. Examples are omega for linear integer arithmetic and grind for general reasoning.
theory lemma
A clause that is true because of a theory, such as arithmetic, and not because of the input's assertions.
trimming
Removing from a clause log the steps that the final refutation does not use.
uninterpreted function
A function symbol with no fixed meaning. The only rule is that equal arguments give equal results.
