In one paragraph

This PR lets the pipeline certify problems that use constant arrays whose index sort is Real. Before, only Int indices were accepted. The Lean side gains one new theorem: no finite list contains every rational number. With it, the existing facts about default values now work over Rat as well as Int. The proof travels through the clause log, and Lean checks the whole refutation. No axiom was added, so the trust boundary stays the same.

Background

PR #70 taught the pipeline to certify constant arrays over Int indices. Its key Lean fact was _int_unbounded, which says Int is an infinite sort. Real-indexed constant arrays were still rejected with an error. Arrays over uninterpreted sorts as index could not be used either, because such a sort may be finite. Plain arrays with store were already certified over Int, Real, and uninterpreted index sorts (PRs #68 and #69). This work belongs to milestone 4 of the project plan, "Broader theories and integration", which treats arrays as one of the theories to add.

What changed

  • Exporter. You can now export a certificate for an input with a constant array over Real indices.
  • Lean prelude. Generated files can now prove that Rat is unbounded, just as they already did for Int.
  • Reconstructor. The default-value lemmas are now used at the array's real index type instead of always at Int.
  • Lean output size. Each file now proves only the unboundedness theorems its own array sorts need, so Int-only output is unchanged.
  • Tests. Five new Real-index inputs are checked in Lean, and new tamper tests show that relabelled certificates are refused.
  • Docs. The README and the plan now say that Int and Real indices are supported and uninterpreted ones are not.

An analogy for the new theorem: for any finite guest list of numbers, you can name a number not on it. Take the largest entry and add one. The default-value lemmas need nothing more.

An array of sort (Array Real Int) becomes a Lean function from Rat to Int.

private theorem _rat_unbounded : forall l : List Rat, Exists (fun x : Rat => Not (List.Mem x l)) := by
  intro l
  have _b : Exists (fun b : Rat => forall y : Rat, List.Mem y l -> y < b) := by
    induction l with
    | nil => exact Exists.intro 0 (fun _ h => nomatch h)
    | cons a t ih =>
      obtain ⟨b, hb⟩ := ih
      refine Exists.intro (max (a + 1) b) (fun y h => ?_)
      cases h with
      | head => grind
      | tail _ h => have := hb y h; grind
  obtain ⟨b, hb⟩ := _b
  exact Exists.intro b (fun h => Rat.lt_irrefl (hb b h))

This is the new theorem. By induction, every finite list of rationals has an upper bound outside the list. The grind tactic closes each arithmetic step.

Both theorems everywhere. The reviewer rebuilt the Lean output for the Int-only inputs with the base code and with the PR. Every file had grown by the unused 14-line Rat theorem. The cost was small, but the claim "Int output is unchanged" was false. Now each file proves only the theorems for its own index sorts. The same comparison then showed no changed lines.

Stale plan heading. The plan section was still titled "Constant arrays over Int indices", and the new note had the wrong date. A reader scanning headings would miss Real support. Both were corrected.

A test with a misleading name. A tamper test called const_of_int changed the element sort, not the index sort. The reviewer relabelled Real indices as Int by hand. The source-match check caught it, but no test asserted that. So a later refactor could weaken the check unnoticed. The test was renamed, and two new cases now expect "certificate source does not match the original input".

Risks and open questions

  • No z3test benchmark uses Real-indexed constant arrays. Only synthetic inputs exercise this path.
  • Real-indexed arrays are modelled as functions over Rat. This reuses PR #69's argument that a rational model always exists.

What comes next

The PR lists these follow-ups, all recorded in the project backlog:

  • Constant arrays over uninterpreted index sorts. They need Z3's small-domain encoding.
  • Comparison facts for constant arrays outside rewrite steps.
  • A real QF_ALRA or QF_AUFLIRA benchmark as a regression test.
  • Bool elements, nested arrays, map, and as-array, which are still rejected.

Glossary

array
A value that maps each index to an element, like a function. (Array Real Int) maps reals to integers.
axiom
A statement Lean accepts without proof. Every new axiom is something the reader must trust.
clause
A disjunction of literals, such as p or not q.
clause log
The record Z3 writes of each clause it learns or assumes, with a hint saying why it holds.
constant array
An array with the same element at every index. In SMT-LIB, ((as const (Array Real Int)) 0) is 0 everywhere.
default value
The element an array holds at all but finitely many indices. A constant array of 0 has default 0.
induction
Proving a fact for the empty list, then showing it survives adding one more element.
infinite sort
A sort with infinitely many values, such as Int or Real. No finite list contains all of them.
rational number
A fraction of two integers, such as 5/2. Lean's type is Rat, used here for SMT-LIB Real.
refutation
A proof that a set of assertions leads to False.
rewrite
A step that replaces a term by an equal, simpler one, such as x + 0 by x.
sort
The type of a value in SMT-LIB, such as Int, Real, Bool, or an array sort.
store
Writing an array at one index. (store a i v) is a with v at i.
tactic
A Lean command that builds part of a proof automatically, such as grind or omega.
tamper test
A test that edits a certificate on purpose and checks that the checker rejects it.
theorem
A statement with a proof that Lean has checked.
theory lemma
A clause that holds by the rules of one theory, such as arrays or arithmetic, and not by pure logic.
trust boundary
The list of things one must believe without checking, such as Lean's kernel and its standard axioms.
uninterpreted sort
A sort declared by name only, with no fixed set of values. It may have just one or two values.
