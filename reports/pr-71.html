Certify constant arrays over Real indices in Lean via the clause log

Pull request levnach/z3#71 into master · State: OPEN · Opened 2026-11-04T09:04:12Z · Loop iteration 71

This pull request is open and not merged. The change under review ends at commit 8c10fbd02.

In one paragraph

This PR lets the pipeline certify unsat results that involve constant arrays whose index sort is Real. Until now, only constant arrays over Int indices were accepted. The array solver links constant arrays to other arrays through their default value. Lean can only define that value when no finite list covers the whole index sort. The PR adds the matching unboundedness theorem for the rational numbers, and reuses the existing default-value facts at that sort. Every new step is a checked theorem. There is no sorry, no new axiom, and the trust boundary is unchanged.

Background

The previous PR, #70, certified constant arrays over Int indices through the clause log. Real-indexed constant arrays were still rejected by the exporter. The rejection was not about soundness. Real is an infinite sort, just like Int. Only the Lean unboundedness theorem for Rat was missing. Uninterpreted sorts as indices stay out of scope, because they may be finite. The work belongs to milestone 4 of the project plan, "Broader theories and integration", which treats arrays as one of the theory extensions.

What changed

  • The exporter now accepts constant arrays over Real indices and still rejects every other index sort except Int.
  • The Lean output now proves that no finite list contains every rational number, the Real counterpart of the existing Int theorem.
  • The reconstructor now picks the right unboundedness theorem from the array's index sort, so default values work over Rat as they did over Int.
  • A generated file now proves only the unboundedness theorems of the index sorts it actually uses, so Int-only output is byte-identical to before.
  • Five new Real-index test inputs are checked in Lean, and new tamper tests show that relabelled certificates are rejected.

Grouped by component: the exporter change is a two-line widening of a check. The replay module got a comment update only. The reconstructor carries the real work: a lookup table _UNBOUNDED maps Int and Real to their theorems. The README and the project plan describe the new scope. There is no C++ change. The PR has two commits: the feature commit d5f4eea00 and a review-fix commit 8c10fbd02.

Worked example

This input is the PR's test real_index_2549, a Real-index version of z3test's 2549.smt2. It is unsat for a simple reason. Writing one cell into two arrays does not change their default values, which are 0 and 1. So the two updated arrays cannot be equal. Think of a default value as the background colour of a canvas. Painting one dot does not change the background.

(a) The input

(declare-const A0 (Array Real Int))
(declare-const A1 (Array Real Int))
(assert (= A0 ((as const (Array Real Int)) 0)))
(assert (= A1 ((as const (Array Real Int)) 1)))
(assert (= (store A0 2.5 3) (store A1 2.5 3)))
(check-sat)

Each array of sort (Array Real Int) becomes a Lean function from rationals to integers, and the constant array holding 0 is the constant function over Rat.

theorem unsat (_atoms : Nat -> Prop) (_vars : Nat -> Rat) (_ivars : Nat -> Int) (_m : Interpretation)

The main theorem says that the three assertions together imply False, for every possible interpretation.

private theorem _rat_unbounded : forall l : List Rat, Exists (fun x : Rat => Not (List.Mem x l)) := by
  intro l
  have _b : Exists (fun b : Rat => forall y : Rat, List.Mem y l -> y < b) := by
    induction l with
    | nil => exact Exists.intro 0 (fun _ h => nomatch h)
    | cons a t ih =>
      obtain ⟨b, hb⟩ := ih
      refine Exists.intro (max (a + 1) b) (fun y h => ?_)
      cases h with
      | head => grind
      | tail _ h => have := hb y h; grind
  obtain ⟨b, hb⟩ := _b
  exact Exists.intro b (fun h => Rat.lt_irrefl (hb b h))

This new theorem shows by induction that any finite list of rationals misses some rational, using the grind tactic to find a number above every element.

private theorem th_lemma_35 ... : (formula_34 _atoms _vars _ivars _m) := by
  unfold formula_34 term_33 term_1
  have _t2 : (term_2 _atoms _vars _ivars _m) = (@_const_array Rat Int (((0 : Int)))) := rfl
  have _d33 := _default_const (I := Rat) _rat_unbounded (((0 : Int)))
  first | omega | grind (splits := 64)

This lemma uses the new theorem to prove that the default value of the constant array of 0 over Rat is 0.

Other lemmas in the file apply _default_store _rat_unbounded in the same way, to show that a store keeps the default value.

Review

The reviewer approved the change with no blocker, major, or minor findings. They ran the full suites, then attacked the change by hand. Swapping the Rat theorem for the Int one made Lean reject the file with type errors. Relabelling Real indices as Int was caught by the check that the certificate matches the input. They reported three nits, and all three were fixed in 8c10fbd02.

Nit 1: every file proved both theorems

The reviewer rebuilt each Int-indexed test input with the old and new code and compared the output. Each new file had 14 extra lines: the Rat theorem, which those files never used. That contradicted the claim that Int output was unchanged, and it made Lean check dead code. The fix emits only the theorems of the index sorts that the file's arrays use. The same comparison now shows zero changed lines.

Nit 2: a stale heading and a wrong date

The project plan still titled the section "Constant arrays over Int indices", and the new note had the wrong date. A reader scanning headings for Real support would have missed it. The heading now names both Int and Real, and the note is dated 2026-11-04.

Nit 3: a test that tested something else

A tamper test named const_of_int claimed to relabel an index to Int. It actually changed the element sort. So no test asserted that a Real-to-Int index relabel is rejected. A later refactor could have weakened that check silently. The test was renamed, and two new cases relabel the whole certificate and expect "certificate source does not match the original input".

Risks and open questions

  • No z3test benchmark uses Real-indexed constant arrays. Only synthetic inputs exercise this path.
  • Real-indexed arrays are modelled as functions over Rat. This rests on the same argument as PR #69: a rational model exists, and arrays are determined by their reads at rational indices.
  • The CI results for this PR are not known yet.

What comes next

  • Constant arrays over uninterpreted index sorts, which need Z3's small-domain encoding.
  • Comparison facts for constant arrays outside rewrite steps.
  • A real QF_ALRA or QF_AUFLIRA benchmark as a regression test.
  • Arrays with Bool elements, nested arrays, map, and as-array, which are still rejected.

Glossary

array
A total map from an index sort to an element sort. (Array Real Int) maps every rational index to an integer.
axiom
A statement Lean accepts without proof. Adding one widens what must be trusted.
certificate
The JSON file the exporter writes. It records the input and every proof step Z3 took.
clause
A disjunction of literals, such as (or (not p) q). A literal is an atom or its negation.
clause log
The record of every clause the solver adds or deletes, with a hint saying why each one holds.
constant array
An array with the same value at every index, written ((as const (Array Real Int)) 0) in SMT-LIB.
default value
The value an array takes at all but finitely many indices. The default of a constant array of 0 is 0.
finite and infinite sorts
A finite sort has finitely many values. Int and Real are infinite. An uninterpreted sort might be finite.
if-then-else term (ite)
A term that picks one of two values by a condition: (ite c a b).
induction
A proof method: show a fact for the empty list, then show it survives adding one element.
rational numbers (Rat)
Fractions such as 5/2. Lean models the SMT-LIB sort Real as Rat.
refutation
A proof that a set of assertions leads to False.
rewrite step
A proof step that replaces a formula with an equivalent, simpler one.
select and store
(select a i) reads array a at index i. (store a i v) is a copy of a with index i set to v.
sorry
A Lean placeholder that skips a proof. A trusted file must contain none.
sort
The type of a value, such as Int, Real, Bool, or (Array Real Int).
tactic
A Lean command that builds part of a proof. grind and omega are tactics.
tamper test
A test that edits a certificate on purpose and checks that the reconstructor rejects it.
theorem
A statement together with a proof that Lean checks.
trust boundary
The set of things one must believe without checking, here Lean's kernel and its standard axioms.
unboundedness theorem
A theorem saying no finite list contains every value of a sort. Like a guest list: however long, someone is left outside.
uninterpreted sort
A sort declared by name only, with declare-sort. Nothing is known about how many values it has.
