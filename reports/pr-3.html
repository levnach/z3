In one paragraph

Before this change, the Lean reconstructor emitted most refutations as a single theorem nesting one let-bound step per proof node. That term elaborates superlinearly, so a 7-level QF_UF equality diamond and pigeonhole-5, each around 1,600 steps, exhausted Lean's default heartbeat budget even though every individual step is trivial. Lemma outlining, which existed only for arithmetic certificates above 2,000 steps, now applies to every fragment above 500 steps, cuts unshared chains every 500 nested steps, and skips derivations the root never uses. Propositional lemmas receive their decidability witnesses as explicit parameters, so that slice still reports no axioms. Both failing inputs now check in about 3 s, and no C++ changed.

Background

The repository's Lean proof plan aims at unsat results from Z3 that an independent Lean checker accepts without trusting the solver. Z3 produces evidence, either a legacy proof object or, for theory problems, the clause log. A Python exporter turns it into a JSON certificate marked "unverified", and a reconstructor translates that into Lean source whose theorem hypotheses are the original assertions. Lean's kernel then checks the file with trust level zero, and only on success is the artifact published.

Z3 proof object or clause log  →  JSON certificate (unverified)  →  Lean source  →  Lean kernel check

The plan's milestone 2 asks for a kernel-checked Boolean slice with no sorry and no solver-oracle axioms, and milestone 3 adds equality and linear arithmetic, one fragment at a time. Both fragments worked for short inputs but not at realistic sizes. The plan's scaling survey of 2026-09-25 had named the nested let chain as a resource cliff, and the iteration-2 backlog recorded heartbeat failures on 8- and 16-level QF_UF diamonds. The maxHeartbeats raise in the generated file covers only the grind lemmas, so every fragment was capped at roughly 1,000 steps. This PR removes that cap by generalizing the outlining built earlier for the LassoRanker arithmetic certificate.

What changed

Lean reconstructor

The outlining threshold drops from 2,000 to 500 proof steps and the arithmetic-only condition is removed. A new boundary computation marks as separate lemmas every shared subproof, the root, and any single-use premise whose size would push its consumer's lemma above 500 nested steps. Sizes are computed in one increasing pass over the proof DAG, since arguments are known to precede their node. Only steps reachable from the root are considered, because the clause log can record derivations the refutation never uses.

Arithmetic and uninterpreted-sort lemmas keep local classical decidability witnesses, since those slices already report the three standard Lean axioms through Rat and grind. Propositional lemmas instead take every witness they or their callees need as explicit Decidable parameters. The main theorem introduces those witnesses with the existing constructive continuation and passes them to the root lemma, so #print axioms still reports none for outlined propositional theorems.

Tests

Twelve tests were added across the three fragment suites, two of them after review. The QF_UF suite checks the 7-level diamond end to end, asserting that every lemma defines at most 500 steps and that the lemma bodies together define exactly the reachable steps, and sweeps all documented QF_UF inputs with forced outlining and chunks of three steps. The integration suite does the same for every documented propositional input and the six z3test Boolean inputs, asserting them axiom-free, and checks pigeonhole-5 end to end. The arithmetic suite now default-outlines a random ite instance above the threshold and forces chunk-3 cuts inside Farkas, gate-clause, and Rat-valued ite subproofs.

Documentation

The Python examples README and the Lean README describe the new rule and the axiom-free witness parameters. The proof plan gained a dated note with measurements, and its LassoRanker section now points at the generalized rule.

Review

The reviewer approved with no blockers and no major findings, and independently verified that the trust boundary is unchanged: no sorry, no new axioms, and trust level zero untouched.

  • Minor 1, arithmetic coverage. The implementer claimed the random QF_LRA suite covered the newly outlined 500 to 2,000 step range, but those instances have at most 418 steps. Fixed: two arithmetic tests were added after review, one default-outlining a 596-step ite instance and one forcing chunk-3 cuts inside arithmetic subproofs.
  • Nit 2, reachable-only emission. Outlined mode emits only root-reachable steps while flat mode emits every step, so an unused derivation that only Lean would reject is accepted above 500 steps and rejected below. Accepted as designed: Python shape checks still run on every node and dropping unused work is sound. Follow-up for the flat path.
  • Nit 3, scraped witness sets. The propositional lemma signature, now load-bearing for the axiom-free guarantee, is derived by pattern-matching identifiers in generated text rather than from per-step support data. Not changed: this is the pre-existing arithmetic mechanism and it is fail-safe, since a wrong parameter makes Lean reject the file. Recorded as a follow-up.
  • Nit 4, stale plan paragraph. The LassoRanker section of the plan still described the old rule. Fixed with a cross-reference to the new dated note.

Risks and open questions

  • Generated text changes for every certificate above 500 steps, including arithmetic ones between 500 and 2,000 steps that were one theorem before. The theorem statement and trust boundary are unchanged in every mode.
  • LassoRanker was not re-run. Its 41,000-step certificate now gets extra chunk boundaries. Smaller lemmas should only reduce per-lemma cost, but the total was not measured.
  • Witness parameter count. Propositional root lemmas take one parameter per witness, 876 for pigeonhole-6, and the main theorem nests that many continuations. This is pre-existing behaviour and it checks, but it is a cost to watch on larger SAT proofs.
  • CI time. The releaseClang Lean step grows by roughly a minute. The forced chunk-3 sweeps are the first candidates to trim.
  • Two Windows gating builds were still running at the last recorded snapshot, so their result is unknown here.

What comes next

  • Per-lemma cost at scale is the next performance item: pigeonhole-6 verifies in 88 s across 3,071 lemmas.
  • Derive witness sets from per-step support data instead of identifier scraping, and consider skipping unreachable steps in the flat path too.
  • Add a long QF_UF or Boolean input to the z3test Lean regression corpus so the CI matrix covers outlining directly.
  • Still on the backlog: harmless set-option commands, QF_UFLRA, several uninterpreted sorts, and QF_LIA.
