Certify one query of an incremental SMT-LIB script

Pull request: levnach/z3 #17 Merge commit: 5126563b Merged: 2026-10-16T08:31:35Z Loop iteration: 17

In one paragraph

Before this change, the exporter accepted an SMT-LIB script with exactly one check-sat query and nothing after it. It rejected push, pop, reset, reset-assertions, check-sat-assuming, and any second query. Now it certifies one query of an incremental script at a time. It replays the script's scopes, collects the assertions in scope at the chosen query, and appends the query's assumptions as further assertions. That snapshot is solved on its own, and the certificate records which query it is about. The reconstructor rebuilds the same snapshot from the original script, so nothing about it is taken from the certificate. The theorem Lean checks says that the assertions in scope at that query, together with its assumptions, are contradictory. Each of them becomes one hypothesis.

Background

The pipeline already certified propositional input, uninterpreted functions with equality, and linear real and integer arithmetic, through either the legacy proof object or the clause log. But its frontend only understood one non-incremental query. The backlog has listed incremental input since iteration 15, under the open question of which snapshot a certificate should describe. This PR answers that question and serves milestone 3 of the plan, which completes each fragment end to end. It is also a first step toward the milestone 4 goal of preserving exact incremental and assumption contexts.

What changed

A short analogy for scopes: think of a stack of transparent sheets laid over a drawing. push adds a sheet, and pop removes the top sheet with everything drawn on it. A certificate is now a photo of the stack at one moment, namely at the chosen query.

  • Pick a query. You can certify a script with push, pop, and several check-sat queries by naming one query with its zero-based index through the --query flag.
  • Assumptions count. The assumptions of check-sat-assuming, and of Z3's check-sat with literal arguments, become hypotheses of the theorem.
  • Z3's reset semantics. reset-assertions removes every assertion but keeps the declarations and the open scopes, exactly as Z3 does, and reset clears everything.
  • Safer certificates. The certificate carries format version 2 and the query index. The reconstructor rejects version 1 certificates and any certificate pointed at a query whose assertions differ.
  • Real corpus files. Five z3test regression scripts (incsat, t143, 3632, 3732, unsatcore) are now certified verbatim in Lean, two of them at both of their queries.

Worked example

This input was built from the incsat test added by the PR. It has three queries. The first is satisfiable, the second is unsatisfiable, and the third is satisfiable again because the pop removed the two negative assertions. We certify the second query, which has index 1.

(a) The input

(declare-const p Bool)
(declare-const q Bool)
(assert (or p q))
(check-sat)
(push)
(assert (not p))
(assert (not q))
(check-sat)
(pop)
(check-sat)

(b) Before

The exporter from the parent of the merge commit stopped at the first scope command.

proof_certificate.py: error: unsupported SMT-LIB command: push

Removing push and pop did not help, because a second query was rejected as well.

proof_certificate.py: error: commands changing the problem after check-sat are not supported

Since no certificate was produced, the old reconstructor had nothing to run on.

(c) After

The exporter was run with --query 1. The certificate records "format_version": 2 and "query": 1. The reconstructor wrote the Lean file below, and the Lean check accepted it with "Lean checks passed." 

-- Certified query: check-sat 2 of 3 (zero-based index 1); the assertions below are the ones in scope there, assumptions included.
-- Atom 0: "p"
-- Atom 1: "q"
...

The header names the certified query so a reader knows which snapshot the theorem is about.

def formula_0 (_atoms : Nat -> Prop) : Prop := _atoms 0
def formula_1 (_atoms : Nat -> Prop) : Prop := _atoms 1
def formula_2 (_atoms : Nat -> Prop) : Prop := (Or (formula_0 _atoms) (formula_1 _atoms))
def formula_3 (_atoms : Nat -> Prop) : Prop := (Not (formula_0 _atoms))
def formula_4 (_atoms : Nat -> Prop) : Prop := (Not (formula_1 _atoms))
...

These definitions name the two atoms and the three assertions in scope at the second query.

theorem unsat (_atoms : Nat -> Prop)
    (_h0 : (formula_2 _atoms))
    (_h1 : (formula_3 _atoms))
    (_h2 : (formula_4 _atoms))
    : False :=
  ...
  let _step_9 : (formula_8 _atoms) :=
    (Or.elim _step_5 (fun _literal => (False.elim (_step_7 _literal))) (fun _tail => (False.elim (_step_6 _tail))))
  _step_9

The theorem takes exactly the three assertions in scope as hypotheses, not the two popped ones, and derives False by case analysis on the disjunction.

Review

The reviewer approved the change. There were no blockers and no major findings, two minor ones, and four nits.

  • Minor, fixed: reset-assertions did not follow Z3. The reviewer read Z3's own implementation, which keeps the scope stack and every declaration. The exporter instead followed the SMT-LIB standard, which pops every scope. The reviewer wrote two scripts that Z3 answers unsat, and the exporter rejected both, once with "unknown constant q" and once with "pop 1 exceeds the 0 open scopes". A rejection is never a wrong theorem, so this was safe. But the documentation described Z3 wrongly and overstated coverage. The fix clears the assertions of every scope and keeps the declarations and the stack, with a new test.
  • Minor, fixed: stale README. A later paragraph still claimed that incremental scripts and check-sat-assuming are rejected. A reader would have concluded the feature does not exist.
  • Nit, fixed: unguarded clause-log test. The new test called the clause log core without the usual guard that skips when no Z3 executable is present. It moved to its own guarded test.
  • Nit, fixed: a confusing error message. A malformed assumption list such as (check-sat-assuming (p) (q)) slipped past the frontend and failed later with a Z3 parse error. The frontend now reports the real problem as soon as a closing parenthesis comes too early.
  • Nit, fixed for reset only. The exporter accepted get-model after a reset, although Z3 answers "model is not available". It now forgets the last result on reset. After reset-assertions Z3 still prints a model, so the exporter still accepts that.
  • Nit, not fixed: the script is tokenized twice. Returning the query index from the parser would change a function signature that the z3test harness uses. The second pass is cheap next to the solver run.

The reviewer also tampered with certificates by hand. Pointing one at a query with different assertions, at a missing query, or at an older format version was rejected every time. Pointing it at a query with an identical snapshot was accepted, which is the same theorem.

Risks and open questions

  • Nothing new is trusted. The query index is only a pointer into the script. The reconstructor rebuilds the snapshot itself and binds the certificate's assertions to it as before.
  • Assumptions are not restricted to literals. SMT-LIB allows only literals in check-sat-assuming, but Z3's parser accepts any Boolean term. The exporter follows Z3.
  • Z3 semantics, not the standard. Scoping and reset-assertions follow Z3 rather than SMT-LIB 2.6, because Z3 is what solves the snapshot. The global-declarations option stays rejected.
  • Incompatible format. Version 1 certificates are now rejected. No stored certificates exist in either repository.
  • Quiet behaviour change. An assertion after the only query is now ignored instead of rejected, since it belongs to no query.
  • Cost. Each query is solved from scratch, one export per query, by design.

What comes next

  • define-sort is now the first rejection of 61 incremental corpus files. Passing it through to Z3's parser is the next frontend widening.
  • The legacy proof object's truth-table proof of wide rewrite steps does not scale. Splitting only the touched atoms, or proving by a tactic first, would let 3632 pass there.
  • global-declarations true could be honoured by keeping declarations global. No corpus file needs it yet.
  • The z3test Lean matrix script needs a query index before the five new inputs can join the matrix.
  • A probe of mixed integer and real arithmetic found integer casts opaque to Lean's arithmetic tactic. That fragment needs explicit cast lemmas and was not attempted.

Glossary

assertion
A formula the script states as true, written (assert ...). Example: (assert (or p q)).
assumption
A formula that holds only for one query, given in (check-sat-assuming (...)). It is not kept afterwards.
Boolean
A value or variable that is either true or false. The sort of such values is written Bool.
certificate
The file the exporter writes. It holds the proof steps and the assertions they refer to, in a versioned format.
check-sat query
The command that asks the solver whether the current assertions can all be true. Also check-sat-using and check-sat-assuming.
clause
A disjunction of literals, such as "p or not q".
clause log
Z3's record of every clause it learned during search, with a hint for each. One of the two proof sources the exporter can use.
congruence
The rule that equal arguments give equal function results. If a = b then f(a) = f(b).
exporter
The Python script that runs Z3 on an input and writes the certificate.
hypothesis
A statement a theorem takes as given. Here, each assertion and assumption of the certified query.
incremental script
An SMT-LIB script with several queries, or with push, pop, or reset commands between them.
legacy proof object
Z3's older proof format, a tree of inference steps produced when proof generation is switched on. The other proof source the exporter can use.
literal
An atom or its negation, such as p or (not p).
propositional
Built only from Boolean variables and connectives such as and, or, not. No arithmetic or functions.
reconstructor
The Python script that turns a certificate and the original input into a Lean file for checking.
refutation
A proof that a set of formulas cannot all be true, ending in False.
rewrite
A proof step that replaces a formula by an equivalent one, for example by simplifying it.
scope
A group of assertions and declarations opened by push and discarded by pop.
snapshot
This project's word for the declarations, definitions, assertions, and assumptions in scope at one query.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that searches for a proof automatically, such as the one for linear arithmetic.
theorem
A statement with hypotheses and a conclusion that Lean has checked. Here the conclusion is always False.
truth table
A proof that tries every assignment of true and false to the atoms. It doubles in size with each atom.
uninterpreted function
A function symbol with a name and sorts but no fixed meaning, such as (declare-fun f (Int) Int).
