Certify negated distincts whose every pair is refuted in Lean

Pull request levnach/z3 #91 · state OPEN · opened 2026-11-07T23:05:53Z · loop iteration 91

This pull request is open and not merged. The change under review is commit 432b82e, on top of base aa82260.

In one paragraph

An input that asserts the negation of a distinct over many Int terms, while pinning every term to a different number, now passes the Lean check. Z3 already produced a refutation for it, but the Lean file failed. The rewrite step that turns the negated distinct into a disjunction of pair equalities was handed to the grind tactic, which ran out of heartbeats. It is now proved by one De Morgan step per pair. Two further changes keep very wide inputs fast. The lemma steps that refute each literal of a wide clause now produce linear text instead of quadratic text. And outlining now counts a very wide step by its width. The 40-term case now checks in about 8 seconds. Every new proof is still checked by Lean, so the trust boundary does not move.

Background

The previous iteration taught the pipeline to handle a positive distinct of more than 32 terms. Its notes listed one gap as "still open". A negated wide distinct, where the proof refutes every pair, exported through the clause log but produced Lean text that grew quadratically and failed. The PR describes failures at 30 and 40 terms. In our run for this report, the old pipeline already failed at 8 terms. This work serves milestone 3 of the project plan, "Equality and linear arithmetic".

What changed

  • The rewrite of (not (distinct ...)) into the disjunction of its pairs is now proved one pair at a time, the way you peel an onion layer by layer, instead of asking grind to search the whole thing.
  • A pair that is written the other way round, such as (= x1 x0), is also handled, using the symmetry of equality. Any other shape still falls back to grind as before.
  • Refuting the hypotheses of a clause wider than 32 literals now starts from a saved "tail" of the negated clause. It is like putting a bookmark every 32 pages, so you never count from page one again.
  • When long proofs are split into separate Lean theorems, a step with more than 64 premises or literals now counts as that many steps. A mover counts a piano as many boxes for the same reason.
  • New tests cover 40 Int terms, 12 terms over an uninterpreted sort, and the reversed-pair case.

The distinct becomes a conjunction of 28 disequalities. Its negation must be shown equivalent to the disjunction of the 28 pair equalities.

private theorem rewrite_64 (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    : (formula_63 _atoms _vars) := by
  unfold formula_63 formula_9 formula_8 formula_62
  refine Iff.trans Classical.not_and_iff_not_or_not (or_congr Classical.not_not ?_)
  refine Iff.trans Classical.not_and_iff_not_or_not (or_congr Classical.not_not ?_)
  ...
  refine Iff.trans Classical.not_and_iff_not_or_not (or_congr Classical.not_not ?_)
  exact Classical.not_not

Each line peels one pair. De Morgan turns "not (A and rest)" into "not A or not rest". Double negation turns "not not (x = y)" into "x = y". The congruence or_congr leaves the rest for the next line. There are 27 such lines and one final exact.

Review

The reviewer approved the change, with no blockers and no major findings.

  • Minor, test coverage: fixed. The reviewer looked for an input where Z3 writes a pair as (= x1 x0). The rewriter never did, so the eq_comm line went untested. A mistake there could break real inputs while every test stayed green. The new test reverses two pairs of a real certificate. Lean accepts it, and rejects a copy without eq_comm.
  • Nit, verbosity: not changed. The 40-term proof splits into about 1,284 small theorems. This is correct and fast. Grouping them would change the outlining design, so it is a follow-up.
  • Nit, documentation: fixed. The comment on _outline_boundaries did not mention width weighting. It now does.

Risks and open questions

  • Splitting into theorems changes only for proofs with more than 500 steps and a step wider than 64. Those proofs now have more, smaller theorems.
  • The lemma-step text changes only for clauses wider than 32 literals.
  • The new proof uses three standard Lean lemmas. They stay within the standard axioms.
  • The 33-term chain and the 34-term uninterpreted-sort input still take 90 to 150 s. That is too slow for CI.

What comes next

  • Group the single-use premises of a very wide unit resolution into shared theorems.
  • A positive distinct rewritten into its conjunction of disequalities still goes to grind.
  • Other candidates from the previous iteration remain open, such as reordered distincts over the same terms.

Glossary

axioms (standard)
The few basic facts Lean assumes without proof, such as classical logic. A proof that uses only these trusts nothing else.
certificate
A file in which Z3 records the steps of its proof so that another tool can check them.
clause
A disjunction of literals, such as x = 1 or not p or y < 3.
clause log
A record of the clauses Z3's solver learns while it works. It is one source of proof steps for the certificate.
congruence
Replacing a part of an expression by an equal or equivalent part. If A is equivalent to C, then A or B is equivalent to C or B.
conjunction
Formulas joined by "and". It is true only when every part is true.
De Morgan's law
"Not (A and B)" is equivalent to "(not A) or (not B)".
disequality
A statement that two terms are different, written x ≠ y or (not (= x y)).
disjunction
Formulas joined by "or". It is true when at least one part is true.
distinct
The SMT-LIB operator that says all its arguments differ. (distinct a b c) means a ≠ b, a ≠ c and b ≠ c. With n terms there are n(n-1)/2 pairs.
double negation
"Not not A" is equivalent to "A". This is a law of classical logic.
grind
A general-purpose Lean tactic that searches for a proof on its own. It is powerful but can be slow on large goals.
heartbeat
Lean's unit for counting work. When a proof uses more than its limit, Lean stops with a timeout error.
hypothesis
A fact assumed for the moment inside a proof, to be discharged later.
lemma step
A proof rule that turns a refutation built under some hypotheses into a clause. The clause says at least one hypothesis is false.
linear and quadratic
How size grows with input. Linear: twice the input gives twice the text. Quadratic: twice the input gives four times the text.
literal
An atomic formula or its negation, such as x = y or not (x = y).
outlining
Splitting a long proof into several separate Lean theorems so that each stays within the heartbeat limit.
refutation
A proof that a set of assertions leads to False, so they cannot all hold.
rewrite step
A proof step that replaces a formula by an equivalent, usually simpler, one.
sort
The type of a value in SMT-LIB, such as Int, Real or Bool.
symmetry of equality
x = y is equivalent to y = x. In Lean this is eq_comm.
tactic
A command in a Lean proof that tells Lean how to make progress on the current goal.
trust boundary
The line between what is checked and what is simply believed. Here, only Lean and its standard axioms are trusted.
uninterpreted sort
A sort declared by the user with no built-in meaning, such as (declare-sort U 0). Only equality between its values is known.
unit resolution
A proof rule that removes literals from a clause using facts that contradict them, until one literal or False is left.
