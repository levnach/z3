In one paragraph

Do not lose the conclusion.

This PR rejects malformed hints that the native arithmetic checker previously accepted. A zero coefficient could erase the conclusion. Omitting the conclusion could leave its row empty. Both looked like successful equality proofs. The fix closes those paths without changing solver search or Lean's independent verification.

This is false proof acceptance, not a demonstrated wrong solver result. The counterexamples are invalid proof logs with satisfiable literals. They are not examples of Lean accepting a false theorem.

How to read the hint

The premises force x = y. The last literal asserts its negation, giving a contradiction. A valid refutation must justify that equality, not discard it.

Worked counterexamples

Two ways to get a misleading zero

Case 01 · zero target coefficient

The equality is multiplied away.

(implied-eq 0 (not (= x y)))

The target equality is represented by a weighted difference. Multiplication by zero destroys the connection to x = y.

Intended target: x − y = 0
Erased target: 0 × (x − y) = 0

The old checker accepted the zero row. Yet the actual countermodel has x = 2 and y = 3. The disequality is true. No contradiction exists.

Case 02 · missing conclusion

There is no equality to prove.

(implied-eq 1 (<= x 0.0))

This hint ends in an inequality, not a disequality. The checker collected a premise but never populated the conclusion row.

Initial conclusion row: 0
Conclusion actually supplied: none

The old fall-through path still checked the untouched zero row. The actual countermodel has x = 0, satisfying the only literal. Again, nothing establishes a contradiction.

The patch

Two guards, no new proof rule

Keep the target meaningful.

- if (!is_numeral(arg1, coeff))
+ if (!is_numeral(arg1, coeff) || coeff.is_zero())
      return false;

The conclusion parser now rejects a zero coefficient. Nonzero coefficients preserve which equality the row represents.

Require the conclusion path.

- return check(rt);
+ return rt != implied_eq_t && check(rt);

An implied-equality hint can succeed only through the earlier branch that parses its final disequality. Missing, empty, and incomplete conclusions cannot fall through.

Scope and next step

A narrow correction, not a blanket guarantee

The patch addresses these conclusion-validation gaps, not every arithmetic proof rule. It does not prohibit zero coefficients elsewhere or introduce new Lean assumptions. Regression evidence supports the change, but is not a formal proof of the entire native checker. The PR is merged. The live check links above show subsequent CI results.

Quick reference

Glossary

Coefficient
A numeric weight attached to a literal or arithmetic expression.
Conclusion
The proposition that the premises are supposed to establish.
Countermodel
A choice of values showing that the claimed inference is not justified.
Disequality
A statement that two values differ, such as (not (= x y)).
Hint
Native evidence proposing how to justify an inference. It still needs checking.
Kernel
The small trusted component that checks the final Lean proof term.
Literal
An atomic proposition or its negation, such as x <= y or x != y.
Premise
A proposition used as an assumption when proving a conclusion.
Refutation
A proof deriving a contradiction from the input assertions.
Row
A stored linear combination of terms and a constant. Here it represents an equality target.
SMT fallback
A solver-based diagnostic attempted when native proof-rule checking does not verify a claim.
Sort
The type of an SMT value, such as Int or Real.
