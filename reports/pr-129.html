In one paragraph

This PR teaches the Lean reconstruction to handle the absolute value of a constant of sort Real, such as (abs (- 2.5)). Z3's rewriter replaces such a term by its numeral, here 2.5. A rewrite step of the certificate then rests on a congruence over that numeral. In Lean the same abs is an if-then-else term. The tactic grind could not match it with the numeral inside the argument of an uninterpreted function. The reconstruction now proves each such abs equal to its value and substitutes the value. Clause-log certificates with these terms now yield a refutation that Lean accepts. No definition, theorem statement, or axiom changes.

Background

Before this PR the pipeline already wrote a Real abs as its if-then-else term. Lean rejected clause-log certificates where the abs of a constant sat under an uninterpreted function, a predicate, an array read, a floor, or is_int. Certificates from the legacy core were not affected, because that proof evaluates the abs itself. The work serves milestone 3 of the plan, equality and linear arithmetic. Arrays themselves belong to milestone 4, broader theories.

What changed

Lean reconstruction

  • A step that reaches a Real abs of a constant now proves the abs equal to its value and replaces it throughout that step, inner abs terms first.
  • A floor over such a term now gets its value, so the floor of |−2.5| is stated as 2.
  • When two function arguments are compared, an abs of a constant counts by its value, so (+ (+ 2.0 (- 3.25)) (abs (- 0.25))) is matched with −1.0.
  • Constant indices of array reads are matched the same way, which also fixes one input without any abs.

An analogy: a teacher first shows that |−2.5| is 2.5, then writes 2.5 over every |−2.5| on the board. After that, two lines compare at a glance.

(assert (not (= (g (abs (- 2.5))) (g 2.5))))

Review

The reviewer approved the first commit with no blockers and no major findings. In 75 certificate pairs from before and after, definitions and theorem statements were identical. The second commit answers the findings.

  • Minor, fixed: a test that could not fail. The reviewer made three replacements name a term the goal does not contain, and Lean still accepted them. The replacement always finds its term in the fact stated just before it. The new test removes only the replacements and requires Lean to reject four inputs.
  • Minor, fixed: a wrong reason for try. The replacement sat under try, which lets a failing tactic pass silently. The reviewer made it mandatory and Lean still accepted everything, so the wrapper could only hide failures. It is removed.
  • Minor, fixed in part: two untested code paths. The reviewer deleted each path, and every test still passed. A new array input now needs the first path in Lean. No input was found that needs the second, so a test pins only its text.
  • Two nits, fixed. The new Lean tests now check that the theorem has one hypothesis per assertion. One more seed is pinned, which Lean rejects when one group of the new facts is missing.

Risks and open questions

  • A failing replacement is now an error, so an uncovered input shape could be rejected where it verified before. None was seen.
  • Many certificates change text, and an extra equation could change what grind does on an uncovered input.
  • The older replacement of floor values is still under try, for the reason the review disproved.
  • An abs over the floor of a constant still fails.
  • Two probe inputs exceeded the solver's 60 second limit at export, which was not investigated.

What comes next

  • Give a value to an abs over the floor of a constant, as in (g (abs (- (to_real (to_int 2.5)) 4.5))).
  • Match read indices that are not constants, store indices, and stored values. No failing input is known.
  • Weigh two reviewer suggestions: state the abs facts only where a floor or an array term is reached, and count an abs by its value in if-then-else conditions too.
  • The other candidates of the loop's backlog are unchanged.

Glossary

absolute value (abs)
The distance of a number from zero. (abs (- 2.5)) is 2.5.
array
A value that maps indices to elements. A read is written (select a i), and a store is written (store a i v).
assertion
A formula the input states as true, written (assert ...).
axiom
A statement accepted without proof. The generated Lean files add none.
certificate
A file of proof steps that an independent checker can replay.
clause log
The list of clauses the solver records while it works, used here as a source of proof steps. A clause is a disjunction of literals.
congruence
The rule that equal arguments give equal results. From x = y it follows that (g x) = (g y).
constant
Here, a term with a fixed numeric value and no variable left in it, such as (+ 1.5 (- 4.0)).
floor
The largest integer not above a number, written to_int in SMT-LIB. The floor of 2.5 is 2. The test is_int asks whether a number equals its floor.
hypothesis
An assumption of a theorem. The generated theorem has one per assertion.
if-then-else term
A term that picks one of two values by a condition, written ite in SMT-LIB. Lean states |t| as "if t ≥ 0 then t else −t".
legacy core
Z3's older solver core, which builds a proof object directly. It is the second source of certificates, next to the clause log.
linear arithmetic
Arithmetic where variables are only added and multiplied by numerals.
mutant
A copy of a program with one deliberate defect. Good tests fail on it.
numeral
A number written out, such as 2.5.
predicate
An uninterpreted function whose result is Boolean, that is, true or false.
refutation
A proof that the assertions together lead to a contradiction.
rewrite step
A proof step that says a formula is equivalent to its simplified form.
rewriter
The part of the solver that simplifies terms before solving, for example by evaluating constants.
seed
The number that fixes what a random generator produces, so a random test can be repeated.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that builds part of a proof. grind searches for a proof by itself. generalize and subst replace a term using a proved equation.
uninterpreted function
A function symbol with no fixed meaning, such as g. Only congruence is known about it.
