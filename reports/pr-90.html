Certify distincts of more than 32 terms and wide distincts over Int

Pull request levnach/z3#90 · state OPEN · opened 2026-11-07T10:49:04Z · loop iteration 90

This pull request is not merged. The change under review is commit 53a2d5482, on top of base 2c5225f74.

In one paragraph

This PR lets the pipeline certify inputs that assert a wide distinct. Two things blocked them. Above 32 arguments, the solver encoded the distinct with fresh symbols, including a new sort and an uninterpreted function. The clause log replay rejected those. Now, when proofs are on, Z3 clausifies the distinct pairwise at any width. The second block was in Lean. The certificate keeps only the few pair equalities the refutation uses. The reconstructor then treated the whole distinct as one opaque leaf. Its cnf lemmas fell to tactics that ran out of heartbeats over Int from 30 arguments. Now each missing pair becomes a placeholder leaf, so a short propagation proof can pick out the one conjunct it needs.

Background

Before this PR, a distinct of up to 32 terms could be exported. The reconstructor already split it into its pair disequalities, but only when every pair had its own node in the certificate. Over QF_UF, the fallback tactic coped. Over linear integer arithmetic, it timed out from about 30 terms. Any root distinct wider than 32 terms failed at export, in every fragment. The work serves Milestone 3 of the plan, "Equality and linear arithmetic", which completes uninterpreted functions and integer arithmetic end to end.

What changed

  • A proof-logging run on a distinct of more than 32 terms now writes plain pair clauses, so the export no longer rejects it.
  • A distinct of which only a few pairs appear in the certificate is now split into all its pairs, with placeholders for the missing ones.
  • A cnf lemma such as "the distinct is false, or c0 differs from c1" now gets a three-step proof in Lean instead of a large search.
  • Runs without proofs behave exactly as before, and the old search is kept as a fallback after each new proof.
  • The plan and the Python README now describe the new rule and its known limits.

An analogy helps with the second and third bullets. Picture a seating rule: "no two of 30 students share a seat." That rule has 435 pairs. The proof only needs one of them, say "Ann and Bob do not share a seat." Before, Lean had to re-read the whole rule and search every pair. Now it points at the right line of the rule and stops.

(c) After

The current scripts produced example.lean. Lean accepted it ("Lean checks passed.").

def term_0 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Int := _vars 0
def term_1 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Int := _vars 1
...
def formula_30 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Prop := (And (Not ((term_0 _atoms _vars) = (term_1 _atoms _vars))) (And (Not ((term_0 _atoms _vars) = (term_2 _atoms _vars))) ... (Not ((term_28 _atoms _vars) = (term_29 _atoms _vars))) ...)

Each constant becomes a Lean term, and the distinct becomes a chain of 435 "not equal" conjuncts.

def formula_71 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Prop := ((term_0 _atoms _vars) = (term_1 _atoms _vars))
def formula_75 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Prop := (Not (formula_30 _atoms _vars))
def formula_76 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Prop := (Not (formula_71 _atoms _vars))
def formula_77 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Prop := (Or (formula_75 _atoms _vars) (formula_76 _atoms _vars))

formula_77 is the clause "the distinct is false, or c0 = c1 is false", one of the pair equalities the proof logged.

theorem unsat (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    (_h0 : (formula_30 _atoms _vars))
    (_h1 : (formula_35 _atoms _vars))
    (_h2 : (formula_38 _atoms _vars))
    (_h3 : (formula_41 _atoms _vars))
    (_h4 : (formula_44 _atoms _vars))
    : False :=
  ...

The theorem says the five assertions together imply False. That is the refutation Lean checks.

private theorem th_lemma_78 (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    : (formula_77 _atoms _vars) := by
  first
    | (refine Classical.byContradiction ?_
       refine (fun (_f1 : (Not (formula_77 _atoms _vars))) => ?_)
       have _f2 := (mt (@Or.inl _ _) _f1)
       have _f3 := (mt (@Or.inr _ _) _f1)
       have _f4 : (Not (formula_30 _atoms _vars)) := (mt (@And.left _ _) _f3)
       exact (False.elim (_f4 (Classical.byContradiction (fun _g => _f2 _g)))))
    | (unfold formula_77 formula_76 formula_75 formula_71 formula_30 term_29 ... term_0
       first | omega | grind (splits := 64))

This is the new feature. The proof assumes the clause is false, so the distinct holds and c0 = c1. And.left takes the distinct's first conjunct, c0 ≠ c1, which contradicts that. The old search stays as a second branch.

The new file has six such propagation proofs. The old file had none, which matches its six timeouts.

Review

The reviewer approved the PR, with no blocker or major findings.

Minor: proof logging is now quadratic. The reviewer asked how far the new pairwise encoding scales. They timed distincts of up to 2000 terms. Without a proof log, Z3 stays under a tenth of a second. With a log, 1000 terms took about 8 seconds and 2000 terms took about 48 seconds, with a 137 MB log. This matters because every tool that reads the log pays that price. The authors chose to document it instead of adding a cap. A cap would bring back the old encoding, which no checker can verify, so those inputs would still fail, only earlier. Proof logging is opt-in, and no z3test regression has a distinct wider than 32 terms. The cost is now stated in the C++ comments and in the plan.

Nit: outdated README. The Python README still said a distinct is split only when every pair was logged. That would mislead the next reader. It was fixed.

Suggestion: record a limit found while probing. The reviewer tried four extra inputs. Three verified. One failed: a wide distinct with an ite argument whose clauses Z3 had simplified under a unit clause. The reviewer showed this failure predates the PR. At 30 terms, the base and new reconstructors write byte-identical Lean text. The limit was added to the plan's "still open" list.

Risks and open questions

  • Proof logs for very wide distincts grow with the square of the width, as measured above.
  • The structural prover now sees split distincts in more cnf lemmas. Its work is bounded, and a failed attempt falls back to the old proof.
  • A placeholder leaf must print exactly like the distinct's conjunct. A test pins this. A mismatch would make Lean reject a proof, never accept a wrong one.
  • The trust boundary is unchanged. Theorem statements are built as before, and no axioms or sorry were added.
  • Whether the CI checks pass is unknown to this report.

What comes next

  • A negated wide distinct, where the proof refutes every pair, exports but gives quadratic Lean text. It needs a tail split of the long disjunction and a structural rewrite of not distinct.
  • Two distincts over the same terms in different orders still fail over Int.
  • Placeholder leaves have no bridge to a pair logged with swapped sides, such as (= b a).
  • The older ite case from the review still times out in Lean.
  • A clear rejection message above some width remains a possible follow-up.

Glossary

certificate
The JSON file Z3 exports that records the proof steps, so a separate checker can rebuild and verify them.
clause
An "or" of literals. (or (not p) q) is a clause with two literals.
clause log
The record of every clause the solver adds or derives while it searches. The exporter replays it against the input.
clausify
To rewrite a formula as a set of clauses. A distinct of n terms clausifies to n(n-1)/2 pair disequalities.
cnf lemma
A proof step that links a formula to the clauses it was turned into. Example: "the distinct is false, or c0 ≠ c1".
conjunct
One part of an "and". In A ∧ B, both A and B are conjuncts.
disequality
A statement that two terms differ, written (not (= a b)) or a ≠ b.
disjunction
An "or" of several formulas. A clause is a disjunction of literals.
distinct
The SMT-LIB operator saying all its arguments are pairwise different. (distinct a b c) means a ≠ b, a ≠ c, and b ≠ c.
equality
A statement that two terms have the same value, written (= a b).
fresh symbol
A name the solver invents during solving that does not appear in the input, such as distinct-elems here.
heartbeat
Lean's unit of work. A proof that uses more than its heartbeat limit is stopped with a timeout error.
if-then-else term (ite)
A term whose value depends on a condition. (ite (> x 0) a b) is a when x > 0 and b otherwise.
linear integer arithmetic (QF_LIA)
Formulas over Int with addition, constants, and multiplication by numbers, and no quantifiers.
literal
An atomic formula or its negation, such as (= c0 c1) or (not (= c0 c1)).
opaque leaf
A sub-formula the reconstructor treats as one unit without looking inside. A placeholder leaf stands for a pair that has no node of its own.
propagation proof
A short Lean proof that follows the and/or/not structure of a formula to reach a clause, without a general search.
QF_UF
Formulas with uninterpreted sorts and functions, equality, and no quantifiers.
refutation
A proof that a set of assertions leads to False.
sort
The type of a value, such as Int, Real, Bool, or a declared sort like U.
tactic
A Lean command that builds part of a proof automatically. omega solves integer arithmetic goals, and grind searches more broadly.
uninterpreted function
A function with a name and a type but no fixed meaning. The solver only knows that equal inputs give equal outputs.
unit clause
A clause with a single literal, so that literal must be true.
