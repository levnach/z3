In one paragraph

Before this change, the Python exporter that turns Z3's clause log into a proof certificate rejected every QF_LRA input containing a Real-valued ite term, even though Z3 solves such inputs and its clause log records them cleanly. The pull request teaches the exporter to treat a Real ite as Z3's arithmetic solver does, as an opaque variable tied to its two branches by gate clauses, and teaches the Lean reconstructor to prove those gate clauses from Lean's own ite_eq_left and ite_eq_right lemmas. It also fixes an independent replay bug: euf hints can carry congruence claims such as (cc (= a b)), which the replay wrongly tried to read as clause literals. The unsat theorem Lean checks is unchanged, no new axiom or trust assumption was introduced, and tampered certificates are still rejected before Lean runs. Common benchmark idioms such as abs, max, and guarded assignments can now be certified end to end by the Lean kernel.

Background

The project's goal, from the plan document in the repository, is unsat results from Z3 that an independent Lean checker accepts without trusting the solver. The pipeline has four stages. Z3 runs with proof or clause-log output enabled. A Python exporter converts that evidence into a versioned JSON certificate preserving the native term DAG, the original assertions, and every inference. The reconstructor translates the certificate into Lean 4 source in which every inference becomes a small lemma. Finally the Lean kernel checks that source at trust level zero, yielding a theorem that the original assertions imply False.

This work serves milestone 3 of the plan, "Equality and linear arithmetic". Its linear real arithmetic slice uses the sat.smt clause log rather than the core's proof objects, because the log carries the Farkas coefficients the proof objects omit. Theory hints become th-lemma nodes, Tseitin hints become def-axiom nodes, and Lean proves each theory lemma with the grind tactic over a Rat encoding of the Real variables. Real-valued ite was a known gap: the plan's acceptance boundary requires the exporter to fail explicitly on unsupported inputs, so these inputs were refused rather than mis-certified.

Z3 already handles the construct the way this change mirrors. Its arithmetic theory treats a Real ite as an opaque variable, and its equality core records the two gate clauses (not c) ∨ (ite c a b) = a and c ∨ (ite c a b) = b as Tseitin inferences. The certificate can follow the solver exactly, in line with the plan's principle of extending native evidence only where replay needs it.

What changed

Exporter (clause log to JSON certificate)

  • Fragment classification accepts a Real ite with linear Real branches and any supported condition. An ite under a nonlinear product or used as a divisor is still rejected.
  • Farkas pre-check treats a Real ite as an opaque variable keyed by identity, matching Z3's arithmetic solver.
  • Gate clauses: the exporter descends into arithmetic atoms and emits the two gate clauses of every Real ite as def-axiom nodes. When the log also records them as Tseitin inferences, they hash-cons to the same nodes.
  • Congruence claims inside an euf hint are shape-checked (a one-argument claim over an equality) and dropped, as Z3's own C++ checker builds the lemma from the Boolean arguments only. A malformed claim, or a claim in any other hint kind, is rejected.

Reconstructor (JSON certificate to Lean source)

  • Declaration validation: a Real ite must be declared as if over (Bool, Real, Real), and node arguments are sort-checked against that domain.
  • Term rendering: an ite becomes Lean's ite over Rat with the classical decidability instance, so term definitions containing one are noncomputable. The PR states this adds no axiom beyond the three the Rat slice already reports.
  • Gate lemma: a def-axiom clause tying an ite to one branch is proved by case analysis on a decidability witness for the condition, in either equality orientation, any literal order, and with weakening. A clause pointing at the wrong branch is rejected before Lean runs.
  • Gate helpers for grind (added after review): every grind lemma first states, for each reachable ite, its two branch equalities, scaled to integer coefficients when a branch has fractions. See the review section for why.

Tests and documentation

  • Certificate tests gain ite classification, nonlinear-ite rejections, a recorded ite clause-log replay, congruence-claim handling with malformed variants, and rejection of a claim inside a tseitin hint.
  • Arithmetic Lean tests gain seven ite inputs, including three where Z3's rewriter pushes a comparison through an ite with fractional branches, plus tampering tests, generated-text tests, a Lean integration test over all seven, and random instances with ite terms.
  • The Python examples README, the Lean README, and the plan document describe the new support and its limits.

Review

The reviewer's verdict was APPROVE, with no blocker or major findings. The reviewer re-ran the test suites and the QF_LRA matrix cell, grepped the diff for sorry, axioms, and trust widening (finding only test assertions and prose), and wrote probe scripts covering extra ite shapes and four certificate tamperings, all rejected in Python. The reviewer confirmed that the decidability witness used by the gate lemma is bound inside the main theorem, so the unsat statement is unchanged, and that Lean still runs at trust level zero with warnings as errors.

SeverityFindingResolution
minor A comparison applied directly to an ite with a fractional numeral branch, for example (>= (ite p x (/ 1.0 2.0)) 1.0) with (< x 1.0), exported a certificate that grind could not close. Z3's rewriter pushes the comparison through the ite, so no gate clause is logged, and grind did not combine the equality ite = 1/2 with its linear facts. The failure was fail-closed, so a completeness gap rather than a soundness issue, but the README promised the input class. fixed A minimal Lean case isolated the cause: t = 1/2, 1 <= t fails under grind while the scaled 2 * t = 1, 1 <= t succeeds, so the gap is the fractional constant, not the case split. Every grind lemma now states the scaled branch equalities of each reachable ite first. The three failing shapes became regression tests and verify in Lean.
nit The condition of an ite was rendered twice, once as the proposition and once inside the decidability instance, doubling inline text per nesting level. fixed The instance is now Classical.propDecidable _ and elaborates from the expected type.
nit Congruence claims were stripped from every literal-carrying hint kind, although Z3 only emits them in euf hints, so a tseitin hint carrying one was silently accepted. fixed Stripping is restricted to euf; a claim in any other hint is rejected, with a test.
nit The README described what the exporter accepts rather than what Lean verified, given the minor finding above. fixed By the fix to the minor finding; the README now also documents the gate helpers.

Risks and open questions

  • Generated Lean text changed for every QF_LRA proof. Arithmetic term definitions take an extra argument and grind lemmas reaching an ite carry gate helpers. The theorem statement is identical and Boolean certificates are unchanged.
  • Unused gate clauses cost checking time. The exporter adds ite gate clauses whether or not the proof uses them, and Lean checks every def-axiom. The PR calls this a small cost; no measurement on large inputs is reported.
  • Congruence claims are not re-validated in Python. Lean's grind must close each euf lemma by itself. It did on every instance tried, and a lemma it cannot close fails the run rather than being trusted.
  • Reliance on grind behaviour. The review finding traces back to how Lean 4.34's grind handles fractional constants, as did an earlier issue in this slice. Whether other shapes expose the same limit is unknown.
  • No corpus coverage in the matrix cell yet. The QF_LRA matrix cell in CI runs the eight pre-existing inputs, none containing an ite. Coverage lives in the in-repo unit tests for now.
