In one paragraph

The Lean file that certifies a refutation is now shorter, so Lean needs less memory to check it. Two kinds of text were dropped because Lean can work them out alone. First, a unit resolution step no longer states its type. Lean gets that type by type inference from the clause being cut down. Second, an application of a step or lemma to its hypotheses is no longer given its own let binding when only the next line uses it. It is written directly where it is used. The largest checked integer difference logic example shrank from 26.1 MB to 23.2 MB of Lean. Its peak memory fell from 7.86 GB to 7.45 GB, which leaves more room under the 8 GB cap. The theorem statement and every lemma statement are unchanged.

Background

Before this PR, the reconstructor already verified QF_IDL DTP_k2_n35_c245_s9, but only just. That success came in the previous iteration, at 7.86 GB of the 8 GB that the checking script allows. Most of its proof terms were resolution steps and short re-applications. Both repeated facts that Lean's elaboration already knows. Any growth in the input could have pushed it over the cap. This work serves milestone 3 of the plan, "Equality and linear arithmetic", by keeping large arithmetic refutations checkable.

What changed

  • A unit resolution that keeps a single literal is now bound with no stated type, and Lean infers it.
  • A re-application that the next term uses exactly once is now written inside that term instead of under its own name.
  • A new Lean-checked test confirms that every untyped step is a pure resolution chain and that the file got smaller.
  • The slow tests now fail early on size, at 23.5 MB for DTP and 21 MB for plan-21, before Lean can run out of memory.

An analogy: in a math homework, you no longer write "let A be the result of step 7 applied to h" and then use A once on the next line. You just write "step 7 applied to h" in that line.

All code changes are in one Python file, examples/python/proof_to_lean.py. No C++ changed.

Worked example

This PR shortens the Lean text but certifies no new small input, so the old pipeline accepted this example too. Both outputs below come from real runs of the old and new scripts.

(a) The input

A tiny disjunctive temporal problem in QF_IDL, in the style of the DTP inputs used by the new test.

(set-logic QF_IDL)
(declare-const x Int)
(declare-const y Int)
(declare-const z Int)
(assert (or (>= (- x y) 1) (>= (- y x) 1)))
(assert (or (not (>= (- x y) 1)) (>= (- y z) 1)))
(assert (or (not (>= (- y z) 1)) (>= (- z x) 0)))
(assert (or (not (>= (- y x) 1)) (>= (- x z) 0)))
(assert (or (not (>= (- x z) 0)) (>= (- z y) 1)))
(check-sat)

Each assertion is a clause of two difference constraints, and together they force a cycle of strict orderings, which is impossible.

(b) Before

There was no rejection. The pre-PR reconstructor printed Lean checked the refutation and wrote a 14,606-character file. Here is the part that this PR changes: 

  let _step_77 (_hyp58 : (formula_58 _atoms _vars)) : (formula_66 _atoms _vars) :=
    (_step_70.neg_resolve_left _hyp58)
  let _step_80 (_hyp58 : (formula_58 _atoms _vars)) : (formula_42 _atoms _vars) :=
    let _step_79 : (formula_30 _atoms _vars) :=
    let _step_78 : (formula_56 _atoms _vars) :=
    let _step_77 := _step_77 _hyp58
    ((_step_75.neg_resolve_left _step_77).neg_resolve_left _hyp58)
    ...
  let _step_83 (_hyp58 : (formula_58 _atoms _vars)) : (formula_82 _atoms _vars) :=
    let _step_77 := _step_77 _hyp58
    let _step_80 := _step_80 _hyp58
    (False.elim ((_step_73.neg_resolve_left _step_77) _step_80))

Every resolution step repeats its type after the colon, and each use of a step under a hypothesis gets its own one-line let.

The resolution steps have lost their stated types, and _step_77 _hyp58 now sits directly inside the term that uses it.

This step is not a plain resolution, so it keeps its type, but its two one-use lets are gone.

Review

The reviewer approved the change with no blocker, major, or minor findings.

  • Nit, fixed. The new paragraphs in the README and the plan were not wrapped like their neighbours. Both were reflowed, which matters only for readability.
  • Suggestion, fixed. The reviewer noticed that the re-application pattern accepted any name as an argument. In theory, one application could then name another step still waiting to be substituted, and the order of substitution would matter. The pattern now accepts only hypotheses and witnesses, and a unit test covers this. The Lean text of all four measured inputs stayed the same.
  • Suggestion, deferred. CI never runs the slow DTP test, so the reviewer proposed a cheap size-only check in the default tier. This is a follow-up. The default tier already bounds the size of DTP seed 1.

The reviewer also scanned eight inputs. Every step left untyped was a plain unit resolution, with no injection, case split, or proof by contradiction inside.

Risks and open questions

  • Soundness does not depend on this change. Lean's kernel still checks every term, so a wrong guess leads to a rejection, never a false acceptance.
  • Both new passes match on the text of generated terms. A future term kind that looks like a resolution chain would fail loudly in Lean.
  • DTP_k2_n35_c245_s9 still uses 7.45 of the 8 GB, and its test runs only in the slow tier.
  • The QF_AUFLIA input swap_t1_pp_sf_ai_00010_008 still runs out of memory, in its theory lemmas rather than its proof steps.

What comes next

  • Add a cheap size-only check for a large DTP or plan-21 input to the default test tier.
  • Profile the theory lemmas of swap_t1_pp_sf_ai_00010_008.
  • Look at the 3,579 typed step headers that remain in DTP and at the hypothesis chains in lemma statements.

Glossary

application
Giving a function or lemma its arguments. f a b is f applied to a and b.
clause
A disjunction of literals: "this or that or the other". Example: x - y >= 1 ∨ y - x >= 1.
elaboration
Lean's step that turns the text you wrote into fully explicit terms, filling in omitted types and arguments.
hypothesis
A fact assumed for the rest of a proof, written as a named argument such as _hyp58.
integer difference logic
The SMT-LIB logic QF_IDL. Every constraint compares a difference of two integer variables with a constant, as in x - y >= 1.
kernel
The small, trusted core of Lean that re-checks every finished proof term.
lemma
A proved helper statement that a larger proof uses.
let binding
Giving a value a local name: let a := 3, then using a later.
literal
An atomic formula or its negation, such as p or not p.
proof by contradiction
Proving a statement by assuming it is false and deriving False.
proof term
A program-like expression whose type is the statement it proves.
refutation
A proof that a set of assertions implies False.
resolution
The rule that combines a clause containing p with a fact about not p to drop p from the clause.
theorem
The final proved statement. Here it says that the input's assertions imply False.
type
In Lean, the statement a proof proves. A proof of A has type A.
type inference
Lean working out a type that was not written, from how the term is built.
unit resolution
Resolution that removes all but one literal of a clause, leaving that literal proved. Example: from a ∨ b and not a, conclude b.
