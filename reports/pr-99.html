State Lean ite gates over folded definitions to fit the 8 GB cap

Pull request levnach/z3#99 · OPEN · 2026-11-08T11:36:53Z · loop iteration 99

This pull request is open and not merged. Its change commit is 36fb9d4.

In one paragraph

Three large QF_UFLIA benchmarks, hard16, hard17 and hard20, now pass the Lean check under its 8 GB memory limit. Their theory lemmas mention deeply nested if-then-else terms. Each lemma used to restate its ite gates with every term written out, and that text grew with each nesting level. Lean keeps an info tree for every command, so the kernel ran out of memory. Now each gate is a short have over named definitions. The proof reverts the gates, unfolds them with the goal, and introduces them again. Lean still proves every gate, so the certificate gains no axiom or other trusted step, and these refutations are now certified.

Background

Before this PR, the pipeline already handled integer linear arithmetic with uninterpreted functions and if-then-else terms. A rescan of the QF_UFLIA sample files up to 160 KB found only 21 of 25 verified under the memory cap. Earlier reports of the three hard files as verified came from checks without the cap. This PR serves milestone 3 of the plan, "Equality and linear arithmetic".

What changed

  • Lean can now check QF_UFLIA files with long chains of nested ite terms without running out of memory.
  • Each integer ite gate is one short line that names definitions, like a recipe saying "see step 3" instead of copying it.
  • One unfold rewrites goal and gates together, so the omega and grind tactics see the same facts as before.
  • Scaled gates over the Real sort, and certificates with arrays, keep the old written-out form.
  • A new generator builds hard16-shaped inputs, and three new tests check the gate shape, the step order, and the Lean result.

Worked example

This is a real run on the depth-2 chain from the PR's new fast test. Two ways of adding 10 modulo 17 are claimed to differ, and each step is an ite.

(a) The input

(set-logic QF_LIA)
(declare-const x Int)
(define-fun a1 () Int (let ((s (+ x 5))) (ite (< s 17) s (- s 17))))
(define-fun a2 () Int (let ((s (+ a1 5))) (ite (< s 17) s (- s 17))))
(define-fun b1 () Int (let ((s (+ x 10))) (ite (< s 17) s (- s 17))))
(assert (and (<= 0 x) (< x 17)))
(assert (not (= a2 b1)))
(check-sat)

The value a2 adds 5 twice and b1 adds 10 once, so they are always equal, and the input is unsat.

Repeated walks. Nested ites share subterms, so one walk per gate revisits the same nodes. The fix walks from all gates at once, and the generated Lean stayed byte-identical.

Docstring. A comment wrongly suggested both gate forms applied to the same inputs. It now says when the old form is used.

Risks and open questions

  • unfold rejects a name that does not occur. The new names all occur in the reverted gates, but an untested shape could still fail.
  • Arrays and scaled Real gates still pay the old text cost.
  • No Lean CI matrix input contains an ite, so only unit tests cover this path in CI.
  • The QF_AX and QF_AUFLIA rescans were not finished.

Glossary

array
An SMT theory of maps from indices to values, with read and write operations.
axiom and sorry
Ways to make Lean accept a statement without proof. A sound certificate uses neither.
certificate
The proof Z3 exports for an unsat answer, which an independent checker replays.
clause
A disjunction of literals, such as p or not q or x < 3.
congruence
The rule that equal arguments give equal function results. Congruence closure applies it everywhere.
definition (folded)
A named Lean def, such as term_14. "Folded" means a term is written by its name, not by its body.
gate (ite gate)
A branch equality of an ite term. Example: if c holds, then ite c a b = a.
grind
A Lean tactic that combines case splits, congruence closure, and arithmetic reasoning.
have
A Lean step that proves a fact and adds it as a hypothesis for the rest of the proof.
hypothesis
A fact assumed in the current proof goal.
if-then-else term (ite)
A term that picks one of two values by a condition. Example: (ite (< s 17) s (- s 17)).
info tree
Data Lean records about each command for editors and error messages. The command-line checker keeps it until the file ends.
integer linear arithmetic
Arithmetic over Int with sums and constant multiples only, such as x + 5 < 17.
kernel
The small core of Lean that checks every proof term.
literal
An atom or its negation, such as x < 3 or not p.
logic (QF_UFLIA)
An SMT-LIB fragment name. QF_UFLIA means quantifier-free, with uninterpreted functions and integer linear arithmetic.
omega
A Lean tactic that decides integer linear arithmetic goals.
refutation
A proof that a set of assertions implies False.
revert and intro
Revert moves a hypothesis back into the goal as a premise. Intro does the reverse.
sort
The type of a value in SMT-LIB, such as Int, Real, or Bool.
tactic
A Lean command that builds part of a proof automatically.
theory lemma
A clause that holds by a theory such as arithmetic, which the solver adds during search.
unfold
A Lean tactic that replaces a definition's name by its body.
uninterpreted function
A function symbol with no fixed meaning, constrained only by congruence.
