In one paragraph

Until now the native-certificate pipeline certified only propositional and linear real arithmetic (QF_LRA) refutations in Lean; any input with an uninterpreted sort was rejected. This PR extends the exporter, the clause-log replay, and the Lean reconstructor so that quantifier-free problems over one uninterpreted sort with constants, functions, and predicates (QF_UF) are certified end to end. In Lean the sort becomes a universally quantified type and the symbols become indexed families, so one theorem signature covers every arity, and grind's congruence closure discharges the equality lemmas under kernel checking. It needs no new proof evidence from Z3, and the trust boundary is unchanged: a false equality lemma that passes every Python check is still rejected by Lean.

Background

The repository's Lean proof plan aims at unsat results from Z3 that an independent Lean checker accepts without trusting the solver. Z3 produces evidence, either a legacy proof object or, for theory problems, the sat.smt clause log. A Python exporter turns it into a JSON certificate marked "unverified". A reconstructor translates the certificate into Lean source, binding the theorem's hypotheses structurally to a reparse of the original input. Lean's kernel then checks the file, and only on success is the artifact published.

Z3 proof object or clause log  →  JSON certificate (unverified)  →  Lean source  →  Lean kernel check

The PR serves milestone 3 of the plan, "Equality and linear arithmetic", which asks for uninterpreted functions and equality reasoning alongside linear arithmetic, one fragment at a time. Iteration 1 landed the QF_LRA slice through the clause log and taught the exporter the shape of euf hints with cc congruence claims. QF_UF came next because the clause log already handles it: equality conflicts arrive as euf hints, distinct as alldiff clauses, and the Boolean structure as tseitin and rup steps. Only a sound Lean encoding of an uninterpreted sort was missing.

What changed

Exporter

The exporter accepts declare-sort with arity 0 and classifies inputs over one uninterpreted sort with constants, functions, and predicates as the new fragment qf_uf, keeping the input's own sort name. It rejects a second sort, mixing the sort with arithmetic (QF_UFLRA), functions with Boolean or Real arguments or results, ite over the sort, and sorts named Bool, Real, or Proof.

Clause-log replay

A log application headed by an input function is rebuilt from the input's own declaration, with arity and argument sorts checked. The log's sort and function declarations must match the input's. Quoted sort names such as |my sort| are accepted after a review fix.

Lean reconstructor

Certificates may use one non-reserved sort name, validated together with the qf_uf fragment. Input binding keeps separate symbol tables for atoms, variables, elements, functions, and predicates, binds each symbol by signature, and checks the sort name and symbol sets against the parsed input. Generated definitions take an interpretation of the sort instead of a rational valuation: 

theorem unsat (_atoms : Nat -> Prop) (_U : Type) (_elems : Nat -> _U)
    (_funs : Nat -> List _U -> _U) (_preds : Nat -> List _U -> Prop)
    (_h0 : formula_k _atoms _U _elems _funs _preds) ... : False

A constant becomes _elems i, an application f(a, b) becomes _funs j [a, b], a predicate application becomes _preds k [a, b], and equality and distinct are Lean's = on _U. The theorem quantifies over every type and every indexed family, so each model of the input is one instance; the encoding over-approximates the models and is therefore sound for unsatisfiability. Equality lemmas over the sort go through the existing grind lemma path.

Tests and documentation

The exporter tests gain QF_UF classification cases, a recorded clause-log replay with nine malformed-log rejections, and a legacy-exporter rejection. A new reconstructor test file covers generated text, malformed declarations, symbol binding by signature, quoted sort names, a Lean integration test over four inputs with #print axioms, three pinned random instances, and a tampering test in which a false euf lemma passes every Python check and is rejected by Lean alone. The exporter README, the Lean README, and the proof plan document the scope, the encoding, and the trust boundary.

Review

The reviewer approved the change with no blockers and no majors. They confirmed that the theorem's hypotheses remain bound to the parsed input, that no sorry, axiom, or widened trust appears, and that a tampered satisfiable input passes Python and is rejected by Lean. Two minors and two nits were raised; all four were fixed before the PR opened.

Minor

  • Equality over proof terms crashed. Declarations of = or distinct with argument sort Proof were accepted and then failed with an internal KeyError. Fixed by excluding Proof from the comparable sorts, with two new tests.
  • Quoted sort names were rejected. The clause-log definition check compared the raw token, so |my sort| failed with a misleading message. Fixed by normalising the token, with a replay variant and an end-to-end test.

Nit

  • Overloaded names undocumented. Overloading a function name by arity is rejected, but the README did not say so. Fixed by documenting it after verifying every overload shape fails closed.
  • Random-instance seeds found at run time. A solver change could silently pick different test inputs. Fixed by pinning seeds 405, 693, and 896 and asserting the unsat-core size.

Deferred: an explicit maxHeartbeats budget on the main theorem, since it affects every certificate.

Risks and open questions

  • Over-approximated model class. Indexed families over argument lists admit interpretations no SMT-LIB model has. This only strengthens the theorem, so it is sound for unsatisfiability; the README states it.
  • Equality lemmas are checked by Lean alone. euf hints carry nothing Python could pre-check, so a wrong lemma is detected only at the kernel. The tampering test shows the rejection; no file is published on failure.
  • Deep equality diamonds hit a heartbeat limit. An 8-level diamond with 3,827 nodes and 365 euf lemmas exports but fails in Lean's main theorem at the default limit. This pre-existing limit of long refutations fails closed and is in the backlog.
  • Internal interface changes. The input-binding helper returns a different shape; the only external caller found ignores the result.
  • Coverage lives in-repo only. The z3test corpus has no QF_UF inputs yet, so the CI proof matrix does not exercise QF_UF.

What comes next

  • Add a uf_*.smt2 set to the z3test Lean regressions with a clause-log matrix step, so the CI matrix covers QF_UF.
  • Give the main theorem an explicit heartbeat budget and reduce export time on long rup replays.
  • Still rejected: QF_UFLRA, several uninterpreted sorts, functions with Boolean or Real arguments or results, ite over the sort, and overloaded symbol names.
