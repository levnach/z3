Prove each normalized rewrite atom in its own Lean lemma

Pull request #46 on levnach/z3 · MERGED · loop iteration 46

Merged 2026-10-30T04:13:16Z as commit 3b7a24739 into master.

In one paragraph

A rewrite step in the legacy proof object can bring many arithmetic atoms into canonical form at once. Before this PR, every one of these normalizations was proved inside one Lean theorem. Each call of the tactic grind saw all earlier atoms and shared one heartbeat budget. Now each normalization is a separate lemma with its own budget. The certificate for a refutation of a conjunction of 1,100 bounds used to time out in Lean, and now it passes. The proofs themselves are unchanged, so the trust boundary stays the same.

Background

PR #45 made the pipeline handle inputs nested 1,100 levels deep. Lean then checked the clause log certificates of deep Boolean and QF_LRA conjunctions. But the legacy rewrite of the 1,100-bound conjunction was only reconstructed, never checked. Lean ran out of heartbeats a little over 200 atoms into it. The cause was the width of the rewrite, not the nesting. This serves milestone 3 of the plan, equality and linear arithmetic, which asks each fragment to work end to end.

What changed

Think of one exam with 1,100 questions and a single clock, where each sheet repeats all earlier answers. Now each question is a short quiz with its own clock.

  • Lean reconstruction: Lean can now check a legacy rewrite over 1,100 atoms, because each normalization has its own lemma, named like normalized_atom_N_A.
  • Lean reconstruction: Each lemma gets a 1,000,000-heartbeat ceiling, so no atom has less room than before.
  • Lean reconstruction: The rewrite theorem now just cites the lemmas, and its final Boolean step is unchanged.
  • Tests: The deep test now runs Lean on the 1,100-bound legacy certificate, so a regression fails the test.
  • Documentation: The plan records the change.

Worked example

The change only matters for very wide rewrites. The PR reports that 200 bounds already passed before, so a ten-line input cannot show it. This is the PR's own test input, shown trimmed. All outputs come from a real run for this report.

(a) The input

(set-logic QF_LRA)
(declare-const x Real)
(declare-const y Real)
(declare-const x0 Real)
...
(declare-const x1099 Real)
(assert (and (< x0 5.0) (and (< x1 5.0) ... (and (< x1099 5.0) (and (< x y) (< y x))) ...)))
(check-sat)

The full file declares 1,102 constants of sort Real. The innermost pair says both x < y and y < x, which is impossible.

The certificate was exported with --core legacy, as in the PR's test. By default the exporter picks the clause log here, which never builds this rewrite.

(b) Before: Lean rejects the old output

We took the reconstructor from the base commit, 4f0b0a39d. Its command line cannot run from a copy, so we called its reconstruction function and checked the output with Lean. Lean gave up after about 64 seconds:

old/example.lean:14149:2: error: (deterministic) timeout at `«tactic execution»`, maximum number of heartbeats (1000000) has been reached

Line 14147 sits deep inside the single rewrite theorem:

  let _atom221 : Prop := ((((-1 : Rat)) * _vars 221) + ((5 : Rat)) <= ((0 : Rat)))
  have _norm444 : (formula_444 _atoms _vars) <-> (Not _atom221) := by

This normalizes the bound on x221, after 221 earlier atoms had used up the shared budget.

Review

The reviewer approved the PR.

SeverityCountResolution
Blocker, major, minor0none needed
Nit2both fixed
Suggestion2one adopted, one deferred

Heartbeat ceiling, adopted. The first version gave each new lemma Lean's default budget of 200,000 heartbeats. Before, one hard atom could use most of the shared 1,000,000. So an atom that passed before could fail after the change. The fix gives each lemma a 1,000,000 ceiling, which costs nothing when unused. All checks were then re-run.

Old code fails, new code passes. The reviewer ran the base reconstructor and saw the same timeout. In the new output, the only differences were the 1,102 new lemmas and the lines that cite them. Neither file contains a sorry or an axiom. This shows the change moves proofs without weakening any of them.

Two nits, fixed. A rewrapped docstring was reflowed. An older note in the plan now says the legacy rewrite is checked by Lean.

One lemma per atom, deferred. Several wide rewrites over the same atoms each repeat their lemmas. Naming lemmas by atom alone would avoid that, but it is outside this PR's scope.

Risks and open questions

  • Each lemma repeats its atom's canonical form, so large certificates grow. See the sizes in the example table.
  • The deep test adds about 16 seconds of Lean to the CI job.
  • The rewrite theorem still ends with one simplification over all atoms. It will be the next cost as width grows.
  • GitHub CI results for this change are unknown here.

What comes next

  • Name lemmas by atom, to stop repetition across wide rewrites.
  • Still open from PR #45: and-elimination over a flat 1,200-operand conjunction, the tta_startup inputs, and slow FISCHER export.

Glossary

atom
A formula with no Boolean connective inside it, such as x0 < 5.
axiom
A statement Lean accepts without proof. This PR adds none.
Boolean
About the values true and false and the connectives and, or, and not.
bound
An atom that limits one variable by a constant, such as x0 < 5.
canonical form
One fixed way to write equivalent formulas, so equal things look equal. Here x0 < 5 becomes not (-1*x0 + 5 <= 0).
certificate
A file that records the solver's proof so an independent checker can replay it.
clause
An "or" of atoms and negated atoms, such as (or a (not b)).
clause log
A proof source that records the clauses the solver learns, step by step, with hints.
conjunction
A formula of the form "A and B". A nested conjunction is "A and (B and (C and ...))".
definitional equality
Two Lean expressions are definitionally equal when unfolding definitions makes them identical. Lean checks this without a separate proof.
heartbeat
Lean's unit of work. A proof that uses more heartbeats than its limit stops with a timeout error.
legacy proof object
The older proof source: one proof term built by the solver's core, made of steps like rewrite and and-elimination.
lemma
A small theorem proved on its own and then used inside a larger proof.
normalization
Rewriting a formula into its canonical form, together with a proof that both mean the same thing.
QF_LRA
The SMT-LIB logic of quantifier-free linear real arithmetic: sums of real variables times constants, compared with <, <=, or =.
refutation
A proof that a set of assertions leads to False, so no assignment satisfies them.
rewrite step
A proof step that states a formula is equivalent to a simpler or normalized formula.
sort
The type of a value in SMT-LIB, such as Int, Real, or Bool.
sorry
A Lean placeholder that skips a proof. Accepted files must contain none.
tactic
A Lean command that builds part of a proof automatically. grind is a tactic that combines case splits, equality reasoning, and arithmetic.
theorem
A named statement in Lean together with a proof that Lean checks.
trust boundary
The set of things one must believe without checking, such as Lean's kernel and the translation of the input.
