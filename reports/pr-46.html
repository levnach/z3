Prove each normalized rewrite atom in its own Lean lemma

Pull request levnach/z3 #46 · State: OPEN · Date: 2026-10-30T03:56:46Z · Loop iteration 46

This pull request is open and not merged. The change under review is commit 7884a34. It has two commits on top of base 4f0b0a3.

In one paragraph

The Lean reconstructor turns one kind of rewrite step, the normalized rewrite, into Lean proofs. Before this PR, the normalization of every atom was proved inside a single theorem. All those proofs shared one heartbeat budget. Each proof also saw every earlier atom in its context. A conjunction of 1,100 bounds ran out of budget, so Lean rejected its certificate. Now each atom gets a private lemma with its own budget. The rewrite theorem only applies these lemmas. The same QF_LRA refutation is now accepted by Lean in about 17 seconds. The tactic proofs are unchanged, so the trust boundary is unchanged.

Background

PR #45 made the pipeline handle inputs nested over a thousand levels deep. The clause log certificates of such inputs were checked by Lean. The legacy core certificate of a 1,100-bound nested conjunction was only reconstructed, because Lean timed out on it. The cause was the width of the normalized rewrite, not the nesting. It serves milestone 3 of the plan, "Equality and linear arithmetic", which asks that each fragment work end to end.

What changed

  • A wide normalized rewrite, over hundreds or thousands of atoms, can now be checked by Lean instead of timing out.
  • Each atom's normalization is now a separate lemma, normalized_atom_N_A, with the full heartbeat limit the whole rewrite used to share.
  • The deep test suite now runs Lean on the 1,100-bound legacy certificate, instead of only building it.
  • The plan document has a dated note on the change, and the older "Deep nesting" note points to it.

An analogy: before, 1,100 students sat one exam in one room with one shared clock, hearing every earlier answer. Around student 220 the clock ran out. Now each student has a separate room and clock.

Worked example

The old code already handled small rewrites, so a tiny input shows no difference. The example is the PR's own test input, deep_bounds_conjunction(1100), trimmed here. All output comes from real runs made for this report.

(a) The input

(set-logic QF_LRA)
(declare-const x Real)
(declare-const y Real)
(declare-const x0 Real)

It asserts 1,100 bounds of the form xi < 5, nested in conjunctions, plus the contradictory pair x < y and y < x.

(b) Before: the base commit's scripts

The base exporter, with --core legacy, and the base reconstructor both finished. Lean then rejected the result:

example.lean:14147:4: error: (deterministic) timeout at `isDefEq`, maximum number of heartbeats (1000000) has been reached

Line 14147 is inside the one big rewrite theorem, at the 222nd atom:

  let _atom221 : Prop := ((((-1 : Rat)) * _vars 221) + ((5 : Rat)) <= ((0 : Rat)))
  have _norm444 : (formula_444 _atoms _vars) <-> (Not _atom221) := by

Every earlier _atom and _norm sits in this grind call's context, and all of them draw on one budget.

The base reconstructor's command line expects to sit inside the repository, so this report called its reconstruct function directly and ran Lean on the output.

Review

The reviewer approved, with no blocker, major, or minor findings. They ran Lean on the old reconstructor's 1,100-bound output and saw the same timeout, so the new test really guards the fix. A diff of old and new output showed only the new lemmas and the have lines that use them. Neither file contains sorry or axioms.

  • Suggestion, heartbeat ceiling (adopted). The first version gave each lemma Lean's default limit, which is lower than the old shared one. So one hard atom could have newly failed, though none in the suites did. The second commit gives each lemma the old 1,000,000-heartbeat limit, so no atom gets a smaller ceiling.
  • Suggestion, repeated lemmas (deferred). Several wide rewrites over the same atoms each repeat their lemmas. Sharing them is left for later.
  • Nit, docstring. A rewrapped docstring left a short broken line. It was reflowed.
  • Nit, plan note. The older "Deep nesting" note still said the legacy rewrite was only reconstructed. It now adds that Lean checks it since the per-atom lemmas.

Risks and open questions

  • Each lemma repeats its atom's canonical form, so certificates grow. The PR reports about 8% for the example. This report measured about 9%.
  • The deep test adds about 16 seconds of Lean to the CI Lean step.
  • The rewrite theorem still holds one let per atom and one simpa only over all of them. That will be the next cost as width grows.
  • CI results are unknown to this report.

What comes next

  • Key the atom lemmas by atom, so several wide rewrites can share them.
  • Still open from PR #45: legacy and-elim over a flat 1,200-operand conjunction, the tta_startup inputs that do not verify yet, and FISCHER's slow equivalence checks of assume.

Glossary

atom
A formula with no Boolean connective inside it, such as x0 < 5.
bound
An atom that compares one variable with a constant, such as x0 < 5.
canonical form
One fixed way of writing equivalent formulas, so that equal things look equal. Here: a sum of coefficient-times-variable terms plus a constant, compared with 0.
certificate
A file that records a proof so another program can check it step by step.
clause log
A proof record that lists the clauses the solver learned, in order, with hints. It is one of the two exporter cores.
conjunction
A formula of the form "A and B". A nested conjunction is "A and (B and (C and ...))".
definitional equality
Two Lean terms are definitionally equal when unfolding definitions makes them identical. Lean accepts this without a separate proof.
heartbeat
Lean's unit of work. Each declaration has a heartbeat limit, and Lean stops with a timeout error when it is used up.
legacy core
The exporter path that reads Z3's older proof object, as opposed to the clause log.
lemma
A small proved statement used as a step in a larger proof.
linear arithmetic
Arithmetic with only addition and multiplication by constants, such as 2x + 3y <= 5.
normalization
Rewriting a formula into its canonical form, together with a proof that both are equivalent.
normalized rewrite
A rewrite step proved in two parts: first each atom is normalized, then the Boolean structure over the normalized atoms is proved.
QF_LRA
The SMT-LIB logic of quantifier-free linear arithmetic over the reals.
refutation
A proof that a set of assertions leads to False.
rewrite step
A proof step that replaces a formula with an equivalent one and records that they are equivalent.
tactic
A Lean command that builds part of a proof automatically. grind and simpa are tactics.
theorem
A named, proved statement in Lean. A lemma is a theorem used as a helper.
trust boundary
The set of things one must trust for a checked result to be correct. Here it is Lean and the translation of the input into Lean, not Z3.
