Define conjunctions of more than 256 operands in chunks in Lean

Date: 2026-11-16T17:11:50Z  ·  Loop iteration 138

This pull request is open and not merged. Its change commit is b5ad06d2a.

In one paragraph

This PR changes how the reconstructor writes a very wide conjunction in Lean. A conjunction with more than 256 operands is now a chain of 32-operand chunks. Each chunk is a named definition, and each has one small projection theorem. The same holds for a distinct over 24 or more arguments, which stands for a conjunction of pairs. Proofs of theory lemmas now reach an operand through those theorems. This matters because one QF_UF benchmark produced a certificate that Lean could not finish checking. Its Lean text shrank from 40.1 MB to 8.5 MB, and it now verifies. No axiom, trust setting, or resource limit changed, so the Lean kernel checks every step as before.

Background

The pipeline already accepted wide conjunctions and wide distinct constraints, but only up to a size. Each one was written out in full inside a single definition. A refutation of it from one false operand then took one proof step per earlier operand. Lean's checking time grew much faster than the width, and the largest cases ran out of heartbeats. The change serves milestone 3 of the plan, equality and uninterpreted functions. It follows the plan's top priority, the regression methodology, by fixing a supported benchmark that failed only on resources.

What changed

Reconstructor

  • You can now certify inputs with conjunctions of thousands of operands, because each is defined as chunks that unfold to exactly the old text.
  • A proof now reaches any operand in at most 31 projection steps from a chunk's theorem, where it used to walk the whole conjunction.
  • Lemmas that fall back to unfolding definitions still work, because every unfold list now names the chunks as well.

Tests and documentation

  • Twelve new tests pin the chunk layout, the order of a distinct's pairs, and the sizes that failed before.
  • Three older tests now follow an upstream change to Z3's arithmetic rewriter, so the suite passes again with no check weakened.

The old definition was a scroll: to read its last line, Lean unrolled everything before it. The new one is a book with chapters. A proof opens the right chapter by name and reads at most a page.

Review

The reviewer approved the change. There was no blocker and no major finding.

  • Minor, not fixed. The reviewer tried a reversed distinct over 100 constants. Its lemma falls back to unfolding, and Lean now makes one pass per chunk name. The case fails with both versions, but in 36.8 s instead of 31.9 s. A lemma that passes only through that fallback would get slower, though none was found. The fix touches about a dozen places, so it went to the backlog.
  • Minor, fixed. The reviewer looked for behaviour that no committed test would catch. Three cases had none: two alike conjunctions sharing one name, the pair order in a chunked distinct, and a Boolean distinct. The code was right, but a later edit could have broken it unnoticed. Three tests were added, and each fails under the mutation it targets.
  • Nit, fixed. Some new tests assumed that Z3 logs exactly one lemma. An upstream change would have crashed them with an unrelated error. They now name the cause.
  • Nit, fixed. The chunk information reached the prover as a hidden attribute on a dictionary. A caller passing a plain dictionary would silently get the old slow path. It is now an explicit argument.
  • Nit, fixed. One test generator sat after its first use. It moved up to the others.

Risks and open questions

  • A lemma that verifies only by unfolding several thousand operands gets slower. No such input is known.
  • Sokoban peaks at 5.1 to 5.5 GB, under the 8 GB cap. Its costly module does not mention the distinct and was not traced.
  • A true distinct over 190 constants in one lemma still fails, in the grind tactic as before.
  • Three code paths for distinct still step through the written-out conjunction. They were not measured at this width.
  • Why Lean is slow on a written-out conjunction was measured, not profiled.
  • Sample texts above 30 MB were not exported again. Whether they hold a wide conjunction is unknown.
  • The three adjusted test expectations move again if upstream changes its rewriter again.

What comes next

  • Unfold all chunk names in one step, which was measured to be linear in the width.
  • Trace sokoban's remaining cost, one module that takes 177.6 of its 213 seconds.
  • Measure the remaining distinct code paths, then move them onto the chunk theorems.

Glossary

and-elimination
The proof rule that concludes one operand from a true conjunction. From "A and B" it gives "B".
assertion
A formula the input states as true, written (assert ...) in SMT-LIB.
axiom
A statement accepted without proof. A certificate should add none of its own.
benchmark
A fixed input file used to test and measure solvers, here from the SMT-LIB collection.
Boolean
The sort with the two values true and false.
certificate
A recorded proof that an independent checker can replay without trusting the solver.
clause
A disjunction of literals, such as (or (not a) b).
conjunction
A formula that is true when all its parts are true, written and in SMT-LIB.
constant
A named value of some sort whose meaning is not fixed, declared with declare-const.
distinct
The SMT-LIB constraint that all its arguments differ pairwise. Over n arguments it stands for n(n-1)/2 disequalities.
heartbeat
Lean's unit of work for a deterministic time limit. A proof that needs more than its budget is rejected.
if-then-else term
A term that equals one of two values depending on a condition, written ite in SMT-LIB.
interpretation
A choice of meaning for every sort, constant and function symbol of the input.
kernel
The small trusted core of Lean that checks every finished proof.
literal
An atomic formula or its negation, such as (= a b) or (not (= a b)).
module
One Lean source file. A large certificate is split into several, checked one after another.
mutation testing
Breaking the code on purpose in one small way to confirm that a test notices.
operand
One of the parts an operator joins. The operands of a conjunction are also called conjuncts.
projection
Taking one side of a proved conjunction. In Lean, h.1 is the left side and h.2 the right.
QF_UF
The SMT-LIB logic of quantifier-free formulas over equality and uninterpreted functions.
refutation
A proof that a formula, or a set of assertions, is false.
rewriter
The solver component that simplifies terms into an equivalent standard form before solving.
sorry
Lean's placeholder for a missing proof. A certificate must contain none.
sort
The type of a value, such as Int, Bool, or a declared sort like U.
tactic
A Lean command that builds part of a proof automatically. grind is a general-purpose one.
theory lemma
A clause that is true by the rules of a theory alone, such as equality, whatever the input says.
unfolding
Replacing a defined name by the body of its definition.
uninterpreted function
A function symbol with no fixed meaning. Only congruence holds: equal arguments give equal results.
