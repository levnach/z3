Merged into master on 2026-10-22T12:49:05Z as commit f19da1010. The two commits of the branch were squashed into this one merge commit.

In one paragraph

Z3's rewriter writes the absolute value (abs x) as the if-then-else term (ite (<= 0 x) x (* -1 x)). The rewrite step that links an assertion to its normal form therefore mentions every absolute value twice, as two different atoms. Before this PR, the Lean lemma for such a rewrite let the tactic split each if-then-else term into two cases. With twelve absolute values that is thousands of cases, and Lean gave up at its heartbeat limit. Now the reconstructor first proves a bridging equality for every two atoms that are equal up to the rewriter's normalization, then generalizes the atoms and decides the remaining linear arithmetic goal. Sums of a dozen absolute values, common in QF_LIA inputs, are now certified in about a second. Soundness is untouched, because each bridge is an equality that Lean must prove.

Background

Before this PR the pipeline certified Boolean refutations, congruence over uninterpreted functions, and linear arithmetic over the sorts Int and Real, including Farkas lemmas and cuts. The previous PR (#29) made the Int theory lemmas treat their div, mod, and abs atoms as opaque, but the rewrite steps of the same inputs were still proved with every definition unfolded. So an assertion over many if-then-else atoms could still exhaust Lean's heartbeats. This PR closes that gap and serves milestone 3 of the plan, equality and linear arithmetic end to end.

What changed

The central idea is a key: a short description of an atom that ignores the rewriter's cosmetic choices. Two atoms with one key denote the same value, like two spellings of one word that share a dictionary entry.

  • Rewrite steps get a two-attempt proof. A theory rewrite over if-then-else, abs, div, mod, or function-application atoms is first proved by bridging same-key atoms, generalizing, and running omega over Int or grind over Real. Only if that fails does the old unfolded proof run.
  • Absolute values are keyed as their defining if-then-else term, so an input's (abs x) and the rewriter's form of it are bridged instead of split.
  • If-then-else conditions are keyed canonically: positive leading coefficient, primitive and rounded over Int, and the complement with swapped branches when needed. The strict form (ite (> x 0) x (- x)) and the scaled form (abs (* 2 x)) now bridge too. This was added after the review.
  • The same key serves arguments of uninterpreted functions, so in QF_UFLIA an Int if-then-else term under a function symbol gets the helper equality the Real case already had.
  • A forged rewrite is still rejected. A new test plants a false rewrite that passes every shape check and confirms Lean refuses the file.

Review

The reviewer approved the change with no blocking or major findings. Two minor findings and one nit were fixed in a second commit.

  • Minor 1, strict conditions never bridged over Int. The reviewer wrote the twelve-wide input with (ite (> x 0) x (- x)) instead of abs and watched it time out like the original bug. Over Int the reconstructor tightens a strict inequality before the key sees it, so the strict case was never flipped. A canonical condition key that takes the complement with a branch swap fixed it. The strict spelling is as common as the non-strict one, so this mattered.
  • Minor 2, factored absolute values not bridged. The reviewer tried (abs (* 2 x)) and found the two atoms keyed apart, again with a timeout. The rewriter divides the condition 0 <= 2x to 0 <= x and keeps the branches scaled. Making the Int condition key primitive and rounded, as the rewriter does, fixed it.
  • Nit 3, the plan note understated finding 1. The note now records the canonical key and the one shape that remains unbridged.
  • Suggestion, chain versus star bridging. Atoms sharing a key are bridged in a chain rather than all to the first atom. Not changed: long groups only arise in the legacy proof core over Int, where omega copes.

The reviewer also confirmed in Lean that a false bridge makes the first attempt fail and the fallback run, while a false conclusion is still rejected.

Risks and open questions

  • Every theory rewrite over these atom kinds now runs a first attempt before the old proof. A rewrite that needs an atom's definition fails that attempt quickly. All existing suites are unchanged in outcome.
  • The keys do not affect soundness. A wrong key can only produce an equality Lean refuses.
  • The abs key assumes one normal form for (abs t). Any other form would not be bridged and would fall back.
  • Over Int, (ite (<= x 0) (- x) x) and abs x have different keys, although their values agree. A rewrite relating them would fall back.
  • The merge rested on the local gate, which ran on macOS. The Linux GitHub CI result on master is not recorded in this report.

What comes next

  • Add the mod bound facts to the unfolded fallback, so omega could replace grind there.
  • Extend the two-attempt proof to implied-eq and euf lemmas, which still use the unfolded proof.
  • Key function applications up to the rewriter's normalization, so (f (- x y)) and (f (+ x (* -1 y))) bridge as atoms of a rewrite.

Glossary

absolute value
The distance of a number from zero, written (abs x) in SMT-LIB. SMT-LIB defines it as the if-then-else term (ite (>= x 0) x (- x)).
atom
A smallest building block that a proof step treats as a unit, such as a variable, an if-then-else term, or a comparison. Linear reasoning sees atoms as opaque names.
Boolean
A value that is either true or false, and the sort of such values.
clause
A disjunction of literals, for example (or (not p) q).
complement
The negation of a condition. Over Int the complement of x <= 0 is x >= 1, and swapping the branches of an if-then-else term compensates for using it.
congruence
The rule that equal arguments give equal results: if a = b then f(a) = f(b).
cut
An integer reasoning step that rounds a bound, for example from 2x <= 3 to x <= 1.
Farkas lemma
A certificate that some linear inequalities contradict each other: a weighted sum of them yields a false statement such as 0 <= -1.
generalize
A proof move that replaces a complex term by a fresh variable, so the rest of the proof cannot look inside it. The generalize tactic does this in Lean.
if-then-else term
A term that picks one of two values by a condition, written (ite c a b) in SMT-LIB.
legacy proof core
Z3's older proof-object output, one of the two proof formats the pipeline certifies. The other is the clause log.
lemma
A small theorem proved on its own and then used in a larger proof. The reconstructor emits one Lean lemma per proof step.
linear arithmetic
Reasoning about sums of variables with constant coefficients, such as 2x - y <= 3, without products of variables.
literal
An atom or its negation, such as p or (not p).
normal form
The standard shape the rewriter gives a term so that equal terms look the same, for example writing x > 0 as (not (x <= 0)).
primitive
A linear form whose coefficients have no common factor. Dividing 0 <= 2x by two gives the primitive 0 <= x.
QF_LIA
The SMT-LIB logic of quantifier-free linear integer arithmetic.
QF_UFLIA
QF_LIA extended with uninterpreted functions.
refutation
A proof that a set of assertions implies False.
rewrite
A proof step that replaces a formula or term by an equivalent one, recorded by the rewriter.
rewriter
Z3's simplifier, which normalizes every term before solving, for example turning (abs x) into an if-then-else term.
sort
The type of a value, such as Int, Real, or Bool.
soundness
The property that nothing false can be proved. Here it rests on Lean checking every step, never on the exporter's bookkeeping.
strict inequality
An inequality that excludes equality, such as x > 0. Over Int it is the same as x >= 1, which is called tightening.
tactic
A Lean command that searches for a proof automatically. omega decides linear integer goals and grind is a general-purpose prover.
theory lemma
A clause that a theory solver, here linear arithmetic, reports as valid, such as a Farkas combination.
uninterpreted function
A function symbol with no fixed meaning. Only congruence is known about it: equal inputs give equal outputs.
