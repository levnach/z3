In one paragraph

Z3 has an extra integer operator, rem, that is not part of standard SMT-LIB. Before this PR, the certificate exporter rejected every input that used it. Now rem by a nonzero numeral is accepted on both proof cores. The exporter treats each rem term as an opaque atom of linear arithmetic, just like div and mod. The solver's two axioms that link rem to mod go through the existing arith check. The Lean theorem states rem as t % k when k is positive and as -(t % k) when k is negative. The Lean kernel then proves every theory lemma, so no new trust is added.

Background

The previous iteration probed hand-written inputs and listed rem among the constructs still rejected. The pipeline already certified div, mod, and abs in QF_LIA and QF_UFLIA refutations. Any rem stopped the exporter with "unsupported arithmetic operator: rem". Other gaps from that probe remain, such as to_int and to_real over Int terms, ^, and enumeration datatypes. This PR serves Milestone 3 of the plan, "Equality and linear arithmetic", which asks that each fragment be complete end to end.

What changed

  • The exporter now accepts rem by a nonzero numeral and still rejects a zero divisor or a divisor that is a term.
  • The clause-log replay now rebuilds rem terms and checks the two rem axioms with the same shape check it uses for div and mod.
  • The Lean reconstructor can now state a rem term, choosing t % k or -(t % k) from the sign of the numeral k.
  • The reconstructor now checks every stated div, mod, or rem node for a nonzero numeral divisor through one shared list, _DIVISION_KINDS.
  • New tests feed rem problems through both cores into Lean, and try tampered certificates that must be rejected.

Think of rem as mod wearing a sign badge. For a positive divisor the badge says "+", so rem equals mod. For a negative divisor it says "−", so rem is the negated mod. The reconstructor reads the badge from the numeral and writes the matching Lean term.

Worked example

This input is the PR's new test lia_rem. The dividend is a sum, so Z3's rewriter keeps the rem terms instead of turning them into mod. Both rem terms must be positive, and the mod must be 1. With divisor −3, rem is minus the mod, so it equals −1. That contradicts the first assertion.

(a) Input

(set-logic QF_LIA)
(declare-const x Int)
(declare-const y Int)
(assert (> (rem (+ x y) (- 3)) 0))
(assert (> (rem (+ x y) 3) 0))
(assert (= (mod (+ x y) 3) 1))
(check-sat)

Review

The reviewer approved the PR with no blocker, major, or minor findings. They checked the encoding against Z3's own definition in its rewriter, and it matched.

  • Nit, fixed. The reviewer read the README and found a sentence that still named only div and mod. A reader could wrongly think a stated (rem t 0) was allowed. The sentence now covers rem too. It also says a rem by zero is rejected everywhere, because its encoding needs the divisor's sign.
  • Suggestion, deferred. A helper adds known bounds for mod atoms, such as "between 0 and |k| − 1", but not for rem. A cut over rem atoms might one day need them. This affects only how many inputs succeed, not soundness, and no fuzz seed needed it. It is in the backlog.
  • Suggestion, pre-existing. One probe used a divisor written as (+ 1 2). The Python parser accepted it, but the z3 executable dropped that assertion as nonlinear. The clause-log core then said "sat: no unsat proof exists". mod behaves the same way, so the PR did not cause it. It is a rejection, not a wrong proof, and it is left for a follow-up.

Risks and open questions

  • The theorem statement now contains an operator outside SMT-LIB. Its meaning is Z3's definition. A consumer that wants strict SMT-LIB can still reject rem declarations.
  • A rem and a mod with the same positive divisor print as the same Lean term but stay separate atoms in Python. This is harmless, because Lean proves each lemma on its own.
  • Nobody has checked yet whether Z3's native C++ arith checker validates the two rem axioms.
  • At larger sizes the fuzzer produces easy instances with no cuts, so hard rem problems are less tested.

What comes next

  • Add rem bounds next to the mod bounds, if a cut ever needs them.
  • Write a harder rem stress generator.
  • Reject constant-expression divisors such as (+ 1 2) up front, with a clear message.
  • Close the other gaps from the probe: to_int, is_int, and to_real over Int terms, ^, and enumeration datatypes.

Glossary

atom (opaque atom)
A term that linear reasoning treats as a single unknown, without looking inside. Example: (rem (+ x y) 3) is handled like a fresh variable.
axiom
A fact a solver adds because it holds by definition. Here, Z3 adds two axioms per rem term that tie it to mod.
clause
A disjunction of literals, read as "at least one of these is true". Example: (or (>= k 0) (= r m)).
cut
An integer reasoning step that rounds a bound to the nearest integer. Example: from 2x ≤ 3 it derives x ≤ 1.
div and mod
Integer division and remainder in SMT-LIB. For a nonzero k, (mod t k) is always between 0 and |k| − 1. Lean's / and % on Int agree with them.
fuzzing
Testing with many randomly generated inputs, each fixed by a seed number so it can be repeated.
if-then-else term (ite)
A term that picks one of two values based on a Boolean condition. Example: (ite (>= k 0) a b).
kernel
The small, trusted core of Lean that checks every proof step.
linear arithmetic
Arithmetic where variables are only added together or multiplied by constants. Example: 2x + 3y ≤ 5.
literal
An atomic formula or its negation. Example: x ≥ 0 or not (x ≥ 0).
numeral
A constant number written directly in the input, such as 3 or (- 3).
proof core
One of the two sources of Z3 proof evidence this project reads: the legacy proof object or the newer clause log.
QF_LIA and QF_UFLIA
SMT-LIB logics. QF_LIA is quantifier-free linear integer arithmetic. QF_UFLIA adds uninterpreted functions.
refutation
A proof that a set of assertions leads to a contradiction, that is, to False.
rem
Z3's remainder operator, an extension to SMT-LIB. It is defined as (ite (>= k 0) (mod t k) (- (mod t k))). Example: (rem 7 -3) is −1.
tactic
A Lean command that builds a proof automatically. omega solves linear integer goals, and grind is a more general search.
theory lemma
A clause that is true by the rules of a theory, such as arithmetic, and that the solver adds during its search.
uninterpreted function
A function symbol with no fixed meaning, only the rule that equal inputs give equal outputs.
