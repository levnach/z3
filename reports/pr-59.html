In one paragraph

Z3 has an extra integer operator, rem, that is not part of standard SMT-LIB. Z3 defines it with an if-then-else term over mod. Until now, any input that used it was rejected on both proof cores. This PR accepts rem when its divisor is a nonzero numeral. The exporter treats each rem term as an opaque atom of a linear arithmetic constraint, the same way it already treats div and mod. The solver adds two axioms per rem term, each a two-literal clause. They link rem to mod, and Lean now proves both of them. In the Lean theorem, rem appears at its numeral divisor k: as t % k when k is positive, and as -(t % k) when it is negative. The result is that a new family of QF_LIA and QF_UFLIA refutations can be checked by the Lean kernel. No new trusted axioms were added.

Background

Before this PR, the pipeline already certified integer div and mod by a nonzero numeral, and abs. It rejected rem with the message "unsupported arithmetic operator: rem". An earlier probe of hand-written inputs, in iteration 58, listed rem among the remaining rejections. Z3's rewriter usually turns (rem t k) into mod or its negation, so the proof never sees rem. When t is a sum or a product, though, the rewriter keeps the rem atom, and the solver needs arith hints for it. This work serves milestone 3 of the project plan, "Equality and linear arithmetic", which asks for each fragment to be complete end to end.

What changed

  • The exporter now accepts rem by a nonzero numeral and still rejects a zero divisor or a divisor that is a term.
  • The clause-log replay can rebuild a rem term, and it checks the shape of the two rem axioms like any other arith hint.
  • The Lean reconstructor declares rem only in certificates over the Int sort and writes it as t % k or -(t % k), depending on the sign of k.
  • A rem by zero or by a term is rejected wherever it appears, because its Lean form depends on the divisor's sign.
  • New tests cover both signs, five kinds of tampered certificate, and three pinned random instances that need cuts and an implied equality.
  • The README and the project plan describe the new operator, its axioms, and its Lean encoding.

The change is Python only. No C++ changed, so the Z3 build is the same as before. The PR has two commits: the feature itself, and a README wording fix from review.

Worked example

The input below is lia_rem, the new documented test input from the PR. It was run through the exporter, the reconstructor, and the Lean check for this report. The default proof source for an integer problem is the clause log.

(a) The input

(set-logic QF_LIA)
(declare-const x Int)
(declare-const y Int)
(assert (> (rem (+ x y) (- 3)) 0))
(assert (> (rem (+ x y) 3) 0))
(assert (= (mod (+ x y) 3) 1))
(check-sat)

The first assertion alone is impossible. With a negative divisor, rem is the negation of mod, and mod is never negative. The dividend is a sum, so Z3 keeps the rem atoms instead of rewriting them away.

Risks and open questions

  • The theorem now contains an operator that is not standard SMT-LIB. Its meaning is Z3's definition, so a consumer that wants strict SMT-LIB may reject rem.
  • A rem and a mod with the same positive divisor become the same Lean term but remain separate atoms in Python. In the example, term_8 and term_10 show this. It is harmless, since Lean proves each lemma on its own.
  • Not yet examined: whether Z3's native C++ arith checker accepts the two rem axioms.
  • When producing this report, the exporter's --help text still listed only "div and mod by a numeral and abs" as the integer extras. This is a small documentation gap that the review did not mention.

What comes next

  • Add rem bounds next to the mod bounds, if a cut ever needs them.
  • Write a harder rem stress generator. At larger sizes, the current one gives easy instances with no cuts.
  • Reject a divisor written as a constant expression up front, with a clear message.
  • Other constructs from the iteration-58 probe are still rejected: Int-to-Real conversions, ^, and enumeration datatypes.

Glossary

arith hint
A label in Z3's proof log for a clause that the arithmetic solver adds on its own, such as the definition of div, mod, or rem. The pipeline checks its shape and Lean proves it.
atom
A term that a reasoning step treats as a single unknown. An "opaque" atom is never looked inside, like a sealed box. Example: (rem (+ x y) 3) treated as one variable.
axiom
A statement accepted as a starting point. Here the solver's axioms are not trusted: each one is proved in Lean.
clause
A disjunction ("or") of literals. Example: (or (>= k 0) (= r m)).
cut
A new inequality that holds for all integer solutions but removes some fractional ones. Integer solvers use cuts to close gaps that pure linear reasoning leaves open.
divisor
The number you divide by. In (rem t k), the divisor is k and the dividend is t.
if-then-else term (ite)
A term that picks one of two values based on a Boolean condition. Example: (ite (>= k 0) a b). Z3 defines rem with one.
implied equality
An equality between two terms that the arithmetic solver derives from the current constraints and passes to other reasoning.
kernel
The small core of Lean that checks every proof. Only what the kernel accepts counts as proved.
lemma
A small proved statement used as a step toward a larger theorem.
linear arithmetic
Arithmetic where variables are only added together and multiplied by constants. Example: 2x + 3y <= 5, but not x * y.
literal
An atomic formula or its negation. Example: (>= k 0) or (not (>= k 0)).
mod (Euclidean remainder)
The remainder of integer division, which is never negative. Example: (mod -7 3) is 2. Lean's % on Int is the same.
numeral
A constant number written directly, such as 3 or (- 3), as opposed to a variable or a term.
QF_LIA and QF_UFLIA
SMT-LIB logics. QF_LIA is quantifier-free linear integer arithmetic. QF_UFLIA adds uninterpreted functions.
refutation
A proof that a set of assertions leads to False, so they cannot all be true.
rem
A Z3 extension for an integer remainder. It equals mod when the divisor is positive and minus mod when it is negative. Example: (rem 7 -3) is −1.
rewriter
The part of Z3 that simplifies terms before solving. Example: it turns (rem x 3) into (mod x 3).
sort
The type of a value, such as Int, Real, or Bool.
tactic
A command that builds a Lean proof automatically. omega solves linear integer goals, including / and % by numerals. grind is a more general fallback.
theorem
The main statement a Lean file proves. Here it says the input's assertions imply False.
uninterpreted function
A function symbol with no fixed meaning, only a name and a type. Example: (declare-fun f (Int) Int).
