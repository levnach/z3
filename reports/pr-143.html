Make Inputs a structure over chunks so lemmas stop unfolding it

In one paragraph

In a large certificate, the refutation is split into many outlined lemmas. Every lemma receives all the assertions as one hypothesis, named Inputs. Until now Inputs was a definition of the conjunction of every assertion. Lean's elaboration unfolded it whenever one lemma named another, and at every projection of an assertion. This PR makes Inputs a structure, which Lean does not unfold, over chunks of 32 assertions. A benchmark with 15,332 assertions had no verdict after 40 minutes and now verifies in about nine minutes. The certified theorem is stated exactly as before.

Background

Before this PR the pipeline already exported this benchmark and wrote its Lean text. Only the Lean check failed, and only on resources. The cost grew as the number of references between lemmas times the number of assertions. The work serves the plan's regression methodology, which the plan names its current top priority. The file is in the logic QF_IDL, whose arithmetic belongs to milestone 3, equality and linear arithmetic.

What changed

Think of a sealed envelope: lemmas hand it on unopened, and whoever needs one page opens one small folder.

Exporter

  • Lemmas now pass the assertions to one another without Lean copying them, because Inputs is a structure with one field.
  • A lemma that needs one assertion opens one chunk of 32, not the whole conjunction.
  • The theorem keeps its statement, and only its last line now builds the structure.

Tests

  • Four new tests pin the chunk layout, the cost under a heartbeat limit at two sizes, and Lean's rejection of wrong projections.

Documentation

  • The plan and the README describe the new hypothesis and record the measurements.

Worked example

This PR changes cost, not coverage, so no ten-line input was rejected before. The input below is a five-assertion instance of the PR's test generator, with outlining forced as the PR's tests do. Without forcing, both exporters write identical Lean for it. Everything quoted comes from runs made for this report.

(a) The input

(declare-const p0 Bool)
(declare-const p1 Bool)
(declare-const p2 Bool)
(declare-const p3 Bool)
(assert p0)
(assert p1)
(assert (or (not p0) (not p1) p2))
(assert (or (not p1) (not p2) p3))

(check-sat)

Five assertions over four Boolean constants: three unit clauses and two longer clauses.

(c) After

def formula_0 (_atoms : Nat -> Prop) : Prop := _atoms 0
def formula_1 (_atoms : Nat -> Prop) : Prop := _atoms 1
...
def formula_5 (_atoms : Nat -> Prop) : Prop := (Or (formula_2 _atoms) (Or (formula_3 _atoms) (formula_4 _atoms)))
...
def formula_9 (_atoms : Nat -> Prop) : Prop := (Not (formula_7 _atoms))
...
def formula_23 (_atoms : Nat -> Prop) : Prop := False

Each formula of the input gets a name, and _atoms gives a truth value to every atom.

private structure Inputs (_atoms : Nat -> Prop) : Prop where
  all : (And (And (And (formula_0 _atoms) (formula_1 _atoms)) (formula_5 _atoms)) (And (formula_8 _atoms) (formula_9 _atoms)))

The new feature: the five assertions sit in the single field of a structure, which Lean passes around without unfolding.

private theorem proof_step_14 {_atoms : Nat -> Prop}
    (_inputs : Inputs _atoms)
    : (formula_1 _atoms) :=
  _inputs.all.1.1.2

private theorem proof_step_24 {_atoms : Nat -> Prop}
    (_inputs : Inputs _atoms)
    : (formula_23 _atoms) :=
  let _step_14 := proof_step_14 _inputs
  let _step_10 : (formula_8 _atoms) :=
    _inputs.all.2.1
  ...
  let _step_20 :=
    ((_step_18.neg_resolve_left _step_19).neg_resolve_left _step_14)
  ...
  (False.elim (_step_22 _step_21))

The first lemma projects the assertion p1 out of the field, and the second names the first and reaches False by resolution.

theorem unsat (_atoms : Nat -> Prop)
    (_h0 : (formula_0 _atoms))
    (_h1 : (formula_1 _atoms))
    (_h2 : (formula_5 _atoms))
    (_h3 : (formula_8 _atoms))
    (_h4 : (formula_9 _atoms))
    : False :=
  @proof_step_24 _atoms (Inputs.mk (And.intro (And.intro (And.intro _h0 _h1) _h2) (And.intro _h3 _h4)))

The statement is unchanged, and only the last line now wraps the hypotheses with Inputs.mk.

Review

Verdict: approve. The reviewer found no blocker and no major problem.

  • Minor, fixed. One new test feeds Lean three deliberately wrong texts, called mutants. It passed whenever Lean reported any error, so a text broken for an unrelated reason would have passed too. That mattered because the test guards a safety property: a wrong projection must be a type mismatch. The test now checks the unchanged text first and requires every error to be a type mismatch.
  • Nit, not changed. The heartbeat limits in two tests depend on how Lean counts work. A new Lean version could fail them with nothing wrong in the exporter. The reviewer asked for no change, so it is listed under Risks.
  • Nit, fixed. Two tests hard-coded the chunk size 32, and now read the exporter's constant.
  • Nit, fixed. The exporter split the assertions into chunks in three separate places. The reviewer planted five slips in that code, and the unit test caught each. One function now does the split, and all 152 sample texts stayed byte-identical.

Risks and open questions

  • Eight of the largest changed texts were not checked in Lean after the change. Nine of the same families verify.
  • A Lean toolchain change could fail the heartbeat limits.
  • The chunk names and Inputs.mk are new names in a certificate, with no clash found.
  • A projection still copies the chunk names, a 32nd of the assertions.
  • One QF_LRA sample file fails in a theory lemma with both exporters. It verified on 2026-11-13, and the cause is unknown.
  • The large benchmark is not in the repository, so a generated family stands in for it.
  • The test suite became about 160 s slower since the previous PR, with either exporter, for an unknown reason.

What comes next

  • Investigate the QF_LRA file that stopped verifying.
  • Check the eight remaining large texts in Lean.
  • Look at the cost of the theorem's own hypotheses, 13.8 s on the large benchmark.
  • Survey other large definitions used as the type of a hypothesis, which Lean unfolds the same way.

Glossary

assertion
A formula the input states to be true, written (assert ...) in SMT-LIB.
atom
A formula with no smaller formula inside it, such as the Boolean constant p0.
axiom
A statement accepted without proof. A certificate that depends on no axioms proves everything it uses.
Boolean
The sort with the two values true and false.
certificate
A file of evidence that an independent checker can verify. Here it is the Lean text of the refutation.
clause
A disjunction of literals, such as (or (not p0) (not p1) p2).
conjunction
The "and" of several formulas. It is true when every operand is true.
definition
A name that stands for an expression. Unfolding a definition replaces the name by that expression.
elaboration
The step in which Lean turns the text a user writes into a fully typed proof term.
heartbeat
Lean's unit of work for its deterministic time limit. A proof that needs more than the limit is rejected.
hypothesis
An assumption that a lemma or theorem takes as given.
lemma
A small proved statement that other proofs can use by name.
literal
An atom or its negation, such as p0 or (not p0).
logic
A named class of SMT-LIB formulas. QF means quantifier-free. IDL is integer difference logic, UF is uninterpreted functions, AX is arrays, LRA is linear real arithmetic, and AUFLIA combines arrays, uninterpreted functions, and linear integer arithmetic.
mutant
A deliberately damaged copy of a correct text. A good checker must reject it.
outlined lemma
A proof step moved out of the main theorem into a lemma of its own, so Lean checks it separately.
projection
Taking one part out of a pair or structure. From a proof of "A and B", .1 gives a proof of A.
refutation
A proof that a set of assertions leads to False.
resolution
The rule that combines two clauses on a literal and its negation. From (or a b) and (not a) it gives b.
sort
The type of a value, such as Int, Real, or Bool.
structure
A Lean type that bundles named fields. Unlike a definition, it is not replaced by its contents during type checking.
theorem
A statement together with a proof that the checker accepts.
theory lemma
A clause that holds because of a theory such as arithmetic, not by Boolean reasoning alone.
type mismatch
Lean's error when a proof proves a different statement than the one required.
uninterpreted function
A function symbol with no fixed meaning. Only equal arguments are known to give equal results.
unit clause
A clause with exactly one literal, such as p0.
