Certify enumeration datatypes through the clause log in Lean

Pull request levnach/z3#67 · State: OPEN · Opened 2026-11-03T21:43:52Z · Loop iteration 67

This pull request is open and not merged. The change described here is commit e14720e.

In one paragraph

Z3 inputs that declare an enumeration datatype can now be certified in Lean. Other kinds of datatype are still rejected. The pipeline treats the enumeration as one more uninterpreted sort, plus two facts read from the input. The constructors are pairwise different, and every value of the sort equals one of them. The hints that Z3's datatype solver writes into the clause log become theory lemmas. Lean proves each of them with a tactic, so none is trusted. The PR also fixes a Z3 crash on a distinct with more arguments than the sort has values. That case is a pigeonhole refutation. No new axiom was added, and no Lean library file changed.

Background

Before this PR, the pipeline certified uninterpreted functions, Int and Real arithmetic, and their mixtures. Every declare-datatype or declare-datatypes command was rejected outright, even for the simplest enumeration. Probing also found three defects: a Z3 crash, colliding constructor names in the clause-log replay, and literals written in a different order in hints than in clauses. The work serves milestone 3 of the plan, "Equality and linear arithmetic", by widening its uninterpreted-function fragments.

What changed

  • You can now give the exporter an input with an enumeration, and it lands in an uninterpreted-function fragment such as qf_uf or qf_uflia.
  • You can now use recognizers in both SMT-LIB spellings, (_ is red) and the older is-red.
  • You can now get a Lean file whose interpretation states that the constructors differ and that each enumeration value is one of them.
  • You can now run Z3 with the clause log on a too-wide distinct without a crash. Z3 adds the pairwise clauses and refutes them by case splits.
  • You now get a clear rejection for datatypes with fields, for parametric datatypes, for accessors, and for a too-wide distinct over an enumeration of more than seven constructors.

Think of an enumeration as a traffic light with exactly three colors, none equal to another. Lean learns those two facts from the input's declaration, never from Z3's output.

Worked example

This input is the documented test none_of_the_constructors from the new test module. The variable a is asked to be none of the three colors, which is impossible.

(a) The input

(declare-datatypes ((Color 0)) (((red) (green) (blue))))
(declare-const a Color)
(assert (not (= a red)))
(assert (not (= a green)))
(assert (not (= a blue)))
(check-sat)

(b) Before

The exporter from the base commit stopped at the first line of the input:

proof_certificate.py: error: unsupported SMT-LIB command: declare-datatypes

(c) After

The current exporter and reconstructor produced a 61-line Lean file. Lean accepted it: check_lean.sh printed "Lean checks passed."

-- Enumeration "Color" is part of _m.U with constructors "red", "green", "blue", _m.ctors 0 to 2 (enum_distinct, enum_cases_*, enum_fcases_*).
...
structure Interpretation where
  U : Type
  elems : Nat -> U
  ...
  ctors : Nat -> U
  enum_distinct : (And (Not (ctors 0 = ctors 1)) (And (Not (ctors 0 = ctors 2)) (Not (ctors 1 = ctors 2))))
  enum_cases_0 : (Or (elems 0 = ctors 0) (Or (elems 0 = ctors 1) (elems 0 = ctors 2)))

The interpretation now carries the three constructors, the fact that they differ, and the fact that a is one of them.

def term_0 (_atoms : Nat -> Prop) (_m : Interpretation) : _m.U := _m.elems 0
def term_1 (_atoms : Nat -> Prop) (_m : Interpretation) : _m.U := _m.ctors 0
...
def formula_13 (_atoms : Nat -> Prop) (_m : Interpretation) : Prop := (Or (formula_8 _atoms _m) (Or (formula_2 _atoms _m) (formula_5 _atoms _m)))

Here a becomes element 0 and red becomes constructor 0. The clause formula_13 says that a is blue, red, or green.

private theorem th_lemma_14 (_atoms : Nat -> Prop) (_m : Interpretation)
    : (formula_13 _atoms _m) := by
  unfold formula_13 formula_8 term_7 formula_5 term_4 formula_2 term_1 term_0
  have _ed := _m.enum_distinct
  have _ec0 := _m.enum_cases_0
  grind (splits := 64)

This is Z3's datatype case split, proved in Lean by the grind tactic from the two enumeration facts.

The theorem takes the three assertions as hypotheses and reaches False by resolution against the case split.

Review

The reviewer approved, with no blocker and no major finding. Five smaller findings were all addressed in a follow-up commit.

The runaway pigeonhole. The crash fix replaced Z3's counting shortcut with pairwise clauses. The reviewer timed this with growing enumerations. At eleven constructors, Z3 wrote a 596 MB log in 60 seconds and still had no answer. Without proofs, the same input is instant. It mattered because a user could fill a disk before the time limit stopped Z3. The exporter now rejects a too-wide distinct over more than seven constructors, before Z3 runs.

The hidden type parameter. The reviewer tried the SMT-LIB 2.5 form (declare-datatypes (T) ...). It passed the first checks and failed much later with a confusing message about a malformed declaration. That contradicted the docs, which promise a rejection. The exporter now rejects it at the start.

The nits. Accessors now get the clear "only enumeration datatypes" message, and two cosmetic issues were tidied.

Risks and open questions

  • Only 19 of the 322 sweep puzzles use a datatype hint at all. Most of the datatype reasoning is exercised by the eleven hand-written inputs.
  • The cap only catches a direct distinct. A pigeonhole built from separate disequalities can still make Z3 search for a long time. The exporter's time limit bounds it.
  • Python checks a datatype hint only through the shape of its clause. A wrong hint is caught by Lean, not earlier.
  • CI results for this PR are not known to this report.

What comes next

  • Log a counting lemma, so Z3 can keep its shortcut for a too-wide distinct under proofs.
  • Support enumerations on the older proof-object path.
  • Support datatypes with fields, such as records, lists and recursive datatypes.
  • Write a random generator that exercises more datatype reasoning.

Glossary

accessor
A function that reads one field of a datatype value. For a pair, fst returns its first part.
axiom
A statement accepted without proof. Adding one would widen what the Lean check trusts.
case split
Reasoning by cases: if a value must be red, green or blue, check each possibility in turn.
clause
A disjunction of literals, true when at least one literal is true. Example: a = red ∨ a = green.
clause log
A file in which Z3 records every clause it adds or learns while solving, each with a hint about why.
constructor
A function that builds a datatype value. In an enumeration, each constructor takes no arguments and is itself a value, like red.
datatype
A sort whose values are built only by its declared constructors, declared in SMT-LIB with declare-datatype.
distinct
The SMT-LIB operator that says all its arguments differ. (distinct a b c) means a≠b, a≠c and b≠c.
enumeration datatype
A datatype whose constructors all have no arguments, so it has a fixed finite list of values. Example: Color with red, green, blue.
fragment
A restricted part of logic that a tool handles, such as qf_uf: quantifier-free formulas with uninterpreted functions.
hint
The justification Z3 attaches to a logged clause, naming the reasoning step that produced it, such as datatype or euf.
literal
An atomic formula or its negation, such as a = red or ¬(a = red).
parametric datatype
A datatype with a sort parameter, like a list of T for any sort T.
pigeonhole principle
If more items than boxes are placed in boxes, two items share a box. Four distinct Colors cannot exist when there are three.
recognizer
A predicate that tests which constructor built a value. ((_ is red) a) is true exactly when a is red.
refutation
A proof that a set of assertions leads to a contradiction, so they cannot all hold.
resolution
The rule that combines a clause containing a literal with the negation of that literal and keeps the rest. From p ∨ q and ¬p, conclude q.
sort
The type of a value in SMT-LIB, such as Int, Real, Bool, or a declared sort like Color.
tactic
A Lean command that builds part of a proof automatically. grind is a tactic that combines case splits and equality reasoning.
theory lemma
A clause justified by one theory, such as datatypes or arithmetic, rather than by pure Boolean reasoning. Here, each one is proved in Lean.
uninterpreted function
A function symbol with no fixed meaning. Only equal arguments are known to give equal results.
uninterpreted sort
A sort with no fixed set of values, declared with declare-sort. Only equality between its values is known.
