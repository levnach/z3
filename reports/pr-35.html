Prove cnf bridges by propagation over opaque theory atoms in Lean

Pull request #35 on levnach/z3 · MERGED · 2026-10-24T03:50:58Z · loop iteration 35

Merged into master on 2026-10-24T03:50:58Z as commit f273d72. The PR carried two commits on top of its base d197a5e: the change and the review fixes.

In one paragraph

Z3's clause log sometimes records a clause it had already simplified. The exporter ties it back to the original assertion with a theory lemma of kind cnf. Before this PR, the reconstructor proved that lemma by unfolding the whole assertion and handing it to an arithmetic tactic. The tactic split on every if-then-else term and disjunction, and on one real QF_UFLIA input it never finished. The lemma is now proved first as a refutation by propagation over the Boolean shape of the clause, with every theory atom kept as an opaque leaf. Two leaves that denote one linear constraint, or complementary ones, or one equality with its sides swapped, are joined by an equivalence the theory tactic proves. The old proof stays as a fallback. Lean still checks every piece, and the cost now grows with the clause, not the whole assertion.

Background

The pipeline already certified QF_UFLIA inputs that mix uninterpreted functions with integer arithmetic, including Farkas, cut, and congruence lemmas. It could not finish the cnf bridges of a large assertion. The corpus scan of iteration 32 left the Wisa family of z3test's SMT-LIB sample unverified, and every theory lemma that timed out there was such a bridge. Z3's clausification only normalizes each atom, for instance by swapping the sides of an equality, so these clauses follow from their sources by propositional reasoning once the atoms are bridged. The work serves milestone 3 of the plan, equality and linear arithmetic.

What changed

Only the Python reconstructor, its tests, and the documentation changed. No C++ or Lean library code was touched.

  • Lemma proof. A cnf lemma is now first proved by contradiction through a chain of small propagation steps, with every theory atom left folded. It is like checking a wiring diagram without opening any of the boxes.
  • Bridges. Two atoms that are really one constraint, such as (= (cnt 0) 1) and (= 1 (cnt 0)), or one equality over an uninterpreted sort with its sides swapped, get a small equivalence proved by the theory tactic.
  • Fallback. The previous unfolded proof remains as the second alternative, and stands alone when propagation finds no refutation.
  • Tests. A short new input reproduces the Wisa shape, and tests force the fallback by replacing the propagation term with one Lean rejects. Through Z3's legacy proof core the same input produced the first live smt steps, which the existing path already proves.
  • Documentation. The README and a dated note in the plan describe the new proof and its fallback.

Worked example

The input is a ten-line cut of the PR's new test input. The counter cnt 0 is 1 for one pair of format values and 0 otherwise, yet the last conjunct demands at least 2.

(a) The input

(set-logic QF_UFLIA)
(declare-fun fmt (Int) Int)
(declare-fun cnt (Int) Int)
(declare-fun percent () Int)
(declare-fun s () Int)
(assert (and (= percent 37) (= s 115)
             (or (= (fmt 0) percent) (= (fmt 0) s))
             (or (= (fmt 1) percent) (= (fmt 1) s))
             (ite (and (= (fmt 0) percent) (= (fmt 1) s)) (= (cnt 0) 1) (= (cnt 0) 0))
             (>= (cnt 0) 2)))
(check-sat)

Z3's clause log assumes the gate clauses of the ite without the ite literal, so the exporter emits three cnf lemmas tying them to the assertion. The exporter did not change, and the old and new certificates are byte-identical.

(b) Before

The pre-PR scripts, extracted from the base commit, did not reject this small input, and Lean accepted their output. The difference is how each cnf lemma was proved. The pre-PR text unfolds every definition, including every theory atom, and hands the whole assertion to the arithmetic tactics: 

private theorem th_lemma_56 (_atoms : Nat -> Prop) (_vars : Nat -> Int) ...
    : (formula_55 _atoms _vars _U _elems _funs _preds _bool _int _ifuns) := by
  unfold formula_55 formula_54 formula_53 formula_46 formula_23 formula_22 term_21
         formula_20 formula_19 formula_18 term_17 formula_16 formula_15 formula_14
         formula_13 term_12 term_11 formula_10 formula_9 formula_8 term_7 term_6
         formula_5 term_4 term_3 formula_2 term_1 term_0
  first | omega | grind (splits := 64)

That is fast here because the assertion is small. On the Wisa file xs-05-12-1-4-2-1.smt2, one 3,600-character assertion with 30 such lemmas, the same shape did not finish. The pre-PR scripts' Lean text for that file was checked again today for this report. Lean rejected it after about seven and a half minutes, with exit status 1. Its first error line was: 

wisa_old.lean:1220:0: error: (deterministic) timeout at `whnf`, maximum number of heartbeats (1000000) has been reached

Line 1220 starts th_lemma_451, one of the cnf lemmas. The same timeout hit seventeen theory lemmas, and the kernel then reported nine of them as unknown constants where the main theorem used them. So the pre-PR pipeline could not certify this input.

(c) After

The declarations behind the first cnf lemma in the new output, with the binder list shortened to ...:

-- (= (cnt 0) 1) as written in the assertion
def formula_18 (_atoms : Nat -> Prop) ... : Prop :=
  ((term_17 ...) = (term_11 ...))
-- (= 1 (cnt 0)) as Z3 wrote it in the clause log
def formula_54 (_atoms : Nat -> Prop) ... : Prop :=
  ((term_11 ...) = (term_17 ...))
-- the cnf clause: not(assertion) or not(gate) or (= 1 (cnt 0))
def formula_55 (_atoms : Nat -> Prop) ... : Prop :=
  (Or (formula_53 ...) (Or (formula_46 ...) (formula_54 ...)))

Two definitions name the same equality with its sides swapped, and the third is the clause to prove.

theorem unsat (_atoms : Nat -> Prop) (_vars : Nat -> Int) (_U : Type) ...
    (_h0 : (formula_23 _atoms _vars _U _elems _funs _preds _bool _int _ifuns))
    : False :=

The main theorem says the single assertion, named formula_23, leads to a contradiction.

private theorem th_lemma_56 (_atoms : Nat -> Prop) (_vars : Nat -> Int) ...
    : (formula_55 _atoms _vars _U _elems _funs _preds _bool _int _ifuns) := by
  unfold formula_55 formula_53 formula_46 formula_23 formula_20 formula_16 formula_15 formula_10
  first
    | (have _f1 : (Iff (formula_18 ...) (formula_54 ...)) := by
         unfold formula_54 formula_18 term_17 term_11 term_6; first | omega | grind (splits := 64)
       exact (Classical.byContradiction (fun (_f2 : (Not (Or (Not (And (formula_2 ...) ...))
                                                             (Or (Not (And (formula_8 ...) (formula_14 ...)))
                                                                 (formula_54 ...))))) =>
         ((have _f3 : (Not (Not (And (formula_2 ...) ...))) := (fun _g => _f2 (Or.inl _g));
           have _f4 : (Not (Not (And (formula_8 ...) (formula_14 ...)))) := (fun _g => _f2 (Or.inr (Or.inl _g)));
           have _f5 : (Not (formula_54 ...)) := (fun _g => _f2 (Or.inr (Or.inr _g)));
           have _f6 : (Not (formula_18 ...)) := (fun _g => _f5 (Iff.mp _f1 _g));
           ...
           (False.elim (_f10 (Classical.byContradiction (fun _g => _f3 _g))))) : False))))
    | (unfold formula_54 formula_22 term_21 formula_19 formula_18 term_17 formula_14 ...
       first | omega | grind (splits := 64))

Only the connectives are unfolded. The bridge _f1 is the one place arithmetic is used, to show the two orientations of the equality agree. The named steps then assume the clause is false and reach False without opening any atom. The second alternative is the old unfolded proof.

Review

The reviewer approved with no blockers and no major findings. Three findings were fixed in the PR's second commit, and one suggestion was declined.

  • Minor, fixed. The reviewer built a QF_UF probe where a Boolean formula appears both in the clause and as the argument of a predicate. The fallback left the inner copy of the formula folded, so a clause that needed that inner structure could fail where it used to pass. The fix keeps every node under a leaf in the fallback's unfold list, and a new test Lean-checks both proofs on that probe.
  • Nit, fixed. With two complementary groups of two atoms each, the code stated five bridges where three suffice. Extra bridges are harmless but cost a tactic call each. A test now pins the count.
  • Nit, fixed. The dated note in the plan repeated the inaccurate bridge count and was corrected with the code.
  • Suggestion, not taken. A Python-side shape check for the newly live smt steps. The hint has no fixed shape and Lean already proves the implication, so such a check could reject valid certificates.

Risks and open questions

  • Axioms. The new proofs use proof by contradiction and the excluded middle. Theory certificates already depended on the standard Lean axioms through grind, so the reported axiom list is unchanged.
  • Text size. Every propagation step restates its proposition over the leaf names, so the Lean text for the Wisa file grew several times over. A per-lemma size cap falls back to the unfolded proof alone.
  • What is not bridged. Applications inside atoms are keyed by node, so (f (+ x 1)) and (f (+ 1 x)) are not recognized as one leaf. Such a lemma falls back to the unfolded proof.
  • CI after the merge. The merge rested on the local gate. The GitHub CI result on master was not available when this report was written.

Glossary

assertion
A formula the input declares to be true, written (assert ...) in SMT-LIB. The refutation shows the assertions cannot all hold.
Boolean
A value that is either true or false, and the connectives over such values: and, or, not, if-then-else.
clausification
Rewriting a formula into a set of clauses before solving. Also called conversion to conjunctive normal form, or CNF.
clause
A disjunction of literals, such as (or (not c) t). A clause holds when at least one literal holds.
clause log
Z3's record of the clauses it assumed and derived while solving, which the exporter turns into a certificate.
congruence
The rule that equal arguments give equal results: from x = y conclude f(x) = f(y).
cut
An integer reasoning step that strengthens a bound by rounding, since an integer below 2.5 is at most 2.
disjunction
An "or" of formulas, written (or a b). It holds when at least one of them holds.
equivalence
A statement that two propositions have the same truth value, written Iff in Lean.
excluded middle
The classical principle that every proposition is either true or false, written Classical.em in Lean.
Farkas lemma
A way to show linear inequalities contradict each other: add non-negative multiples of them to reach a false statement such as 0 < 0.
gate clause
A clause that defines one connective of the input, for example that an if-then-else term agrees with its "then" branch when its condition holds.
if-then-else term
A term that picks one of two values by a condition, written (ite c t e) in SMT-LIB.
linear constraint
An equality or inequality between sums of variables with constant coefficients, such as x + 2y <= 5.
literal
An atom or its negation, such as p or (not p).
predicate
An uninterpreted function whose result is Boolean, such as (P x).
proof by contradiction
Proving a statement by assuming it is false and deriving False, written Classical.byContradiction in Lean.
propagation
Deriving the truth value of a connective's parts from the connective, step by step, as when "a or b" is false so both a and b are false.
refutation
A proof that a set of formulas cannot all be true, ending in False.
sort
The type of a value, such as Int, Real, or Bool. An uninterpreted sort is one whose elements have no fixed meaning.
tactic
A Lean command that searches for a proof automatically, such as omega for integer arithmetic or grind for equalities and case splits.
theory atom
The smallest formula a theory decides, such as (= (cnt 0) 1) or (<= x y), with no Boolean connective at the top.
theory lemma
A clause that holds by the rules of a theory alone, for example integer arithmetic, recorded in the certificate with a hint such as farkas or cnf.
uninterpreted function
A function symbol with no definition, such as cnt here. Only congruence is known about it.
