In one paragraph

The QF_UF slice of Z3's Lean-checked certificate pipeline used to refuse any input containing an ite (if-then-else) term whose branches have the uninterpreted sort, although Z3 solves such inputs instantly and its clause log already records the two "gate" clauses tying the term to its branches. This PR makes the exporter classify such inputs as QF_UF, makes the clause-log replay add the gate clauses as def-axiom nodes, and makes the Lean reconstructor render the term as Lean's ite over the carrier type, with gates proved exactly as for Real-valued ite. Random stress inputs with nested ite terms also exposed two older replay gaps, fixed here. No trust is widened: every new acceptance path ends in a Lean-checked lemma, and tampered sorts and declarations are rejected in Python before Lean runs. A common shape of hardware-derived QF_UF benchmarks can now be certified by the Lean kernel without trusting the solver.

Background

The project's goal is unsat results from Z3 that an independent Lean checker accepts without trusting the solver. Z3 produces native evidence, a legacy proof object or, for theory fragments, a clause log from its sat.smt core. A Python exporter replays that evidence into a versioned JSON certificate, checking the shape of each inference. A reconstructor emits Lean source in which every inference is a lemma, and the Lean kernel checks that the assertions imply False under only the three standard axioms.

The PR serves milestone 3 of the plan, "Equality and linear arithmetic", which adds uninterpreted functions and equality reasoning alongside linear real arithmetic, completing each fragment end to end before adding another. The QF_UF slice from loop iteration 2 models the uninterpreted sort as a Lean type variable with indexed families of constants, functions, and predicates, and listed ite over the sort as a known gap. No new hint kind was needed: Z3's euf core keeps an ite term opaque and records (not c) ∨ (ite c a b) = a and c ∨ (ite c a b) = b as tseitin inferences, the same clauses the Real ite support from iteration 1 already handled. The gap was in the adapter, not the certificate format.

What changed

Exporter

Fragment classification accepts an ite whose branches have the uninterpreted sort, under any supported condition. The reserved-name and single-sort checks moved into a helper shared with function signatures, so a two-sort ite is still rejected.

Clause-log replay

  • Gate clauses for any term sort. The two branch clauses are added as def-axiom nodes for ite terms of every non-Boolean sort, found by descending into equalities, distinct, and predicate applications.
  • Narrower last-resort cnf lemma. When no single assertion implies a logged clause, the replay now negates an unsat core of the assertions instead of all of them, and keeps a clause literal that is already the negation of a source rather than resolving it away. This fixes the alldiff clauses Z3 emits after simplifying an ite under an already-asserted unit, which previously produced a unit-resolution step the reconstructor rejected. The change applies to every fragment.
  • Clearer errors. A core check cut off by the resource limit reports a resource-limit error rather than a mismatched assertion, and an ill-sorted built-in application in the log reports an export error instead of a raw Z3 exception.

Lean reconstruction

  • The declaration table accepts if : (Bool, U, U) -> U, rendered as @ite _U c (Classical.propDecidable _) a b inside noncomputable definitions, as for Real.
  • Gate lemmas cover any term sort, and the def-axiom checker constructively proves the two condition-free Boolean gates (or (not (ite p q r)) q r) and (or (ite p q r) (not q) (not r)) that Z3 records and that were previously rejected.

Tests and documentation

Certificate tests gain classification cases and pinned replays for ite over the sort and for the alldiff-under-a-unit input, including rejection of undeclared, ill-sorted, and tampered terms. The two new Boolean gate clauses join the shared def-axiom list, so every literal order is Lean-checked and every weakening rejected. The QF_UF Lean suite adds two documented inputs verified end to end plus three pinned random instances. Both READMEs and the plan document gain a dated note.

Review

The reviewer approved the change with no blocker, major, or minor findings and three nits, after reading the full diff and surrounding replay and reconstruction code, re-running every suite, and probing tampering and edge cases.

  1. Nit, resource exhaustion looked like a mismatch. In the new unsat-core helper, a solver answer of unknown surfaced as a mismatched-assertion error, so a user could not tell whether to raise the limit. Fixed in the final commit with a distinct resource-limit error, a module-level limit constant, and a test that pins the message.
  2. Nit, pinned literal bound depends on core minimality. A test asserts at most three literals per cnf lemma, assuming Z3's non-minimal core excludes an irrelevant assertion. Not changed. The suggested looser bound equals three for this input, the companion Lean test uses the same bound, and QF_UF core extraction involves no platform-dependent arithmetic.
  3. Nit, gate clauses not registered for dependency-scoped RUP. Gate clauses of non-Boolean ite terms enter the clause database but not the gate-entry table, so reverse unit propagation over a trimmed log cannot use them implicitly. Not changed. This was already so for Real ite, trimmed logs carry the tseitin clauses explicitly, and no replay fails today.

Risks and open questions

  • The cnf fallback changed for every fragment. Cores are supersets of a minimal implying set, so the lemma stays valid and a different core only changes which hypotheses grind sees. The QF_LRA matrix still verifies, but this is the one change reaching beyond QF_UF.
  • Large cores, large lemmas. Z3's cores are not minimal, so many assertions can yield a grind lemma over many hypotheses. Not measured beyond the stress set.
  • Gate discovery visits more nodes per literal. Inputs without ite gain no clauses and keep identical Lean text, but the traversal cost on large logs is not quantified.
  • Platform sensitivity of the pinned core bound stays open until the wheel jobs have run across platforms over time.
  • Still rejected: a second uninterpreted sort, QF_UFLRA, uninterpreted functions with Bool or Real arguments or results, and QF_LIA.
