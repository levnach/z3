## Summary

- Check the two `distinct` gate clauses in the native `alldiff` proof checker instead of trusting every hint.
- Log root `distinct` clausification as input clauses, like other root clausification.
- Add direct checker, native-replay, and live clause-log regressions.

## Motivation

The native `alldiff` plugin returned true for every hint. A log inferring
`(or (= a b) (= a c) (= b c))` with an `alldiff` hint and no assumption replayed
as `+alldiff 1` despite the clause having a countermodel.

Z3 used the label for two different operations. Root `distinct` clausification
follows from an asserted formula that is not recorded in the hint; those clauses
are input, not independently checkable theory inferences. The two clauses for a
`distinct` below the root, `(or (not d) (not some_eq))` and `(or d some_eq)`,
are tautologies, where `some_eq` is the disjunction of pairwise equalities.

## Changes

- **Proof production:** `add_not_distinct_axiom` and `add_distinct_axiom` use
  `sat::status::input()` for root clauses. Remove the unused
  `mk_distinct_status` overloads.
- **Native checker:** move the implementation into
  `distinct_theory_checker.cpp` and register it in CMake. Require two literals
  of the same polarity, one a `distinct` and the other its equality disjunction.
  The positive clause must cover every argument pair not already known distinct,
  up to equality symmetry; the negative clause must contain only equalities
  between arguments. Handle constants, repeated arguments, and the two-argument
  case. Non-gate shapes fall back to the existing SMT check.
- **Regressions:** direct checker tests cover valid gates, wrong polarities,
  missing pairs, foreign disjuncts, repeated arguments, constants, and root
  shapes. Native replay requires `+alldiff 2` for a genuine gate pair. A Python
  test checks that root clauses are assumptions and below-root clauses retain
  their gate hints; it skips when no `z3` executable is available.
- **Documentation:** update the clause-log comments and add a dated native
  `alldiff` note under Boolean and EUF proof infrastructure.

No Lean, axiom, trust-flag, or CI workflow changes. The Python exporter's logic
is unchanged; its existing assumption path handles the root clauses.

## Risks and follow-ups

- Root `distinct` clauses now appear as assumptions to clause-log and
  `OnClause` consumers. Encodings above 32 arguments use fresh symbols and are
  equisatisfiable rather than equivalent; the Lean exporter rejected those
  encodings before this change and still does.
- Level-zero simplification can shorten an input clause, including to an empty
  assumption. The exporter's existing unsat-core fallback handles that shape.
- The default `theory_checker_plugin::vc` still combines the logged clause
  with the hint for SMT fallback. A tautological hint can therefore mask an
  invalid logged strict sub-clause. This pre-existing framework behavior is
  unchanged here and remains a separate follow-up with a regression needed
  across plugins.
- Other follow-ups are direct Lean def-axiom support for the gate clauses,
  single-argument `distinct` reconstruction, and the pre-existing finite-sort
  empty `tseitin` clause case.

The implementation was reviewed and integrated in the fork. This PR is left
open for upstream review and is not merged automatically.
