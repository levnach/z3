## Summary

- Check xor gate clauses using the assignment that falsifies the other clause literals.
- Require the correct parity and evidence for every xor argument, for both positive and negated gates.
- Add direct checker and native-replay regressions, and prevent early replay exits from silently passing the unit test.

## Motivation

The native Tseitin checker accepted invalid xor clauses. For positive gates, its signed count only tracked whether an even number of arguments appeared, not their actual parity. Arguments left free by the clause were ignored. For negated gates, it iterated the outer `not` node rather than the xor arguments.

Examples previously accepted despite falsifying assignments:

| Clause | Counterexample |
| --- | --- |
| `(or (xor a b) a b)` | `a = false`, `b = false` |
| `(or (xor a b) (not a) (not b))` | `a = true`, `b = true` |
| `(or (not (xor a b)) (not a))` | `a = true`, `b = false` |

## Changes

- **Native checker:** share a parity helper between both xor branches. Determine argument values from the other clause literals or constants, reject unfixed arguments, and require the gate value that makes the clause true.
- **Regressions:** cover the four defining xor clauses, wrong polarities, free arguments, repeated/constants/nested arguments, unaffected `and` gates, and replay requiring `+tseitin 4` without SMT fallback.
- **Test reliability:** replay currently calls `exit(0)` on an invalid step. An exit guard makes this fail the unit binary instead of skipping remaining tests with a successful exit. Scoped cleanup restores the captured stream and guard state on normal return or exceptions.
- **Documentation:** add the dated native xor checker note and concrete counterexamples.

## Risks and follow-ups

This changes native proof-checker acceptance, not solver search or proof production. Live logs generally rewrite xor to negated Boolean equality before clausification. Lean's independent def-axiom checking is unchanged.

The production replay frontend's zero exit status on a rejected proof remains a separate follow-up. The test-only guard prevents it from silently passing this regression suite. The loop stops with the C++ PR open; it is not merged automatically.
