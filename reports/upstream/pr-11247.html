## Summary

Generated Lean proofs for conjunctions and disjunctions with a few hundred
operands exceeded Lean's default recursion limit while elaborating formula
definitions, before the existing per-theorem limit took effect.

Raise the elaboration limit for the generated namespace and use proof-term
shapes that avoid unnecessary elaboration work on wide conjunctions and unit
resolution chains. This changes elaboration limits and generated terms, not
the trust boundary, accepted proof rules, Lean library, or solver.

## Changes

- Set `maxRecDepth 100000` once inside the generated namespace, covering
  definitions, lemmas, outlined steps, and the final theorem instead of only
  selected declarations.
- Project conjuncts and outlined input hypotheses using field notation such
  as `_step_N.2.2.1`, so elaboration starts from a known type.
- Remove eliminated and false literals with `Or.resolve_left`; retain
  `Or.elim` case splits for literals that remain in the conclusion. The
  existing resolution validation checks are unchanged.
- Add six end-to-end regressions over 200-260 operands, covering conjunctions
  and disjunctions through the legacy and clause-log proof sources, including
  QF_UF cases and axiom checks.
- Document the scaling improvement and remaining limits.

## Scope and remaining limits

No C++ or Lean library files change, and generated files still go through the
pinned checker with `--trust=0`. The recursion limit is an elaboration resource
setting, not a trust setting.

This does not remove all scaling limits. At roughly 600 operands, outlined
proofs can still exceed the heartbeat limit because of quadratic input
projections. The motivating `NEQ004_size4` benchmark also has independent
clause-log trimming and rewrite-lemma limitations. Sharing conjunction tails
and improving outlined projections remain follow-ups.
