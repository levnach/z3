Prove the logged clause in the proof checker's SMT fallback

Pull request Z3Prover/z3#11248 · state OPEN (not merged) · opened 2026-10-21T02:27:55Z · loop iteration 25

The change is commit 795f37b on top of upstream 68a8a75. The PR has not been merged, so there is no merge commit to report.

In one paragraph

Z3's proof replay checks each inferred clause against its hint. When no theory checker plugin accepts the hint, the step goes to the SMT fallback. Before this PR the fallback's verification condition contained the logged clause and the hint's clause together. Whenever the hint's clause was a tautology, any logged clause was accepted, even a satisfiable unit clause. The PR makes the fallback refute the negation of the logged clause alone. A plugin's shortcut is used only when the logged clause follows from the hint's clause by subsumption plus RUP. The replay is the first filter on exported clause logs, so a soundness hole there lets a wrong refutation look clean until Lean rejects it.

Background

Before this PR the replay checked hints natively for Boolean gates, arithmetic, equality, and, since the previous iteration, distinct constraints. Hints from the array, datatype, quantifier, and floating-point theories always used the SMT fallback. The fallback silently accepted everything when the hint's clause was a tautology, which is the shape of the alldiff gate clauses and most theory lemmas. A second gap sat next to it: the quantifier instantiation shortcut never related the logged clause to the hint's clause. This work serves milestone 3, equality and linear arithmetic, and prepares milestone 4, broader theories, where the C++ checker stays in use for diagnostics.

What changed

  • The fallback proves the right thing. A step whose hint is a tautology but whose logged clause does not hold is now rejected with a countermodel instead of being marked verified-smt.
  • Plugin shortcuts are gated. A plugin's simplified condition is honoured only when every logged literal occurs in the hint's clause and the dropped literals are false by RUP. The old stamp certified the recipe, not the dish.
  • The checker reports instead of exiting. The inference routine returns whether the step verified and leaves a failed clause unrecorded. Both replay frontends still stop on failure, so command-line behaviour is unchanged.
  • Diagnostics mean what they say. The line unit ... is not rup is printed only on steps that end in did not verify, because z3test's matrix script reads it as a rejection.
  • Unit tests drive the checker directly. A new test feeds assumptions, one inferred clause, and a hint to the checker in-process and inspects the verdict and the printed text.

Worked example

This PR fixes the native C++ checker, not Lean reconstruction, so the example shows the checker's verdict before and after. The input is the probe from the previous PR's review, now also in the new unit test. It assumes that three constants of an uninterpreted sort are not all distinct, then claims they are distinct under an alldiff hint. The hint's clause is a tautology. The logged unit clause is not, so a correct checker must reject the step.

(a) The input

Same file as the unit test probe, with the declarations on separate lines.

(declare-sort U 0)
(declare-fun a () U) (declare-fun b () U) (declare-fun c () U)
(define-const $15 Bool (= a b)) (define-const $16 Bool (= b c)) (define-const $13 Bool (= a c))
(define-const $9 Bool (distinct a b c))
(define-const $14 Bool (or $15 $13 $16))
(declare-fun alldiff (Bool Bool) Proof) (declare-fun rup () Proof)
(assume (not $9))
(infer $9 (alldiff $9 $14))
(infer rup)

Review

The fork reviewer's verdict was APPROVE, with no blocker or major findings. The reviewer reproduced the probe, wrote four more for the quantifier paths, and found no way to make the new code accept an unproved clause.

  • Minor: a diagnostic that lied. The reviewer's probe had a valid logged clause whose hint dropped a non-RUP literal. The step correctly verified, but the output also said is not rup, which z3test's matrix script treats as a rejection. Fix: the message is buffered and printed only before did not verify, and a unit test asserts its absence.
  • Nit: noisy test logs. The test helper echoed the captured checker output, so passing tests filled the log with did not verify blocks. Fix: the echo was removed.
  • Suggestion, deferred. The quantifier tautology shortcut is counted as a native hit under +inst. This predates the PR.

Risks and open questions

  • Stricter acceptance. A replay that was verified-smt only because its hint's clause was a tautology now ends in did not verify. No corpus or Lean matrix case does this. External logs might.
  • Slower quantifier steps in rare shapes. A quantifier instantiation whose logged clause differs from the hint's clause beyond RUP-false dropped literals is now proved against the full quantified premise. Sound but slower.
  • Exit status unchanged. A refuted replay still exits with status 0, so CI can only detect it by reading the text.
  • Upstream CI pending. Most checks had not finished at the time of writing. None had failed.

What comes next

  • Return a nonzero exit status from the replay frontends on a refuted step, once z3test's text-based classifier can cope.
  • Add a distinct counter for the quantifier tautology shortcut.
  • Remove the stale t8.smt2 annotation in z3test, which predates this change.
  • Carry alldiff gate clauses into the Python exporter and Lean rules, still on the backlog.

Glossary

assumption
A clause the replay takes as given without proof, usually an input assertion. Written (assume ...) in the clause log.
clause
A disjunction ("or") of literals, such as (or (= a b) (= a c)). A clause is true when at least one literal is true.
countermodel
An assignment of values that satisfies the negation of a claimed clause, proving that the claim does not hold. Example: a = b for the claim "a, b, c are distinct".
distinct
The SMT-LIB constraint (distinct a b c) saying that no two of the listed terms are equal. Z3's native checker for it is called alldiff.
hint
A short justification attached to an inferred clause in the log, naming the rule and its arguments, such as (alldiff d some_eq). The checker verifies the step from the hint.
literal
An atomic formula or its negation, such as (= a b) or (not (= a b)).
negation
The "not" of a formula. To prove a clause, a solver can show that its negation has no model.
proof replay
Re-running a logged sequence of clauses through an independent checker that verifies each step. In Z3 it is enabled with solver.proof.check=true.
quantifier instantiation
Deriving a concrete fact from a universally quantified one by substituting a term for the bound variable. The checker's shortcut for it uses the instance itself as the condition.
refutation
A proof that a set of clauses is contradictory, ending in the empty clause.
RUP (reverse unit propagation)
A cheap check: assume every literal of a clause is false, propagate unit clauses, and see whether a conflict appears. If so, the clause follows from the clauses already recorded.
satisfiable
Having at least one model, that is, one assignment of values that makes every formula true.
SMT fallback
The last resort of the replay checker: when no native plugin verifies a step, a fresh solver instance is asked to refute the negation of the clause under the current assumptions.
soundness
The property that a checker never accepts a step that does not follow. A soundness hole is a way to get a wrong step accepted.
subsumption
One clause subsumes another when every literal of the first occurs in the second. The shorter clause is then at least as strong.
tautology
A formula that is true under every assignment, such as "a, b, c are distinct, or some pair among them is equal". Its negation is unsatisfiable on its own.
theory
A family of symbols with fixed meaning, such as linear arithmetic, arrays, or equality with uninterpreted functions. Each theory has its own reasoning rules.
theory checker plugin
A native module of the replay checker that knows how to verify hints of one theory, for example the alldiff or farkas plugin.
uninterpreted sort
A sort, that is a type, with no built-in meaning or fixed size, declared with (declare-sort U 0). Its values are only known to be equal or different.
unit clause
A clause with exactly one literal, such as (distinct a b c) on its own.
verification condition
The formula a checker hands to the solver to establish a step. The step is accepted when the condition's negation has no model.
