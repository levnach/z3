## Summary

Accept plain and parametric SMT-LIB `define-sort` aliases in the proof
certificate exporter, scoped like declarations.

Z3's parser expands the aliases when the exporter parses the selected query
and when the solver writes the clause log. The certificate and reconstructed
Lean statement therefore refer only to expanded sorts, which still pass the
existing fragment and sort checks. No C++, Lean library, axiom, or trust-flag
changes are involved.

## Changes

- Keep `define-sort` commands in query snapshots so push/pop, reset, and
  reset-assertions handle them consistently with declarations.
- Validate definition shape and reject repeated parameters explicitly;
  Z3's parser handles sort resolution and type checking.
- Add exporter regressions for aliases, malformed definitions, unsupported
  expanded sorts, and scope/reset behavior.
- Add end-to-end Lean checks for an alias of an uninterpreted sort and a
  parametric alias, plus a popped-scope regression.
- Update the exporter documentation and proof plan.

## Scope and limitations

Aliases do not enable new underlying theories: an alias of an unsupported sort
is still rejected when used. `global-declarations` and unsupported SMT-LIB
commands remain rejected. Invalid alias bodies can raise `z3.Z3Exception`,
consistent with other parser errors.
