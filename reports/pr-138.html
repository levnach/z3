This pull request is open. It is not merged. The change commit is 21a8ecc85, proposed for master.

In one paragraph

A certificate whose Lean text exceeds 8 MB is now split into a chain of modules of at most 1 MB. Each module is checked by its own Lean process, under the unchanged flags and memory cap. A later module imports the compiled form of the one before it, and the last holds the theorem of the refutation. One Lean process keeps memory for all the text it reads, so long certificates ran out of memory. Nine benchmark files that did not certify before now do. The kernel still checks every declaration once.

Background

Before this PR, one Lean process checked every certificate as a single file. Its memory grew with the length of the text, not with the hardest lemma. Seventeen sample files were exported but did not certify, and five smaller ones passed close to the cap. All use fragments already supported: uninterpreted functions, integer difference logic, and arrays. So this PR adds scale to milestones 3 and 4 of the plan: equality with linear arithmetic, and broader theories.

What changed

An analogy: one proofreader with a whole long book runs out of desk. Now each gets one chapter, plus the stamped results of earlier chapters.

  • Reconstructor. A certificate above 8 MB is cut between top-level declarations into modules of at most 1 MB.
  • Checker script. The new --chain option checks files in order, one Lean process each, and stops at the first rejection.
  • Publication. A large certificate is published as several files, only after the whole chain passes.
  • Guard. A large text with a layout the splitter does not recognise is rejected, never split wrongly.
  • Tests. Every reconstructed text must be splittable, and tampered chains must fail in Lean.

Certificates up to 8 MB are unchanged byte for byte.

Review

The reviewer approved the change, with no blocker and no major finding. The reviewer also tampered with chains in seven ways, such as a sorry or an added axiom. Lean rejected or reported every one.

  • Minor, fixed. The reviewer killed a chain run with a signal that allows no cleanup. The compiled modules stayed in the system's temporary directory, where a stopped measurement had left 706 MB. Deadlines kill runs this way, so disks could fill. A caller can now name a directory with Z3_LEAN_CHAIN_DIR and remove it itself.
  • Minor, fixed. The reviewer declared a constant named a/-b. The splitter took those characters in a header comment for the start of a block comment, and refused a valid certificate. Comment lines are now skipped.
  • Minor, fixed. The reviewer re-checked a published chain with a shell wildcard. The shell sorted module 10 before module 2, so Lean rejected a valid chain. Module numbers are now zero-padded.
  • Two nits, fixed. A command before the namespace is now rejected, and a stale README sentence was reworded.
  • Nit, not changed. One commit carries the code under a generic message. Squashing the PR removes it.

Risks and open questions

  • A later module trusts the compiled form of an earlier one, as every Lean file trusts Lean's own library.
  • Above 8 MB, the output file alone no longer checks.
  • A large text the splitter does not recognise is rejected, not checked as one file.
  • A chain is somewhat slower and needs 5 to 9 MB of disk per MB of text while it runs.
  • Only macOS was run locally, and no Linux CI result is known.
  • The sokoban file still fails: a lemma runs out of heartbeats. One file got no verdict in 40 minutes, and six were not measured.

What comes next

  • Shorten the sokoban lemmas, which walk a long nested conjunction one part at a time.
  • Measure the six remaining files, and find why the modules of vlsat3_c27 are slow.
  • Let modules import only what they use, so they can be checked in parallel.

Glossary

array
A value that maps indices to elements, read with select and updated with store.
assertion
A formula the input states to be true, written (assert ...) in SMT-LIB.
axiom
A statement accepted without proof. Lean can list the axioms a theorem depends on.
benchmark
A standard input file used to test and measure solvers.
certificate
The evidence for a result, written so that an independent checker can verify it. Here it is Lean text.
chain of modules
Modules in a fixed order, where each one imports the one before it.
compiled module
The file Lean writes after it accepts a module, with the extension .olean. Later files read it instead of the source.
conjunction
A formula that joins parts with "and". It is true only when every part is true.
declaration
One named item in a Lean file, such as a definition or a theorem.
fragment
A part of the input language that the pipeline supports, such as formulas over uninterpreted functions.
heartbeat
Lean's unit of work. A proof that uses more than its budget of heartbeats is stopped with an error.
hypothesis
An assumption of a theorem. Here each assertion of the input is one hypothesis.
import
A line at the top of a Lean file that makes the declarations of another module available.
interpretation
A choice of meaning for the uninterpreted sorts and functions. A refutation must hold for every such choice.
kernel
The small core of Lean that checks every proof. Only the kernel has to be trusted.
lemma
A small proved statement used as a step toward a larger one.
linear arithmetic
Arithmetic where variables are only added and multiplied by constants, such as 2x + y <= 5.
logic
In SMT-LIB, a named fragment that says which theories an input uses. QF_UF has uninterpreted functions, QF_IDL has differences of integers, QF_AX and QF_AUFLIA have arrays.
memory cap
A limit on the memory one process may use. Here it is 8 GB per Lean process.
module
One Lean file, treated as a unit that other files can import.
namespace
A named scope that prefixes the names declared inside it, so that they cannot clash with others.
proof step
One inference of the solver's proof. Here each step becomes a small Lean theorem.
refutation
A proof that a set of assertions leads to a contradiction.
sorry
Lean's placeholder for a missing proof. The checker treats it as an error.
sort
The type of a value, such as Int, Real, or Bool. An uninterpreted sort, such as I above, has no fixed meaning.
theorem
A statement together with a proof that Lean has checked.
theory
The rules that give certain symbols a fixed meaning, such as the theory of arrays or of integer arithmetic.
uninterpreted function
A function symbol with no fixed meaning. Only one rule holds: equal arguments give equal results. Example: op above.
