Certify QF_UF refutations from the legacy proof object in Lean

Pull request: levnach/z3 #7 Merge commit: 41dbe2b0 Merged: 2026-10-14T16:33:25Z Loop iteration: 7

In one paragraph

This PR lets the pipeline certify refutations in the QF_UF fragment from Z3's legacy proof object. A refutation is a proof that a set of assertions cannot all be true at once. QF_UF is the fragment of inputs built from equality and uninterpreted functions, which are function symbols with no fixed meaning, only the rule that equal inputs give equal outputs. Each value has a sort, which is the type of the value, such as a user-declared sort or Boolean. The legacy proof object is the step-by-step proof that Z3's default solver core records when proofs are requested. The exporter now accepts it for QF_UF, and the reconstructor turns each equality step into an explicit Lean proof term that the kernel checks directly, instead of re-proving it with an automated tactic.

Background

Before this PR the pipeline could certify QF_UF only through the clause log of the newer solver core. That route starts after preprocessing and relies on Lean's grind tactic to re-prove each equality hint. The legacy proof object records every equality step explicitly, but the exporter rejected it for QF_UF input. The reconstructor also knew the equality rules only for Boolean formulas. This work serves milestone 3 of the plan, "Equality and linear arithmetic", and was the first item on its backlog.

What changed

  • Exporter. With --core legacy you can now export QF_UF refutations from the legacy proof object, with sort names kept, while linear arithmetic is still rejected.
  • Equality steps. Reflexivity, symmetry, and transitivity, which say equality holds for a term with itself, can be flipped, and can be chained, now become Lean equality terms when the sides are terms of a sort.
  • Congruence. A congruence step says that applying the same function or predicate to equal arguments gives equal results. Lean now checks it one argument at a time, like matching two shopping lists item by item before concluding the totals agree.
  • If-then-else and distinct. Congruence through an if-then-else term, written ite in SMT-LIB, uses one helper lemma per file, and the distinct operator, which says several terms are pairwise unequal, is matched against its expansion into disequalities.
  • Commutativity and rewrites. A commutativity rule, which swaps the two sides of a symmetric operator, is now supported, and a rewrite that changes nothing is proved by reflexivity in place.
  • No solver changes. Only Python, tests, and documentation changed, and the default route for QF_UF still uses the clause log.

Worked example

The input below was built from the shapes in the PR's new tests and run through the real pipeline for this report. It declares a sort, two constants of that sort, a function, and a predicate, which is a function whose result is Boolean. The three assertions, the facts the input claims, are contradictory because of congruence.

(a) The input

(set-logic QF_UF)
(declare-sort U 0)
(declare-fun a () U)
(declare-fun b () U)
(declare-fun f (U) U)
(declare-fun p (U) Bool)
(assert (= a b))
(assert (p (f a)))
(assert (not (p (f b))))
(check-sat)

Review

The reviewer approved the PR with no blocking, major, or minor findings and four nits. They also tried several forged certificates, such as a congruence step with swapped sides, and Python rejected each one before Lean ran.

  • Nit, fixed: congruence with no arguments. Such a step always produced a Boolean reflexivity term, even for sides that were terms of a sort, so Lean would have failed with a type error instead of Python giving a clear message. Z3 never emits this step, so the outcome was only a false rejection. The code now picks the term by sort, and a new test covers it.
  • Nit, fixed: outdated README sentence. The Boolean section still said every rewrite is checked by a truth table, which the new QF_UF section contradicted. The sentence now lists the three cases.
  • Nit, not changed: pinned random seeds. The new test pins random seeds and expects at least ten congruence steps, so an unrelated solver change could require new seeds. This matches an existing test pattern.
  • Nit, not changed: duplicate classification. The exporter classifies the assertions twice on the legacy path, which is cheap and keeps a function signature that z3test depends on.

Risks and open questions

  • Three reconstructor functions now branch on the sort of the sides for every fragment. The Boolean output is unchanged and its suites pass.
  • Gate-clause matching now identifies distinct with its expansion. A wrong match can only make the Lean lemma fail, since the lemma is checked, never trusted.
  • Boolean commutativity shapes were checked only in a Lean probe, since Z3 did not emit them on any scanned input.
  • Legacy QF_UF proofs beyond about 1,200 steps were not measured.

What comes next

  • Add QF_UF inputs and a legacy QF_UF cell to the z3test regression matrix, so this route is exercised beyond unit tests.
  • The default route still sends QF_UF to the clause log, and switching it is a separate decision.
  • Linear arithmetic over the legacy proof object still needs Farkas coefficients from the C++ side.
