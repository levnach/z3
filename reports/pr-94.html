Certify scripts with optimization commands; refute Boolean distincts

Pull request levnach/z3 #94 into master · State: OPEN · Opened 2026-11-08T03:16:20Z · Loop iteration 94

This pull request is open and not merged. The change it proposes is commit 4e67be7b7. It contains three commits.

In one paragraph

This PR does two things. First, the exporter now accepts scripts that use optimization commands, such as soft assertions and objectives. It drops them and certifies that the hard assertions alone are contradictory. Second, it fixes a Lean failure on a distinct of three or more Booleans. Such a distinct is always false by the pigeonhole principle. Before, the tactic omega ran out of heartbeats on it, and the rewrite step could not be proved. Now a small proved lemma removes the distinct first. Together, these changes let two real z3test regressions get a refutation that Lean checks.

Background

Before this PR, the exporter's frontend rejected every script containing assert-soft, minimize, or maximize. The previous PR, #93, had already taught it to drop print-only commands. Of the z3test regressions with optimization commands, Z3 answers unsat on four. Two of them, 3402.smt2 and 3524.smt2, are QF_LIA and so lie inside the certified fragments. Once 3524 could be exported, it exposed the second problem with Boolean distincts. This work serves milestone 3, equality and linear arithmetic. It also moves toward milestone 4, a frontend that accepts real scripts and explicitly rejects what it cannot handle.

What changed

  • A script with assert-soft, minimize, maximize, or get-objectives can now be certified, and the certificate speaks only about the hard assertions.
  • The opt.* options, which only tune how Z3 searches for an optimum, are now ignored instead of rejected.
  • An unsat answer that only means "no more optimal solutions" gets no certificate, because the hard assertions are satisfiable.
  • A distinct of three or more Booleans inside an integer rewrite step is now proved false in about a second instead of timing out.
  • The same fix also works when the reconstructor first replaces div, mod, or abs terms with fresh names, called generalizing them.

An analogy for the soundness argument: a soft assertion is a wish, and a hard assertion is a rule. If the rules alone already contradict each other, no wish can help, and that is all the certificate claims.

The distinct (distinct p q r) becomes three pairs, "p differs from q", "p differs from r", and "q differs from r".

private theorem rewrite_14 (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    : (formula_13 _atoms _vars) := by
  unfold formula_13 formula_12 formula_11 formula_7 formula_6 term_5 term_4 formula_3 formula_2 formula_1 formula_0
  have _bd3 : Not (And (Not (Iff (_atoms 0) (_atoms 1))) (And (Not (Iff (_atoms 0) (_atoms 2))) (Not (Iff (_atoms 1) (_atoms 2))))) := fun _h => _bool_distinct3 _h.1 _h.2.1 _h.2.2
  (try (set_option linter.unusedSimpArgs false in simp only [↓ _bd3])) <;> (first | omega | grind (splits := 64))

This rewrite step justifies Z3's simplification of the first assertion to x > 5. The fact _bd3 states the distinct is false, simp removes it, and only then do omega or grind run.

Review

The reviewer approved the PR. There were no blocker, major, or minor findings, only three nits.

  • Nit, design note. The reviewer read the new pointer sentence in the plan document and could not parse it. It read "accepted since, see the next note". It now says "Since 2026-11-07 the optimization commands are accepted".
  • Nit, README. One edited line was 86 characters wide, while the rest of the paragraph wrapped near 79. This was cosmetic. The paragraph was rewrapped.
  • Nit, duplicated renderer. The reviewer noticed the new facts were printed by a private copy of the existing _inline function. If the two copies ever drifted apart, a fact would no longer match the goal word for word. Then simp would silently do nothing, and the old timeout would come back. This could not make Lean accept something false, but it could quietly undo the fix. The copy was removed, and _inline gained an optional argument instead. The full Lean suite was re-run.

Three further suggestions were not adopted: clearing the facts after simp, a per-tactic heartbeat budget, and a command-line note for optimization sources.

Risks and open questions

  • A certificate for an optimization script says only that the hard assertions are contradictory. It says nothing about any optimum.
  • When Z3 answers unsat because it ran out of Pareto or box solutions, the exporter answers sat and gives no certificate. A test pins this.
  • All opt.* options are ignored as one family. The PR argues they only configure the optimization search, not how the input is read.
  • Each new fact is a theorem the Lean kernel checks. A wrong fact makes Lean fail. It cannot make Lean accept a false statement.
  • The general hazard remains. In first | omega | grind, an omega timeout escapes first, so grind never gets its turn. This PR fixes it only for Boolean distincts.

What comes next

A backlog candidate tracks the general heartbeat hazard, for example a separate heartbeat budget for omega. Nine z3test files with optimization commands are still rejected, for options that change how input is read and similar reasons. None of them has an unsat answer. Two other unsat optimization regressions, 3342 and 3420, use bit-vectors and remain outside the certified fragments.

Glossary

atom
A smallest formula with no Boolean connectives inside, such as p or x > 5.
Boolean
A value that is either true or false. In SMT-LIB its sort is Bool.
distinct
An SMT-LIB operator that says all its arguments differ pairwise. (distinct a b c) means a≠b, a≠c, and b≠c.
generalization
Replacing a complicated term, such as (mod x 7), with a fresh variable so a tactic can treat it as an unknown number.
grind
A Lean tactic that combines case splitting, equality reasoning, and arithmetic to close goals automatically.
hard assertion
An ordinary assert. Every solution must satisfy it. Also called a hard constraint.
heartbeat
Lean's unit of work budget. When a proof uses more heartbeats than allowed, Lean stops it with a timeout.
kernel
The small trusted core of Lean that re-checks every finished proof.
lemma
A small proved statement used as a step inside a bigger proof.
objective
A term the solver should make as small (minimize) or as large (maximize) as possible.
omega
A Lean tactic that decides linear arithmetic over integers and natural numbers.
optimization command
An SMT-LIB extension that asks for a best solution, not just any solution: assert-soft, minimize, maximize, and get-objectives.
Pareto front
For several objectives, the set of solutions where no objective can improve without another getting worse. Z3 lists them one per check-sat and answers unsat when none remain. Box mode is a similar search that treats each objective on its own.
pigeonhole principle
If you put more items than boxes, two items share a box. Three Booleans have only two values, so two of them must be equal.
QF_LIA
The SMT-LIB logic of quantifier-free linear integer arithmetic, for example 2x + y < 7 over integers.
refutation
A proof that a set of assertions leads to False, so they cannot all hold together.
rewrite step
A proof step saying Z3's simplifier replaced a formula with an equivalent one, such as (or (distinct p q r) (> x 5)) with x > 5.
simp
A Lean tactic that rewrites a goal using given equations or facts. simp only uses just the listed ones.
soft assertion
An assert-soft: a constraint the solver tries to satisfy but may break, optionally with a weight for how much it matters.
sort
The type of a value in SMT-LIB, such as Int or Bool.
tactic
A command in a Lean proof that builds part of the proof automatically, such as omega or simp.
