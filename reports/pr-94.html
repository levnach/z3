Certify scripts with optimization commands; refute Boolean distincts

Pull request #94 State: MERGED Merged: 2026-11-08T03:29:32Z Loop iteration 94

Merge commit: a49658ac9cd4 on master of levnach/z3.

In one paragraph

This PR does two things. First, the exporter's frontend now accepts scripts that contain soft assertions and objectives. It drops those commands and certifies only that the hard assertions are contradictory. Second, the Lean reconstructor now proves every distinct of three or more Booleans false with one small lemma. It removes them with a rewrite before the arithmetic tactics run. Before, the omega tactic used up its heartbeats on such terms and the whole proof failed. Together, the two changes let two z3test regressions in the QF_LIA fragment end in a refutation that Lean accepts.

Background

Before this PR, the frontend stopped at the first assert-soft, minimize, or maximize command. It also refused every opt.* option. Z3 answers unsat on four of the 90 z3test regressions with such commands, and two of them, 3402.smt2 and 3524.smt2, lie inside the certified fragments. Once 3524 could be exported, a second gap appeared. Its proof contains a rewrite that folds distincts of 8 and 13 Booleans to false. Lean timed out on that step, and the kernel then reported a missing constant. The PR serves Milestone 3 of the plan, equality and linear arithmetic. It also widens the frontend that Milestone 4 describes.

What changed

  • You can now certify a script that uses assert-soft, minimize, maximize, or get-objectives, and the certificate speaks only about its hard assertions.
  • You can now leave opt.* options in a script, and the exporter ignores them like printing options.
  • A :named label inside one of these commands is still rejected with a clear message.
  • You can now check in Lean an integer problem whose proof relies on a distinct of three or more Booleans being false.
  • The Lean fix also works when the arithmetic contains div, mod, or abs.

An analogy for the Lean fix: three light switches cannot all be in different positions, because each switch has only two. That is the pigeonhole principle. The new lemma _bool_distinct3 states it once. Each long distinct then needs only three of its pairs to be refuted.

Worked example

This input combines the two new tests. It was run through the merged code and the PR's base scripts.

(a) The input

(declare-const x Int)
(declare-const p Bool)
(declare-const q Bool)
(declare-const r Bool)
(assert (or (distinct p q r) (> x 5)))
(assert-soft (> x 9) :weight 2)
(minimize x)
(assert (< x 3))
(check-sat)

The two hard assertions clash: the distinct is false, so x must exceed 5 and stay below 3.

(b) Before

proof_certificate.py: error: unsupported SMT-LIB command: assert-soft

The old exporter stopped at the soft assertion, so no Lean file was produced at all.

The old Lean step was never reached for this file. On a larger input of the same kind, the PR's test saw it time out after 80 seconds.

theorem unsat (_atoms : Nat -> Prop) (_vars : Nat -> Int)

The theorem has exactly two hypotheses, the hard assertions, and nothing from assert-soft or minimize.

private theorem _bool_distinct3 {a b c : Prop} (_ab : Not (Iff a b)) (_ac : Not (Iff a c))
    (_bc : Not (Iff b c)) : False := by
  by_cases _a : a <;> by_cases _b : b <;> simp_all

The new lemma says three propositions cannot be pairwise different, proved by trying each case.

private theorem rewrite_14 (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    : (formula_13 _atoms _vars) := by
  unfold formula_13 formula_12 formula_11 formula_7 formula_6 term_5 term_4 formula_3 formula_2 formula_1 formula_0
  have _bd3 : Not (And (Not (Iff (_atoms 0) (_atoms 1))) (And (Not (Iff (_atoms 0) (_atoms 2))) (Not (Iff (_atoms 1) (_atoms 2))))) := fun _h => _bool_distinct3 _h.1 _h.2.1 _h.2.2
  (try (set_option linter.unusedSimpArgs false in simp only [↓ _bd3])) <;> (first | omega | grind (splits := 64))

The rewrite step first states the distinct false, then lets simp erase it, and only then runs omega or grind.

Lean accepted the file. The check script printed "Lean checks passed."

Review

The reviewer approved the PR. There were no blocker, major, or minor findings, only three nits.

  • Nit, plan note. The reviewer read the new pointer sentence in the plan and could not parse it. It read "accepted since, see the next note". It now says "Since 2026-11-07 the optimization commands are accepted".
  • Nit, README. One edited README line was 86 characters long while its neighbours wrapped near 79. The paragraph was rewrapped. This was purely cosmetic.
  • Nit, duplicated printer. The new fact builder had its own copy of the formula printer _inline. If the copies drifted apart, the fact would stop matching the goal. The simp step would then silently do nothing, and the old timeout would return. That is not unsound, but it would quietly bring back failures. The fix gave _inline an optional argument and deleted the copy. The full Lean suite was run again.

Three further suggestions were not adopted. No failing input supports them, or they were out of scope.

Risks and open questions

  • A certificate for an optimization script means "the hard assertions are contradictory". It says nothing about any optimum.
  • Z3 can also answer unsat when the hard assertions are satisfiable but a Pareto front or box search is exhausted. Such queries get no certificate, and a test pins this.
  • The opt.* options are ignored as a family. The PR argues they never change the parsed assertions.
  • The general hazard remains. In first | omega | grind, an omega timeout still escapes first for terms other than Boolean distincts.

What comes next

  • A per-alternative heartbeat budget would let grind run even when omega runs out. It is tracked as a backlog candidate.
  • Nine z3test optimization files are still rejected for input-reading or unknown options. None of them has an unsat answer, so none blocks a certificate today.

Glossary

Boolean
A value that is either true or false. Its sort is written Bool in SMT-LIB and is a Prop in Lean.
conjunction
A formula joined by "and". It is true only when every part is true. Lean writes it And.
distinct
An SMT-LIB term that says all its arguments differ pairwise. (distinct p q r) means p≠q, p≠r, and q≠r.
equivalence
Two Booleans have the same truth value. Lean writes it Iff, so "p and q differ" is Not (Iff p q).
fragment
A limited part of the input language that the pipeline supports, usually named by an SMT-LIB logic.
frontend
The part of the exporter that reads the SMT-LIB script and decides which commands it can certify.
grind
A general-purpose Lean tactic that tries case splits, equalities, and arithmetic together.
hard assertion
A formula added with assert that every solution must satisfy.
heartbeat
Lean's unit for counting work. When a tactic uses more than the allowed number, Lean stops it with a timeout.
hypothesis
A fact a theorem assumes. Here the hypotheses are the script's hard assertions.
kernel
The small core of Lean that finally checks every proof. Nothing is accepted unless the kernel agrees.
lemma
A small proved statement used as a step inside a larger proof.
objective
A term to make as small or as large as possible, given with minimize or maximize.
omega
A Lean tactic that decides linear arithmetic over integers and natural numbers.
Pareto front
With several objectives, the set of solutions that cannot improve one objective without worsening another.
pigeonhole principle
If you put more items than boxes into boxes, two items share a box. Three Booleans have only two values, so two agree.
QF_LIA
The SMT-LIB logic of quantifier-free linear integer arithmetic, such as x + 2y < 7 over Int.
refutation
A proof that a set of assertions leads to false, so they cannot all hold.
rewrite
A proof step that replaces a term by an equal or equivalent one, for example a distinct of Booleans by false.
simp
A Lean tactic that rewrites a goal with given facts. simp only [↓ h] uses just h, outermost terms first.
soft assertion
A formula added with assert-soft that the solver tries to satisfy but may violate at a cost given by its weight.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that builds part of a proof automatically, such as omega, grind, or simp.
