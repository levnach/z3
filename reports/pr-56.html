In one paragraph

This PR lets the Lean reconstructor prove two kinds of rewrite step that used to fail. In the first kind, Z3 reshapes if-then-else terms of sort Real. The two sides of the rewrite then hold different-looking ites that always have the same value. In the second kind, one side holds a wide disjunction nested to the left, and the other side holds it flattened. Before, both ended in one large grind call that ran out of heartbeats, so the whole refutation failed. Now matching ites are proved equal by small lemmas, and matching pieces of the two sides are linked first. Three QF_LRA benchmarks now pass the Lean check. Every new step is checked by the Lean kernel, so the trust boundary does not move.

Background

The reconstructor already had a fast path for rewrites, the normalized rewrite. It replaces each arithmetic atom by its linear form and then proves the Boolean skeleton. That path refused any rewrite containing an ite, so such rewrites went to grind, which timed out on larger inputs. The propositional prover also did work quadratic in a disjunction's width. Iteration 55 found four exported QF_LRA inputs that Lean rejected in a rewrite step, and this PR fixes three. It serves Milestone 3, "Equality and linear arithmetic", which asks each fragment to work end to end.

What changed

All code changes are in the Python reconstructor examples/python/proof_to_lean.py. There is no C++ change.

  • Ite value tables. A rewrite that reshapes a Real ite can now be certified, because ites with the same value under every assignment of their conditions count as one term, like two recipes that list steps differently but make the same dish.
  • A fallback for ite lemmas. When grind cannot prove two matched ites equal, as with an iff or xor condition, the lemma now does a case split on every ite.
  • Links between equal structures. Sides that differ only by flattening, operand order, duplicates, constants, or double negation are now proved equal piece by piece, smallest pieces first.
  • Linear refutation of wide false disjunctions. Refuting each disjunct of a long false disjunction now starts from a saved tail at most 32 disjuncts back, not from the front.
  • Tests and notes. New tests reproduce the benchmark shapes, and the plan document has a dated section on this work.

Review

The reviewer approved the PR with no blockers and no major findings.

  • Minor, fixed: ites with iff or xor conditions. The reviewer changed the test's inner condition from and to = or xor. The tables still matched the ites, but bare grind could not prove them equal, so Lean rejected the file. The fix added the case-split fallback, and both variants became a regression test. The base commit failed these inputs too, so it was not a regression.
  • Nit, fixed: a misleading comment. A comment implied that absolute-value ites have no table. They do. Such rewrites still go to grind for another reason, and the comment now says so.
  • Nit, partly fixed: size bookkeeping. One header line per link was missing from the proof size budget, and it is now counted. A link that fails still leaves an unused binding, which the author kept because removing it safely needs a larger change.

The reviewer also forced a deliberately wrong ite match, and Lean rejected the output. A wrong match cannot slip through.

Risks and open questions

  • The tail change touches every prover use, but only for false disjunctions wider than 32. The proof terms are the same, in shorter chains.
  • Linked proofs are larger per step. The 16-clock test lemma is 540 KB, under the 1 MB budget. A much wider rewrite could still fall back to grind.
  • Value tables grow exponentially with condition leaves, so they are capped at 8 leaves and 200 nodes. The case-split fallback is also exponential, but runs only after grind fails.
  • Post-merge CI results on master are not known to this report.

What comes next

  • Carpark2-ausgabe-6 still fails. Its rewriter evaluates atoms over ites inside other ites' conditions, which a table over independent leaves cannot see. It is on the backlog.
  • Links could also be enabled for the non-theory propositional rewrites.
  • The main search partly repeats the top link. Reusing it directly would roughly halve the proof text.

Glossary

atom
A formula with no Boolean connectives inside it, such as (< x 3) or a Boolean variable b.
Boolean
The sort of truth values, true and false. The Boolean skeleton of a formula is its and/or/not structure with the atoms left opaque.
case split
Proving a goal separately for each possible case, for example once with the condition true and once with it false.
clause log
Z3's record of the clauses it learned while solving, one of the two kinds of proof evidence the exporter reads.
conjunction
An and of formulas. It is true when every part is true.
disjunction
An or of formulas, called disjuncts. It is true when at least one disjunct is true.
double negation
A formula negated twice, (not (not p)), which in classical logic is equivalent to p.
flattening
Rewriting nested operators of the same kind into one wide operator, for example (or (or a b) c) into (or a b c).
grind
A Lean tactic that searches for a proof automatically, using case splits, equalities, and arithmetic.
heartbeat
Lean's unit for counting work. A proof that exceeds the heartbeat limit fails with a timeout.
if-then-else term (ite)
A term (ite c a b) whose value is a when condition c is true and b otherwise.
iff
"If and only if": two formulas that are both true or both false. SMT-LIB writes it as = between Booleans.
kernel
The small core of Lean that checks every proof term. Only the kernel has to be trusted.
lemma
A helper theorem proved on its own and then used inside a larger proof.
linear form
A sum of constant multiples of variables plus a constant, such as 1*y - 1*x + 0.
normalization
Rewriting a formula or term into one standard shape, so that equal things look the same.
QF_LRA
The SMT-LIB logic of quantifier-free linear real arithmetic.
refutation
A proof that a set of assertions implies False.
rewrite step
A proof step saying that a formula is equivalent to the simplified formula Z3's rewriter produced from it.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that builds part of a proof, such as grind or split.
trust boundary
The line between what must be trusted, here the Lean kernel and the input, and what is checked.
xor
Exclusive or: true when exactly one of its two arguments is true.
