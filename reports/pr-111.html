State euf lemma facts only for nodes outside their folded ites

Pull request levnach/z3 #111 · state MERGED · loop iteration 110

Merged on 2026-11-10T23:46:28Z as commit a9ae1d3, on top of base 5aa5f9f.

In one paragraph

Each euf lemma in a Lean certificate is now written with fewer hypotheses. When such a theory lemma keeps its if-then-else terms folded, it now states facts only about the terms it reaches outside those ites. Facts about terms hidden inside a folded ite cannot help the tactic. They were dead text that Lean still had to elaborate. The theorem statements and tactics do not change. Only hypotheses that Lean proves by itself are dropped, so the trust boundary stays where it was. On the largest benchmark measured, the euf lemmas shrink to about 40 percent of their old size. This makes large refutations over arrays and uninterpreted functions cheaper to certify.

Background

Since PRs #108 and #109, grind proves an euf lemma by congruence while treating each ite as an opaque leaf. PR #110 then trimmed the facts of each array lemma to the part outside its ites. It listed euf lemmas as the follow-up. Before this PR, euf lemmas still stated facts about every term they reach, inside the ites too. Those facts include each store body, the excluded middle of Boolean arguments, cast facts, and distinct facts. The work serves milestone 3 of the project plan, equality reasoning, and milestone 4, arrays as a broader theory. Its target benchmark is z3test's QF_AUFLIA file cvc/dlx-regfile.

What changed

  • An euf lemma whose ites stay folded now states facts only for terms reachable outside those ites, as array lemmas already did.
  • The excluded-middle facts for Boolean arguments now use the same narrowed set of terms.
  • Lemmas without folded ites see no change, because for them the narrowed set equals the full set.
  • A test now checks that no euf lemma states a store body or Boolean fact for a term hidden inside an ite, and that the lemmas stay small.
  • The README and the project plan record the change and its measured effect.

Think of a folded ite as a sealed envelope. The tactic never opens it, so notes about its contents are useless. All code changes are in the Lean reconstructor, proof_to_lean.py. No C++ changed.

Worked example

This PR newly certifies no input. It only removes unneeded hypotheses. The authors reconstructed 542 test inputs with the old and the new code. There was no new rejection, and 11 inputs produced different Lean text. So the example below shows a smaller output, not a new acceptance. It is the enumeration test predicate_and_ite. Both versions were run again for this page.

(a) The input

(declare-fun P (Color) Bool)
(declare-const c Color)
(declare-const p Bool)
(assert (P red))
(assert (P green))
(assert (P blue))

Review

The reviewer approved the change. There were no blocker or major findings.

  • Minor: the store-identity alternative. The reviewer traced a rarely used second proof attempt. That attempt opens all ites, but it now gets only the narrowed facts. So a store reached only through an ite could lose its rewrite there, and a proof could fail. The reviewer then scanned 1,018 euf lemmas over ites in all test inputs. None used this alternative. The authors kept the code and added a comment that explains the gap and how to fix it if needed. It matters little because the worst case is a Lean rejection, never a false acceptance.
  • Nit: a missing space. A code line read congruence =prefix. It was fixed.
  • Nit: a size bound in the test. The test requires the euf lemmas to stay under 550,000 characters. A future change in Z3's proof search could trip it without any real regression. The bound was kept because it has 18 percent headroom and guards against the size problem this PR fixes.

Risks and open questions

  • The change affects completeness, not soundness. Removing hypotheses can only make Lean reject more, never accept more.
  • If some euf lemma did need a fact about a term inside a folded ite, its certificate would be rejected. The full suite shows no such case.
  • The GitHub CI result on master after the merge is not known to this report.

What comes next

  • dlx-regfile still fails on one cnf lemma, th_lemma_1612. That is the rewriter-bridge item in the backlog.
  • Datatype lemmas could also keep their ites folded, using the same mechanism.

Glossary

array
An SMT-LIB value that maps indices to elements. You read it with select and update it with store.
array lemma
A theory lemma from Z3's array solver. Each one is a single instance of an array axiom.
Boolean
The sort with exactly two values, true and false. In SMT-LIB it is Bool.
cast
A conversion between sorts, such as to_real from Int to Real.
certificate
A file of proof evidence that an independent checker can verify without trusting the solver.
clause
A disjunction of literals, such as a or not b or c. A theory lemma is a clause.
completeness
The ability of a checker to accept every correct proof. A loss of completeness means some correct proofs get rejected.
congruence
The rule that equal arguments give equal results. If a = b, then f(a) = f(b).
distinct
An SMT-LIB predicate saying that its arguments are pairwise different, such as (distinct a b c).
enumeration
A datatype with a fixed list of constant constructors, such as Color with red, green, and blue. Every value is one of them.
euf lemma
A theory lemma from equality with uninterpreted functions. It follows from equalities and congruence alone.
excluded middle
The fact that a statement is either true or false. For a Boolean p, p or not p.
folded term
A term kept behind its Lean definition name instead of being unfolded into its body. The tactic treats it as an opaque leaf.
grind
A Lean tactic that combines congruence closure, case splits, and arithmetic to close a goal automatically.
hypothesis
A fact available inside a proof. In the generated Lean, each have line adds one.
if-then-else term
A term that picks one of two values by a Boolean condition, written (ite p a b) in SMT-LIB. It equals a when p holds, else b.
literal
An atom or its negation, such as P red or not (P red).
refutation
A proof that a set of assertions leads to False, so they cannot all hold.
soundness
The guarantee that a checker never accepts a wrong proof.
sort
The type of a value, such as Int, Bool, or a declared sort like Color.
store
An array update. (store a i v) is the array a with index i changed to v.
tactic
A Lean command that builds part of a proof, such as unfold or grind.
theorem statement
The claim a Lean theorem proves, written after its name and before :=.
theory lemma
A clause that is valid in a background theory, such as equality or arrays. Z3 records it as a th-lemma step.
trust boundary
The line between what Lean checks itself and what must be taken on trust. A change that only drops facts Lean proves itself does not move it.
uninterpreted function
A function with a name and a signature but no fixed meaning. Only congruence constrains it. P in the example is one.
