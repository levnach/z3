Skip assumption-search conjuncts a model already refutes

Pull request #120 on levnach/z3, targeting master · State: OPEN · Date: 2026-11-11T15:49:05Z · Loop iteration 119

This pull request is open and not merged. The change under review is commit 610d490a6.

In one paragraph

The replay of the clause log must tie every assumed clause back to an assertion. It asks one bounded implication question per conjunct. This PR reuses the answers. When a check returns a model that makes a conjunct true and the clause false, that conjunct is refuted, and so is every conjunct nested inside it through conjunctions. The search then skips all of them. Only checks that could never succeed are dropped, so the chosen source and the certificate stay byte-for-byte the same. Lean still proves every cnf lemma itself, so nothing new is trusted. The gain is speed: on one large QF_IDL benchmark, export time dropped from 259 s to 141 s.

Background

Before this PR, the search for an assumed clause's source checked every candidate conjunct that shares a symbol with the clause, one at a time. When no single conjunct implied the clause, it tried them all and only then fell back to an unsat core. On the QF_IDL benchmark qlock-4-10-8, with about a thousand nested conjunctions, one clause took up to 680 checks. The replay took 259 s, over the 120 s limit of the project's regression scan. The work serves Milestone 3, equality and linear arithmetic, and the regression matrix that the plan names as its top priority.

What changed

  • The assumption search now remembers every conjunct a model has refuted and skips its implication check.
  • A model from a failed equivalence check now counts as a refutation too, when it makes the clause false.
  • An undecided result, unknown, refutes nothing, so a check that hits the resource limit cannot hide a good source.
  • A new test builds a chain of 300 conjuncts and pins all five behaviours, including the two the reviewer asked for.
  • The plan document and the examples README each describe the new skip in a short paragraph.

An analogy helps here. A model is like a photo of a whole group of conditions holding while the clause fails. Every condition inside the group is in that photo, so none of them can force the clause.

Review

The reviewer approved. There were no blocker and no major findings.

  1. Minor: the equivalence refutation was untested. The reviewer deleted the three lines that refute after a failed equivalence check, and all 120 tests still passed. This mattered because on qlock only that leaf's model can refute it. Fixed: a new case forces those checks to unknown and asserts the leaf is skipped.
  2. Minor: unknown was untested. Refuting on any result except unsat kept every test green, yet could change the certificate. Fixed: a new case shows a leaf below undecided conjunctions is still checked and chosen.
  3. Nit: dead code. The old _valid helper had no caller left. Fixed: it was removed.
  4. Nit: ragged text. Two reflowed paragraphs had short lines. Fixed: both were reflowed.

Risks and open questions

  • Soundness is unchanged. A conjunct is skipped only when a real model shows it cannot imply the clause.
  • The speedup is modest, about 1.8 times. Most remaining checks hit the resource limit and return unknown.
  • Checking equivalence candidates first took the export to 28 s, but it changed sources and broke a Lean proof. It was dropped.
  • qlock-4-10-8 still fails in Lean. One theory lemma times out in its tactic, and the 38 MB proof exceeds the 8 GB memory cap.

What comes next

  • Stop omega heartbeat timeouts from escaping first. qlock-4-10-8 is now a real reproducer.
  • Reduce Lean memory: on one benchmark, definitions alone take about 2.1 GB.
  • Revisit the faster search order once the prover no longer depends on which source is chosen.

Glossary

assertion
A formula the input states as true, written (assert ...) in SMT-LIB.
certificate
The proof Z3 exports as JSON, which the reconstructor turns into a Lean file.
clause
An "or" of literals, such as x > 3 or y < 1.
clause log
Z3's record of the clauses it assumed and derived while solving.
cnf lemma
A proof step saying that some assertions imply a clause, which Lean proves by itself.
conjunct
One part of an "and". In (and A B), both A and B are conjuncts.
conjunction
An "and" of formulas. Nested conjunctions are "and" inside "and".
equivalence
Two formulas that are true in exactly the same cases.
implication
A implies B when every case that makes A true also makes B true.
literal
An atom or its negation, such as r or (not r).
logic (SMT-LIB)
A named input fragment. QF_IDL means integer difference logic without quantifiers. QF_LIA means linear integer arithmetic without quantifiers.
model
A concrete assignment of values that makes a formula true, such as x = 4, y = 0.
mutation test
Breaking the code on purpose to see whether some test fails. A test that still passes misses that bug.
refutation
Evidence that a claim is false. Here, a model showing a conjunct cannot imply the clause.
replay
Rebuilding a proof step by step from the clause log, checking where each clause comes from.
resource limit
A cap on the work a single solver check may do. When it is reached, the answer is unknown.
resolution
Combining a clause with facts that rule out some of its literals, leaving the rest. From A or B and not A we get B.
tactic
A Lean command that searches for a proof, such as omega for integer arithmetic or grind.
theory lemma
A clause that holds because of arithmetic or another theory, not just Boolean logic. For example, x < 1 or x >= 1.
unknown
A solver answer meaning it gave up, often at the resource limit. It proves nothing either way.
unsat core
A subset of the assertions that is already contradictory on its own.
