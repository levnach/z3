Skip assumption-search conjuncts a model already refutes

Pull request #120 in levnach/z3 · State: MERGED · Merged 2026-11-11T16:04:06Z · Merge commit e40f7f2 · Loop iteration 119

In one paragraph

When the clause log is replayed, every assumed clause must be tied to an assertion of the input. The replay searches the conjuncts of the assertions. It runs one bounded solver check per candidate, for equivalence and then for implication. This PR reuses the model that a failed check returns. If a model makes a conjunct true and the clause false, that conjunct cannot imply the clause. Neither can any conjunct nested below it, so all of them are now skipped. The checks keep their order, so the cnf lemma Lean checks is unchanged. On the QF_IDL benchmark qlock-4-10-8 the export dropped from 259 s to 141 s, with an identical certificate.

Background

Before this PR the search was correct but slow on deeply nested assertions. On qlock-4-10-8, one assertion holds about a thousand nested conjunctions. One clause took up to 680 checks. Ten clauses had no single implying conjunct. They fell back to an unsat core only after every candidate was checked. The replay took 259 s, beyond the 120 s replay limit of an earlier scan. This work serves milestone 3, equality and linear arithmetic, and the regression methodology that gates it.

What changed

  • The replay now skips any candidate conjunct that a model has already shown is consistent with the clause's negation.
  • Such a model can come from a failed implication check or from a failed equivalence check whose model makes the clause false.
  • An undecided check, one that returns unknown under the resource limit, rules out nothing.
  • A new test on a 300-conjunct chain pins the skip, including both cases the reviewer asked for.
  • The README and the plan document now describe the skip.

Think of a detective whose suspects are grouped. One alibi now clears a whole group at once. The interviews keep their order, so the same culprit is found.

Only the Python replay changed. No C++ or Lean file changed.

Worked example

This PR makes no new input certifiable. It only removes checks that could not succeed. So the example shows one input accepted by both versions, with fewer checks after the change. A ten-line file cannot reproduce the time-limit rejection seen on qlock-4-10-8. The input follows the shape of the new test.

(a) The input

(set-logic QF_LIA)
(declare-const x Int)
(declare-const y Int)
(declare-const r Bool)
(assert (and (> y 2) (and (or (> x 3) (< y 1) r) (and (or (< x 0) (> y x)) (< y 4)))))
(assert (not r))
(check-sat)

Here r is a Boolean constant. The clause with the two literals x > 3 and y < 1 follows from the second conjunct only together with (not r), so the search must fall back to an unsat core.

Review

The reviewer approved with no blocker and no major finding. There were two minor findings and two nits.

  1. Minor: the equivalence refutation was untested. The reviewer deleted the lines that skip conjuncts after a failed equivalence check, and all tests still passed. This mattered because on qlock the larger checks often return unknown, and only this path can skip a leaf. A new case forces those checks to unknown, and the deletion now fails it.
  2. Minor: unknown results were not pinned. The reviewer let an unknown check skip conjuncts too, and nothing failed. That bug could skip the conjunct that really implies the clause and change the certificate. A new case checks that a leaf below undecided conjunctions is still checked and chosen.
  3. Nit: a leftover helper. The old function _valid had no caller left and was removed.
  4. Nit: ragged text. Two doc paragraphs had uneven lines and were reflowed.

Risks and open questions

  • Soundness is unchanged. The replay only picks where a lemma starts, and Lean still checks every lemma.
  • The gain is modest. Most remaining checks on qlock-4-10-8 hit the resource limit and cannot be skipped this way.
  • qlock-4-10-8 still fails in Lean. One theory lemma times out in a tactic, and the proof exceeds the 8 GB memory cap.

What comes next

  • Checking equivalence candidates first cut the export to 28 s. It changed the chosen sources and broke one Lean check, so it waits until the prover tolerates other sources.
  • The omega timeout now has a real reproducer in qlock-4-10-8.
  • Another benchmark spends about 2.1 GB on definitions alone, so cutting proof steps will not make it fit.

Glossary

assertion
A formula the input states as true, written (assert ...) in SMT-LIB.
Boolean
The sort with the two values true and false, written Bool.
clause
A disjunction of literals, for example x > 3 or y < 1.
clause log
A record of the clauses the solver assumed and derived, replayed afterwards to build a proof.
cnf lemma
A lemma stating that a clause follows from the formulas it came from when they were turned into clauses.
conjunct
One part of a conjunction. In (and A B), both A and B are conjuncts.
conjunction
A formula that is true only when all its parts are true, written and.
equivalence
Two formulas are equivalent when they are true in exactly the same models.
implication
A implies B when every model that makes A true also makes B true.
literal
An atomic formula or its negation, such as r or (not r).
model
An assignment of values to the symbols that makes a formula true, for example x = 0, y = 3.
negation
The formula that is true exactly when the original is false, written not.
refutation
A proof that a set of formulas leads to False. A model refutes a claim of implication by being a counterexample.
resource limit
A cap on how much work one solver check may do before it gives up.
soundness
The property that a checker never accepts a false claim.
tactic
A Lean command that builds part of a proof automatically, such as omega for integer arithmetic or grind.
theory lemma
A clause that holds by the rules of a theory such as arithmetic, for example x < 0 or x >= 0.
unknown
A solver result meaning the check gave up, often at the resource limit, without deciding.
unsat core
A subset of the assertions that is already contradictory on its own.
