Certify arrays over Bool indices in Lean via the clause log

Pull request levnach/z3#75 into master · State: MERGED · Date: 2026-11-06T04:06:09Z · Loop iteration 76

Merged into master on 2026-11-06T04:06:09Z as commit ffcd21f.

In one paragraph

Z3 can now certify refutations of inputs that use arrays whose index sort is Bool, written (Array Bool E), and Lean checks them. Before this PR, the exporter and the reconstructor both rejected such inputs outright. In Lean, each index becomes a proposition, so an array over Bool is a function from Prop to its element sort. Two smaller gaps had to close along the way. Reads through a store at true or false now follow Z3's rewriter. Unit resolution now accepts a literal under a double negation, the way Z3's SAT solver treats it. This unblocks one more z3test regression file and adds no new axiom.

Background

Earlier iterations taught the pipeline arrays whose index sort is an uninterpreted sort, Int, or Real. They also covered Bool as the element sort, which gives sets, and maps over sets. Bool as the index sort was still refused with an "unsupported sort" error. That gap blocked z3test regressions/smt2/5798.smt2 and had been on the backlog since iteration 73. The work serves milestone 4 of the plan, "Broader theories and integration", where arrays are one of the listed theory extensions.

What changed

  • You can now export a certificate for an input that declares (Array Bool E), for any supported element sort.
  • The reconstructor now turns such an array into a Lean function over Prop, and the extensionality witness becomes a formula.
  • A read at true past a store at false now gets the fact Lean needs, because the two are treated as different values, like two different numerals.
  • A unit-resolution step that drops a double negation, turning (not (not p)) into p, is now proved in Lean by contradiction instead of rejected.
  • Twelve Bool-index inputs are now checked in Lean on every test run, and three tampered certificates are shown to be rejected.

Think of an array over Bool as a light switch with two labelled positions. Lean does not see "on" and "off" as values. It sees statements that are either true or false, and two statements count as the same index when they are equivalent.

Worked example

This input is the test bool_index_negated_stores from the PR. It exercises both the new array sort and the new double-negation step. All output below comes from real runs of the old and new scripts.

(a) The input

(declare-fun a () (Array Bool Int))
(declare-fun b () (Array Bool Int))
(declare-fun p () Bool)
(assert (= (store a p 0) (store b (not p) 0)))
(assert (not (= (select a (not p)) (select b p))))
(check-sat)

Both stores write 0, one at p and one at (not p). The two indices always differ, so a at (not p) must equal b at p. The second assertion denies this, so the input is unsatisfiable.

(b) Before this PR

proof_certificate.py: error: unsupported sort: Array(Bool, Int) (only arrays over uninterpreted sorts, Int, and Real, with Bool elements too)

The old exporter stopped at the array sort. Fed the new certificate, the old reconstructor also refused it:

proof_to_lean.py: error: unsupported array sort: (Array Bool Int)

With only the new double-negation step switched off, the reviewer saw this input fail with "incorrect unit-resolution conclusion at node 40".

(c) After this PR

The new scripts produced a 285-line Lean file, and scripts/check_lean.sh reported "Lean checks passed." Excerpts follow.

Risks and open questions

  • The unit-resolution change affects every proof path, including the legacy one. It only accepts more, in one narrow shape. Lean still checks each proof, and a tamper test confirms that a wrong conclusion is rejected.
  • grind must connect Bool equalities, rendered as Iff, to equalities of propositions inside the store facts. It worked on every input tried, but all of them were small.
  • Other rules that compare the literals of a clause exactly may hit the same double-negation shape, for example with Bool arguments to uninterpreted functions. No failing input has been seen yet.

What comes next

  • Constant arrays and default over Bool indices, which are still rejected, as are arrays of arrays. These need a model of how the array solver handles a finite index sort.
  • A small fuzz run over Bool-argument inputs with nested not, as the reviewer suggested.
  • Other z3test files with Bool-indexed arrays are still blocked by unrelated features, such as nested arrays, maximize, and :opt.priority.

Glossary

array
A value that maps each index to an element, like a table with one row per index. Its sort is written (Array I E).
axiom
A statement accepted without proof. A trustworthy certificate adds none of its own.
Boolean (Bool)
The sort with exactly two values, true and false.
clause
A disjunction of literals, true when at least one literal is true. Example: (or p (not q)).
constant array
An array with the same element at every index, written ((as const (Array I E)) v).
congruence
The rule that applying the same function to equal arguments gives equal results. If a = b, then (h a) = (h b).
double negation
A formula negated twice, (not (not p)). In classical logic it is equivalent to p.
element sort
The sort of the values stored in an array. In (Array Bool Int) it is Int.
extensionality
The rule that two arrays are equal if they agree at every index.
gate clause
A clause that links a compound formula, such as an equality, to its parts, so the SAT solver can reason about it.
index sort
The sort of the positions of an array. In (Array Bool Int) it is Bool.
lemma
A small proved fact used as a step inside a larger proof.
literal
A Boolean atom or its negation, such as p or (not p).
map
An operator that applies a function at every index of one or more arrays, such as ((_ map and) a b).
proposition
A statement that is true or false. Lean's type of propositions is Prop. Two equivalent propositions are equal, a principle called propositional extensionality.
refutation
A proof that a set of assertions leads to a contradiction, so they cannot all hold.
rewriter
The part of Z3 that simplifies terms before solving. Example: a read at 3 skips a store at 2.
SAT solver
The engine that searches for an assignment of true and false to literals that makes every clause true.
select
Reading an array at an index, written (select a i).
set
An array with Bool elements. The element at an index says whether that index is a member.
sort
The type of a value, such as Int, Real, Bool, or an array sort.
store
Writing an element at one index, written (store a i v). It gives a new array that differs from a only at i.
tactic
A Lean command that builds part of a proof automatically. grind and omega are tactics.
uninterpreted function
A function symbol with no fixed meaning. Only congruence is known: equal arguments give equal results.
uninterpreted sort
A sort declared with declare-sort, whose values have no fixed meaning.
unit resolution
A proof rule that takes a clause and some literals known to be false, removes those, and concludes what is left.
value
A fixed constant such as 3, true, or false. Two different values are always distinct.
witness
A specific object that shows a claim holds. The extensionality witness is an index where two unequal arrays differ.
