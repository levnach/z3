State floor values as Int equations for floors under applications

MERGED Pull request levnach/z3#128, merged into master.

Merge commit: 1bfec896f · Merged: 2026-11-13T00:22:16Z · Loop iteration 127

In one paragraph

This PR lets the Lean reconstructor handle a floor, written to_int, inside an application. When a floor is the argument of an uninterpreted function, a predicate, or an array read, Z3's rewriter often computes it. For example, (f (to_int 0.5)) becomes (f 0). Lean must then accept that both applications are equal, a congruence step. The old certificate stated the floor's value only after a cast into the rationals, which Lean's grind tactic could not use. The new certificate states it as an equation between terms of sort Int. In one random family of such inputs, about three quarters of the refutations failed in Lean before, and all pass now. No axiom is added, so the trust boundary does not move.

Background

Before this PR the pipeline already certified to_int and is_int inside linear arithmetic. It stated bounds for each floor, and its value only as a rational. That served arithmetic but not congruence. So rewrite steps that simplified a floor under an application failed in Lean on the clause log. The legacy proof object failed only on is_int of a constant. The lone assertion (assert (is_int 0.5)) was rejected by the fragment check. The work serves milestone 3, “Equality and linear arithmetic”.

What changed

Lean reconstructor

  • A floor under an uninterpreted function, a predicate, or an array read now verifies, because its value is stated between Int terms.
  • A floored integer expression plus any constant, such as x + 0.5, now gets a value through the new lemma _floor_value.
  • The floor of a constant is replaced by its value, which removes a timeout on one kind of input.
  • The input (assert (is_int 0.5)) is now accepted, because is_int counts as Int arithmetic.
  • A step whose goal is already closed by simplifying casts no longer stops with “No goals”.

Tests and documentation

  • New documented inputs, pinned random seeds, and text checks cover both proof sources.

Think of f as a lock whose key is the integer itself. The old certificate only matched photocopies of two keys, the rational copies.

private theorem _floor_value (a : Rat) (k : Int) (_lower : (k : Rat) <= a) (_upper : a < (k : Rat) + 1) :
    Rat.floor a = k :=
  Int.le_antisymm
    (Int.lt_add_one_iff.mp (Rat.floor_lt_iff.mpr (by push_cast; exact _upper)))
    (Rat.le_floor_iff.mpr _lower)

The new lemma: a rational between an integer k and k + 1 has floor k.

Review

The reviewer approved the change, with no blocker and no major finding. All fixes were made before the merge.

Minor findings

  • The reviewer read an array through two stores, with index (to_int 2.5) in one. Lean still rejected it, as before the PR. The plan had claimed that such floors verify. The claim was narrowed, and the array repair is a follow-up.
  • The reviewer tried new seeds. Seed 685 still fails on the clause log, as before the PR. The documents said “all verify”, true only for the earlier seeds. The plan now names this seed.

Nits

  • A dated note in the plan separated an older note from its paragraph. It was moved.
  • One generated tactic read all_goals all_goals. The harmless duplicate is gone.
  • One test compared a length with itself. It now checks the generated facts.

Suggestion

  • The reviewer proposed replacing constant floors after all other facts, so no later fact mentions a vanished floor. Nobody could build an input where the order matters. The reorder was taken and changed no certificate text.

Risks and open questions

  • No soundness risk was identified. Lean's kernel checks every new fact.
  • Every proof step with cast facts has new text, so grind could behave differently on untested inputs.
  • The replacement of a constant floor runs under try, so an unexpected failure there would stay silent.
  • GitHub CI had not reported on the merge commit when this report was written.

What comes next

The PR lists these follow-ups. The first two still fail in Lean.

  • Reads past a store at the floor of a constant, under another store.
  • Argument equalities when two terms floor the same constant, as in seed 685.
  • The absolute value of a Real constant under an application, which fails the same way.
  • Wider random sweeps, such as sets indexed by floors.

Glossary

application
A function or predicate applied to arguments, such as (f 0).
array
A map from indices to values. select reads one index, and store writes one index.
assertion
A formula that the input states to be true, written (assert ...).
axiom
A statement accepted without proof.
Boolean
The sort with the two values true and false.
cast
A conversion of a value from one sort to another. Example: to_real turns the Int 2 into the Real 2.0.
certificate
A record of a proof that a separate checker can replay.
clause
A disjunction of literals, such as “p or not q”.
clause log
One of the two proof sources: the list of clauses the solver derived, in order.
congruence
Equal arguments give equal results. Example: from a = b conclude f(a) = f(b).
constant
Here, a fixed number such as 0.5 or −2, also called a numeral.
exporter
The script that saves Z3's proof as a certificate file.
floor
The largest integer not above a number, written to_int in SMT-LIB. The floor of 0.5 is 0, and the floor of −0.5 is −1.
fragment
The part of the logic an input uses. Example: QF_UFLIRA has no quantifiers, and has uninterpreted functions with linear Int and Real arithmetic.
goal
The statement that a Lean proof still has to prove at a given moment.
interpretation
A choice of meaning for every uninterpreted symbol and variable.
is_int
The SMT-LIB predicate that holds when a Real number is a whole number, that is, equal to its floor.
kernel
The small core of Lean that checks every proof. It is the part one has to trust.
legacy proof object
The other proof source: the proof term built by Z3's older solver core.
lemma
A small proved statement used as a step in a larger proof.
linear arithmetic
Arithmetic with sums and multiplication by constants only, such as 2x + y ≤ 3.
literal
An atomic formula or its negation, such as p or “not p”.
predicate
A function whose result is Boolean.
reconstructor
The script that turns a certificate into a Lean proof file.
refutation
A proof that the assertions lead to a contradiction.
regression
Something that worked before a change and fails after it.
rewriter
The part of the solver that simplifies terms. Example: it evaluates (to_int 0.5) to 0. A rewrite step is one such simplification recorded in the proof.
seed
A number that fixes the choices of a random generator, so the same input can be produced again.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that builds part of a proof. grind and omega are automatic ones.
term
An expression that denotes a value, such as (+ x 1).
theorem
A named statement together with its proof.
trust boundary
The line between what is checked and what is simply believed.
uninterpreted function
A function symbol with no fixed meaning. Only congruence is known about it.
