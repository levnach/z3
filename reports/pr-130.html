Certify subset over sets in Lean certificates

Pull request #130 State: MERGED Date: 2026-11-13T05:58:18Z Loop iteration 129

Merged into master on 2026-11-13T05:58:18Z as commit 1192f9bcf.

In one paragraph

An input may now say that one set is a subset of another, written (subset a b). Before, the pipeline refused every such input at the first stage. Now the certificate carries the subset, and the Lean theorem states it as a hypothesis in its plain meaning. Z3's rewriter replaces the subset by an equality between sets, and only that equality reaches the clause log. A new lemma, checked by the Lean kernel, proves the two forms equal. No axiom was added and no check was removed. Of 1105 random unsat inputs with a subset, 1104 now yield a refutation that Lean accepts.

Background

The pipeline already certified sets, which are arrays with Boolean elements. It read union, intersection, set difference, and complement through the clause log. Subset was the last of Z3's set operators it rejected, and it sat in the backlog since iteration 120. The work serves milestone 4 of the plan, "Broader theories and integration", which lists arrays. This PR covers sets whose index sort is Int or Real. Sets over an uninterpreted sort or over Bool are covered only in part.

What changed

  • Exporter. You can now export a certificate for an input that compares two sets of one sort with subset.
  • Clause-log replay. The replay now reads a subset that Z3 logs as written, and accepts the array solver's theory lemma about it.
  • Reconstructor, statement. The Lean theorem now states the subset as "every member of the first set is in the second", and the lemma _subset_eq ties that to the rewriter's equality.
  • Reconstructor, helper facts. Each proof step that reaches a subset now gets small facts, chosen by a truth table and proved in Lean.
  • Tests and docs. A new test module pins accepted inputs, rejected inputs, and random seeds, and the docs list the known limits.

An analogy: the theorem keeps a contract's original wording, and a proven lemma shows Z3's translation says the same.

Review

The reviewer approved the change with no blockers and no major findings. Every tampered certificate the reviewer built was rejected. All six findings were fixed in the PR's second commit. The minor ones mattered because Lean rejected a correct certificate. None let a wrong one through.

  1. Minor. The reviewer ran fresh random seeds, and two failed in Lean. In both, the subset fails at an index written by a store, yet the rewriter keeps its equality. The code stated only one of two needed facts. Now it states both, and both seeds are pinned.
  2. Minor. A third seed put the full set below a one-element set. The rewriter answers false, but Lean got no fact naming a counterexample. The fix picks an index different from every stored one.
  3. Minor. The reviewer compared constant arrays holding p and (not p), and Lean failed. The fix states the subset as the implication between the two values.
  4. Minor. Over an uninterpreted index sort, a subset decided false failed in Lean. The proof needs one element of the sort, and nothing supplied it. The fix uses an element the certificate already names.
  5. Nit. One test matched exact node numbers, so a harmless reordering would break it. It now matches by pattern.
  6. Nit. Sets indexed by a bit-vector or an enumeration got a rejection message that blamed the subset. They now report "unsupported sort".

Risks and open questions

  • A known Lean failure. The input (subset (store empty 0 p) empty) with a Boolean p is exported and then fails in Lean. It is documented but not pinned by a test.
  • Seed 1089. A rewrite between two set equalities still fails, as at the base commit.
  • Other index sorts. Over an uninterpreted or Bool index sort, a subset verifies only when the rewriter decides it outright.
  • Facts chosen by tables. A wrongly computed table yields a failed certificate, never a wrong one.
  • An older faithfulness question. All uninterpreted sorts share one Lean type, so some hypotheses can be stronger than the input. This predates the PR.
  • CI on master. Its result for the merge commit was not known when this page was written.

What comes next

  • Constant arrays over uninterpreted and Bool index sorts.
  • A fact that reads a subset by cases of a Boolean stored value.
  • The rewrite behind seed 1089.
  • The shared-type question, which stays first in the backlog.

Glossary

array
A value that maps every index to an element, like a table with one entry per index. (Array Int Bool) maps integers to Booleans.
assertion
A formula the input requires to be true, written (assert ...) in SMT-LIB.
axiom
A statement accepted without proof. Adding one enlarges what must be trusted.
bit-vector
A fixed-width string of bits, used to model machine integers. (_ BitVec 2) has four values.
Boolean
The sort with the two values true and false.
certificate
A file of evidence for a solver's answer that a separate program can check.
clause
A disjunction of literals, such as p or not q.
clause log
The list of clauses a solver records while it works. Replaying it rebuilds the proof.
constant array
An array with the same element at every index. The empty set is the constant array of false.
enumeration
A sort with a fixed, named list of values, such as red and green.
extensionality
The rule that two functions, or two arrays, are equal when they agree at every argument.
hypothesis
An assumption of a theorem. Here each assertion of the input becomes one.
implication
The formula "if p then q". It is false only when p is true and q is false.
index
The position at which an array is read or written. For a set, the candidate member.
kernel
The small core of a proof assistant that checks every proof step. Only it must be trusted.
lemma
A small proven statement used as a step toward a larger theorem.
literal
An atomic formula or its negation, such as p or not p.
refutation
A proof that a set of assertions leads to False, so they cannot all hold.
rewriter
The part of a solver that replaces a term by a simpler equivalent one. Example: (subset a b) becomes (= (setminus a b) empty).
select
Reading an array at an index. For a set, (select a 1) says 1 is a member.
set
Here, an array with Boolean elements. An index is a member when its element is true.
set difference
The members of one set that are not in another, written (setminus a b).
sort
The type of a value, such as Int, Real, or Bool.
store
An array equal to another except at one index. (store a 1 true) adds 1 to the set a.
subset
A set whose every member is also a member of another set.
tactic
A proof-search command in a proof assistant. grind and omega are tactics. The kernel checks what they produce.
theorem
A statement together with a proof that the kernel has checked.
theory lemma
A clause that is true because of the meaning of a theory, such as arrays or arithmetic.
truth table
A list of a Boolean formula's value for every combination of its inputs.
uninterpreted sort
A sort the input declares without saying what its values are, as in (declare-sort U 0).
