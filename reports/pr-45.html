Fix RecursionError on deeply nested inputs in proof export/reconstruct

In one paragraph

Some benchmarks assert a conjunction nested about a thousand levels deep. On such inputs, the exporter and the reconstructor crashed with a RecursionError instead of producing a certificate or a clean rejection. This PR moves every recursive formula walk on those paths, and the case-split search of the propositional prover, onto an explicit stack. Deeply nested Boolean and QF_LRA inputs can now become refutations that the Lean kernel checks. Output that worked before is byte-identical, and no Lean rule, check or axiom changed.

Background

Before this PR, the pipeline handled wide inputs but not deep ones. The iteration 44 scan of the smtlib sample found three real inputs that hit Python's limit. The QF_IDL file FISCHER6-4-ninc crashed during export. Two QF_LRA tta_startup files crashed during reconstruction, about 1,000 case splits deep. This serves the plan's regression methodology, its top priority, and the Boolean and linear arithmetic slices of milestones 2 and 3.

What changed

  • The clause-log exporter can now list the conjuncts of a thousand-level conjunction and give each subformula its canonical key.
  • The reconstructor can now read and print the Boolean structure of formulas of any depth.
  • The propositional prover can now follow more than 1,000 nested case splits and still emit a proof that Lean checks.
  • A rewrite over a very wide conjunction now reconstructs in about one second instead of about two minutes, because the prover stopped redoing work it had already done.
  • A new test module, test_proof_to_lean_deep.py, covers inputs nested 1,100 levels deep.

An analogy helps here. Recursion is like stacking a plate for every level you go down, and Python's cupboard holds only about 1,000 plates. An explicit stack is a list the program keeps on its own, so the cupboard size no longer matters.

Each formula_k names one subformula, so the 1,100 levels become 1,100 short definitions instead of one giant term.

private theorem rewrite_3306 (_atoms : Nat -> Prop)
    : (formula_3305 _atoms) := by
  refine Iff.intro (fun (_f1 : (formula_3302 _atoms)) => ?_) (fun (_f3304 : False) => ?_)
  · have _f2 : (Not False) := (fun _absurd => _absurd)
    have _f3 := (And.left _f1)
    have _f4 := (And.right _f1)
    have _f5 := (And.left _f4)
    have _f6 := (And.right _f4)
    ...
    have _f2203 := (And.left _f2202)
    have _f2204 := (And.right _f2202)
    have _f2205 : (Not (_atoms 1099)) := (fun _g => _f2204 (_f2203 _g))
    have _f2206 : (Not (_atoms 1098)) := (fun _g => _f2205 (_f2201 _g))
    ...
    have _f3303 : (Not (_atoms 1)) := (fun _g => _f3302 (_f7 _g))
    exact (False.elim (_f3303 (_f5 _f3)))
  · have _f3305 : (Not False) := (fun _absurd => _absurd)
    exact (False.elim (_f3305 _f3304))

This lemma peels the conjunction one level at a time by and-elimination, then walks the implications backward until p1 is false while p0 is true.

theorem unsat (_atoms : Nat -> Prop)
    (_h0 : (formula_3302 _atoms))
    : False :=
  let _step_3303 : (formula_3302 _atoms) :=
    _h0
  let _step_3306 : (formula_3305 _atoms) :=
    (@rewrite_3306 _atoms)
  let _step_3307 : (formula_3304 _atoms) :=
    (Iff.mp _step_3306 _step_3303)
  let _step_3308 : (formula_3304 _atoms) :=
    (False.elim _step_3307)
  _step_3308

The final theorem states that the assertion implies False, using the rewrite lemma above.

A caveat: for a propositional file, the exporter picks the legacy proof object by default. On this input, Lean rejected the legacy output with heartbeat timeouts. So the example uses the clause-log core, like the PR's Lean-checked test.

Review

The reviewer approved the PR with no blocker, major or minor findings.

Nit: a traceback that grew with the input. The reviewer imagined a nonlinear atom at the bottom of a 1,100-level conjunction. The exporter correctly rejects that atom. But the new code re-raised the stored error at every parent level, and each raise added its own frames. The final error carried thousands of frames. The message was right, but anyone debugging would drown in noise. The fix reuses the traceback from the first failure, and a new test checks that it stays short.

Suggestion: extra work after a false conjunct. The new code also keys conjuncts the old code skipped. The fuzz showed no visible difference, so this was accepted as is.

Risks and open questions

  • None of the three real inputs verifies in Lean yet. They now export and reconstruct, but each hits a separate limit.
  • In tta_startup, the grind fallback for one CNF lemma runs out of heartbeats, and other lemmas exhaust kernel memory.
  • FISCHER6-4-ninc spends most of its long export in repeated equivalence checks. That is too slow for CI.
  • Deep legacy certificates only reconstruct. Their rewrite lemma is too wide for the heartbeat limit, as the worked example also showed.
  • The key computation now catches every exception and raises it later. An unrelated bug in a subformula the old code never visited would stay silent.

Glossary

and-elimination
The rule that gets A from A and B. In Lean, And.left and And.right.
Boolean
The sort with exactly two values, true and false. Bool in SMT-LIB.
case split
Proving a goal by trying each possibility in turn, for example first assuming a is true, then that it is false.
certificate
A file that records the solver's proof steps so another tool can check them.
CNF (conjunctive normal form)
A formula written as an and of clauses, where each clause is an or of literals.
conjunct
One of the parts joined by and. In (and a b), both a and b are conjuncts.
conjunction
A formula built with and. It is true only when all its parts are true.
explicit stack
A list the program manages itself to remember pending work, used instead of having a function call itself.
grind
A Lean tactic that searches for a proof automatically. It can run out of time on large goals.
heartbeat
Lean's unit of work. Each proof gets a budget of heartbeats and fails if it uses more.
implication
"If A then B", written (=> A B) in SMT-LIB and A -> B in Lean.
kernel
The small core of Lean that checks every proof. It is the part that must be trusted.
propositional
Using only Boolean variables and connectives such as and, or, not and =>, with no arithmetic or functions.
QF_LRA
The SMT-LIB logic of quantifier-free linear real arithmetic, for example (< x 5.0).
recursion
A function solving a problem by calling itself on a smaller part, such as one nesting level down.
recursion limit (RecursionError)
Python's cap of about 1,000 nested calls. Going deeper raises RecursionError.
refutation
A proof that a set of assertions leads to False, so no assignment satisfies them.
