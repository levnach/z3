Fix RecursionError on deeply nested inputs in proof export/reconstruct

Pull request #45 on levnach/z3 · OPEN · opened 2026-10-30T02:39:27Z · loop iteration 45

This pull request is open and not merged. The change it proposes is commit 81d6c245a, on top of base 1b859b6bc.

In one paragraph

Some real benchmarks nest one conjunction inside another about a thousand levels deep. On such inputs, the exporter and the reconstructor crashed with RecursionError, giving neither a certificate nor a clean rejection. This PR rewrites every affected recursive walk to use an explicit stack. That includes the case-split search that builds propositional refutations. It also removes a cubic slowdown on very wide conjunctions. Output is byte for byte the same on every input that worked before. No Lean rule or check changed, so the trust boundary is unchanged. Deep inputs can now reach the Lean kernel instead of stopping at a Python crash.

Background

Before this PR, the pipeline already handled propositional, QF_UF and QF_LRA inputs through the clause log and the legacy proof object. But its formula walks used recursion, so deep inputs ran into Python's recursion limit. The previous iteration scanned a sample of SMT-LIB benchmarks and found three inputs that hit this limit. One is FISCHER6-4-ninc, a QF_IDL model-checking benchmark that writes (and a (and b ...)) about 1,000 levels deep. The other two are QF_LRA tta_startup inputs whose CNF lemma needed about 1,000 nested case splits. The work serves Milestones 2 and 3 of the plan, the Boolean and linear arithmetic slices.

What changed

  • The clause-log exporter can now list the conjuncts of an assertion nested any number of levels deep.
  • The exporter can now compute canonical keys for deep formulas, and an error in one subformula still surfaces only when a parent actually needs it.
  • The reconstructor can now read, render, and index deep Boolean structure, in both the clause-log core and the legacy core.
  • The propositional prover can now search through more than a thousand nested case splits, and Lean checks the deep proof it emits.
  • A legacy rewrite over a 1,200-operand conjunction now reconstructs in about a second instead of about two minutes.
  • A new test module covers all of this at depth 1,100, and the plan document and README describe it.

Think of the old code as someone going down a staircase who leaves a bookmark on every step. Python hands out only about a thousand bookmarks. The new code keeps a single to-do list instead, which can grow as long as needed.

Review

The reviewer approved the PR. There were no blocker, major, or minor findings.

  • Nit, fixed. The reviewer put a nonlinear atom at the bottom of a 1,100-level conjunction. The exporter correctly rejected it. But every parent formula raised the same stored error again and added its frames to the traceback, which grew past three thousand frames. A printout or a debugging session would drown in that noise. The fix reuses the traceback from the first failure, and a new test checks that it stays short.
  • Suggestion, accepted as is. The new code also computes keys for conjuncts after a false one. The fuzz found no visible difference, and no slowdown was observed.
  • Suggestion, done. The README test list now names the new module.

Risks and open questions

  • None of the three real benchmarks passes Lean yet. In tta_startup, the grind tactic runs out of heartbeats and some lemmas exhaust kernel memory. FISCHER6-4-ninc is too slow to export.
  • The deep legacy test only reconstructs. Its rewrite lemma exceeds the heartbeat limit in Lean, a width problem rather than a nesting problem.
  • The key code now catches every exception and raises it later. A real bug in a subformula the old code never visited could go unnoticed.

What comes next

  • Speed up the equivalence checks that make FISCHER6-4-ninc slow to export.
  • Make tta_startup pass Lean.
  • Split the legacy rewrite's normalizations into separate lemmas.
  • Re-run the SMT-LIB sample scan now that the recursion fixes are in.

Glossary

and-elimination
The proof step that goes from A ∧ B to A or to B. In Lean it is written .1 or .2.
assertion
A formula stated as true in the input with (assert ...).
bound
An atom that limits a variable from one side, such as x < 5.
canonical key
A label given to a formula so that formulas with the same meaning up to simple rewriting get the same label.
case split
Proving a goal by considering each possibility in turn. For a ∨ b, prove the goal once assuming a and once assuming b.
certificate
A file holding the solver's proof evidence for one input, which a separate checker can verify.
clause log
A record of the clauses the solver assumed, derived, and deleted while solving, used here as proof evidence.
CNF (conjunctive normal form)
A formula written as a conjunction of clauses, where each clause is a disjunction of literals. A CNF lemma links a formula to its clauses.
conjunct
One of the parts joined by a conjunction. In (and a b), both a and b are conjuncts.
conjunction
A formula built with "and", written (and a b) in SMT-LIB. It is true when all its parts are true.
explicit stack
A list the program keeps itself to remember work still to do, used instead of nested function calls.
heartbeat
Lean's unit of work. Each proof gets a heartbeat budget and fails if it runs over.
kernel
The small core of Lean that checks every proof step. A proof is trusted only once the kernel accepts it.
QF_LRA
The SMT-LIB logic of quantifier-free linear real arithmetic, such as 2*x + y < 3 over real numbers.
recursion
A function solving a problem by calling itself on a smaller part, such as one level deeper in a formula.
recursion limit
The most nested calls Python allows at once, 1,000 by default. Going past it raises RecursionError.
refutation
A proof that a set of assertions leads to False, so they cannot all hold together.
rewrite
A proof step that replaces a formula with an equivalent one, such as turning x < y into not (y <= x).
tactic
A Lean command that searches for a proof automatically. grind is one such tactic.
theory lemma
A fact that holds because of the theory, here arithmetic, not because of Boolean logic. For example, x <= y or y <= x.
traceback
The list of function calls Python prints when an error happens, showing where it came from.
trust boundary
The set of components that must be correct for a verified result to be believed. Here that is the Lean kernel and the Lean rules, not the Python scripts.
