In one paragraph

Some cnf lemmas could not be proved in Lean before this PR. Z3 states their clause over the rewriter's form of an if-then-else term, while the assertion keeps the original form. So the lemma does not follow from the propositional abstraction alone. Now the reconstructor runs a small lazy SMT loop. Z3 acts as an untrusted oracle and proposes theory clauses over the lemma's leaves. Lean proves each clause with a tactic before the refutation search uses it. As a result, the QF_LRA benchmark tta_startup with 11 nodes now checks in Lean. It had been a known failure since loop iteration 45. The trust boundary is unchanged: no sorry and no new axiom.

Background

Before this PR, a cnf lemma got two propositional searches. The first ran over every gate, the second over Z3's relevant unsat core. If both failed, the lemma fell back to grind over the fully unfolded clause. On the 11-node tta_startup input, that clause unfolds to 227 ites. There grind ran out of heartbeats, and the whole file failed. The existing bridges between pairs of literals did not help. This work serves milestone 3, equality and linear arithmetic, and the regression scans.

What changed

Think of a proofreader who checks a translation word by word. When a word appears in two spellings, the check stalls. Z3 now says "these two spellings mean the same", and Lean checks that note before anyone relies on it.

  • When both propositional searches fail on a cnf lemma, the reconstructor now asks Z3 for theory clauses over the lemma's leaves, and Lean proves each one as a have.
  • With those clauses added, the search retries with ten times its usual step and size limits, but the proof it keeps must still fit the old size bound.
  • The search stops and leaves the old grind fallback alone when a check is undecided, a model survives, 256 clauses are reached, or a clause covers every leaf.
  • The 11-node benchmark is now in the repository, with a slow test that checks it in Lean.
  • Small tests now cover the new search, its stop rules, and the size cap.

The loop is a form of CEGAR. Each round checks one model against the theory solver and turns the unsat core into a blocking clause.

(set-logic QF_LRA)
(declare-fun b0 () Bool)
(declare-fun b1 () Bool)
(declare-fun c () Real)
(declare-fun n () Real)
(declare-fun w () Real)
(assert (and (= n (ite (= c 5) 1 (+ c 1)))
             (= w (ite (and (not b0) (not b1)) 0 0))
             (= c 3)
             (or b0 (not (= w 0)) (= n 5))

(check-sat)

Here w is an ite whose two branches are both 0, so w is 0. The disjunction then forces n = 5, but c = 3 makes n equal 4.

Review

The reviewer approved, with no blocker and no major finding.

  • Minor: timeouts are not caught. The safety story said a bad clause just fails, and the old fallback then runs. The reviewer tested this in a small Lean file. A have that ran out of heartbeats failed the whole lemma, despite a working second branch. So a new clause could break a lemma that grind used to prove. Partly fixed: the kept proof is capped at the old size bound, a test checks the cap, and the docs were corrected. The 208-input sweep found no remaining case.
  • Nit: no total time limit. Each check has a fixed resource limit, with at most 256 rounds. Not changed, because a wall-clock limit would make the output vary between runs.
  • Nit: the stop rules had no direct tests. A refactor could have dropped one silently. Fixed with a test for each rule.
  • Nit: one summary claim was wrong. The implementer flipped a clause to show Lean rejects it, but the flipped clause was still true. Accepted, and the claim was dropped. Soundness does not depend on it, since Lean checks every step.

Risks and open questions

  • One theory-clause have that runs out of heartbeats can still fail a lemma.
  • Python time grows on lemmas where both searches fail.
  • CI tests cover only the simplest kind of theory clause. Other kinds need the slow test.
  • The 15-node tta_startup file still fails, now in a propositional lemma.

What comes next

  • Retry at the larger budget when the abstraction is already unsat, as on two QF_IDL inputs.
  • Minimize each unsat core before shrinking it.
  • Rescan QF_LRA, QF_LIA, and QF_IDL for cnf lemmas that theory clauses may now prove.
  • Add a CI-sized input that needs a clause about an ite's value.

Glossary

atom
A formula with no Boolean connective inside, such as b0 or (= c 3).
axiom
A statement Lean accepts without proof. Adding one would mean trusting something unchecked.
Boolean
The sort of truth values, true and false. In SMT-LIB it is Bool.
CEGAR
Counterexample-guided abstraction refinement. Solve a simpler problem, check its answer, and add a fact that rules out each wrong answer.
clause
A disjunction of literals, such as (or b0 (not (= w 0))).
cnf lemma
A step where Z3 claims that a clause follows from an assertion by conversion to conjunctive normal form.
grind
A general Lean tactic that searches for a proof by case splits and rewriting. It is strong but can be slow.
heartbeat
Lean's unit of work. A proof that uses more than its limit stops with a timeout error.
if-then-else term (ite)
A term that picks one of two values by a condition. (ite (= c 5) 1 (+ c 1)) is 1 when c is 5, else c + 1.
lazy SMT
A solving style where a SAT search treats theory atoms as plain letters, and a theory solver adds clauses when a candidate answer breaks the theory.
leaf
A part of a formula that the propositional abstraction treats as one opaque letter, usually a theory atom.
literal
An atom or its negation, such as b0 or (not b0).
model
An assignment of values that makes a set of formulas true.
oracle
A helper that gives answers without proof. Here Z3 suggests clauses, and Lean checks each one.
propositional abstraction
The formula seen with every theory atom replaced by a letter. (= w 0) and (= w (ite c 0 0)) become two unrelated letters.
refutation
A proof that a set of facts leads to False.
rewriter
The part of Z3 that simplifies terms, for example (+ 0 x) to x and (ite c 0 0) to 0.
sorry
A Lean placeholder that skips a proof. A trusted result must not contain it.
tactic
A Lean command that builds part of a proof, such as grind or omega.
theory clause
A clause that is true because of what its atoms mean in arithmetic, not because of Boolean structure. Example: w = (ite c 0 0) implies w = 0.
theory solver
The part of a solver that decides whether literals about numbers or functions can hold together.
unsat core
A subset of formulas that is already contradictory on its own.
