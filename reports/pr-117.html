Refute cnf lemmas over rewritten ites with z3-found theory clauses

Pull request levnach/z3#117 · state OPEN · opened 2026-11-11T10:07:11Z · loop iteration 116

This pull request is open and not merged. The change is commit 91af1c3, on top of base 8e3f758. The PR has two commits: the feature and the review fixes.

In one paragraph

This PR lets the Lean reconstruction prove a cnf lemma whose clause mentions if-then-else terms in the rewriter's simplified form. Until now, such a lemma was refuted only from its Boolean structure. Every theory atom was an opaque leaf. When that propositional abstraction is satisfiable, the search fails. Now Z3 acts as an untrusted oracle in a lazy SMT loop. It supplies the missing theory clauses, one unsat core at a time. Lean proves each clause with a tactic before the refutation search uses it. As a result, the QF_LRA benchmark tta_startup with 11 nodes now checks in Lean. It had been a known failure since loop iteration 45. The trust boundary is unchanged: no sorry and no new axiom.

Background

Before this PR, a cnf lemma got two propositional searches. The first ran over every gate, the second over Z3's relevant core. If both failed, the lemma fell back to grind over the fully unfolded clause. On the 11-node tta_startup input, that clause unfolds to 227 ites. grind ran out of heartbeats there, so Lean rejected the file. The PR traces the cause to the rewriter. Z3 logs the clause over simplified forms, such as (ite c 0 0) written as 0. So the clause follows from what its leaves mean in linear real arithmetic, not from their Boolean shape alone. This serves milestone 3 of the plan, equality and linear arithmetic. It also serves the regression scans, which the plan names as the top priority.

What changed

Think of two crossword clues that secretly have the same answer. A solver who sees only the grid cannot know this. Z3 now whispers "these two agree", and Lean checks that hint before anyone relies on it.

  • When both propositional searches fail on a cnf lemma, the reconstructor now asks Z3 for theory clauses over the lemma's leaves, and Lean proves each one as a have.
  • With those clauses added, the search retries with ten times its usual step and size limits, but the proof it keeps must still fit the old size bound.
  • The clause search stops, and the old grind fallback stays alone, when Z3 is undecided, finds a genuine model, needs more than 256 clauses, or proposes a clause over every leaf.
  • New tests check two small tta-shaped inputs in Lean with the fallback removed, cover every stop rule and the size cap in pure Python, and verify the full 11-node file in a slow test.
  • The plan document and the examples README now describe the new step, including the heartbeat caveat.

Worked example

(a) The input

This is ite_with_equal_branches, one of the PR's new test inputs, copied verbatim.

(set-logic QF_LRA)
(declare-fun b0 () Bool)
(declare-fun b1 () Bool)
(declare-fun c () Real)
(declare-fun n () Real)
(declare-fun w () Real)
(assert (and (= n (ite (= c 5) 1 (+ c 1)))
             (= w (ite (and (not b0) (not b1)) 0 0))
             (= c 3)
             (or b0 (not (= w 0)) (= n 5))
             (not b0)))
(check-sat)

The assertion says w equals an ite whose two branches are both 0. Z3's clause later speaks of (= w 0) instead.

Review

The reviewer approved, with no blocker and no major finding.

  • Minor: timeouts escape first. The reviewer built a tiny Lean file whose first alternative ran out of heartbeats. Lean failed the whole theorem, even though the second alternative would have worked. So a slow theory-clause have could break a lemma that grind alone used to prove. Partly fixed: the kept proof is now capped at the old size bound, and the docs state the caveat. A single slow have is still not caught, but no input in the sweep hit this.
  • Nit: no overall time budget for the clause loop. The reviewer worried that a big lemma could spend minutes in Python. Not changed: the loop is capped at 256 clauses with a fixed limit per check. The worst case seen was 2.24 s, and a wall-clock deadline would make output nondeterministic.
  • Nit: the stop rules had no direct tests. A refactor could have dropped one silently. Fixed: new pure-Python tests cover each stop rule and the size cap.
  • Nit: a corruption experiment proved less than claimed. The implementer flipped a theory clause, but the flipped clause was still true. Lean rejected the file for a different reason. Accepted: the claim was dropped. Soundness does not rest on it, since Lean proves every have.

Risks and open questions

  • A theory-clause have that exhausts heartbeats would still fail its lemma. The size cap and the every-leaf rule only make this less likely.
  • The small CI inputs need only the (ite c 0 0) kind of clause. The other kinds are covered only by the slow test, which CI skips.
  • The 15-node tta_startup input still fails, now in a different, purely propositional lemma.

What comes next

  • Retry at the larger budget when the clause search returns an empty list. Two QF_IDL inputs reach that case.
  • Minimize each unsat core with Z3 before shrinking it one literal at a time.
  • Rescan QF_LRA, QF_LIA, and QF_IDL for cnf lemmas that theory clauses may now prove.

Glossary

atom
The smallest true-or-false piece of a formula, such as (= c 3) or a Boolean variable b0.
axiom
A statement Lean accepts without proof. The certificates add none of their own.
Boolean
The sort with two values, true and false. Boolean structure means the and/or/not shape of a formula.
clause
A disjunction ("or") of literals. Example: b0 or not (w = 0) or n = 5.
cnf lemma
A step in Z3's proof that turns an assertion into a clause, for conjunctive normal form. It must follow from the assertion.
grind
A general-purpose Lean tactic that combines case splits, congruence, and arithmetic. It is powerful but can be slow on big goals.
heartbeat
Lean's unit of work. When a proof uses more than its heartbeat limit, Lean stops with a timeout error.
if-then-else term (ite)
A term whose value depends on a condition. (ite (= c 5) 1 (+ c 1)) is 1 when c is 5, and c+1 otherwise.
lazy SMT (CEGAR loop)
A loop that solves the Boolean abstraction, checks the answer against the theory, and adds a theory clause to rule out each wrong answer. CEGAR means counterexample-guided abstraction refinement.
leaf
A part of a formula that the propositional search treats as one opaque variable, such as a theory atom.
linear real arithmetic (QF_LRA)
The theory of real numbers with addition and multiplication by constants. QF_LRA is the SMT-LIB logic for it without quantifiers.
literal
An atom or its negation, such as b0 or not (w = 0).
model
An assignment of values to variables that makes a formula true.
oracle (untrusted)
A helper that suggests answers. Nothing it says is believed until Lean proves it.
propositional abstraction
The formula you get by replacing every theory atom with a plain Boolean variable. It keeps the and/or/not shape and forgets the arithmetic.
refutation
A proof that a set of facts leads to False, so the facts cannot all hold.
rewriter
The part of Z3 that simplifies terms, for example (+ 0 x) to x.
satisfiable
Having at least one model.
sorry
A Lean placeholder that skips a proof. A certificate containing it proves nothing.
soundness
The guarantee that the checker never accepts a false claim.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that builds part of a proof automatically, such as grind or omega.
theory clause
A clause that is true because of what its atoms mean in a theory, not because of its Boolean shape. Example: not (w = (ite c 0 0)) or w = 0.
unsat core
A subset of literals that is already contradictory on its own. Its negation is a clause that always holds.
