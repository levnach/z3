Name hypotheses by binders and close resolutions with resolve_right

Pull request levnach/z3#114 · MERGED · loop iteration 113

Merged 2026-11-11T04:47:39Z as commit 43df4dcc0 into master. Base commit: cd47fe51c.

In one paragraph

This PR makes the Lean proof terms that the reconstructor writes for a Z3 refutation shorter, without changing what they prove. It removes two kinds of redundant text. First, a hypothesis is no longer copied into a proof step of its own. Every user now names the hypothesis by its binder directly. Second, a unit resolution that keeps only one literal of a clause no longer opens a case split. It uses a single step of disjunctive syllogism instead. Lean's memory grows with the proof text it must elaborate, and large QF_IDL refutations hit the 8 GB cap. Less text brings more of them within reach.

Background

Before this PR, the pipeline could already certify these refutations in principle. The obstacle was size. The 36.9 MB Lean file for the QF_IDL benchmark DTP_k2_n35_c245_s9 exceeded the 8 GB cap. Of that file, 3.3 MB was hypothesis plumbing, including 527 lemmas that only returned their own binder. Another 5.4 MB was case splits inside unit resolutions. The planning benchmark plan-21 passed, but close to the cap. This work serves milestone 3, "Equality and linear arithmetic", by making large linear arithmetic refutations fit in Lean's memory.

What changed

  • A proof step can now use a hypothesis by its binder name, so the generated Lean no longer wraps each hypothesis in a step and re-applies it.
  • A unit resolution that keeps one literal and eliminates everything after it now closes in one step, with Lean's Or.resolve_right instead of an Or.elim case split.
  • The one exception is kept safe: a hypothesis that is the premise of a lemma still has its own step, because the lemma discharges its binder.
  • Tests now pin nine clause shapes for the new resolution form, plus the lemma-premise exception, each one checked by Lean.
  • The plan document and the README describe the change and its sizes.

An analogy: before, every time a proof wanted to cite "assumption A", it first wrote "let B be assumption A" and then cited B. Now it simply cites A.

Worked example

This PR makes no new input certifiable. It only shrinks the Lean text. So "Before" is not a rejection but the pre-PR output, which Lean also accepted. Both come from real runs at the base and merge commits.

(a) The input

(set-logic QF_LRA)
(declare-const p Bool) (declare-const q Bool)
(declare-const x Real) (declare-const y Real) (declare-const z Real)
(assert (or p q))
(assert (not q))
(assert (or (not p) (< x y) (< y z)))
(assert (or (>= x y) (< z x)))
(assert (or (>= y z) (< z x)))
(assert (<= x z))
(check-sat)

A small mix of Boolean clauses and real inequalities with no model.

(b) Before: the pre-PR output

The old scripts printed Lean checked the refutation. Two spots of the old file:

  let _step_41 : (formula_11 _atoms _vars) :=
    (Or.elim _step_33 (fun _literal => _literal) (fun _tail => (False.elim (_tail _step_39))))
...
  let _step_44 (_hyp4 : (formula_4 _atoms _vars)) : (formula_43 _atoms _vars) :=
    let _step_40 : (formula_4 _atoms _vars) :=
    _hyp4
    (False.elim (_step_18 (_step_17.resolve_left _step_40)))

The first piece splits the clause x >= y ∨ ¬(x <= z) into two cases, though the second is impossible. The second copies the hypothesis ¬p into a new step just to use it once.

(c) After: the Lean the reconstructor now generates

def formula_0 (_atoms : Nat -> Prop) (_vars : Nat -> Rat) : Prop := _atoms 0
...
def formula_11 (_atoms : Nat -> Prop) (_vars : Nat -> Rat) : Prop := ((term_5 _atoms _vars) >= (term_6 _atoms _vars))
...
def formula_30 (_atoms : Nat -> Prop) (_vars : Nat -> Rat) : Prop := (Or (formula_11 _atoms _vars) (formula_29 _atoms _vars))
...

Each sub-formula of the input becomes a Lean definition over the Boolean atoms and the real variables.

theorem unsat (_atoms : Nat -> Prop) (_vars : Nat -> Rat)
    (_h0 : (formula_2 _atoms _vars))
    (_h1 : (formula_3 _atoms _vars))
    (_h2 : (formula_10 _atoms _vars))
    (_h3 : (formula_13 _atoms _vars))
    (_h4 : (formula_15 _atoms _vars))
    (_h5 : (formula_16 _atoms _vars))
    : False :=
...

The theorem statement is unchanged by this PR: the six assertions together imply False.

  let _step_41 : (formula_11 _atoms _vars) :=
    (_step_33.resolve_right (fun _literal => _literal _step_39))
...
  let _step_44 (_hyp4 : (formula_4 _atoms _vars)) : (formula_43 _atoms _vars) :=
    (False.elim (_step_18 (_step_17.resolve_left _hyp4)))
...

The resolution now says "the right side is false, so the left side holds" in one step, and the hypothesis is used directly by its binder _hyp4.

Lean result: ./scripts/check_lean.sh printed Lean checks passed. The file shrank from 9,206 to 8,872 bytes, with one case split and five hypothesis copies removed.

Review

The reviewer approved with no blockers, majors, or minors. They reported two nits and two suggestions.

Nit: stale numbers in a test comment

The slow plan-21 test's comment still said 25 MB and 7.5 GB. Someone tuning the memory cap could trust that stale baseline. It now says 23.4 MB and 7.0 GB.

Nit: awkward wording

The README and two docstrings said a hypothesis "is no step". It now reads "not bound as a step".

Suggestion: pin the one exception

A hypothesis that is a lemma's premise keeps its step, and another step may re-apply it. The reviewer checked this path in a scratch test, but no committed test covered it. The implementer added test_hypothesis_premise_of_a_lemma_used_by_another_step. It matters because the old re-application code still runs only there.

Suggestion: avoid rewriting text afterwards

The change swaps step names for binders with a regular expression. The reviewer suggested resolving names while building each term. This is deferred as a follow-up. It is safe today because every name in a step term is generated, and a wrong reference fails the Lean check.

Risks and open questions

  • Soundness is unchanged. The theorem and lemma statements are the same, and Lean still checks every term.
  • The name rewrite depends on the naming scheme of generated steps. A future change to that scheme could break it, though Lean would reject the result.
  • DTP_k2_n35_c245_s9 and the swap file still exceed the 8 GB cap. plan-21 passes but peaks at 7.0 GB of 8.
  • GitHub CI results after the merge are not recorded here.

What comes next

  • Merge each import of a shared step under hypotheses with its one re-application. That is about 1 MB of DTP.
  • Shrink the chains of hypotheses in the lemma statements. That is 4.66 MB of DTP.
  • Resolve hypothesis references while building the terms, instead of rewriting text afterwards.

Glossary

binder
The name a function gives its input, such as h in fun h => .... Inside the function, the name stands for that input.
Boolean
A value that is either true or false. In SMT-LIB its sort is Bool.
case split
Proving a goal from "A or B" by giving one proof that assumes A and another that assumes B.
clause
A disjunction of literals, such as p ∨ ¬q ∨ r. It is true when at least one literal is true.
disjunctive syllogism
The rule "from A ∨ B and not B, conclude A". Lean calls it Or.resolve_right, and Or.resolve_left for the mirror case.
elaboration
Lean's work of turning written proof text into fully typed terms that its kernel can check. It costs time and memory in proportion to the text.
hypothesis
A fact assumed temporarily inside a proof, to be discharged later. For example, "assume p, derive false, so not p".
lemma
A proved statement used as a step in a larger proof. In Z3's proofs, the lemma rule also discharges hypotheses. The reconstructor also outlines large shared steps as separate Lean lemmas.
linear arithmetic
Constraints that add numbers and multiply them only by constants, such as x + 2y ≤ 5.
literal
An atom or its negation, such as p or ¬p, or an inequality such as x < y.
proof step
One inference in a proof, with premises and a conclusion. The reconstructor writes each one as a Lean let.
proof term
A proof written as a program expression whose type is the statement it proves.
QF_IDL
The SMT-LIB logic of quantifier-free integer difference logic. Its constraints have the form x - y ≤ c.
refutation
A proof that a set of assertions leads to false, so they cannot all hold.
unit resolution
An inference that takes a clause and some single-literal facts that contradict some of its literals, and keeps the remaining literals. From p ∨ q and ¬q it concludes p.
