In one paragraph

This PR lets the pipeline certify inputs that use arrays whose element sort is Boolean. Such arrays are the usual SMT-LIB encoding of sets. In Lean, a set becomes a predicate, so each select on it is a formula. The PR also fixes a gap that affected every element sort. Z3's rewriter sometimes evaluates a read through several stores in one rewrite step. The certificate has no term for the levels in between, so Lean's grind tactic could not prove that step. The reconstructor now adds one small fact per level. Each fact holds by rfl. There is no new axiom and no change to what Lean trusts.

Background

Before this PR, the clause log path already handled arrays over uninterpreted sorts, Int, and Real. It also handled constant arrays and uninterpreted functions into arrays. Arrays of Booleans were rejected twice: once by the exporter and once by the reconstructor. Some reads through store chains were accepted by the exporter but then failed in Lean. This work serves milestone 4 of the plan, "Broader theories and integration", which treats arrays as one of the distinct extensions.

What changed

  • You can now certify inputs over sets of uninterpreted, Int, or Real elements, written (Array I Bool).
  • A read of a store over a constant array now verifies in Lean, for example a read of a singleton set.
  • A read that skips stores at other numerals now verifies, including where the skip lands on a store at the read's own index.
  • Negative numerals and Real fractions such as (/ 1 3) are compared by value, just as Z3 compares them.
  • New tests show that each added fact is needed, because Lean fails once the facts are removed.

Think of a store chain as a stack of sticky notes on a page. Z3 can peel off several notes at once. Lean needs to be told what each note said. The new facts are those notes, one per level.

The PR had three commits before it was squash-merged. The first applied iteration 73's patch for sets and constant arrays. The second added the numeral-skip facts for plain arrays. The third fixed the review findings below.

Worked example

This input is the singleton_set test from the PR. It says that x is a member of the set {y}, yet x differs from y. It uses both new features: a set and a read of a store over a constant array.

Input

(set-logic QF_ALIA)
(declare-fun x () Int)
(declare-fun y () Int)
(assert (select (store ((as const (Array Int Bool)) false) y true) x))
(assert (not (= x y)))
(check-sat)

Review

The reviewer asked for changes but found no blocker. All four findings were fixed in the third commit.

  • Major: the store where a skip stops had no fact. The reviewer tried (select (store (store a 3 5) 2 7) 3), which Z3 rewrites to 5. The rewriter skips the store at 2 and reads the store at 3 in the same step. Only the skipped level had a fact, so grind failed. Such reads are common in array benchmarks. The fix adds a fact for the level where the skip stops, with new Lean-checked tests.
  • Minor: negative numerals were missed. A store at (- 1) was not seen as a numeral, so grind failed on reads skipping it. The fix compares each index by its value. This also covers (/ 1 3).
  • Nit: a stale count. The plan said "fourteen" Bool inputs. It now says "sixteen".
  • Nit: an overlong README line. It was rewrapped.

Risks and open questions

  • The new facts are rfl theorems. An extra fact therefore cannot make Lean accept a false claim.
  • The shape check on array lemmas is looser. It now allows Bool equalities when some array has Bool elements. Lean still proves each clause.
  • A read gets one fact per skipped numeral store. A long chain of numeral stores grows the proof linearly.
  • No z3test input is newly certified. Its Bool-array files also need map, nested arrays, Bool indices, or quantifiers.
  • Other rewriter expansions, such as the expand_select_store option, are not covered. No failing input was seen with default options.

What comes next

The PR names map over arrays as the natural next set feature. Bool index sorts could also be admitted. Arrays of arrays, arrays with several indices, and as-array remain rejected. The legacy proof core still rejects arrays.

Glossary

array
A value that maps each index to an element, like a total function. (Array Int Int) maps integers to integers.
axiom
A statement Lean accepts without proof. Adding one widens what must be trusted.
Boolean
The sort with the two values true and false, written Bool in SMT-LIB.
certificate
The proof data Z3 emits so that another tool can check the result without trusting Z3.
clause
A disjunction of literals, such as x = y or not (p).
clause log
A record of the clauses the solver derived, with the reason for each, in order.
constant array
An array with the same element at every index, written ((as const (Array Int Bool)) false).
formula
An expression that is true or false. In Lean it has type Prop.
grind
A Lean tactic that proves goals by equality reasoning and case splits over the facts it is given.
numeral
A literal number in the input, such as 3, (- 1), or (/ 1 3).
rewrite step
One simplification of a term into an equal, simpler term, recorded in the proof.
rewriter
The part of Z3 that simplifies terms before and during solving.
rfl
Lean's proof that two sides are equal because they compute to the same thing.
select
The read of an array at an index. (select a 3) is the element of a at 3.
set
An array of Booleans. The element at an index says whether that index is a member.
sort
The type of a value, such as Int, Real, Bool, or an array sort.
store
A write to an array. (store a i v) is a with the element at i replaced by v.
store chain
Several stores nested on top of one another, such as (store (store a 1 5) 2 7).
tactic
A Lean command that builds part of a proof automatically.
uninterpreted function
A function symbol with no fixed meaning, only its name and sorts. Equal arguments still give equal results.
uninterpreted sort
A sort declared by name only, with no fixed set of values, such as (declare-sort Index 0).
