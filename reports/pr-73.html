Certify sets and reads through store chains in Lean via the clause log

Pull request #73 on levnach/z3 · State: OPEN · Opened 2026-11-05T22:44:38Z · Loop iteration 74

This pull request is open and not merged. The change under review ends at commit 901fb0d72. It contains three commits on top of 4d7571b93.

In one paragraph

Before this PR, the pipeline rejected every array whose element sort is Boolean. Such arrays are the usual way to write a set in SMT-LIB. Now the exporter and the reconstructor accept them, and a select on a set becomes a Lean Prop. The PR also fixes a gap that affected every element sort. Z3's rewriter can read through a whole store chain in one step. The certificate then has no term for the levels in between, so the grind tactic could not prove that step. The reconstructor now adds one small rfl fact per level the rewriter passes. More refutations over arrays now check in Lean, with no new axiom and no sorry.

Background

Earlier iterations taught the clause log path to handle arrays over uninterpreted sorts, Int, and Real. They also added constant arrays and uninterpreted functions into and over arrays. Arrays with Bool elements were still the most common array rejection. Reads that the rewriter evaluated through several stores also failed in Lean, even when Z3 itself was fine. This work belongs to milestone 4 of the plan, "Broader theories and integration", where arrays are one of the listed extensions.

What changed

  • You can now certify inputs that use sets, (Array I Bool), with an uninterpreted, Int, or Real index sort.
  • In Lean a set is a predicate, a function from the index type to Prop, and each membership test is a formula.
  • A read through stores over a constant array now checks, because each store level and the constant at the bottom get their own fact.
  • A read that skips stores at other numerals now checks, and so does a read whose skip stops at a store at its own index.
  • Numerals are compared by value, so negative indices such as (- 1) and fractions such as (/ 1 3) are skipped correctly.

Think of a store chain as a stack of sticky notes on a page. Each note says "position 2 now holds false". To read position 3 you look past every note about another position. You stop at the first note about position 3. The rewriter does this in one jump. Lean needs to be told, note by note, what each one says about position 3. The new facts are exactly those notes.

Worked example

This input comes from the PR's new test set_read_through_numeral_stores_to_own_index. It uses both new features: a set, and a read that skips two stores and stops at a third. All output below comes from real runs.

(a) The input

(set-logic QF_ALIA)
(declare-fun a () (Array Int Bool))
(assert (not (select (store (store (store a 3 true) 2 false) 1 false) 3)))
(check-sat)

Put 3 into set a, then remove 2 and 1. The input claims that 3 is not a member, which is impossible.

Review

The reviewer asked for changes but found no blocker. All four findings were fixed in the last commit.

The missing stopping level (major). The reviewer tried (select (store (store a 3 5) 2 7) 3), which Z3 rewrites to 5. The second commit gave a fact to the store at 2, which the read skips. It gave none to the store at 3, where the skip stops. Lean's grind failed, and a set version failed the same way. This shape is common in array benchmarks with numeral indices, so it mattered. The fix adds the fact for the stopping store as well.

Negative numerals (minor). The reviewer tried stores at (- 1) and (- 2) with a read at 3. In the certificate a negative numeral is a minus applied to a numeral, not a single numeral. The old check did not see it as a numeral, so it gave no facts and grind failed. Z3 does treat it as a value and skips those stores. The fix computes the constant value of each index, which also covers the fraction (/ 1 3).

Two small text fixes (nits). The plan had an outdated count of set inputs, and one README line was too long. Both were corrected.

Risks and open questions

  • Soundness. The new facts are rfl theorems. An extra fact cannot make Lean accept a false claim.
  • Relaxed shape check. Array lemmas may now compare Bool terms when some array has Bool elements. This is only a shape guard, and Lean still proves each clause.
  • Proof size. A read gets one fact per numeral store it skips. A long chain of such stores adds one fact per level.
  • No z3test input is newly certified. Its set files also need map, nested arrays, Bool indices, or quantifiers.
  • Other rewriter expansions are not covered. No failing input for them was seen with default options.

What comes next

  • Support map over arrays, the natural next set feature.
  • Possibly admit Bool index sorts.
  • Cover the remaining rewriter expansions if a failing input appears.
  • The legacy core still rejects arrays.

Glossary

array
A value that maps each index to an element, like a table with one row per index. In SMT-LIB its sort is written (Array I E).
axiom
A statement Lean accepts without proof. Adding one would mean trusting something unchecked.
Boolean
The sort with exactly two values, true and false. SMT-LIB calls it Bool.
certificate
The file Z3 exports to justify its answer. It lists the input's terms and the proof steps.
clause
A disjunction of literals, an "or" of simple facts. Example: x = 1 or not p.
clause log
A record of the clauses Z3's solver learned or used, which the pipeline replays as the proof.
constant array
An array that holds the same value at every index. Example: the empty set holds false everywhere.
element sort
The sort of the values an array holds. In (Array Int Bool) it is Bool.
exporter
The script that runs Z3 and writes its proof as a certificate.
grind
A Lean tactic that proves goals by congruence closure, case splits, and arithmetic.
literal
An atomic formula or its negation. Example: p or not p.
Prop
Lean's type of propositions, the statements that can be proved. A Bool value becomes a Prop.
reconstructor
The script that turns a certificate into a Lean file for Lean to check.
refutation
A proof that a set of assertions leads to false, so they cannot all hold.
rewriter
The part of Z3 that simplifies terms before solving. Example: it turns a read through stores into a shorter term.
rfl
Lean's proof that two things are equal because both sides compute to the same value.
select
Reading an array at an index. (select a 3) is the element of a at 3.
set
An array with Bool elements. The element at an index says whether that index is a member.
sorry
A Lean placeholder that skips a proof. A trusted certificate must contain none.
sort
The type of a value in SMT-LIB, such as Int, Real, or Bool.
store
Writing an array at an index. (store a 3 true) is a with the element at 3 replaced by true.
store chain
Several stores nested inside each other. Example: (store (store a 1 5) 2 7).
tactic
A command that tells Lean how to build a proof, such as grind or omega.
uninterpreted function
A function symbol with no fixed meaning. The only rule is that equal arguments give equal results.
uninterpreted sort
A sort declared by the user with no built-in meaning, such as (declare-sort Index 0).
