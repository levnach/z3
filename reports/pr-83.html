Certify constant arrays of enumerations and constant-array rewrites

Pull request levnach/z3#83 · State: OPEN · Date: 2026-11-07T03:16:24Z · Loop iteration 83

This pull request is open and not merged. The change commit is 7823e020d. The pull request holds two commits in total.

In one paragraph

Lean can now check refutations that use a constant array whose elements belong to an enumeration datatype, such as an array of colors that is red at every index. It can also check reasoning about the default value of such an array, when the array is built from constant arrays by store and if-then-else terms. While testing this, the loop found four places where Z3's rewriter simplifies constant arrays in ways the generated Lean file never restated. Those gaps broke plain (Array Int Int) inputs too, so this pull request closes them for all arrays. Every new step is a theorem proved inside the generated Lean file. No axiom was added, so the trust boundary stays the same.

Background

The previous iteration added arrays whose elements are an enumeration, certified through the clause log. It still rejected two shapes. A constant array of an enumeration was refused. So was every default over such an array. A random sweep from that iteration also left four seeds failing in Lean. They involved a read through an ite over arrays. This work belongs to milestone 4 of the project plan, "Broader theories and integration", which treats arrays as one of the theory extensions.

What changed

  • The exporter now accepts constant arrays of an enumeration over Int or Real indices, instead of rejecting them.
  • The exporter accepts (default a) over an enumeration array when a is built only from constant arrays, stores, and ites.
  • The Lean reconstructor can prove that such a read or default value is one of the enumeration's constructors, using three new proved theorems.
  • Four rewriter simplifications of constant arrays now have matching Lean facts or simp lemmas, so those inputs verify for any element sort.
  • After review, the exporter's default-value check visits each shared subterm once, so deeply shared inputs no longer hang it.

The four rewriter gaps are easiest to see as shortcuts. The rewriter is like a student who skips steps in homework. Lean is the teacher who wants every step written down. The fix writes down each skipped step as a small proved lemma:

  • Comparing two stores into constant arrays inside a cnf step, which now gets the same default-value facts that rewrite steps already had.
  • Folding (store (const c) i (select (const c) j)) back into (const c).
  • Deciding (= (const c) (store (const c) i v)) as (= c v), in either order. One direction needs extensionality, which the automatic tactic does not do by itself.
  • Pushing a read into an ite over arrays and evaluating each branch's read.

Worked example

This input is the PR's test default_of_constant_arrays. The array k is either a store into a constant array of c, or the constant array of blue. The three assertions use a recognizer each to say its default value is none of the three colors. That is impossible, so the input is unsatisfiable. All outputs below come from real runs on this input.

(a) The input

(declare-datatypes ((Color 0)) (((red) (green) (blue))))
(declare-const c Color)
(declare-const i Int)
(declare-const p Bool)
(define-fun k () (Array Int Color)
  (ite p (store ((as const (Array Int Color)) c) i green) ((as const (Array Int Color)) blue)))
(assert (not ((_ is red) (default k))))
(assert (not ((_ is green) (default k))))
(assert (not ((_ is blue) (default k))))
(check-sat)

def _const_array (I : Type) {E : Type} (v : E) : I -> E := fun _ => v

The colors are three distinct constructors, the constant c is one of them, and a constant array is a function that ignores its index.

private theorem _cases_default_const {I E : Type} (P : E -> Prop)
    (h : forall l : List I, Exists (fun x : I => Not (List.Mem x l))) (v : E) (hv : P v) :
    P (_default h (_const_array I v)) := by
  rw [_default_const]
  exact hv

private theorem _cases_default_store {I E : Type} (P : E -> Prop)
    (h : forall l : List I, Exists (fun x : I => Not (List.Mem x l))) (a : I -> E) (i : I) (v : E)
    (ha : P (_default h a)) : P (_default h (_store a i v)) := by
  rw [_default_store]
  exact ha

Two of the new theorems: the default value of a constant array is its value, and a store does not change an array's default value.

Review

The reviewer approved the change. There were no blocker or major findings.

  • Minor: the default-value check could hang. The reviewer built a chain of ites in which each level refers to the level below twice. The exporter's new check walked the term as a tree, not as a shared graph. So the work doubled with each level: 150 seconds at 22 levels, and practically forever near 30. Nothing wrong would be certified, but the tool would stall. The fix keeps a set of already visited terms, and a 30-level test now passes in milliseconds.
  • Nit: a stale backlog marker. The project plan still listed the ite-read problem as open, although this change fixed it. Someone searching for open work could have chased a solved item. It is now marked done.
  • Nit: an inaccurate README sentence. It said an ite's default value is "that of the arrays below it". In fact it is the default of one of the two branches. The sentence was corrected.

Two suggestions were not taken and are listed as follow-ups. One asks for an input that needs _cases_const alone. The other asks for a cap on the new per-branch read facts.

Risks and open questions

  • The theorem _cases_const is sound, but no known input needs it alone. The automatic tactic finds the same cases another way.
  • The new read facts for ites over arrays have no size cap. A wide ite tree over long store chains could make files large.
  • The rule that a default value must be over constant arrays is enforced only by the exporter. A tampered certificate would still fail in Lean, so soundness is kept.
  • Proof text over a heavily shared ite graph can still grow quickly. This pattern existed before this change.
  • CI results were not available to this report.

What comes next

Several shapes are still rejected: the default value of an array constant of an enumeration, arrays indexed by an enumeration, arrays of an enumeration nested in other arrays, maps over arrays of an enumeration, and equalities between a constant array and a chain of more than one store into it. The pull request suggests a general "store chain over a constant equals the constant" lemma for the last one.

Glossary

array
A value that maps each index to an element, like a function. (Array Int Color) maps integers to colors.
axiom
A statement Lean accepts without proof. Adding one means trusting it.
clause log
The record of clauses Z3 learns while solving, which the exporter turns into a certificate.
cnf step
A step that rewrites a formula into conjunctive normal form, an AND of clauses. A clause is an OR of literals.
constant array
An array with the same element at every index. ((as const (Array Int Color)) red) is red everywhere.
constructor
One of the named values of a datatype. red, green, and blue are the constructors of Color.
default value
The element an array holds at all but finitely many indices. (default a) in Z3. The default of a constant array of red is red.
enumeration datatype
A sort with a fixed, finite list of constructors and no fields, such as Color with red, green, and blue.
extensionality
The rule that two arrays are equal if they agree at every index.
if-then-else term (ite)
A term that picks one of two values by a Boolean condition. (ite p a b) is a when p holds, else b.
read (select)
Looking up the element of an array at an index. (select a i).
recognizer
A test for which constructor a value is. ((_ is red) x) is true exactly when x is red.
refutation
A proof that a set of assertions leads to False, so they cannot all hold.
rewriter
The part of Z3 that simplifies terms before and during solving, for example turning a read of a constant array into its value.
simp lemma
A proved equation that Lean's simp tactic uses to rewrite goals automatically.
sort
The type of a value, such as Int, Real, Bool, or Color.
store
Writing one element into an array. (store a i v) is a except that index i now holds v.
tactic
A Lean command that builds part of a proof automatically, such as grind or omega.
theorem
A statement together with a proof that Lean has checked.
trust boundary
The set of things a reader must take on faith, such as Lean's kernel and any axioms. Everything else is checked.
