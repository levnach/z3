In one paragraph

Before this PR, the exporter refused any constant array whose elements belong to an enumeration. It also refused the default value of such an array. Now both pass through the clause log, and Lean checks the resulting refutation. Three new lemmas, each proved inside the generated file, let the reconstructor show that such a value is one of the constructors. While testing this, the loop found four rewriter steps on constant arrays that no Lean fact restated. They broke even plain (Array Int Int) inputs. The PR closes all four with new proved facts and simp lemmas. Nothing in the trusted Lean base changed.

Background

The previous iteration, PR #82, certified arrays of an enumeration through the clause log. It left constant arrays, default values, and maps of such arrays rejected. That iteration's review also recorded four random inputs with an if-then-else term over arrays that still failed in Lean. This PR lifts the first two rejections and fixes those four failures. It serves milestone 4, "Broader theories and integration", which treats arrays as one of the extensions.

What changed

Think of a constant array as a notebook with every page pre-printed in the same color. A store repaints one page. The default value is the color most pages still show.

  • You can now certify inputs that use constant arrays of an enumeration, with Int or Real indices.
  • You can now certify (default a) when a is built from constant arrays by stores and if-then-else terms. Other default values are still rejected with a clear message.
  • Lean can now prove that such a default value is one of the constructors, through three new proved lemmas such as _cases_default_store.
  • Plain integer-array inputs that Z3 solves now pass Lean when the rewriter compares, folds, or equates constant arrays.
  • A select through an if-then-else term over arrays now gets a fact for each branch, which fixes the four failing inputs left by PR #82.

Worked example

This input is default_of_constant_arrays from the PR's new enumeration tests. The array k, with elements of sort Color, is a store into a constant array or another constant array, chosen by p. Each assertion applies a recognizer to its default value. Together they say that value is no color at all, which is impossible.

(a) The input

(declare-datatypes ((Color 0)) (((red) (green) (blue))))
(declare-const c Color)
(declare-const i Int)
(declare-const p Bool)
(define-fun k () (Array Int Color)
  (ite p (store ((as const (Array Int Color)) c) i green) ((as const (Array Int Color)) blue)))
(assert (not ((_ is red) (default k))))
(assert (not ((_ is green) (default k))))
(assert (not ((_ is blue) (default k))))
(check-sat)

Review

The reviewer approved. There were no blocker or major findings.

  • Minor: a slow walk. The reviewer built a chain of if-then-else terms that share their sub-arrays, each level reusing the previous one. The new exporter check visited a shared sub-array once per path to it. That is like re-reading the same chapter each time a footnote cites it. Time doubled with each level, reaching 150 seconds at 22 levels. This could hang the exporter, though it could not make a wrong proof pass, so soundness was never at risk. The fix records each term it has visited, and a new test with 30 shared levels now runs in milliseconds.
  • Nit: a stale backlog note. The plan document still listed the PR #82 read problem as open. It is now marked done.
  • Nit: an inaccurate sentence. The README misdescribed the default of an if-then-else term. It now says the default is that of one branch.

Two suggestions were deferred as follow-ups: a test that needs _cases_const alone, and a cap on the new per-branch facts.

Risks and open questions

  • The lemma _cases_const is sound but redundant on every input seen so far. No test depends on it alone.
  • The per-branch facts for reads have no cap. A wide tree of if-then-else terms over long store chains could make large files.
  • The rule "default only over constant arrays" is enforced by the exporter only. A tampered certificate would still fail in Lean, so soundness holds.

What comes next

  • The default value of an array constant of an enumeration is still rejected.
  • Arrays indexed by an enumeration, nested arrays of an enumeration, and maps over them stay rejected.
  • Equalities between a constant array and a chain of two or more stores need a general extensionality lemma.

Glossary

array
A total map from indices to values. (Array Int Color) maps every integer to a color.
clause
A disjunction of literals, such as p or not q. A refutation derives the empty clause.
clause log
The record of clauses the solver derived, with hints on how each one follows. The exporter turns it into a certificate.
constant array
An array with the same value at every index, written ((as const (Array Int Color)) red).
constructor
One of the named values of a datatype. red, green, and blue are the constructors of Color.
default value
The value an array holds at all but finitely many indices, written (default a). For a constant array of red, it is red.
enumeration
A datatype whose constructors take no arguments, such as Color with red, green, and blue.
extensionality
The rule that two arrays are equal when they agree at every index.
if-then-else term
A term (ite p x y) that equals x when p holds and y otherwise.
lemma
A proved statement used as a step in a larger proof.
literal
An atom or its negation, such as p or not p.
recognizer
A test for one constructor, such as (_ is red) x, which holds when x is red.
refutation
A proof that a set of assertions leads to a contradiction, so they cannot all hold.
rewriter
The part of Z3 that simplifies terms before and during solving, for example reading a constant array to its value.
select
Reading an array at an index, written (select a i).
simp lemma
An equation Lean's simp tactic uses to rewrite a goal, left side to right side.
sort
The type of a value, such as Int, Real, Bool, or Color.
soundness
The guarantee that a checker never accepts a wrong proof. A failure to accept a right proof is a liveness problem, not a soundness one.
store
Writing one value into an array, written (store a i v). The result equals a except at index i.
tactic
A Lean command that builds part of a proof automatically, such as grind, omega, or simp.
theory lemma
A clause that holds because of a theory, such as arrays or arithmetic, rather than by pure Boolean logic.
