Certify QF_UFLRA refutations in Lean through both proof cores

Pull request: levnach/z3#10 Merge commit: cfee4d8ae Merged: 2026-10-15T16:08:33Z Loop iteration: 10

In one paragraph

This PR lets the pipeline certify refutations for the SMT-LIB logic QF_UFLRA. A refutation is a proof that a set of assertions cannot all be true. QF_UFLRA is the fragment, meaning the restricted input language, that mixes uninterpreted functions with linear real arithmetic. An uninterpreted function is a function symbol with no fixed meaning, only the rule that equal inputs give equal outputs. Linear real arithmetic is reasoning about real numbers with addition, comparison, and multiplication by constants. Before this PR the exporter refused any input that combined the two. Now such inputs are exported through both proof cores and become a Lean theorem that Lean checks with no new axiom or trusted step.

Background

Before this PR the pipeline handled three fragments: propositional inputs built only from Boolean values, QF_UF with uninterpreted functions over a sort, and QF_LRA with linear real arithmetic. A sort is the type of a value, such as Real or a user-declared type. Each fragment worked through both proof cores. The clause log is a list of clauses the newer solver learned, each tagged with a hint naming the reasoning behind it. The legacy proof object is the complete proof tree of the older solver. Neither path accepted a function that takes or returns a real number. This PR fills that gap under milestone 3 of the plan, equality and linear arithmetic, which must be complete before broader theories are attempted.

What changed

  • Classification. The exporter now labels an input qf_uflra when arithmetic meets a sort or an uninterpreted function, instead of stopping with an error.
  • Lean encoding. The theorem gains two universally quantified binders, meaning variables it holds for under every possible choice. One maps reals into the shared carrier type, and one interprets functions with a Real result. The carrier is one bag holding sort elements, Booleans, and now reals, so one notion of equality covers them all.
  • Congruence through both cores. Congruence is the rule that equal arguments give equal function results. Both cores now yield Lean proofs of congruence over real-valued arguments.
  • Argument normalization. Z3 merges arguments with the same linear form, such as x - y and x + (-1)*y. Lean's automation kept them apart and failed on 3 of 130 random inputs. Each lemma now proves such pairs equal first.
  • Two completeness fixes. Numerals as function arguments were wrongly treated as identical when matching clauses. A rewrite lemma crashed on an if-then-else term, written ite in SMT-LIB, used as an atom.
  • Cross-checked labels. A certificate whose fragment label disagrees with its declarations or with the input's classification is rejected.

Review

The reviewer approved with no blocking or major findings. Three smaller findings were fixed before merge.

  • Minor, stale plan notes. Four earlier dated entries in the plan document still said QF_UFLRA was rejected. Each now carries a forward annotation pointing to the new entry.
  • Nit, incomplete README limit. The reviewer built an input with (distinct (f x) (f y)) where Z3 eliminates the application as unconstrained. It was rejected as intended, but with a second message the README did not mention. The README now names both.
  • Nit, tests silently skipped. Three checks that need neither the z3 executable nor Lean sat in a class skipped without z3. They were moved to an in-process class.

The reviewer also re-checked soundness. Nothing assumes the injection of reals is one-to-one, and every new helper is proved by Lean's automation. A wrong helper can make Lean fail but never accept a bad proof.

Risks and open questions

  • Behavior change for callers. Inputs that used to produce an error message now produce a certificate. Tools that matched on the old message will see different output.
  • Known limit on the clause-log path. A real variable that occurs in only one function argument is eliminated by Z3's unconstrained-variable simplifier, even with the option to disable it set. Such inputs are rejected explicitly on that path. The fix needs C++ plumbing.
  • Bool-only predicates over reals. A predicate is a function whose result is Boolean. The newer core Ackermannizes these, meaning it replaces applications by fresh variables plus congruence constraints, so they route to the legacy core only.
  • Runtime and scale. Each pair of real arguments with equal linear forms adds one automation call. The full suite grew by about half a minute. Real SMT-LIB QF_UFLRA benchmarks have not been tried.

What comes next

Glossary

Ackermannization
Replacing function applications by fresh variables plus constraints that equal arguments give equal results.
Binder, universally quantified
A variable in a theorem statement that the theorem holds for every possible choice of.
Boolean
A value that is either true or false.
Carrier
The one Lean type that holds every value the theorem reasons about, here sort elements, Booleans, and reals.
Clause
A disjunction, an "or", of literals.
Clause log
A list of clauses the solver learned, each tagged with a hint naming the reasoning that produced it.
Congruence
The rule that a function applied to equal arguments gives equal results.
Farkas step
A weighted sum of linear inequalities that yields a contradiction.
Fragment
A restricted language of inputs, such as QF_UF or QF_UFLRA, that the pipeline handles with one encoding.
If-then-else term
A term that picks one of two values depending on a condition, written ite in SMT-LIB.
Legacy proof object
The complete proof tree recorded by the older solver core, with explicit equality steps.
Linear form
A sum of variables multiplied by constants, plus a constant.
Linear real arithmetic
Reasoning about real numbers with addition, comparison, and multiplication by constants.
Literal
An atomic formula or its negation.
Predicate
A function whose result is Boolean.
QF_UFLRA
The SMT-LIB logic of quantifier-free formulas mixing uninterpreted functions with linear real arithmetic.
Refutation
A proof that a set of assertions cannot all be true at once.
Sort
The type of a value, such as Real, Bool, or a user-declared type.
Uninterpreted function
A function symbol with no fixed meaning, only the rule that equal inputs give equal outputs.
