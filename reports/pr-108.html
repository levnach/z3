Prove euf lemmas by grind over folded ites, without gates or axioms

Pull request levnach/z3 #108 · MERGED · 2026-11-10T19:21:22Z · loop iteration 107

Merged into master on 2026-11-10T19:21:22Z as commit 4dedeb2e2.

In one paragraph

This pull request changes how the reconstructor proves one kind of theory lemma: the ones whose hint says euf. Each such lemma is a congruence conflict over its literals. Before, every one of them also received the gates of each if-then-else term it reached, plus array axiom instances for each array read. Now it receives neither. It is proved by the grind tactic alone, without omega. When it reaches if-then-else terms, it is first tried with those terms kept folded. The old proof stays as a fallback. This matters because these extra facts made big Lean files slow or impossible to check. On a test instance shaped like a hard benchmark, Lean time dropped from 136 s to 20 s. Theorem statements did not change, and no new axiom or sorry was added.

Background

After pull request #107, the pipeline already handled QF_AUFLIA inputs with arrays, uninterpreted functions, and if-then-else terms. It still could not check the z3test benchmark cvc/dlx-regfile. Its Lean file was 44 MB. Lean used 12 GB and was stopped after 20 minutes. Most of its theory lemmas were euf lemmas, and they carried facts that Z3's egraph never uses. Removing those facts was not enough on its own. Omega and grind still ran out of heartbeats on over a hundred lemmas. This work serves milestone 3 (equality and linear arithmetic) and milestone 4 (arrays and broader theories) of the project plan.

What changed

  • An euf lemma is now proved from its literals by congruence alone, the way Z3's egraph proves it, with no ite gates and no array axiom instances.
  • An euf lemma now uses grind alone, so omega can no longer burn its heartbeat budget first.
  • An euf lemma that reaches if-then-else terms is first tried with them folded, so grind sees each one as an opaque leaf.
  • The test suite can now build instances shaped like dlx-regfile and check that the folded attempt works without its fallback.
  • The README and the plan document now describe how euf lemmas are proved.

An analogy for the folded attempt: two sealed boxes with the same label hold the same thing. Congruence only compares labels. It never needs to open the boxes and look at both branches inside. The gates were never part of an euf lemma in Z3 anyway. Z3 states them as separate Tseitin clauses.

Only definitional array facts remain, plus one commutativity fact for extensionality witnesses. Other lemma kinds are unchanged, and there is no C++ change.

Worked example

This pull request is a speed and size change. It does not newly certify a small input. The old pipeline also accepted the PR's test instances, and the largest one took 136 s. So the example below runs one input through both versions and compares the generated Lean proofs. The input is register_file_instance(1) from the new test generator, with the declarations reordered. Both versions were run for real for this report.

(a) The input

(set-logic QF_AUFLIA)
(declare-fun f (Int Int) Int)
(declare-fun p (Int) Bool)
(declare-const A (Array Int Int))
(declare-const u0 Int)
(declare-const w0 Int)
(define-fun u1 () Int (ite (p u0) (f u0 (select A u0)) (select (store A u0 1) (f u0 1))))
(define-fun w1 () Int (ite (p w0) (f w0 (select A w0)) (select (store A w0 1) (f w0 1))))
(assert (= u0 w0))
(assert (not (= u1 w1)))
(check-sat)

Two copies of one pipeline stage get equal inputs of sort Int, yet their outputs are claimed to differ. Congruence shows this is impossible.

Review

The reviewer approved the change. There were no blockers and no major findings.

  • Minor, fixed. The README still said every theory lemma gets ite gates and tries omega. A maintainer debugging an euf lemma would hunt for facts that no longer exist. Three passages now describe euf lemmas.
  • Nit, fixed. One condition was dead code, and its comment implied a behaviour change that never happened. Both were cleaned up.
  • Nit, fixed. The Lean test could not notice a broken folded attempt, because Lean would silently use the fallback. Big files would then become slow again. The test now also checks each euf lemma with its folded attempt alone, and a mutation check showed this catches breakage.
  • Suggestion, fixed. The plan document now names all map identities, not just one.
  • Suggestion, not changed. The heartbeat budget is shared by a whole declaration, so a slow failing first attempt starves the fallback. No such lemma was seen, so this is a follow-up.

Risks and open questions

  • If a folded attempt times out instead of failing quickly, the fallback is not reached. None was seen in the test suite, dlx-regfile, or hard16.
  • dlx-regfile still does not verify. Its single cnf lemma reaches 227 ite terms and runs out of heartbeats. Its full file, including the proof steps, was not checked.
  • Each euf lemma that reaches ite terms now holds two proof attempts, so its text is longer than one attempt would be.

What comes next

  • Drop the fallback for euf lemmas once the helper facts are also stated folded. That would roughly halve their text and remove the shared-budget risk.
  • Try the folded-first approach on other lemma kinds that treat ite terms as leaves, such as array lemmas.
  • Make the remaining dlx-regfile cnf lemma and its large proof steps fit in Lean's budget.

Glossary

array
A map from indices to values. select A i reads index i, and store A i v is a copy of A with v written at i.
array axiom
A basic rule about reads and writes, such as "reading index i right after storing v at i gives v".
Boolean
The sort with only two values, true and false. In the example, p returns a Boolean.
clause
A disjunction of literals, such as a or not b or c.
congruence
The rule that equal arguments give equal results: if x = y, then f x = f y.
egraph
Z3's data structure for congruence closure. It groups terms known to be equal and merges groups by congruence.
euf
Equality with uninterpreted functions. As a hint, it marks a theory lemma proved only by equality reasoning and congruence.
extensionality
The rule that two arrays are equal when they agree at every index. A witness is an index where two different arrays differ.
fallback
A second proof attempt that runs only if the first one fails. Lean's first | A | B tries A, then B.
folded definition
A definition kept as its name rather than replaced by its body. Unfolding replaces the name by the body.
gate
A fact that links an if-then-else term to a branch, such as "if c then ite c a b = a".
grind
A Lean tactic that combines congruence closure, case splits, and some arithmetic.
heartbeat
Lean's unit of work. Each declaration gets a maximum number, and a proof that uses more is stopped.
if-then-else term
A term that picks one of two values by a Boolean condition. It is written ite in SMT-LIB, as in (ite c a b).
literal
An atomic formula or its negation, such as u0 = w0 or not (u1 = w1).
omega
A Lean tactic that decides linear arithmetic over integers.
refutation
A proof that a set of assertions leads to False, so they cannot all hold.
sort
The type of a value, such as Int, Bool, or (Array Int Int).
tactic
A Lean command that builds part of a proof automatically, such as grind or unfold.
theory lemma
A clause that holds in a background theory, such as arithmetic or equality, and that Z3 adds during a refutation.
Tseitin clause
A clause that defines a new name for a subterm or subformula. Z3 states an ite's gates as such clauses, separately from euf lemmas.
uninterpreted function
A function with no fixed meaning. Only congruence is known about it, as with f and p in the example.
