In one paragraph

The Lean files generated for the QF_UF, QF_UFLRA and QF_UFLIA logics now pass the interpretation of every uninterpreted sort, uninterpreted function and predicate as one structure argument. Before, every declaration took five to seven separate binders for it. Very large files are also elaborated one declaration at a time. Together, these let the 21 MB refutation of NEQ004_size4 pass Lean's kernel under the 8 GB memory cap. The theorem states the same thing. A certificate only counts once Lean finishes checking it, and for large QF_UF proofs memory was the wall.

Background

Before this PR, small QF_UF certificates already checked in Lean. NEQ004_size4 is a 16 KB benchmark with 20,634 proof steps. Its Lean file was written without trouble. But since the 8 GB cap of 2026-10-27, Lean stopped with "(kernel) excessive memory consumption". This serves milestone 3 of the plan: equality reasoning over uninterpreted functions, completed end to end.

What changed

  • Every definition, lemma and proof step in a UF file now takes one Interpretation argument instead of five to seven.
  • Files above 8 MB of Lean text now elaborate serially, using far less memory at about three times the time.
  • NEQ004_size4 now verifies under the 8 GB cap, and a new end-to-end test checks it.
  • QF_UFLRA and QF_UFLIA files use the same structure, with extra fields for their Real or Int parts.
  • The READMEs and the plan document describe the new encoding and the measurements.

An analogy: before, every citation in an essay listed title, author, year and publisher. Now it just says "see the book". The meaning is the same, but Lean keeps far less in memory. Serial elaboration is like washing dishes one at a time instead of piling half-washed plates on the counter.

Worked example

The newly certified input is NEQ004_size4, the new test file. Its one assertion is about 15 KB long, so it is trimmed below. All output comes from real runs made for this report: the "before" on the base commit's code, the "after" on the merge commit.

(declare-sort U 0)

...

...

(assert (let ((?v_52 (= c_0 c_0))) ... (and (distinct c_0 c_1 c_2 c_3) (p4 c14 c12) (p4 c14 c13) ... )))

It declares a sort U, constants, one function and eight predicates, then asserts one large conjunction of clauses.

On the merge commit, the reconstructor printed "Lean checked the refutation", and a separate check_lean.sh run printed "Lean checks passed." Lean accepted the file. It has 21,629,470 characters, above the 8 MB threshold.

The file switches on serial elaboration and declares the one structure that bundles the carrier type with the constants, functions and predicates.

def term_0 (_atoms : Nat -> Prop) (_m : Interpretation) : _m.U := _m.elems 0
...
def formula_7 (_atoms : Nat -> Prop) (_m : Interpretation) : Prop := _m.preds 0 [(term_5 _atoms _m), (term_6 _atoms _m)]
...
def term_208 (_atoms : Nat -> Prop) (_m : Interpretation) : _m.U := _m.funs 0 [(term_0 _atoms _m), (term_0 _atoms _m)]

Terms and formulas now read their symbols from fields of _m, such as _m.preds 0 for the predicate p4.

  unfold formula_814 formula_813 formula_812 formula_811 formula_798 formula_777 formula_320 term_190 formula_111 term_6 term_3 term_2

private theorem proof_step_815 (_atoms : Nat -> Prop) (_m : Interpretation)

    : (formula_814 _atoms _m) :=

A theory lemma is proved by the grind tactic, and each proof step passes the short pair _atoms _m along instead of six arguments.

theorem unsat (_atoms : Nat -> Prop) (_m : Interpretation)
    (_h0 : (formula_810 _atoms _m))
    : False :=
  proof_step_25464 _atoms _m _h0

For every interpretation, the one assertion implies False. Quantifying over a structure is quantifying over its fields, so the meaning is unchanged.

This run did not measure memory or print the axioms. The PR's test reports the axioms [propext, Classical.choice, Quot.sound].

Review

The reviewer read the full diff, reran the tests, and approved.

The misplaced tests. The two new tests had been pasted into the middle of an older congruence test. That test's last checks, which guard against axioms, then ran under the serial-elaboration test's name. Deleting that test later would silently lose them. The checks were moved back.

Stale comments. Some comments still said _U and similar old names, which would mislead readers. They now use the field names.

Skipped statement checks. To run Lean only once, the NEQ004 test bypassed the helper that counts the theorem's hypotheses. A bug dropping a hypothesis on large files only would have gone unnoticed. The test now counts them itself.

Risks and open questions

  • NEQ004 leaves about 1 GB of headroom on macOS. CI uses Linux, whose allocator may differ, so the test could fail there. No CI result on master was available for this report.
  • The NEQ004 test adds about 110 s to the CI Lean step, and serial elaboration triples the time of any file above 8 MB.
  • The UF theorem statement's text changed. A tool parsing the old binders would break, but the z3test scripts do not.
  • The larger QF_UF gensys_* benchmarks, at 100 to 640 MB of Lean text, remain out of reach.

What comes next

Glossary

axiom
A statement Lean accepts without proof. The certificates use only Lean's three standard ones, propext, Classical.choice and Quot.sound.
binder
A named parameter of a Lean declaration, such as (_m : Interpretation).
Boolean
The sort with the two values true and false, written Bool in SMT-LIB.
certificate
A file that records a solver's proof in enough detail for another program to check it.
clause
A disjunction of literals, for example (or (not a) b).
congruence
The rule that equal arguments give equal results: if a = b then f(a) = f(b).
declaration
One named item in a Lean file, such as a definition, lemma or theorem.
elaboration
Lean's work of turning source text into fully explicit terms before the kernel checks them. It can run several declarations in parallel or one at a time, called serial.
equality
The relation = between two terms of the same sort.
interpretation
A choice of meaning for every symbol: a set of values for each sort, and an actual function for each function symbol.
kernel
The small trusted core of Lean that does the final check of every proof.
lemma
A helper theorem proved on the way to the main one.
literal
An atom or its negation, such as p or (not p).
predicate
A function whose result is Boolean, such as p4 in the example.
proof step
One inference in a proof, deriving a new formula from earlier ones.
QF_UF
The SMT-LIB logic of quantifier-free formulas over uninterpreted sorts and functions with equality. QF_UFLRA and QF_UFLIA add linear Real or Int arithmetic.
refutation
A proof that a set of assertions leads to False, so they cannot all hold.
sort
The type of a value, such as Int, Real, Bool, or a declared sort like U.
structure
A Lean type that bundles several named fields into one value, like a record. _m.U reads the field U of _m.
tactic
A Lean command that builds a proof automatically or step by step, such as grind.
theorem
A proved statement. Here, the final one says the input's assertions imply False.
uninterpreted function
A function symbol with no fixed meaning. Any function is allowed, as long as equal arguments give equal results. Example: f5.
uninterpreted sort
A sort with no fixed set of values, declared with declare-sort, such as U.
