Prune only implied literals in proof trimming and reject failed probes

Pull request #33 State: OPEN Date: 2026-10-22T21:35:02Z Loop iteration 33

This pull request is not merged. The report covers both of its commits, up to the change commit 5864a6a.

In one paragraph

Z3's native proof trimmer shortens a large clause log before the exporter replays it. When it removes a clause, it unassigns the literal that clause implied. It used to unassign any true literal of the clause, not only the one whose justification was that clause. Z3 logs the same binary clause several times when it re-derives a theory lemma, so removing one copy dropped a level-0 fact that other copies still supported. A later reverse unit propagation step then found no conflict in its probe, and the trimmer emitted an arbitrary dependency core that the exporter rejected. The PR fixes the pruning, makes a failed probe an explicit error, and lets the exporter fall back to the untrimmed log. Two QF_UFLIA benchmarks that were rejected at export now yield a refutation that Lean accepts.

Background

The pipeline already replayed every retained step of a trimmed log from its listed premises, so a wrong dependency core could never make Lean accept a false refutation. But a core the replay could not use failed the whole export. The iteration 32 scan left two QF_UFLIA inputs in that state, hard16.smt2 and hard20.smt2, although Z3 solves them in seconds. An earlier trimmer defect, fixed on 2026-10-07, concerned a satisfied clause. This PR serves milestone 3 of the plan, equality and linear arithmetic with uninterpreted functions, completed end to end on real benchmarks.

What changed

  • Precise pruning. When the trimmer removes a clause, only the literal whose justification is that clause is unassigned. Think of a fact held up by several ropes: cutting one rope no longer drops the fact.
  • A failed probe is an error. If unit propagation finds no conflict for an inferred clause, the trimmer raises "not derivable by unit propagation" instead of emitting made-up dependencies.
  • Corner cases are explicit. A probe over a clause a level-0 fact already satisfies depends on that fact alone, an unregistered core clause is an internal error, and a step no longer lists itself as a dependency.
  • The exporter falls back. In proof_clause_log.py a trimmer error or an unusable dependency graph now warns and replays the untrimmed log, so the export succeeds but takes longer.
  • Tests and docs. Two C++ tests and two Python tests pin both behaviours. The README, the trimmer comment, and the plan record the fallback and a remaining limitation.

Review

The reviewer approved with no blocking or major findings. They rebuilt and ran the tests, re-ran hard16.smt2 through Lean, and fed two small logs to the real trimmer: the duplicate-binary log above trimmed correctly, and an underivable inference produced the new error with a non-zero exit code. Four findings remained.

  • Minor: the README still called trimming unconditional. A maintainer seeing a "trimming failed" warning would not know why the export still succeeded. Fixed in the second commit.
  • Nit: "Z3 never logs binary deletions" was wrong. In-processing does log them. Since copies of a binary clause are told apart only by counting them in the watch list, a deleted-then-re-added copy could still lose a fact. The outcome is the explicit error and the fallback, not a wrong core, so the limitation was recorded in the code comment and the plan.
  • Nit: the plan note interrupted another section. Fixed by giving it its own dated heading.
  • Nit: one literal declared apart from the others in the C++ test. Fixed.

The reviewer suggested surfacing a fallback flag in the Lean report. That was recorded as a follow-up.

Risks and open questions

  • Soundness is unaffected by construction. The replay re-derives every retained step and Lean checks the result, so the C++ changes alter which inputs are accepted and how fast, not what can verify.
  • The pruning assumes complete propagation after each step. The implementer checked that the forward pass drains its queue, so the trail at a step holds exactly the facts derived before it.
  • Binary copies are counted, not identified. A deleted and re-added binary clause can still lose a fact, which ends in the explicit error and a slow untrimmed replay.
  • Fallbacks are easy to miss. A fallback leaves the report status as verified with only a warning as evidence.
  • CI status is unknown at the time of writing.

Glossary

axiom
A statement a proof checker accepts without proof. The Lean theorems here rely only on three standard ones from Lean's own library.
binary clause
A clause with exactly two literals, such as (or (not a) b). If one literal is false, the other must be true.
Boolean
A value that is either true or false, or a variable holding such a value.
clause
A disjunction of literals: a list of literals of which at least one must be true. Example: (or (not u) (not d) c).
clause log
Z3's record of every clause it assumed, inferred, or deleted while solving, written as SMT-LIB-style commands.
dependency core
The subset of log steps needed for the final empty clause, each with the earlier steps it depends on. The trimmer computes it and the replay checks it.
justification
The reason a literal became true: the clause that forced it, or none if it was assumed directly.
level-0 fact
A literal that is true without any guesses, because it follows from the clauses alone.
literal
A Boolean variable or its negation, such as a or (not a).
probe
The trimmer's test of one inferred clause: assume all its literals false and check that unit propagation reaches a conflict.
propositional
Involving only Boolean variables and the connectives and, or, and not, with no arithmetic or functions.
QF_UFLIA
The SMT-LIB logic of quantifier-free formulas over uninterpreted functions and linear integer arithmetic.
refutation
A proof that a set of assertions is contradictory, ending in the empty clause or in False.
replay
Re-deriving every step of a log or core from its listed premises in Python, so nothing the trimmer or solver claims is taken on trust.
reverse unit propagation (rup)
A proof step justified because assuming the clause false and running unit propagation yields a conflict. Written rup in the clause log.
satisfied clause
A clause one of whose literals is already true. It forces nothing further.
theory lemma
A clause valid by the rules of a theory, such as integer arithmetic, rather than by Boolean reasoning alone.
trail
The ordered list of literals currently assigned true, each with its justification.
uninterpreted function
A function symbol with no fixed meaning, only the rule that equal arguments give equal results.
unit clause
A clause with a single literal, which forces that literal to be true.
unit propagation
Repeatedly finding a clause with all literals but one false and making the remaining literal true, until nothing changes or a conflict appears.
watch list
The solver's index from a literal to the clauses to re-examine when that literal becomes false. The trimmer counts binary-clause copies there.
