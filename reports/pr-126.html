In one paragraph

The reconstructor now writes every negation of a term of sort Int as the difference 0 - t. A quotient by a negative constant becomes a difference too. A small theorem beside it, checked by the kernel, says it equals the ordinary quotient. The values are unchanged. This removes the known kernel rejections caused by a defect in the tactic grind, which mishandles the numeral -0. Inputs such as (f (div 2 (- 5))), with an uninterpreted function applied to such a term, now get a certificate that Lean accepts. No axiom was added, and the trust boundary did not move.

Background

Before this PR, a negation became a difference only when the reconstructor's own evaluation showed the negated term to be zero. Lean's simplifier reaches zero in more ways. Examples are a remainder by 1, an if-then-else term with a decided condition, and a quotient by a negative constant. There grind met -0, the kernel rejected its proof, and the refutation failed in Lean. A read from an array at such an index failed the same way. The work serves milestone 3 of the plan, equality and linear arithmetic.

What changed

An analogy: a clerk misreads one spelling of "minus nothing". So every form now says "nothing, take away t", which is the same amount.

  • Reconstructor, negations. Inputs with terms such as (- (mod x 1)) or (- (ite true 0 1)) now verify, because every Int negation is written 0 - t.
  • Reconstructor, quotients. A div by a negative constant, such as (- 5) or (* 5 (- 1)), now verifies, written 0 - t / (0 - d) beside a kernel-checked theorem.
  • Reconstructor, remainder bounds. Bounds on a remainder under a negative divisor now prove however the divisor is spelled, a fix made after review.
  • Tests. New regression tests pin the new forms, check the inputs in Lean, and confirm the old forms still fail.
  • Documentation. The plan, the README, and a generated header comment describe the new forms.

A negated positive numeral stays -k, and Real negations are unchanged. The previous PR's evaluator is deleted. No C++ changed.

Review

The reviewer approved the change with one minor finding, two nits, and no blocker. All three were fixed before the merge.

Minor: a helper fact that could no longer be proved

The reviewer wrote the divisor −3 as (- (- (- 3))) inside a cut. For such a step the reconstructor states helper facts that bound each remainder. The upper bound's proof used a rewrite that only matches a divisor written as a negation. This divisor is now a difference, so the fact was stated but could not be proved. The certificate still verified, but only through a fallback. It mattered because the fallback hid a fact Lean could never prove. The bound is now proved from the divisor's absolute value. A new Lean test checks it for four spellings of −3. The integrator corrected one detail: the first attempt already failed before this PR, so no fast path was lost.

Nit: documentation showed the old forms

The README still described rem and abs with the old minus forms, which no certificate contains any more. It now shows the difference forms.

Nit: tests used one spelling of a negative divisor

Every negative divisor in the tests was written (- k). A later edit could narrow the rule to that spelling and still pass, while (div 2 (* 5 (- 1))) failed again. Two inputs with other spellings were added.

Risks and open questions

  • Soundness. None identified. 0 - t equals -t, and the kernel checks the quotient identity.
  • Breadth. Every certificate with an Int negation changes its text. A proof that needs to see -t could exist outside the tests, and it would fail closed.
  • Toolchain. The workaround targets a defect in the grind of Lean 4.34.0. Two counterfactual tests fail once a toolchain lacks it, which signals removal.
  • Cost. One measurement showed about 10% more reconstruction time on a heavily shared divisor.

What comes next

These backlog items remain open.

  • A rewrite that normalizes the divisor of a mod always wastes one failed attempt.
  • (f (to_int 0.5)) against (f 0) still fails in grind.
  • A map over two stores with the Int negation map still fails in grind.
  • Two random seeds are rejected with unsupported or invalid def-axiom clause.
  • The exporter rejects quotients and remainders of numerals by a negative numeral.

Glossary

array
A value that maps indices to elements. (select a i) reads the element at index i, and store writes one.
axiom
A statement accepted without proof. Adding one would mean trusting something Lean did not check.
Boolean
Having one of the two values true and false. A Boolean input uses only such values and connectives like and, or, and not.
certificate
A file of evidence for a result that an independent checker can verify. Here it is the generated Lean file.
constant
An expression with no variables, so its value is fixed. Examples: (- 5) and (* 5 (- 1)).
counterfactual test
A test that switches a fix off and checks that the old failure comes back. It shows the fix is still needed.
cut
A step in integer arithmetic that uses the fact that variables are whole numbers. Example: from 2x ≥ 1 conclude x ≥ 1.
divisor
The number divided by. In (div 2 (- 5)) the divisor is −5.
Euclidean division
Integer division where the remainder is never negative. Example: 2 divided by −5 is 0 with remainder 2.
fail closed
To fail by rejecting. A broken proof is refused. It is never accepted by mistake.
if-then-else term
A term that picks one of two values by a condition, written ite in SMT-LIB. Example: (ite true 0 1) is 0.
kernel
The small core of Lean that checks every finished proof. A proof counts only if the kernel accepts it.
lemma, theorem
A proved statement. A lemma is usually a small one used as a step toward a larger theorem.
linear arithmetic
Arithmetic where variables are only added and multiplied by constants. Example: 2x + 3y ≤ 7.
numeral
A number written out directly, such as 5 or -2.
quotient
The result of integer division, written div in SMT-LIB and / in Lean.
refutation
A proof that a set of assertions cannot all hold. It ends by deriving False.
regression test
A test kept so that a fixed problem is noticed if it returns.
remainder
What is left after integer division, written mod in SMT-LIB and % in Lean. Z3 also has rem, which is the negated mod when the divisor is negative.
rewrite
A proof step that replaces a term or formula with an equal one. Example: replacing (div 2 (- 5)) with 0.
satisfiable
Having at least one assignment of values that makes every assertion true. Such an input has no refutation.
simplifier
The part of a prover that rewrites terms into simpler equal ones, for example by evaluating constants.
sort
The type of a value, such as Int, Real, or Bool.
soundness
The property that only true statements can be proved. A sound checker never accepts a wrong proof.
tactic
A Lean command that builds part of a proof. grind, omega, and decide are tactics. The kernel still checks what they build.
term
An expression that denotes a value, such as x, (- x), or (f 0).
trust boundary
The line between what is checked and what is simply believed. It moves when a new unchecked assumption is added.
uninterpreted function
A function symbol with no fixed meaning. All that is known is that equal arguments give equal results. Example: f in (declare-fun f (Int) Int).
