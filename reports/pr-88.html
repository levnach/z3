In one paragraph

Z3's rewriter simplifies array terms by value. It sees that the store index (* 1 2) and the index (- 3 1) are both 2. It then applies a store identity and drops the inner store. The Lean reconstructor only matched indices that were the very same term. So Lean rejected these rewrite steps, and the whole refutation failed. This PR compares numeral expressions by their value. It also writes each value as a small lemma that the grind tactic proves inside Lean. The simp tactic then uses these lemmas with pre-order rewriting before it applies the store identity. More array certificates now check in Lean. No axiom, no sorry, and no trusted hint were added.

Background

Earlier iterations taught the reconstructor the store identities for arrays and constant arrays. These worked only when the two indices were the same node in the certificate, such as 2 and 2. They failed when one side was written (/ 2 2) and the other 1.0. The plan listed this as the open item "Unnormalized numeral indices", found in iteration 86. The work serves milestone 4, "Broader theories and integration", where arrays are one of the extensions.

What changed

  • The reconstructor now treats two indices or stored values as equal when both are numeral expressions with the same value, such as (/ 2 2) and 1.0.
  • For such steps, the generated Lean states the value of each outermost numeral expression as a lemma, and grind proves it.
  • Simp applies those lemmas outside-in, so a bigger expression is rewritten before a smaller one inside it can change its shape.
  • Division by an expression whose value is zero is never evaluated, because Z3 and Lean disagree on what x / 0 means.
  • Six new test inputs, a test proving the lemmas are needed, and a new knob on the random generator now guard this case.

An analogy: two letters are addressed to "house two dozen" and "house 24". Before sorting them, you first write both addresses as plain numbers. Then the sorter can see they go to the same house.

Worked example

This input is the test store_over_a_store_at_products from the PR. All three pieces below come from real runs of the pre-change and post-change scripts.

(a) The input

(set-logic ALL)
(declare-const a (Array Int Int))
(declare-const b (Array Int Int))
(declare-const v Int)
(declare-const w Int)
(declare-const p Bool)
(assert (or p (= b (store (store a (* 1 2) v) (- 3 1) w))))
(assert (not p))
(assert (not (= b (store a 2 w))))
(check-sat)

Writing v at index 2 and then w at index 2 is the same as writing only w there, so the assertions contradict each other.

These declarations are the input's terms: term_5 is 1 * 2, term_9 is 3 - 1, and term_11 is the store chain.

private theorem _store_store {I E : Type} (a : I -> E) (i : I) (v w : E) :
    _store (_store a i v) i w = _store a i w := by
  funext _j
  by_cases _h : _j = i <;> simp [_store, _h]

This is the store identity, proved in Lean: a second store at the same index hides the first one.

Review

The reviewer approved the PR. There were no blocker, major, or minor findings. There were two nits.

  • Nit, fixed: repeated work. The reviewer built indices that double themselves sixteen times, like (+ t t) nested inside itself. The new value function recomputed shared parts again and again, and it evaluated every argument before giving up. Reconstruction took 0.62 s on that input. The fix caches each node's value and stops at the first argument that is not a numeral expression. The time dropped to 0.35 s. This matters because certificates share subterms heavily.
  • Nit, not changed: extra lemmas. The reviewer noticed lemmas for numeral expressions that no store depends on, such as (+ 1.0 1.0) in an arithmetic atom. Each such lemma is a closed fact that grind proves, and it appears only in the last-resort alternative. Trimming them would mean following reads through stores, which adds code and new ways to miss a needed lemma. The author kept the simpler version.

Risks and open questions

  • If grind ever failed to prove a value lemma, the last alternative would fail where it once succeeded. No such failure appeared in the tests or the 673 sweep certificates.
  • The store-identity check now says yes more often. A step that fails anyway costs one more attempt. This is a time cost, not a soundness issue.
  • Two helper functions still compare store indices by node identity. With equal-valued indices they state extra facts. That is sound but not minimal.

What comes next

The PR names a follow-up from Real/Int seed 102. An if-then-else term whose branches are store chains is compared with a store chain over constant arrays. Lean rejects that step even with plain numerals. A fact per branch, comparing it with the other side, would likely cover it.

Glossary

array
A map from indices to values, like a function. (Array Int Int) maps integers to integers.
axiom
A statement Lean accepts without proof. Adding one would add trust.
certificate
The file Z3 exports that records each step of its proof, so another tool can check it.
constant array
An array that holds the same value at every index, written ((as const (Array Int Int)) 1).
grind
A Lean tactic that combines equality reasoning, arithmetic, and case splits to close a goal automatically.
if-then-else term
A term that picks one of two values by a Boolean condition, written (ite c x y) in SMT-LIB.
lemma
A small proved statement used as a step toward a bigger proof. In the generated Lean these appear as have lines.
numeral
A constant number written directly, such as 2, 1.0, or (/ 1 2).
numeral expression
Numerals combined only by + - * / or to_real, such as (* 1 2). It has one fixed value.
pre-order rewriting
Rewriting a term before its subterms, outside-in. In Lean's simp it is marked with ↓.
refutation
A proof that a set of assertions leads to False, so they cannot all hold.
rewrite step, rewriter
A proof step where Z3 replaces a term by a simpler equal term. The rewriter is the Z3 component that does this.
select
Reading an array at an index, written (select a i).
simp
A Lean tactic that repeatedly rewrites a goal with a given list of equations.
sorry
A Lean placeholder that skips a proof. A checked file must not contain it.
sort
The type of a value, such as Int, Real, Bool, or an array sort.
store
Writing a value into an array at an index, written (store a i v). It returns a new array.
store identity
An array law that removes a store. Examples: (store (store a i v) i w) equals (store a i w), and (store a i (select a i)) equals a.
tactic
A Lean command that builds part of a proof automatically.
trusted hint
Information from Z3 that the checker accepts without checking it. The project avoids adding new ones.
