In one paragraph

Before Z3's certificate can be checked in Lean, the exporter must tie every assumed clause in the clause log back to an input assertion. It does this with small solver checks, first for equivalence with a conjunct, then for implication. On a deeply nested conjunction, the equivalence pass tried every suffix, and none of those tries ever succeeded. This PR narrows that pass to conjuncts over exactly the clause's symbols, plus leaf conjuncts that contain them. The QF_IDL benchmark FISCHER6-4-ninc now exports in about two seconds instead of about eight minutes, and Lean accepts its refutation. Nothing new is trusted, since only the search order changed.

Background

The exporter already picked candidate conjuncts that share a symbol with the clause. But in a nested conjunction every suffix shares those symbols. So each clause met over a thousand candidates, and each failed check asserted a large formula. Then the implication pass succeeded on its first candidate, the whole assertion. Such inputs were certifiable in principle, but not in practical time. Iteration 45 logged this as a backlog item. The work serves milestone 3, equality and linear arithmetic, and the plan's priority of adding real benchmark files.

What changed

  • The equivalence pass now skips and conjuncts whose symbol set differs from the clause's, compared by a hash, so a thousand-level nesting no longer costs a thousand solver checks per clause.
  • Leaf conjuncts that contain all of the clause's symbols are still checked, so a conjunct that Z3's preprocessing simplified (for example (f (* 0 y)) to (f 0)) still gets a small rewrite bridge.
  • The QF_IDL input FISCHER6-4-ninc is now test data that a new test exports and checks in Lean.
  • A new QF_UFLIA test with an uninterpreted function guards the leaf case the reviewer found.

An analogy: to find a book's shelf, the old search emptied every bookcase holding it. The new search reads only shelf labels that match.

Review

The reviewer approved. There were no blocker or major findings.

  1. Minor: a lost rewrite on wide conjunctions. The first version checked only conjuncts over exactly the clause's symbols. The reviewer built a 1,000-wide QF_UFLIA conjunction whose middle conjunct was (= (f (* 0 y)) 1). Z3 simplified away y, so that conjunct was skipped. The clause got a cnf lemma over the whole assertion, and Lean ran out of heartbeats. A valid result could no longer be certified. That is a completeness loss, not a soundness bug. The fix also checks leaf conjuncts containing the clause's symbols. The repro is now a regression test that Lean accepts.
  2. Nit: a stale note. The plan still said FISCHER does not verify. Fixed.
  3. Nit: inconsistent figures. Comments quoted different call counts and times. All now use the measured 12,207 calls and 459 seconds.

Risks and open questions

  • An equivalent conjunct that is an and over extra symbols is still skipped. Its clause gets a larger cnf lemma. No test or swept input hits this.
  • A clause with no symbols, such as False, is still checked against every leaf, as before.
  • The FISCHER test adds up to half a minute to the Lean CI job.
  • GitHub CI results for the merge are unknown here.

What comes next

  • Descend from an implying and to its smallest implying conjunct, so cnf lemmas shrink. This is on the backlog.
  • The tta_startup inputs still fail in Lean. Arithmetic bridges between leaves are the proposed fix.

Glossary

assertion
A formula given to the solver with (assert ...). The input claims it is true.
assumed clause
A clause the clause log records as coming from the input, without a proof. The exporter must justify it from an assertion.
certificate
The exported record of a proof, which an independent checker can verify step by step.
clause
A disjunction of literals, such as p or not q.
clause log
Z3's record of the clauses it assumed and derived during solving, in order.
cnf lemma
A proved fact of the form "this formula implies this clause". Here it bridges an assumed clause to an assertion.
completeness
The ability to certify every correct result. Losing it means some valid results are left uncertified.
conjunct
One operand of an and. In A and B, both A and B are conjuncts.
equivalence
Two formulas are equivalent when each one is true exactly when the other is.
hash
A short number computed from data. Equal data gives an equal hash, so comparing hashes is a fast first test.
heartbeat
Lean's unit of work for a proof. A proof that uses more than its limit fails with a timeout.
implication
A implies B when B is true in every case where A is true.
leaf conjunct
A conjunct that is not itself an and, such as (<= x (+ y 1)).
literal
An atom or its negation, such as p or not p.
nested conjunction
An and whose operand is another and, many levels deep: (and a (and b (and c d))).
preprocessing
Simplification Z3 applies to the input before the main search, such as turning (* 0 y) into 0.
QF_IDL
The SMT-LIB logic of quantifier-free integer difference logic. Constraints compare differences of integers, such as x - y <= 3.
refutation
A proof that the assertions together lead to False.
rewrite
A proof step that replaces a formula by an equivalent one. Here it is the small bridge from a conjunct to an equivalent clause.
solver check
A call to a solver to test whether a claim always holds, by searching for a counterexample.
soundness
The guarantee that a certified result is really true. A soundness bug would let a wrong result pass.
suffix (of a nested conjunction)
The inner and that holds all conjuncts from some point onward. In (and a (and b c)), (and b c) is a suffix.
symbol
A declared constant or function name, such as x or f.
tactic
A Lean command that builds part of a proof automatically. omega handles integer arithmetic and grind does general case reasoning.
uninterpreted function
A function symbol with no fixed meaning. The only rule is that equal arguments give equal results. QF_UFLIA combines them with integer arithmetic.
