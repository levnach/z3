Skip suffix conjunctions in clause-log assume's equivalence search

Pull request levnach/z3#48 into master · state OPEN · 2026-10-30T08:05:54Z · loop iteration 48

This pull request is open and not merged. The change under review ends at commit a869d788a. It contains two commits.

In one paragraph

When the clause log is replayed, each assumed clause must be tied back to an input assertion. Before this PR, the replay ran an equivalence check against every conjunct that shared a symbol with the clause. On a deeply nested conjunction, that meant every suffix of the conjunction, and every check failed. Now it checks only conjuncts over exactly the clause's symbols, plus leaf conjuncts that contain them. A QF_IDL model-checking benchmark that spent minutes in these checks now exports in seconds. Lean accepts its refutation. Nothing new is trusted: every bridge from an assertion to a clause is still a rewrite or a cnf lemma proved in Lean.

Background

Before this PR, the replay tried three things in order for each clause. It looked for a matching key, then for an equivalent conjunct, then for an implying conjunct through an implication check. On FISCHER6-4-ninc, from the z3test smtlib-sample collection, the second step did over twelve thousand solver calls before the third step succeeded at once. The pipeline could certify this input in principle, but too slowly for practical use or CI. The backlog has listed it since iteration 45 as "Quadratic equivalence checks in assume". The work serves Milestone 3, equality and linear arithmetic, and the regression matrix that the plan calls the top priority.

What changed

Think of the assertion as a set of boxes nested inside each other, with the clause as one letter to find. Before, the replay opened every box that might hold the letter, including all the huge outer ones. Now it reads only the letters themselves and the boxes labeled with exactly the right names.

  • The replay no longer runs equivalence checks against nested and conjuncts whose symbol set differs from the clause's.
  • It still checks leaf conjuncts that contain all of the clause's symbols, so a conjunct where preprocessing dropped a symbol still gets a small rewrite bridge.
  • Inputs with 64 or fewer conjuncts behave exactly as before, because no symbol index is built for them.
  • The FISCHER benchmark is now test data, and a test pins its solver-call counts and checks its Lean proof.
  • A new QF_UFLIA test keeps the reviewer's thousand-wide case from regressing.

The code change lives in examples/python/proof_clause_log.py. There are no C++ changes and no Lean library changes. The plan document gained a dated note describing the new search order.

Review

The reviewer approved, with no blocker or major findings.

Minor: a dropped symbol lost its small bridge

The reviewer built a QF_UFLIA input with a thousand nested conjuncts. The middle one was (= (f (* 0 y)) 1), using an uninterpreted function f. Z3 simplifies that to (f 0), so the clause has one symbol fewer than its conjunct. The first commit skipped that conjunct, so the clause was tied by a cnf lemma over the whole assertion. Lean's tactics then ran out of heartbeats after four minutes. This mattered because a correct certificate failed to check, even though nothing unsound happened. The fix was the reviewer's first suggestion: also check leaf conjuncts that contain the clause's symbols. The case is now a regression test, and Lean checks it in seconds.

Nit: a stale note in the plan

An older plan note still said FISCHER did not verify, and one line was too wide. Both were fixed.

Nit: numbers that did not agree

Comments quoted 12,000, 12,200, and 12,207 calls, and 450 to 480 seconds. All now use the measured 12,207 calls and 459 s.

Risks and open questions

  • An equivalent conjunct that is itself an and over more symbols is still skipped. Its clause gets a larger cnf lemma instead of a rewrite. No test or swept input hits this.
  • The implication pass takes the first implying conjunct, often the whole assertion. That makes cnf lemmas bigger than needed.
  • A clause with no symbols, such as False, is still checked against every leaf.
  • The FISCHER test adds about 15 to 27 s to the Lean CI job and a 97 KB data file.
  • CI results were unknown when this report was written.

What comes next

  • Descend from an implying and to its smallest implying part, so cnf lemmas shrink. This is already on the backlog.
  • Fix tta_startup. It has been diagnosed, and arithmetic bridges between leaves over one linear form look like the next step.

Glossary

assertion
A formula stated as true in the input, written (assert ...).
Boolean
The sort with the two values true and false, Bool in SMT-LIB.
clause
A disjunction of literals, such as (or p (not q)). Here, one line of Z3's clause log.
clause log
Z3's record of the clauses it assumed, derived, and deleted while solving, replayed to build the certificate.
cnf lemma
A proof step stating that a formula implies a clause, such as "assertion implies (or a b)".
conjunct
One part of an and. In (and A B), both A and B are conjuncts.
equivalence check
A solver call asking whether two formulas are always both true or both false.
heartbeat
Lean's unit of work. A proof that uses more than its heartbeat budget fails with a timeout.
implication check
A solver call asking whether one formula being true forces another to be true.
leaf conjunct
A conjunct that is not itself an and, such as (<= x 5).
literal
An atom or its negation, such as p or (not p).
nested conjunction
An and whose parts are again ands, such as (and a (and b (and c d))). Each inner and is a suffix of the whole.
preprocessing
Z3's simplification of the input before search, such as turning (* 0 y) into 0.
QF_IDL
The SMT-LIB logic of integer difference constraints without quantifiers, such as (<= (- x y) 10).
QF_UFLIA
The SMT-LIB logic of uninterpreted functions and linear integer arithmetic, without quantifiers.
refutation
A proof that the assertions together imply False.
rewrite
A proof step stating that two formulas are equivalent, such as (f (* 0 y)) and (f 0).
solver call
One question handed to Z3 during export, here an equivalence or implication check with a time bound.
sort
The type of a value, such as Int or Bool.
symbol
A declared constant or function name, such as x or f.
tactic
A Lean command that builds part of a proof automatically, such as omega for integer arithmetic or grind.
uninterpreted function
A function with only a name and sorts, and no fixed meaning, such as (declare-fun f (Int) Int).
