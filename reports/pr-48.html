In one paragraph

When the exporter replays Z3's clause log, it must tie every assumed clause back to the input assertions. It first runs a solver check for a conjunct that is equivalent to the clause. Before this PR it tried every conjunct that shared a symbol with the clause. In a nested conjunction, that meant every suffix of a huge formula. Now it tries only conjuncts over exactly the clause's symbols, plus leaf conjuncts that contain them. A QF_IDL benchmark now exports in seconds instead of minutes, and its refutation checks in Lean. Nothing new is trusted. Every bridge is still a Lean-proved rewrite or cnf lemma.

Background

Iteration 45 let the pipeline export and reconstruct three very deep inputs. One of them, FISCHER6-4-ninc, was still impractical. Its export spent nearly all its time in failed equivalence checks in the replay step assume. PR #47 had already made and-elim steps cheap on such inputs, and this PR removes the next bottleneck. It serves milestone 3, "Equality and linear arithmetic", and the plan's priority on regression tests.

What changed

  • The replay now checks an assumed clause for equivalence only against conjuncts whose symbol set, compared by hash, is exactly the clause's.
  • It also checks single leaf conjuncts that contain all the clause's symbols, so a conjunct where Z3 simplified a symbol away still gets a cheap rewrite.
  • The second search, for a conjunct that implies the clause, is unchanged, so a skipped candidate is still tied and still proved in Lean.
  • The FISCHER input is now test data, and a test fails if its export needs more than a handful of solver checks or stops verifying in Lean.
  • A new QF_UFLIA test and new unit tests pin down which candidates get checked.

An analogy: you look for one sentence in a long book. The old search compared it with "page 1 to the end", then "page 2 to the end", and so on. The new search compares it only with single sentences that use the same words.

Review

The reviewer approved the change. There were no blocker or major findings.

Minor: a lost rewrite. The reviewer built a QF_UFLIA input with 1,000 nested conjuncts. The middle one was (= (f (* 0 y)) 1), with f an uninterpreted function. Preprocessing turns (* 0 y) into 0, so the assumed clause loses the symbol y. The first commit's filter then skipped the matching conjunct, and a cnf lemma over the whole assertion tied the clause. Lean ran out of its heartbeat budget on that lemma, so the result no longer verified. The fix, suggested by the reviewer, also checks leaf conjuncts that contain the clause's symbols. That input is now a regression test.

Nits. The plan still said FISCHER did not verify, and comments quoted inconsistent call counts and times. Both were fixed.

Risks and open questions

  • An equivalent conjunct that is itself an and over extra symbols is still skipped. It gets a cnf lemma, not a rewrite. No known input hits this.
  • The implication search takes the first implying conjunct, often the whole assertion. That makes cnf lemmas large.
  • The FISCHER test adds roughly 15 to 27 seconds to the Lean CI job.

What comes next

  • Descend from an implying and to its smallest implying conjunct, to shrink cnf lemmas.
  • Fix the tta_startup input, which was diagnosed in this iteration but not fixed.

Glossary

and-elim
A proof step that takes one conjunct out of a true conjunction. From A and B it gets A.
assertion
A formula the input states as true, written (assert ...) in SMT-LIB.
assumed clause
A clause the clause log introduces as given, rather than derived. The checker must show it follows from the assertions.
Boolean
The sort with exactly two values, true and false.
bridge
A proof step that connects an assumed clause to an input assertion, here a rewrite or a cnf lemma.
clause
A disjunction of literals, such as (or p (not q)).
clause log
Z3's record of the clauses it assumed and derived while searching for a refutation.
cnf lemma
A lemma of the form "this formula is false, or this clause holds". It shows the formula implies the clause.
congruence
The rule that equal arguments give equal function results. If a = b, then f(a) = f(b).
conjunct
One operand of a conjunction. In (and A B), both A and B are conjuncts.
equivalence
Two formulas are equivalent when they are true in exactly the same situations.
hash
A short number computed from data. Equal data gives equal hashes, so comparing hashes is a quick first test.
heartbeat
Lean's unit for counting work. A proof that needs more heartbeats than allowed is stopped as a failure.
implication
A implies B when B is true in every situation where A is true.
leaf conjunct
A conjunct that is not itself an and, such as (<= x 5).
literal
A Boolean atom or its negation, such as p or (not p).
nested conjunction
A conjunction built from many two-operand ands inside each other, such as (and A (and B (and C D))).
preprocessing
Simplification Z3 applies to the assertions before the main search, such as turning (* 0 y) into 0.
QF_IDL
The SMT-LIB logic of integer difference constraints, such as x - y <= 3, without quantifiers.
QF_UFLIA
The SMT-LIB logic of uninterpreted functions and linear integer arithmetic, without quantifiers.
refutation
A proof that a set of assertions leads to False, so they cannot all hold.
rewrite
A proof step showing two formulas are equivalent, so one may replace the other.
solver check
A call to Z3 that asks whether a formula can be false. If it cannot, the formula is valid.
sort
The type of a value, such as Int, Real, or Bool.
suffix
In a nested conjunction, the inner and that holds everything from some point to the end.
symbol
A declared name in the input, such as a constant x or a function f.
tactic
A Lean command that builds part of a proof automatically. omega solves integer arithmetic, and grind is a general search.
uninterpreted function
A function symbol with no fixed meaning. The only rule is congruence: equal arguments give equal results.
