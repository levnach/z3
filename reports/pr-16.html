In one paragraph

Before this PR, the legacy proof object path refused every input in the QF_LIA and QF_UFLIA fragments. Z3 had produced those proofs all along, but their steps had never been inventoried. This PR maps the three shapes they use: a theory lemma that is a cut, a division axiom resolved against the unit clause true, and a Farkas lemma whose coefficients do not add up over the rationals. Each ends in a lemma that Lean proves itself, so no new step is trusted. Congruence through integer division, modulo, and absolute value is handled too. Both proof sources now certify linear integer arithmetic refutations, with or without uninterpreted functions.

Background

The pipeline has two proof sources. The clause log has certified both integer fragments since iterations 12 to 14. The legacy proof object runs in process and needs no separate executable. It certified propositional, QF_UF, QF_LRA, and QF_UFLRA input, but rejected Int input with an explicit message. That gap had been on the backlog since iteration 12. The PR serves milestone 3 of the plan, equality and linear arithmetic, whose rule is to complete each fragment end to end.

What changed

  • Integer input is accepted. Running the exporter with --core legacy on QF_LIA or QF_UFLIA input now yields a certificate instead of a rejection.
  • Unverifiable coefficients are stripped. When a Farkas or bound step's coefficients do not re-derive the conflict over the rationals, the exporter drops them and leaves the step to Lean. Think of a receipt whose totals do not add up: rather than trust the numbers, the whole bill goes to the auditor.
  • Two new step shapes are checked. The reconstructor accepts a bare arith theory lemma with premises, which is how the legacy core states a cut, and a true-axiom rule whose unit clause true resolves away a false literal.
  • Congruence covers integer operators. Equal arguments to div, mod, or abs now give an equality proved as a Lean lemma, as for the Real operators.
  • The divisor rule is scoped to the statement. Z3's rewriter can produce an if-then-else term whose dead branch divides by zero inside a proof step. The nonzero-constant-divisor rule now applies to the assertions and their subterms, the only terms the theorem mentions.

Worked example

The input below is the QF_LIA test from the PR's exporter tests. Over the rationals it has solutions, such as x = 2/3 and y = 1/3. Over the integers it has none: each even sum must equal 2, so x + y = 1 and 2x − y = 1, which forces 3x = 2. The rational region is a thin sliver with no integer grid point inside it. Both runs use --core legacy, because the default source for Int input is the clause log, which already handled this file.

(set-logic QF_LIA)
(declare-const x Int)

(assert (>= (+ (* 2 x) (* 2 y)) 1))
(assert (>= (- (* 4 x) (* 2 y)) 1))

Review

The reviewer approved the change with no blocker, major, or minor findings and two nits. They reproduced every test result, ran the CI Lean matrix step, and probed fresh random instances through the legacy core with zero rejections. They also confirmed the soundness argument: coefficient stripping can only move a step from "re-derived in Python" to "proved by Lean", never skip a check.

  • Nit, fixed: a confusing rejection message. The message for a cut step with premises was ungrammatical and mentioned Farkas and bound steps, which may have premises. The reviewer's scenario of a Real certificate hitting it did not apply, but the text would mislead anyone debugging a certificate. It now speaks about cuts alone.
  • Nit, fixed: untested coverage. The two pinned random seeds each contain three congruence steps over div, but the test never asserted so. Had Z3's proof output changed, the test would keep passing while the new congruence code went untested. It now asserts such a step for both seeds.
  • Suggestion, deferred. The reviewer's probe stripped coefficients from few Farkas steps and from no bound step. A generator biased toward systems feasible over the rationals but not the integers would exercise that path. Recorded as a follow-up.

Risks and open questions

  • Nothing new is trusted. Every new step shape is shape-checked in Python and then proved by Lean. A test confirms that a false one is rejected without a proof being published.
  • The divisor rule is narrower. A division by zero inside an intermediate step is now allowed, because the theorem speaks only about the assertions, whose divisors are still checked.
  • Only one integer shape was seen. The hint names gomory-cut and gcd-test stay rejected until an input emits them, as does a bare arith step over Real.
  • Two rejection messages changed for Int input on the legacy path. The z3test harness is unaffected.
  • The bound path is thinly exercised. No pinned input yet reaches a stripped bound step through the legacy core.

What comes next

  • A random generator for rationally feasible, integer-infeasible systems, to exercise the cut path and the Lean-alone bound path on both cores.
  • The z3test matrix runner's legacy cell is still propositional-only and could take the documented QF_LIA and QF_UFLIA inputs now.
  • Map the still-rejected integer hint names when an input emits them.

Glossary

axiom
A statement accepted without proof. Here, Z3's definition of integer division, stating that x = 3 · (x div 3) + (x mod 3), which Lean then re-proves.
Boolean
A value that is either true or false, and the sort of such values.
certificate
The JSON file the exporter writes: Z3's proof steps, the terms they mention, and the original input, ready for an independent checker.
clause
A disjunction of literals, such as (or (not p) q). A clause is true when at least one of its literals is true.
clause log
Z3's second proof source: a text log of every clause the newer solver core learned, written by the z3 executable and replayed by the exporter.
coefficient
The number an inequality is multiplied by when several inequalities are added together. In a Farkas step the coefficients are the evidence that the sum is a contradiction.
congruence
If the arguments are equal, the results are equal: from a = b conclude f(a) = f(b). Z3 calls these proof steps monotonicity.
cut
An inequality that holds for every integer solution but cuts away part of the rational solutions, such as deriving x ≤ 1 from 2x ≤ 3.
Farkas lemma
The rule that a set of linear inequalities with no rational solution can be added up, with nonnegative coefficients, into the false statement 0 < 0 or 0 ≤ −1. Z3 labels such steps farkas.
fragment
A named subset of the SMT-LIB language, fixing which sorts and operators an input may use. QF_LIA and QF_UFLIA are fragments.
if-then-else term
A term written ite in SMT-LIB: (ite c a b) is a when the condition c holds and b otherwise.
legacy proof object
Z3's first proof source: the proof term built in memory by the older solver core when proof generation is on, read directly through the Python API.
linear integer arithmetic
Arithmetic over Int with addition, subtraction, and multiplication by a numeral only, plus comparisons. Here it also includes div, mod, and abs by a nonzero numeral.
literal
An atomic formula or its negation, such as x + y ≤ 1 or (not p).
premise
A statement a proof step relies on. The step's conclusion is justified only if all its premises hold.
QF_LIA
The fragment of quantifier-free linear integer arithmetic: Int variables, numerals, linear sums, and comparisons.
QF_UFLIA
QF_LIA together with uninterpreted sorts and uninterpreted functions, which may take and return Int.
refutation
A proof that a set of assertions implies False, that is, that they cannot all hold at once.
resolution
Combining two clauses, one containing a literal and the other its negation, into one clause without that literal. Resolving (or false l) with the unit clause true removes the false literal.
rewrite
A proof step stating that a term or formula equals a simplified form, such as 2x + 2y ≤ 3 being equivalent to x + y ≤ 1 over the integers.
sort
The type of a value, such as Int, Real, or Bool. An uninterpreted sort is one with no fixed meaning beyond equality.
tactic
A Lean command that searches for a proof automatically. Here omega decides linear integer arithmetic and grind handles the rest.
theory lemma
A clause that is valid by the rules of a theory, such as arithmetic, rather than by Boolean logic alone. Z3 labels these steps th-lemma with a hint naming the rule used.
uninterpreted function
A function symbol with no fixed definition, such as f in f(x) = f(y). Only congruence constrains it: equal inputs give equal outputs.
unit clause
A clause with exactly one literal. The unit clause true is the simplest possible fact.
