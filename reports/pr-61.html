In one paragraph

Before this PR, the exporter refused any input that declared both Int and Real variables. Such input is now accepted as a new fragment named qf_lira. The condition is that no term converts between the two sorts. Each atom then stays within one sort, and so does every theory lemma Z3 uses. The Lean theorem now takes two valuations. One sends Real variables to rational numbers, the other sends Int variables to integers. Every step of the refutation is still proved by the Lean kernel, so nothing new is trusted. This works on both proof cores, the proof object and the clause log. The PR also fixes a clause-log reader gap that hit every arithmetic fragment. Numerals and coercions that Z3 logs after an assertion folds to false are now read with the right sort.

Background

Before this PR, the pipeline certified linear arithmetic over Real and over Int separately. It also handled uninterpreted functions, if-then-else terms, abs, div, mod, and rem. Int lemmas were proved through Farkas lemmas and cuts. But one input could use only one numeric sort. An unsat input such as z3test's regressions/smt2/3277.smt2 was rejected outright. This PR serves milestone 3 of the project plan, "Equality and linear arithmetic". It is the first step toward full QF_LIRA, the step that needs no cast lemmas.

What changed

  • You can now certify an input with both Int and Real variables on either proof core, as long as no term converts between the sorts.
  • The Lean statement for such input reads each numeral, variable, ite, and abs in its own sort, so Int values never leak into Rat formulas.
  • Each theory lemma is proved on the Int path or the Real path, picked by the sort of its atoms, and a lemma over both sorts is rejected.
  • A plain QF_LRA input declared under logic ALL now exports through the clause log, because the reader understands the raw tail Z3 logs after a false assertion.
  • Conversions such as to_int, and both sorts next to uninterpreted functions, are still rejected with a clear message.

An analogy: think of two ledgers, one kept in whole euros and one in exact fractions. Boolean logic may link entries in both ledgers. But no single sum ever adds an entry from one ledger to an entry from the other. That is exactly the shape this PR certifies.

Worked example

The input is the lira_ite case from the new tests. One Boolean p selects an Int branch and a Real branch at once. Both outputs below come from real runs of the scripts on this input.

(a) The input

(set-logic QF_LIRA)
(declare-const x Real)
(declare-const n Int)
(declare-const p Bool)
(assert (= x (ite p 1.5 2.5)))
(assert (= n (ite p 3 4)))
(assert (or (> x 2.0) (> n 3)))
(assert (or (< x 2.0) (< n 4)))
(check-sat)

If p holds, then x is 1.5 and n is 3, which breaks the third assertion. Otherwise x is 2.5 and n is 4, which breaks the fourth.

Review

The reviewer approved the change. There were no blockers and no major findings.

Minor: an Int ite and a Real ite shared one representative

The reviewer built a wide rewrite with (ite p 1 2) over Int and (ite p 1.0 2.0) over Real. The two ites have the same value table, and the table key ignored the sort. So the Real atoms were printed over the Int ite, and Lean silently inserted a cast. The kernel still proved each lemma, so this was not a soundness hole. But it could make a valid proof fail to check. The fix adds the sort to the key, and a new test covers it.

Nit: the soundness argument was not restated

The README argued that reading Real variables as rationals is safe, but only for Real-only input. The fix extends it to inputs with Int variables: once the Int values and every atom's truth value are fixed, the Real part is a rational linear system. Such a system has a rational solution whenever it has a real one.

Nit: repeated work per lemma

The check that finds a lemma's sort walked the same nodes up to four times per lemma. Only qf_lira certificates paid this cost. The fix caches the answer per node.

Risks and open questions

  • If the clause-log reader gives a numeral the wrong sort, the term matches no input atom. The result is a rejection, not a wrong proof.
  • z3test's proof_lean.py still reports qf_lira inputs as unsupported, now with a different message.
  • The random generator covers only linear atoms and Booleans. It has no ite, div, mod, or abs yet.
  • The GitHub CI result on master after the merge is unknown to this report.

What comes next

  • Conversions: to_real of Int terms, to_int, and is_int. These need cast lemmas in Lean.
  • qf_lira next to uninterpreted functions.
  • A wider mixed generator with ite, div, mod, and abs.

Glossary

atom
The smallest true-or-false piece of a formula, such as (> x 2.0).
Boolean
The sort with exactly two values, true and false. A Boolean variable such as p can be used as a condition.
certificate
A file holding the evidence for an unsat answer, which a separate checker can verify.
clause log
A record of every clause a solver derives, step by step. A clause is an "or" of atoms or their negations.
coercion
A term that converts a value from one sort to another, such as (to_real 3).
cut
An Int step that rounds a bound, for example from n > 2.5 to n ≥ 3.
Farkas lemma
A proof that some linear inequalities conflict, by showing a weighted sum of them gives 0 < 0.
fragment
A named subset of the input language, such as QF_LRA: quantifier-free linear Real arithmetic.
if-then-else term
A term whose value depends on a condition, written (ite p 1 2) in SMT-LIB.
kernel
The small core of Lean that checks every proof step. It is the only part that must be trusted.
linear arithmetic
Arithmetic where variables are only added or multiplied by constants, such as 2x + 3y ≤ 5.
numeral
A constant number written in the input, such as 3 or 2.5.
proof object
Z3's older proof format: one tree of proof steps built in memory.
rational number
A fraction of two integers, such as 3/2. Lean calls the type Rat.
refutation
A proof that a set of assertions leads to False.
rewrite
A step that replaces a formula with an equivalent one, for example x > 2 by "not (2 ≥ x)".
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that builds a proof automatically, such as omega for integer arithmetic or grind.
theory lemma
A fact that holds because of arithmetic, not pure logic, such as "x < 1 or x > 0".
uninterpreted function
A function symbol with no fixed meaning. The only rule is that equal inputs give equal outputs.
valuation
An assignment of a value to every variable. Here, _vars gives Real values and _ivars gives Int values.
