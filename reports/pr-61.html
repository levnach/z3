Certify Int and Real arithmetic side by side (qf_lira) on both cores

Pull request levnach/z3#61 · State: OPEN · Opened 2026-11-02T17:31:44Z · Loop iteration 61

This pull request is open and not merged. The change it proposes is commit 38a90b2c6, on top of base 45e89a0c7.

In one paragraph

Before this PR, the exporter rejected any input that declared both Int and Real variables. Now such input is accepted as a new fragment, qf_lira, as long as no term converts one sort into the other. The generated Lean theorem now takes two valuations, one into the rationals and one into the integers. Every numeral, variable, if-then-else term, and theory lemma reads its sort from its own node. A theory lemma that mixes both sorts is rejected. The PR also fixes a gap in the clause log reader that broke some plain linear real arithmetic inputs. The kernel still checks every step of each refutation, so no new trust is added.

Background

Earlier iterations certified linear arithmetic over Int alone and over Real alone, including cuts, Farkas lemmas, abs, div, mod, and rem, on both proof cores. An input with both sorts failed at once with "mixing integer and real arithmetic is not supported". That was true even when every atom used only one sort. The project backlog named this disjoint case as the first step toward QF_LIRA, because it needs no conversion lemmas. The work serves Milestone 3 of the plan, "Equality and linear arithmetic", which asks to complete each fragment end-to-end before adding another.

What changed

  • Exporter. You can now export a certificate for an input with Int and Real variables side by side, as the opt-in qf_lira fragment. Conversions such as to_int, and both sorts next to an uninterpreted function, are still rejected.
  • Lean statement. The theorem now quantifies over two separate valuations. Think of two ledgers, one kept in whole coins and one in any fraction, with no exchange between them yet.
  • Per-lemma sort. Each theory lemma now takes the Int path or the Real path by the sort of its atoms, and a lemma over both sorts is refused.
  • Clause log reader. A plain QF_LRA input under logic ALL now exports even after an assertion folds to false, because the reader now handles the raw Int numerals and to_real coercions Z3 logs at that point.
  • Tests and docs. A new test module checks four hand-written inputs and four random ones in Lean on both cores, and the README and plan describe the new encoding.

Worked example

The input is lira_ite from the PR's new test module. One Boolean p picks a branch of a Real ite and an Int ite at once. Each choice of p makes both literals of one clause false.

(a) The input

(set-logic QF_LIRA)
(declare-const x Real)
(declare-const n Int)
(declare-const p Bool)
(assert (= x (ite p 1.5 2.5)))
(assert (= n (ite p 3 4)))
(assert (or (> x 2.0) (> n 3)))
(assert (or (< x 2.0) (< n 4)))
(check-sat)

Review

The reviewer approved the change with no blocker and no major finding. All three smaller findings were fixed in the second commit.

Minor: an Int ite and a Real ite shared one stand-in

The reviewer built a wide rewrite with (ite p 1 2) over Int and (ite p 1.0 2.0) over Real. Both have the same value table, so the reconstructor gave them one stand-in. Real atoms then mentioned the Int ite, and Lean accepted them only through a silent cast. This was not unsound, but in a rarer case a valid proof could have been rejected. The fix adds the sort to the table key, and a new test covers it.

Nit: a missing soundness argument in the README

The README justified modelling Real as rationals only for Real-only input. It now adds the argument for mixed input: with the integers fixed, the rest is a rational linear system.

Nit: repeated work per lemma

The per-lemma sort check walked the same nodes up to four times. It is now cached per node.

Risks and open questions

  • If the clause log reader gave a numeral the wrong sort, no input atom would match it. The result would be a rejection, not a wrong proof.
  • The z3test script proof_lean.py still reports qf_lira inputs as unsupported, now with a different message.
  • CI results and the loop's local gate were not yet available when this page was written.

What comes next

  • Conversions: to_real of Int terms, to_int, and is_int. These need cast lemmas in Lean.
  • Int and Real next to uninterpreted functions.
  • A wider random generator for mixed input, with ite, div, mod, and abs.

Glossary

atom
A formula with no Boolean connectives inside, such as (< x 2.0).
Boolean
The sort with exactly two values, true and false. p in the example is a Boolean.
clause
A disjunction of literals: at least one of them must be true. Example: (or (> x 2.0) (> n 3)).
clause log
A proof record that lists each clause the SAT core learns, with a hint saying why it holds. Here it comes from the sat.smt core.
conversion (coercion)
A term that turns a value of one sort into another, such as to_real from Int to Real.
cut
A step that uses the fact that a value is an integer to rule out fractions. Example: 2a = 2b + 1 has no integer solution.
Farkas lemma
A refutation of linear inequalities: adding them with nonnegative coefficients yields an obviously false one, such as 0 < 0.
fragment
A restricted part of a logic, named by what it allows. QF_LIRA means quantifier-free linear Int and Real arithmetic.
if-then-else term (ite)
A term whose value depends on a condition. (ite p 3 4) is 3 when p is true and 4 otherwise.
Int
The sort of mathematical integers, with no size limit.
kernel
The small core of Lean that checks every proof term. It is the only part that must be trusted.
linear real arithmetic (QF_LRA)
Constraints that add and scale Real variables by constants, without multiplying two variables.
literal
An atom or its negation, such as (> n 3) or (not p).
numeral
A constant number written in the input, such as 3 (Int) or 2.5 (Real).
proof core
One of the two places Z3 records a proof: the legacy proof object and the sat.smt clause log.
Real
The sort of real numbers. The Lean encoding uses rationals (Rat) for it, which is enough for linear constraints.
refutation
A proof that a set of assertions leads to False.
rewrite
A proof step that replaces a formula with an equivalent, usually simpler, one.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that builds part of a proof automatically. omega solves integer arithmetic, and grind is a general-purpose prover.
theorem
A named statement together with a proof that Lean checks.
theory lemma
A clause that holds because of arithmetic facts, not because of Boolean logic alone.
uninterpreted function
A function symbol with no fixed meaning. The only rule about it is congruence: equal inputs give equal outputs.
valuation
An assignment of a value to every variable. Here _vars gives the Real values and _ivars the Int values.
