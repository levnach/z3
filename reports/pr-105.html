Relate Lean is_int of nested Real chains to the rewriter's normal form

Pull request levnach/z3#105 · OPEN · opened 2026-11-09T21:07:04Z · loop iteration 105

This pull request is open and not merged. The change under review is commit c04cdfb16. It contains two commits on top of 39bdf1001.

In one paragraph

Some valid certificates from the clause log could not be checked in Lean. They applied is_int to a deep chain of nested if-then-else terms of sort Real. The rewriter replaces (is_int t) by a floor of t', the normal form of t. Nothing told Lean that t and t' are equal. So the tactic grind tried every case split of both chains and gave up. This PR makes the reconstructor state t = t' as a proved fact, one nesting level at a time. Lean can then link the two formulas by congruence. The same refutations now check in seconds, and the trust boundary does not move.

Background

Before this PR, the reconstructor related equal Real chains only as arguments of uninterpreted functions, including floors under them (PR #104). It ignored the term inside an is_int. It also skipped this step in certificates without uninterpreted symbols. So QF_LIRA inputs with is_int over deep chains failed in Lean, although the legacy core passed on them. The work serves Milestone 3, "Equality and linear arithmetic".

What changed

  • Clause-log certificates where is_int wraps a deep Real if-then-else chain now check in Lean.
  • Floored terms with one linear form now get an equality that Lean proves level by level.
  • This now works in certificates without uninterpreted symbols, whenever they contain to_int or is_int.
  • Large certificates pay little extra, because each formula's floored terms are cached rather than recomputed per lemma.
  • Tests now cover is_int compared directly and under a predicate p, on both cores.

An analogy: two recipes take different routes to the same cake. Before, Lean had to bake both to compare them. Now it gets a checked note per step saying both routes agree.

Review

The reviewer approved, with no blocker, major, or minor findings. Two nits and two suggestions came up.

  • Nit: nested floors are missed. The reviewer found that a to_int inside an if-then-else term, abs, or div is not collected. Such inputs keep the old behaviour. It limits completeness, never soundness, so it became a follow-up.
  • Nit: the new test reads printed Lean text. It finds formulas with regular expressions, so a printing change would break it. It was kept, because it would fail loudly rather than pass silently.
  • Suggestion: cache the floored terms. Without a cache, every lemma recomputed the linear forms of every reachable comparison. This was done in the second commit, and the output stayed byte-identical.
  • Suggestion: triage two old failures. Random inputs ite30 and ite35 fail in Lean both before and after the PR. They are not a regression and were recorded as a follow-up.

Risks and open questions

  • Certificates with a floor now always run the equality pass. Each fact cost 1–5 s on the tests, so a large benchmark with many pairs could run out of heartbeats.
  • A wrong pairing cannot be accepted. It only yields an equality that Lean fails to prove.
  • Depth 10 and above, and the legacy core at depth 8, were not checked.
  • CI and local-gate results were not available for this report.

What comes next

  • Collect to_int nested under if-then-else terms, abs, or div inside comparisons.
  • Speed up (p (<= (to_int a6) 3)) over Real chains, which verifies but takes 42 s and 3.25 GB.
  • Triage the QF_LIRA grind failures ite30 and ite35.
  • Finish the level-by-level _e bridges left open from iteration 104.

Glossary

Boolean
The sort with exactly two values, true and false. SMT-LIB calls it Bool.
case split
Proving a goal by trying each possibility in turn, such as "the condition is true" and "the condition is false". Six nested conditions can give dozens of cases.
certificate
A file Z3 emits that records the steps of its proof, so another tool can check them.
clause
A disjunction of literals, read as "at least one of these holds". Example: ¬A ∨ B ∨ C.
clause log
One of Z3's two proof sources. It records each clause the solver learns or uses, in order.
congruence
The rule that equal inputs give equal outputs. If t = t', then is_int t equals is_int t'.
floor
The largest integer not above a number. SMT-LIB writes it to_int, and Lean writes Rat.floor. Example: the floor of 7/2 is 3.
heartbeat
Lean's unit of work for a proof. Running out of heartbeats means the proof took too long.
if-then-else term
A term that picks one of two values by a condition, written ite in SMT-LIB. Example: (ite (< s 5) s (- s 5)).
is_int
The SMT-LIB test of whether a Real value is a whole number. It holds exactly when the floor of the value equals the value.
legacy core
Z3's older proof source, a proof object built during solving. The other source is the clause log.
lemma
A small proved statement used as a step toward a larger proof.
linear form
A sum of numbers times atoms, plus a constant, such as 2·x + 5. The reconstructor uses it as a key to spot equal terms.
literal
A formula that is an atom or the negation of an atom. Example: (is_int a6) or (not (is_int a6)).
normal form
The standard shape the rewriter gives a term. Two different-looking inputs can share one normal form.
predicate
A function that returns a Boolean, such as p : Bool -> Bool.
QF_LIRA
The SMT-LIB logic of quantifier-free linear arithmetic over both Int and Real. QF_UFLIRA adds uninterpreted functions.
refutation
A proof that a set of assertions leads to a contradiction, that is, to False.
rewriter
The Z3 component that simplifies formulas into normal form before solving.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that searches for part of a proof automatically. grind and omega are tactics.
theory lemma
A clause that holds because of arithmetic or another theory, not because of pure logic. Each needs its own Lean proof.
trust boundary
The set of things one must believe without proof. Here only Lean and its standard axioms are trusted. Every new fact is proved, so nothing is added.
uninterpreted function
A function symbol with no fixed meaning. The only rule it obeys is congruence. Example: (declare-fun f (Int) Int).
