Certify to_int and is_int in qf_lira proofs on both cores

Pull request levnach/z3 #63 · State: OPEN · Date: 2026-11-02T22:29:24Z · Loop iteration 63

This pull request is open and not merged. The change under review is commit 5aaa853. The PR holds two commits, and this page describes both.

In one paragraph

Z3 can now produce proof certificates for inputs that use to_int and is_int. These two operators take the floor of a Real term and test whether it is an integer. They live in the qf_lira fragment, where Int and Real sorts meet. Both proof cores are covered. In Lean, to_int t becomes Rat.floor t. Each theory lemma that touches a floor gets extra facts. These facts are instances of lemmas from Lean's core library, checked by the kernel. No new axiom and no sorry were added. So a refutation that reasons about floors can now be checked end to end.

Background

PR #62 let qf_lira certificates use to_real, the conversion from Int into Real. The two conversions out of Real were still rejected by the exporter on both cores. So a single to_int or is_int atom meant no certificate at all. One such input is the z3test regression issue-1608.smt2. Inputs that mix the conversions with uninterpreted functions were rejected then and still are. This PR serves Milestone 3 of the project plan, "Equality and linear arithmetic". It completes the conversions of the Int and Real linear arithmetic fragment.

What changed

  • The exporter now accepts to_int and is_int applied to linear Real terms, and labels such input qf_lira.
  • The reconstructor writes to_int t as Rat.floor t, and is_int t as "the floor of t, cast back to a rational, equals t", which is the SMT-LIB definition.
  • Every theory step that reaches a floor now gets the two floor bounds, ⌊a⌋ ≤ a < ⌊a⌋ + 1, as proved facts.
  • Floors of terms that differ by an integer are now related, so ⌊x + 1⌋ = ⌊x⌋ + 1 is available to the proof. Think of moving a ruler by one whole mark: the reading moves by exactly one.
  • The floor of a term that is already an integer, such as to_real n, is now stated to equal that integer. This was added after review.
  • Congruence steps through to_int and is_int on the legacy core now have Lean proofs.

Minor: the floor of an integer. The reviewer tried (not (is_int (to_real n))), where n is an Int. This is plainly contradictory, since an integer is always an integer. The exporter accepted it, but Lean failed on both cores. The floor bounds alone only placed the floor within one of n. So Lean's grind found a "model" where the floor was 2 and n was 3. That is not unsound, but an accepted input should not then fail. The fix adds the fact ⌊n⌋ = n through Rat.floor_intCast. Two new test inputs cover it, and a negative control confirmed they failed before.

Nit: reversed sides. The README wrote the is_int equation with its sides swapped, which would confuse a reader comparing it with generated Lean. It now matches.

Nit: the cap. Pairwise floor facts stop at 12 floors per step, but no test reached that cap. A new test now checks the behavior with 13 floors. The Lean cost just below the cap was not measured.

Risks and open questions

  • Integrality cuts through floors are still unsupported. An example is x and x/2 both being integers. This caused the 11 failing sweep runs. The clause-log core rejects these explicitly. The legacy core instead emits them as Farkas steps, which Lean then fails to prove.
  • Pure-Int steps over floors take the slower path. They are proved by the grind tactic instead of omega. Sweep inputs were small, so the cost at scale is unknown.
  • Extra facts on to_real steps. Each integrality fact now adds a cast fact, which also touches PR #62 inputs. The full suite still passes.
  • Cut shape mismatch. The exporter and reconstructor check cut shapes differently. Both reject.
  • Cost near the 12-floor cap is unmeasured.

What comes next

  • Support integrality cuts through floors with branch-and-bound facts taken from an untrusted LP value of each floor.
  • Reject those cuts explicitly on the legacy core, so both cores behave the same.
  • Align the cut shape checks of the exporter and the reconstructor.
  • Measure the Lean cost of a step just below the floor cap.
  • Try z3test regression 6196, which has several queries, with the --query option.

Glossary

atom
The smallest true-or-false statement in a formula, such as x <= 3 or (is_int x).
axiom
A statement accepted without proof. Adding one to a Lean proof means trusting it.
branch and bound
A way to handle integers: if a value v is fractional, split into the cases "at most ⌊v⌋" and "at least ⌊v⌋ + 1".
cast
A conversion of a value from one sort to another, such as the Int 3 to the Real 3.0.
clause
A disjunction of literals, for example "p or not q". At least one literal must hold.
congruence
The rule that equal inputs give equal outputs: if a = b, then f(a) = f(b).
cut
A step that uses the fact that a value is an integer to tighten a bound. From 2n < 3 it concludes n <= 1.
Farkas lemma
A proof that linear inequalities clash: multiply each by a non-negative number, add them, and get something false such as 0 < 0.
floor
The largest integer not above a number. The floor of 2.7 is 2, and the floor of −0.5 is −1. Written ⌊a⌋.
fragment
A restricted part of the input language that a tool supports, such as linear arithmetic without quantifiers.
hypothesis
An assumption a theorem starts from. Here each input assertion is one hypothesis.
Int
The sort of mathematical integers, with no size limit.
is_int
The SMT-LIB test of whether a Real value is a whole number. (is_int 2.0) is true.
kernel
The small, trusted core of Lean that checks every proof step. Tactics only propose proofs, and the kernel accepts or rejects them.
lemma
A proved helper statement used inside a larger proof.
linear arithmetic
Arithmetic where variables are only added and multiplied by constants, as in 2x + 3y <= 5, never x * y.
literal
An atom or its negation, such as x <= 3 or not (x <= 3).
proof certificate
A file that records how the solver reached its answer, so another program can check each step.
proof core
One of Z3's two internal sources of proofs. The legacy proof object records rules such as rewrite and unit resolution. The clause log records each learned clause with a hint.
qf_lira
Quantifier-free linear arithmetic with both Int and Real variables.
Real
The sort of real numbers. These proofs encode Real values as rationals, Lean's Rat.
refutation
A proof that a set of assertions leads to False, so they can never hold together.
sort
The type of a value in SMT-LIB, such as Int, Real, or Bool.
tactic
A Lean command that searches for a proof. omega handles integer arithmetic, and grind is a general-purpose search.
theory lemma
A clause the solver derives from a theory such as arithmetic, rather than from pure logic. Example: "x < 1 or x >= 1".
to_int
The SMT-LIB operator that maps a Real to its floor, an Int. (to_int 2.7) is 2.
to_real
The SMT-LIB operator that casts an Int to the equal Real. (to_real 3) is 3.0.
uninterpreted function
A function symbol with no fixed meaning, only a name and a signature. The solver may pick any meaning that fits the assertions.
