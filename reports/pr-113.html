Bind proof steps under hypotheses inside their one consumer in Lean

Pull request levnach/z3#113 · MERGED · 2026-11-11T03:09:01Z · loop iteration 112

Merged into master on 2026-11-11T03:09:01Z as commit cd47fe5, on top of base 46bd831.

In one paragraph

This PR changes only the layout of the Lean text that the reconstructor writes for a refutation. A proof step under a hypothesis is now written inside the one step that uses it, as a let binding without extra binders. Each outlined lemma now states its own step directly. Lemmas also take the interpretation as an implicit argument. The proof terms and the main theorem are unchanged, so the trust boundary is untouched. The text gets much smaller, and Lean's memory during elaboration grows with the text. As a result, the difference logic benchmark plan-21 now passes the Lean kernel check under the 8 GB memory cap.

Background

Before this PR, the pipeline already produced correct certificates for difference logic. But search-style refutations, with many unit resolutions under hypotheses, produced huge Lean files. plan-21 had failed with a kernel memory error since iteration 096. DTP_k2_n35 failed the same way. This work serves milestone 3, equality and linear arithmetic, at the size of real SMT-LIB benchmarks.

What changed

  • A step under hypotheses that exactly one other step uses is now written inside that step, so its hypotheses are not restated and it is not re-applied.
  • An outlined lemma's statement is now its own step, written as a fun over its hypotheses, instead of a copy bound a second time.
  • Importing a lemma is now just proof_step_N _inputs, because Lean infers the interpretation by itself.
  • The reconstructor now stops with a clear error if an interpretation binder cannot be made implicit, instead of writing a file Lean would reject.
  • New tests cover the nested layout, the depth limit of 32 nested steps, and the full plan-21 benchmark in the slow tier.

An analogy: printing a sub-recipe used once right inside its step saves a "see step 4" and a repeated ingredient list.

Review

The reviewer approved, with no blocker, major or minor findings. All three nits were fixed.

SeverityFindingResolution
nitBinders with parenthesised types silently stay explicitfixed: generation now fails
nitNo test reaches the nesting depth limitfixed: new test
nitGenerator docstring quoted the wrong seedfixed

The silent binder. The reviewer noticed that the pattern making binders implicit skips types with parentheses. Such a future binder would stay explicit, every lemma import would be ill-typed, and Lean would reject the certificate. Nothing current is affected. Now the reconstructor stops with a clear error instead.

The untested limit. The reviewer tried depth limits from 1 to a million. The limit of 32 never mattered on the tests, so Lean never checked the fallback. A new test sets the limit to 1, and Lean accepts the result.

The docstring. It quoted seed 1 while the test uses seed 2. It now gives both. A suggestion to record plan-21's peak memory was left as a follow-up.

Risks and open questions

  • plan-21 peaks at about 7.5 GB against an 8 GB cap. A Lean upgrade or a change in Z3's proof could push it over again.
  • Lemmas rely on Lean inferring the implicit interpretation from the type of _inputs. The main theorem passes it explicitly with @.
  • GitHub CI results for this change are not recorded here.

What comes next

  • DTP_k2_n35 still fails. It now gets through 11,991 of 17,084 lemmas, up from 7,921.
  • Most of what remains there is lemma imports, Or.elim resolution terms, and re-applied shared steps.

Glossary

atom
A formula with no Boolean connectives inside, such as b - a >= 2.
binder
A named parameter with a type, such as (_hyp41 : formula_41), introduced by a function or theorem.
certificate
A file of proof evidence that an independent checker can verify without trusting the solver.
clause
A disjunction of literals, such as (or p (not q)). It is true when at least one literal is true.
difference logic
Integer arithmetic where every atom bounds a difference of two variables, such as a - b >= 2. Its SMT-LIB name is QF_IDL.
elaboration
Lean's step that turns written text into fully explicit terms, filling in implicit arguments and checking types.
hypothesis
A fact assumed temporarily inside a proof. A later lemma step discharges it, for example by concluding its negation.
implicit argument
An argument written in braces, such as {_atoms}, that Lean fills in itself from the types of the other arguments.
interpretation
An assignment of values to the symbols of a formula. Here it is _atoms and _vars, which give each Boolean atom and integer variable a value.
kernel
The small trusted core of Lean that does the final type check of every proof.
lemma
A proved statement used inside a larger proof. In Z3's proofs, the lemma rule also turns a derivation of False from a hypothesis into the hypothesis's negation.
let binding
A local name for a value, written let x := v, usable in the lines that follow.
outlining
Splitting one long proof into many separate Lean theorems, here named proof_step_N, so each one stays small.
proof step
One inference in a proof, deriving a conclusion from earlier steps by one rule.
refutation
A proof that a set of formulas leads to False, so they cannot all be true together.
theorem
A named statement in Lean together with its proof. Lean checks the proof when the file is compiled.
trust boundary
The parts a reader must trust to believe a result. Here it is the Lean kernel and the statement of the main theorem.
unit resolution
The rule that removes false literals from a clause. From (or p q) and (not p) it derives q.
