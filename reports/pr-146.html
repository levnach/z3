In one paragraph

Z3 often logs a clause that it simplified under a unit. The reconstructor ties that clause to its source with one unit resolution. Before this PR, the Lean text for such a step opened one case split per kept literal and moved each literal back into its place. That text grew with the square of the number of kept literals. With 400 kept literals, Lean ran out of heartbeats and rejected the whole refutation. Now, when more than eight literals are kept in their original order, the exporter writes a short term that leaves every literal where it is. The term grows only in step with the clause. The same 400-literal input now produces a Lean file that the kernel accepts.

Background

Before this PR, the pipeline already certified this family of QF_LRA inputs at small sizes. The case-split text was correct, only too large. A resolution step that kept 400 literals became a single line of about 745 kB. Its outlined lemma hit Lean's limit after about 17 seconds. This iteration chose to remove a cost that grows faster than its input, rather than add a new theory. It serves the Boolean core of milestone 2, the kernel-checked Boolean slice, as it is reused by the clause log path of milestone 3, equality and linear arithmetic.

What changed

  • A unit resolution that keeps more than eight literals, in order, is now written as a term whose size grows linearly with the clause.
  • Literals cut at the front of the clause are removed one by one with Lean's Or.resolve_left, and nothing else is needed.
  • Literals cut further along are removed by one composed function that walks past each kept literal without opening a case split.
  • Two small helper theorems do the walking, and Lean checks them without any axiom.
  • Narrower or reordered resolutions are written exactly as before, so only six sample texts changed, and all six still verify in the same time.

An analogy helps here. Think of a row of 400 numbered boxes with one box to remove. The old text unpacked every box and repacked it on a fresh shelf, counting from the start each time. The new text simply says "skip this box" for each kept box and "remove this one" for the cut one.

The two helpers, as added to proof_to_lean.py:

private theorem resolve_first {p q r : Prop} (n : Not p) (f : q -> r) : p \/ q -> r :=
  fun h => f (h.resolve_left n)

private theorem resolve_rest {p q : Prop} (n : Not q) : p \/ q -> p :=
  fun h => h.resolve_right n

The first cuts the first literal of a disjunction and hands the rest on. The second cuts everything after the last kept literal.

Worked example

The input comes from the PR's new test helper wide_clause_under_a_unit(400). It has 400 Real variables. It is shown below with "..." for the repeated parts and with the assertion spread over three lines. The real file has one declaration per line and the whole assertion on one line.

(a) The input

(set-logic QF_LRA)
(declare-const b Bool)
(declare-const x0 Real)
...
(declare-const x399 Real)
(assert (and (not b)
             (or b (<= 1.0 x0) (<= 1.0 x1) ... (<= 1.0 x399))
             (< x0 1.0) (< x1 1.0) ... (< x399 1.0)))
(check-sat)

Each bound 1 <= xi is contradicted by xi < 1, and b is contradicted by not b, so no assignment satisfies the assertion.

(b) Before: the pipeline at the PR's base

The old certificate exporter succeeded. The old Lean exporter wrote its file, and Lean then rejected it after 16.9 seconds:

old.lean:9393:0: error: (deterministic) timeout at `isDefEq`, maximum number of heartbeats (200000) has been reached
...
Lean checking failed; no proof was published.

The case-split text for the one wide resolution step was too large for Lean to check within its default budget.

(c) After: the Lean text generated now

def formula_0 (_atoms : Nat -> Prop) (_vars : Nat -> Rat) : Prop := _atoms 0
def formula_4 (_atoms : Nat -> Prop) (_vars : Nat -> Rat) : Prop := ((term_2 _atoms _vars) <= (term_3 _atoms _vars))
...
def formula_804 (_atoms : Nat -> Prop) (_vars : Nat -> Rat) : Prop := ((term_3 _atoms _vars) < (term_2 _atoms _vars))
...

Each atom and bound of the input gets a definition. Here formula_0 is b, formula_4 is 1 <= x0, and formula_804 is x0 < 1.

def formula_1206 (_atoms : Nat -> Prop) (_vars : Nat -> Rat) : Prop := (Not (formula_1204 _atoms _vars))
def formula_1207 (_atoms : Nat -> Prop) (_vars : Nat -> Rat) : Prop := (Or (formula_1206 _atoms _vars) (Or (formula_4 _atoms _vars) (Or (formula_6 _atoms _vars) ...
...

formula_1207 is the wide clause: "the assertion is false, or 1 <= x0, or 1 <= x1, and so on up to x399".

private theorem proof_step_3213 {_atoms : Nat -> Prop} {_vars : Nat -> Rat}
    (_inputs : Inputs _atoms _vars)
    : (formula_3211 _atoms _vars) :=
  let _step_1205 := proof_step_1205 _inputs
  let _step_1208 : (formula_1207 _atoms _vars) :=
    (th_lemma_1208 _atoms _vars)
  let _step_1210 :=
    (_step_1208.neg_resolve_left _step_1205)
  ...

This is the new feature at work. _step_1210 cuts the first literal using the proof of the assertion, and the 400 kept bounds stay exactly as they stand, in one short line instead of 745 kB.

theorem unsat (_atoms : Nat -> Prop) (_vars : Nat -> Rat)
    (_h0 : (formula_1204 _atoms _vars))
    : False :=
  @proof_step_3213 _atoms _vars (Inputs.mk _h0)

The final theorem states that the input assertion implies False.

Lean accepted this file. The check printed "Lean checks passed." in about 11 seconds on the loop machine. In this input the only cut sits at the front, so the helpers resolve_first and resolve_rest are not needed here. They are exercised by the PR's hand-made test certificates, which cut literals in the middle and at the end.

Review

The reviewer approved the change. There were no blockers and no major findings.

  • Minor, fixed. The reviewer noticed that large proofs are split into a chain of Lean modules. No test checked the new helpers in such a chain, where they are declared in one file and used in a later one. A breakage there would only cause a rejection, never a false acceptance, but it would still lose a certificate. The integrator added a test that splits a certificate into four or more modules, and Lean accepts the chain with no axioms.
  • Nit, fixed. The plan document gave three counts of rewritten resolutions that came from different sample sets. A reader could not reconcile them. The document now says which set each count comes from.
  • Nit, partly fixed. The exporter decided whether to emit the helpers by searching the text for their names. The reviewer called that a fragile coupling. The search now looks only for an application, such as (resolve_first . No separate flag was added, because a wrong decision can only make Lean reject a proof.

Risks and open questions

  • The middle and end cuts, which use the helpers, are covered only by hand-made test certificates. No Z3-produced certificate in this iteration had such a cut.
  • A resolution whose result is the clause's tail is now bound without a stated type. Lean checks it where it is used. A consumer that needs the formula's name would reject it. None was found.
  • The limit of eight kept literals keeps sample texts unchanged. It is not a measured optimum.
  • Lean's time on this family is still superlinear because of a different step, the cnf lemma. At 1,600 bounds it took 408 seconds and 5.55 GB. Inputs with a few thousand literals still do not certify.

What comes next

  • The cnf lemma of a clause simplified under a unit is the first candidate in the backlog. It builds one bridge per literal, and its cost grows between the square and the cube of the clause.
  • Resolutions that keep two to eight literals remain case splits. Lowering the limit is in the backlog but not recommended on its own.
  • A conclusion that reorders a wide clause still costs the square of its width. This was not seen above eight literals in the sample.

Glossary

axiom
A statement Lean accepts without proof. A certificate that depends on no extra axioms trusts only Lean's own logic.
case split
A proof that handles "A or B" by proving the goal once assuming A and once assuming B. In Lean this is Or.elim.
clause
A disjunction of literals, such as b or (1 <= x0) or (1 <= x1).
clause log
A record Z3 writes of the clauses it learns and the inferences that justify them. The pipeline replays it to build a proof.
cnf lemma
A clause that holds because of how a formula is translated into clauses (conjunctive normal form). For example, "not (A and B), or A".
disjunction
An "or" of formulas. It is true when at least one part is true.
heartbeat
Lean's unit of work for elaboration. By default a declaration may use 200,000 of them before Lean stops with a timeout.
kernel
The small trusted core of Lean that checks every finished proof term.
lemma
A helper theorem proved on the way to the main result. The exporter outlines large proof steps into separate lemmas.
literal
An atom or its negation, such as b, not b, or 1 <= x0.
module
One Lean source file. Very large proofs are split into a chain of modules, each importing the one before it.
QF_LRA
The SMT-LIB logic of quantifier-free linear real arithmetic. Example: (<= 1.0 x0) with x0 of sort Real.
refutation
A proof that a set of assertions leads to False, so they cannot all hold.
theorem
A named statement together with a proof that Lean checks.
unit
A clause with a single literal, that is, a fact known to hold, such as not b.
unit resolution
An inference that removes literals from a clause using units that contradict them. From "b or c" and "not b" it concludes "c".
