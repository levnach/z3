In one paragraph

Some QF_LIRA refutations rest on an integrality cut through the floor of a Real term. An example is x = 5 while x/2 must be an integer. Before this PR, both proof cores failed on such steps. Now the reconstructor computes a projection of the step onto its Int atoms. It removes every Real atom exactly, by substitution and Fourier–Motzkin elimination. Each remaining constraint is stated over Int through an existing cast lemma, so Lean's tactic can see the integer contradiction. No new axiom, no new lemma, and no sorry were added. A wrong projection can only make Lean fail, never accept a false claim. On 400 random floor puzzles, every unsat run now verifies in Lean.

Background

After PR #63, the pipeline certified to_int and is_int in QF_LIRA on both cores. It still missed one shape of theory lemma: a cut whose literals mention a Real variable under a floor. The clause-log exporter rejected such a cut outright. On the legacy core, the step became a Farkas step without coefficients, and Lean's grind could not close it. The reason is that the rational relaxation of these steps has a solution. Of 162 runs over the unsat seeds 1–200, 11 had no verified certificate. This work serves Milestone 3 of the plan, "Equality and linear arithmetic", which completes each arithmetic fragment end to end.

What changed

  • The clause-log exporter now accepts a cut when some literal reaches an Int atom, and a floor counts as one.
  • The reconstructor applies the same rule, so the two shape checks now agree.
  • For a cut or a coefficient-free Farkas or bound step, the reconstructor now adds projection facts that tell Lean the integer consequence of the step.
  • The projection skips constraints it cannot read as linear, stays within a size limit, and states at most 16 facts per step.
  • New tests pin two hand-written inputs, two random seeds, and the new rejection and limit rules.

Think of the projection as a shadow. The Real variables are flattened away. The shadow keeps exactly the integer points that some real values can extend. The change is Python only. The C++ code of Z3 is untouched.

Worked example

The input is the PR's new test is_int_parity, with a check-sat line added. I ran it through the exporter and reconstructor at the merged commit, and through the scripts of the base commit.

(a) The input

(set-logic QF_LIRA)
(declare-const x Real)
(assert (is_int x))
(assert (is_int (/ x 2.0)))
(assert (or (= x 3.0) (= x 5.0)))
(check-sat)

If x and x/2 are both integers, x is even, so it cannot be 3 or 5.

Review

The reviewer approved. There were no blocker, major, or minor findings, only three nits. All three were fixed before merge.

  • Nit: the size limit came too late. The reviewer imagined a step with hundreds of bounds on one Real atom. Fourier–Motzkin pairs every lower bound with every upper bound, so thousands of rows were built before the limit applied. This only wasted time. The fix checks the limit before each round builds its rows, and a new test pins it.
  • Nit: the exporter and reconstructor disagreed. The exporter looked at raw syntax, so it counted an Int term hidden under a Real ite as an Int atom. The reconstructor then rejected the same cut later, with a less precise error. The fix makes the exporter follow the linear form, and Int numerals no longer count. Int atoms that cancel out still pass the exporter, but the reconstructor rejects them.
  • Nit: one bad constraint dropped all facts. If a single premise had no linear form, the projection gave up on the whole step. That cost completeness, not soundness. Now such a premise is left out, and the rest is still projected. A test breaks each premise of seed 5 in turn.
  • Suggestion, not done: pin an end-to-end test of a cut mixing a Real variable with an Int term. It is a listed follow-up.

Risks and open questions

  • The cut shape check is looser. An invalid cut is now caught by Lean instead of at export time. Soundness is unchanged, because Lean still proves every clause.
  • Some steps that verified before now carry extra projection facts. No slowdown showed up, but larger inputs were not measured.
  • Success depends on grind's Int module solving the projected problem. Every sweep case closed.

What comes next

  • Larger floor sweeps, with more variables, unbounded Real variables, and floors of sums.
  • A pinned test for cuts that mix Real variables with to_real of Int terms.
  • Projection facts on the generalized, combination, and split proof paths, which get none today.

Glossary

atom
A smallest term a linear constraint treats as one unknown, such as the variable x or the floor floor(x/2).
axiom
A statement Lean accepts without proof. Adding one would weaken the trust in a certificate.
cast
A conversion of a value from one sort to another, such as to_real turning the Int 3 into the Real 3.
clause
A disjunction of literals: at least one of them must be true. Example: not (x = 5) or not (x = 3).
cut (integrality cut)
A step that uses the fact that some quantity must be an integer to rule out fractional solutions. Example: from 2f = 5 with f an integer, conclude a contradiction.
Farkas lemma
The rule that a set of linear inequalities has no solution exactly when some nonnegative combination of them adds up to an obvious falsehood like 0 < 0. The multipliers are the "coefficients".
floor
The largest integer not above a number, written to_int in SMT-LIB. Example: the floor of 2.5 is 2.
Fourier–Motzkin elimination
A method that removes a variable from linear inequalities by pairing each lower bound with each upper bound on it.
lemma
A small proved statement used as a step inside a larger proof.
literal
An atomic formula or its negation, such as x = 5 or not (x = 5).
projection
The constraints that remain on some variables after the others are eliminated. Any solution of the projection extends to a solution of the original system.
QF_LIRA
The SMT-LIB logic of quantifier-free linear arithmetic over both Int and Real values.
rational relaxation
The same constraints solved over rational numbers, ignoring which values must be integers. It can have a solution even when the integer problem has none.
refutation
A proof that a set of assertions leads to False.
sort
The type of a value, such as Int, Real, or Bool.
sorry
A Lean placeholder that skips a proof. A certificate containing it proves nothing.
tactic
A Lean command that builds part of a proof automatically, such as omega or grind.
theory lemma
A clause that holds because of the rules of a theory, such as arithmetic, rather than by Boolean logic alone.
