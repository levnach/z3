Certify integrality cuts through floors of Real terms in qf_lira

Pull request: levnach/z3#64 · State: OPEN · Opened 2026-11-03T01:07:09Z · Loop iteration 64

This pull request is open and not merged. The change commit is 022e4eda9. It sits on top of the base commit 011a7409b.

In one paragraph

Some refutations in the QF_LIRA logic need an integrality cut that goes through the floor of a Real term. An example is x = 5 with x/2 an integer. Neither proof core could certify such a step before. Now the exporter and the reconstructor accept these cuts. The reconstructor also computes a projection of the step onto its Int atoms. It removes every Real atom exactly, using substitution and Fourier–Motzkin elimination. Each resulting constraint is handed to Lean as an instance of a lemma that Lean has already checked. Lean's tactic grind then finds the integer contradiction. The PR adds no axiom and no sorry. A wrong projection can only make Lean fail, never make it accept.

Background

PR #63 taught both proof cores to certify to_int and is_int in QF_LIRA. After it, 11 of 162 runs on random floor puzzles still had no verified certificate. Every one of them needed a cut through the floor of a Real term. The clause-log exporter rejected these with "cut hint over Real atoms". On the legacy core, a Farkas lemma step without coefficients reached Lean, and grind could not prove it. The rational relaxation of the step has a solution, so only integer reasoning finds the contradiction. This work serves Milestone 3 of the plan, "Equality and linear arithmetic", which asks that each arithmetic fragment be complete end to end.

What changed

  • The clause-log exporter now accepts a cut whenever some literal reaches an Int atom, and a floor counts as one. A cut over Real atoms alone is still rejected.
  • The reconstructor applies the same rule, so the two shape checks now agree on which cuts are allowed.
  • For such a cut, the reconstructor adds "projection facts": the step's constraints with every Real atom eliminated, restated over Int so that grind can reason about whole numbers.
  • Legacy-core Farkas and bound steps without coefficients get the same projection facts, which closes the three legacy failures.
  • New test inputs, random seeds, and validation tests pin the behavior, and the docs describe it.

An analogy: solve a system of equations for its one fractional unknown and plug it in everywhere. What remains talks only about whole numbers, so a whole-number solver can see that nothing fits. The elimination is capped at 200 constraints and 16 facts per step.

Review

The reviewer approved. They found no blocker, major, or minor issues, and three nits. All three were fixed in the second commit.

  • Nit: the size limit came too late. The reviewer pictured a step with 300 premises on one Real atom. Its first round would build about 22,000 rows before the limit applied. That wastes time but is never wrong. Now the limit is checked before each round, and a test pins it.
  • Nit: the two shape checks disagreed. The exporter read raw syntax. The reconstructor read the linear form. So an Int term under an if-then-else term of sort Real passed export and failed later. The exporter now follows the linear form too. Int atoms that cancel out are still counted, but the reconstructor rejects them clearly.
  • Nit: one bad constraint dropped all facts. A premise without a linear form made the whole projection give up. That costs completeness only. Now such a premise is left out, and a test checks that facts remain.
  • Suggestion, not done: an end-to-end test of a cut mixing a Real variable with an Int term. It is a follow-up.

Risks and open questions

  • The cut shape check is looser. Lean, not the exporter, now catches an invalid cut. Soundness is unchanged.
  • Steps that already verified now also get projection facts. No slowdown showed up in the tests.
  • Completeness depends on how far grind's integer reasoning reaches.
  • GitHub CI results and the local gate result are not known yet.

What comes next

  • Larger floor sweeps, with more variables, unbounded Real variables, and floors of sums.
  • A pinned test for to_real cuts that mix Real variables and Int terms.
  • Projection facts on the other proof paths, such as the generalized, combination, and split paths, which get none today.

Glossary

atom
A smallest unit that a formula or linear sum is built from, such as a variable x or the floor of x/2.
axiom
A statement Lean accepts without proof. Adding one would mean trusting it blindly.
Boolean
The sort with the two values true and false, written Bool in SMT-LIB.
certificate
A file of proof steps that an independent checker can verify.
clause
An "or" of literals, such as x ≠ 5 ∨ x/2 ≠ ⌊x/2⌋.
cut (integrality cut)
A lemma that is true only because some values are integers. Example: if x = 5, then x/2 cannot be an integer.
Farkas lemma
A proof that some linear inequalities cannot all hold, shown by adding them with nonnegative multipliers until you get 0 < 0.
floor
The largest integer not above a number. to_int in SMT-LIB, Rat.floor in Lean. The floor of 2.5 is 2.
Fourier–Motzkin elimination
A way to remove a variable from inequalities. Each lower bound is paired with each upper bound, and the variable cancels.
if-then-else term
A term that picks one of two values by a Boolean condition, written ite in SMT-LIB.
Int
The sort of integers: …, -1, 0, 1, 2, ….
is_int
The SMT-LIB test that a Real value is a whole number. (is_int 2.0) is true.
lemma
A proved statement used as a step inside a larger proof.
linear form
A term rewritten as a sum of atoms times numbers, plus a constant. x/2 + 1 has the form 0.5·x + 1.
literal
An atomic formula or its negation, such as x = 5 or not (x = 5).
premise
A fact that a proof step takes as input.
projection
What a set of constraints says about some variables once the others are eliminated. Like the shadow of a shape on a wall.
QF_LIRA
The SMT-LIB logic of quantifier-free linear arithmetic over Int and Real together.
rational relaxation
The same problem with the integer requirement dropped, so fractions are allowed. It can have a solution even when the integer problem has none.
Real
The sort of real numbers. The Lean encoding here uses rational numbers, Rat.
refutation
A proof that a set of assertions leads to False.
sort
The type of a value, such as Int, Real, or Bool.
sorry
A Lean placeholder that skips a proof. A trusted proof must contain none.
tactic
A Lean command that builds part of a proof automatically, such as omega or grind.
