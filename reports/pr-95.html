In one paragraph

The clause log replay now accepts applications of +, *, and distinct to a single argument, such as (+ x). Z3's parser keeps these terms exactly as written. When one assertion folds to false, Z3 logs the later assertions unsimplified. The replay then met these one-argument terms and stopped with "unsupported operator". Now it rebuilds each term as the very same hash-consed term the parser made. So the logged clauses still tie to the input's assertions. The certificate format and the Lean reconstruction did not change. A whole family of unsat inputs that used to be rejected now ends in a Lean theorem that Lean checks.

Background

Before this PR, the replay built + and * only with two or more arguments. It built distinct the same way. Inputs in the fragments QF_LIA, QF_LRA, QF_LIRA, QF_UFLIA, and QF_UF, and inputs over arrays, failed when a one-argument form appeared after a folded assertion. A random QF_LIA generator with Boolean structure, using ite and similar connectives, hit the failure on 8 of 89 unsat seeds. The problem had been on the backlog since iteration 62. This PR serves Milestone 3, "Equality and linear arithmetic", which completes each fragment end to end.

What changed

  • The clause-log replay now rebuilds (+ t), (* t), and (distinct t), so these inputs export instead of failing.
  • A sum with no arguments, or a sum of a Boolean, is still rejected, so a malformed log is still caught.
  • Six new test inputs, one each for LIA, LRA, LIRA, UFLIA, arrays, and pure uninterpreted functions, now go through export and through Lean.
  • A new test that needs only the Python bindings confirms that each rebuilt term equals the parser's own term.
  • The plan document has a dated note, and the README lists one-argument + and * in the qf_lra paragraph.

An analogy: a library matches a returned book by its exact catalog number, not its title. Reading (+ x) as plain x would change the number, and the match would fail. So the new table _ONE_ARGUMENT_HEADS rebuilds the exact term.

Worked example

This is the lia case of the PR's new tests. All outputs come from real runs on the merged code and its base.

(a) The input

(declare-const x Int)
(declare-const y Int)
(declare-const c Bool)
(assert (= c (not c)))
(assert (> (+ (* -2 x)) 2))
(assert (< (+ x y) (* (+ y))))

The first assertion can never hold, so it folds to false. The next two contain (+ (* -2 x)), (+ y), and (* (+ y)).

(b) Before: the base commit's exporter

proof_certificate.py: error: unsupported operator in the clause log: +

The old exporter exited with code 2, so the old Lean generator was never reached.

(c) After: the generated Lean file, trimmed

Review

The reviewer approved. There were no blockers, majors, or minors. Three nits were fixed, and one suggestion led to no change.

  • Nit, fixed: a check hidden behind a skip. The check that rebuilt terms equal the parser's terms sat in a test that skips without the z3 executable. It needs only the Python bindings, so it could silently never run. It is now its own test.
  • Nit, fixed: the Lean test skipped the usual checks. The new Lean test called a lower-level helper and skipped the check of one hypothesis per assertion. A future bug that dropped a hypothesis would then go unnoticed here. The class helper already returns the report, so the test now calls it.
  • Nit, fixed: a test name split over two lines. A search for the name failed, so it now sits on one line.
  • Suggestion, no change: distinct of any sort. The one-argument distinct is accepted for an argument of any sort. This matches the existing many-argument case. The fragment check still decides what reaches Lean.

Risks and open questions

  • The replay ties logged clauses to assertions by exact term identity. A test asserts that the rebuilt term equals the parser's term.
  • The newly certified inputs are refuted by the folded assertion alone. They are trivially unsat, though they were rejected before.
  • The PR merged on the local gate, which ran on macOS. GitHub CI results on Linux are not yet known to this report.

What comes next

  • Division or mod by a zero numeral in an otherwise trivially unsat input stays rejected. Lean's fixed x/0 = 0 is not a sound stand-in for Z3's unspecified value.
  • A possible timeout hazard in the omega tactic, from iteration 94, was not reproduced. It needs a generator with wide Boolean theory lemmas.

Glossary

application
A function or operator applied to arguments. (+ x y) applies + to two arguments, and (+ x) applies it to one.
array
A sort of maps from indices to values, read with select and updated with store.
assertion
A formula the input states as true, written (assert ...) in SMT-LIB.
Boolean
The sort with the two values true and false, written Bool.
certificate
The JSON file that records the input's terms and the proof steps, for an independent checker to verify.
clause
A disjunction of literals, such as (or p (not q)). It holds if at least one literal holds.
clause log
The record of clauses and their justifications that Z3's SAT-based core writes while it solves.
distinct
The SMT-LIB operator that states all its arguments differ. With one argument it is simply true.
fold
To simplify a term to a constant. (= c (not c)) folds to false.
fragment
A named subset of SMT-LIB, such as QF_LIA, quantifier-free linear integer arithmetic.
hash-consing
Storing each distinct term once, so two equal terms are the same object and compare by identity.
hypothesis
An assumption a theorem takes as input. Here each assertion becomes one hypothesis.
if-then-else term
A term that picks one of two values by a condition, written (ite cond a b).
lemma
A small proven statement used as a step inside a larger proof.
literal
An atom or its negation, such as p or (not p).
refutation
A proof that the assertions together imply false.
replay
Reading a log step by step and rebuilding each term and clause, to connect the log to the input.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that builds part of a proof automatically. omega decides linear integer facts.
term
An expression that denotes a value, such as (+ x 1).
theorem
A statement together with a proof that Lean has checked.
uninterpreted function
A function declared only by its sorts, with no definition. The solver knows only that equal arguments give equal results.
