In one paragraph

This PR lets two more kinds of inputs pass through the clause log into a checked certificate. Both appear when one assertion simplifies to false and Z3 then logs the later assertions unsimplified. First, the replay now leaves out the clauses that the arithmetic solver states about a division by zero. Second, the reconstructor now proves the gate clause of an if-then-else term whose condition is a constant. Of 244 random QF_UFLIA unsat inputs, 27 were rejected for these reasons, and all 27 now verify in Lean. No axiom is added, and the final theorem still has exactly the input's assertions as hypotheses.

Background

Before this PR, the pipeline certified Int div, mod, and rem by a nonzero numeral, and gate clauses of ordinary ite terms. It failed when an earlier assertion folded to false and the log was replayed without trimming. Then a divisor written as a constant expression, such as (- 3), reached the arithmetic solver before the rewriter folded it. The replay rejected the log, and a gate clause for (ite true a b) was rejected as invalid. The refutation used none of these clauses. The work serves milestone 3, equality and linear arithmetic.

What changed

Clause-log replay

  • You can now certify an Int division by a constant expression after a false assertion, because the solver's division-by-zero clauses are skipped.
  • A log is still rejected when it assumes such a clause, or when a later step needs a skipped one.
  • An input may declare its own function named div0, and the argument sorts tell it apart from Z3's.

Lean reconstructor

  • The gate clause of an ite with a constant condition is now proved from the branch that holds, with no case split.

Tests and documentation

  • New inputs, random seeds, and a pinned log guard both fixes, and the plan and README describe them.

An analogy for the first change: an auditor strikes out side notes the ledger cannot express. If the final total depends on a struck note, the audit fails.

Review

The reviewer approved the change with no blocker, major, or minor finding. All four nits were fixed before the merge.

  1. Nit, fixed: a namesake function. The reviewer declared an uninterpreted function named div0 next to a division by (- 3). The replay mistook Z3's own application for the input's and rejected an input Z3 solves. It now compares the argument sorts with the declared ones.
  2. Nit, fixed: a misplaced error message. The message about an assumed clause came from code that does not know its caller. It is now raised where a clause is assumed, and it names the literal.
  3. Nit, fixed: a stale comment. The gate lemma's documentation now describes the decided case.
  4. Nit, fixed: a test that could not fail. One new test passed on the old code, because it only pinned the shape of Z3's log. It now also reconstructs each certificate, so it fails on the base.

Risks and open questions

  • No soundness risk was identified. Leaving a clause out can only cause a rejection.
  • Divisions by zero are recognized by name and spelling. A wrong guess can drop or reject a clause, never admit one.
  • Lean must still prove the unused guarded division lemmas, so a former rejection could become a Lean failure.
  • Only logs short enough to be replayed untrimmed show either case.
  • Unknown: the CI result on master, and whether the two live-log tests find a z3 executable in the Python wheel job.

What comes next

  • Old-style recognizers such as (is-A x) in unsimplified assertions are still rejected.
  • An Int abs nested in a Real term, without a declared logic, is still rejected when unsimplified.
  • Unused lemmas of an untrimmed log are still proved in Lean, which costs time and could fail.

All three are in the loop's backlog.

Glossary

assertion
A formula the input states must hold, written (assert ...) in SMT-LIB.
axiom
A statement accepted without proof. This PR adds none.
case split
A proof step that considers a condition true, then false, and proves the goal in both cases.
certificate
A file of evidence for a result that an independent checker can verify without trusting the solver.
clause
A disjunction of literals, such as "a or not b or c".
clause log
The list of clauses a solver writes while it works: assumed, inferred, and deleted ones.
constant expression
A term with a fixed value that is not written as a single number. Example: (- 3) or (+ 1 2).
division by zero
SMT-LIB leaves (div t 0) unspecified: it may be any value. Z3 names that value with internal functions div0 and mod0.
gate clause
A clause that defines a compound term by its parts, also called a Tseitin clause or definitional axiom. Example: "not c, or (ite c a b) equals a".
hypothesis
An assumption a theorem is allowed to use. Here the hypotheses are the input's assertions.
if-then-else term
A term (ite c a b) that equals a when c is true and b otherwise. It is "decided" when c is a constant.
literal
An atomic formula or its negation, such as (= x y) or (not (= x y)).
numeral
A number written out as digits, such as 3.
QF_UFLIA
The SMT-LIB logic of quantifier-free formulas over uninterpreted functions and linear integer arithmetic.
refutation
A derivation of a contradiction from the assertions. It shows they cannot all hold.
replay
Re-deriving each logged clause step by step, to turn a clause log into a proof.
rewriter
The solver component that simplifies terms before solving. Example: it turns (- 3) into the numeral −3.
sort
The type of a value, such as Int, Real, or Bool.
theorem
A statement together with a proof that Lean has checked.
theory lemma
A clause that holds by the rules of a theory such as integer arithmetic. Example: "d equals 0, or d times the quotient plus the remainder equals the dividend".
trimming
Cutting a clause log down to the clauses the refutation depends on.
uninterpreted function
A function the input declares with no built-in meaning. Only its argument and result sorts are known. Example: (declare-fun f (Int) Int).
