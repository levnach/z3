Check the arith solver's div, mod and abs axioms natively

Pull request levnach/z3#44 · State: OPEN · Opened 2026-10-29T18:02:32Z · Loop iteration 44

This pull request is not merged. The change described here is commit 3944722f0, which sits on top of a second commit in the same pull request.

In one paragraph

Z3's arithmetic solver adds some theory axioms about div and mod, abs, and division by a numeral. Each one is a clause written to the clause log with a bare arith hint. Z3's own native checker had no rule for that hint. So every such step went to the SMT fallback, which asks Z3 to re-solve the step. This PR teaches the native checker to check these axioms directly with linear arithmetic. On the arithmetic test generators, all 5,213 fallback steps of this kind are now checked natively. The Lean certificates do not change, because Lean already re-proved these steps. The gain is that Z3's native certificates no longer lean on a fallback for them.

Background

Before this PR, the native checker handled Farkas lemma hints, congruence hints from euf, and RUP steps. It had no checker plugin named arith. Every arith-hinted clause of a refutation became a verified-smt step. The Python replay and Lean were not affected. This work serves Milestone 3, "Equality and linear arithmetic", which asks for checked side conditions and native evidence wherever replay needs it.

What changed

  • The native checker now accepts the identity u = k*(div u k) + (mod u k) for any nonzero integer numeral k, without the fallback.
  • It also accepts the bounds 0 <= (mod u k) <= |k|-1 and the real-division fact q*(p/q) = p for a nonzero numeral q.
  • It accepts the two case splits of abs, such as "x < 0 or (abs x) = x".
  • Anything else under arith is still rejected and still falls back, for example a zero or symbolic divisor, to_int, or a nested mod.
  • The proof trimmer keeps working on these steps, and its test for hints that have no checker is still covered.

One detail needed care. A division axiom's hint can start with true. That true stands for the literal q = 0, which is false and so is left out of the log. The checker now drops it, so the clause it reports matches the logged clause.

Worked example

This PR changes the native C++ checker only. Lean reconstruction is unchanged, so no new Lean file is produced. The example below therefore shows the real native hint and the checker's output before and after. The input is the "small mod" input of the PR's new Python test, written as a file.

(a) The input

(declare-const x Int)
(declare-const y Int)
(assert (< (+ (* 2 (abs x)) y) 1))
(assert (> y 0))
(assert (> (mod x 3) 0))
(check-sat)

Since y > 0 and 2*|x| + y < 1, x must be 0, but then mod x 3 is 0, so the formula is unsat.

Running Z3 with clause logging on the current build produced three arith steps. Here they are, cut from the log:

(define-const $16 Int (mod x 3))
(define-const $39 Int (div x 3))
(define-const $40 Int (* 3 $39))
(define-const $41 Int (+ $40 $16))
(define-const $43 Bool (= $41 x))
(declare-fun arith (Bool) Proof)
(define-const $44 Bool (not $43))
(define-const $45 Proof (arith $44))
(infer $43 $45)
(define-const $42 Bool (>= $16 0))
...
(infer $42 $47)
(define-const $48 Bool (<= $16 2))
...
(infer $48 $50)
...

Each infer line adds a one-literal clause. They say 3*(div x 3) + (mod x 3) = x, (mod x 3) >= 0, and (mod x 3) <= 2.

(b) Before

The same log was replayed by an older Z3 binary kept from loop iteration 43. It was built from commit c95b61cb0, an ancestor of this PR's base. The arithmetic checker file is identical in the two commits. The exact base binary could not be rebuilt in this session. The first fallback reads: 

(proofs +tseitin 2 -arith 1)
(verified-smt
(arith (not (= (+ #54 #52) x)))
 (= (+ (* 3 #53) (mod x 3)) x))
...
(proofs +tseitin 2 +farkas 3 +euf 4 +rup 5 -arith 3)

The -arith 3 count means three steps had no native check and went to the SMT fallback.

(c) After

The current build replays the same input's log natively:

(proofs +tseitin 1)
(proofs +tseitin 2)
(proofs +tseitin 2 +arith 1)
(proofs +tseitin 2 +arith 2)
(proofs +tseitin 2 +arith 3)
...
(proofs +tseitin 2 +arith 3 +farkas 3 +euf 4 +rup 5)

All three axioms are now counted as +arith, with no verified-smt lines and no minus counts.

Review

The reviewer approved the change. There were no blockers and no major findings.

  1. Minor: a guard lost its test. An older test checked that the trimmer survives a hint with no checker plugin. It used arith as that hint. The reviewer noticed that arith now has a plugin, so the test no longer reached the guard. If someone later removed the guard, Z3 could crash again and no test would notice. The fix renames the hint to unchecked in a copy of the log. The integrator removed the guard on purpose, saw the test fail with a crash, then restored it.
  2. Nit: a stale comment in the trimmer. It still named arith as a hint without a plugin. A reader could have drawn the wrong conclusion about which path these steps take. Fixed.
  3. Nit: wrong origin in test comments. Comments said the axioms came from the legacy solver core. The reviewer ran the legacy core and found it logs them under a different hint. The comments now name the sat.smt arithmetic solver. Fixed.
  4. Nit: hidden coverage gap. The Python input described as "mod/abs" logged no abs axiom at all, as the example above also shows. Only one other input covered abs, and silently. The integrator found that Z3 rewrites abs away in small inputs. The test now asserts that the remaining input really logs an abs case. Fixed.

One cosmetic suggestion was not taken: releasing some temporary terms earlier. They are released at the next reset anyway.

Risks and open questions

  • The native checker now accepts more steps. A wrong acceptance would be a soundness bug in Z3's native certificates. It would not affect Lean certificates, because Lean re-proves every step. The negative unit tests and the two fuzz runs are the main safeguards.
  • The trimmer now treats arith hints like Farkas and euf hints. When the hint's clause is longer than the logged one, it uses the hint's clause. The true case is handled. The Lean division suites passed with no trimming warning.
  • The PR was not run on Windows, according to the review.

What comes next

  • Three large SMT-LIB samples fail Lean export with "maximum recursion depth exceeded". The PR names these as the best next candidates.
  • Some arith shapes still fall back: to_int, is_int, powers, rem, and symbolic divisors. None appeared in the generators.

Glossary

abs
The absolute value of a number. (abs -3) is 3.
bound
An inequality that limits a term from above or below, such as (mod x 3) <= 2.
case split
A clause that covers two cases. For abs: either x < 0, or (abs x) = x.
certificate
A record of a proof that a separate checker can verify without trusting the solver.
clause
A disjunction of literals: at least one of them must be true. Example: (not p) or q.
clause log
A file where the solver writes each clause it learns or adds, in order, with a hint for each.
congruence
The rule that equal arguments give equal results: if a = b then f(a) = f(b).
cut
An integer step that rounds a bound, such as going from 2x <= 5 to x <= 2.
div and mod
Integer division and remainder. (div 7 3) is 2 and (mod 7 3) is 1.
Farkas lemma
A proof that some inequalities conflict: adding them with non-negative weights gives a false fact like 0 < 0.
hint
A label on a logged clause that says which rule justifies it, such as farkas or arith.
linear arithmetic
Arithmetic with sums of variables times constants, but no variable times variable.
literal
An atomic formula or its negation, such as x >= 0 or (not (x >= 0)).
native checker
Z3's own C++ code that re-checks each step of a clause log.
numeral
A constant number written in the formula, such as 3 or 2.0.
refutation
A proof that a set of formulas leads to a contradiction, so they cannot all be true.
RUP
Reverse unit propagation: a clause follows if assuming its negation lets simple propagation reach a conflict.
SMT fallback
When no native rule applies, the checker asks Z3 itself to confirm the step. It is reported as verified-smt.
soundness
A checker is sound if it never accepts a wrong step.
theory axiom
A clause that is true by the meaning of the theory's operations alone, like (mod x 3) >= 0.
trimming
Removing steps from a proof log that the final contradiction does not need.
