In one paragraph

This PR changes one number in the Lean reconstructor. A theory lemma that is a cut, or a Farkas lemma or bound step without coefficients, is proved over its atoms after generalization by the grind tactic, which works on the integer lattice. Such a lemma now gets two million heartbeats instead of one million. The newer simplex in upstream Z3 produces a different refutation for one pinned test input, and one of its cuts, with 25 distinct literals, ran out of heartbeats, so the upstream pull request failed its Lean step. With the larger budget the same file verifies. Nothing new is trusted: a budget only bounds work, and a false lemma still fails.

Background

Before this PR the pipeline already certified linear integer arithmetic inputs with div, mod, and abs terms, and mixed inputs with an uninterpreted function. Each theory lemma is tried first over its generalized atoms and then, if that fails, with every atom unfolded. Lemmas with coefficients go to omega, lattice lemmas go to grind, and every lemma had the same one-million-heartbeat budget. That was enough for every proof the fork's own Z3 produced. Upstream CI tests the branch merged with upstream master, where the solver searches differently, and there one cut over thirteen atoms exhausted the budget. The work serves milestone 3 of the plan, equality and linear arithmetic.

What changed

  • Lattice lemmas get a bigger budget. A cut, or a coefficient-free Int Farkas or bound lemma, proved over generalized atoms now runs under two million heartbeats. Think of heartbeats as fuel: a bigger tank lets the tactic finish a long road, but it can never make a wrong road arrive.
  • Every other lemma is unchanged. Coefficient lemmas proved by omega, the unfolded fallback, rewrites, and Boolean lemmas keep the million.
  • A new helper names the shape. The function _lattice_step recognizes an Int theory lemma whose only parameter is a hint of kind cut, farkas, or bound.
  • Tests pin the budget. The lemma-shape test expects the budget per hint kind, the seed-67 division test asserts it and explains the upstream failure, and the QF_UFLIA seed-75 test asserts it for cuts.
  • The plan records why a race was rejected. See the Review section.

The main theorem takes the four assertions as hypotheses and derives False from the lemmas.

private theorem th_lemma_133 (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    : (formula_132 _atoms _vars) := by
  unfold formula_132 formula_131 formula_130 term_125 term_124 term_123 term_62 term_40 term_13 term_5
  first
    | (have _m0_0 : ((0 : Int)) <= (term_114 _atoms _vars) := by unfold term_114 term_62 term_13 term_6; exact Int.emod_nonneg _ (by decide)
       have _m0_1 : (term_114 _atoms _vars) < ((2 : Int)) := by unfold term_114 term_62 term_13 term_6; rw [Int.emod_neg]; exact Int.emod_lt_of_pos _ (by decide)
       revert _m0_0 _m0_1
       generalize (term_114 _atoms _vars) = _o0
       generalize (term_102 _atoms _vars) = _o1
       grind (splits := 64))
    | (unfold term_114 term_102 term_62 term_33 term_13 term_6 term_1
       first | omega | grind (splits := 64))

This is the cut. It states the two mod bounds, replaces both atoms by fresh integers, and lets grind decide the lattice goal under the new budget. If that fails, it unfolds everything and tries omega, then grind.

Review

No reviewer report was recorded in this iteration's inputs. The PR body carries one self-review that reads like a finding. The author first tried the obvious fix: run omega, which proves the failing cut in under a second, before grind, under a small budget so it would give up fast on cuts it cannot do. That broke six other lemmas in the same file. A heartbeat timeout in Lean is a runtime exception, and the first combinator does not catch it, so the timeout failed the whole lemma instead of moving on to grind. It mattered because the iteration-29 case is the mirror image, a twenty-atom cut where omega took minutes and grind took a second. Neither tactic dominates. The resolution was the budget increase alone, with the race recorded as open work in the plan.

Risks and open questions

  • Twice the wasted work on a hopeless lemma. A false lattice lemma now burns up to two million heartbeats before the fallback runs. That is tens of seconds, not a soundness risk.
  • The seed-67 test tracks the solver's search. The next simplex change may move the proof again. The budget has about a third of headroom over the observed need.
  • The local gate tests fork master alone. Solver drift upstream shows only in upstream CI.
  • One budget for both tactics is a stopgap. A real race between omega and grind needs a tactic that catches runtime exceptions, hence a heavier import in every generated file.

What comes next

  • Decide whether a budget race with Lean.Core.tryCatchRuntimeEx is worth the heavier import.
  • Consider a loop gate that builds the fork merged with upstream master.
  • Watch the upstream pull request's Lean step now that the budget is in place.

Glossary

atom
The smallest formula, with no Boolean connective inside. In arithmetic, also an integer term treated as a unit, such as x mod -2.
bound
A theory lemma hint saying a variable or term lies above or below a constant, as in 0 <= x mod 3.
Boolean
The sort of truth values, true and false.
clause
A disjunction of literals, such as A or not B or C. A refutation is built from clauses.
cut
An inference valid only over integers. Example: from 2x <= 3 conclude x <= 1, which fails over the reals.
div, mod
Integer division and remainder. SMT-LIB fixes the remainder to be non-negative, even for a negative divisor.
Farkas lemma
A contradiction obtained by adding inequalities with non-negative coefficients until 0 < 0 appears. The coefficients are the certificate.
generalization
Replacing a term in a goal by a fresh variable, so the tactic no longer sees inside it. Here, x mod -2 becomes an unknown integer with its known bounds.
grind
A Lean tactic that combines case splitting, congruence closure, and an integer arithmetic module that works on the integer lattice.
heartbeat
Lean's unit of work, roughly thousands of small memory allocations. The option maxHeartbeats stops a proof attempt that exceeds the budget.
hint
The label Z3 attaches to a theory lemma saying how it was found, such as farkas, bound, cut, or euf.
integer lattice
The grid of integer points inside the real solutions of a set of inequalities. Reasoning about which grid points exist is what makes integer problems harder than real ones.
linear integer arithmetic
Formulas over integer variables with addition and multiplication by constants. SMT-LIB calls the quantifier-free fragment QF_LIA.
literal
An atom or its negation.
omega
A Lean decision procedure for linear integer arithmetic. It is complete for that fragment but can be slow on goals with many case splits.
refutation
A proof that a set of assertions cannot all be true, ending in the empty clause or False.
simplex
The algorithm Z3's arithmetic solver uses to find or rule out real solutions of linear constraints. Changes to it change which proof Z3 finds.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that builds part of a proof automatically, such as omega, grind, or unfold.
theory lemma
A clause Z3's arithmetic or equality solver asserts as valid, which the Lean file must prove on its own. Written th-lemma in the certificate.
uninterpreted function
A function symbol with no definition, only the rule that equal arguments give equal results. Example: f in (declare-fun f (Int) Int).
