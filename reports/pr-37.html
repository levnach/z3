In one paragraph

This PR changes how the Lean reconstructor proves the propositional part of a normalized linear rewrite, which relates a wide disjunction as written to its flattened form. Before, a small search tried to build a proof term and otherwise handed the whole equivalence to the grind tactic. Now the existing propagation prover builds the term. Every conjunction and disjunction inside it is named once by a let binding, and a true disjunction gets case analysis before any atom is split with excluded middle. The last untriaged QF_LRA corpus failure, a clock synchronization benchmark, now has a complete Lean refutation. The grind fallback stays, no axiom is added, and Lean still checks every term.

Background

Before this PR the pipeline certified Boolean refutations, congruence over uninterpreted functions, and linear arithmetic over reals and integers, with theory lemmas justified by the Farkas lemma and by cuts. A wide rewrite over many arithmetic atoms rewrote each atom to a canonical form, and one lemma over the atom names carried the propositional change. The search for that lemma knew nothing about a constant atom such as (<= 0 0), and grind ran out of time on a 74-way disjunction whose literals are shared among several conjunctions. So a benchmark Z3 solves in a second had no certificate. The work serves milestone 3 of the plan, equality and linear arithmetic completed end to end.

What changed

Lean reconstructor

  • Propagation instead of a projection search. A rewrite that drops a conjunct made false by a constant atom now gets a direct proof term instead of a bare grind call. The old search did not know that (<= 0 0) is true.
  • Structures named once. Every and, or, implies and iff node inside a term gets a let name, like an abbreviation defined at the top of a document. A step through a deeply nested disjunction now costs a few names instead of restating the whole chain.
  • Lean infers the easy types. Steps through conjunctions and disjunctions carry enough explicit operands that their have lines need no type, which makes terms smaller still.
  • Cases before splits. A true disjunction with undetermined disjuncts is case-analysed, one branch per disjunct, before any atom is split. Checking each door of a hallway in turn beats flipping every light switch in the building.

Tests and documentation

  • Two new Lean-checked instances: a small flattening rewrite with a constant atom, and the exact Boolean skeleton of the clock synchronization rewrite, which the old reconstructor could not certify. Unit tests pin the new term shape, and the plan document gains a dated note.

Review

The reviewer approved the change with no blocker, major or minor finding and three nits.

  • Dead branch in the disjunction eliminator (nit, fixed). The helper that builds an Or.elim chain had a branch for a single handler, but both callers always pass two or more. Dead code makes a reader work out why it is dead, so the second commit replaced it with an assertion.
  • Stale docstring (nit, fixed). The prover's summary still said an unsettled direction splits on an atom, while the term now case-analyses an assumed disjunction first. The paragraph now describes the real order.
  • Sibling names repeated per step (nit, deferred). Three helpers write out all remaining siblings at every step through a wide gate, which is quadratic in its width. No current input comes near the budget, and fixing it changes the term shape again, so it is a follow-up.

The reviewer also stripped the grind fallback and confirmed that Lean accepts the direct terms alone, for the test instances and for generated inputs with a Boolean if-then-else term, exclusive or, equality and implication under the disjunction. They also confirmed that the clock-shaped test fails under the base commit.

Risks and open questions

  • Every propositional term changed shape. The let-named form is now used for all propositional rewrites and CNF lemmas. Lean checks each term and the fallbacks are unchanged, but a corpus re-scan is the right next evidence.
  • A propositional rewrite has no first. Its truth-table fallback is chosen ahead of time, so a term Lean rejected would fail the certificate, as before the PR.
  • Case split scanning. The search for a true disjunction rescans every structure on each call, which a lemma with thousands of structures and splits would feel.
  • GitHub CI did not gate the merge. The local gate passed, but the CI status on master was unknown when this report was written.

What comes next

Glossary

atom
A formula with no Boolean connective inside it, such as x <= 5 or a Boolean variable.
axiom
A statement accepted without proof. Lean's standard ones are propositional extensionality, choice, and quotient soundness.
Boolean
The sort of truth values, true and false.
case analysis
Proving a goal from a disjunction by proving it once under each disjunct. In Lean this is Or.elim.
clause
A disjunction of literals, such as (or (not a) b).
CNF, conjunctive normal form
A formula written as a conjunction of clauses. A CNF lemma relates a formula to the clauses that encode it.
congruence
Equal arguments give equal results: from a = b follows f(a) = f(b).
conjunction
An "and" of formulas, true only when every part is true.
constant atom
An atom with no variables, such as (<= 0 0), which is simply true or simply false.
cut
An inequality over integers tightened by rounding, such as 2x <= 3 giving x <= 1.
disjunction
An "or" of formulas, true when at least one part is true.
equivalence
Two formulas that always have the same truth value, written iff or = on Booleans.
excluded middle
The principle that every proposition is either true or false, used to split a proof into two cases.
exclusive or (xor)
A connective that is true when exactly one of its two operands is true.
Farkas lemma
A set of linear inequalities is contradictory exactly when some nonnegative combination of them gives 0 < 0.
flattening
Rewriting nested disjunctions such as (or (or a b) c) into one wide disjunction (or a b c).
hypothesis
A formula assumed to be true for the course of a proof.
if-then-else term (ite)
A term that picks one of two values by a Boolean condition, written (ite c a b) in SMT-LIB.
implication
A formula "if a then b", written (=> a b), false only when a is true and b is false.
let binding
A local name for a sub-expression inside a term, so the expression is written once and referred to by name.
linear arithmetic
Reasoning about sums of variables times constants compared by <=, < and =, over reals (QF_LRA) or integers (QF_LIA).
literal
An atom or the negation of an atom.
normalized atom
An arithmetic atom rewritten to one canonical shape, here c1 * x + c0 <= 0, so equal atoms get the same name.
proof term
An explicit expression whose type is the statement being proved. Lean checks it directly, with no search.
propositional
Concerning only the Boolean structure of a formula, with the atoms treated as opaque.
refutation
A proof that a set of assumptions leads to False.
rewrite
A step that replaces a formula by an equivalent one, such as the simplifier's flattening of a disjunction.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A procedure that searches for a proof, such as grind. It may fail or run out of time where a proof term cannot.
theory lemma
A fact that holds by arithmetic alone, such as x <= 1 and x > 2 being contradictory.
uninterpreted function
A function symbol with no definition, about which only equality facts are known.
unit clause
A clause with exactly one literal, which fixes that literal's truth value.
