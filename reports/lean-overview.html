Certifying Z3 unsat results with Lean: overview

Status as of 2026-11-02

Goal

When Z3 reports unsat, produce a certificate that an independent Lean checker accepts, so the result does not depend on trusting the solver. Proof certification is opt-in, so users who do not request proofs see no change. Z3's proof format is a means to that end, not something to preserve: the exporter is a thin adapter, and the Lean rules follow the meaning of each inference rather than its encoding. The plan lives in doc/lean-proof-plan.md in Z3Prover/z3.

Pipeline

  1. examples/python/proof_certificate.py runs Z3 and exports its native proof as JSON from one of two proof cores:
    • the clause log of the new sat.smt core, with theory hints such as Farkas coefficients, euf, Tseitin and cuts;
    • the legacy proof object of the classic SMT core.
  2. examples/python/proof_clause_log.py replays and trims the clause log.
  3. examples/python/proof_to_lean.py translates the certificate into Lean source. Long proofs are split into bounded lemmas, and steps are proved by direct terms, grind, or propagation tactics.
  4. The lean/ project (Z3Proofs) checks the generated proof with scripts/check_lean.sh.
  5. In C++, the native proof checkers in src/sat/smt/*_checker* (arith, euf, Tseitin, distinct) check more hint kinds directly, so that fewer steps fall back to "trust an SMT call".

scripts/proofs/proof_matrix.py in Z3Prover/z3test runs inputs under different proof settings. In CI, the releaseClang job requires Lean to accept every Boolean regression (lean-verified). The loop's local gate also runs a Lean-certified QF_LRA matrix.

New: incremental SMT-LIB scripts (push/pop, reset, several check-sat calls, check-sat-assuming). Previously only files with exactly one check-sat were accepted. A certificate covers one selected query: the assertions in scope at that check-sat, plus its assumptions, are unsat. This works through both proof cores.

The loop also added native C++ checks for xor, alldiff and distinct gate clauses, and split long proofs into bounded Lean lemmas.

Inputs with unsupported constructs are rejected explicitly, so an unsupported proof is never counted as accepted.

How the work is done: the lean-loop

An unattended loop (levnach/Lean-loop) runs one pull request per iteration on the fork levnach/z3. Each iteration has these steps:

  1. Rebase onto upstream and build Z3.
  2. Implementer agent: picks the next item from the plan or backlog, implements it, and tests it.
  3. Reviewer agent: reviews the change read-only, with soundness of the trust boundary first.
  4. Integrator agent: fixes what the review found and writes the PR.
  5. Driver: opens the PR and publishes an HTML report (https://levnach.github.io/z3/reports/pr-N.html).
  6. Gate (the check a fork PR must pass before the loop merges it): changes to Python, docs, or Lean only use a local gate; C++ changes use full GitHub CI, with a ci_fixer agent if CI fails.
  7. Merge the PR into the fork.

Changes to Python, docs, and Lean collect on the fork. The first change to C++ stops the loop (run_until_cpp.sh). The collected commits then go to Z3Prover/z3 as one batched PR.

Progress

  • 60 iterations from 2026-10-11 to 2026-10-31 (fork PRs #1–#60). Two iterations failed on the first try and succeeded on a retry.
  • 19 upstream PRs merged into Z3Prover/z3, from #11143 (2026-10-12) to #11451 (2026-10-30). Two of them were contributions forwarded from elefthei/z3: define-sort aliases and wide n-ary connectives.
  • Open: Z3Prover/z3#11519 covers iterations 45–60 (16 commits): rem, Real abs, coerced numerals, scaling to deep and wide inputs, and native rem axiom checks.
  • Running now: iteration 61 (QF_LIRA).

Milestones:

  • Lemma outlining for long proofs (iteration 3)

  • QF_LIA and QF_UFLIA, including div, mod and abs (iterations 12–16)
  • Native checks for xor, alldiff and distinct (iterations 23–26)
  • Fixes to the proof trimmer (iterations 33, 36, 41–42)
  • Time and memory limits on exports and the Lean check (iterations 40, 49–50)
  • Int Farkas lemmas and cut lemmas (iterations 51, 54)

Next steps (from the loop's backlog)

  • QF_LIRA conversions (to_real, to_int, is_int). These need cast lemmas, because Lean's grind does not reason through Int.cast and the project does not use Mathlib.
  • Mixing Int and Real arithmetic with uninterpreted functions.
  • Native checks of cut steps. These are the last native fallbacks in the test generators and need the cut's derivation from the C++ cut generators.
  • Quantified logics (UF, UFLIA) and the jreeves3/SMT-Skeleton-Check benchmark collections, which are still planned.
  • Measuring Lean on large QF_IDL inputs (41–84 MB of generated Lean).

Known operational issues

  • Upstream CI tests the PR merged with upstream master. Solver changes on master have broken a Lean test with a fixed random seed (#11276, fixed by a larger heartbeat budget).
  • The local gate's slowest step, the Lean reconstruction tests, has grown from about 6 minutes per iteration (iteration 9) to about 23 minutes (iteration 59), so each local-gate iteration waits longer before it merges.
