Certify reads through stores into maps and sets equated with stores

In one paragraph

The reconstructor now writes two kinds of facts that its Lean proofs about sets were missing. The first covers a select that goes through a store into a map at a variable index. The second covers a cnf lemma about the members of a set that an assertion equates with a store. With them the tactic grind proves rewrite steps and cnf lemmas that failed before. The four random set inputs that still failed the Lean check in the first sweep range now pass. The final theorem keeps its statement, and no Lean axiom is added. Each refutation that passed before keeps its proof.

Background

Before this PR, the exporter wrote a certificate for these inputs, but Lean rejected the generated file. The map below a store got a fact only when the store's index was a numeral different from the select's. Z3's rewriter also simplifies such selects at variable indices. A cnf lemma got member facts only when it reached a map. The work serves milestone 4 of the plan, "Broader theories and integration", for arrays.

What changed

Picture a set as a row of light switches. A store sets one switch, and a map builds a new row from other rows. To know one switch of a stored row, you may have to look underneath. The old proofs never did.

  • Reconstructor. A select through up to eight stores at variable indices now gets a fact for every store and for the map below, found by _read_levels.
  • Reconstructor. The same facts now follow the branches of an if-then-else term over arrays and the stored rows of nested arrays.
  • Reconstructor. A cnf lemma that reaches a store of a Boolean set now gets the members of both sides of each asserted equality, by congruence.
  • Reconstructor. The new select facts sit in extra proof attempts placed last, so the earlier attempts are the old ones, line for line.
  • Tests and documentation. Ten new inputs and four pinned random seeds are checked in Lean, and the plan gains a dated section.

Review

The verdict on the first commit was REQUEST_CHANGES, with one major and two minor findings. The second commit fixes all three.

  • Major, fixed. The reviewer read stores alternating with complements at several indices. One such input verified in half a second at the base commit and failed after 55 seconds with the first commit. The new facts were in every proof attempt. Each store is a case split for grind, so an early attempt hit the heartbeat limit instead of failing fast. Lean does not try the next attempt after that, so a certificate that passed before was rejected. Now the new facts appear only in attempts added last.
  • Minor, fixed. The limit of eight stores counted one run of stores only, so alternating stores and maps got thousands of facts. It now covers the whole walk of one select.
  • Minor, fixed. No test read such a term at more than one index. The failing input is now a Lean-checked test, and a new test checks the order of the attempts.

Two further suggestions concern failures that exist at the base commit. They are follow-ups.

Risks and open questions

  • Soundness: only facts inside tactic proofs are added, and Lean rejects a wrong one.
  • An input that fails anyway now fails more slowly, 60 seconds instead of 13 in the reviewer's largest case.
  • The added attempts always combine the new select facts with the pointwise facts. No tested input needs one kind alone.
  • The member facts cover Boolean sets only.
  • All runs were on macOS, and no GitHub CI result is recorded.

Glossary

array
A value that maps every index to an element, like a function. Example: (Array Int Bool) maps integers to Booleans.
assertion
A formula the input states as true, written (assert ...) in SMT-LIB.
axiom
A statement accepted without proof. A Lean file that adds none relies only on Lean's standard ones.
Boolean
The sort with the two values true and false.
case split
A proof step that considers two cases separately, such as "the index is 1" and "the index is not 1".
certificate
A file of evidence for a result that an independent checker can verify without trusting the solver.
clause
A disjunction of literals, such as "p or not q".
cnf lemma
A proof step that ties a clause to the formula it was derived from.
complement
The set of all indices that are not members of a given set. It is a map of "not".
congruence
The rule that equal things give equal results. Example: if two sets are equal, they have the same member at every index.
definitional equality
Two expressions that become identical once definitions are unfolded. Lean proves such an equality with rfl.
exporter
The script that replays the solver's proof log and writes the certificate.
heartbeat limit
Lean's budget of work for one proof. A proof that exceeds it stops with a timeout error.
hypothesis
An assumption of a theorem. Here the hypotheses are exactly the input's assertions.
if-then-else term
A term that picks one of two values by a condition, written (ite c a b) in SMT-LIB.
index
The position at which an array is read or written.
literal
An atomic formula or its negation.
map
An array built by applying a function at every index of other arrays, written ((_ map f) a b). The set operators are maps.
numeral
A number written out in the input, such as 1, as opposed to a variable such as i.
pointwise fact
A fact about two sets that is stated and proved member by member.
reconstructor
The script that turns a certificate into a Lean file for Lean to check.
refutation
A proof that a set of assertions leads to a contradiction.
rewrite step
A proof step that replaces a term with a simpler equal one.
rewriter
The part of the solver that simplifies terms before and during solving. Example: it turns (select (store a 1 v) 2) into (select a 2).
seed
A number that fixes the output of a random generator. Each seed here names one random set problem.
select
A read of an array at an index, written (select a i). For a set it asks whether i is a member.
set
An array with Boolean elements. An index is a member when its element is true.
set difference
The members of one set that are not in another, written (setminus a b). It is a map of "and not".
sort
The type of a value, such as Int, Real, or Bool.
soundness
The property that a checker accepts only correct proofs.
store
An array equal to another except at one index, written (store a i v).
tactic
A Lean command that searches for a proof automatically. The generated files use grind and omega.
theorem
A statement with a proof that Lean has checked.
