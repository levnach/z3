In one paragraph

This PR opens a new fragment, qf_uflira. It covers uninterpreted functions and uninterpreted sorts next to both the Int and the Real sort. Examples are a function f : Int -> Real, a predicate over both sorts, or a conversion such as to_real beside any uninterpreted symbol. Before, the exporter refused all of these. Now they get a certificate on both proof cores, and the Lean kernel checks every theory lemma of the refutation. The Lean theorem takes one valuation per numeric sort and an interpretation with a separate injection for each sort. The trust boundary did not move.

Background

Before this PR, the pipeline certified Int and Real side by side (qf_lira). It also certified uninterpreted functions next to one numeric sort (qf_uflia or qf_uflra). It could not combine the two. The Lean encoding had a single injection and a single family of numeric functions per certificate. Two backlog items, from iterations 61 and 62, tracked this gap. The work serves milestone 3 of the project plan, "Equality and linear arithmetic". That milestone asks to complete each fragment end to end before adding another.

What changed

  • Inputs with uninterpreted symbols next to both Int and Real now get a certificate on both proof cores, as an opt-in fragment.
  • Each function argument now enters the carrier through the injection of its own sort.
  • Farkas lemmas and congruence steps over an application such as (f n) are now judged by the application's sort, not its arguments' sorts.
  • Helper equalities between function arguments no longer pair an Int term with a Real term.
  • Error messages, the README, and the project plan now name the new fragment.
  • A new test module checks five documented inputs and pinned random inputs in Lean on both cores.

The change is Python only. There is no C++ change.

Worked example

The input is the first documented case of the new tests. All output below comes from real runs.

(a) The input

(set-logic QF_UFLIRA)
(declare-fun f (Int) Real)
(declare-const n Int)
(declare-const m Int)
(declare-const x Real)
(assert (= n (+ m 1)))
(assert (= m 2))
(assert (> (f n) x))
(assert (< (f 3) (- x 1.0)))
(check-sat)

Int arithmetic gives n = 3. By congruence, (f n) equals (f 3). Then the two Real bounds on f contradict each other.

(b) Before

The exporter from the base commit stopped at once, with exit code 2:

proof_certificate.py: error: mixing integer and real arithmetic with uninterpreted functions is not supported

No certificate was written, so the old reconstructor never ran.

Review

The reviewer first asked for changes. All three findings were fixed before the merge.

Major: an Int term equated with a Real term

The reviewer wrote an input where an Int function and a Real function take the same if-then-else term: (ite (> x 0.0) 1 0) and (ite (> x 0.0) 1.0 0.0). Both share one linear form, so the reconstructor grouped them and wrote an ill-sorted Int = Rat helper. Lean's grind tactic failed on it, on both cores. It is like equating one dollar with one kilogram because both read "1". The failure was fail-closed, so nothing false was certified, but valid inputs were lost. The fix adds the sort to the grouping key. The reviewer's input became a test, along with a Lean-free check and a pinned random seed.

Nit: an incomplete error message

A wrong label produced a message naming only qf_lia and qf_uflia as Int fragments. It now also names qf_lira and qf_uflira.

Nit: an incomplete README paragraph

The legacy-core paragraph listed two opt-in integer fragments. It now lists all four.

Risks and open questions

  • Known gap, shared with qf_lira: an Int ite whose condition compares Reals, outside a function argument, is still rejected. The PR says this is fail-closed and older than this change.
  • The random inputs need little arithmetic, so wider arithmetic shapes are untested.
  • No z3test regression is in qf_uflira, so the proof matrix does not exercise it.
  • The earlier sweeps were not rerun after the review fix. The PR argues the fix cannot affect single-sort inputs.

What comes next

  • Treat ite conditions as their own sort when classifying a step, to close the known gap.
  • A random generator with more arithmetic reasoning for this fragment.
  • Other inputs that are still rejected, such as ^ of numerals and enumeration datatypes.

Glossary

atom
A smallest unit inside a formula, such as a variable or an application (f n). Arithmetic treats it as one unknown.
carrier
The type whose elements the uninterpreted symbols range over. Here it is _m.U.
certificate
The exported proof file that a separate checker can verify.
clause
A disjunction of literals, such as a ∨ ¬b ∨ c.
congruence
The rule that equal arguments give equal results: if n = 3 then f n = f 3.
conversion
An SMT-LIB function between Int and Real: to_real, to_int, or the test is_int.
fail-closed
A failure that rejects a valid proof instead of accepting a wrong one. It costs coverage, not soundness.
Farkas lemma
A theory lemma proved by adding inequalities with nonnegative coefficients until 0 < 0 appears.
fragment
A named subset of the input language, such as qf_lra or qf_uflira. "qf" means quantifier-free.
if-then-else term (ite)
A term that picks one of two values by a condition: (ite c 1 0).
injection
A map that places values of one sort into the carrier, such as _m.int : Int -> U.
interpretation
A choice of meaning for every uninterpreted sort, function, and predicate. Here it is the Lean structure Interpretation.
kernel
The small core of Lean that checks every proof. It is the part one must trust.
linear form
A sum of atoms times numbers plus a constant, such as 2x + 3y − 1.
literal
An atom or its negation, such as x ≤ 3 or ¬(x ≤ 3).
predicate
An uninterpreted function whose result is Boolean.
proof core
One of Z3's two sources of proofs here: the clause log or the legacy proof object.
refutation
A proof that the assertions together lead to False.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that searches for a proof, such as omega or grind.
theory lemma
A clause that holds by a theory alone, such as arithmetic or equality. Each one becomes a separate Lean theorem.
trust boundary
The line between what is checked and what is taken on faith. Here the Lean kernel checks every lemma, so no step of Z3 is taken on faith.
uninterpreted function
A function with a name and a signature but no fixed meaning, such as f : Int -> Real.
uninterpreted sort
A sort declared by name only, such as (declare-sort U 0), with no built-in values.
valuation
An assignment of values to variables. Here _vars values the Real variables and _ivars the Int ones.
