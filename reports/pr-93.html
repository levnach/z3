Certify scripts with print-only commands, define-const, and exit

Pull request #93 in levnach/z3, targeting master

State: MERGED on 2026-11-08T01:42:19Z · merge commit 6c5a6721d · loop iteration 93

In one paragraph

The exporter's frontend used to reject a whole SMT-LIB script if it contained a command that only prints something, such as simplify, get-value, or apply. Now it drops those commands, reads define-const as a definition, and stops reading at exit, exactly as Z3's own parser does. None of these commands touch the assertion stack, so the assertions that the Lean theorem talks about stay the same. One exception is kept out: a printing command that carries a :named label is still rejected, because the label defines a name. With this change, four more regression files from z3test now get a Lean-checked refutation through the clause log.

Background

Before this PR, the pipeline could already certify every unsat query in z3test's regressions/smt2 folder that lies inside the certified fragments. A rescan found 35 such queries, and all 35 verified in Lean. The remaining gap was not in the proofs. It was in the frontend, which refused scripts over harmless commands and options like :trace. This work serves milestone 4 of the plan, a proof-required frontend that keeps the exact incremental context and rejects only what it truly cannot handle. It also follows the plan's regression methodology, which measures progress on real z3test inputs.

What changed

  • You can now certify a script that uses get-value, eval, simplify, apply, display, or get-assertions, because the frontend skips them.
  • You can now write (define-const y Int (+ x 1)), and the frontend treats it like the matching define-fun.
  • You can now put anything after (exit), even text that does not parse, because reading stops there.
  • You can now set the debug options :trace and :trace_file_name, and :global-decls false, which is Z3's default.
  • You will still get a clear rejection if a skipped command contains a :named label, or if you set :global-decls true.

Think of a recipe that says "take a photo of the bowl" between two steps. Skip that line and the cake comes out the same. A :named label is different. It writes a name on the bowl that later steps may use. Only the Python exporter changed, with no C++ or Lean library changes.

Worked example

This input was built from the PR's synthetic output_commands test script. It uses a debug option, a define-const, two printing commands, and broken text after exit.

(a) The input

(set-option :trace true)
(declare-const x Int)
(define-const y Int (+ x 1))
(simplify y)
(assert (< y x))
(check-sat)
(get-value (x y))
(exit)
(assert (= x y)) (unbalanced "string

The only real assertion says x + 1 < x, which no integer satisfies. Z3 itself prints (+ 1 x) for the simplify, then unsat, then an error for get-value, and it never reads past exit.

(b) Before: the base commit's exporter

proof_certificate.py: error: option :trace is not supported; only output, model, resource, and search options are ignored

The old frontend stopped at the first line, before reaching the other constructs it also rejected.

(c) After: the Lean file the reconstructor now writes

def term_0 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Int := _vars 0
def term_1 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Int := ((1 : Int))
def term_2 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Int := ((term_0 _atoms _vars) + (term_1 _atoms _vars))
def formula_3 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Prop := ((term_2 _atoms _vars) < (term_0 _atoms _vars))
...

The constant y appears as its body x + 1, so the definition was read correctly.

theorem unsat (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    (_h0 : (formula_3 _atoms _vars))
    : False :=
...

The theorem has exactly one hypothesis, x + 1 < x. The assertion after exit is not part of it.

private theorem rewrite_9 (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    : (formula_8 _atoms _vars) := by
  unfold formula_8 formula_4 formula_3 term_2 term_1 term_0
  first | omega | grind (splits := 64)

This rewrite step says x + 1 < x is equivalent to False, and Lean proves it with the omega tactic.

The exporter chose the clause log and the qf_lia fragment. The reconstructor printed "Lean checked the refutation", and scripts/check_lean.sh reported "Lean checks passed". Lean accepted the file.

Review

Major: a dropped label could certify a satisfiable script

The reviewer wrote a five-line script. It labels x as p inside a simplify, then defines p as true and asserts (not p). Z3 keeps the label and rejects the definition, so it answers sat. The exporter dropped the label and kept the definition. It then produced a Lean-checked unsat theorem for that sat script. This mattered because a certificate must describe the input Z3 actually read. The fix rejects any skipped command that contains :named. Five such scripts are now rejection tests, including both review examples.

Nit: a reference to a file outside the repository

The plan note cited a loop scratch script that readers of the repository cannot see. The scan is now described in words.

Suggestion: say what t119 certifies

t119.smt2 has no check-sat. The note now says the certified statement is that its final state is unsat.

Risks and open questions

  • Skipping a command is sound only if Z3 changes neither the assertions, the declarations, nor the number of queries for it. The implementer checked this in Z3's source code for each skipped command.
  • GitHub CI results for this PR are unknown to this report.
  • Still rejected: minimize, maximize, assert-soft, and :opt.* options, because they change what check-sat answers. Also still rejected: get-consequences, include, :error-behavior, and :global-decls true.

What comes next

The unsat queries in z3test's crash.smt2 need lblpos labels and the :nnf.sk-hack option, a possible follow-up. The other files this change lets through are either sat or leave the fragments, using quantifiers, nonlinear arithmetic, or strings. Those are separate theory extensions under milestone 4.

Glossary

assertion
A formula the script states to be true, written (assert ...).
assertion stack
The assertions and declarations currently in force, organized in levels that push opens and pop closes.
clause log
A record of every clause Z3's SAT-based core derives while solving, used as the raw material for the proof.
definition
A name bound to a fixed term, such as (define-const y Int (+ x 1)), so every use of y means x + 1.
fragment
A restricted family of formulas the pipeline supports, such as qf_lia, quantifier-free linear integer arithmetic.
frontend
The part of a tool that reads the input text and decides what it means before any reasoning starts.
incremental script
A script that adds and removes assertions over time and asks several questions, using push, pop, and repeated check-sat.
:named label
An SMT-LIB annotation, (! term :named p), that gives a term the name p for later use.
option
A setting changed with set-option, such as :trace or :global-decls.
refutation
A proof that a set of assertions leads to False, so they cannot all hold.
regression test
A saved input that is run again after each change to catch things that used to work and broke.
rewrite
A proof step that replaces a formula by an equivalent, simpler one, such as x + 1 < x by False.
sat
The answer when some assignment of values makes every assertion true.
script
An SMT-LIB file: a sequence of commands such as declare-const, assert, and check-sat.
sound
Never certifying something false. A sound exporter never yields an unsat theorem for an input Z3 reads as sat.
tactic
A command that builds part of a proof automatically. In Lean, omega proves facts of linear integer arithmetic. In Z3, apply runs a solver tactic.
theorem
A statement together with a proof that Lean has checked.
unsat query
One check-sat in a script, or its final state if it has none, whose assertions in scope cannot all be true.
