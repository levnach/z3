In one paragraph

This PR changes how the Lean reconstructor writes one kind of helper fact. Z3's rewriter puts the arguments of an uninterpreted function into normal form. The rewrite step's lemma then needs each argument to equal its normal form. Before, the reconstructor wrote both sides of that equality out in full. An argument built from nested if-then-else terms grew to more than 100 KB of text. The tactic proving it ran out of heartbeats, and the whole file failed. Now the equality is stated over two short definition names. Lean unfolds them only inside the proof, then unfolds the finished fact in place. The proved fact is the same, Lean still checks it, and the trust boundary does not change. A refutation that failed before now verifies.

Background

The previous PR, #99, made the same move for the ite gates of a theory lemma. That let deeply nested inputs in linear integer arithmetic with uninterpreted functions verify. One such input is the QF_UFLIA benchmark hard16. The argument equalities, however, were still written out in full. So an input that compares two nested chains through a function f still failed in Lean. Certificates that use arrays keep the written-out form, before and after this PR. The work serves Milestone 3 of the project plan, "Equality and linear arithmetic".

What changed

  • Inputs that apply an uninterpreted function to a deeply nested if-then-else argument can now be certified in Lean.
  • The reconstructor in proof_to_lean.py now writes each argument equality as two short lines instead of one huge line.
  • Certificates with arrays behave exactly as before, so no array input can newly break.
  • New tests check the shape of the new lines and confirm that Lean accepts a six-step chain compared through f.
  • The project plan and the examples README now describe the new form.

An analogy: before, every footnote pasted in a whole chapter. Now the footnote cites the chapter's title. Lean opens the chapter only while it proves that one footnote.

A harmless rewriter change could break the test while every line still had the right shape. The fix now requires at least one fact and checks the shape of every one.

Nit. The reviewer traced where the new tests run in CI. The manylinux wheel step runs only one test file, so the shape test runs only through ci_lean_proofs.sh. Other QF_UFLIA tests run the same way, so nothing regressed, and the step was left as is.

Risks and open questions

  • Lean's unfold fails on a name that does not occur. The list holds exactly the definitions the two terms reach, using the same method as the existing fallback. The full suite passes.
  • Each argument equality now costs two extra unfolds. The PR judges this negligible next to the theory tactic.
  • It is unknown whether certificates with arrays hit the same blow-up. No test yet combines nested ites with array reads.

What comes next

  • Apply the same folded pattern to other helpers that still write nested terms out. These include scaling facts, Boolean distinctness facts, bridge statements, excluded-middle facts, and cast facts.
  • Build a generator that mixes nested ites with array reads, to test the array branch.
  • Rescan the QF_AX and QF_AUFLIA benchmarks, which iteration 99 left open.

Glossary

argument
A value passed to a function. In (f a6), the argument is a6.
array
The SMT theory of maps from indices to values, read with select and written with store.
definition
A named Lean term, such as term_30, that stands for a longer expression. A definition left by name is "folded".
heartbeat
Lean's unit of work. A proof that uses more than the allowed number of heartbeats stops with a timeout error.
if-then-else term
A term that picks one of two values by a condition, written ite in SMT-LIB. Example: (ite (< s 17) s (- s 17)).
ite gate
A pair of facts about one if-then-else term: if the condition holds it equals the first branch, otherwise the second.
lemma
A smaller proved fact that a larger proof uses. Here each Z3 proof step becomes one Lean lemma.
linear integer arithmetic
Arithmetic over whole numbers using only addition, subtraction, and multiplication by constants. QF_UFLIA adds uninterpreted functions.
normal form
One standard way of writing a term, so that equal terms look the same. Example: (- x y) becomes (+ x (* -1 y)).
refutation
A proof that a set of assertions leads to False, so they cannot all hold.
rewrite step
A proof step saying a formula is equivalent to its rewritten form.
rewriter
The part of Z3 that simplifies terms into normal form before solving.
tactic
A Lean command that builds a proof automatically. omega handles integer arithmetic. grind handles equalities and case splits.
theory lemma
A fact that holds because of a theory, such as arithmetic, rather than because of the input's logical structure.
trust boundary
The line between what Lean checks and what must be taken on faith. Moving nothing across it means nothing new is trusted.
uninterpreted function
A function with a name and a signature but no fixed meaning. The only rule is that equal arguments give equal results. Example: (declare-fun f (Int) Int).
unfold
To replace a definition's name with the expression it stands for. Lean's unfold tactic does this.
