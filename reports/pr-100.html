State Lean argument equalities over folded definitions

Pull request #100 in levnach/z3 · MERGED

In one paragraph

When Z3 proves a formula with an uninterpreted function, its rewriter often replaces each argument of the function by its normal form. The Lean proof then needs an equality between each original argument and its normal form. Before this PR, both sides of that equality were written out in full. For an argument built from nested if-then-else terms, the text exploded, and the tactic ran out of heartbeats. Now the equality is stated over two short definition names. It is proved after unfolding those names, then unfolded in place. The fact is the same up to delta reduction, so the trust boundary does not move. A QF_UFLIA input that Lean used to reject now gets a checked refutation.

Background

The previous PR, #99, made the same move for the gates of if-then-else terms. It stated them over folded definitions, so large QF_UFLIA benchmarks fit under Lean's 8 GB memory cap. That PR left one more helper written out: the argument equalities inside the lemma for a rewrite step. They matter when an uninterpreted function is applied to a deep numeric term. The work serves Milestone 3 of the plan, "Equality and linear arithmetic".

What changed

  • A rewrite step that normalizes the argument of an uninterpreted function now verifies in Lean, even when that argument is a deep chain of if-then-else terms.
  • Each argument equality is now written as one short line over two definition names, instead of a line that repeats every inner term.
  • Certificates that use arrays keep the old written-out form, because unfolding leaves array terms folded.
  • The test generator for "modular chains" can now compare its two results through a function f, so the failing shape is a permanent test.

An analogy: a recipe that says "use the sauce from page 12" stays short. Copying page 12 in, when page 12 itself copies page 11 three times, makes the recipe explode. The new code keeps the page reference and opens the page only while cooking.

Review

The reviewer approved, with no blockers and no major findings. They ran both new tests against the old reconstructor. Both failed with the heartbeat timeout, so the tests do catch the bug.

The fixed count. The new shape test required exactly two argument equalities. The reviewer saw that this number is Z3's choice. A rewriter change could break the test while every line still had the right shape. The fix asks for at least one equality and checks each one. A test should fail only when its property breaks.

The wheel step. One CI step runs only the base Lean test file. So the new shape test runs in CI only through the Lean proof script. It was left alone, because the other QF_UFLIA tests are in the same position.

Risks and open questions

  • Lean's unfold fails on a name that does not occur. The list holds exactly the definitions both terms reach, parents first, as in the main fallback.
  • Each equality now costs two extra unfolds. The unchanged hard16 timing suggests this is negligible.
  • Certificates with arrays still write the equality out. Whether nested ites under array reads blow up the same way is not yet tested.
  • The GitHub CI result for the merge is not recorded in the inputs.

What comes next

  • Apply the same folded pattern to the other helpers that still write terms out, such as scaling facts, cast facts, and argument equalities with arrays.
  • Write a generator that mixes nested ites with array reads, to see which helpers matter.
  • Run the QF_AX and QF_AUFLIA rescans that iteration 99 left open.

Glossary

argument
A value passed to a function. In (f a6), the argument is a6.
certificate
The proof Z3 exports as a file, which the reconstructor turns into Lean.
definition
A named Lean term, written with def. Using the name instead of the body keeps statements short.
delta reduction
Replacing a defined name by its body. Two statements that differ only by this step are the same fact to Lean.
equality
A statement that two terms have the same value, such as a = b.
gate
A helper fact about an if-then-else term: if the condition holds, the term equals its first branch, else its second.
goal
The statement a Lean proof still has to show at a given point.
heartbeat
Lean's unit for counting work. A proof that uses more than the limit stops with a timeout error.
if-then-else term
A term that picks one of two values by a condition. In SMT-LIB it is (ite c a b): a if c holds, else b.
lemma
A smaller theorem proved on the way to the main one. The generated file checks many proof steps as separate lemmas.
normal form
The single standard way the rewriter writes a term, so equal terms look alike. For example (- x y) becomes (+ x (* -1 y)).
QF_UFLIA
The SMT-LIB logic of quantifier-free formulas with uninterpreted functions and linear integer arithmetic.
refutation
A proof that a set of assertions leads to False, so they cannot all hold together.
rewrite step
A proof step that replaces a formula by an equivalent, simpler one and records that the two are equivalent.
rewriter
The part of Z3 that simplifies terms into normal form before and during solving.
tactic
A Lean command that builds part of a proof automatically. Here omega and grind prove arithmetic facts.
trust boundary
The line between what must be trusted and what is checked. Here Z3 is not trusted: Lean checks every step.
unfold
The Lean tactic that performs delta reduction: it replaces named definitions by their bodies in a goal or hypothesis.
uninterpreted function
A function symbol with no fixed meaning. The only rule is that equal arguments give equal results. Example: (declare-fun f (Int) Int).
