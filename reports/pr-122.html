Compare sets member by member in Lean rewrites and cnf lemmas

Pull request #122 in levnach/z3, targeting master · MERGED · 2026-11-11T22:37:17Z · loop iteration 121

Merged on 2026-11-11T22:37:17Z as commit bf5411254.

In one paragraph

Z3's rewriter simplifies sets built with set operators by looking at their members. The reconstructor now does the same. For each rewrite step and cnf lemma over sets, it computes a truth table for every set term. Two terms with the same table are stated equal, and Lean proves the equality by function extensionality. Two sides of an equality whose tables disagree in every row are stated different. On a sweep of random set inputs, 43 certificates failed in Lean before, and now all of them pass. Lean checks every new fact, so no refutation rests on the tables.

Background

Before this PR the pipeline certified many inputs over sets and other arrays. Its facts about a map of a connective each covered a single map. The rewriter goes further. It knows that a set minus itself is empty. The certificate records the set before and after, and no single-map fact links the two. Lean's tactic grind then failed in that step. A second failing shape was a cnf lemma that goes from an equality of sets to one select. The work serves milestone 4, "Broader theories and integration", which covers arrays.

What changed

  • Reconstructor, equal sets. You can now certify a rewrite step that replaces a set term by a differently written term with the same members.
  • Reconstructor, different sets. You can now certify a step where an equality of sets is decided false because the two sides differ at every index.
  • Reconstructor, cnf lemmas. A cnf lemma that goes from an equality of sets to one member now verifies, by congruence at each index it reads.
  • Reconstructor, cost bounds, added after review. Deeply nested maps of xor or of an if-then-else term keep a small Lean file and still verify.
  • Tests. Twelve new documented inputs and four pinned random inputs are checked in Lean, and each new kind of fact is shown to be needed.

An analogy. Two clubs write their membership rule in different words. The old reconstructor compared the wording. The new one picks an arbitrary person and asks whether both rules give the same answer.

Review

The reviewer asked for changes. There was no blocker. All five findings were fixed in the PR's second commit, before the merge.

Major: nested xor maps made the Lean file explode

The reviewer nested sixteen maps of xor. A map of xor writes each argument twice, so the formula doubles at every level. The size limit counted maps, not written text. Lean ran out of heartbeats on an input that passed at the base, a regression. Now the limit counts what is written. Each step is also tried without the new facts first, and only then with them.

Minor: a test had become weaker

One test removes a fact and expects Lean to fail, which shows the fact is needed. The first commit removed the new facts together with each older fact. A later change could then break an older fact unnoticed. Now each kind of fact is removed alone.

Minor: no test nested xor or if-then-else maps deeply

The tests missed exactly the major finding. Two sixteen-level inputs are now checked in Lean. Both fail with the reviewed commit.

Nits

Auxiliary theorems with the same formula on both sides are now proved by rfl. Repeated ones are stated once. One overlong README line was rewrapped.

Risks and open questions

  • Soundness. The truth tables only choose which facts to state. A wrong table gives a fact Lean cannot prove, and Lean rejects the file.
  • All or nothing. A step that needs some new facts but cannot afford all would fail. None is known.
  • Timeouts. If the first attempt times out instead of failing, the second is never tried. None was seen.
  • Still failing. An equality of sets decided false over an uninterpreted sort of indices, when the interpretation does not state that the sort is nonempty.
  • Still rejected. Inputs whose refutation needs the default-map axiom.
  • Not covered. Maps over elements that are not Boolean. Wider random generators were not swept.
  • CI. No GitHub CI result is recorded here.

What comes next

  • State that an uninterpreted index sort is nonempty, as a separate change to the theorem's hypotheses.
  • Certify refutations that need the default-map axiom.
  • Sweep wider inputs: real and uninterpreted indices, deeper terms, and sets of sets.

Glossary

array
A value that maps each index to an element. (Array Int Bool) maps integers to Booleans.
assertion
A formula the input states as true, written (assert ...).
auxiliary theorem
A small helper theorem, proved first and then used inside a larger proof. Also called a lemma.
Boolean
The sort with the two values true and false.
certificate
A file that records the solver's proof, so that another program can check it.
clause
A disjunction of literals, such as "p or not q".
cnf lemma
A clause the solver adds when it turns a formula into clauses. It ties the formula to its parts.
congruence
Equal inputs give equal outputs. If two sets are equal, their members at one index agree.
connective
A Boolean operator that builds a formula from others: and, or, not, implies, xor.
default-map axiom
A fact Z3 states about the default value of a map. The pipeline does not certify it, so it rejects proofs that need it.
equality
The statement that two terms have the same value, written (= s t).
function extensionality
Two functions are equal if they give the same result on every input. For sets: same members, same set.
heartbeat
Lean's unit for counting the work of a proof step. A step over its budget is stopped with a timeout.
if-then-else term
A term that picks one of two values by a condition, written ite in SMT-LIB.
index
The position at which an array is read or written. For a set, the candidate member.
interpretation
A choice of meaning for every declared symbol. A refutation must hold under all of them.
literal
An atomic formula or its negation, such as (select a i) or (not (select a i)).
map
An array built by applying a function at every index. ((_ map and) s t) is the intersection of two sets.
member
An index at which a set holds true.
proposition
A statement that is true or false. Lean's type for it is Prop.
refutation
A proof that the assertions lead to a contradiction.
rewrite step
A proof step that says a term equals its simplified form.
rewriter
The part of a solver that simplifies terms, for example (setminus s s) to the empty set.
select
Reading an array at an index, written (select a i). On a set it asks whether i is a member.
set
An array with Boolean elements. An index is in the set when the array holds true there.
set operator
Union, intersection, difference (setminus), or complement. Z3 turns each into a map of a Boolean connective.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that searches for a proof. grind is one.
truth table
A list of a Boolean formula's value for every combination of its inputs. Two formulas with the same table are equivalent.
uninterpreted sort
A sort the input declares without saying what its values are, as in (declare-sort Index 0).
xor
Exclusive or. It is true when exactly one of its two arguments is true.
