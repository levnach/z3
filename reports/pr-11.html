Bypass the frontend's tactic preamble in both proof exporters

Pull request: levnach/z3#11 Merge commit: 54beea1c8 Merged: 2026-10-15T17:56:25Z Loop iteration: 11

In one paragraph

Both proof exporters now tell Z3 to skip its tactic preamble. A tactic is a rewriting pass that simplifies the input before solving, and the preamble is the fixed chain of such passes that Z3 runs first. The assertions now go straight to a proof core, the part of the solver that searches for a refutation and records the evidence. A refutation is a proof that a set of assertions cannot all be true at once. There are two cores: the clause log, which records every clause the solver assumes or infers, and the legacy proof object, which records a proof tree. A clause is an "or" of literals, and a literal is an atomic statement or its negation. The preamble invented fresh symbols absent from the input, and Lean refuses any certificate that mentions an undeclared symbol. Four separate rejections from earlier iterations had this one cause, and one option on each path removes them all.

Background

Before this PR the pipeline certified propositional input, uninterpreted functions, linear real arithmetic, and their QF_UFLRA mix through both cores. An uninterpreted function is a function symbol with no fixed meaning, only the rule that equal inputs give equal outputs. Four gaps remained. A Real variable occurring in a single function argument became a fresh constant, and the certificate was rejected. A predicate over Bool alone, a function whose arguments and result are all Boolean, certified only through the legacy proof object. Arithmetic input with an if-then-else term failed on the legacy path. And a phantom constant appeared in some clause logs. Earlier iterations blamed the cores' own simplifiers. The work serves milestone 3 of the plan, equality and linear arithmetic, completed one fragment at a time.

What changed

  • Exporters bypass the preamble. Both paths set one Z3 option, combined_solver.ignore_solver1, so a QF_UFLRA input with a variable in a single function argument now certifies through both cores.
  • Bool-only predicates use the clause log too. The special routing to the legacy core is gone. The automatic core choice is now "legacy for propositional input, clause log otherwise".
  • If-then-else terms certify on the legacy path. An if-then-else term, written ite in SMT-LIB, picks one of two values based on a condition. All seven arithmetic inputs with such terms now verify through the legacy proof object.
  • The reconstructor recognises rewritten if-then-else terms. Z3's rewriter puts terms into a normal form, a standard spelling that equal terms share. For an ite it may flip the condition and swap the branches. The Lean lemmas now group such terms by normal form and state their equality, which Lean proves itself. It is like seeing that "if not raining, stay in, else go out" means "if raining, go out, else stay in".
  • Tests and documentation follow. Two new documented inputs cover the cases above, and fixtures moved to inputs that still produce the old proof shapes.

Worked example

The input is the new documented test for the single-occurrence case. A sort is the type of a value, here Real or Bool. After Z3's rewriter normalizes the two spellings of x - y, the variable y appears in exactly one function argument. That is the pattern the preamble replaced by a fresh constant.

(assert (or (not (q (f (+ x (* (- 1.0) y))))) (< (f (+ 2.0 2.0)) 4.0)))

Review

The reviewer approved the change with no blocker or major finding. Four smaller findings were recorded.

  • Minor: an untested fallback. The reviewer read the new grouping test and saw that its check for "opaque" conditions, meaning conditions that are not linear comparisons, never met such a term. A later edit could break that fallback with no test failing. The fix added a documented input whose conditions are a Bool variable and a predicate. Both cores certify it, and the test asserts that the two terms stay apart with no helper equality.
  • Nit: a test that pins Z3. Half of the new preamble test runs Z3 without the option and expects a fresh symbol. That pins Z3's preamble, so an upstream Z3 change could fail it although the exporter is correct. It was kept as the witness that the bypass matters, with a failure message naming the responsible passes.
  • Nit: a mismatch in z3test. The external matrix script keeps its own copy of the options without the bypass, so its raw replay runs the preamble while its Lean column does not. CI clones upstream z3test, so this is a recorded follow-up. Today the eight QF_LRA logs are identical either way.
  • Nit: unreachable code. The handling of the older arithmetic engine's hint names is no longer reached by real inputs and is covered by constructed declarations only. No change, because a Z3 option still reaches it.

Risks and open questions

  • The clause log now shows assertions after the core's own rewriter only. Unknown inputs may surface normal forms the Lean bridging has not seen, as the if-then-else case did. Such cases fail in Lean, never pass.
  • The legacy proofs changed shape, so fixtures for transitivity and if-then-else congruence moved to other inputs. The reconstructor's rules are unchanged.
  • If-then-else conditions rewritten beyond a polarity flip, for example scaled by a constant, are not grouped and stay opaque.
  • The GitHub CI result for the merge commit was unknown when this report was written.

What comes next

  • Align the z3test matrix script's options with the exporter's and add a matrix cell for uninterpreted-function inputs.
  • Decide whether to group if-then-else conditions rewritten beyond polarity.
  • Continue milestone 3: the plan names real and integer linear arithmetic, and the exporter still rejects integer rules.

Glossary

Assertion
A statement the input declares to be true.
Boolean
A value that is either true or false.
Sort
The type of a value, such as Real or Bool.
Literal
An atomic statement or its negation.
Clause
An "or" of literals.
Refutation
A proof that a set of assertions cannot all be true at once.
Uninterpreted function
A function symbol with no fixed meaning, only the rule that equal inputs give equal outputs.
Predicate
A function whose result is Boolean. A predicate over Bool alone also takes only Boolean arguments.
Congruence
The rule that equal arguments give equal function values.
If-then-else term
A term, written ite in SMT-LIB, that picks one of two values based on a condition.
Tactic
A rewriting pass that simplifies the input before solving starts.
Tactic preamble
The fixed chain of tactics that Z3's frontend runs before handing the input to a proof core.
Proof core
The part of the solver that searches for a refutation and records the evidence.
Clause log
A proof core's record of every clause it assumes or infers.
Legacy proof object
The older proof format, a tree of inference steps produced by the other proof core.
Fresh constant
A new symbol the solver invents during simplification, absent from the input.
Normal form
The standard spelling a rewriter gives to a term, so that equal terms share one spelling.
Polarity
Whether a condition is stated positively or as its negation. Flipping it swaps the branches of an if-then-else term.
Opaque condition
An if-then-else condition that is not a linear comparison, so the reconstructor treats it as an unanalysed atom.
Theory lemma
A clause justified by a theory, such as arithmetic or congruence, rather than by pure propositional logic.
QF_UFLRA
The SMT-LIB fragment mixing uninterpreted functions with linear real arithmetic, without quantifiers.
