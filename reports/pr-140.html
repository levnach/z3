Replay deeply nested conjunctions linearly; tie clauses by leaf cores

Pull request #140 in levnach/z3 State: OPEN Date: 2026-11-16T20:07:13Z Loop iteration 139

This pull request is open. It is not merged. The change commit is 17ff13edd.

In one paragraph

This PR changes the clause-log replay. Its tables for a deeply nested conjunction now grow linearly with the nesting depth, not quadratically. A conjunction with more than 8,192 parts is no longer handed whole to a solver. Instead, an assumed clause is tied to an unsat core of leaf conjuncts, each reached by and-elimination. One QF_IDL benchmark, whose single assertion nests 41,822 conjunctions, could not get a certificate at all. It now does, and Lean verifies the refutation. Nothing new is trusted. The core only chooses the premises of a theory lemma, which Lean must still prove.

Background

Before this PR the replay handled shallow and moderately nested conjunctions. For a very deep one, three of its tables grew quadratically with the depth. It also asked a solver to check the whole conjunction for each clause. On the benchmark above, the replay passed 17 GB of memory before reading the clause log. The inputs name no milestone. The work is about scale in fragments that already work. The plan files it under Boolean and EUF proof infrastructure. The benchmark's logic falls under milestone 3, equality and linear arithmetic.

What changed

The replay

  • Paths. Each conjunct now remembers only the conjunction directly above it, so an assertion nested 40,000 levels deep fits in memory.
  • Keys. The canonical key of a conjunction now names its set of operands by one shared number, and formulas match exactly as before.
  • Index. The symbol index lists leaf conjuncts only and finds the conjunctions above them by walking up.
  • Solver limit. A conjunction with more than 8,192 parts is never given to a solver whole, so one slow check cannot stall the export.
  • Leaf cores. A clause that no single conjunction settles is tied to an unsat core of leaf conjuncts, so its lemma names only the conjuncts that matter.

Tests and documentation

  • Six new tests pin the linear memory, the solver limit, and the leaf cores, and the plan and README describe them.

An analogy for the leaf cores: the old lemma cited a whole book as evidence. The new one cites the two sentences that matter.

Worked example

This PR is about size, so no ten-line input is newly certified. The example is the PR's test generator guarded_chain at 2,500 links, shown with cuts. Its one assertion has 10,007 parts, above the new limit. At 2 links, old and new code wrote identical certificates.

Each link is a guard (not wi) and a clause that starts with wi. Z3 logs the clause without wi as assumed. That shorter clause follows only from the link together with its guard.

Each and-elimination step takes one side of the conjunction above it. Resolution then combines the two leaves with the lemma.

Review

The reviewer approved the change, with no blocker and no major finding.

  1. Minor, fixed. The reviewer removed the guard that keeps a large conjunction out of the last-resort solver call. Every test still passed, because the test raised its expected error before it inspected the solver's input. That guard prevents a 24 second, 10 GB solver call on the benchmark. The test now checks both outcomes and catches the removal.
  2. Minor, fixed. Deleting the same limit from the equivalence check also went unnoticed. A new test case requires that a large conjunction gets no such check.
  3. Nit, fixed. Switching off the loop that shrinks a core broke no test, and would only make Lean files larger. A test now pads a core with five unneeded leaves and expects the smallest lemma.
  4. Nit, kept with a comment. Some tests expect an exact core size, which depends on the core Z3 returns. They stay, because the smallest core is unique there. Removing the dependence is a follow-up.
  5. Nit, fixed. The README read as if the limit counted leaf conjuncts only. It now says nested conjunctions count too.
  6. Nit, fixed. One search function rebuilt a set on every call. It is now computed once.

Risks and open questions

  • Certificates change where a conjunction was undecided. Of the sample only plan-21 changed, and it still verifies.
  • The limit is a cliff. Just below it, a chain of 2,000 links exports with neither version in 300 seconds.
  • Why Z3 needs 24 seconds and 10 GB to assert a deeply nested conjunction was not traced.
  • Inputs where most clauses need a core over all leaves still grow faster than linearly.
  • The benchmark files are not in the repository, so tests pin the generated reduction only.

What comes next

  • Use leaf cores below the limit too, which requires checking the sample again.
  • Fix three sample files that now export but fail in Lean. Two run out of heartbeats on an arithmetic lemma. One times out deep in a 115,040-operand conjunction.
  • Make the chosen core independent of which core Z3 returns.

Glossary

and-elimination
The proof rule that takes one part out of a conjunction. From (and p q) it gives p.
assertion
A formula the input states as true, written (assert ...) in SMT-LIB.
assumed clause
A clause the solver logs as taken from the input, not derived. The replay must show that the assertions really imply it.
Boolean
The sort with the two values true and false.
canonical key
A number given to a formula so that formulas equal up to the order and grouping of operands get the same number.
certificate
A file that records a proof step by step, so that an independent checker can confirm it.
clause
A disjunction of literals, such as (or (not b0) b1).
clause log
The list of clauses a solver assumed, derived, and deleted while it searched for the refutation.
clause-log replay
The step that reads the clause log and rebuilds it as a certificate, connecting every assumed clause to the assertions.
conjunct
One operand of a conjunction. In (and p q) the conjuncts are p and q.
conjunction
A formula built with and. It is true when all its operands are true.
difference logic (QF_IDL)
Quantifier-free formulas over integers whose arithmetic atoms compare a difference with a constant, such as x - y <= 3.
equivalence check
A solver query that asks whether two formulas always have the same truth value.
EUF
The theory of equality with uninterpreted functions, where only = has a fixed meaning.
heartbeat
Lean's unit of work. A proof step that uses more heartbeats than its budget is stopped.
leaf conjunct
A conjunct that is not itself a conjunction. In (and p (and q r)) the leaves are p, q, and r.
linear and quadratic growth
Linear: twice the input costs twice as much. Quadratic: twice the input costs four times as much.
linear real arithmetic (QF_LRA)
Quantifier-free formulas over real numbers with sums and comparisons, such as x + 2 * y < 5.
literal
An atomic formula or its negation, such as b0 or (not b0).
mutation
A small deliberate bug put into a copy of the code, to see whether some test fails.
nesting depth
How many levels of operators sit inside one another. (and p (and q r)) has depth 2.
refutation
A proof that the assertions together imply False.
resolution
The proof rule that combines two clauses holding opposite literals. From (or a b) and (not a) it gives b.
symbol
A declared name in the input, such as the constant b0.
theory lemma
A clause that is valid on its own and enters the proof without premises. Here Lean proves each one from the Boolean structure of its formulas.
unsat core
A subset of formulas that is already contradictory. Here it is the few conjuncts that suffice to imply a clause.
