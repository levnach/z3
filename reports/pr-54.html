Prove Int cut lemmas by one split that z3 finds

Pull request levnach/z3#54 · State: OPEN · Opened 2026-10-31T02:21:08Z · Loop iteration 54

Open and not merged. Change commit 61b7494. This page covers both of the PR's commits.

In one paragraph

Some integer theory lemmas reach Lean with no multipliers at all. These are every cut and every Farkas lemma that z3 did not explain. Before this PR, Lean's arithmetic tactics had to redo z3's integer search, which could take minutes or many gigabytes. Now each such lemma is proved by one case split. z3, acting as an untrusted oracle, finds the split and two linear combinations under a fixed rlimit. Python checks that answer, and Lean checks each side's refutation. With two memory fixes, a 20-variable QF_LIA benchmark now verifies end to end. Nothing new is trusted.

Background

Earlier iterations proved integer Farkas lemmas that come with large multipliers by summing their bounds directly. Lemmas without multipliers, which this page calls lattice lemmas, still went to Lean's general arithmetic tactics. On the z3test input cut_lemma_02_002, with 188 such lemmas, Lean ran out of memory. This PR serves Milestone 3, equality and linear arithmetic.

What changed

  • A lattice lemma can now be proved by one case split, k < s or s ≤ k, each side closed by a linear combination.
  • The split and its multipliers come from a small z3 search under an rlimit, and Python re-checks the answer.
  • A wide Farkas lemma whose bounds span 8 or more atoms now also gets a direct combination.
  • Lean files from 5 MB, down from 8 MB, use serial elaboration, which saves memory.
  • The summing helper now itself rejects a negative multiplier on an inequality.
  • The old tactic proofs remain as a fallback, so a lemma without a split loses nothing.

An analogy: to show no whole number lies between 2.3 and 2.7, say “it is at most 2, or at least 3”. Each case contradicts one bound. The split does the same over a sum of variables.

Review

The reviewer approved, with no blocker and no major finding.

Minor: the rlimit margin might be too thin on Linux

The reviewer measured the split search on all 188 lemmas. The largest used 2.9M of a 5M rlimit. Linux CI might count differently, and one missing split would fail the new tests. The second commit raised the bounded search's limit to 20M. The unbounded search keeps 5M, since it once needed over 400M.

Minor: a slow split could block the fallback

Lean's first does not catch a heartbeat timeout. A slow split would fail the whole lemma instead of reaching the fallback. The reviewer never saw it, as splits took about 0.7 s. It was not changed, and is a follow-up.

Nit: a precondition lived only in a comment

The summing helper assumed only equalities get negative multipliers. A future caller could break this and waste a proof attempt. The second commit added the check and a test.

Risks and open questions

  • The new test adds about 3 minutes and 6.7 GB to a CI job that already uses over half its time limit. Linux was not measured.
  • Another z3 build may find another split. Lean still checks it.
  • Split searches have no total budget per certificate.
  • The heartbeat interaction from the review remains open.

What comes next

  • The cut in lia_gomory needs rounding inside one side of the split, so it still uses the tactic fallback.
  • A cheaper identity check would cut the roughly 26 MB each split costs Lean.
  • A rescan of the QF_LIA sample for lattice lemmas that get no split.
  • A per-certificate budget for split searches.
  • Real Farkas lemmas still go to grind.

Glossary

atom
A smallest unit inside a formula, here a single integer variable such as x5.
axiom
A statement Lean accepts without proof. The proofs here may use only Lean's standard axioms.
bound
An inequality or equality on a linear expression, such as x1 + x2 ≤ 7.
case split
A proof that considers every possible case separately. For integers, “k < s or s ≤ k” always covers everything.
clause
A disjunction of literals, where a literal is an atom or its negation. Example: x ≤ 3 or not (y ≤ 0).
cut
A new inequality that every integer solution satisfies but some fractional solutions do not. A Gomory cut is a common kind that z3 derives.
elaboration
Lean's step of turning source text into fully checked terms. Doing it in parallel is faster but uses more memory.
Farkas lemma
A theory lemma showing that some inequalities conflict, because a nonnegative sum of them gives a false statement such as 0 ≤ -1.
heartbeat
Lean's unit of work. A proof that uses more heartbeats than allowed is stopped with a timeout.
lattice lemma
This project's name for an integer theory lemma without multipliers: a cut, or a Farkas lemma that z3 did not explain. It holds only because the variables are integers.
linear combination
A sum of facts, each multiplied by a number. Example: 2·(x ≥ 1) plus 1·(−2x ≥ 0) gives 0 ≥ 2, which is false.
multiplier
The number each fact is scaled by in a linear combination. A multiplier on an inequality must not be negative.
oracle
A helper whose answers are used but not trusted. Every answer is checked before it counts.
QF_LIA
The SMT-LIB logic of quantifier-free linear integer arithmetic: sums of Int variables times constants, compared with ≤, <, and =.
refutation
A proof that a set of facts leads to False.
rlimit
z3's resource limit. Unlike a time limit, it gives the same result on every run of the same build.
sorry
Lean's placeholder for a missing proof. A file that uses it proves nothing.
tactic
A Lean command that builds part of a proof automatically. Example: omega decides integer linear arithmetic.
theory lemma
A clause that z3 asserts is true in a theory, here integer arithmetic. The certificate calls it a th-lemma, and Lean must prove each one.
