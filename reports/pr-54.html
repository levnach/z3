In one paragraph

Some integer theory lemmas reach Lean with their bounds listed but without the multipliers that combine them. These lattice lemmas include every cut and every unexplained Farkas lemma. The tactics omega and grind used to redo z3's integer search for them. Now each one is proved by a single case split. z3, as an untrusted oracle, finds a linear form s and a constant k. Each side of k < s or s ≤ k then ends in a short refutation. Python checks the answer, and Lean checks the proof. With two memory fixes, a 20-variable QF_LIA benchmark now verifies for the first time. Nothing new is trusted.

Background

Since PR #51, an integer Farkas lemma with multipliers got a direct proof. A lattice lemma has none, so it still went to omega or grind. That worked on small inputs. On the z3test benchmark cut_lemma_02_002, with 188 lattice lemmas, Lean ran out of memory. The plan listed it as still open. This PR serves Milestone 3, equality and linear arithmetic, which completes each fragment end to end.

What changed

  • A lattice lemma can now be proved by one case split, k < s or s ≤ k, with each side closed by a Farkas combination.
  • The split comes from a small z3 search, a mixed integer problem under a fixed rlimit, and Python re-checks it.
  • A wide Farkas lemma whose bounds span 8 or more atoms now also gets a direct combination.
  • Lean files from 5 MB, down from 8 MB, use serial elaboration, which saves memory.
  • The old tactic proofs stay as a fallback, so a lemma without a split loses nothing.

An analogy: to show no whole number lies between 2.3 and 2.7, say “it is at most 2, or at least 3”. Each case contradicts one bound. The split does the same over a sum of variables.

Review

The reviewer approved, with no blocker or major finding.

Minor: a thin margin in the benchmark test

The test demands a split for all 188 lattice lemmas within the search limit. The hardest search used over half of it on macOS, and Linux may count differently. A missing split would send a lemma back to grind, which had run out of memory. Fixed: the bounded search got its own, four times larger limit.

Minor: a slow split cannot fall through to the fallback

Lean's first does not catch a heartbeat timeout. So a slow split would fail the whole lemma instead of trying grind. No test showed this. Recorded as a follow-up: the older Farkas combination already behaved this way.

Nit: a rule stated only in a comment

The summing helper assumed only equalities get a negative multiplier, and said so only in a comment. Fixed: it now refuses such input, and a unit test covers it. A suggested per-certificate search budget is a follow-up.

Risks and open questions

  • Reconstruction now runs z3 searches, usually fast but up to a few seconds per lemma.
  • Another z3 build may find a different split. Lean still checks it.
  • The benchmark test adds about 3 minutes and a 6.7 GB peak to CI, measured on macOS only.
  • The heartbeat issue from the review remains open, and the post-merge CI result is unknown.

What comes next

  • The cut in lia_gomory needs gcd rounding inside a side, so it keeps grind.
  • A cheaper identity check, a QF_LIA rescan, and a per-certificate search budget.
  • Real-valued Farkas lemmas still go to grind.

Glossary

atom
A smallest term that a linear form is built from, usually one variable. In 2*x + 3*y the atoms are x and y.
bound
An inequality or equality on a linear form, such as x + y ≤ 3.
case split
A proof that covers every possibility by cases. Here: either k < s or s ≤ k, and both cases lead to a contradiction.
cut
A new inequality that holds for every integer solution but removes some fractional ones. A Gomory cut is a common kind. A split cut is a cut justified by one case split.
elaboration
Lean's step that turns source text into checked terms. Serial elaboration does one declaration at a time, which is slower but uses less memory.
Farkas lemma
A theory lemma proved by adding bounds with nonnegative multipliers until the sum reads 0 ≤ -1. That sum is the Farkas combination.
heartbeat
Lean's unit of work for a single declaration. A proof that uses too many heartbeats stops with an error.
lattice lemma
In this project, an integer theory lemma that lists its bounds without multipliers: a cut, or an unexplained Farkas or bound lemma.
linear form
A sum of variables times constant coefficients, such as -x1 + x14 - x5 - x10.
mixed integer problem
A system of linear constraints where some unknowns must be integers and others may be fractions.
multiplier
The constant that a bound is scaled by before it is added to the others in a combination.
oracle
A helper that proposes an answer without being trusted. Every answer is checked before it is used.
QF_LIA
The SMT-LIB logic of quantifier-free linear integer arithmetic.
refutation
A proof that a set of facts leads to False.
rlimit
z3's resource limit. It counts internal steps instead of seconds, so a run stops at the same point every time on one build.
tactic
A Lean command that builds part of a proof automatically. omega decides linear integer goals, and grind is a general automated prover.
theory lemma
A clause that holds in a background theory, such as integer arithmetic, and that the solver adds to its search. Written th-lemma in z3 proofs.
