This pull request is open and not merged. The change under review is commit f18b84b81.

In one paragraph

Some theory lemmas need small helper facts before a tactic can prove them. These are cast facts, floor bounds, integrality facts, and the excluded middle of each Boolean argument of an uninterpreted function or predicate. Until now the reconstructor wrote each such fact with every if-then-else term spelled out in full. Over nested ite chains, one fact could exceed a megabyte of Lean text. This PR states those facts over folded definitions instead, and unfolds them together with the goal. Lean text for the PR's test inputs shrinks from 8 to 16 MB to under 1 MB. Inputs that made Lean run out of heartbeats or kernel memory now check, so their refutations are certified. The trust boundary is unchanged.

Background

Iterations 100 to 102 already moved the ite gates, scaling facts and argument equalities of theory lemmas to folded definitions. The facts listed above were the last large ones still written out. On two chains of eight nested Int ite terms, the clause log certificates in the fragments QF_LIRA and QF_UFLIA failed in Lean. This work serves milestone 3 of the project plan, equality and linear arithmetic, which asks that each fragment work end to end.

What changed

  • Lemmas that compare Int terms through to_real now check when those terms are deep ite chains.
  • Lemmas whose atoms apply to_int or is_int get their floor bounds in folded form too.
  • A Real atom over Int terms is now tied to its Int twin by a short folded integrality fact.
  • A predicate or function with a Boolean argument over deep ite chains no longer blows up the Lean file.
  • Certificates with arrays behave exactly as before, so nothing that already worked there can break.
  • Two new tests check the shape of the facts without Lean and run all three variants through Lean on both cores.

An analogy: before, every helper fact carried a full photocopy of a long recipe. Now each fact points to the recipe by its page number, and Lean opens the book once.

All behaviour changes are in proof_to_lean.py. The rest is tests and documentation.

Review

The reviewer approved, with no blockers and no major findings.

  • Minor, fixed. The reviewer read the new shape test and asked what it would miss. It demanded the expected facts only on the clause-log core. On the legacy core it only checked file size. Its pattern also skipped the floor bound _f. So a regression that wrote facts out again, or dropped them, could slip through. Commit f18b84b81 now lists the expected facts for every variant and core, and the pattern matches _f. This matters because the Lean test only runs where Lean is installed.
  • Nit, fixed. A README sentence said “in any fragment”. That suggested the Boolean facts are folded even with arrays, which they are not. It now says “in every fragment without arrays”.
  • Nit, accepted. The new Lean test adds about 70 seconds to the CI Lean gate. It was kept, since it is the only end-to-end check of the folded facts on both cores.

Risks and open questions

  • The folded facts now come earlier in each lemma's hypotheses. All tests pass, but grind or omega might search differently on unseen inputs.
  • The integrality proof now unfolds only as deep as it needs. If that is too shallow, Lean rejects the lemma. It cannot accept a wrong one.
  • Still failing: to_int of nested Real chains under a function f, at depth 8, in QF_UFLIRA. Depth 6 passes.
  • CI and local gate results are not known at the time of writing.

What comes next

  • The to_int depth-8 failure is in the backlog.
  • Some facts are still written out in full: _bd, the _e bridges, the floor shifts, the projections, and every fact in certificates with arrays.

Glossary

atom
A formula with no Boolean structure inside it, such as a8 < 9.
Boolean
The sort with exactly two values, true and false. In SMT-LIB it is Bool.
cast
A conversion between sorts. to_real turns an Int into a Real, and to_int rounds a Real down to an Int.
clause
A disjunction of literals, such as x < 3 or not p(x). A literal is an atom or its negation.
clause log
One of two proof sources the exporter reads. It records the clauses the solver derived. The other source is the legacy proof object, called the legacy core.
congruence
The rule that equal arguments give equal results: if a = b then f(a) = f(b).
excluded middle
The fact that every proposition is either true or false: P or not P. In Lean it is Classical.em.
floor
The largest integer not above a number. The floor of 2.7 is 2. Its bounds are floor(r) ≤ r and r < floor(r) + 1.
folded definition
A named definition used by its name, such as term_10, instead of its full body.
fragment
A named subset of SMT-LIB, also called a logic. QF_UFLIA means quantifier-free, with uninterpreted functions and linear Int arithmetic.
grind
A Lean tactic that combines case splits, congruence closure and arithmetic to close a goal.
heartbeat
Lean's unit for counting work. A proof that uses more than the limit stops with a timeout error.
hypothesis
A fact available in a proof, introduced in Lean by have or as a theorem argument.
if-then-else term
A term that picks one of two values based on a condition, written (ite c a b) in SMT-LIB.
integrality fact
A fact saying a Real atom built only from Int terms means the same as an Int atom, so integer reasoning applies to it.
kernel
The small core of Lean that finally checks every proof. It is the part that must be trusted.
predicate
An uninterpreted function whose result is Boolean, such as p in the example.
refutation
A proof that a set of assertions leads to False.
revert and intro
Lean tactics. revert moves a hypothesis back into the goal, and intro takes it out again. Between them, a rewrite of the goal also rewrites that hypothesis.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A command that builds part of a Lean proof automatically, such as omega or grind.
theory lemma
A clause that holds because of a theory such as arithmetic, not because of Boolean logic alone.
trust boundary
The line between what must be trusted and what is checked. Here, every helper fact is still proved in Lean, so nothing new is trusted.
unfold
Replacing a definition's name by its body. A Lean tactic of the same name does this.
uninterpreted function
A function with a name and a signature but no fixed meaning. The only rule it obeys is congruence: equal arguments give equal results.
