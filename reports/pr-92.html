Certify distincts over the same terms in other orders in Lean

Pull request levnach/z3 #92 · State: OPEN · Opened 2026-11-08T00:21:28Z · Loop iteration 92

This pull request is open and not merged. The change under review is commit b85f48a.

In one paragraph

Some inputs assert a distinct over a list of constants and then deny a second distinct over the same constants in another order. Z3 refutes this right away. Its rewriter sorts the arguments, so both assertions become the same formula. The exporter ties the two distincts together with a single cnf lemma. Lean could not check that lemma once there were 12 or more Int constants. The Lean tactics ran out of heartbeats. This PR now splits both distincts into their pairs. It links each pair a = b to its reversed form b = a with the symmetry of equality. Then fast Boolean propagation closes the lemma. The result is a full Lean-checked refutation for these inputs. It adds no new axiom and no sorry.

Background

Earlier iterations taught the reconstructor to read a distinct as a conjunction of negated pair equalities. It only did so when the clause log held at least one pair written in the same order as the distinct. A reversed distinct has no pair in its own order. So it stayed one opaque atom. The lemma then fell back to slow arithmetic tactics over every unfolded pair. That fallback timed out at 12 Int constants, and also at 33. This work belongs to milestone 3, "Equality and linear arithmetic", of the project plan. It closes two backlog items, from iterations 53 and 90.

What changed

  • Two distincts over the same constants, in any order, now certify in Lean. This works over Int, Real, and an uninterpreted sort.
  • A distinct whose pairs appear in the log only with swapped sides is now read pair by pair. Before, it stayed one opaque atom.
  • Each reversed pair gets a one-line Lean bridge proved by core Lean's symmetry lemma eq_comm.
  • If the new proof attempt fails, Lean still tries the old unfolded proof. A wrong proof can never be accepted.
  • The plan document records the measured cost for 60 constants and the known limits.

Think of two guest lists of the same twelve people, one written forwards and one backwards. Before, the checker treated each list as a sealed envelope. It had to try every possible seating to prove they matched. Now it opens both lists and notes that "Ann is not Bob" is the same fact as "Bob is not Ann". After that, matching the lists is quick bookkeeping.

Worked example

This input is built from the PR's new test generator for 12 Int constants. Only the declarations are packed four to a line. All outputs below come from real runs of the scripts before and after the PR.

(a) The input

(set-logic QF_LIA)
(declare-const c0 Int) (declare-const c1 Int) (declare-const c2 Int) (declare-const c3 Int)
(declare-const c4 Int) (declare-const c5 Int) (declare-const c6 Int) (declare-const c7 Int)
(declare-const c8 Int) (declare-const c9 Int) (declare-const c10 Int) (declare-const c11 Int)
(assert (distinct c0 c1 c2 c3 c4 c5 c6 c7 c8 c9 c10 c11))
(assert (not (distinct c11 c10 c9 c8 c7 c6 c5 c4 c3 c2 c1 c0)))
(check-sat)

The first line says all twelve constants differ. The second denies the same fact with the list reversed.

Each constant becomes a term. The two distincts become conjunctions of 66 negated equalities, and formula_349 is the cnf lemma's clause "not the first distinct, or not the negated second one".

The theorem says the two assertions together imply False, and its last steps use the lemma that used to time out.

private theorem th_lemma_350 (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    : (formula_349 _atoms _vars) := by
  first
    | (have _f1 : (Iff ((term_1 _atoms _vars) = (term_0 _atoms _vars)) (formula_17 _atoms _vars)) := eq_comm
       have _f2 : (Iff ((term_2 _atoms _vars) = (term_0 _atoms _vars)) (formula_22 _atoms _vars)) := eq_comm
       ...
       have _f66 : (Iff ((term_11 _atoms _vars) = (term_10 _atoms _vars)) (formula_342 _atoms _vars)) := eq_comm
       refine Classical.byContradiction ?_
       ...
       have _f207 : (formula_17 _atoms _vars) := (Iff.mp _f1 _f206)
       exact (False.elim (_f74 _f207)))
    | (unfold formula_349 formula_348 formula_16 formula_14 formula_13 formula_12 term_11 ... term_0

The 66 new eq_comm lines say that each reversed pair, like c1 = c0, means the same as the logged pair c0 = c1. Propagation then finishes the proof, and the old omega path stays as a fallback.

Review

The reviewer approved the change. There were no blocker or major findings.

Minor: cost above 33 terms was untested

The reviewer tried a reversed distinct of 60 Int constants. Lean accepted it, but it took about 32 seconds. The bridges grew 3.4 times while the time grew about 11 times. A list of about 100 constants could hit the heartbeat limit. This matters because a slow check looks like a failure to a user. The author recorded the measurement in the plan document and added no size cap. Such inputs already failed from 12 constants before, so nothing got worse.

Minor: the expansion rule looks at the whole certificate

A distinct now splits into pairs in every lemma once any other distinct over the same constants exists anywhere. The reviewer built "bystander" inputs to see whether this caused extra work in unrelated lemmas. The output was byte-identical to the old exporter, so no regression appeared. This was not fixed. It is recorded as a follow-up to make the rule local to each clause.

Nit: a fragile test assertion

One test counted which pair equalities Z3's trimmed log happened to keep. A harmless change in Z3's log trimming could break that test while the exporter stayed correct. The assertion was removed. The test still checks the total pair count and one bridge per pair.

Risks and open questions

  • More lemmas now hand pairs to the propagation prover. The prover has a work bound, and a failed attempt falls back to the unchanged proof.
  • A reordered distinct of about 100 constants may still exceed the heartbeat limit. No test covers that size.
  • CI results and the local gate result are unknown at the time of writing.

What comes next

  • Expand a distinct only when the other distinct appears in the same clause.
  • Bridge swapped pairs outside cnf lemmas too. Today only cnf lemmas get them.
  • Rescan the benchmarks that contain wide distincts. That task from iteration 90 is still open.

Glossary

assertion
A formula the input states as true, written (assert ...) in SMT-LIB.
atom
A formula with no Boolean connective inside it, treated as one unit. Example: c0 = c1. An opaque atom is one whose inside the prover does not look at.
axiom
A statement Lean accepts without proof. Adding one would widen what must be trusted.
clause
A disjunction ("or") of literals. Example: (or (not p) q).
clause log
The record of clauses Z3's solver learned or used, which the exporter turns into a certificate.
cnf lemma
A clause that holds by pure Boolean structure, used to break a formula into clauses (conjunctive normal form). Example: (or (not (and p q)) p).
conjunction
An "and" of several formulas. Each part is called a conjunct.
distinct
The SMT-LIB operator saying all its arguments are pairwise different. (distinct a b c) means a ≠ b, a ≠ c, and b ≠ c.
heartbeat
Lean's unit of work for a proof step. When a step uses more than its limit, Lean stops with a timeout error.
literal
An atom or its negation. Example: c0 = c1 or (not (= c0 c1)).
propagation
Deriving new facts step by step from known ones by simple Boolean rules. Example: from "p or q" and "not p", conclude "q".
refutation
A proof that a set of assertions leads to a contradiction, that is, to False.
rewriter
The part of Z3 that simplifies formulas before solving, for example by sorting the arguments of a distinct.
sort
The type of a value, such as Int, Real, or Bool.
symmetry of equality
The rule that a = b holds exactly when b = a holds. Core Lean calls it eq_comm.
tactic
A Lean command that searches for a proof automatically. The omega tactic decides integer arithmetic. The grind tactic is a broader general search.
uninterpreted sort
A sort with no built-in meaning, declared by the input. Example: (declare-sort U 0). Only equality between its values is known.
