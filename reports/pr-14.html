In one paragraph

Inputs in QF_LIA and QF_UFLIA may now use integer div and mod by a nonzero numeral, and abs. Before this PR the exporter rejected every such input. Now the division operators are atoms of the linear arithmetic, like variables. Z3's defining clauses for them arrive in the clause log under a hint named arith, and each becomes a theory lemma that Lean proves by itself. In Lean, div and mod become the integer / and %, which follow the same Euclidean convention as SMT-LIB, and abs becomes the if-then-else term SMT-LIB defines it as. A zero or non-constant divisor is still rejected, which keeps the soundness boundary explicit.

Background

Iterations 12 and 13 brought linear integer arithmetic, then integer arithmetic with uninterpreted functions, into the Lean pipeline. The Farkas, bound, cut, and implied equality hints were already checked. But any refutation mentioning div, mod, or abs stopped at the exporter with "unsupported arithmetic operator", although QF_LIA benchmarks use these operators routinely. The PR serves milestone 3 of the plan, which asks for each fragment to be completed end to end before another is added.

What changed

  • Exporter. You can now export a certificate for an integer input that divides by a nonzero numeral or takes an absolute value. A zero, variable, or function divisor is still refused, as are rem and abs over the Real sort.
  • Clause-log replay. The replay rebuilds the log's division terms, keeps them opaque, and shape-checks every literal of an arith hint. It acts like a doorman who checks that each guest looks like an arithmetic fact, without asking whether it is true.
  • Lean reconstructor. It renders div and mod as / and %, renders abs as its defining ite, and proves each arith lemma with the tactic first | omega | grind. Any division node with a zero or non-constant divisor is rejected.
  • Tests. Seven documented inputs, a random generator with pinned seeds, and tampering tests, including a false arith lemma that Lean must refuse.
  • Documentation. Both READMEs and the plan document describe the new operators and the soundness boundary.

No C++ or Lean library source changed.

Worked example

The input is the PR's documented test lia_div. It says that y is x divided by 3, that x is 7 or 8, and that y is not 2. Both 7 div 3 and 8 div 3 equal 2, so the assertions contradict each other.

(a) The input

(set-logic QF_LIA)
(declare-const x Int)
(declare-const y Int)
(assert (= y (div x 3)))
(assert (>= x 7))
(assert (<= x 8))
(assert (not (= y 2)))
(check-sat)

(b) Before the PR

The exporter from the parent commit refused the input. Its complete output:

proof_certificate.py: error: unsupported arithmetic operator: div

(c) After the PR

The new pipeline wrote a certificate and a Lean file, and the Lean check accepted it with "Lean checks passed". Below are the parts that embody the new feature.

-- Int div and mod by a numeral are Lean's Euclidean / and %; abs is the ite SMT-LIB defines.

def term_1 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Int := _vars 1
def term_2 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Int := ((3 : Int))
def term_3 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Int := ((term_1 _atoms _vars) / (term_2 _atoms _vars))
...
def term_13 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Int := ((term_1 _atoms _vars) % (term_2 _atoms _vars))
def term_14 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Int := ((term_12 _atoms _vars) + (term_13 _atoms _vars))
def formula_15 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Prop := ((term_14 _atoms _vars) = (term_1 _atoms _vars))
...

The SMT-LIB (div x 3) has become x / 3, and the solver's own remainder term, which the input never wrote, has become x % 3.

set_option maxHeartbeats 1000000 in
private theorem th_lemma_16 (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    : (formula_15 _atoms _vars) := by
  unfold formula_15 term_14 term_13 term_12 term_3 term_2 term_1
  first | omega | grind (splits := 64)

set_option maxHeartbeats 1000000 in
private theorem th_lemma_19 (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    : (formula_18 _atoms _vars) := by
  unfold formula_18 term_17 term_13 term_2 term_1
  first | omega | grind (splits := 64)
...

These are Z3's arith axioms. The first says 3 times x / 3 plus x % 3 equals x, the second says the remainder is at least 0. They have no premises, so Lean proves them from scratch. A third lemma, cut here, bounds the remainder by 2.

theorem unsat (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    (_h0 : (formula_4 _atoms _vars))
    (_h1 : (formula_6 _atoms _vars))
    (_h2 : (formula_8 _atoms _vars))
    (_h3 : (formula_11 _atoms _vars))
    : False :=
  ...
  let _step_16 : (formula_15 _atoms _vars) :=
    (th_lemma_16 _atoms _vars)
  ...

The main theorem takes the four assertions as hypotheses and derives False. Its first step is the division axiom above.

Review

The reviewer approved the change with no blocker or major finding. Three smaller findings were raised.

  • Minor: Real abs slipped through the exporter. The reviewer probed thirteen unusual inputs. One took abs of a Real variable, which SMT-LIB does not define but Z3 accepts. The exporter let it through and only the reconstructor refused it, which the regression matrix counts as a failing checker rejection instead of the benign "unsupported" status. Nothing was published, so soundness was never at risk. The exporter now rejects it, with a new test.
  • Nit: the documentation credited the wrong tactic. Three passages said that omega decides the arith axioms. The reviewer tried a negative divisor and found that omega fails there, while the grind fallback proves it. The code was already right. The prose now says which tactic handles which sign of divisor.
  • Nit: the arith shape check ignores polarity. The sibling cut path refuses a disequality, but the arith check accepts either polarity. The integrator judged this correct: cut builds a linear combination, which a denied equality cannot join, while arith leaves the whole clause to Lean. Comments in both files now say so.

Risks and open questions

  • Division by zero. Lean's integer division is total, so x / 0 is 0, while SMT-LIB leaves it undefined. A zero divisor that slipped through could let Lean prove a refutation valid under only one reading of the input. Both the exporter and the reconstructor refuse it.
  • The arith lemma is checked by Lean alone. Python checks only its shape, as for cut, and a test confirms that Lean rejects a false one. Real certificates accept the hint too, and one that grind cannot close is rejected rather than misproved.
  • Structural mismatch costs a solver call. The replay matches division atoms by identity. A log term written in a different order from the input falls back to an unsat core and an extra solver call.

What comes next

  • Division by a term, which is nonlinear, plus rem and the Int-to-Real conversions stay rejected.
  • The legacy proof core still rejects all integer input, so integer certificates flow through the clause log only.
  • A division input in the z3test matrix would let CI exercise the arith hint directly. That repository is outside this loop.

Glossary

abs
The absolute value of an integer. SMT-LIB defines (abs t) as (ite (>= t 0) t (- t)).
atom
A smallest building block that a proof rule does not look inside. Here (div x 3) is treated like a plain variable.
Boolean
A value that is either true or false.
bound hint
A proof step that derives a new upper or lower bound on a term from existing ones.
clause
A disjunction of literals, that is, a list of literals of which at least one must hold. The empty clause is a contradiction.
clause log
Z3's record of every clause the solver learned while running, each tagged with the hint that explains it.
congruence
The rule that equal inputs give equal outputs: if a = b then f(a) = f(b).
cut
An integer-only step that tightens a bound by rounding, since an integer cannot sit strictly between two whole numbers.
disequality
A literal of the form a ≠ b, the negation of an equality.
div
Integer division in SMT-LIB, written (div t k). With the Euclidean convention, 7 div 3 is 2 and -7 div 3 is -3.
divisor
The number you divide by. In (div x 3) the divisor is 3.
Euclidean convention
The rule that the remainder is always between 0 and |k| - 1, even for negative inputs or divisors. SMT-LIB and Lean's Int both follow it.
Farkas lemma
A proof step that adds up linear inequalities with positive weights to reach an obvious contradiction such as 0 < 0.
fragment
A restricted family of inputs, named by its logic, such as QF_LIA, that a tool supports as a unit.
hint
A tag on a logged clause naming the rule that justifies it, for example farkas, cut, or arith.
implied equality
A step that concludes a = b from two bounds a <= b and a >= b.
if-then-else term
A term (ite c a b) whose value is a when the condition c holds and b otherwise.
linear arithmetic
Arithmetic in which variables are only added, subtracted, or multiplied by constants, never by each other.
literal
An atom or its negation, such as x >= 7 or not (y = 2).
mod
The remainder of integer division in SMT-LIB, written (mod t k). With the Euclidean convention, -7 mod 3 is 2.
nonlinear
Arithmetic where variables multiply or divide each other, such as (div x y). Much harder to decide than linear arithmetic.
numeral
A literal number written in the input, such as 3 or -3, as opposed to a variable.
polarity
Whether a literal appears positively (a = b) or negated (not (a = b)).
QF_LIA
The logic of quantifier-free linear integer arithmetic.
QF_UFLIA
QF_LIA extended with uninterpreted functions.
refutation
A proof that a set of assertions leads to a contradiction, so no assignment can satisfy them all.
sort
The type of a value, such as Int, Real, or Bool.
soundness
The property that the checker accepts only genuinely valid proofs. A soundness boundary states where that guarantee stops.
tactic
A Lean procedure that searches for a proof automatically. omega decides linear integer facts and grind is a broader fallback.
tampering test
A test that deliberately corrupts a certificate and checks that the pipeline rejects it rather than publishing a proof.
theory lemma
A clause that is true by arithmetic alone, with no reference to other proof steps. Lean must prove it from scratch.
uninterpreted function
A function symbol with no fixed meaning. The only thing known about f is that equal arguments give equal results.
unsat core
A subset of the assertions that is already contradictory on its own.
