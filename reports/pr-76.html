In one paragraph

This PR lets the pipeline certify unsat results over nested arrays. These are arrays whose index sort or element sort is itself an array sort. A two-dimensional matrix (Array Int (Array Int Int)) is the typical case. The exporter, the clause log replay, and the reconstructor now accept such sorts at any depth. In Lean, each one becomes a function type such as Int -> (Int -> Int). The PR also closes two gaps in the generated lemmas. A read through a row that was stored into a matrix now carries the facts that the grind tactic needs. A gap that already broke some flat-array inputs on master is fixed too. No new axioms and no sorry are added, and the trust boundary is unchanged.

Background

Earlier PRs taught the pipeline arrays whose components are flat: uninterpreted sorts, Int, Real, and Bool. They also covered sets, maps, and constant arrays. Any input that declared an array of arrays was still rejected by the exporter. The messages were "unsupported array operator: select" or "only arrays over uninterpreted sorts, Int, Real, and Bool". That blocked every unsat input over two-dimensional arrays, arrays of sets, or arrays indexed by arrays. Such inputs are common in the memory models of the SMT-LIB logics QF_ALIA and QF_AUFLIA. Z3 already produced clause logs for them with its usual array and EUF hints. Only the checking side was missing. The work serves milestone 4 of the plan, "Broader theories and integration", which treats arrays as their own extension.

What changed

  • You can now export a certificate for an input that declares arrays of arrays, or arrays indexed by arrays, at any depth.
  • The reconstructor turns each nested array sort into a Lean function type, so a matrix of Int becomes Int -> (Int -> Int).
  • A read through a row stored inside a matrix now comes with the read-over-write facts that Lean needs to follow it.
  • A seven-line flat Int array input, stored_read_atom, failed in Lean on master and now verifies.
  • Tampered or absurdly deep sort names, and Boolean maps over sets indexed by arrays, are now rejected with a clean error.

An analogy helps with the third bullet. Think of a matrix as a cabinet of drawers. Putting a new drawer in the cabinet and then reading one slot of it takes two steps. Z3's rewriter does both at once, and no term for the new drawer's slot appears in the certificate. The reconstructor now writes down what the new drawer holds at that slot, for every drawer stored along the way.

Worked example

The input below reads cell (i, j) after writing v there in a matrix. It is a shortened form of the PR's test input nested_read_own_write, with the two copies of each index merged. All three pieces come from real runs of the base and the merged code.

(a) The input

(declare-fun a () (Array Int (Array Int Int)))
(declare-fun i () Int)
(declare-fun j () Int)
(declare-fun v () Int)
(assert (not (= (select (select (store a i (store (select a i) j v)) i) j) v)))
(check-sat)

(b) Before: the base commit

proof_certificate.py: error: unsupported array operator: select

The old exporter stopped at the first read whose value is an array, so no Lean file was produced.

(c) After: the generated Lean file

The matrix sort becomes a family of functions from Int to rows, and each row is a function from Int to Int.

def term_2 ... : (Int -> Int) := (_select (term_0 _atoms _vars _m) (term_1 _atoms _vars _m))

def formula_10 ... : Prop := (Not (formula_9 _atoms _vars _m))

Each subterm of the input gets a name: term_2 is the row a[i], term_5 is that row with v written at j, and term_8 is the final cell.

Review

The reviewer approved the PR. There were no blocker or major findings. All four smaller findings were addressed.

  1. Minor: array-valued default values stayed folded. The reviewer wrote a six-line input that sets a matrix equal to a constant array of rows. Z3's array solver introduced the default row of that array on its own. The reconstructor kept that term opaque, so grind could not connect it to the constant row and failed in three lemmas. The fix unfolds default values like reads, and the input is now a documented test called const_rows_default. It mattered because "constant arrays of arrays" was advertised as supported.
  2. Minor: the soundness argument missed Boolean maps over sets indexed by arrays. The argument places each outer array inside Lean's function space and gives it one fixed value off the embedded indices. The reviewer noticed that a complement flips that fixed value, so the argument no longer applied. The reviewer did not think the result was unsound, but the written argument did not cover it. The implementer chose to reject these maps in both the exporter and the reconstructor, with new tests. Maps over rows of sets, indexed by Int, are still accepted.
  3. Nit: a crash on deeply nested tampered names. A forged sort name nested 2000 levels deep raised a Python recursion error instead of a clean rejection. The parser now stops at 64 levels and rejects the name, and a test covers the 2000-level case.
  4. Nit: a stale code comment. It still listed only flat element sorts and was corrected.

Risks and open questions

  • The PR flags a possible soundness gap in older code from PR #74, reasoned but not checked in Lean. Maps over sets indexed by an uninterpreted sort rely on the same fixed-value argument, which may fail when Lean's single carrier type holds more than one sort. It matters only if Z3 ever emits a wrong unsat proof.
  • The changes to which terms stay folded touch every array lemma. All earlier array inputs still verify.
  • The new stored-row facts grow with long store chains. Twelve symbolic row stores gave 420 facts and about 1.5 s in Lean. A 30-row case was not checked in Lean.
  • grind relates row equalities through congruence and extensionality. This was tested only on small inputs.
  • Still not covered: reads of an if-then-else term over a store, constant arrays over array indices, and array-valued default values in the input.
  • No z3test regression newly certifies, because every nested-array file there is sat.

What comes next

  • Restrict maps over sets indexed by uninterpreted sorts, or find a different embedding, to close the possible gap above.
  • Carry the stored-row facts through the branches of an ite. This gap affects flat arrays too and caused about 5% of the reviewer's random failures.
  • Add a random generator for arrays indexed by arrays and for Bool or Real leaves.
  • Search the SMT-LIB QF_AUFLIA samples for unsat nested-array inputs.

Glossary

array
A total map from an index sort to an element sort. (Array Int Bool) maps every Int to a Bool.
axiom
A statement Lean accepts without proof. Adding one widens what must be trusted.
Boolean (Bool)
The sort with exactly two values, true and false.
clause log
The record Z3 writes while solving: each learned clause, plus a hint naming the theory step that justifies it. A clause is a disjunction of literals, such as x = 1 or y < 0.
congruence
The rule that equal arguments give equal results: if i = j, then a[i] = a[j].
constant array
An array with the same value at every index, written ((as const (Array Int Int)) 5). Its default value is that constant.
EUF
Equality with uninterpreted functions: the theory of equality and congruence over function symbols with no fixed meaning.
exporter
The script that runs Z3 on an input and writes the certificate, a JSON file with the terms and proof steps.
extensionality
The rule that two arrays are equal if they agree at every index. When they differ, a witness index shows where.
function type
A Lean type of functions, written A -> B. Int -> (Int -> Int) takes an Int and returns a row.
grind
A Lean tactic that combines congruence, case splits, and arithmetic to close a goal.
if-then-else term (ite)
A term that picks one of two values by a condition, written (ite c x y).
kernel
Lean's small core that checks every proof term. It is the part that must be trusted.
lemma
A small proved statement used by a larger proof. Each proof step here becomes one lemma.
logic (SMT-LIB)
A named fragment of SMT-LIB. QF_ALIA means quantifier-free arrays and linear Int arithmetic, and QF_AUFLIA adds uninterpreted functions.
map (array map)
An operator that applies a function at every index, such as ((_ map not) s). Set union and complement are maps.
nested array
An array whose index or element sort is itself an array sort, such as a matrix (Array Int (Array Int Int)).
read-over-write
The rule that reading index j after a write at i gives the written value if j = i, and the old value otherwise.
reconstructor
The script that turns a certificate into a Lean file whose main theorem states the refutation.
refutation
A proof that a set of assertions leads to False.
sat
Satisfiable: some assignment makes all assertions true. A sat input has no refutation to certify.
select (read)
The array read (select a i), the value of a at index i.
set
An array with Bool elements, such as (Array Int Bool). The index is a member when the value is true.
sort
The type of a value in SMT-LIB, such as Int, Real, Bool, or (Array Int Int).
sorry
A Lean placeholder that skips a proof. A file containing it proves nothing.
soundness
The property that a checker accepts only true statements. A soundness gap could let a false unsat through.
store (write)
The array write (store a i v), a new array equal to a except that index i holds v.
tactic
A Lean command that builds part of a proof automatically, such as omega for integer arithmetic.
trust boundary
The line between what is checked and what is trusted. Here the theorem's hypotheses are bound to the original input, and only Lean's kernel is trusted.
uninterpreted sort
A sort declared with no fixed meaning, such as (declare-sort U 0). Only equality between its values is known.
