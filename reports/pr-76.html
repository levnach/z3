In one paragraph

The pipeline now certifies arrays whose index sort or element sort is itself an array, at any depth. Examples are a matrix (Array Int (Array Int Int)) and a table keyed by arrays, (Array (Array Int Int) Bool). Such inputs come from the QF_ALIA and QF_AUFLIA fragments, often from memory models of programs. In Lean each nested array becomes a function type, such as Int -> (Int -> Int). The PR also closes two gaps in the lemma proofs. One of them already broke a 7-line input over plain arrays. No new axiom is added, so every certified refutation still rests only on theorems proved in the generated file.

Background

Earlier PRs (#73 to #75) taught the pipeline arrays over uninterpreted sorts, Int, Real, and Boolean indices. They also covered constant arrays, sets, and maps over sets, all replayed from the clause log. But any array of arrays, or array indexed by arrays, was rejected by the exporter. The messages were "unsupported array operator: select" or "only arrays over uninterpreted sorts, Int, Real, and Bool". This PR serves milestone 4 of the plan, "Broader theories and integration", which lists arrays as a distinct extension.

What changed

  • Exporter. You can now export an unsat input whose arrays nest other arrays, and a select may return a whole row.
  • Clause-log replay. The replay now reads nested sort names like (Array Int (Array Int Int)), also inside constant arrays.
  • Reconstructor types. Lean now receives each nested array as a function returning a function, with a family name such as arrs_iaii.
  • Reconstructor lemmas. Reads through a row that was just stored now get the facts Lean's tactic needs, so these proofs now check.
  • A fix for plain arrays. A read that is both a lemma atom and a stored value is now unfolded, so the 7-line input stored_read_atom now verifies.
  • Safe rejections. Maps and set operators over sets indexed by arrays are now rejected, because the soundness argument does not cover them.

Worked example

This input is nested_read_own_write_evaluated from the PR's new tests. Think of a as a grid of numbers. We write v into cell (i, j) and read that cell back. The input claims the result is not v, which is impossible.

(a) The input

(declare-fun a () (Array Int (Array Int Int)))
(declare-fun i () Int)
(declare-fun j () Int)
(declare-fun v () Int)
(assert (not (= (select (select (store a i (store (select a i) j v)) i) j) v)))
(check-sat)

The main theorem says: in every interpretation, the input's assertion leads to False.

private theorem rewrite_16 (_atoms : Nat -> Prop) (_vars : Nat -> Int) (_m : Interpretation)
    : (formula_15 _atoms _vars _m) := by
  ...
    | (unfold term_8 term_7 term_3 term_1
       ...
       have _s7 := _store_apply ((term_0 _atoms _vars _m)) (_vars 0) ((term_5 _atoms _vars _m)) (_vars 0)

Z3's rewriter simplified the double read to v in one step, and this lemma checks that step. The fact _s7 reads the new row back from the grid. The fact _n8_0 is the new "stored row" fact: it reads cell j of the stored row, which never appears as its own term in the certificate.

Review

The reviewer approved the PR. There were no blocker or major findings. All four findings were resolved in the second commit.

  1. Minor: default rows stayed folded. The reviewer wrote a 6-line input with constant arrays of rows. Z3's array solver added its own default terms whose values are rows. The reconstructor kept those terms opaque, so Lean's grind tactic failed in three lemmas. This mattered because "constant arrays of arrays" was advertised as supported. The fix unfolds these default terms too, and the input became the test const_rows_default. That test fails without the fix and passes with it.
  2. Minor: the soundness argument missed maps over array-indexed sets. The argument places each outer array into Lean's function space, with one fixed value at indices outside the embedding. The reviewer noticed that complement flips that fixed value, so the argument no longer applies. The reviewer did not think this was actually unsound. The implementer chose the safe route: such maps are now rejected, and new tests check the rejection.
  3. Nit: a crash on absurdly deep sort names. A tampered certificate with about 2000 nesting levels raised a Python recursion error instead of a clean rejection. The parser now stops at 64 levels, and a 2000-level test checks it.
  4. Nit: a stale comment about select declarations was corrected.

Two suggestions were left for later: stored-row facts through if-then-else terms, and a random generator for arrays indexed by arrays.

Risks and open questions

  • A possible soundness gap in older code. The PR author reasoned, without a Lean check, that sets over uninterpreted indices (from PR #74) may have the same embedding problem as review finding 2. It would only matter if Z3 emitted a wrong unsat proof.
  • Proof size. Stored-row facts grow with long store chains. With 12 symbolic row stores, Lean still took about 1.5 seconds. A 30-row case was not checked in Lean.
  • Not covered yet. Reads of an if-then-else over a store fail, also for flat arrays. Constant arrays over array indices and default values that are arrays in the input stay rejected.
  • Limited real-world coverage. All z3test regressions with nested arrays are sat, so none newly certifies. The random sweep covered only 2-D Int grids.

What comes next

  • Restrict maps over uninterpreted-index sets to safe inputs, or give a different embedding.
  • Extend stored-row facts through if-then-else branches.
  • Add a random generator for arrays indexed by arrays.

Glossary

array
A total map from an index sort to an element sort. (Array Int Bool) maps every integer to true or false.
axiom
A statement accepted without proof. A trustworthy certificate adds none of its own.
Boolean
The sort with exactly two values, true and false. SMT-LIB calls it Bool.
clause log
A record, written by Z3 while solving, of the clauses it learned and the theory lemmas behind them. A clause is a disjunction of literals.
constant array
An array with the same element at every index, such as ((as const (Array Int Int)) 5).
default value
The element an array holds at all but finitely many indices. Z3's array solver uses it to reason about constant arrays.
embedding
A one-to-one translation of values from one structure into another that keeps the operations meaningful.
extensionality
The rule that two arrays are equal if they agree at every index. If they differ, a witness index shows where.
fragment
A named family of SMT inputs. QF_ALIA means quantifier-free arrays with linear integer arithmetic.
function type
The Lean type of functions, written A -> B. Int -> (Int -> Int) returns a function for each integer.
if-then-else term
A term that picks one of two values by a condition, written (ite c x y) in SMT-LIB.
kernel
The small core of Lean that finally checks every proof. Trust rests on it.
lemma
A helper theorem proved on the way to the main result. Here, each step of Z3's proof becomes one lemma.
map
An operator that applies a function at every index, such as ((_ map not) s). Set operators are maps over Boolean arrays.
refutation
A proof that a set of assertions leads to False.
rewriter
The part of Z3 that simplifies terms, for example a read right after a write at the same index.
select
The array read operation. (select a i) is the element of a at index i.
set
An array with Boolean elements. (select s x) is true when x belongs to s.
sort
The type of a value, such as Int, Real, Bool, or (Array Int Int).
soundness
The guarantee that a checker only accepts true claims. An unsound step could certify a wrong unsat answer.
store
The array write operation. (store a i v) is a with index i changed to v.
tactic
A Lean command that builds a proof automatically. grind and omega are tactics.
uninterpreted sort
A sort declared with only a name, like (declare-sort U 0). Nothing is known about its values except equality.
