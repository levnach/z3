State enumeration cases of applications over folded definitions

Pull request #112 State: MERGED Date: 2026-11-11T01:12:54Z Loop iteration: 111

Merge commit: 46bd831e4 Merged: 2026-11-11T01:12:54Z

In one paragraph

This PR shrinks the Lean proofs of theory lemmas over enumeration sorts. Such a lemma needs one fact per application of an uninterpreted function that returns an enumeration value. The fact says the value is one of the sort's constructors. Before, the fact spelled out the application's arguments in full. Over a nested if-then-else term chain, that copied the whole chain again and again. Now the fact names each argument by its definition, and it is unfolded together with the goal. On the PR's eight-level test input, the certificate went from too big to check to about one second of checking. The trust boundary does not move. Lean still checks every fact.

Background

In iterations 107 to 110, EUF lemmas learned to keep if-then-else terms folded in the goal. The grind tactic then proves them. But the enumeration facts that grind needs for its case splits were still written out in full. So these facts filled most of the file, and they did not even mention the goal's folded terms. An input with two eight-level chains of Color ites was therefore rejected for lack of memory and time. This work extends the plan's milestone 3, equality and uninterpreted functions, to enumeration datatypes. Those datatypes are one of the broader theories of milestone 4.

What changed

  • A theory lemma can now state the cases of an enumeration-valued application by citing its arguments' definitions instead of copying them.
  • These facts are now reverted before the lemma's unfold and reintroduced after it, so the unfold rewrites them exactly as it rewrites the goal.
  • Inputs whose ite chains are eight or twelve levels deep now produce small certificates that Lean checks in seconds.
  • Developers can now generate ite-chain inputs of any depth with the new test generator enumeration_chain_instance.
  • A pinned Int test seed now catches the mistake of naming the application itself in the unfold.

Think of a paper that writes "by equation 5" instead of copying equation 5 into every later step. The new facts work the same way. Certificates that contain arrays still write the facts out in full.

Review

The reviewer approved the PR with no blockers and no major findings.

  • Minor: a key design choice had no test. The new code lists the arguments, not the application, as names to unfold. In an Int lemma with opaque atoms, the application's own definition is already unfolded earlier. Naming it again makes unfold fail. The reviewer planted exactly that mistake. All 31 enumeration tests still passed, yet 11 real inputs failed in Lean. So a future edit could break such certificates without any test noticing. The fix pins Int seed 53 in ENUM_SEEDS, and the planted mistake now fails that test.
  • Nit: a regular expression was too narrow. It matched one-digit field numbers only. With ten or more enumeration-valued functions, the test would fail for no reason. It now accepts any number of digits.
  • Suggestion: a dense README sentence was rewritten more simply.

Risks and open questions

  • The change affects completeness only. A fact that Lean cannot check, or a failed unfold, rejects the certificate. Nothing is skipped or trusted.
  • Most of the 155 changed inputs grow slightly, by up to 5 percent, because of the extra revert and intro lines. Lean time on them stayed the same within noise.
  • With arrays, the enumeration facts are still written out in full and could still grow large.

What comes next

  • A sixteen-level chain with extra disequalities is still 247 MB and runs out of memory. Most of that is proof steps, the next size item.
  • Datatype lemmas with folded ites, from iteration 110, need their own input generator to be tested.
  • Folding the enumeration facts in certificates that contain arrays is still open.

Glossary

application
A function applied to arguments, such as (g u0 red).
case split
Proving a goal by checking each possible case separately, for example "x is red, or green, or blue".
certificate
The proof that Z3 exports, which Lean then checks step by step.
clause
A disjunction of literals, that is, an "or" of them, such as (or (not (= a b)) (= (f a) (f b))).
congruence
The rule that equal arguments give equal results: if a = b then f a = f b.
constructor
One of the named values of a datatype. red, green, and blue are the constructors of Color.
definition
A name given to a term, such as term_45, so later text can cite it instead of repeating it.
disequality
A statement that two terms differ, such as (not (= u8 w8)).
enumeration sort
A datatype whose values are a fixed list of constants, such as Color with three colors.
EUF
Equality with uninterpreted functions, the theory of reasoning with = and congruence alone.
folded
Kept as a short name instead of being replaced by its full definition. The opposite is unfolded.
goal
The statement that a Lean proof is currently trying to prove.
grind
A Lean tactic that proves goals automatically by combining facts, equalities, and case splits.
if-then-else term
A term whose value depends on a condition, written (ite c a b): it is a if c holds, and b otherwise.
interpretation
An assignment of meaning to every symbol of the input. The Lean proof must work for every interpretation.
literal
A Boolean atom or its negation, such as (= a b) or (not (= a b)).
opaque atom
A subterm that an arithmetic lemma treats as an unknown number, such as one built with div or mod.
refutation
A proof that the assertions together lead to a contradiction, that is, imply False.
revert
A Lean tactic that moves a known fact back into the goal, so later rewriting steps change it too.
sort
The type of a value, such as Int, Bool, or Color.
tactic
A command inside a Lean proof that performs one proof step, such as unfold or grind.
theory lemma
A clause that is true by the rules of a theory, such as equality or arithmetic, and that the solver adds during its search.
trust boundary
The line between what Lean checks and what must be taken on faith. This PR keeps everything on the checked side.
unfold
Replacing a defined name by its definition. In Lean it is also the name of the tactic that does this.
uninterpreted function
A function symbol with no fixed meaning, such as f or g. Only congruence is known about it.
