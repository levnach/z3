Retry failed cnf lemma searches over a z3 unsat core of the gates

Pull request levnach/z3#97 · State: OPEN · Opened 2026-11-08T07:31:36Z · Loop iteration 97

This pull request is not merged. The change it proposes ends at commit 00b99a83d. It contains three commits on top of 7115198.

In one paragraph

A search proves each cnf lemma in Lean by propagation and case splits over its gates. When it ran out of budget, the pipeline fell back to one tactic call, grind, which can fail on large inputs. Now the reconstructor first asks z3 for an unsat core of the lemma's propositional abstraction, then searches again over the core's gates only. The core is an untrusted oracle: it only steers the search, and the Lean kernel still checks every step. No axiom or sorry is added. This matters because the failing cnf lemma of a QF_IDL benchmark now gets a step-by-step refutation instead of a fallback that Lean rejects.

Background

Before this PR, the propositional prover always chose the true disjunction with the fewest open disjuncts, earliest first. On QF_IDL planning/plan-21, a single assertion holds one disjunction per time step. The prover worked through about fifty earlier steps before reaching the one the clause is about, and ran out of budget. The grind fallback then failed in Lean with "maximum number of steps exceeded". This work serves milestone 2, the kernel-checked Boolean slice, on inputs from the QF_IDL regression scans.

What changed

  • When the search for a cnf lemma gives up, the reconstructor now retries over the gates z3's unsat core says are needed.
  • The retried search ignores gates outside the core, so it no longer wastes its budget on unrelated time steps.
  • A gate outside the core that feeds a needed gate is now split like an atom, using the law of excluded middle.
  • If z3 finds the abstraction satisfiable, or hits its resource limit, the old grind fallback still applies.
  • Lemmas that the first search already proves get exactly the same Lean output as before.

An analogy: the core is a friend who points at the pages of a long contract that matter. You still read those pages yourself, so a wrong hint costs time, never correctness.

Review

The reviewer first asked for changes, with one blocker, one minor finding, and two nits.

  • Blocker, fixed. The reviewer ran the tests with Lean hidden, as in the wheel CI job. The two new tests failed with "elan was not found", so every PR would have failed that job. Their Lean checks moved to the integration module, and the run without Lean then passed.
  • Minor, left as a follow-up. On RTCL tf_20 the second search also fails. Reconstruction slowed from 0.7 s to over 5 s, with identical output. Three measured inputs are too few to pick a core-size cutoff, so the cost is recorded in the plan.
  • Nit, kept on purpose. A check in the frontier code looked redundant. Without it, an atom in the relevant set would never be split, and the search would become incomplete.
  • Nit, not a defect. The excluded-middle split line is not counted in the character budget, like the other split lines.

The inputs contain no second review after these fixes.

Risks and open questions

  • A failed first search now also costs a z3 call and a second search.
  • The core is not minimized. A large core only makes the retry fail, never unsound.
  • plan-21 as a whole still does not verify. Its 33 MB Lean file runs out of kernel memory elsewhere.
  • The worked example shows the gain only under a reduced budget, and the cause of its "before" failure is unknown.
  • GitHub CI results were not available to this report.

What comes next

  • Bound the second search once more inputs are measured.
  • Make plan-21's outlined proof steps lighter so the file fits in memory.
  • Replay SAT refutations for RTCL inputs such as tf_20, where core guidance is not enough.
  • Let the rewrite provers retry over a core too.

Glossary

atom
A formula with no Boolean connective inside, such as a Boolean variable p or a comparison x - y <= 3.
axiom
A statement Lean accepts without proof. Adding one would let a certificate assume what it should prove.
case split
Proving a goal separately for each disjunct of a true disjunction. From A ∨ B, prove the goal assuming A, then assuming B.
clause
A disjunction of literals, such as ¬p ∨ q ∨ r.
cnf lemma
A clause that z3 derives while converting a formula to conjunctive normal form, together with the claim that it follows from the original formula.
disjunction
An "or" of formulas. It is true when at least one disjunct is true.
excluded middle, law of
Every proposition is true or false. In Lean it is Classical.em p : p ∨ ¬p.
gate
A named subformula built by one connective (not, and, or, implies, iff) from smaller subformulas.
kernel
The small trusted core of Lean that checks every proof term. Nothing else needs to be trusted.
literal
An atom or its negation, such as p or ¬p.
oracle, untrusted
An outside tool whose answer is used only as a hint. If the hint is wrong, the proof fails to check, but nothing false is accepted.
propagation
Deriving the forced value of a formula from values already known. If A ∧ B is true, then A is true.
propositional abstraction
A formula where each atom is replaced by a fresh Boolean variable, so only the Boolean structure remains.
QF_IDL
The SMT-LIB logic of quantifier-free integer difference logic. Its atoms compare a difference of two integers with a constant, such as x - y <= 3.
refutation
A proof that a set of facts leads to a contradiction, that is, to False.
resource limit (rlimit)
A cap on how much work z3 may do on one query. When it is reached, z3 answers "unknown".
satisfiable
A formula is satisfiable if some assignment of values makes it true.
tactic
A Lean command that searches for a proof step, such as omega for integer arithmetic or grind for general reasoning.
unsat core
A subset of the assumed facts that is already contradictory on its own. Here, the facts are the gate definitions, each under its own guard.
