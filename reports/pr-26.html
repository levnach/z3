Prove distinct gate clauses as def-axioms; fix one-argument distinct

Pull request levnach/z3 #26 · MERGED · 2026-10-21T17:51:43Z · loop iteration 26

Merged into master on 2026-10-21T17:51:43Z as commit fdc8ac3. That merge commit is also the change commit, since the branch was squashed into one commit.

In one paragraph

When a distinct constraint sits inside an or rather than at the top of the input, Z3 explains it to the SAT core through two gate clauses. Before this PR the clause-log exporter did not recognise those two clauses. It tied them to the assertions through an unsat core and a theory lemma of kind cnf. That cost a solver call at export time and a heavy tactic in Lean. The exporter now labels well-formed gate clauses as def-axioms, and the reconstructor proves each one from the pairwise disequalities of the distinct. A malformed gate is rejected instead of being accepted through the solver. Separately, a distinct with a single argument, which Z3 rewrites to true, used to make Lean fail. It now reconstructs on both proof paths.

Background

Before this PR the pipeline already certified uninterpreted functions, uninterpreted sorts, congruence, and linear arithmetic through both the clause log and the legacy proof object. A root-level distinct was already split into assumed clauses, and the legacy proof object already stated the gate clauses as def-axioms. The gap was the clause-log path for a distinct below the root, where the alldiff hint had no rule of its own and the exporter fell back to the solver. Closing it serves milestone 3 of the plan, equality and linear arithmetic.

What changed

  • Exporter. A gate clause of the right shape becomes a def-axiom node, so a distinct below the root needs no solver call at export time.
  • Reconstructor. Lean proves each gate clause from the pairwise disequalities: a case split over the disjunction of equalities one way, building the conjunction of disequalities the other way.
  • Validation. A gate with a missing pair, a foreign disjunct, or mixed polarities is rejected as an unsupported or invalid def-axiom clause.
  • One-argument distinct. An input such as (assert (not (distinct a))) now certifies on both proof paths, because the reconstructor renders it as True with no argument to unfold.
  • Tests and documentation. New tests cover a constructed gate log, malformed gates, tampered certificates, and the one-argument case through both cores. The README and the plan describe the new rule.

The exporter's shape check is only a classifier, like a doorman reading a badge. The badge admits the clause, but the Lean kernel still checks the proof. Only Python and documentation changed.

(c) After the PR

The merged reconstructor generates the following, trimmed to the declarations, the rewrite lemma, and the theorem. Lean accepted it.

def term_0 (...) : _U := _elems 0
def formula_1 (...) : Prop := True
def formula_2 (...) : Prop := (Not (formula_1 ...))
def formula_3 (...) : Prop := False
def formula_7 (...) : Prop := (Iff (formula_2 ...) (formula_3 ...))

The one-argument distinct is formula_1, defined as True without mentioning its argument.

private theorem rewrite_8 (...) : (formula_7 ...) := by
  unfold formula_7 formula_3 formula_2 formula_1
  exact (Iff.intro (fun (_f1 : (Not True)) => ...) (fun (_f4 : False) => ...))

The rewrite lemma proves the negated distinct equivalent to False, and its unfold list no longer names term_0.

The gate clauses, before and after

The headline feature needs a second input, the PR's test uf_distinct_gates, which the old pipeline accepted only by the slower route. Its key line is (assert (or p (distinct (f a) b c))).

Before: the old certificate carried two cnf theory lemmas, each proved with grind:

private theorem th_lemma_41 (...) : (formula_40 ...) := by
  unfold formula_40 formula_39 formula_38 formula_17 formula_16 ... formula_0
  grind (splits := 64)

After: no cnf lemma, and both clauses are def-axioms proved from the three disequalities of formula_5, the distinct:

private theorem def_axiom_41 (...) : (formula_40 ...) :=
  @Decidable.byContradiction (formula_40 ...) _df40 fun _not_clause =>
  let _lit0 : Not (formula_5 ...) := fun _value => _not_clause (Or.inl _value)
  let _lit1 : Not (formula_16 ...) := fun _value => _not_clause (Or.inr _value)
  (_lit0 (And.intro (fun _eq => _lit1 (Or.inl _eq))
                    (And.intro (fun _eq => _lit1 (Or.inr (Or.inl _eq)))
                               (fun _eq => _lit1 (Or.inr (Or.inr _eq))))))

This is the clause "distinct or some pair is equal". With both halves denied, each disequality follows from the denied disjunction.

private theorem def_axiom_39 (...) : (formula_38 ...) :=
  ...
  ((fun _tail => Or.elim _tail
      (fun _eq => (And.left (...)) _eq)
      (fun _tail => Or.elim _tail (fun _eq => (And.left (And.right (...))) _eq)
                                  (fun _eq => (And.right (And.right (...))) _eq)))
   (...))

This is the clause "not distinct or no pair is equal". A case split over the three equalities refutes each by the matching conjunct. One euf theory lemma remains for the congruence step. Lean accepted the new file.

Review

The reviewer approved the change with no blocker and no major finding. They re-ran all test suites, then probed a distinct over Int, over compound Real terms, over an if-then-else term, and under a function, plus the one-argument form in several positions. Lean accepted every probe.

  • Minor, fixed. The README still said every alldiff clause must be derived from the assertions. Someone auditing a new certificate would have found two def-axioms and no cnf lemma, contradicting the text. The bullet was corrected.
  • Nit, fixed. The plan's hint-conventions bullet carried the same stale sentence and was updated.
  • Nit, follow-up. The exporter is stricter than Z3 for a distinct over two different numerals, such as (distinct x 1 2). Z3 drops the equality between the numerals, so that gate still takes the old cnf route. This is the previous behaviour, not a regression.
  • Nit, fixed. The new validation test pinned exact substrings of Lean text that depend on Z3's literal order, so a harmless reordering would have failed it. It now checks the shape of both lemma terms instead.

Risks and open questions

  • A Z3 build that simplifies or adds gate disjuncts falls back to the old path, never to silent acceptance.
  • Soundness rests on the reconstructor's check and on the Lean kernel re-checking each def-axiom theorem. The exporter's label authorises nothing.
  • Helpers that scan reachable nodes never see the argument of a one-argument distinct. That is correct because it is not rendered, but it is a new asymmetry.
  • The merge relied on the local gate. GitHub CI results on master were not recorded when this report was written.

What comes next

  • Accept gates where Z3 dropped an equality between two numerals, with a Lean proof that the numerals differ.
  • Support unary xor, as in (assert (xor false)), which the reconstructor's arity check still rejects.
  • Remove the remaining cnf lemma for a one-argument distinct under a function on the clause-log path, where Z3 simplifies the assertion before logging.

Glossary

assertion
A formula the input declares to be true, written with assert in SMT-LIB. The refutation shows the assertions together imply False.
Boolean
A value that is either true or false. The sort Bool.
clause
A disjunction of literals, such as (or p (not q)). SAT solvers reason over clauses.
clause log
Z3's record of every clause it learned or assumed while solving, each with a hint that says where it came from. One of the two proof paths the pipeline reads.
congruence
The rule that equal arguments give equal function results. From a = d it follows that f(a) = f(d).
def-axiom
A proof node for a clause that holds on its own by the definition of a connective, with no help from the assertions. Lean proves it as a closed theorem.
disequality
A statement that two terms differ, written (not (= a b)). A distinct unfolds to the conjunction of all pairwise disequalities of its arguments.
disjunction
An or of several formulas. It holds when at least one disjunct holds.
distinct
The SMT-LIB constraint that all listed terms differ from one another. (distinct a b c) means no two of a, b, c are equal.
gate clause
A clause that defines a compound formula in terms of its parts, so the SAT core can treat the compound as one literal. For a distinct there are two: "distinct or some pair is equal" and "not distinct or no pair is equal".
hint
The label Z3 attaches to a logged clause, such as tseitin, alldiff, euf, or cnf. It tells the exporter which rule to apply but never authorises a theorem by itself.
if-then-else term
A term that picks one of two values depending on a condition, written ite in SMT-LIB. (ite c x y) is x when c holds and y otherwise.
legacy proof object
Z3's older proof format, a tree of inference steps produced with proof generation enabled. The other of the two proof paths.
literal
An atomic formula or its negation, such as p or (not p).
polarity
Whether a literal is positive or negated. The two gate clauses have opposite polarity on each of their literals.
refutation
A proof that a set of formulas is contradictory, ending in False.
rewrite
A simplification step that replaces a formula by an equivalent one. Z3 rewrites (distinct a) to true.
SAT core
The part of the solver that searches over Boolean clauses. It treats compound formulas as single literals and learns their meaning from gate clauses.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that searches for a proof automatically. grind is a heavy tactic, while a hand-built proof term needs none.
theory lemma
A clause that is valid in a theory such as equality or arithmetic, and that Lean must prove by theory reasoning. The hint kind, such as euf or cnf, says which.
uninterpreted function
A function symbol with no fixed meaning, only the rule that equal inputs give equal outputs. f in (declare-fun f (U) U).
uninterpreted sort
A sort with no fixed set of values, declared with declare-sort. Only equality between its values is known.
unsat core
A subset of the assertions that is already contradictory on its own. The old fallback asked the solver for one at export time.
