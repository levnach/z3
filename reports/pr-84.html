Certify Z3's rewriting of store chains over two constant arrays

Pull request levnach/z3#84 into master · State: OPEN · Date: 2026-11-07T04:21:48Z · Loop iteration 84

This pull request is open and not merged. Its change commit is 8ff7d94b6.

In one paragraph

Z3's rewriter decides whether two store chains over two constant arrays are equal. It compares their values at the stored indices and compares the two constants. Lean could already follow one direction of that equivalence, by congruence. The other direction needs extensionality, and the grind tactic does not do that. This PR makes the reconstructor write that direction as a small proved fact inside each affected lemma. It also lets the simp set drop an if-then-else term whose two branches are equal. Lean used to reject the refutations of three randomly generated inputs. They now check. No new axiom is added, so the trusted base is unchanged.

Background

Before this PR, the pipeline handled arrays over Int and Real indices, constant arrays, and several of the rewriter's evaluations of them. For an equality between a constant array and a store, it covered only one store into the same constant array. The previous iteration found its gaps with a generator of arrays over an enumeration sort. No random generator yet covered plain (Array Int Int) with constant arrays in the QF_ALIA logic. This PR adds that generator and fixes the three gaps it found. It serves milestone 4 of the project plan, "Broader theories and integration", which treats arrays as one of the extensions.

What changed

  • A rewrite of (= S T), for store chains S and T over constant arrays, can now be checked in Lean even when its proof needs extensionality.
  • This also works for chains of different lengths, and for an ite whose two branches are the same constant array.
  • Storing (ite p c c) into a constant array of c now folds back to that constant array in Lean, as it does in Z3.
  • Developers can generate random constant-array inputs with a new test generator, and the three seeds it broke are pinned as regression tests.
  • A new test shows each new fact is needed: without it, all five new hand-written inputs fail in Lean.

An analogy: picture each array as an endless shelf, where a store refills one slot. If two shelves agree at every refilled slot and share the same background fill, they are the same shelf. The new theorem _store_off supplies the "untouched slots keep their fill" part. The PR has two commits. The second removed a code branch that no test needed.

Worked example

The input is the PR's new test store_over_another_constant, run through both versions for this report.

(a) The input

(set-logic QF_ALIA)
(declare-const x Int)
(declare-const y Int)
(declare-const k Int)
(declare-const p Bool)
(assert (or p (not (= (store ((as const (Array Int Int)) x) k y) ((as const (Array Int Int)) y)))))
(assert (not p))
(assert (= x y))
(check-sat)

Storing y at index k into an array full of x gives an array full of y when x = y. Then the literal (not (= …)) is false, and p is false too. So nothing can satisfy the first clause.

An array is a Lean function, a store changes one index, and a constant array returns the same value everywhere.

private theorem _store_off {I E : Type} (a : I -> E) (i : I) (v : E) (j : I) (h : Not (j = i)) :
    _store a i v j = a j := by
  simp [_store, h]

The untested branch. The reviewer undid only the new (ite p c c) branch and reran the two inputs it was meant for. Both still passed, so the docs credited the branch with a fix it did not make. The implementer removed it and found identical Lean output on all 528 seeds. The ite_self simp entry did the real work, and a test still covers it.

One bad fact sinks the lemma. The new facts sit in a block that every proof attempt of a lemma repeats. If one failed to check, a lemma that used to pass would fail. That loses a proof but never accepts a wrong one. The reviewer found no such case, even on a 24-store chain, which checked a little slower.

No timeout. A new test calls Lean without a time limit, so a hang would last until the CI job times out. Its sibling tests do the same, so the fix belongs in their shared helper.

Risks and open questions

  • A new fact that fails to check would turn a passing lemma into a rejection. This hurts completeness, not soundness.
  • For large comparisons, the per-index read facts are dropped above a cap, but the new fact is still stated. grind may then lack what it needs.
  • The pinned seeds depend on Z3's answers and on Python's random numbers. The test checks that each seed is still unsatisfiable, so drift fails loudly.

What comes next

  • State the new fact only when the rewrite has the matching shape, or try it as a separate proof attempt.
  • State read facts only at the stored indices, so large chains stay provable.
  • Add a generator variant with Real elements.
  • Cover the rewriter's other ways to compare stores, including indices built from uninterpreted functions.
  • Add a process-group timeout to the shared Lean test helper.

Glossary

array
A map from an index sort to an element sort. (Array Int Int) maps integers to integers.
axiom
A statement Lean accepts without proof. Adding one would enlarge what must be trusted.
clause
A disjunction of literals, such as (or p (not q)).
completeness
Whether every correct result can be certified. A completeness gap means a true proof is rejected.
congruence
Equal inputs give equal outputs. If S = T, then (select S i) = (select T i).
constant array
An array with the same value at every index, written ((as const (Array Int Int)) x).
enumeration
A sort with a fixed finite list of values, such as Color with red, green, blue.
extensionality
Two arrays are equal if they agree at every index. In Lean this is funext.
grind
A Lean tactic that searches for a proof using equalities, case splits, and arithmetic.
if-then-else term (ite)
A term that picks one of two values by a Boolean condition. (ite p a b) is a when p holds, else b.
lemma
A helper theorem. Here each step of Z3's proof becomes one lemma.
literal
A Boolean atom or its negation, such as p or (not p).
QF_ALIA
The SMT-LIB logic of quantifier-free formulas over arrays and linear integer arithmetic.
refutation
A proof that a set of assertions leads to False.
rewriter
The part of Z3 that replaces a term by a simpler equivalent one. Each replacement is a rewrite step in the proof.
simp set
The list of equations Lean's simp tactic uses to simplify. ite_self turns (ite p c c) into c.
sort
The type of a value, such as Int, Real, Bool, or an array sort.
soundness
The guarantee that nothing false is ever certified. A soundness bug would be serious.
store
An array with one index changed. (store a i v) equals a except at i, where it holds v.
store chain
Several stores applied one after another, such as (store (store a i u) j v).
tactic
A command that tells Lean how to build a proof step, such as simp, grind, or by_cases.
theorem
A statement together with a proof that Lean's kernel has checked.
uninterpreted function
A function symbol with no fixed meaning, only that equal arguments give equal results.
