In one paragraph

Z3's rewriter decides whether two store chains over constant arrays are equal. It looks only at the stored indices and at the two constant values. Lean could already follow one direction of that rule, by congruence. The other direction needs extensionality, and the grind tactic does not do it. This PR makes the reconstructor state and prove that missing direction as a fact inside each affected lemma, backed by one new prelude theorem. It also lets Lean drop an if-then-else term whose two branches are the same. Three random inputs that Lean used to reject now check, so more refutations over arrays end in a kernel-checked theorem.

Background

Before this PR, the pipeline handled a constant array compared with a single store into the same constant array. It could not handle two different constant arrays, or chains of several stores. A new random sweep over plain integer arrays in the logic QF_ALIA found these gaps. The work serves milestone 4 of the plan, "Broader theories and integration", which includes arrays.

What changed

  • Lean can now prove that two store chains over constant arrays are equal when they agree at every stored index and their constants are equal.
  • This works when one side is a single store and the other a plain constant array, and when both sides are chains of different lengths.
  • It also works when one side is an ite that picks the same constant array in both branches.
  • Lean can now fold a store of (ite p c c) into a constant array of c, because the simplifier now knows the standard fact ite_self.
  • The test suite can now generate random QF_ALIA inputs with constant arrays and pins the three seeds that used to fail.

An analogy for the first bullet: picture a wall painted one color, with a few stickers. Two such walls look identical when every sticker spot matches and the paint colors match. Lean now gets a written proof of that rule for each pair it meets. No axiom, sorry, or trust setting was added.

Review

The reviewer approved, with no blocker and no major finding.

  1. Minor: an untested branch. The first version also taught a helper to see through (ite p c c). The reviewer reverted only that helper, and both inputs meant to need it still passed. A later break would have gone unnoticed. The implementer removed the branch, and the Lean output stayed byte-identical on all 528 sweep seeds.
  2. Minor: one bad fact could sink a whole lemma. The new facts sit in a shared block that every proof attempt of a lemma repeats. If one failed, a lemma that used to pass would be rejected. Nothing false would be accepted, but it would be a regression. The reviewer found no such case, so this became a follow-up.
  3. Nit: no timeout in one test. A new test calls Lean without a timeout, so a hang would block CI until the job limit. It copies five sibling tests, so the fix belongs in their shared helper later.

Risks and open questions

  • Review finding 2 remains open. It risks rejections, never false acceptances.
  • Above 64 read facts, the reads are dropped while the new fact stays. grind may then be unable to use it.
  • The pinned seeds depend on Z3's answers and Python's random numbers. Drift would fail the test clearly.
  • GitHub CI results for this change are unknown.

What comes next

  • Move the new fact into its own proof attempt, or emit it only for the rewriter's exact shape.
  • State read facts only at the stored indices, to lift the 64-read limit.
  • Cover the rewriter's other branches and add a Real-element generator.
  • Add a timeout to the shared Lean test helper.

Glossary

array
In SMT, a total map from an index sort to an element sort, such as (Array Int Int). It has a value at every index, not just a finite list.
axiom
A statement Lean accepts without proof. Certificates must not add new ones.
case split
Proving a goal twice, once assuming a condition and once assuming its negation. Example: either j = k or j ≠ k.
congruence
The rule that equal inputs give equal outputs. If a = b, then (select a i) = (select b i).
constant array
An array with the same value at every index. In SMT-LIB, ((as const (Array Int Int)) 5) holds 5 everywhere.
extensionality
The rule that two arrays are equal when they agree at every index. It is the converse of congruence. Lean's version for functions is funext.
grind
A general-purpose Lean tactic that combines equality reasoning, arithmetic, and case splits. It does not apply extensionality on its own here.
if-then-else term
A term that picks one of two values by a Boolean condition. Written (ite p a b) in SMT-LIB. When a and b are the same, the result is just a.
index sort
The sort of an array's positions, such as Int or Real. Both are infinite, which the rewriter's rule relies on.
lemma
A helper theorem used to prove a bigger one. Here, one lemma per solver step that needs its own proof.
logic
An SMT-LIB name for a family of inputs. QF_ALIA means quantifier-free formulas over arrays and linear integer arithmetic.
prelude
Definitions and theorems placed at the top of every generated Lean file, before the per-input part.
refutation
A proof that a set of assertions leads to a contradiction, that is, to False.
rewrite step
A proof step where Z3's rewriter replaces a term by a simpler equivalent one. The rewriter is the Z3 component that does this simplification.
select
Reading an array: (select a i) is the value of a at index i.
sort
The type of a value, such as Int, Real, Bool, or (Array Int Int).
sorry
A Lean placeholder that skips a proof. A certificate containing it would prove nothing.
store
Writing to an array: (store a i v) is a with index i changed to v. It is a new array, not an update in place.
store chain
Several stores nested on top of one base array, such as (store (store c i u) j y).
tactic
A Lean command that builds part of a proof automatically, such as simp, omega, or grind.
theorem
A statement with a proof that Lean's kernel has checked.
