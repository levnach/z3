Proof trimming: strip every negation so Boolean arguments trim

Pull request #42 on levnach/z3 · OPEN · Date: 2026-10-28T15:49:44Z · Loop iteration 42

This PR is open and not merged. The change commit is a264539.

In one paragraph

This PR fixes how Z3's native proof trimming reads negation. A Boolean argument of an uninterpreted function, such as (not q) inside (pb (not q)), is its own propositional variable in the solver. The clause log then prints the opposite literal as (not (not q)). The trimmer removed only one not, so it missed the conflict and fell back to the untrimmed log. Now it removes every not, as the Python replay always did. It also honors the deletion of a clause whose literals repeat. So these inputs now reach Lean as smaller, trimmed certificates. The trust boundary does not move, because every kept step is still checked.

Background

Clause logs of 4 KB or more pass through the native trimmer before the refutation is rebuilt in Lean. The trimmer keeps only the core of steps that the final empty clause needs. Before this PR, three Lean tests with Boolean arguments hit a trimmer failure and replayed the untrimmed log. A wider scan found 9 such failures in 615 generated logs. Lean still accepted the untrimmed certificates, so no result was wrong, only larger. The PR serves Milestone 3 of the project plan: equality and uninterpreted functions, checked end to end.

What changed

Think of "not not hungry". The old trimmer dropped one "not" and filed "not hungry" as a new word, unrelated to "hungry". The fix drops every "not" and flips the sign each time.

  • The trimmer now reads (not (not q)) as q, so it finds conflicts that pass through a negated Boolean argument.
  • Deleting a clause that repeats a literal, like "q or q or a", now really removes it from the trimmer's clause set.
  • The Boolean-argument and Boolean-predicate Lean tests now fail on any trimmer fallback, so Lean checks the trimmed certificates.
  • New C++ and Python tests pin both fixes, and each one fails on the old code.
  • A stray solver trace file that had been committed by accident is removed, and git now ignores it.

Worked example

The input comes from the PR's new Python test. All output below is from real runs.

(a) The input

(set-logic QF_UF)
(declare-fun pb (Bool) Bool)
(declare-const q Bool)
(assert (not q))
(assert (pb true))
(assert (not (pb (not q))))
(check-sat)

Since q is false, (not q) equals true. By congruence, (pb (not q)) must then equal (pb true), which contradicts the last two assertions.

(b) Before

Z3 writes this clause log for the input. The lines that matter are: 

(define-const $6 Bool (not q))
(infer $6 $10)
(define-const $8 Bool (pb $6))
...
(infer (not $7) $8 (not $6) $13)
(declare-fun rup () Proof)
(infer rup)

The congruence step writes (not $6), which spells out to (not (not q)). The old trimmer read it as a variable unrelated to q, so the final RUP step found no conflict. The bug is in the z3 binary, not the Python scripts, so the old scripts would not show it. This old-trimmer output on this exact log was recorded with the fix reverted: 

RuntimeWarning: native proof trimming exited with status 1, replaying the untrimmed log: (error "line 21 column 10: proof trimming: the empty clause is not derivable by unit propagation from the preceding clauses")

The export then replayed the whole log, and Lean accepted that larger certificate.

(c) After

This log is 597 bytes, below the 4 KB trimming threshold. So the export ran with the threshold at zero, as the PR's test does, and with warnings as errors. No warning was raised. The trimmed core kept four steps: 

(define-const $23 Bool (not q))
(define-const $24 Bool (pb true))
(define-const $26 Bool (pb $23))
...
(infer (not $24) $26 (not $23) $30 $41)
(assume $24 $37)
(assume (not q) $35)
(assume (not $26) $39)
(infer rup $43)

The trimmer kept the three assertions and the congruence step, and dropped the trivial (assume true) and the Tseitin step.

These encode (not q), (pb true), (pb (not q)), and the congruence clause "not pb(true), or pb(not q), or q".

This lemma proves the congruence clause: it splits on whether q holds and lets a tactic finish each case.

Stray trace file. Some regression inputs turn tracing on and write z3.log when run from the repository root. The loop driver had committed that file by accident, and every later run would recommit it. It is now removed and ignored.

Test plumbing. The new C++ test captured output by hand and reset the trimming setting to "false". A crash would lose its diagnostics, and an exception would leak the setting into later tests. It now uses the shared replay helper and a guard that restores the old setting.

Ignored deletions. The reviewer logged "q or q or a", deleted it, then derived the empty clause. The trimmer stored "q or a" but looked up "q or q or a", so it ignored the deletion. This was not unsound, since the replay re-checks every step. Both paths now normalize clauses the same way, and a new test fails without the fix.

Test placement. The new export-only test runs in only one CI job. It stayed there, because the C++ and certificate tests cover the defect on every platform.

Risks and open questions

  • The trimmer now treats the variable (not q) and "q negated" as one. They are logically equivalent, but the kept steps may differ from before. Every kept step is still replayed.
  • Two solver clauses can now map to one trimmer clause. Deleting one copy of a two-literal clause may drop a shared watched literal. At worst the export falls back with a warning. No such case appeared.
  • Only the implementer ran the 615-log scan and the negation-revert check.
  • CI results are unknown at the time of writing.

What comes next

Glossary

Boolean
The sort with exactly two values, true and false. Written Bool in SMT-LIB.
certificate
A file that records a proof so that an independent checker can verify it step by step.
clause
An "or" of literals. Example: q or not a.
clause log
Z3's record of every clause it assumed, inferred, or deleted while solving, with a hint for each inferred step.
congruence
The rule that equal inputs give equal outputs. If a = b, then f(a) = f(b).
core
The subset of logged steps that the final empty clause actually depends on.
empty clause
A clause with no literals. It can never be true, so deriving it proves a contradiction.
lemma
A helper theorem proved once and used inside a larger proof.
literal
A propositional variable or its negation. Example: q or (not q).
negation
The "not" of a formula. It is true exactly when the formula is false.
predicate
An uninterpreted function whose result is Boolean. Example: pb in this PR's tests.
proof trimming
Cutting a clause log down to its core, so the certificate and its check are smaller.
propositional variable
A name the solver treats as a single true-or-false unknown. Z3 also gives one to each Boolean term it sees as an argument.
refutation
A proof that a set of assertions leads to a contradiction, that is, to False.
replay
Re-checking each logged step, one by one, before building the certificate.
RUP step
A "reverse unit propagation" step. A clause is accepted if assuming it false and running unit propagation reaches a conflict.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that builds part of a proof automatically. Example: grind.
trust boundary
The line between code that must be correct for a result to be trusted and code whose output is re-checked anyway.
Tseitin step
A clause that links a compound formula to a new variable naming it. Example: q or (not q) for the name of (not q).
uninterpreted function
A function symbol with no fixed meaning. The only rule it obeys is congruence. Example: (declare-fun pb (Bool) Bool).
unit propagation
Repeatedly finding clauses with one literal left that is not false, and making that literal true.
watched literal
One of two literals the solver monitors in each clause, so it notices quickly when the clause can propagate.
