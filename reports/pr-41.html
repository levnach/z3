Fix native proof trimmer bugs that forced untrimmed replays

Pull request levnach/z3#41 · state OPEN · 2026-10-28T07:29:37Z · loop iteration 41

This pull request is open and not merged. The change under review ends at commit d12b33842. It contains four commits.

In one paragraph

Large clause logs go through Z3's native trimming before the Python replay and the Lean check. Three bugs in the trimmer made it fail on about a third of those logs. It missed conflicts because it put a clause's watched literals on literals that were already false. It treated an assumed empty clause as "no conflict yet". It crashed on the div and mod axioms, whose hint has no checker plugin. Each failure fell back, with a warning, to the slow untrimmed log. Now these logs use the trimmed dependency core. Lean still checks every step of the refutation, so nothing new is trusted.

Background

PR #40 lowered the trimming threshold to 4 KB, which exposed old trimmer bugs. Logs with if-then-else terms, with integer division, or with an assertion that simplifies to false fell back to the untrimmed replay. Those certificates were correct, but each one checked Z3's whole search. This PR serves milestone 3, "Equality and linear arithmetic", and the plan's regression methodology.

What changed

  • The trimmer now finds the conflicts it used to miss, because it watches literals that are not already false.
  • An input that simplifies to false now trims to a tiny core that points at its assumed empty clause.
  • Logs with integer div and mod now trim instead of crashing the trimmer.
  • When the trimmer cannot justify the final empty clause, it now says why instead of writing a self-dependent core.
  • Four Lean tests that had silently checked untrimmed certificates now ask for the untrimmed log on purpose.

An analogy for the first fix: each clause has two smoke detectors, its watched literals. The old trimmer sometimes mounted both in rooms already burned out, so a real fire went unnoticed.

Worked example

This PR changes the trimmer, not the Lean code generator. So the example follows the division input of the PR's crash test through the trimmer.

(a) The input

(set-logic QF_LIA)
(declare-const x Int)
(declare-const y Int)
(assert (= (+ (* 2 y) (mod x 2)) 7))
(assert (or (= x 0) (= x 2)))
(check-sat)

If x is 0 or 2, then x mod 2 is 0. Then 2y would have to equal 7, which no integer y can do.

Z3's 61-line clause log for it matches the test's log. It starts with div and mod axioms under a bare arith hint:

(define-const $24 Bool (= $22 x))
(declare-fun arith (Bool) Proof)
(define-const $25 Bool (not $24))
(define-const $26 Proof (arith $25))
(infer $24 $26)
...

(b) Before

I could not rerun the old trimmer, because the pre-PR z3 binary was not available. The pre-PR Python scripts are unchanged, so they would not show the bug. The implementer's scan of the old build recorded this warning for every division log:

native proof trimming exited with status -10, replaying the untrimmed log:

Status -10 is a bus error with no output. The PR reports the same failure for this test on the old build.

(c) After

I ran today's trimmer on the log with solver.proof.trim=true. It exited with status 0 and kept the axiom as a theory axiom:

(define-const $30 Proof (arith $29))
(define-const $61 Proof (deps 0))
(infer $28 $30 $61)
...
(define-const $82 Proof (deps 23 4 14 15 7 3 8 0 18 16))
(infer rup $82)

In deps, the first number is the step's own id and the rest are its premises. The final empty clause, justified by RUP, depends on real earlier steps, including step 0, the division axiom.

This log is under 4 KB, so, like the PR's test, I forced trimming and turned warnings into errors. The theorem that proof_to_lean.py generated from the trimmed certificate is:

theorem unsat (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    (_h0 : (formula_7 _atoms _vars))
    (_h1 : (formula_11 _atoms _vars))
    : False :=
  ...

The two hypotheses are the two assertions, and the conclusion is False.

def formula_33 (_atoms : Nat -> Prop) (_vars : Nat -> Int) : Prop := ((term_21 _atoms _vars) = (term_3 _atoms _vars))
...
private theorem th_lemma_37 (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    : (formula_33 _atoms _vars) := by
  unfold formula_33 term_21 term_20 term_19 term_4 term_3 term_0
  first | omega | grind (splits := 64)

This lemma is the division axiom 2·(x div 2) + (x mod 2) = x, the step the old trimmer crashed on. Lean proves it with a tactic, not by trust.

Result: Lean accepted the trimmed file ("Lean checks passed."). The default, untrimmed file passed too.

Review

The reviewer approved with no blocker or major findings, after reproducing every result.

  • Minor: a theory empty clause still depended on itself. The reviewer logged x ≥ 1 and x ≤ 0, then an empty clause under a bare arith hint. The trimmer made that empty clause depend only on itself. The replay caught the cycle and fell back, so nothing unsound happened. Now the trimmer stops with a clear error instead.
  • Nit: a late empty assumption was kept. An assumed empty clause after the conflict stayed in the output, though nothing used it. Now it enters the core only when the conflict uses it.
  • Suggestion: run the trimmer tests in the releaseClang job too. Not done, because it changes CI. It is listed as a follow-up.

Risks and open questions

  • Logs of 4 KB and up may now trim to different, usually smaller, cores.
  • Four Lean tests now pin the untrimmed log. Trimmed, the wide division cores drop the Farkas lemmas those tests target. One keeps only cuts and bounds.
  • A few logs still fall back, when unit propagation cannot reach the final empty clause.
  • A hint without a checker plugin is now treated as a theory axiom for trimming only. The native checker is unchanged.

What comes next

  • Fix two seeds that still fail to trim, likely over congruence lemmas the native checker calls "not congruent".
  • Fix "inferred clause 47 -59 is not derivable", from Boolean predicates without a sort.
  • Rescan z3test's smtlib-sample, since its division and QF_UF logs may now trim.
  • Run test_proof_certificate.py in the releaseClang job.

Glossary

assumption
A clause the log takes as given, such as an input assertion or a theory axiom. It is written (assume ...).
Boolean
The sort with exactly two values, true and false.
clause
An "or" of literals, such as (or (not a) b). It holds if at least one literal is true.
clause log
A file in which Z3 records every clause it assumed, inferred, or deleted while solving.
conflict
A moment when every literal of some clause is false. It shows the current facts cannot all hold.
congruence
The rule that equal arguments give equal results: if a = b, then f(a) = f(b).
cut
An integer reasoning step that rounds a bound, for example from 2y ≤ 7 to y ≤ 3.
dependency core
The steps of a log that the final empty clause really depends on. Trimming keeps only these.
div and mod
Integer division and remainder. For example, 7 div 2 is 3 and 7 mod 2 is 1.
empty clause
A clause with no literals. It can never be true, so deriving it ends a refutation.
Farkas lemma
A linear-arithmetic step: adding inequalities with nonnegative weights gives an obvious contradiction, such as 0 < 0.
hint
A tag on a logged step that says which rule justifies it, such as rup, euf, cut, or arith.
if-then-else term
A term that picks one of two values by a condition, written ite in SMT-LIB: (ite (> x 0) x 0).
lemma
A helper theorem proved once and then used in a bigger proof.
literal
A Boolean atom or its negation, such as a or (not a).
refutation
A proof that a set of assertions leads to false, so they cannot all hold together.
replay
Rechecking a logged proof step by step, here in Python before the Lean check.
reverse unit propagation (RUP)
A way to justify a clause: assume all its literals are false and show unit propagation reaches a conflict.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that builds part of a proof automatically. omega and grind are examples.
theorem
A statement together with a proof that Lean has checked.
theory axiom
A clause that is true by the meaning of arithmetic or equality, such as x = 2·(x div 2) + (x mod 2).
trimming
Cutting a proof log down to the steps the final result needs, like keeping only the receipts an audit asks for.
unit propagation
Repeatedly setting the last unassigned literal of a clause to true when all its other literals are false.
watched literal
One of two literals per clause that the solver monitors. The clause is revisited only when a watched literal becomes false.
