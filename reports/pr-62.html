In one paragraph

Inputs in the qf_lira fragment may now use to_real to turn an Int term into a Real one, and both proof cores produce a certificate that Lean checks. In Lean, to_real becomes a cast from Int into the rationals. The hard part is that a single theory lemma can now mention atoms of both sorts. Lean's grind tactic cannot see through the cast on its own. So the generated proof first states small bridging facts, each proved by the Lean kernel, and only then calls grind. These facts cover tightening of Int literals and the integrality of Real atoms built from Int terms. No new axiom and no sorry were added.

Background

The previous iteration let Int and Real atoms sit side by side in one refutation, as long as each theory lemma stayed within one sort. Any conversion between the sorts was still rejected. That blocked the most common way an input links the sorts, x = (to_real n). It also blocked an Int if-then-else term used in a Real position under logic ALL, an item open since iteration 55. The work serves milestone 3 of the project plan, "Equality and linear arithmetic", which asks for real and integer linear arithmetic with checked certificates.

What changed

  • The exporter now classifies an input with to_real of an Int term as qf_lira, instead of rejecting it.
  • The clause-log reader can now rebuild (to_real t) terms and accept Z3's cuts over Real atoms whose terms are all Int.
  • The Lean reconstructor can now prove theory lemmas that mix the sorts, using three cast lemmas proved inside each generated file.
  • The legacy core can now prove congruence steps that pass through to_real.
  • A Real atom built only from Int terms is now tightened before it is stored, so it matches the equivalent Int atom. This was the review fix.
  • Still rejected: to_int, is_int, and mixed sorts next to uninterpreted functions.

Worked example

This input comes from the PR's new tests, where it is called cast_tightening. A Real x equals an Int n, and x lies strictly between 0 and 1. No integer fits there, so the input is unsat. Think of a staircase with steps only at whole numbers: you cannot stand between two steps.

A cast lemma, emitted once per file.

private theorem _int_cast_le (s t : Int) :
    (s <= t <-> (s : Rat) <= (t : Rat)) /\ (Not (s <= t) <-> (t : Rat) + 1 <= (s : Rat)) := by
  constructor
  . exact Rat.intCast_le_intCast.symm
  . rw [Int.not_le, Int.lt_iff_add_one_le, <- Rat.intCast_le_intCast]; push_cast; exact Iff.rfl

It says an Int comparison means the same after casting, and that "not s ≤ t" tightens to "t + 1 ≤ s".

The theory lemma that mixes the sorts.

set_option maxHeartbeats 1000000 in
private theorem th_lemma_25 (_atoms : Nat -> Prop) (_vars : Nat -> Rat) (_ivars : Nat -> Int)
    : (formula_24 _atoms _vars _ivars) := by
  unfold formula_24 formula_23 term_22 formula_21 formula_16 term_6 formula_3 term_2 term_1 term_0
  have _c23 := _int_cast_le (_ivars 1) (((0 : Int)))
  push_cast at *
  first | omega | grind (splits := 64)

The clause says: if x = n and not n ≤ 0, then 1 ≤ x. The have line adds the fact that n > 0 means n ≥ 1, which lets grind finish.

Review

The reviewer approved the PR, with no blockers and no major findings. They tried to tamper with certificates and found every attempt rejected.

Minor: wrong keys for some Real atoms. The reconstructor gives each atom a normalized key, so that equal meanings match. The reviewer fed in the atom -2n + 1/2 ≤ 0, which means n ≥ 1. It was keyed as if it meant n ≥ 0. The cause was a step that is valid only for tightened Int atoms, applied to an untightened Real atom. Wide rewrites and ite tables using that key would then fail in Lean. This was a completeness bug: Lean refused good proofs, but nothing false was accepted. The fix tightens such an atom first, so it shares its key with the matching Int atom. A new test compares every key against its atom's meaning, and it fails without the fix.

Nit: README drift. The README still said every atom ranges over terms of its own sort. That is no longer true through to_real, and the text was corrected.

Nit: stale text in the reconstructor. A comment named the wrong helper, and a cut error message was out of date. Both were corrected.

Two suggestions were left for later: accepting cuts over a Real variable defined as a cast through an ite, and limiting the cast facts to the atoms of each clause.

Risks and open questions

  • The bridging facts go only into the general grind fallback. A long lemma over many to_real atoms may be slow, and tested inputs are small.
  • A normalized rewrite that pairs a Real atom with an Int atom needs Lean to bridge the cast. If it cannot, the proof fails safely.
  • Some Farkas lemma hints without coefficients are now left for Lean to prove, where they used to be rejected earlier.
  • The PR merged on the local gate, before GitHub CI results were in. Those results are not known to this report.

What comes next

  • to_int and is_int, which need floor facts.
  • to_real next to uninterpreted functions.
  • A unary + in Z3's raw clause-log output, which the reader still rejects.
  • Cuts over a Real variable defined as a cast through an ite.

Glossary

atom
A formula with no Boolean connectives inside, such as x < 1 or n = 3.
axiom
A statement Lean accepts without proof. Adding one would mean trusting it blindly.
cast
A function that moves a value from one sort to another, such as Int 3 to rational 3.
certificate
The proof record exported from Z3 that an independent checker can replay.
clause
A disjunction of literals, read as "at least one of these is true".
congruence
The rule that equal inputs give equal outputs: if a = b then f(a) = f(b).
cut
An integer step that rounds a bound to a whole number, e.g. from 2n ≤ 3 to n ≤ 1.
Farkas lemma
A proof that some linear inequalities conflict: adding them with nonnegative coefficients gives 0 < 0.
fragment
A restricted class of inputs, defined by which sorts and operators may appear.
grind
A Lean tactic that searches for a proof automatically, combining equalities and arithmetic.
if-then-else term
A term that picks one of two values by a condition, written (ite p a b) in SMT-LIB.
integrality
The fact that a value is a whole number, so it cannot lie strictly between two neighbours.
kernel
The small core of Lean that checks every proof step. Only it needs to be trusted.
linear arithmetic
Arithmetic where variables are only added and multiplied by constants, never by each other.
literal
An atom or its negation, such as n ≤ 0 or not (n ≤ 0).
proof core
One of Z3's two proof sources: the legacy proof object or the clause log.
qf_lira
Quantifier-free linear arithmetic over both Int and Real variables.
refutation
A proof that a set of assertions leads to False.
sort
The type of a value, such as Int, Real, or Bool.
sorry
A Lean placeholder that skips a proof. A real certificate must contain none.
tactic
A Lean command that builds part of a proof, such as omega or grind.
theory lemma
A clause that holds because of arithmetic or another theory, not just Boolean logic.
tightening
Turning an Int bound into its strongest whole-number form, e.g. n > 0 into n ≥ 1.
to_real
The SMT-LIB function that converts an Int term into a Real term.
uninterpreted function
A function symbol with no fixed meaning, only that equal arguments give equal results.
