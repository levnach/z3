In one paragraph

Before this PR, the pipeline refused any input with an uninterpreted function whose result is an array, such as (declare-fun h (Index) (Array Index Element)). Both the certificate exporter and the Lean reconstructor rejected it. Now such inputs are certified through the clause log. The refutation is checked by the Lean kernel. Each Lean array type gets one new universally quantified function family in the interpretation. Each application of such a function also gets a small rfl fact. That fact lets the grind tactic use congruence to compare two applications by their arguments. No axiom or sorry is added. For every input without functions into arrays, the generated Lean is byte-identical to before.

Background

Recent iterations taught the pipeline to certify arrays over uninterpreted sorts, Int, and Real. They also added constant arrays, and functions that take arrays as arguments. A function could take an array in, but it could not return one. The exporter stopped with "uninterpreted functions over Array(I, E)". The reconstructor stopped with "unsupported array declaration". The backlog listed this gap as "functions into arrays". The work serves milestone 4 of the plan, "Broader theories and integration", which treats arrays as one extension.

What changed

  • The exporter now accepts a function whose result is a supported array sort, not only one that takes an array as an argument.
  • The reconstructor now writes such a function as a member of one family per Lean array type, such as _m.arrs_funs.
  • Each application of such a function now gets an rfl fact that shows its arguments, so grind can prove that equal arguments give equal arrays.
  • The certificate gets a new symbol table, "Array function N", and it is matched against the original input by name and signature, so a swapped or renamed function is rejected.
  • Eleven new test inputs cover stores, extensionality, an if-then-else term, constant arrays, Int and Real arrays, and arrays to arrays.

An analogy for the rfl facts: array terms stay folded, like sealed envelopes. grind cannot see which argument made each envelope. The fact writes the argument on the envelope. Then two envelopes with the same argument are known to hold the same array.

Worked example

This is the PR's test input function_into_arrays. It was run through the code before and after the PR for this report.

(a) The input

(set-logic QF_AUF)
(declare-sort Index 0)
(declare-sort Element 0)
(declare-fun h (Index) (Array Index Element))
(declare-fun i () Index)
(declare-fun j () Index)
(declare-fun e () Element)
(assert (= (h i) (store (h j) i e)))
(assert (= i j))
(assert (not (= (select (h j) i) e)))
(check-sat)

Since i = j, the arrays h i and h j are equal. So reading h j at i must give e, which the last assertion denies.

(b) Before

proof_certificate.py: error: uninterpreted functions over Array(Index, Element) are not supported: h

The old exporter stopped with exit code 2, so the old reconstructor was never reached.

The new field arrs_funs gives every function into this array type: a number picks the function, and a list of arguments picks the array.

...

The terms h i and h j become function 0 of the family applied to i and to j, and the theorem says the three assertions imply False for every interpretation.

private theorem th_lemma_21 (_atoms : Nat -> Prop) (_m : Interpretation)
    : (formula_20 _atoms _m) := by
  unfold formula_20 formula_19 formula_18 formula_17 formula_15 term_14 formula_9 term_8 formula_7 formula_6 term_4 term_2 term_0
  have _t1 : (term_1 _atoms _m) = _m.arrs_funs 0 [(_m.elems 0)] := rfl
  have _t3 : (term_3 _atoms _m) = _m.arrs_funs 0 [(_m.elems 1)] := rfl
  have _t5 : (term_5 _atoms _m) = (_store ((term_3 _atoms _m)) (_m.elems 0) (_m.elems 2)) := rfl
  have _s14 := _store_apply ((term_3 _atoms _m)) (_m.elems 0) (_m.elems 2) (_m.elems 0)
  grind (splits := 64)

The new _t1 and _t3 facts expose the arguments of h i and h j, so grind can close this clause by congruence.

Review

The reviewer approved. There were no blockers and no major findings.

  • Minor: no swap or rename test. The tamper tests changed a function's declaration shape, but none swapped two functions. If the input binding were loosened later, a certificate that swaps f and g could slip through. The current code already rejects it, so this was a coverage gap, not a bug. The fix added a new input where two functions share one family in different roles. The tamper test now swaps their names and also renames one of them. Both certificates are rejected because they no longer match the input.
  • Nit: unused loop variable. A leftover index in the exporter's signature check was removed.
  • Nit: stale docstring. The summary line now mentions arrays.
  • Nit: wrong wording in the implementer's notes. The notes said the symbol tables are "numbered together", but each starts at zero. That is sound, and the code and docs never made the claim.

Risks and open questions

  • Soundness rests on one argument. A model's function into arrays returns model arrays. They embed into the Lean array type by the same map as array constants, and that map respects select and store.
  • No z3test input becomes newly certifiable. The fuzzsmt regressions with such functions are satisfiable, so all coverage comes from synthetic inputs.
  • An unused constant-array field is still emitted when an array sort appears only as a function result. This is harmless.

What comes next

  • Arrays over Bool elements, that is sets, are the next array candidate. The backlog plans a Prop element type for them.
  • Nested arrays stay rejected, both as arguments and as results.
  • The legacy core's congruence step does not inject array arguments. This cannot be reached while the legacy core rejects arrays.

Glossary

array
A sort (Array I E) of maps from an index sort I to an element sort E. In Lean it is a function I -> E.
axiom
A statement Lean accepts without proof. A certificate that needs a new one would not be trustworthy.
clause
A disjunction of literals, such as a or not b or c. A proof step usually proves one clause.
clause log
The record of clauses Z3 derives while solving. The exporter turns it into a certificate.
congruence
The rule that equal arguments give equal results: if i = j then h i = h j. Congruence closure applies it automatically.
constant array
An array with the same element at every index, written ((as const (Array Int Real)) 2.0).
extensionality
The rule that two arrays are equal if they agree at every index.
grind
A Lean tactic that combines congruence closure, case splits, and arithmetic to close a goal.
if-then-else term (ite)
A term (ite c a b) that equals a when c is true and b otherwise.
interpretation
A choice of meaning for every symbol: a carrier type, values for constants, and functions for function symbols. In the Lean file it is the structure Interpretation.
kernel
The small core of Lean that checks every proof. Trust rests on it, not on the tactics.
literal
An atom or its negation, such as i = j or not (i = j).
refutation
A proof that a set of assertions implies False.
rfl
Lean's proof that something equals itself. It works when both sides unfold to the same term.
select
Reading an array at an index: (select a i).
sort
The type of a value, such as Int, Real, Bool, or (Array Int Int).
store
Writing one index of an array: (store a i v) is a with the value at i replaced by v.
tactic
A Lean command that builds part of a proof automatically. The kernel still checks the result.
uninterpreted function
A function symbol with a signature but no fixed definition, such as h : Index -> (Array Index Element). Any function of that signature may stand for it.
uninterpreted sort
A sort declared by name only, such as Index, with no built-in values.
universally quantified
Stated "for all" values. The theorem holds for every interpretation, so it holds for any model.
