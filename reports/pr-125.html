In one paragraph

This PR changes how the generated Lean file writes the negation of an Int term whose value is always zero. It is now 0 - t instead of -t. Both are the same integer. The reason is a defect in the grind tactic of the pinned Lean version. When it met the term -0 under an uninterpreted function, an array read, or a store, it built a proof that the Lean kernel rejected. A correct refutation therefore could not be certified. With the new spelling these inputs pass the Lean check. No axiom is added and no check is skipped.

Background

Before this PR, Int inputs with uninterpreted functions and arrays were already certified through the clause log. One family was an exception: inputs that negate a zero-valued Int term in an argument, such as (f (- 0)). Lean rejected them with a kernel error that no fallback tactic could catch. The same error appeared when a map negated an array holding a stored zero, as the review of PR #124 reported. The Real sort never had the problem. Certificates built from the older proof object already passed. The work serves milestone 3, equality and linear arithmetic, and the array part of milestone 4.

What changed

Reconstructor

  • You can now certify Int inputs that negate an always-zero term in an argument, such as (select a (- (mod 6 3))).
  • You can now certify inputs where the Int negation map runs over an array holding a zero.
  • Other negations are untouched: (- 2) is still the numeral -2, and Real negations keep -t.

Tests

  • You can now tell when the workaround is obsolete: tests restore the old spelling and expect the kernel error.

Documentation

  • The plan and the README now list which inputs are covered and which still fail.

An analogy: one clerk misreads “minus zero” on a form, so the form now says “zero minus zero”. The amount is the same.

Review

The reviewer approved the change, with no blocker, no major finding, one minor finding, and two nits.

  • Minor, documented and not fixed in code. The reviewer tried inputs with no negation of zero at all, such as (f (div 2 (- 5))). Lean's simplifier turns the quotient into a negated quotient, which is -0 again. The kernel rejects these as before, so nothing wrong is accepted. It mattered because the documentation made the problem look closed. The plan, the README, and the backlog now list them.
  • Nit, documented and not fixed. The reviewer negated a term in which each level adds the previous level to itself. The new zero check walks it as a tree, so its time doubles per level. The old code already grew this way, so the fix is left for later.
  • Nit, fixed. One new test checked which axioms Lean reports. It also passed if the report said nothing about axioms. It now requires Lean's explicit statement.

On the reviewer's suggestion, the tests that pin the Lean defect now say what to remove after a Lean upgrade.

Risks and open questions

  • Soundness: no risk was identified. A wrong zero check would only pick the other spelling of the same number.
  • The fix is a partial workaround for a defect of Lean 4.34.0. The cases of the minor finding still fail, as before.
  • Three existing inputs with an Int negation map produce different text. They still verify.
  • The CI result on master after the merge is unknown here.

What comes next

  • Zeros reached without a negation in the input: quotients by a negative numeral, and mod or rem by 1 or -1 under a variable.
  • A negated if-then-else term whose condition is already decided.
  • A map over a chain of two stores with the Int negation map.
  • Two unrelated rejections: (f (to_int 0.5)) and some rem terms.
  • Caching the linear form of each term, which removes the slowdown on heavily shared terms.

Glossary

array
A value that maps every index to an element, like a table with one entry per index. Example: (Array Int Int).
axiom
A statement accepted without proof. A proof that adds none rests only on the logic's standard foundations.
certificate
A file with the evidence for a solver's answer, detailed enough for an independent checker to confirm it.
clause
A disjunction of simple facts or their negations. Example: “f(0) is not 2, or f(0) is not 1”.
clause log
The solver's record of the clauses it derived while solving, each with a hint about why it holds.
congruence
The rule that equal arguments give equal results. Example: if a = b then f(a) = f(b).
div, mod, rem
Integer division and its two remainders in SMT-LIB. Example: (div 7 3) is 2 and (mod 7 3) is 1.
if-then-else term
A term that picks one of two values by a condition. Written (ite c a b) in SMT-LIB.
kernel
The small core of a proof assistant that checks every finished proof. A proof counts only if the kernel accepts it.
linear arithmetic
Arithmetic where variables are only added and multiplied by constants. Example: 2x + y ≤ 3.
map
An array operator that applies a function to every element. Example: negating each element of an array.
negation (arithmetic)
The unary minus of a number. Written (- t) in SMT-LIB and -t in Lean.
numeral
A number written out as a constant, such as 0, 2, or -2.
read
Looking up an array at an index. Written (select a i) in SMT-LIB.
refutation
A proof that a set of assertions is contradictory, ending in False.
rewrite step
A proof step that replaces a formula by an equivalent, usually simpler one.
simplifier
The part of a prover that rewrites terms to simpler equal terms. Example: 0 - 0 becomes 0.
sort
The type of a value, such as Int, Real, or Bool.
soundness
The property that only true statements can be proved. A soundness bug would let a wrong result pass.
store
An array equal to another except at one index. Written (store a i v) in SMT-LIB.
tactic
A proof-search procedure in a proof assistant. It builds a proof, which the kernel then checks.
term
An expression that denotes a value. Examples: 0, x + 1, f(0).
uninterpreted function
A function symbol with no fixed meaning. Only congruence is known about it. Example: (declare-fun f (Int) Int).
