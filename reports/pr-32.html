Balance outlined Inputs and normalize wide rewrites over opaque terms

Merged on 2026-10-22T19:53:03Z as commit 614975f. The pull request was opened at 2026-10-22T19:30:29Z and squash-merged as that single commit.

In one paragraph

This PR changes only the Python reconstructor that turns a Z3 certificate into Lean text. It fixes two limits that a scan of sample QF_LIA and QF_UFLIA files exposed. First, long proofs are split into chunk lemmas, and every chunk receives all input assertions as one conjunction. That conjunction was nested to the right, so reaching the last of 1,211 assertions took 1,210 projections, and Lean ran out of its heartbeat budget. The conjunction is now a balanced tree, so no assertion is more than about ten projections deep. Second, a wide theory rewrite over many arithmetic atoms is proved atom by atom and then propositionally. That path accepted only atoms over plain variables. It now also accepts linear forms over opaque terms such as applications of an uninterpreted function, modulo, and integer division. Both fixes keep the trust boundary where it was: every new Lean statement is still checked by Lean, and nothing is taken on faith from Z3.

Background

Before this PR, the pipeline certified Boolean, QF_UF, QF_LRA, QF_LIA, QF_UFLRA, and QF_UFLIA refutations, including proofs long enough to be outlined into chunks. On the arithmetic side it already replayed Farkas lemmas and cuts over the integers. Two sample files that Z3 solved in seconds still failed in Lean. One had 1,211 assertions and timed out on the projection chain. The other rewrote an equivalence between two disjunctions of twenty integer equalities over function applications, and the grind tactic split exponentially on it. Both failures were reconstructor limits rather than rejections of a bad certificate. The work serves milestone 3 of the plan, equality and linear arithmetic, by closing gaps that real benchmark files hit.

What changed

  • Balanced input conjunction. Outlined proofs can now pull any assertion out of a conjunction of hundreds or thousands of assertions without exhausting Lean's heartbeat budget. It works like finding a name by halving a sorted list instead of reading from the top.
  • Wide rewrites over opaque terms. A rewrite with more than sixteen arithmetic atoms whose linear forms mention (f x), modulo, or integer division is now proved atom by atom and then propositionally, instead of being handed whole to the grind tactic.
  • A gate that keeps the hard cases with grind. When an atom over an opaque term appears on only one side of the rewrite, Z3's simplifier must have reasoned about that term. Such rewrites still go to grind, which can prove them through congruence and the bounds of modulo.
  • Terms with an if-then-else term inside stay excluded. The logged form of absolute value is an ite, whose condition is a formula. Those rewrites keep the bridging path added in iteration 30.
  • Tests and documentation. Five new Lean-checked tests cover both features and the gate, one unit test checks the balanced projection paths for every count up to 69, and the plan document gained a dated note.

(b) Before

The pre-change reconstructor accepted the certificate and produced Lean text with the last assertion 600 projections deep. Lean rejected that text after 7.7 seconds.

old_example2.lean:2547:0: error: (deterministic) timeout at `isDefEq`, maximum number of heartbeats (200000) has been reached
old_example2.lean:3656:8: error: (kernel) unknown constant '...proof_step_1806'

The lemma at line 2547 is the one that gathers the chunk results. Its projection of the last assertion was _inputs.2.2.2.2 followed by 596 more .2 fields.

(c) After

The current reconstructor generates a balanced conjunction. Lean accepted the file. The declarations:

def formula_0 (_atoms : Nat -> Prop) : Prop := _atoms 0
...
def formula_600 (_atoms : Nat -> Prop) : Prop := (Or (formula_0 _atoms) (Or (formula_1 _atoms) ...
def formula_601 (_atoms : Nat -> Prop) : Prop := (Not (formula_0 _atoms))
...
private def Inputs (_atoms : Nat -> Prop) : Prop :=
  (And (And (And (And (And ... (And (formula_600 _atoms) (formula_601 _atoms)) (formula_602 _atoms)) ...

Every assertion becomes a named formula, and the conjunction of all 601 of them is split in halves at every level.

private theorem proof_step_1804 (_atoms : Nat -> Prop)
    (_inputs : Inputs _atoms)
    : (formula_1200 _atoms) :=
  let _step_1804 : (formula_1200 _atoms) :=
    _inputs.2.2.2.2.2.2.2.2.2
  _step_1804

The lemma for the last assertion now reaches it in nine projections instead of 600. No path in the file is longer than ten.

theorem unsat (_atoms : Nat -> Prop)
    (_h0 : (formula_600 _atoms))
    (_h1 : (formula_601 _atoms))
    ...
    (_h600 : (formula_1200 _atoms))
    : False :=
  proof_step_1806 _atoms (And.intro (And.intro (And.intro ... (And.intro _h0 _h1) _h2) (And.intro _h3 _h4)) ...

The main theorem packs the 601 hypotheses into the same balanced shape and hands them to the chunk lemmas. The check with check_lean.sh reported "Lean checks passed".

Review

The reviewer's verdict on the implementer's commit was "request changes", with one major finding and two nits. All three were fixed on the branch before the PR was opened, and the branch was squash-merged as one commit.

Major: a decided modulo bound slipped through the gate

The first version of the gate asked only whether both sides of a rewrite mentioned the same set of opaque terms. The reviewer built a QF_LIA input with eighteen atoms over (mod x 10) plus one extra literal in the clause, (< (mod x0 10) 0). Z3's simplifier knows that a remainder by a positive divisor is never negative, so it dropped that literal in one rewrite step. The modulo term still appeared in the other atoms, so the gate judged the rewrite normalizable. The propositional lemma then saw an atom on the left with no partner on the right, and Lean failed with grind failed. Before the PR the same input had verified through grind, so this was an acceptance regression. The fix compares the canonical keys of the atoms on each side. A key present on one side only is allowed only when its atom ranges over variables alone, so any disappearing atom over an opaque term sends the rewrite back to grind. The reviewer's input became a Lean-checked regression test for both forms of the bound.

Nits

  • Duplicated test code. The uflia test built two hand-made certificates with fifteen identical lines and had a spacing slip. A local helper now builds both.
  • Quadratic membership test. The gate checked list membership inside a loop. It now builds a set first. No benchmark was affected.

Risks and open questions

  • Soundness is unchanged. A wrong routing decision can only make Lean reject a proof, never accept a wrong one.
  • Acceptance may shift. Some wide rewrites that grind used to prove whole now take the atom-by-atom path. If a per-atom lemma or the propositional lemma fails, the result is a Lean failure, as before.
  • Every outlined proof's text changed. All outlined tests were re-run, but any downstream tool that compared generated text would see differences.
  • CI time grows. The Lean CI step gets about 46 s longer from the new tests.
  • CI on master is unverified here. The merge rested on the local gate on one machine. The GitHub run on master had not been recorded when this report was written.

What comes next

  • Profile the outlined 1,001-assertion disjunction, which verifies but takes 86 s.
  • Admit if-then-else terms to the normalized rewrite path.
  • Reuse the balanced conjunction for eliminating conjuncts of very wide asserted conjunctions, a shape still rejected today.
  • Investigate the scan's other findings: two trimmer steps with incomplete dependencies, one trimming failure, and two Lean failures on other sample files that are not this shape.

Glossary

assertion
A formula the input declares to be true. Each (assert ...) line is one assertion.
atom
A smallest formula with no connective inside, such as x < 5 or p.
Boolean
The sort of truth values, true and false.
certificate
The record of proof steps Z3 emits, which the reconstructor turns into Lean text for checking.
clause
A disjunction of literals, such as (or (not p) q r).
congruence
The rule that equal arguments give equal results: if x = y then f x = f y.
conjunction
A formula joined with "and". It is true only when every part is true.
cut
An integer reasoning step that rounds a bound, for example from 2x <= 5 to x <= 2.
disjunction
A formula joined with "or". It is true when at least one part is true.
equivalence
A formula stating that two formulas have the same truth value, written Iff in Lean.
Farkas lemma
A proof step that adds linear inequalities with nonnegative weights to reach a contradiction such as 0 < 0.
heartbeat
Lean's unit of work for a single declaration. A declaration that exceeds the budget fails with a deterministic timeout.
if-then-else term
A term that picks one of two values by a condition, written ite in SMT-LIB. Z3 logs absolute value this way.
linear form
A sum of terms times constants, such as 2x + 3y - 7. Here the terms may be variables or opaque terms like (f x).
literal
An atom or its negation, such as p or (not p).
modulo
The remainder of integer division, written mod. For a positive divisor it lies between zero and the divisor minus one.
projection
Taking one component out of a conjunction proof, written .1 or .2 in Lean for the left or right part.
propositional
Reasoning only with connectives like and, or, and not, treating atoms as opaque names.
refutation
A proof that the assertions together lead to false.
rewrite
A proof step stating that a formula equals its simplified form, such as flattening or reordering a disjunction.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that searches for a proof automatically. grind is a tactic that combines case splitting with congruence and arithmetic.
theory
A fixed set of symbols with their meaning, such as integer arithmetic or uninterpreted functions.
uninterpreted function
A function symbol with a declared signature but no definition. Only congruence can be assumed about it.
