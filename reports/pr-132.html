## Summary

- Constant arrays `((as const (Array I E)) v)` are now certified over an uninterpreted index sort and over Bool indices, not only over Int and Real. Only constant arrays indexed by arrays stay rejected.
- This also covers the constant arrays Z3's rewriter makes in inputs that write none: `(= s (setminus t t))` and every `(subset a b)` it does not decide, over a declared sort or Bool.
- A constant array gives its uninterpreted index sort a Lean type of its own (`_m.S0`, ...), by the mechanism of #131, so the theorem's hypotheses mean what the input's assertions do. Default values stay Int and Real only.
- The trust boundary is unchanged: no axiom, no `sorry`, no check removed. Everything that reconstructed at the base reconstructs to the same text.
- Python only (`examples/python`), one new test module, docs. No C++ change.

## Motivation

The exporter rejected a constant array over an uninterpreted sort or Bool ("constant arrays are supported over Int and Real indices only"), and the reconstructor rejected those the rewriter introduces ("invalid constant array declaration"). Sets over a declared sort are common, so ordinary inputs were lost: 30 of the 248 unsatisfiable seeds 1-1500 of `random_index_sort_instance`, and both subset inputs of `REJECTED_SUBSET_INPUTS` (`over_a_sort`, `over_bool_indices`).

The reason given for the rejection was the default values, which need an infinite index type. A constant array itself does not: it is the constant function over any index type. What it needs is a Lean index type that is exactly the model's index sort. Over the shared carrier `_m.U` it is not. For

    (declare-sort I 0) (declare-sort E 0)
    (assert (= (store ((as const (Array I E)) v) i w) (store ((as const (Array I E)) w) i w)))
    (assert (not (= v w)))

Z3 answers `sat` (`I` has one element, `E` two), but over one carrier the two Lean hypotheses are contradictory. So the index sort becomes a type of its own unless it is all of the carrier anyway (the condition of #131, unchanged).

## Changes

**Reconstructor (`examples/python/proof_to_lean.py`)**
- `_declaration` admits a constant array unless its index sort is an array (a model's outer array is constant on the embedded indices only).
- `_index_sorts`: a constant array makes its uninterpreted index sort a Lean type of its own, with the same carrier exception as maps, set operators, and subsets. Bool indices are `Prop`.
- `default` declarations are unchanged (Int and Real indices only). No default-value fact is stated over the other sorts.
- `_Graph.constant_indices` and `_index_witness`: for the index sorts other than Int and Real that constant arrays are over, `_constant_array_comparisons` states that each equality of arrays a rewrite reaches holds at one index of the sort (`_m.s0_elems 0`, `_m.elems 0`, or `True` over Bool) and that a constant array has its value there. This proves the rewriter's `(= (const v) (const w))` to `(= v w)`, which over Int goes through default values. The facts are `congrArg` and `_select_const` (`rfl`).
- The header comment of a sort with its own type names the reason: pointwise maps, constant arrays, or both.

The rewriter expands an equality between stores over constant arrays over a possibly finite sort into a quantified formula; this was rejected before as "unsupported application head in the clause log".

## Risks and follow-ups

- The soundness argument is the choice of the index type: a constant array over an uninterpreted sort is stated over a type of its own, or over a carrier that holds nothing else. The condition is that of #131 and now decides more inputs. Bool indices rest on the existing embedding of arrays over Bool into functions on `Prop`.
- Theorem statements change only for inputs that were rejected before, so nothing that verified can fail now.
- Part of Z3's reasoning over these sorts stays rejected by design: the array solver's default value of a constant array over such a sort (35 of the 1010 unsatisfiable sweep seeds, the largest remaining rejection) and the rewriter's quantified equalities between stores over constant arrays (11 seeds).
- 46 sweep seeds reconstruct but fail in Lean with "`grind` failed" (the safe direction); 38 fail the same way with Int for the index sort. The 8 that are specific: stores over constant arrays over Bool indices compared off the stored index, an array lemma with an `Iff` index equality, a read of a map of constant arrays, and an ite whose condition is an equality with a store of a constant array's own value.
- Two rejected inputs of the new module depend on what Z3 does (`stores_compared_with_a_constant_array`, `solver_default_over_a_sort`); a Z3 change there fails the test, which then needs its input replaced.
- The default-value prelude is still emitted for certificates whose constant arrays are over a sort only (45 unused lines).
