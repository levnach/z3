In one paragraph

This PR lets the pipeline certify a refutation that uses a constant array whose index sort is an uninterpreted sort or Boolean. Until now such arrays were accepted over Int and Real indices only. The change also covers constant arrays that the rewriter creates on its own, for example when it turns a subset test into an equality with the empty set. In the Lean theorem, the index sort becomes a type of its own. Each hypothesis then means exactly what its assertion means. Sets over a declared sort are common, so ordinary inputs were lost before. No axiom is added and no check is removed.

Background

Before this PR, the exporter refused every constant array over these index sorts. The reconstructor refused the ones that the rewriter introduced. The stated reason was the default value of an array, which needs an infinite index sort. PR #131 had already moved the index sorts of pointwise maps and set operators out of the shared carrier, and this PR reuses that mechanism. It serves milestone 4 of the plan, "Broader theories and integration", which lists arrays as a theory to add.

What changed

  • Exporter. An input with a constant array over an uninterpreted or Boolean index sort can now be exported as a certificate.
  • Exporter. A quantifier made by the rewriter is now refused by name.
  • Reconstructor. A constant array now gives its uninterpreted index sort a Lean type of its own, unless that sort is all the carrier holds.
  • Reconstructor. Lean can now prove that two equal constant arrays hold equal values, by reading both at one witness index.
  • Reconstructor. Inputs with subset or a set difference over a declared sort or Bool now go through.
  • Tests and documentation. A new test module pins the newly certified inputs, the inputs that stay rejected, and tampered certificates.

Why one index is enough. A constant array is like a rule that puts the same card on every seat of a room. If two such rules agree, one seat shows that the cards are equal. A sort always has at least one value, so a seat exists.

Why the sort needs its own type. Before, all uninterpreted sorts shared one Lean type. An equality of arrays then also spoke about values that are not indices. The hypotheses could then contradict each other although the input is satisfiable.

A constant array is a function that ignores its index. The two assertions become the formulas numbered 4 and 6.

private theorem rewrite_9 (_atoms : Nat -> Prop) (_m : Interpretation)
    : (formula_8 _atoms _m) := by
  unfold formula_8 formula_5 formula_4 term_2 term_0
  have _t1 : (term_1 _atoms _m) = (@_const_array _m.S0 _m.U (_m.elems 0)) := rfl
  have _t3 : (term_3 _atoms _m) = (@_const_array _m.S0 _m.U (_m.elems 1)) := rfl
  have _e4 : ((term_1 _atoms _m)) = ((term_3 _atoms _m)) -> _select ((term_1 _atoms _m)) (_m.s0_elems 0) = _select ((term_3 _atoms _m)) (_m.s0_elems 0) := congrArg (fun _x => _select _x (_m.s0_elems 0))
  have _dc1 := _select_const (I := _m.S0) (_m.elems 0) (_m.s0_elems 0)
  have _dc3 := _select_const (I := _m.S0) (_m.elems 1) (_m.s0_elems 0)
  grind (splits := 64)

This lemma proves the rewriter's step: the arrays are equal exactly when their values are. The last three facts are new and read both arrays at the witness index _m.s0_elems 0. The first is a congruence step, and the tactic grind finishes the proof.

Review

The reviewer approved the change with no blocker, major, or minor finding. Attempts to make Lean accept a tampered certificate all failed. Removing the new rule for index sorts made the new tests fail, so they guard it.

Four nits were found, and all were fixed in the second commit.

  • Stale README sentence. One paragraph still said that constant arrays work over Int and Real indices only. A reader would think the new inputs are rejected. It now excludes array indices only.
  • Stale code comment. One helper's comment still spoke of infinite index sorts only. That could mislead the next person who reasons about soundness. It was corrected.
  • Incomplete header comment. For an input with a union, the generated comment gave constant arrays as the only reason for the sort's own type. It now names both reasons.
  • Miscounted measurement. The reviewer's fresh seeds showed inputs that never mention the second sort. Their index sort stays the carrier, yet the plan counted them as the own-type case. The plan now gives the split below.

Risks and open questions

  • Soundness rests on the choice of the index type. The condition is that of PR #131, and it now decides more inputs.
  • Theorem statements change only for inputs that were rejected before, so nothing that verified can fail now.
  • Default values over these sorts, and quantified equalities between stores, stay rejected by design.
  • Some inputs are reconstructed but grind finds no proof. Most fail the same way with Int indices.
  • Two rejected test inputs depend on Z3's behaviour and need replacing if it changes.
  • The CI result and the local gate result are unknown at the time of writing.

Glossary

array
A value that maps each index to an element, like a function. (select a i) reads it and (store a i v) gives a copy with one entry changed.
assertion
A formula that the input requires to be true, written (assert ...) in SMT-LIB.
axiom
A statement that a proof checker accepts without proof. Fewer axioms mean less to trust.
Boolean
The sort Bool with the two values true and false.
carrier
The collection of values that a sort stands for in an interpretation. Here it is also the single Lean type that holds the values of all uninterpreted sorts without a type of their own.
certificate
A file that records the solver's proof steps so that another program can check them.
congruence
The rule that equal inputs give equal outputs. Example: if a = b then (select a i) = (select b i).
constant array
An array that holds the same element at every index, written ((as const (Array I E)) v).
default value
The element that an array holds at all but finitely many indices, written (default a). It is well defined only when the index sort is infinite.
equality
The statement that two terms have the same value, written (= s t).
exporter
The part of the pipeline that turns Z3's proof output into a certificate.
hypothesis
An assumption of a theorem. Here each assertion of the input becomes one hypothesis.
index sort
The sort of the positions of an array. In (Array I E) it is I, and E is the element sort.
interpretation
A choice of concrete values for every sort, constant, and function of the input. One that makes all assertions true is called a model.
pointwise map
An array built by applying a function at every index of other arrays. Set union is the pointwise map of "or".
quantifier
The operators "for all" and "exists", written forall and exists.
reconstructor
The part of the pipeline that turns a certificate into a Lean theorem with its proof.
refutation
A proof that a set of assertions cannot all be true together.
rewriter
The solver component that replaces a term by a simpler equal one before and during solving.
satisfiable
Having at least one interpretation that makes all assertions true. Z3 then answers sat.
set
An array with Boolean elements. An index is a member when the array holds true there.
set operator
An operator that combines sets: union, intersection, difference (setminus), and complement.
sort
The type of a value, such as Int, Real, or Bool.
soundness
The property that everything the checker accepts is really true.
subset
The relation "every member of the first set is a member of the second", written (subset a b).
tactic
A Lean command that searches for a proof automatically. grind is one.
theorem
A statement together with a proof that the checker has accepted.
theory
A fixed meaning for some sorts and operators, such as arrays or linear arithmetic.
uninterpreted sort
A sort declared by the input with no fixed meaning, written (declare-sort I 0). It can have any number of values, but at least one.
witness
One concrete value that is picked to show something. Here it is the index at which two arrays are read.
