Certify ites of store chains compared with store chains in Lean

Pull request levnach/z3#89 · MERGED · merged 2026-11-07T09:44:32Z · merge commit 2c5225f · loop iteration 89

In one paragraph

Some inputs equate an if-then-else term whose branches are store chains over constant arrays with another store chain. Z3 logs such an assertion as the outcome of comparing each branch with the other side, and links the two by a rewrite step. Lean's grind tactic could split the ite, but it could not prove a branch equal to the other side. That proof needs extensionality. This PR makes the Lean reconstructor state that missing converse as a small proved lemma for each pair of leaves. The rewrite step now checks, so the whole refutation is certified. Nothing new is trusted: every added fact is proved inside Lean.

Background

Before this PR, the reconstructor already proved the converse for an equality between two store chains over constant arrays. It accepted an ite only when both branches were the same array. An ite of two different chains got no converse, so Lean rejected the rewrite step with "grind failed". This was the last failure in the random constant-array sweeps of iteration 88: seed 102, with Real indices and Int elements. The work serves milestone 4 of the plan, "Broader theories and integration", which treats arrays as a separate extension.

What changed

  • An equality with an ite of different store chains on one side, both sides, or nested ites now certifies in Lean.
  • The reconstructor states one Lean-proved converse per pair of different leaves, capped at 16 pairs per equality.
  • A shared ite DAG is now walked once per node, so deep sharing no longer takes exponential time.
  • Equalities above the 16-pair cap no longer use up the shared budget of read facts that other comparisons rely on.
  • Three new documented inputs and the pinned seed 102 now run in the test suite and in CI.

An analogy helps with the new lemma. Picture two shelves of numbered boxes, each filled with one default item, with a few boxes swapped out. To show the shelves are equal, you only check the swapped boxes and the default item. That is what each converse says about two leaves.

Review

The reviewer approved the change with no blockers and no major findings.

  • Minor, fixed. The reviewer built an ite DAG where each level reuses the two ites below it. The leaf walk treated it as a tree, so its time roughly doubled per level. At 22 levels it took about one second, and deeper inputs could hang. The walk now remembers the nodes it has visited. A new test walks 60 levels instantly, which would never finish without the fix.
  • Nit, fixed. The reviewer put an ite equality next to two long chains in one rewrite step. Its reads counted toward a shared budget, which could push the step over and drop all read facts. Lean still verified that probe. Now equalities above the cap are skipped, and the new test checks the 16-pair edge.
  • Nit, fixed. The README did not mention the new converses. One paragraph was added to its array section.

Risks and open questions

  • Lean's work grows with the number of leaf pairs times the stored indices. The 16-pair cap bounds it. A wider ite tree gets no facts, as before.
  • A store on top of an ite of different arrays, such as (store (ite p (const x) (const y)) k v), is still not a chain and gets no converse.
  • An ite of chains equated with an array variable, a function application, or a map also gets no converse. No failing input has been seen for either case.
  • The GitHub CI result on master is not recorded in the inputs.

What comes next

No generator deliberately produces ites of chains. The constant-array generator hit this shape once in about 1,100 seeds. A targeted generator would be a useful follow-up.

Glossary

array
A value of sort (Array I E) that maps each index of sort I to an element of sort E. In Lean it is a function I -> E.
assertion
A formula the input states as true, written (assert ...).
case split
Proving a goal twice, once assuming a condition holds and once assuming it does not. Example: either j = 1 or j ≠ 1.
constant array
An array with the same element at every index, written ((as const (Array Int Int)) v).
converse
The statement read in the other direction. If "A implies B" is known, its converse is "B implies A".
DAG
A directed acyclic graph. Terms share subterms, so one node can appear under many parents.
extensionality
The rule that two arrays are equal when they agree at every index.
funext
Lean's function extensionality: to prove two functions equal, prove they agree on every argument.
grind
A Lean tactic that searches for a proof using case splits, congruence, and arithmetic.
if-then-else term (ite)
A term (ite c a b) that equals a when the Boolean c is true, and b otherwise.
leaf
In a tree of nested ites, a branch that is not itself an ite. In (ite p A (ite q B C)) the leaves are A, B, and C.
lemma
A small proved statement used as a step in a larger proof.
refutation
A proof that the assertions together lead to False.
rewrite step
A proof step saying one formula is equivalent to a simpler one, as the solver's simplifier rewrote it.
sort
The type of a value, such as Int, Real, Bool, or (Array Int Int).
store and select
(store a i v) is array a with index i changed to v. (select a i) reads a at index i.
store chain
Several stores applied one after another to a base array, such as (store (store a 1 x) 2 y).
tactic
A Lean command that builds part of a proof automatically, such as funext or grind.
