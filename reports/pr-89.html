Certify ites of store chains compared with store chains in Lean

Pull request levnach/z3#89 · OPEN · opened 2026-11-07T09:34:22Z · loop iteration 89

This pull request is open and not merged. The change it proposes is commit 52467036a, on top of an earlier commit of the same PR.

In one paragraph

Some inputs equate an if-then-else term whose branches are store chains over constant arrays with another store chain. Z3 handles such an equality with a rewrite step that replaces it by a simpler equality between the values. Lean rejected that step, because the tactic grind could not prove a branch equal to the other side without extensionality. The reconstructor now states a Lean-proved converse lemma for each pair of leaves of the two sides. No new axiom or trusted step is added. One more family of Z3 refutations is now checked end to end.

Background

Before this PR, the reconstructor already stated extensionality converses when both sides of an array equality were plain store chains over constant arrays. It also accepted an ite whose two branches are the same array. It had nothing for an ite of two different chains, so the rewrite step from the clause log failed in Lean. In iteration 88, the random constant-array tests left exactly one such failure: seed 102, with Real as the index sort and Int as the element sort. The work serves milestone 4 of the project plan, "Broader theories and integration", where arrays are one of the listed extensions.

What changed

  • An equality with an ite of different store chains on one side, both sides, or nested ites now gets a Lean-proved converse for every pair of leaves.
  • At most 16 leaf pairs per equality get these lemmas, so Lean's work stays bounded on wide ite trees.
  • The helper that collects the leaves visits each shared node once, so a deeply shared ite DAG no longer takes exponential time.
  • Equalities above the 16-pair cap no longer use up the shared budget of read facts, so they cannot crowd out reads that other comparisons need.
  • Three new documented inputs and the pinned random seed 102 are now checked in Lean by the test suite.

An analogy: each array is a row of lockers holding one default item, except a few changed lockers. To compare two rows, you open only the changed lockers and compare the defaults. An ite is a switch that picks one of two rows. Lean now gets this argument for every row the switch could pick.

Worked example

(a) The input

This is the PR's new test input ite_of_chains_against_a_chain.

(set-logic QF_ALIA)
(declare-const p Bool)
(declare-const k0 Int)
(declare-const x0 Int)
(declare-const x1 Int)
(declare-const y Int)
(assert (= (ite p (store ((as const (Array Int Int)) x0) k0 x1) ((as const (Array Int Int)) x0))
           (store ((as const (Array Int Int)) x1) 1 x0)))
(assert (= ((as const (Array Int Int)) x0) (store ((as const (Array Int Int)) x1) 2 y)))
(assert (not (= y x1)))
(check-sat)

The first assertion compares an ite of two different chains with a third chain. Z3 rewrites it to x0 = x1.

Review

The reviewer approved. There were no blocker or major findings, one minor finding, and two nits.

Minor: exponential walk. The reviewer built ites that share sub-terms, so many paths reach the same leaves. The leaf collector walked every path, and the time grew about fourfold every two levels. That could hang an export. The fix remembers visited nodes, and a new test walks a 60-level shared DAG.

Nit: read budget. The reviewer put two long chains and a small ite equality in one rewrite step. The ite's reads pushed the total over the shared budget, so all read facts were dropped. Lean still passed, but a nearby input might not. Equalities above the 16-pair cap are now skipped when counting. Per-pair read indices were not adopted, because the cap already bounds the cost.

Nit: README. The README did not mention the new converses for ites of chains. One paragraph was added.

Risks and open questions

  • Lean's work grows with leaf pairs times stored indices. The 16-pair cap and the read budget bound it.
  • A store over an ite of different arrays is not a chain, so it gets no converse. No failing input has been seen.
  • An ite of chains equated with an array variable, an application, or a map gets no converse either.
  • CI and the local gate had not reported when this page was written.

What comes next

The random generator hit this shape once in about 1,100 seeds. A generator that deliberately builds ites of store chains would test the new code harder. The two uncovered shapes above come next if a failing input appears.

Glossary

array
A value that maps each index to an element, like a function. (Array Int Int) maps integers to integers.
axiom
A statement Lean accepts without proof. Adding one means trusting it.
clause
A disjunction of literals, such as a or not b.
clause log
The record Z3 writes of each clause it derives, with a hint saying why. The reconstructor replays it in Lean.
constant array
An array that holds the same element at every index. In SMT-LIB it is written ((as const (Array Int Int)) x0).
converse
The reverse direction of an implication. If "A implies B" is known, its converse is "B implies A".
DAG
Directed acyclic graph. Here, a term tree where identical sub-terms are stored once and shared.
equality
A formula (= s t) stating that two terms have the same value.
extensionality
The rule that two arrays are equal if they agree at every index. In Lean, funext applies it.
if-then-else term (ite)
A term (ite c a b) whose value is a when the Boolean c is true and b otherwise.
lemma
A small proved statement used as a step toward a larger proof.
literal
A Boolean variable or atom, or its negation.
read (select)
Looking up an array at an index: (select a i).
refutation
A proof that a set of assertions leads to False.
rewrite step
A proof step that replaces a formula by an equivalent, simpler one, such as an array equality by x0 = x1.
sort
The type of a value, such as Int, Real, Bool, or (Array Int Int).
store
An array update: (store a i v) equals a except that index i now holds v.
store chain
Several stores applied one after another to a base array, here a constant array.
tactic
A Lean command that builds part of a proof automatically. grind, omega, and funext are tactics.
theorem
A named statement together with its proof, checked by Lean.
