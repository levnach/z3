In one paragraph

This pull request changes the Lean text that the reconstructor writes for a lemma step. The old text was a proof by contradiction whose size grew with the square of the number of literals in the step's clause. The new text proves the clause one literal at a time, so its size grows linearly. The certificates of large refutations become shorter, and Lean checks them faster. A generated lemma step over 1,539 literals, which Lean used to reject, now verifies. No axiom is added. The Lean kernel still checks every step against the clause it states.

Background

The pipeline already certified refutations with lemma steps, but at a high cost. In the benchmark sample, their lines were about 15% of all generated Lean text. A very wide step used up Lean's heartbeats, and its certificate was rejected. The change covers long refutations with linear arithmetic or uninterpreted functions. The work serves milestone 3 of the plan, equality and linear arithmetic, by reducing cost.

What changed

Picture a row of lockers, one per literal. The old proof walked from the door to each locker separately. The new proof walks down the row once and opens each locker as it passes.

  • Reconstructor. A lemma step in a long arithmetic or uninterpreted-function refutation is now one chain that handles each literal once, so its text grows linearly.
  • Reconstructor. One helper theorem, classical_or_intro, is written once per file and proved in Lean, so the chain needs no new axiom.
  • Reconstructor. Propositional refutations and refutations of at most 500 proof steps keep the old form, so propositional certificates still use no axiom.
  • Tests. New tests pin a chain's exact text, show that Lean rejects seven wrong chains, and verify the 1,539-literal step.

Each constant is an entry of _vars, and each equality is a named formula. The last definition, formula_4819, is the wide clause.

private theorem classical_by_contradiction {p : Prop} (h : Not p -> False) : p :=
  @Decidable.byContradiction p (Classical.propDecidable p) h

private theorem classical_or_intro {p q r : Prop} (g : r -> q) (f : Not p -> r) : p \/ q :=
  @Decidable.byCases p (p \/ q) (Classical.propDecidable p) (fun _p => Or.inl _p) (fun _n => Or.inr (g (f _n)))

The second theorem is the new helper: it puts one literal p in front of the rest of a clause.

Review

The reviewer approved the change, with no blocker and no major finding.

  • Minor, documented. The reviewer put one chain alone in a file and made it wider and wider. Lean's time and memory grew much faster than the width, but the documentation recorded time only. A very wide step would be rejected for memory, because nothing splits a chain. The integrator measured again and added the table below to the plan document. The old form failed on narrower steps, so nothing regressed.
  • Nit, fixed. A test comment said the helper avoids two of Lean's standard axioms. The reviewer had Lean print the axioms and saw the same three for every variant. A false comment could send a maintainer on a pointless rewrite, so it was corrected.
  • Nit, fixed. The documentation gave one cost per literal. The reviewer found a second kind of literal that costs more, which skews size estimates by a quarter. The documents now give both costs.
  • Suggestions, taken. The integrator added two tests of chains over clauses given as definitions. It also checked four more large texts in Lean and ran every slow test.

Risks and open questions

  • Seven changed sample texts, each above 80 MB, were not checked in Lean after the change. Their siblings verify.
  • A lemma step over about 4,000 literals would be rejected for memory. The widest one in the sample has 154 literals. Where the memory goes was not traced.
  • The chain relies on the order in which Lean's elaboration fixes the helper's argument types. A future Lean version could reject such certificates, but it could not accept a wrong one.
  • One sample file that already failed is now checked as a single file, so its failure takes longer to report.

What comes next

  • Split a chain into pieces of 32 literals, and test it at a few thousand literals.
  • Give propositional and short refutations the same chain.
  • Fix the De Morgan rewrite of a negated distinct over 80 terms, which fails with both reconstructors.
  • Shrink unit resolutions and restated hypotheses, which now dominate the largest texts.

Glossary

assertion
A formula that the input requires to hold. Example: (assert (= x0 0)).
axiom
A statement that Lean accepts without proof. These certificates use at most Lean's three standard axioms.
certificate
A file that records a solver's proof so that another program can check it.
clause
A disjunction of literals. Example: (or (= x0 x1) (not (= x0 x2))).
constant
A symbol that names one unknown value of a given sort. Example: (declare-const x0 Int).
De Morgan rewrite
Replacing "not (A and B)" by "(not A) or (not B)", or the same with "and" and "or" exchanged.
disjunction
An "or" of formulas. It is true when at least one of them is true.
distinct
The SMT-LIB formula saying that no two of the listed terms are equal. Example: (distinct x0 x1 x2).
elaboration
The stage in which Lean fills in the types and arguments that a proof text leaves out, before the kernel checks the result.
heartbeat
Lean's unit for counting its own work. A declaration that needs more than the limit, 200,000 by default, is rejected.
hypothesis
A formula assumed for part of a proof. A later step must discharge it, which means remove the assumption.
kernel
The small core of Lean that makes the final check of every proof.
lemma step
A proof step of Z3. Given a derivation of false from some hypotheses, it concludes the clause of their negations. Example: from "A and B give false" it concludes "(not A) or (not B)".
linear and quadratic growth
A size grows linearly when doubling the input doubles it. It grows quadratically, with the square, when doubling the input makes it four times larger.
linear arithmetic
Formulas over integers or reals that only add terms and multiply them by constants. Example: (<= (+ x (* 2 y)) 5).
literal
An atomic formula or its negation. Example: (= x0 x1) and (not (= x0 x1)).
logic
In SMT-LIB, a named fragment of formulas that an input declares. Example: QF_LIA is quantifier-free linear integer arithmetic.
negation
The "not" of a formula. It is true exactly when the formula is false.
premise
An earlier result that a proof step uses.
proof by contradiction
Proving a statement by assuming its negation and deriving false.
proof step
One inference in a proof. It derives a new formula from earlier ones by a named rule.
propositional
Built only from Boolean variables and the connectives "and", "or", "not", and "implies".
refutation
A proof that derives false from the assertions, which shows that they cannot all hold.
sort
The type of a value, such as Int, Real, or Bool.
term
An expression that denotes a value. Example: x0 and (+ x0 1).
theorem
In Lean, a named statement together with a proof that Lean has checked.
uninterpreted function
A function symbol with no fixed meaning. All that is known is that equal arguments give equal results.
unit resolution
A proof step that removes from a clause the literals already known to be false.
