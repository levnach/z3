In one paragraph

When Z3's rewriting flattens a nested conjunction or disjunction, the Lean reconstructor must prove a propositional lemma that states the equivalence of the two forms. Its prover first proves small "links" between matching sub-formulas. Then it searches for the full equivalence. Both parts used to share one step budget. On a large QF_LRA benchmark, the links used up the whole budget. The search never ran, the lemma fell back to the grind tactic, and grind failed. This PR gives the links an allowance of their own, capped at the size of the budget. That benchmark now gets a full refutation that Lean checks. Nothing new is trusted. Every link and search step is still a have step that Lean's kernel checks.

Background

Before this PR, the previous iteration had fixed the CNF lemma of the z3test benchmark tta_startup/simple_startup_15nodes. The file still failed at one normalized rewrite lemma. It relates a left-nested Boolean formula over 480 atoms to its flattened form. The prover could handle such lemmas when they were small. It could not handle them when the links alone exceeded the shared budget. This work serves milestone 3, "Equality and linear arithmetic", of the project plan.

What changed

Think of a moving crew that must pack boxes and then drive the truck. Before, packing could eat the whole day, so the truck never left. Now packing gets its own time slot, and it is capped, so packing can never take more than one extra day.

  • A normalized rewrite with many links can now get a structural proof, because the links no longer starve the search.
  • Each link gets an allowance of 100 steps and 5,000 characters, and the total is capped at the normal budget.
  • A rewrite with very many links still falls back to grind alone, so its proof stays within twice the old limits.
  • The 15-node tta_startup benchmark now verifies in Lean, where before it failed.
  • Two new tests pin the allowance and the cap on a generator with the same Boolean shape as that benchmark.

The first have is one link. It proves that the nested form (a ∧ ¬b) ∧ c equals the flat form a ∧ (¬b ∧ c). The file has 13 such links, then the search joins them into the full equivalence. grind remains only as a fallback.

Lean accepted the file. check_lean.sh printed "Lean checks passed." It also passed with the grind fallback replaced by fail "no fallback", so the links and the search do the proving.

Review

Major: the allowance had no cap. The reviewer scaled up the test's own generator and compared old and new certificates in Lean. At 30 and 35 nodes, the new structural proofs took 3 to 5 times longer than grind. At 40 nodes the new file ran Lean out of memory, while the old file passed. So the change had broken an input that used to verify. The fix caps the total allowance at the normal budget. The 30, 35 and 40 node certificates became byte-identical to the old ones again, and a new test pins the cap.

Minor: the test could not catch a broken link. The new test checked the lemma with grind still available as a fallback. grind proves the small lemma by itself, so a malformed link would have passed unnoticed. The test now replaces the fallback with fail "no fallback". The reviewer also confirmed by hand that a tampered link is then rejected.

Nit: the plan overstated the bound. The plan still said a structural proof never exceeds the normal limits. It now says linked rewrites may use up to twice those limits, and it describes the cap.

Risks and open questions

  • Soundness is unchanged. No axiom, sorry, or skipped check was added.
  • A rewrite with a few hundred links can now get a long structural proof that Lean tries before grind. It is valid but may be slower. The cap bounds this cost.
  • No test pins the 15-node benchmark itself. That would need 180 KB of data in a slow test.
  • The GitHub CI result after the merge is not known from the inputs.

What comes next

The follow-up is cheaper link proofs. A link could be proved by a direct re-association term instead of by search. That would cut the per-link cost that made the allowance necessary.

Glossary

atom
A formula with no Boolean connective inside it, such as x1 <= 5.
Boolean
A true-or-false value, or a formula built from such values with and, or, and not.
CNF (conjunctive normal form)
A formula written as an "and" of clauses, where each clause is an "or" of literals.
conjunction
An "and" of formulas. It is true only when every part is true.
disjunction
An "or" of formulas. It is true when at least one part is true.
equivalence
Two formulas that are true in exactly the same cases. Lean writes it Iff.
flattening
Rewriting nested connectives of one kind into one level. For example, (a ∧ b) ∧ c becomes a ∧ b ∧ c.
kernel
The small trusted core of Lean that checks every proof term.
lemma
A helper theorem proved on the way to the main theorem.
linear real arithmetic (QF_LRA)
Formulas over real variables using only addition, constants, and comparisons, with no quantifiers. For example, x + 2y <= 5.
propositional
About Boolean structure only. Atoms are treated as opaque true-or-false values.
refutation
A proof that a set of assertions leads to a contradiction, that is, to False.
rewriting
Replacing a formula with a simpler or normalized formula that means the same thing.
tactic
A Lean command that builds part of a proof automatically. grind is a general-purpose tactic.
