This pull request is open and not merged. The change under review is commit 3ca6390f8, the second of its two commits.

In one paragraph

The certificate exporter now stops on time in its two remaining in-process stages. The first stage is the legacy proof object solve, which handles propositional input. The second is the replay of the clause log. Both now obey the same time limit and memory limit as the z3 runs. When a limit is hit, the export fails with an error that names the limit. This matters for certifying refutations in Lean at scale. A batch run over many benchmarks no longer hangs on one hard input. Nothing about what Lean checks has changed. A certificate produced within the limits is the same as before.

Background

The previous pull request put limits on every run of the z3 executable during a clause-log export. Two stages ran inside the Python process and were still unbounded. A hard pigeonhole formula with eleven holes ran for ever under the legacy proof object path, even with a one-second limit. A difference logic benchmark took 622 seconds to export under a 60-second limit, because the replay had no deadline. This work serves the regression methodology that the project plan names as its current top priority. That methodology runs large benchmark sweeps, and every stage must end in bounded time.

What changed

  • Legacy exporter: you can now pass --timeout to a propositional export and it stops at that limit instead of running for ever.
  • Legacy exporter: you can now pass --memory to a propositional export, and z3 stops the search once its memory in the process passes that limit.
  • Error messages: you can now tell a time limit, a memory limit, and an outside interrupt apart, because each produces its own message.
  • Clause-log replay: you can now rely on the replay to stop near its time limit, because it checks a deadline before each log command and each solver call.
  • Tests and docs: two new tests cover both limits, and the README and the plan describe them.

The memory limit uses a z3 setting called the memory high watermark. It is a global setting, so the exporter sets it just for the check and restores it afterwards. Think of it as borrowing a shared thermostat: you change it for your meeting and set it back when you leave.

Worked example

This pull request does not make any new input certifiable. Its effect is that a hard input now stops with a clear error, while easy inputs certify exactly as before. So the example has two parts, both from real runs made for this report. The hard input is the pigeonhole formula with 11 holes and 12 pigeons, built by the test helper _pigeonhole(11). It has 132 Boolean variables and is too long to show. The small input below is the same family with 2 holes and 3 pigeons.

(a) The input

(declare-const p0_0 Bool) (declare-const p0_1 Bool) (declare-const p1_0 Bool) (declare-const p1_1 Bool) (declare-const p2_0 Bool) (declare-const p2_1 Bool)
(assert (or p0_0 p0_1))
(assert (or p1_0 p1_1))
(assert (or p2_0 p2_1))
(assert (or (not p0_0) (not p1_0)))
(assert (or (not p0_0) (not p2_0)))
(assert (or (not p1_0) (not p2_0)))
(assert (or (not p0_1) (not p1_1)))
(assert (or (not p0_1) (not p2_1)))
(assert (or (not p1_1) (not p2_1)))
(check-sat)

Variable p1_0 means pigeon 1 sits in hole 0. Each clause either puts a pigeon in some hole or keeps two pigeons out of the same hole.

(b) Before

On the 11-hole version, the old exporter ignored the one-second limit. It was still solving after 60 seconds, when this report's script killed it.

$ python3 examples/python/proof_certificate.py --timeout 1 php11.smt2
(no output; still running after 60 s, killed)

On the small input above, the old exporter succeeded. Its certificate is byte-for-byte identical to the new one.

(c) After

On the 11-hole version, the new exporter stops after about one second with exit code 2.

$ python3 examples/python/proof_certificate.py --timeout 1 php11.smt2
proof_certificate.py: error: the legacy solver run exceeded the time limit of 1 s

The error names the limit, so a batch run can record why this input was skipped.

On the small input, the new exporter still produces a certificate, and the reconstructor turns it into this Lean file.

-- Atom 0: "p0_0"
-- Atom 1: "p0_1"
...
def formula_0 (_atoms : Nat -> Prop) : Prop := _atoms 0
def formula_1 (_atoms : Nat -> Prop) : Prop := _atoms 1
def formula_2 (_atoms : Nat -> Prop) : Prop := (Or (formula_0 _atoms) (formula_1 _atoms))
...

Each SMT-LIB variable becomes a numbered atom, and each subformula becomes one Lean definition.

theorem unsat (_atoms : Nat -> Prop)
    (_h0 : (formula_2 _atoms))
    (_h1 : (formula_5 _atoms))
    ...
    (_h8 : (formula_20 _atoms))
    : False :=

The theorem says that the nine assertions together imply False.

  ...
  let _step_41 : (formula_9 _atoms) :=
    (Or.elim _step_40 (fun _literal => _literal) (fun _tail => (False.elim (_tail _step_37))))
  let _step_42 : (formula_1 _atoms) :=
    (_step_30.resolve_left _step_41)
  let _step_43 : (formula_34 _atoms) :=
    (False.elim ((_step_21.resolve_left (fun _literal => _literal _step_42)) _step_39))
  _step_43

The last steps are resolution steps that remove one literal at a time until False remains.

Lean accepted this file. The reconstructor reported "Lean checked the refutation", and scripts/check_lean.sh reported "Lean checks passed."

Review

The reviewer approved the change and found no blocker or major issues.

Minor: the memory message blamed the wrong thing. The reviewer exported the trivial input (assert false) with a 1 MB memory limit. It failed at once, saying the legacy solver run exceeded the limit. The watermark counts all of z3's memory in the process, not only this solve. A long-running harness that already holds large z3 contexts could see trivial inputs rejected with a misleading message. The fix reworded the error and the help text to say "z3's memory in this process".

Nit: an interrupt looked like a timeout. z3 reports both its own timer and an outside cancel as "canceled". The first version called every "canceled" a time-limit hit. The fix reports a time limit only when the check actually ran for the full limit. Otherwise the result stays "unknown: canceled". A new subtest covers this case.

Suggestions. The reviewer noticed that the memory subtest would wait 60 seconds if the watermark ever stopped working. It now uses a 5-second limit, so such a failure shows up quickly. A second suggestion, passing the z3test matrix limit through to the replay, lives in another repository and was left as a follow-up.

Risks and open questions

  • The memory watermark is global to the process. A caller with other large z3 contexts reaches the limit sooner.
  • Another thread using z3 during the check would also see the watermark. The exporter itself is single-threaded.
  • A replay that truly needs more than its limit, 600 seconds by default, now fails where it used to finish.
  • The deadline is checked only between steps. One very slow step can still overrun it.
  • The Python work that builds the certificate after the legacy check is not bounded.

What comes next

  • The z3test scripts proof_lean.py and proof_matrix.py should pass their own limits through to the exporter.
  • Lean runs out of memory on some large QF_UF certificates. Fewer and smaller declarations are the planned levers, with NEQ004_size4 as a concrete target.

Glossary

Boolean
A value that is either true or false. In SMT-LIB its sort is Bool.
certificate
A file that records a proof in enough detail for an independent checker to verify it, here a JSON file read by the Lean reconstructor.
clause
An "or" of literals, such as (or (not p0_0) (not p1_0)).
clause log
A record that z3 writes while solving, listing each clause it learned and the input it used. The exporter rebuilds a proof from it.
difference logic
Integer arithmetic limited to constraints of the form x - y <= c. Its SMT-LIB name is QF_IDL.
legacy proof object
The proof term that z3's older proof mode builds in memory. The exporter uses it for propositional input.
literal
A Boolean variable or its negation, such as p0_0 or (not p0_0).
memory high watermark
A z3 setting. When z3's total memory use passes it, the search stops and reports "memout".
pigeonhole formula
The claim that n+1 pigeons fit in n holes with at most one pigeon per hole. It is false, and proving that by resolution takes very long as n grows.
propositional
Built only from Boolean variables and the connectives and, or, not, and implies, with no numbers or functions.
QF_UF
The SMT-LIB logic of quantifier-free formulas with uninterpreted functions and equality.
refutation
A proof that a set of assertions leads to False, so they cannot all hold.
replay
Reading a clause log step by step and rebuilding each step as an explicit proof step.
resolution
The rule that combines two clauses with opposite literals into one. From a or b and not a it derives b.
theorem
A statement that Lean has checked to follow from its hypotheses.
time limit
The longest a stage may run before it gives up. Here the default is 600 seconds.
