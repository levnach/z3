Certify pseudo-Boolean constraints in Lean through the legacy core

Pull request levnach/z3#65 · loop iteration 65 · 2026-11-03T03:19:17Z

State: OPEN. This PR is not merged. Change commit: c7730e75f.

In one paragraph

Input that uses pseudo-Boolean constraints can now be certified in Lean. This covers cardinality constraints such as at-most and at-least, and weighted ones such as pble, pbge and pbeq. Their arguments must be Boolean variables or single negations of them, which makes each one a literal. Lean states each constraint as an integer comparison: a weighted sum of 0/1 literal values against a bound. The pseudo-Boolean theory lemmas and rewrites in Z3's refutation are proved with the omega tactic. No new axioms are added. Lean's kernel also exposed two places where Z3 itself emitted theory lemmas that do not hold on their own. The PR fixes both, only when proofs are enabled.

Background

Before this PR, the exporter rejected every pseudo-Boolean constraint with "unsupported propositional operator". So no propositional input with a cardinality bound could be certified, not even the two unsat queries of the z3test file pb.smt2. The pipeline already handled plain clauses and Boolean structure on the legacy core. This PR widens that kernel-checked Boolean slice (milestone 2 of the plan) with the first theory that lives next to it, a step toward milestone 4, broader theories.

What changed

  • You can now certify propositional input that contains at-most, at-least, pble, pbge or pbeq with integer parameters.
  • Lean now proves Z3's pseudo-Boolean theory lemmas and rewrites by turning each literal into an integer that is 0 or 1 and handing the arithmetic to omega.
  • A certificate whose bound or coefficients differ from the input is now rejected, because the parameters are part of how a constraint is matched to the input.
  • Z3 with proofs enabled no longer emits pseudo-Boolean lemmas that silently rely on unstated facts.
  • Inputs outside the supported shape now get a clear rejection: compound or doubly negated arguments, constraints next to arithmetic or uninterpreted functions, and the clause-log core.

Think of a pseudo-Boolean constraint as a budget. Each true literal costs its coefficient, and the total must stay within the bound. The first C++ defect was like subtracting money already spent from the budget without keeping the receipt. At the base level, Z3 folded known variable values into the bound. It then stated the shrunken constraint as if it held alone. With proofs enabled, Z3 now leaves the bound alone and reads those values later. The second defect was in conflict resolution. Z3 combined several constraints into a cutting-plane resolvent, but its justification cited only some of them. With proofs enabled, Z3 now learns the plain conflict clause instead, which is a valid theory lemma.

Worked example

This input is the PR's test case pb_at_most_pairs. At most one of three variables may be true, yet every pair must contain a true one. It was run through the old and the new scripts for this report.

(declare-const b Bool)
(declare-const c Bool)

private theorem _pb_bit (p : Prop) :
    (0 <= (@ite Int p (Classical.propDecidable p) 1 0) /\ (@ite Int p (Classical.propDecidable p) 1 0) <= 1)
      /\ (p <-> (@ite Int p (Classical.propDecidable p) 1 0) = 1) := by
  by_cases _h : p <;> simp [_h]

A helper proved once per file: a literal's value is between 0 and 1, and the literal is true exactly when its value is 1.

The main theorem says that the four assertions together imply False.

private theorem th_lemma_24 (_atoms : Nat -> Prop)
    : (formula_12 _atoms) -> (formula_1 _atoms) -> (formula_9 _atoms) := by
  unfold formula_12 formula_11 formula_10 formula_9 formula_2 formula_1 formula_0
  (try simp only [_pb_not])
  have _r0 := (_pb_bit (_atoms 0)).1
  have _e0 := (_pb_bit (_atoms 0)).2
  generalize (@ite Int (_atoms 0) (Classical.propDecidable (_atoms 0)) 1 0) = _x0 at _r0 _e0 |-
  ...
  (try simp only [_e0, _e1, _e2]) <;> omega

This is one of Z3's pseudo-Boolean theory lemmas: if at least two negations hold and b is true, then a is false, and omega checks the arithmetic.

Review

The reviewer approved the PR with no blockers and no major findings. The reviewer confirmed there are no new axioms and no sorry.

  • Minor: double negation slipped through. The reviewer fed in ((_ at-least 2) (not (not a)) b) with (not a). The exporter accepted it, but the reconstructor then failed with "unsupported Boolean congruence". That was a clean failure, not a soundness bug. Still, the accepted inputs were wider than what could be certified. Both scripts now accept at most one negation per argument, and the input became a rejection test.
  • Nit: a test checked too loosely. The satisfiable-query test matched any error containing "sat", which also matches "unsat". An unrelated error would have passed it. The pattern now matches the exporter's exact message.
  • Nit: negative numbers were untested. No test used negative coefficients or bounds, although the API can produce them. A new Lean end-to-end input, pb_negative_coefficients, now covers them.
  • Suggestion: explain why learning is off. A comment in theory_pb.cpp now says why conflict learning is disabled under proofs.

Risks and open questions

  • With proofs enabled, Z3 loses some early propagation and no longer learns cutting-plane resolvents. Solving could be slower on pseudo-Boolean-heavy input. The reviewer measured no difference on pigeonhole 6 to 8 or on 40×60 random instances. Solving without proofs is unchanged.
  • Each pseudo-Boolean lemma restates three lines per variable it touches, so very wide constraints give large Lean files.
  • z3test's legacy matrix cell now classifies pseudo-Boolean input as propositional. None of its inputs use such constraints today.

What comes next

  • Certify these constraints on the clause-log core, whose pseudo-Boolean solver would first need to log the constraints and a pb hint.
  • Support compound arguments, and constraints next to arithmetic or uninterpreted functions.
  • Re-enable cardinality conflict learning under proofs, once the justification cites every constraint it combines.

Glossary

axiom
A statement accepted without proof. A trustworthy certificate adds none beyond Lean's standard ones.
base level
The solver's state before it has made any guess. Values fixed here follow directly from the input.
Boolean
A value that is either true or false. In SMT-LIB its sort is Bool.
bound
The number a weighted sum is compared with. In ((_ at-most 1) a b c) the bound is 1.
cardinality constraint
A pseudo-Boolean constraint where every coefficient is 1, so it counts true literals. Example: ((_ at-least 2) a b c).
clause
A disjunction of literals, true when at least one literal is true. Example: (or a (not b)).
conflict
A moment in search where the current assignment makes some constraint false.
conflict clause
A clause the solver learns from a conflict so it never repeats the same mistake.
congruence
The rule that equal inputs give equal results. If x equals y, then (not x) equals (not y).
cutting plane
A way to combine linear inequalities into a new one that every 0/1 solution still satisfies.
if-then-else term
A term that picks one of two values by a condition, written ite. Here ite l 1 0 gives a literal's 0/1 value.
kernel
The small trusted core of Lean that checks every proof step.
literal
A Boolean variable or its negation, such as a or (not a).
negation
The opposite of a Boolean, written (not a). It is true exactly when a is false.
omega
A Lean tactic that decides linear arithmetic over integers and natural numbers.
pigeonhole problem
Putting n+1 pigeons into n holes with at most one per hole. It is always unsat, and it is a standard hard test.
propagation
Deriving a forced value from the current assignment, such as concluding a is false.
propositional
Built only from Boolean variables and connectives like and, or, not, with no arithmetic or functions.
pseudo-Boolean constraint
A linear inequality or equation over literals counted as 0 or 1. Example: ((_ pble 6 2 3) a b) means 2·a + 3·b ≤ 6.
refutation
A proof that a set of assertions leads to false, so they cannot all hold.
resolvent
The new constraint obtained by combining two constraints to eliminate a variable.
rewrite
A proof step stating that a term equals a simpler or normalized one. Example: at-most 1 of three becomes at-least 2 of their negations.
satisfiable
Having at least one assignment that makes all assertions true. Such input has no refutation.
tactic
A Lean command that builds part of a proof automatically, such as simp or omega.
theory lemma
A clause that a theory solver claims is valid by its own reasoning. Z3 writes it th-lemma, and here its hint is pb.
uninterpreted function
A function symbol with no fixed meaning, only that equal arguments give equal results.
