Trim clause logs from 4 KB and cap Lean memory at 8 GB

Pull request #40 in levnach/z3 · state OPEN · 2026-10-28T04:17:47Z · loop iteration 40

This pull request is not merged. The change it proposes ends at commit d324b2b29.

In one paragraph

The pipeline replays Z3's clause log to build a refutation for Lean. Until now, only logs of 1 MB or more went through Z3's native proof trimming first. This PR lowers that threshold to 4,096 characters. Most real inputs now get a certificate with only the clauses that the final empty clause depends on. On the measured inputs, certificates got 3 to 45 times smaller. The trust boundary does not move. The trimmer's output is only a hint, and Lean still checks every kept step. The PR also caps every Lean process at 8 GB, so a runaway proof fails instead of freezing the machine.

Background

The pipeline could already certify QF_UF, QF_LRA and QF_LIA inputs through the clause log. But a log below 1 MB was replayed in full. Lean then re-checked Z3's whole search, dead ends included. One 695 KB QF_UF log became 17.4 MB of Lean. PR #39 had made trimmed QF_UF logs usable over a declared sort. This PR applies trimming to far more inputs. It serves milestone 3, "Equality and linear arithmetic". The memory cap answers an urgent backlog item: on 2026-10-27, four Lean processes at 24 to 41 GB each froze the development machine.

What changed

  • Clause logs of 4,096 characters or more are now trimmed before replay, so a 32 KB QF_UF log yields about 120 KB of Lean instead of 711 KB.
  • When trimming fails, the warning now says why: the trimmer "exited with status N" or "reported an error".
  • Every Lean run started by check_lean.sh or by the library build now stops at 8 GB with "excessive memory consumption detected".
  • A real SMT-LIB QF_UF benchmark now tests that a mid-sized log is trimmed and still verifies.
  • The plan records three native trimmer bugs that now show up more often.

Think of a detective's notebook and final report. The notebook holds every lead. The report keeps only the clues that prove the case. Lean now reads the report, and still checks each clue itself. No C++ code changed.

Worked example

This PR makes no new input certifiable. It changes which certificate is produced. So "Before" shows the old, larger result, not a rejection. All output comes from real runs on the PR's base and final commit.

(a) The input

Four values (f a) to (f d) must differ, yet each equals one of three constants. This is the pigeonhole principle over an uninterpreted function. Its clause log has 7,537 characters, above the new threshold.

(set-logic QF_UF)
(declare-sort U 0)
(declare-fun f (U) U)
(declare-const a U) (declare-const b U) (declare-const c U) (declare-const d U)
(declare-const x U) (declare-const y U) (declare-const z U)
(assert (distinct (f a) (f b) (f c) (f d)))
(assert (or (= (f a) x) (= (f a) y) (= (f a) z)))
(assert (or (= (f b) x) (= (f b) y) (= (f b) z)))
(assert (or (= (f c) x) (= (f c) y) (= (f c) z)))
(assert (or (= (f d) x) (= (f d) y) (= (f d) z)))
(check-sat)

The crash. The reviewer chased some silent fallbacks by cutting a QF_LIA log to ten lines. The native trimmer crashes whenever a step reasons about div and mod by a constant. The result stays correct, because the untrimmed log is replayed. But each crash prints a warning, which fails callers that treat warnings as errors. The fix needs C++, so the bug went into the plan with its reproducer.

The smaller ones. The README still said 1 MB and now says 4,096 characters. A warning that blamed "exit status 0" now says "reported an error". A test that could trim a longer second log by accident now switches trimming off with infinity. The benchmark's trailing spaces were kept, because it is copied verbatim.

Risks and open questions

  • More inputs now reach a trimmer with three known bugs. Each falls back safely, at the cost of a wasted run and a warning.
  • One bug rejects a step as "not derivable by unit propagation". Another makes the empty clause depend on itself.
  • A trimmer timeout still fails the whole export instead of falling back.
  • The 8 GB cap could fail a very large proof in CI. The largest proof in the suite peaks at about 4.5 GB.
  • Only about 15 benchmark files were measured.

What comes next

C++ fixes for the three trimmer bugs, each with a regression test. A trimmer timeout that falls back like other failures. Then a full re-scan of the smtlib-sample benchmarks with the new threshold.

Glossary

certificate
A file that records a proof in a form another program can check, here the JSON that the Lean generator reads.
clause
An "or" of literals, such as p or not q. It is true when at least one literal is true.
clause log
The list of clauses Z3 writes while it searches, each with the reason it was added.
empty clause
A clause with no literals. It can never be true, so deriving it ends a refutation.
hint
Information from the solver that guides the checker but is not trusted. A wrong hint makes checking fail, never succeed.
literal
A Boolean atom or its negation, such as (= (f a) x) or (not (= (f a) x)).
logic (SMT-LIB)
A named fragment of SMT-LIB. QF_UF is quantifier-free formulas with uninterpreted functions. QF_LRA and QF_LIA are quantifier-free linear real and integer arithmetic.
proof trimming
Keeping only the proof steps the final conclusion depends on, and dropping the rest.
refutation
A proof that a set of assertions leads to a contradiction, that is, to False.
replay
Re-deriving each step of a log independently, instead of trusting that the solver got it right.
sort
The type of a value in SMT-LIB, such as Int, Bool, or a declared sort like U.
tactic
A Lean command that builds part of a proof automatically. grind is one.
theory lemma
A clause that is true because of a theory, such as equality or arithmetic, not because of Boolean logic alone. Z3 marks these steps th-lemma.
transitivity
The rule that if s = t and t = u, then s = u.
trust boundary
The line between the parts whose mistakes could make a wrong result pass, and the parts whose mistakes can only make checking fail.
uninterpreted function
A function symbol with no fixed meaning. The only rule is that equal arguments give equal results.
unit propagation
If all literals of a clause but one are false, the last one must be true. Z3 marks these steps unit-resolution.
