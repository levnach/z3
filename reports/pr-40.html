In one paragraph

Before the exporter replays a clause log, Z3's native proof trimmer can cut it down to the clauses that the final conflict needs. This PR starts trimming at 4,096 characters instead of 1 MB. On real QF_UF and QF_LIA inputs, the certificate shrinks by 3x to 45x, and checking gets up to 10x faster. The trust boundary does not move. Every kept step is still replayed and checked in Lean, and a failed trim falls back to the whole log. The PR also caps every lean process at 8 GB of memory. Together, these make larger refutations practical to certify.

Background

Before this PR, only clause logs of 1 MB or more went through the trimmer. Smaller logs were replayed whole. The Lean refutation then covered Z3's entire search, including dead ends that the final empty clause never uses. Nothing was rejected, but proofs were much larger than needed. Lean processes also ran without a memory limit, and on 2026-10-27 four of them froze the development machine. This work serves milestone 3, equality and linear arithmetic. That milestone covers uninterpreted functions with congruence. It also serves the plan to check larger SMT-LIB collections.

What changed

  • Exporter: clause logs of a few kilobytes are now trimmed, so their certificates keep only the steps the refutation needs.
  • Exporter: when trimming fails, the warning now says why.
  • Lean tooling: each Lean check and the library build now stop at 8 GB of memory instead of exhausting the machine.
  • Tests: a real SMT-LIB QF_UF benchmark now guards the change. Its 32 KB log must be trimmed and still verify in Lean.
  • Docs: the plan now lists three known trimmer bugs that more inputs reach, each with a reproducer.

Trimming is like an editor who cuts a detective's notebook down to the clues that name the culprit. Lean is the judge who rereads every kept clue, so a bad edit cannot sneak a false clue past it.

Review

The reviewer approved the change with no blocker and no major finding.

  • Minor: the trimmer crashes on integer division. The reviewer fed the trimmer QF_LIA logs, which the lower threshold now sends there. Any arithmetic step over integer division by a constant crashed it, even in a ten-line log. The result stayed correct, because a crash falls back to the untrimmed replay. But each crash wastes a run and raises a warning. The fix belongs in C++, so the PR recorded the bug in the plan with its reproducer.
  • Minor: stale documentation. The exporter README still said trimming starts at 1 MB, which would mislead users. It now says 4,096 characters.
  • Nit: a misleading warning. When the trimmer exited normally but printed an error, the warning blamed “exit status 0”. It now says “reported an error” in that case, and a test checks both wordings.
  • Nit: a fragile test. The comparison run could trim a slightly longer log by accident. It now disables trimming completely.
  • Nit: trailing whitespace in the new benchmark. It was kept, because the file is copied verbatim from SMT-LIB.

The reviewer also suggested treating a trimmer timeout like other trimmer failures. That was not done in this PR.

Risks and open questions

  • More inputs now reach a trimmer with three known bugs. They are the division crash, an empty clause that depends on itself, and a step it rejects as not derivable by unit propagation. Each falls back soundly, but a caller that treats warnings as errors will fail.
  • A trimmer timeout still fails the whole export instead of falling back.
  • Trimming changes the certificate, and so the Lean text, for every log of 4 KB or more.
  • The 8 GB cap could fail a very large proof in CI. The largest proof in the suite peaks at about 4.5 GB.
  • Only about 15 SMT-LIB files were measured. The full effect on larger collections is unknown.

What comes next

  • Fix the three trimmer bugs in the native trimmer, each with a C++ regression test.
  • Make a trimmer timeout fall back to the untrimmed log.
  • Rescan z3test's smtlib-sample end to end with the new threshold.

Glossary

certificate
The exported proof data that Lean checks. Here it is a JSON graph of proof nodes, such as asserted facts, lemmas, and resolution steps.
clause
A disjunction of literals, such as p or not q or r. At least one literal must be true.
clause log
A record of every clause the solver added, learned, or deleted during its search, with a hint for each inference.
conflict
A point in the search where the current assignment makes some clause false. The final conflict proves the empty clause.
congruence
The rule that equal arguments give equal results. If a = b, then f(a) = f(b).
empty clause
A clause with no literals. It can never be true, so deriving it ends a refutation.
hypothesis
A fact a theorem assumes. In the generated theorem, each input assertion is one hypothesis.
literal
A Boolean atom or its negation, such as x = y or not (x = y).
logic (QF_UF, QF_LIA, QF_LRA)
An SMT-LIB name for a class of formulas. QF means quantifier-free. UF is uninterpreted functions, LIA is linear integer arithmetic, and LRA is linear real arithmetic.
pigeonhole principle
If more items than boxes are placed in boxes, some box holds two items. Four distinct values cannot fit into three.
proof trimming
Keeping only the steps that the final conclusion depends on and dropping the rest. Z3's trimmer works on clause logs.
refutation
A proof that a set of assertions implies False, so they cannot all hold at once.
replay
Re-deriving each logged step from its premises instead of trusting the log.
resolution
Combining two clauses that contain a literal and its negation. From p or q and not p, conclude q.
sort
The type of a value in SMT-LIB, such as Int, Bool, or a declared sort like U.
tactic
A Lean command that builds part of a proof automatically. grind is one example.
theory lemma
A clause that holds because of a theory, such as equality, not because of Boolean logic alone. It appears as th-lemma in certificates.
trust boundary
The line between what must be trusted and what is checked. The solver and its trimmer sit outside it: their output is checked, not trusted.
uninterpreted function
A function symbol with no fixed meaning. The only rule it obeys is congruence. Example: f in the input above.
unit propagation
When all literals of a clause but one are false, the last one must be true. Repeating this is unit propagation.
