Certify QF_LRA refutations from the legacy proof object in Lean

Pull request #8 Merge commit b4f85f2 Merged 2026-10-14T19:05:51Z Loop iteration 8

In one paragraph

This PR makes Z3's default solver core record the evidence behind each arithmetic step, so its QF_LRA proofs can become Lean files. A refutation is a proof that a set of formulas cannot all be true at once. QF_LRA is the fragment of linear constraints over real-valued variables, without quantifiers. Until now the default core's theory lemmas (steps justified by arithmetic rather than pure logic) said only "these facts clash" without saying how. Each now carries Farkas coefficients, the multipliers showing which weighted sum of the premises adds up to a contradiction. The exporter re-derives every sum exactly, and the Lean reconstructor states each step as an implication from its premises. The trust boundary is unchanged.

Background

Z3 has two proof producers. The newer core writes a clause log, a list of learned clauses with hints, and the pipeline already certified QF_LRA from it. The default core writes a proof object, a complete tree of inference steps including preprocessing. That path was certified only for propositional input and for QF_UF, the fragment with uninterpreted functions (function symbols with no fixed meaning, only the rule that equal inputs give equal outputs). The plan listed this PR as the last of two legacy items under milestone 3, "Equality and linear arithmetic".

What changed

  • Solver core. The arithmetic module now records Farkas coefficients on every conflict and every bound propagation (deriving a new limit on a variable from existing limits).
  • Exporter. It accepts QF_LRA from the default core's proof object, writes the sort (the type of a value) Real with its numerals, and unifies the three hint conventions Z3's arithmetic modules use.
  • Reconstructor. A theory lemma may now have premises (earlier steps it rests on), and Lean proves the implication from their conclusions to the step's conclusion.
  • Reconstructor. Congruence (equal inputs give equal outputs) through arithmetic operators and comparisons is now proved too.
  • Safety. A theory lemma without coefficients, or one using an integer-only rule, is rejected at export.

Worked example

The input is the reviewer's command-line test from the PR, with a logic declaration added. Adding the last two facts gives x plus y at least 2, which contradicts the first. That sum, with weight 1 on each fact, is what the Farkas coefficients 1 1 1 record.

(a) The input

(set-logic QF_LRA)
(declare-const x Real)
(declare-const y Real)
(assert (<= (+ x y) 1.0))
(assert (>= x 2.0))
(assert (>= y 0.0))
(check-sat)

(b) Before the PR

The parent commit's exporter, asked for the default core's proof object, refused the input.

$ proof_certificate.py --core legacy example.smt2

The old reconstructor also rejects the new certificate:

In automatic mode the exporter used the clause log for this input before and after the PR, with identical output. The PR adds a second route and leaves the automatic choice unchanged.

(c) After the PR

The current exporter accepts the input in legacy mode and the reconstructor writes the file below, which the project's Lean checker accepted with "Lean checks passed."

def term_1 (_atoms : Nat -> Prop) (_vars : Nat -> Rat) : Rat := _vars 1
def term_2 (_atoms : Nat -> Prop) (_vars : Nat -> Rat) : Rat := ((term_0 _atoms _vars) + (term_1 _atoms _vars))

Each variable becomes a rational-valued table entry, and each assertion a named formula.

private theorem th_lemma_13 (_atoms : Nat -> Prop) (_vars : Nat -> Rat)
    : (formula_8 _atoms _vars) -> (formula_6 _atoms _vars) -> (formula_4 _atoms _vars) -> (formula_12 _atoms _vars) := by
  unfold formula_12 formula_8 term_7 formula_6 term_5 formula_4 term_3 term_2 term_1 term_0
  grind (splits := 64)

The new shape: the theory lemma is an implication from its three premises to False, proved by Lean's grind tactic after Python re-derived the weighted sum.

Review

The reviewer approved with no blocking or major findings: one minor issue and three nits, all fixed before the PR was opened.

  1. Minor: one propagation path still wrote empty evidence. The reviewer found a second place where the arithmetic module asserts a fresh bound literal (an atomic formula or its negation), used only under an optional aggressive propagation setting, that still left the coefficient list empty. The integrator confirmed it: with the setting on, one of 44 random instances carried a bare theory lemma and the exporter refused the whole certificate. The fix records bound coefficients there too and adds a test for that mode. The rejected instance now checks in Lean. It mattered because a correct proof would have been reported as uncheckable.
  2. Nit: tests pinned solver heuristics. Some tests asserted facts that depend on which arithmetic module Z3 picks, so a tuning change would have broken CI with no real defect. They now check the exporter's promises instead: coefficient count equals premises plus clause literals, and every coefficient is positive.
  3. Nit: a debug trace printed the coefficient list before it was filled, so it always showed empty. It was moved after the fill.
  4. Nit: an error message said "coefficients for N literals" although the count includes premises. It now reports both separately.

The reviewer also relabelled a step as an implied equality that passed the Python shape check, and confirmed that Lean refused it and nothing was published.

Risks and open questions

  • The C++ change runs on every proof-enabled arithmetic solve in the default core, but it only fills a list, and nothing changes without proofs.
  • Coefficients are hints: the reconstructor re-derives each weighted sum exactly before Lean runs, so a wrong convention causes a rejection, not an unsound proof.
  • No input produced an equality propagation step (a derived equality between two variables) from the default core, so that shape has no end-to-end test.

What comes next

  • Inputs with a real-valued if-then-else term (written ite in SMT-LIB) are still rejected on this path, because the default core names each one by a fresh definition the certificate cannot tie to the input. The plan names this as the next legacy item.
  • Until then, automatic mode keeps the clause log for arithmetic.
  • The regression matrix cell for the default core's proof object still checks propositional input only.

Glossary

Refutation
A proof that a set of formulas cannot all be true at the same time.
QF_LRA
Quantifier-free linear real arithmetic: inputs made of linear constraints over real-valued variables.
QF_UF
Quantifier-free formulas with uninterpreted functions and equality.
Uninterpreted function
A function symbol with no fixed meaning, only the rule that equal inputs give equal outputs.
Sort
The type of a value, such as Bool or Real.
Literal
An atomic formula or its negation.
Clause
A disjunction (an "or") of literals.
Premise
An earlier proof step that a later step rests on.
Theory lemma
A proof step justified by a theory such as arithmetic, rather than by pure logic.
Farkas coefficients
Non-negative multipliers showing which weighted sum of linear constraints adds up to a contradiction.
Bound propagation
Deriving a new upper or lower limit on a variable from existing constraints.
Equality propagation
Deriving that two variables must be equal from existing constraints.
Congruence
If the inputs of an operation are equal, its outputs are equal.
If-then-else term
A term whose value is one of two branches depending on a condition, written ite in SMT-LIB.
Difference logic
The sub-fragment where every constraint compares the difference of two variables with a constant.
Proof object
The complete inference tree the default core produces, including preprocessing steps.
Clause log
The list of learned clauses with hints that the newer core produces.
Hint
Untrusted evidence attached to a step, re-derived by the checker before it is used.
