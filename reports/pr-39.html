Use trimmed QF_UF clause logs and search assumptions by shared symbols

Pull request #39 on levnach/z3 · state OPEN · 2026-10-28T02:07:42Z · loop iteration 39

This pull request is open and not merged. The change under review is commit 70998c7d9.

In one paragraph

This PR makes two fixes to the Python exporter that turns a Z3 clause log into a certificate. First, the exporter now uses trimmed logs for QF_UF inputs. Before, a trimmed log started with the declaration of an uninterpreted sort, and the exporter rejected that line. It then fell back to the full log and built a much longer refutation. Second, when the exporter ties an assumed clause to an input assertion, it now runs solver checks only against the conjuncts that share an uninterpreted symbol with that clause. On one large input this cut the export from 90 seconds to about one second. Lean still checks every step, so soundness is untouched.

Background

The clause-log path could already certify many QF_UF inputs. Logs of 1 MB or more are first shortened by Z3's native trimmer, but for QF_UF this never worked. The trimmer copies the input's declare-sort line, and the exporter refused it. This was an open item in the plan's scaling survey. On inputs with many assertions, each unmatched assumed clause was also compared with every conjunct. The PR serves milestone 3, which adds uninterpreted functions and equality reasoning end to end.

What changed

  • Exporter: a trimmed clause log for a QF_UF input is now used directly, with no warning and no fallback to the full log.
  • Exporter: on inputs with more than 64 conjuncts, an assumed clause is checked only against conjuncts that share a symbol with it, plus conjuncts that have no symbols.
  • Exporter: the index behind that search uses memory linear in the input, even on a chain of thousands of nested if-then-else terms.
  • Tests: four new tests pin this down, including one that sends a trimmed QF_UF log through Lean with warnings turned into errors.
  • Docs: the plan gains a dated note, and the NEQ004_size4 survey item is marked fixed.

The second fix works like a library index: look up a word instead of reading every book. A satisfiable conjunct with no shared symbol cannot imply a clause unless the clause is valid. A missed clause still reaches the unsat core fallback. At worst, the filter costs completeness.

Review

The reviewer approved with no blocker or major finding, and confirmed the speed numbers.

  • Minor, fixed: memory blow-up on deep terms. The reviewer fed in a very deep chain of nested if-then-else terms. The first version kept a symbol set for every subterm, and memory grew quadratically. Such chains are not unusual in real encodings, so the exporter could run out of memory before Lean even started. The fix walks the DAG once per conjunct and frees the sets afterwards. A new test with a 16 MB limit guards it.
  • Nit, fixed: a test comment said “two minutes” where every other source said 90 s.
  • Nit, fixed: a badly wrapped paragraph in the plan's new note was reflowed.

Risks and open questions

  • On large inputs the filter can change which conjunct ties a clause. Such cases fall to a later candidate or the unsat core fallback. Soundness is unaffected.
  • Subterms shared between conjuncts are walked once per conjunct, not once overall.
  • CI results are unknown at the time of writing.

What comes next

  • Lower the 1 MB trim threshold for QF_UF. Cambridge's untrimmed log gives about 178k steps, its trimmed log 460.
  • The qg5 inputs still fail: trimming times out, or the Lean output is too large.
  • Cap Lean's memory, an urgent backlog item. Parallel Lean runs crashed the machine during this iteration.

Glossary

assertion
A formula the input states as true, written (assert …) in SMT-LIB.
clause
A disjunction of literals, such as p or not q. It is true when at least one literal is true.
clause log
A record Z3 writes while solving: every clause it assumed, inferred, or deleted, with hints for theory steps.
completeness
The ability to find a proof whenever one exists. Losing completeness means some inputs may fail, never that a wrong proof is accepted.
conjunct
One part of a conjunction. In (and p q) the conjuncts are p and q.
congruence
The rule that equal arguments give equal results: from a = b follows f a = f b.
DAG
Directed acyclic graph. Z3 stores terms this way, so a shared subterm is stored once and pointed to many times.
if-then-else term
A term that picks one of two values by a condition, written (ite c x y) in SMT-LIB.
literal
A Boolean atom or its negation, such as p or not p. An equation like a = b can be an atom.
QF_UF
The SMT-LIB logic of quantifier-free formulas over uninterpreted sorts and functions with equality.
refutation
A proof that a set of assertions leads to False, so they cannot all hold.
satisfiable
A formula is satisfiable when some assignment of values makes it true.
solver check
One call to Z3 asking whether a formula is satisfiable, used here to test equivalence or implication.
soundness
The guarantee that only true statements get proofs. A sound checker never accepts a wrong proof.
sort
The type of a value, such as Int, Real, or Bool.
tactic
A Lean command that builds part of a proof automatically, such as grind. Lean's kernel still checks the result.
theory lemma
A clause that holds because of a theory, such as equality, rather than pure Boolean logic. Example: a ≠ b or f a = f b.
trimming
Removing the steps of a clause log that the final contradiction does not depend on, like keeping only the recipe steps the finished dish needs.
uninterpreted function
A function symbol with no fixed meaning. The only thing known is congruence. Example: (declare-fun f (U) U).
uninterpreted sort
A sort with no fixed meaning, declared with (declare-sort U 0). Lean treats it as an arbitrary type.
uninterpreted symbol
A constant or function declared by the input, such as a or f, as opposed to built-ins like and or =.
unit resolution
A rule that removes a literal from a clause when its negation is known. From p or q and not p it gives q.
unsat core
A subset of the assertions that is already unsatisfiable on its own.
valid
A formula is valid when every assignment makes it true, such as p or not p.
