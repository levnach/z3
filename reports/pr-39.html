In one paragraph

This PR changes only the Python exporter that turns Z3's clause log into a certificate. Before, every trimmed QF_UF log was thrown away, because its sort declaration was not accepted. The full log gives a refutation with about three times as many unit resolution steps. Now the trimmed log is used. The PR also speeds up the search that ties each assumed clause to an assertion. On large inputs, it only checks conjuncts that share an uninterpreted function or constant with the clause. Lean still checks every step, so soundness is untouched. Certificates for larger QF_UF inputs become smaller and faster to build.

Background

For big inputs, the pipeline asks Z3 to trim the clause log first. That only happens when the log is at least 1 MB. Before this PR, trimming never worked for QF_UF inputs over a declared sort. The plan's scaling survey listed this as open for the z3test input NEQ004_size4. Large QF_UF files also caused hundreds of thousands of small solver checks for equivalence and implication. The work serves milestone 3, "Equality and linear arithmetic", which covers uninterpreted functions and congruence reasoning end to end.

What changed

  • The exporter now keeps declare-sort lines in a trimmed log, so trimmed QF_UF logs are used instead of discarded.
  • On NEQ004_size4, the certificate now needs about a third of the unit resolution steps, and export is several times faster.
  • When an assumed clause matches no assertion directly, the exporter now checks only conjuncts that share a symbol with it, plus symbol-free ones.
  • That filter only applies to inputs with more than 64 conjuncts, and anything it misses still reaches the existing unsat core fallback.
  • Building the symbol index now uses memory that grows linearly with the formula, even on very deep if-then-else chains.

The filter works like a librarian tracing a quote about Paris: books that never mention Paris are skipped.

Worked example

This is the smallest congruence case: a = b but f(a) ≠ f(b). Its log is far below 1 MB, so the default pipeline never trims it and works both before and after the PR. To reach the fixed code, a small wrapper sets the trim threshold to 0, as the PR's new Lean test does.

Review

The reviewer approved, with no blockers and no major findings.

Minor: quadratic memory in the symbol index (fixed)

The reviewer built an input with 72 conjuncts and one deep ite chain over distinct Boolean atoms. The first draft stored a symbol set for every subterm, and used 5.5 GB at depth 16,000. The code before the PR used 183 MB. Deep chains are common in hardware and software encodings, so the exporter could run out of memory before Lean starts. The fix computes one set per conjunct in a single pass and drops the sets after indexing. Memory fell to 194 MB, and a new test guards the bound.

Nit: inconsistent timing in a test comment (fixed)

A comment said "two minutes" where other sources said 90 s. It was corrected.

Nit: broken line wrapping in the plan note (fixed)

The new doc paragraph was badly wrapped. It was rewrapped and now also describes the index.

Risks and open questions

  • Above 64 conjuncts, the filter can change which conjunct ties a clause. That needs an unsatisfiable conjunct or a valid clause, and only completeness could suffer.
  • Subterms shared between conjuncts are walked once per conjunct.
  • The CI result for the new tests is unknown to this report.

What comes next

  • Lower the 1 MB trim threshold for QF_UF, since trimming shrinks the cambridge certificate from about 178k steps to 460.
  • Fix the qg5 inputs, where trimming times out or the Lean file exceeds 100 MB.
  • Cap Lean's memory in scripts/check_lean.sh, an urgent backlog item.

Glossary

assertion
A formula the input states as true with assert, such as (= a b).
Boolean
The sort with exactly two values, true and false. A Boolean atom is a Boolean variable or predicate.
clause
A disjunction of literals, read as "at least one of these holds". Example: f(a) = f(b) or not a = b.
clause log
A file in which the solver records each clause it assumes or derives, in order, with a hint for each step.
completeness
The ability to produce a certificate for every input that is in fact unsat. Losing it means some inputs get no certificate, never a wrong one.
congruence
The rule that equal arguments give equal results: if a = b then f(a) = f(b).
conjunct
One part of an "and". The assertion (and p q) has the conjuncts p and q.
equivalence
Two formulas are equivalent when they are true in exactly the same cases.
if-then-else term (ite)
A term that picks one of two values by a Boolean condition: (ite c x y) is x when c holds, else y.
implication
A formula P implies Q when Q is true in every case where P is true.
literal
A Boolean atom or its negation, such as a = b or not (a = b).
refutation
A proof that the assertions together lead to False, so they cannot all hold.
soundness
The guarantee that an accepted certificate is correct. Here, Lean's check provides it.
sort
The type of a value, such as Int, Bool, or a declared sort like U from (declare-sort U 0).
tactic
A Lean command that builds part of a proof automatically, such as grind.
theory lemma
A clause that is true by the rules of a theory, such as equality, rather than by the input.
trimming
Removing from a clause log every step the final contradiction does not depend on.
uninterpreted function
A function symbol with no fixed meaning, only congruence. Example: (declare-fun f (U) U). A constant such as a is one with no arguments.
unit resolution
A step that removes literals from a clause using clauses that say those literals are false. From P or Q and not P, it derives Q.
unsat core
A subset of the assertions that is already contradictory on its own.
valid
True in every case, such as p or not p.
