This pull request is open and not merged. The change under review is commit 2a374f3. It contains two commits: the change and a follow-up that addresses the review.

In one paragraph

The pipeline already asked Z3, acting as an untrusted oracle, for theory clauses that help prove a cnf lemma. Until now, that oracle could not read uninterpreted functions, predicates, or constants of an uninterpreted sort. This PR declares them in the oracle. The oracle can now find clauses that rest on congruence or on an if-then-else term that the rewriter simplified. Lean still proves each proposed clause with a tactic, so the trust boundary does not move. More lemmas in the UF family of logics now get a structural proof before the fallback. No benchmark moves from failing to verified. The gain is in how the refutation is proved, not in how many inputs are certified.

Background

PR #117 added the oracle for cnf lemmas whose propositional abstraction search had failed. It read only arithmetic and Boolean nodes. An application such as (f 0) stayed an opaque leaf to it. So when Z3 logged a clause over the rewritten form of an application, the oracle's search ended in a model. That lemma then kept the fallback alone. This PR serves milestone 3 of the plan, "Equality and linear arithmetic", which adds uninterpreted functions and equality reasoning.

What changed

Think of the oracle as a translator. Before, it left every word it did not recognise untranslated. Now it knows the names of functions and sorts, even though it still knows nothing about what they mean.

  • The oracle can now see functions, predicates, and constants of an uninterpreted sort, over Bool, Int, Real, and named sorts.
  • Cnf lemmas that need congruence, or an ite with equal branches, can now get a structural proof that Lean checks without the fallback.
  • Array terms and datatype constructors stay opaque, and an enumeration sort is treated as uninterpreted, so the oracle never knows more than Lean.
  • Three new inputs, in QF_UF, QF_UFLIA, and QF_UFLRA, are checked in Lean with the fallback removed.
  • Two new unit tests pin down exactly which terms the oracle declares and which it leaves free.
  • The plan document and the examples README describe the new behaviour.

The core change is the new function _theory_function in the reconstructor. Four existing tests were adjusted because the new clauses changed the text they inspect.

Worked example

This PR does not newly certify any input. The PR says so, and the run below confirms it. The old pipeline also accepts this file. What changes is the proof of one lemma. It used to be a single automated tactic call. Now it is a short structural proof with a single oracle clause.

(a) The input

This is the QF_UF input from the PR's new test, with declarations packed onto fewer lines.

(set-logic QF_UF)
(declare-sort U 0)
(declare-fun b0 () Bool) (declare-fun b1 () Bool)
(declare-fun a () U) (declare-fun e () U) (declare-fun z () U)
(declare-fun n () U) (declare-fun w () U)
(declare-fun f (U) U) (declare-fun g (U) U)
(assert (and (= n (ite (= (f a) e) (f e) (g (f a))))
             (= w (ite (and (not b0) (not b1)) z z))
             (= (f a) e)
             (or b0 (not (= w z)) (not (= n (f e))))
             (not b0)))
(check-sat)

The second conjunct says w equals an ite whose two branches are both z. Z3 logged the related clause using w = z directly.

The base commit's scripts, run on the same file, gave no error. They printed this line, with the path shortened:

Review

The reviewer approved the change, with no blocker, major, or minor findings. They raised four nits, and all four were fixed.

Nit44 fixed
  1. Repeated work. The reviewer read the new translation loop and saw that each application's declaration was built twice. The result was correct but wasteful on wide terms. The fix builds it once and keeps it until the node is processed.
  2. Untested promise. The docstrings said enumeration constants are treated as uninterpreted and constructors stay free, but no test checked this. A later edit could have broken it silently. A new unit test now covers both cases. The reviewer had also checked an enumeration input by hand, and Lean accepted it.
  3. A test filter that was too wide. An adjusted test skipped every proof attempt that started with a contradiction step, not only the attempts in cnf lemmas. That could hide a future bug in other lemmas. The filter now applies only to cnf lemmas, identified from the certificate.
  4. Formatting. One paragraph in the plan document had an overlong line. It was rewrapped.

The reviewer also suggested a per-clause limit on Lean's effort, so that a slow clause falls back gracefully. That suggestion was not adopted in this PR and is listed as a follow-up.

Risks and open questions

  • Soundness is unchanged. A wrong clause is an error inside first, and Lean moves on to the fallback.
  • More lemmas now try the structural attempt first. If a clause's tactic runs out of heartbeats, first does not catch that, and the whole lemma fails. Every checked case took under 3 seconds, but that is not a guarantee.
  • The QF_UF qg5 and qg7 files and the QF_AUFLIA and QF_UFLRA sample sets were not rescanned.
  • It is unknown whether any input exists where only the new clauses succeed. Generated inputs of up to 24 nodes still passed through the fallback.

What comes next

  • Cap each clause's heartbeats, so that a slow clause degrades to the fallback.
  • Find a UF input where the fallback fails but the theory clauses succeed.
  • Teach the oracle about arrays and datatypes, for inputs such as dlx-regfile.
  • Rescan the qg5 and qg7 QF_UF files.

Glossary

array
A theory of maps from indices to values, read with select and written with store.
Boolean
A value that is either true or false. Its sort is Bool.
clause
A disjunction of literals, such as b0 ∨ ¬(w = z). It holds when at least one literal holds.
cnf lemma
A clause Z3 records when it turns a formula into clauses. The reconstructor must prove it from the input formula.
congruence
The rule that equal arguments give equal results. If a = b, then f(a) = f(b).
constant
A symbol with no arguments, such as w of sort U.
datatype constructor
A function that builds a value of a datatype, such as red in an enumeration of colours.
enumeration sort
A sort with a fixed, finite list of distinct values, such as Color with red and green.
fallback
The second proof attempt, used when the first one does not check. Here it unfolds all definitions and calls grind.
heartbeat
Lean's unit for measuring how much work a tactic does. A proof that exceeds its heartbeat limit stops with an error.
if-then-else term
A term that picks one of two values by a condition, written (ite c x y) in SMT-LIB.
leaf
A subterm that a procedure treats as an opaque unit, without looking inside it.
literal
An atomic formula or its negation, such as b0 or ¬(w = z).
model
An assignment of values to symbols that makes a formula true. Finding one shows the formula is satisfiable.
oracle
A helper whose answers are used as hints but never trusted. Each hint is checked independently.
predicate
An uninterpreted function whose result is Boolean, such as (r x).
propositional abstraction
A formula with each theory atom replaced by a Boolean variable, so only its Boolean structure remains.
refutation
A proof that a set of assertions leads to False.
rewriter
The part of Z3 that simplifies terms, for example turning (ite c z z) into z.
sort
The type of a value, such as Int, Real, Bool, or a declared sort like U.
structural proof
A proof built step by step from named facts, rather than one call to an automated tactic.
tactic
A Lean command that builds part of a proof, such as unfold or grind.
theory clause
A clause that is true because of what its symbols mean, such as ¬(w = ite c z z) ∨ w = z.
trust boundary
The line between parts whose output must be checked and parts that are trusted. Here Lean checks every hint from Z3, so Z3 is not trusted.
uninterpreted function
A function symbol with no fixed meaning. Only congruence is known about it. Example: (declare-fun f (U) U).
uninterpreted sort
A declared sort with no fixed values, such as (declare-sort U 0).
