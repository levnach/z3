Backjump over unused splits in propositional Lean proofs

Pull request levnach/z3#96 · state OPEN · 2026-11-08T06:15:41Z · loop iteration 96

This pull request is open and not merged. The change under review is commit 95213a7. It contains two commits on top of master.

In one paragraph

The Lean reconstructor contains a small propositional prover. It proves the cnf lemmas in Z3's proofs by propagation and case splits. This PR makes that prover track which facts each finished branch really uses. When a branch never uses its own hypothesis, the split was not needed. The prover then drops the split and its other branches. This is called backjumping. Every proof also keeps only the steps it uses. As a result, a real SMT-LIB integer difference logic circuit, ckt_PROP1_tf_10, now gets a Lean-checked refutation. Before, its widest lemma ran out of heartbeats. Three other benchmarks check several times faster. Only the text of the generated proof changes. Lean still checks every line, and the trusted base is unchanged.

Background

This iteration first measured 17 small QF_IDL files from the SMT-LIB sample in z3test. Six verified in Lean. Three of the failures were RTCL circuits built from Boolean if-then-else terms over difference atoms. In each, one cnf lemma ties a wide clause to the single assertion. The prover split 31 atoms deep and used up its character budget. The fallback proof by tactics then timed out in Lean. The clause itself is propositionally valid. The search was the problem. The work serves Milestone 3 of the plan, equality and linear arithmetic, on real benchmark inputs. It builds on the Boolean proof rules of Milestone 2.

What changed

  • A propositional proof can now skip a case split whose branch closes without the split's hypothesis, instead of exploring every branch.
  • Every generated propositional proof now keeps only the have steps that a later line uses, so Lean reads far less text.
  • The SMT-LIB circuit ckt_PROP1_tf_10 is now a test input, and its wide cnf lemma must verify by its structural proof alone.
  • A new unit test, which needs no Lean, shows the prover drops an irrelevant disjunction and leaves no unused step.
  • The plan document and the examples README describe the new behavior.

An analogy for backjumping: you argue “either it rained or it did not.” If your argument for the “rained” case never mentions rain, the same argument works without the case split at all. An analogy for trimming: a recipe draft lists the whole pantry, but the final recipe keeps only what goes into the dish.

Review

The reviewer approved with no blocker, major, or minor findings. They read the whole diff and the code around it. They used fuzzing on the prover with 3,000 random inputs and ran a scope checker that found no name used outside its scope.

One nit, fixed. The reviewer noticed that the new circuit test only checked that a structural proof was written. It did not check that Lean accepted that proof rather than the fallback. A later bug could break the structural proof, and the test would only report a vague whole-file failure. The second commit fixes this. The test now deletes the fallback and checks the file in Lean. A one-off negative check showed the test fails when the structural proof is broken.

Three suggestions, left as follow-ups. Drop unused bridge steps in _cnf_lemma. Charge the budget for kept rather than generated characters. Assert that emitted lines are single lines. None affects soundness.

Risks and open questions

  • Every proof from the propositional prover now has different text. Tests that pin exact text still pass.
  • The trimming relies on two text conventions: prover names look like _f plus digits, and steps are single unindented lines. A future change that breaks them would make Lean reject a proof. That is visible, but not unsound.
  • The character budget still counts generated lines, not kept ones. This is conservative.
  • CI and local gate results were unknown when this page was written.

What comes next

  • The larger circuits tf_20 and tf_30 still fail. Their search explodes even with 100 times the budget. They likely need clause learning or guidance from a SAT solver's refutation.
  • Two other QF_IDL failures are not yet investigated: DTP_k2_n35 on kernel memory and plan-21 on a simp step limit.
  • The reviewer's three suggestions above.

Glossary

atom
A smallest true-or-false statement inside a formula, such as the Boolean variable rdy_9 or the comparison S1_9 - cvclZero = 6.
backjumping
Leaving a case split early because a branch's proof did not need the split's hypothesis. The split and its other branches are dropped.
Boolean
The sort with exactly two values, true and false. Written Bool in SMT-LIB.
case split
Proving a goal separately in each case of a disjunction, for example once assuming p and once assuming not p. In Lean this shows up as Or.elim with one bullet per branch.
clause
A disjunction of literals, such as (or a (not b) c). It is true when at least one literal is true.
clause learning
A SAT solver technique: after a conflict, record a new clause that explains it, so the same dead end is never searched again.
cnf lemma
A theory lemma in Z3's proof stating that a clause follows from the conversion of a formula to conjunctive normal form, a conjunction of clauses.
disjunction
An “or” of formulas, such as (or x y). It holds when at least one part holds.
fallback proof
A second proof attempt used when the first fails. Here it unfolds every definition and calls the general tactics omega and grind.
fuzzing
Testing a program on many randomly generated inputs to find cases that break it.
heartbeat
Lean's unit of work for a proof step. A step that uses more than its heartbeat limit fails with a timeout.
hypothesis
A fact assumed inside a proof, such as the assumption of one branch of a case split.
if-then-else term
A term that picks one of two values based on a Boolean condition. Written (ite c x y) in SMT-LIB.
integer difference logic
The SMT-LIB logic QF_IDL. Its atoms compare a difference of two integer variables with a constant, such as x - y <= 3.
literal
An atom or its negation, such as p or (not p).
propagation
Deriving forced facts one at a time. If the clause (or a b) holds and a is false, then b must be true.
propositional
Reasoning only with and, or, not, and implication over atoms, without looking inside the atoms.
propositionally valid
True for every true-or-false assignment to its atoms, without any theory reasoning.
refutation
A proof that a set of assertions leads to False, so they cannot all hold together.
sort
The type of a value in SMT-LIB, such as Int or Bool.
structural proof
A proof that follows the shape of the formula step by step, rather than handing the whole goal to a general tactic.
tactic
A Lean command that builds part of a proof automatically, such as omega for integer arithmetic.
theory lemma
A clause in Z3's proof justified by a theory, such as arithmetic, rather than by the Boolean steps of the search. Z3 also uses this rule kind for cnf lemmas.
trusted base
The parts that must be correct for a checked proof to be believed. Here, the Lean kernel and the translation of the input.
