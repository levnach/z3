Omit redundant mod bounds from re-derived Int Farkas lemmas in Lean

Pull request #31 on levnach/z3 · MERGED · merged 2026-10-22T16:56:03Z · merge commit 914b4b8 · loop iteration 31

In one paragraph

This PR makes some Lean proofs much faster without changing what is proved. For a Farkas lemma over Int atoms that include mod terms, the reconstructor used to state two bounds per mod atom before calling the omega tactic. Those bounds are not needed there. The reconstructor has already re-derived the lemma as a linear combination of its literals, so the generalized goal holds without them. The extra facts only made omega do case analysis. On one wide QF_UFLIA certificate, Lean time fell from 48 s to 22 s. That matters because a lemma twice as wide could have run out of heartbeats. Z3 would solve such an input, but Lean would fail to certify it.

Background

The previous iterations taught the reconstructor to prove Int theory lemmas over div, mod, abs and uninterpreted function atoms by first generalizing those atoms to plain integers. For every such lemma, the bounds of each mod atom were stated and reverted into the goal. A stress run at twice the usual instance size found no rejected input. But one refutation spent most of its Lean time on a single 33-literal Farkas lemma with 14 mod atoms. This work serves milestone 3, equality and linear arithmetic, where each fragment must be completed end-to-end.

What changed

  • A Farkas or bound lemma that carries coefficients is now proved by omega over its bare atoms, with no mod bounds in the way.
  • A cut, a lemma without coefficients, and a theory rewrite still get the bounds, because they may silently rely on them.
  • A new Lean-checked test runs the wide seed-75 instance and checks the shape of every generalized lemma by its hint.
  • The README and the plan document now describe which lemmas get bounds, with timings measured on an idle machine.

The decision is one new predicate, _combination_certified, in the reconstructor. Think of it like a receipt: once the reconstructor has checked the sum itself, Lean does not need the extra hints about each price. No Lean library file and no C++ code changed.

Worked example

This PR is a speed fix, not a new feature. The old code already accepted every input that the new code accepts, including the slow seed-75 instance. So there is no small input with a "before" rejection. Instead, the example below shows the real change in the generated Lean text on a tiny input. Both versions were run on it, and Lean accepted both files.

(a) Input

(declare-const x Int)
(declare-const y Int)
(assert (>= (mod x 3) 1))
(assert (>= (mod y 3) 1))
(assert (<= (+ (mod x 3) (mod y 3)) 1))
(check-sat)

Two remainders that are each at least 1 cannot add up to at most 1. Z3 closes this with one Farkas lemma whose coefficients are 1, 1, 1.

(b) Before: the pre-PR reconstructor

The old reconstructor printed Lean checked the refutation. There was no error. Its Farkas lemma stated four bounds before omega:

private theorem th_lemma_49 (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    : (formula_48 _atoms _vars) := by
  unfold formula_48 formula_47 formula_46 formula_45 formula_41 formula_36 formula_22 term_8 term_3
  first
    | (have _m0_0 : ((0 : Int)) <= (term_6 _atoms _vars) := by unfold term_6 term_5 term_1; exact Int.emod_nonneg _ (by decide)
       have _m0_1 : (term_6 _atoms _vars) < ((3 : Int)) := by unfold term_6 term_5 term_1; exact Int.emod_lt_of_pos _ (by decide)
       have _m1_0 : ((0 : Int)) <= (term_2 _atoms _vars) := by unfold term_2 term_1 term_0; exact Int.emod_nonneg _ (by decide)
       have _m1_1 : (term_2 _atoms _vars) < ((3 : Int)) := by unfold term_2 term_1 term_0; exact Int.emod_lt_of_pos _ (by decide)
       revert _m0_0 _m0_1 _m1_0 _m1_1
       generalize (term_6 _atoms _vars) = _o0
       generalize (term_2 _atoms _vars) = _o1
       omega)
    | ...

Each have _m line proves 0 <= y mod 3 < 3 or the same for x. On a tiny lemma this costs little. On the 14-atom lemma these facts took omega 27 s.

A theory rewrite has no coefficients to check, so it still gets the bounds.

private theorem th_lemma_49 (_atoms : Nat -> Prop) (_vars : Nat -> Int)
    : (formula_48 _atoms _vars) := by

The Farkas lemma now goes straight to generalizing the two atoms and calling omega. The unfolded fallback after the second | is unchanged.

Review

The reviewer approved the PR with no blocker or major findings.

The stale README. The reviewer read the user-facing README next to the code. It still said every Farkas lemma gets mod bounds before omega. A maintainer debugging a slow lemma would have been misled. The paragraph was rewritten to say only cuts and coefficient-free lemmas get the bounds.

The confusing name. The new test used WIDE_DIVISION_SEED for seed 75. The QF_LIA tests already use that name for seed 67 at a different size. Someone searching after a failure would land on the wrong test. The constant became WIDE_FARKAS_SEED.

The inflated timings. The reviewer re-timed the slow file on an idle machine. It took 48 s before the change, not 140 s. The first figures were taken while stress runs loaded the machine. The speedup was real, but wrong numbers would mislead anyone tuning heartbeat budgets later. The plan note, a docstring and a test comment now give idle timings and mark the loaded ones.

The pinned test. The reviewer noted that the test expects at least 14 mod atoms and all three hints on one seed. An unrelated change in Z3's explanations could break it. The author kept it, because it proves the test exercises the wide case. Existing tests pin seeds the same way.

Risks and open questions

  • Soundness is unaffected. Only ordinary have lines were dropped, and nothing new is trusted. A missing fact can make a proof fail, never succeed wrongly.
  • If the Python re-derivation and Lean's generalized goal ever disagreed, the generalized attempt would fail. The unchanged unfolded fallback would then run.
  • The new test depends on how Z3 explains conflicts for seed 75. A change there could break it without any reconstructor bug.
  • GitHub CI results for the merged commit are not recorded here.

What comes next

  • Build a direct Farkas proof term from the coefficients, so these lemmas no longer depend on how omega eliminates variables.
  • Profile the other slow stress certificates, such as lia-ite79, lia-ite88 and legacy lia-ite86.
  • Widen the frontend for get-value after check-sat and for commands after exit.

Glossary

atom
A term the arithmetic treats as one opaque unknown, such as (mod x 3) or (f y).
bound
A fact that limits a value from below or above. For mod by k, the bounds are 0 <= m and m < |k|. In Z3, bound is also a hint for a lemma derived from bounds.
case analysis
Proving a goal by splitting into cases and proving each one. Bounded variables invite splits over their range.
certificate
The proof Z3 exports as a file, which an independent checker replays.
cut
An integer lemma that rounds a bound, for example from 2x <= 3 to x <= 1. Z3 marks these with the hint cut.
Farkas lemma
A theory lemma whose literals, each multiplied by a nonnegative coefficient and added up, give an obvious contradiction such as 0 < 0.
generalize
Replacing a term in the goal with a fresh variable, so the proof cannot look inside it. In Lean this is the generalize tactic.
heartbeats
Lean's work counter. A proof that exceeds maxHeartbeats is stopped and fails.
Int
The sort of mathematical integers, with no overflow.
linear combination
A sum of terms, each multiplied by a constant, such as 2a + 3b.
literal
An atomic formula or its negation, such as x >= 1 or not (x >= 1). A clause is a disjunction of literals.
mod
The remainder of integer division. SMT-LIB's mod is Euclidean, so the result is never negative.
omega
A Lean tactic that decides linear arithmetic over integers and naturals.
QF_UFLIA
The SMT-LIB logic of quantifier-free formulas with uninterpreted functions and linear integer arithmetic.
refutation
A proof that a set of assertions leads to False.
sort
The type of a value in SMT-LIB, such as Int, Real or Bool.
tactic
A Lean command that builds part of a proof automatically, such as omega or grind.
theory lemma
A clause that is valid in a background theory, here integer arithmetic. Z3 records it as a th-lemma step with a hint.
uninterpreted function
A function symbol with no fixed meaning. The only thing known is that equal arguments give equal results.
