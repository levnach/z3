Certify maps of functions, arithmetic, and ite in Lean via clause log

Pull request levnach/z3#77 · State: MERGED · Loop iteration 78
Merged on 2026-11-06T15:13:21Z as merge commit b5b691b76 (a squash of the PR's two commits onto master).

In one paragraph

Before this PR, an array map could be certified in Lean only when it applied one of four Boolean connectives to sets. Now maps of xor, =, distinct, Int and Real + and -, the comparisons, the if-then-else term, and uninterpreted functions and predicates of up to three arguments are certified too. The elements can be of an uninterpreted sort, Int, Real, or Bool. These proofs go through the clause log. The PR also closes a gap found by random testing: when Z3's rewriter skipped a store to read a map underneath, the Lean refutation lacked a needed fact. The trust boundary is unchanged. There is no sorry, no new axiom, and no change to the trusted options.

Background

The previous PR in this line, #74, added maps of not, and, or, and => over sets. Any other map made the exporter stop with "maps are supported over the connectives not, and, or, => only", even though Z3 solved the input. That left out maps of an uninterpreted function and pointwise arithmetic such as (_ map +). The plan listed "Maps of other functions" as the next backlog item. The work serves milestone 4 of the plan, "Broader theories and integration", which treats arrays as one of the extensions to cover.

What changed

Think of an array map like a spreadsheet column whose formula is "f of the cell to the left". Every row gets the same function. This PR teaches the pipeline many more such formulas.

  • The exporter now accepts maps of uninterpreted functions, arithmetic, comparisons, xor, =, distinct, and ite, and checks each one's sorts.
  • The clause-log replay can now rebuild a built-in map such as (_ map +), which Z3 logs without its signature.
  • The Lean reconstructor writes a map as a small Lean lambda, so each read of a map follows by rfl.
  • A certificate can no longer swap a mapped function for another one, because each is bound to the input's own symbol and signature.
  • Maps of commutative functions such as + and xor now get a proved swap rule, which matches how Z3 compares them during congruence reasoning.
  • A read that the rewriter takes straight through stores down to a map now gets the map's facts, for set operators too.

This input is the PR's new test map_function_read. Array b is f mapped over array a. Position 3 of a holds 4, so position 3 of b must be f(4). The last assertion claims otherwise, so the input is unsatisfiable.

(declare-fun a () (Array Int Int))
(declare-fun b () (Array Int Int))
(assert (= b ((_ map f) a)))

(assert (not (= (select b 3) (f 4))))

The theorem says the three assertions together imply False for every interpretation of f, a, and b.

private theorem th_lemma_22 (_atoms : Nat -> Prop) (_vars : Nat -> Int) (_m : Interpretation)
    : (formula_21 _atoms _vars _m) := by
  unfold formula_21 term_20 term_19 term_5 term_4
  have _t2 : (term_2 _atoms _vars _m) = (_map1 (fun (_v0 : Int) => (_m.ifuns 0 [(_m.int _v0)])) ((term_1 _atoms _vars _m))) := rfl
  have _m19 : _select ((term_2 _atoms _vars _m)) (((3 : Int))) = (_m.ifuns 0 [(_m.int (_select ((term_1 _atoms _vars _m)) (((3 : Int)))))]) := rfl
  first | omega | grind (splits := 64)

This lemma is the new feature at work: the fact _m19 says "position 3 of the map is f of position 3 of a", and Lean proves it by rfl.

Review

The reviewer approved the change. There were no blockers and no major findings.

  • Minor: a crash instead of a clean rejection. The reviewer fed the clause-log replay a deliberately broken log. It mapped <= over an uninterpreted sort and unary - over Bool. The replay crashed with a Python TypeError instead of rejecting it. Nothing reached Lean, so soundness was never at risk. Still, a checker should refuse bad input predictably. The fix reports an ill-sorted map, and a regression test covers three such heads.
  • Nit: a path readers could not follow. The plan cited a sweep script that lives only on the loop machine. It now describes the sweep as a one-off run outside the repository.
  • Nit: an incomplete list. The README did not say that functions of four or more arguments are rejected. The README and plan now say so, and the plan's vague "n-ary functions" was made precise.

Risks and open questions

  • Each map of a commutative function adds one more tactic call to grind. This is cheap on the tests, but map-heavy inputs could slow down.
  • Reads of a map over long store chains now carry more facts.
  • The Lean text for a map body copies how other terms are printed. If one changes without the other, Lean fails. That is a failure, not an unsound result.
  • Z3's trimmer cannot re-read map logs. Logs of 4 KB or more fall back to the slower untrimmed replay, with a warning.
  • No file in the z3test collection newly certifies. Its other maps are satisfiable or use unsupported commands.

What comes next

  • Fix Z3's clause-log printer so map logs can be trimmed again. This is a C++ backlog item.
  • Maps of *, conversions, abs, functions of four or more arguments, and maps over arrays of arrays remain rejected.
  • The default-map axiom is still rejected. 2 of the 92 unsat sweep inputs needed it.

Glossary

array map
An array made by applying one function to every position of one or more arrays. ((_ map f) a) holds f(a[i]) at each index i.
axiom
A statement accepted without proof. Adding a new one would mean trusting more than Lean's standard base.
Boolean
A value that is either true or false. The SMT-LIB sort is Bool.
clause
A disjunction of literals, read as "at least one of these holds". Example: p or not q.
clause log
The record Z3 writes of each clause it derives during solving, which is replayed to build the proof.
congruence
The rule that equal inputs give equal outputs. If x = y, then f(x) = f(y).
if-then-else term
A term that picks one of two values by a condition, written (ite c x y) in SMT-LIB.
lambda
An unnamed function written in place, such as fun x => x + 1.
lemma
A small proved statement used as a step toward a larger proof.
literal
An atomic formula or its negation, such as p or not p.
predicate
A function whose result is Boolean. (declare-fun p (Int) Bool) declares one.
refutation
A proof that a set of assertions leads to a contradiction, that is, to False.
rewriter
The part of Z3 that simplifies terms before and during solving, for example turning a read of a known store into its value.
rfl
Lean's proof that two sides are equal because they compute to the same thing.
set
In SMT-LIB, an array from some index sort to Bool. Index i is a member when the array holds true there.
sort
The type of a value, such as Int, Real, or Bool.
sorry
A Lean placeholder that skips a proof. A trustworthy certificate must contain none.
store
The array write operation. (store a i v) is a with position i changed to v. Its counterpart select reads a position.
tactic
A Lean command that searches for a proof step automatically. grind and omega are tactics.
trust boundary
The list of things a checked result still relies on without proof, such as Lean's kernel and its standard axioms.
uninterpreted function
A function symbol with no fixed meaning. A proof about it must hold for every possible function. Example: (declare-fun f (Int) Int).
uninterpreted sort
A sort declared by name only, with no fixed values, as in (declare-sort E 0).
